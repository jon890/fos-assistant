# 원격 검증

이번 계획·로컬 구현 검증에서 운영 브라우저·실계정·승인·저장·글 조회를 실행하지 않는다.
전체 구현 뒤 새로 승인한 지정 시험글로만 확인한다. 기존 승인 영수증을 재사용하지 않는다.
운영 값과 실행 방법은 비공개 운영 저장소가 갖는다. 공개 문서에는 확인 결과만 남긴다.

| 선행 조건 | 실행 위치 | 확인 항목 | 기대값 |
| --- | --- | --- | --- |
| 모든 구현 단계 머지·배포와 본문 없는 진단 정책 구현·가림 검증 | 승인된 시험 환경 | 실제 Hermes MCP·dashboard HTTP·CP·worker 왕복 | 승인 revision·hash·binding·jobId가 일치하고 start는 1회 |
| 같은 지정 저장 작업을 시작한 뒤 | 같은 시험 환경 | 대화 끊김·재접속·조회 timeout·gateway/CP restart | 같은 job만 조회하고 추가 저장·승인·start는 0회 |
| 새로 승인한 실패 주입 시험 | 같은 시험 환경 | 클릭 직전·직후 중단과 원고 수정·삭제·실제 사용자/agent 철회·CANCELLED 커밋 | save claim 전은 클릭 차단, claim 후 불확실성은 UNKNOWN, 무조건 재시도 없음 |
| 전체 연결 구현 완료 | #399의 승인된 30장 시험 환경 | 합성 표식 30장과 manifest·실제 전송 bytes·포함/빠진 ID | 입력 대응을 위치·ID·지문으로 판정하고 내용 판독은 별도 판정 |
| 실제 component 형태의 별도 관측 완료와 새 저장·읽기 승인 | 같은 지정 시험 환경 | 업로드 alias와 저장·재불러온 실제 component 대응 | 관측 근거가 있는 사진만 원본 대응 성공, 누락·중복·이름 변경은 미확인 |

EXECUTING binding 해제·계정 변경은 실제 API의 기존 거절을 확인한다. 해제 성공으로 claim 차단을 증명하지 않는다. stop 응답만으로 취소 커밋을 대신하지 않는다.

실제 사진 component와 alias 보존은 아직 미확인이다. 위 마지막 검증은 이번 계획의 read 메타데이터 구현 지시가 아니다.
필드 형태 관측이 먼저 끝나야 별도 구현 범위를 정할 수 있다. projection 번호·CDN basename·사진 count로 성공을 대체하지 않는다.
