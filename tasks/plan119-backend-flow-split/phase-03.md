# Phase 03. 에이전트와 스킬, 사용자 추가와 브라우저, 커넥터의 flow 를 줄인다

**Execution profile**: deep

## 목표

`backend/docs/flow/` 의 agent, user, connector 세 파일을 줄인다.
코드를 말로 옮긴 부분과 코드와 어긋난 낡은 내용을 지우고, 코드만 봐서는 알 수 없는 것만 남긴다.
목표 줄 수: 세 파일 합계 1,000줄 이하(옮긴 직후 약 2,150줄)

**범위 외**: 다른 flow 파일(phase 02, 04)과 `backend/docs/data-schema.md`(phase 05).

## 컨텍스트

**근거 문서**: `docs/adr/ADR-20261009-docs-per-module.md` 의 「결정」 중 「코드와 설정이 이미 가진 값을 문서에 옮겨 적지 않는다」. flow 를 기능별 파일로 나눈 결정은 phase 01 이 만드는 `flow-folder` ADR 이 갖는다

사용자 원칙(2026-10-09): 로직은 코드가 말한다. 문서에는 **코드만 봐서는 알 수 없는 것**만 남긴다.
의사결정과 그 까닭, 흐름이 갈리는 지점(실패, 빈 상태, 동시 요청, 재시작), 외부 계약(Hermes, MCP, plugin, 웹과 주고받는 약속)이다. 코드를 말로 옮긴 부분은 지운다.

### 지우는 것

| 종류 | 예 |
| --- | --- |
| 칸과 목록 복사본 | 요청과 응답 칸 목록, 설정 키 표, enum 값 목록, 오류 코드 목록, 색인 목록 |
| 상수 값 | 시간, 개수, 한도 값. 값이 왜 그만한지가 결정이면 까닭만 남기고 수치는 코드 이름으로 가리킨다 |
| 코드 순서 서술 | 「A 가 B 를 부르고 C 를 저장한다」 처럼 메서드 순서를 말로 옮긴 문장, 「어느 클래스가 무엇을 하나」 같은 클래스 소개 표 |
| 다른 문서의 복사본 | 같은 내용이 `web/docs/flow.md`, 루트 `docs/flow.md`, `hermes/docs/hermes-contract.md`, ADR 본문에 있으면 여기서 지우고 그 문서를 링크한다 |
| 낡은 내용 | 코드와 어긋난 문장. 고쳐 쓰지 않고 지운다. 남길 가치가 있는 결정이면 지금 코드에 맞게 한 문장으로 다시 쓴다 |
| 이미 끝난 일의 이력 | 「옛 …에서 옮겼다」, 「다음 단계」 중 이미 된 것 |

### 남기는 것

- 까닭이 붙은 결정(「…때문이다」, 「…하지 않으면 …된다」). ADR 링크는 남긴다.
- 실패, 빈 상태, 동시 요청, 재시작에서 갈리는 지점. 표로 된 분기는 표를 남기되 코드 복사 칸은 뺀다.
- Hermes, MCP 도구, plugin, 웹이 기대는 외부 계약. 칸 이름이라도 상대가 기대는 약속이면 남긴다.
- 사람이 판단한 기준(왜 그 순서인지, 왜 그 경계인지).

### 지켜야 하는 것

- **헤딩 이름을 바꾸지 않는다.** 코드 주석과 다른 문서가 「절 이름」 으로 가리킨다. 본문이 다 지워지는 절도 헤딩은 남기고 한두 문장(결정이나 갈리는 지점, 없으면 「코드는 `<클래스>` 가 갖는다」)을 둔다.
  다만 다른 곳이 가리키지 않는 `###`, `####` 절은 합치거나 지워도 된다. 가리키는지는 `node --test test/unit/doc-references.test.ts test/unit/doc-links.test.ts` 로 확인한다.
- 남기는 문장에 적힌 클래스, 메서드, 경로, 오류 코드, 설정 키는 코드에서 실제 정의를 찾아 맞는지 확인한다. `test/unit/doc-code-references.test.ts` 가 경로, API, 설정 키, `클래스.멤버`, 환경 변수를 본다. 클래스 이름 단독과 대문자 값은 알림만 내므로 직접 `git grep` 으로 확인한다.
- 동작을 바꾸지 않는다. 코드, 시험, 다른 문서는 고치지 않는다. 지운 절을 다른 문서가 링크하면 그 링크만 남은 절로 바꾼다.
- 새 문서 파일을 만들지 않는다.
- 공개 저장소다. 홈서버 주소, 포트, 컨테이너 이름, 경로, 계정을 적지 않는다(새로 쓰는 문장이 거의 없으므로 지우는 쪽이면 해당 없음).
- 한국어 문장은 조사와 어미를 생략하지 않고, 한 줄에 한 문장을 둔다.

## 의도 메모

- 목표는 줄 수가 아니라 「코드만 봐서는 알 수 없는 것」 이다. 다만 flow 전체 2~3천 줄, 파일 하나 500줄 이하를 넘기면 아직 복사본이 남았다는 신호로 보고 다시 훑는다.
- 고쳐 쓰기보다 지우기를 먼저 한다. 지우고 나서 앞뒤 문장이 끊기면 그 연결만 고친다.
- 커밋 메시지 본문에 파일마다 줄 수 전후와 지운 종류(위 표의 종류 이름)별 대략의 줄 수, 코드와 어긋나 지운 낡은 내용 목록을 적는다. PR 본문의 표가 이것을 모은다.

## 작업 항목

### 1. `backend/docs/flow/agent.md` 를 줄인다

1. 파일을 `##` 절 단위로 읽고, 절마다 그 기능의 코드(`backend/src/main/java/com/bifos/assistant/` 의 해당 패키지)를 연다.
2. 위 「지우는 것」 에 드는 줄을 지우고, 남는 문장의 식별자와 동작을 코드와 대조한다. 어긋나면 지우거나 지금 코드에 맞게 한 문장으로 고친다.
3. 그 절의 시험 파일(`backend/src/test/java/` 의 같은 패키지)에서 갈리는 지점이 시험으로 확인되는지 본다. 시험이 확인하는 분기는 문서에 한 줄 결론만 남겨도 된다.

### 4. 이 phase 를 검증하는 시험

새 시험은 만들지 않는다. 문서만 바뀌므로 문서 검사 시험(`test/unit/doc-*.test.ts`)이 이 phase 의 검증이다.
헤딩을 지워 코드 주석의 「절」 이 끊기면 `doc-references` 가, 백틱으로 남긴 이름이 코드에 없으면 `doc-code-references` 가 실패한다.

## 검증

```bash
node --test test/unit/doc-files.test.ts test/unit/doc-code-references.test.ts test/unit/doc-references.test.ts test/unit/doc-links.test.ts
node scripts/check-file-length.mjs
wc -l backend/docs/flow/agent.md backend/docs/flow/user.md backend/docs/flow/connector.md
```

- 첫 줄은 종료 코드 0 이다. 둘째 줄은 이 phase 의 파일에 대한 `알림:` 이 없어야 한다.
- 셋째 줄의 각 파일이 500줄 이하이고 합계가 목표 줄 수 안이다. 넘으면 남은 절을 다시 훑고, 그래도 넘으면 까닭을 회신에 적는다.
- `node --test test/unit/doc-code-references.test.ts` 의 `알림:` 가운데 이 phase 파일의 것은 새로 늘지 않는다.
