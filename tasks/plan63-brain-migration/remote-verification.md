# 원격 검증

실행 방법은 비공개 저장소 `fos-home-infra` 가 갖는다. 여기에는 확인할 것만 적는다.
**실제 지식은 위에서부터 차례로 확인한 뒤에 들인다.** 처음 확인에는 지어낸 본문을 쓴다.

| 선행 조건 | 실행 위치 | 명령 | 기대값 |
|---|---|---|---|
| 배포한 뒤 | 홈서버 | `fos-home-infra` 의 배포 확인 절차 | 컨테이너가 새로 만들어졌고 기동 로그에 `Started Assistant` 가 있으며 `Schema validation` 이 실패하지 않는다 |
| 같은 배포 뒤 | 브라우저 | 지어낸 본문의 항목 둘(일반 `MEMORY` 하나, 민감 `DOCUMENT` 하나)을 담은 묶음을 손으로 만들어 `/memory` 의 「기존 기록 가져오기」 에 올린다 | 미리보기에 둘 다 「새로 가져와요」 로 보이고, 가져온 뒤 「나에 대해 아는 것」 과 「문서」 에 하나씩 보인다 |
| 위를 가져온 뒤 | 브라우저 | 같은 묶음을 한 번 더 올린다 | 둘 다 「이미 가져왔어요」 이고 항목이 늘지 않는다 |
| 위를 가져온 뒤 | 홈서버 | `fos-home-infra` 의 데이터베이스 조회 절차로 그 두 줄의 `source_type`, `source_date`, `content_key_id` 를 본다 | `source_type` 이 `brain` 이다. 민감 문서의 `content` 가 `v1.` 으로 시작하고 `content_key_id` 가 채워져 있다 |
| 확인이 끝난 뒤 | 브라우저 | 확인에 쓴 두 항목을 지운다 | 목록에 남지 않는다 |
| 위가 모두 통과한 뒤 | 주인의 기기 | 분석기로 보고서를 만들고, `scripts/brain-import/decisions.ts init` 으로 결정 파일을 만들어 검토하고, `scripts/brain-import/bundle.ts` 로 신원을 뺀 묶음을 만든다 | 표준 출력에 개수만 나온다. 묶음이 저장소 밖에 0600 으로 있다 |
| 묶음을 만든 뒤 | 브라우저 | 묶음을 올려 미리보기를 읽고 가져온다 | 「같은 이름이 있어요」 와 「가져올 수 없어요」 항목은 저장되지 않는다. 결정 파일을 고쳐 다시 묶는다 |
| 가져오기가 끝난 뒤 | 주인의 기기 | `scripts/brain-import/bundle.ts clean` | 묶음 파일이 남지 않는다 |
| 신원을 뺀 이관이 끝난 뒤 | 홈서버와 홈서버 밖의 기기 | ADR-058 의 「신원 항목을 여는 조건」 셋을 관측한다 | 셋이 모두 맞다. 하나라도 어긋나면 신원 묶음을 만들지 않는다 |
| 위 셋이 맞은 뒤 | 주인의 기기와 브라우저 | `--identity only` 로 신원 묶음을 만들어 올리고, 끝나면 `clean` 을 돌린다 | 신원 문서가 「문서」 에 「민감」 으로 보이고 본문은 열 때만 보인다 |
