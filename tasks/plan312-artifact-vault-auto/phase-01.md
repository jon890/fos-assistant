# Phase 01. turn 이 끝날 때 완성 결과물을 요청자에게 자동 보관한다

**Execution profile**: standard

## 목표

에이전트가 결과물로 낸 완성 파일을 turn 완료 때 대화 요청자의 보관함에 자동으로 보관한다. 같은 일이 두 번 돌아도 한 건이고, 서버가 재시작해도 이어서 끝낸다.
새 테이블을 만들지 않는다(2026-11-01 사용자 결정).

**범위 외**: 원고 revision, PDF·문서 보관, 외부 Drive 내보내기, 그룹 공유.

## 컨텍스트

**근거 문서**: `docs/adr/ADR-20261101-artifact-vault.md`, `docs/features/workspace.md` 의 「보관한 결과물」

- PR 1·2 가 `chat_artifact` 의 보관 사본 행과 보관 서비스(`ArtifactVaultService`)를 만들었다. 이 계획은 그 서비스를 turn 완료 쪽에서 부른다
- 자동 보관 대상은 결과물로 등록한 완성 파일만이다. 로그·캐시·중간 파일과 일반 파일은 제외하고 일반 파일은 사용자가 골라서 보관한다
- 보관 주인은 대화 요청자이고 그룹 공개 에이전트를 써도 요청자에게만 보관한다. 취소되거나 답이 없는 실행의 파일은 자동으로 완성본이라 보관하지 않는다
- **지운 보관본을 자동 보관이 다시 만들지 못하게 하는 지우기 이력이 필요하다.** PR 1 의 지우기는 행을 지워 이력이 없다. 이력을 둘 곳은 새 테이블이 아니라 기존 사건 기록 테이블(`decision_feedback_event` 등)을 먼저 본다. 새 테이블이 꼭 필요하면 만들기 전에 까닭을 정리해 사용자에게 묻는다
- 재시도 가능한 작업 기록과 재시작 복구가 필요하다. 이 기록을 기존 테이블로 담을 수 있는지 먼저 정한다
- 보관이 실패해도 대화 답과 원본 파일은 유지하고 재시도 가능한 이유를 화면에 보인다
- 사용자 설정(자동 보관 켜기·끄기)의 위치를 정한다. 기본값은 화면 결정이라 사용자에게 묻는다
- Hermes 연동을 바꾸면 배포 뒤 실제 실행 왕복이 필요하다. 운영 절차는 비공개 저장소가 갖는다

## 작업 항목

1. 지우기 이력과 작업 기록을 둘 기존 테이블을 정하고 ADR 을 고친다
2. turn 완료 훅에서 등록된 결과물을 멱등으로 보관하는 작업과 재시작 복구
3. 대화에서 결과물 옆에 「보관 중」, 「보관 완료」, 「보관 실패」와 「다시 보관」 표시
4. 자동 보관 설정

## 검증

- 재전송, 동시 덮어쓰기, 응답 유실, 재시작에서도 중복 0건
- 과거 버전 불변, 그룹 공개 에이전트에서도 요청자에게만 보관
- 보관 실패 때 답과 원본 유지, 지운 보관본이 다시 생기지 않음
