# 원격 검증

운영 값과 실행 방법은 `fos-home-infra` 가 갖는다. 여기에는 무엇을 확인하는지만 적는다.
화면과 zip 올리기는 다음 PR 이라 아래는 모두 API 로 한다.

| 선행 조건 | 실행 위치 | 명령 | 기대값 |
|---|---|---|---|
| 이 PR 을 배포한 뒤, 운영 정책에 `skill_root` 를 넣기 전 | 홈서버, `fos-home-infra` 의 Hermes 배포 확인 절차 | 기존 실행 공간 profile 에서 셸 도구를 다시 저장하고 셸을 쓴다 | 저장과 셸이 배포 전처럼 된다. 정책이 무효가 되지 않는다 |
| 위와 같음 | 같은 곳 | 셸이 켜진 에이전트에 `PUT /api/v1/agents/{code}/skills/{name}` 으로 `scripts/hello.sh` 가 든 스킬을 저장한다 | 409 `SKILL_SCRIPTS_NEED_SANDBOX` 이고 지금 버전이 바뀌지 않는다. scripts 없는 스킬은 저장된다 |
| 운영 정책에 `skill_root` 를 넣고 socket proxy 가 그 마운트를 허용한 뒤 | 같은 곳 | 같은 저장을 다시 하고 대화에서 그 스킬을 부른다 | 저장되고, 모델이 `skill_view` 가 준 경로의 스크립트를 실행 공간에서 돌려 출력을 답한다 |
| 위와 같음 | 같은 곳 | `hello.sh` 출력을 바꿔 다시 저장하고 컨테이너를 다시 만들지 않은 채 부른다. 그 뒤 `POST /api/v1/agents/{code}/skills/{name}/restore-previous` 하고 다시 부른다 | 바뀐 출력이 나오고, 되돌린 뒤에는 첫 출력이 나온다 |
| 위와 같음 | 같은 곳 | 스킬이 없는 실행 공간 profile 의 셸 도구를 저장하고 셸을 한 번 쓴다 | 컨테이너가 생기고 셸이 돈다. 없는 스킬 디렉터리를 붙이지 않는다 |
