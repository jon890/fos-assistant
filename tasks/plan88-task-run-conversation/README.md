# plan88 대기 중인 발화의 대화

시작 단계는 `QUEUED` 발화에 대화를 먼저 만들어 두고 turn 잠금을 얻으면 연다. 그 사이에 두 문제가 생긴다.

- 기다리는 동안 작업의 에이전트를 바꿔도 이미 만든 대화를 다시 써서 옛 에이전트로 돈다
- 결국 `SKIPPED` 로 닫히면 메시지 없는 빈 대화가 사이드바 「예약 작업」 묶음에 남는다

둘 다 「발화가 미리 만든 대화를 언제 버리는가」 라는 같은 관심사라 한 plan 으로 둔다. 계약은 `docs/backend/task.md` 의 「시작」 이 갖는다.

| phase | 만드는 것 |
| --- | --- |
| 01 | 대화 재사용의 에이전트 검사, 건너뛸 때 빈 대화 지우기, 검사 |

이슈: #177 의 「`NEW_PER_RUN` 발화가 ... 빈 대화가 남는다」, 「`QUEUED` 동안 에이전트를 바꾸면 이미 만든 대화는 옛 에이전트로 돈다」.
