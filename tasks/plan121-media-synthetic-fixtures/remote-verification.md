# 원격 검증

검증 대상은 선행 머지 후 최신 main을 fetch/일반 merge한 head다. 새 lane은 최신 main에서 시작하며 rebase와 force push는 금지다. 로컬 검사와 CI가 통과한 일반 push 결과만 배포 확인 대상으로 전달한다.

운영 접근·배포 방법과 값은 fos-home-infra가 갖는다.
공개 계획서에 운영 명령·경로·계정·포트·토큰 조회 방법을 옮기지 않는다.
이 목록은 phase가 아니며 구현 커밋 뒤 코디네이터가 담당한다.

| 선행 조건 | 실행 위치 | 확인 항목 | 기대값 |
| --- | --- | --- | --- |
| 이 관심사 구현이 머지되고 관련 plugin/backend가 배포된 뒤 | 운영 저장소가 관리하는 검증 환경 | 실제 Hermes와 Control Plane 새 계약 왕복, 옛 계약 호환 | 새로운 표면이 계약대로 작동하고 권한 밖 접근은 거절 |
| 모든 파이프라인 구현과 #397 보호가 배포되고 실제 실행 별도 승인을 받은 뒤 | 승인된 합성 테스트 계정 | 30장 실제 provider와 네이버 임시저장, 원본·runtime·decoded 길이/SHA, 단계 ID, snapshot hash, 비용·p95, 재시작 | 중복 저장0·무승인 WRITE0·누락/불확실성의 정직한 보고. 실제 미측정은 No-Go |

실제 확인에서는 구현된 단계의 활성화 범위만 주장한다. 구조화 저장은 영속 job 예약까지 갖춘 뒤에만 실행하며 preview 지문·수명, 승인된 외부 확인, 전체 snapshot 검증과 만료한 실행 맥락의 재전달 차단을 해당 단계에서 확인한다. 운영 접근 방법은 fos-home-infra가 갖는다.

JPEG/PNG/GIF만 기존 JDK로 실제 바이트·표식 픽셀을 검증한다. WebP metadata와 실제 판독 UNMEASURED를 구분하고 실제 첫 프레임 양성은 머지된 PR #394 runtime 회귀와 후속 통합 검증으로 전달한다. 별도 CI job의 Pillow 공유와 새 의존성은 가정하지 않는다. reducer 통과는 실제 provider/브라우저 성공이 아니다.
