# 원격 검증

실행 방법과 접속 값은 운영 저장소 `fos-home-infra` 가 갖는다. 이 표의 명령 칸은 이 저장소의 명령만 적고, 환경 변수와 로그 파일을 채우는 일은 운영 저장소의 평가 실행 스크립트가 맡는다.

| 선행 조건 | 시점 | 실행 위치 | 명령 | 기대값 |
|---|---|---|---|---|
| 배포 | PR 뒤 | 홈서버, 운영 저장소의 평가 실행 스크립트 | 사진을 붙인 메시지 뒤 사진 없는 메시지를 한 번 보낸 대화의 backend 로그 | 두 번째 실행 입력에서 `referenced` 줄이 남고, 모델이 `attachment_inspect` 를 부른 실행에서 `inspected` 줄이 `OK` 로 남는다. 두 줄에 좌표, 파일 이름, 바이트가 없다 |
| 배포 | PR 뒤 | 홈서버, 운영 저장소의 평가 실행 스크립트 | `node test/model-eval/blog/run.ts send --out <디렉터리>` 뒤 `node test/model-eval/blog/run.ts score --out <디렉터리> --log <파일>` | 네 시나리오의 보고서가 만들어진다. 지난 사진 안내를 고치기 전의 기준값이므로 `past-only` 와 `many-past` 의 `FAIL` 은 예상한 결과다. 시나리오별 결과와 사진별 문제의 수를 `docs/features/naver-blog-connector.md` 의 「블로그 사진 평가」 에 측정 날짜와 함께 적는다 |
| 배포 | PR 뒤 | 홈서버, 운영 저장소의 평가 실행 스크립트 | 사용자 동의를 받은 비공개 재현. 운영 저장소가 그 대화의 지시문과 사진을 저장소 밖 임시 디렉터리에 꺼낸 뒤 `node test/model-eval/blog/run.ts send --scenario-file <경로> --out <디렉터리>` 와 `score` | 사진 조회와 되묻지 않음의 판정이 나온다. 미리보기는 관리자가 직접 읽는다. 임시 디렉터리와 결과 디렉터리를 지운다. 결과에는 수치만 적고 대화 글과 사진을 적지 않는다 |
