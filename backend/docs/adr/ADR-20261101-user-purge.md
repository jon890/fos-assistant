## ADR-20261101 / user-purge: 관리자가 끈 사용자를 「정리 예약」 하면 30일 뒤 정리 작업이 그 사용자의 데이터를 지우고, 그룹 공유 데이터는 관리자에게 넘긴다

- **status**: `accepted`
- Date: 2026-11-01
- **대체된 부분**: `backend/src/test/resources/purge/tables.tsv` 머리말의 「USER 는 물리 삭제 경로가 없다」 와 `app_user`, `allowed_person` 의 「접근 해제는 개인 데이터를 물리 삭제하지 않는다」 를 이 결정이 구현되는 단계마다 바꾼다. 접근 해제(끄기) 자체는 지금처럼 데이터를 지우지 않는다.

### 결정

**관리자가 사용자를 끈 뒤 따로 「정리 예약」 을 눌러야 정리가 시작된다. 예약한 지 30일이 지나면 정리 작업이 지운다. 30일 안에 다시 켜면 예약이 취소되고 아무것도 지워지지 않는다.**

- 사용자 정리는 끄기와 별개 동작이다. 끄기만으로는 아무것도 지우지 않는다.
- 예약 상태는 새 테이블 없이 `allowed_person.purge_scheduled_at` 한 칸에 둔다. 비어 있으면 예약이 없다. 다시 켜면(`setEnabled(true)`) 이 칸을 비운다.
- 진입점은 `/admin/people` 의 꺼진 사용자 줄이다. 예약과 취소는 `ADMIN` 만 부른다. 예약 전에 지울 범위를 미리보기(`GET /api/v1/admin/people/{id}/purge-preview`)로 보인다.
- 정리 작업은 대화 정리, 에이전트 정리와 같은 방식으로 매분 후보를 보고 실패하면 다시 한다. 한 사용자는 한 트랜잭션 단위로 끝내지 않고 단계마다 이어서 한다(아래 순서).

### 지울 범위

| 대상 | 정리 때 하는 일 |
| --- | --- |
| 대화(`conversation`)와 그 본문 | 그 사용자의 모든 대화를 지운 것으로 표시해 기존 대화 정리(ADR-20261008 / conversation-purge)가 Hermes session, 첨부, 결과물, 메시지를 지우게 한다 |
| 보관본(`chat_artifact` 의 `vault_user_id` 행) | 묶음 자식 행과 본문 없는 지우기 이력 행까지 지운다. 다른 사용자의 행은 건드리지 않는다. 본문을 푸는 key 를 지우기 전에 먼저 지운다 |
| 비공개 에이전트 | 지운 것으로 표시해 기존 에이전트 정리(ADR-20261009 / agent-purge)가 7일 뒤 지운다 |
| 그룹에 공개한 에이전트 | 지우지 않고 `owner_user_id` 를 그룹의 관리자에게 넘긴다. 관리자가 여럿이면 `app_user.id` 가 가장 작은 관리자에게 넘긴다 |
| 그룹 공용 기억 항목(`memory` 의 `scope = 'GROUP'`) | 지우지 않고 소유 칸을 같은 관리자에게 넘긴다 |
| 개인 기억(`scope = 'USER'`)과 그 임베딩, 링크, 변경 이력 | 지운다 |
| 할 일, 예약 작업과 실행 이력, 알림, 주의 이벤트, 자동 실행 동의, 커넥터 연결과 도구 권한, 브라우저 | 지운다. 커넥터 연결의 비밀값과 브라우저 profile 은 외부 정리까지 한다 |
| 데이터 key(`user_data_key`) | 위가 모두 끝난 마지막에 지운다. 지운 뒤에는 남은 암호문을 풀 수 없다 |
| 사용자 줄(`app_user`) | 마지막에 지운다 |
| `allowed_person` | 줄은 남기고 꺼진 채 둔다. 같은 주소가 다시 들어오려면 관리자가 켜야 한다. 켜면 새 사용자가 새로 만들어진다 |
| 사용량 원장(`agent_execution`, 실행 사건) | 남긴다. 금액과 토큰은 회계에 필요하다. 본문은 대화 정리가 이미 비운다 |
| 그룹 공용 설정(`group_setting`, `memory_collection`, `toolset_hidden`) | 사용자 한 사람의 것이 아니므로 건드리지 않는다 |
| Hermes profile 과 MCP 토큰 | 사용자의 기본 profile 은 기존 profile 거두기로 정리한다 |

### 되돌리기

- 예약 뒤 30일 안: 다시 켜면 예약이 취소된다. 그 시점까지 아무것도 지우지 않았다.
- 정리가 시작된 뒤: 되돌릴 수 없다. 데이터 key 까지 지우므로 백업으로도 암호문을 풀 수 없다. 그래서 key 는 마지막에 지운다.
- 단계가 중간에 실패하면 남은 단계를 다시 한다. 단계마다 이미 지운 것을 다시 지워도 같은 결과다.

### 단계

1. 지울 범위 미리보기(읽기 전용). 지우는 코드는 없다.
2. 예약 칸, 예약과 취소 API, 다시 켜면 취소. 정리 작업은 아직 지우지 않는다.
3. 보관본과 개인 데이터 삭제, 그룹 공유 데이터 이관, 데이터 key 와 사용자 줄 삭제, 정리 작업을 연다. 이 단계에서 `tables.tsv` 의 USER 칸을 DELETE, TRANSFER 로 바꾼다.

### 대안 기각

- **끄면 곧바로 지운다**: 실수로 끈 사용자의 데이터가 사라진다.
- **유예를 7일로 둔다**: 데이터 key 를 지우면 복구 방법이 없다. 되돌릴 시간을 더 길게 둔다.
- **그룹에 공개한 에이전트도 지운다**: 다른 사용자의 사용이 끊긴다. 관리자에게 넘기면 끊기지 않는다.
- **보관본만 지운다**: 대화와 기억은 남는데 보관본만 사라진 상태가 된다. 사용자 결정은 주인 없는 암호화 본문을 남기지 않는 것이다.
- **새 테이블에 정리 상태를 둔다**: 테이블을 늘리지 않는다는 결정에 따라 `allowed_person` 의 칸 하나로 둔다.

### 결과

- 얻는 것: 정리 뒤 주인이 없는 암호화 본문이나 개인 기억이 남지 않는다. 다른 사용자의 사용은 끊기지 않는다.
- 감당할 것:
  - 정리가 시작되면 되돌릴 수 없다.
  - 관리자는 넘겨받은 에이전트와 기억을 떠맡는다.
  - 사용량 원장에 사라진 사용자의 번호가 남는다. 이름과 주소는 `app_user` 와 함께 사라진다.
