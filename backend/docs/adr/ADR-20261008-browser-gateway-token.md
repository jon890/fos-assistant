## ADR-20261008 / browser-gateway-token: 브라우저 중계의 접근 표식은 바인딩 번호에서 HMAC 으로 만들고 표에 두지 않는다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-20261007 / user-browser](../../../docs/adr/ADR-20261007-user-browser.md) 의 「접근 표식은 바인딩마다 만든 무작위 값이고 DB 에는 해시만 둔다」 를 바꾼다. 중계가 넘기는 것과 자동으로 켜는 것은 그 ADR 을 그대로 따른다.

### 결정

**중계의 접근 표식은 Control Plane 만 아는 비밀로 바인딩 번호를 HMAC 한 값이다. 표식을 저장하는 표는 두지 않는다.**

| 항목 | 정한 것 |
| --- | --- |
| 바인딩 표식 | `b<바인딩 번호>.<HMAC-SHA256 16진수 64자>`. 서명할 글은 `v1`, `binding`, 바인딩 번호를 `\n` 으로 이은 것이다. 같은 바인딩은 늘 같은 표식을 받는다 |
| 호출 표식 | 연결 등록과 연결 확인, 선택지 조회처럼 바인딩 없이 커넥터를 부를 때 쓴다. `u<사용자 번호>.<만료 epoch 초>.<HMAC>`. 서명할 글은 `v1`, `call`, 사용자 번호, 만료 시각이다. 5분 뒤 만료된다 |
| 비밀 | `assistant.browser.gateway-secret`. 운영 비밀값이다. Hermes 와 나누지 않는다 |
| 브라우저 고르기 | 바인딩 표식은 그 바인딩의 연결 주인, 호출 표식은 그 사용자의 브라우저다. 요청할 때마다 표에서 다시 읽는다 |
| 끊기 | 바인딩을 떼면 줄이 없어져 그 표식은 바로 404 다. 비밀을 바꾸면 모든 표식이 무효가 되고, 바인딩을 다시 설치해야 한다 |
| 브라우저가 없다 | 중계가 그 주인의 브라우저를 만들고 켠다. 동시 수와 자동 중지는 화면으로 켤 때와 같다 |

### 맥락

바인딩 설치는 서버 정의의 env 가 바뀌면 공유 gateway 의 재시작을 요구한다(`restart_required`).
연결 확인과 값 교체는 붙은 바인딩마다 설치를 다시 보낸다.
설치마다 새 무작위 표식을 만들면 연결 확인마다 서버 정의가 바뀌어, 관리자가 gateway 를 재시작할 때까지 바인딩이 `PENDING` 에 머문다.

연결 등록과 확인은 바인딩이 생기기 전에 확인 도구를 부른다. 이 호출도 그 사용자의 브라우저에 닿아야 로그인 여부를 볼 수 있다.

커넥터 MCP 서버는 Hermes 프로세스의 자식이다. 같은 Hermes 의 다른 profile 설정 파일을 읽을 수 있으므로 표식은 모델과 요청 본문이 다른 사용자의 브라우저를 고르지 못하게 하는 장치이고, 커넥터 코드 자체를 막는 경계는 아니다. 그 경계는 이 저장소가 검토한 커넥터 코드다.

### 대안 기각

- **무작위 표식과 해시 표(앞 ADR 의 초안)**: 위 「맥락」 의 재시작 문제가 생긴다.
- **무작위 표식과 해시 표에, 대시보드가 이미 설치된 표식을 지키는 왕복을 더한다**: Control Plane 이 해시를 보내고 대시보드가 설치된 값의 해시가 맞으면 옛 값을 둔다. 재시작은 피하지만 두 쪽에 계약이 늘고, 설치 기록이 사라진 경우를 따로 다뤄야 한다.
- **JWT 서명 비밀을 같이 쓴다**: 운영 값이 하나 줄지만 사용자 토큰의 비밀을 바꾸면 모든 바인딩을 다시 설치해야 한다. 쓰임이 다른 비밀은 나눈다.
- **Hermes 서비스 토큰으로 서명한다**: Hermes 가 아무 바인딩 번호의 표식이나 만들 수 있다.
- **표식을 DB 에 원문으로 둔다**: 비밀값을 데이터베이스에 넣지 않는다는 저장소 규칙에 어긋난다.

### 결과

- 얻는 것:
  - 연결 확인과 다시 설치가 서버 정의를 바꾸지 않아 재시작 대기가 생기지 않는다.
  - 표와 마이그레이션이 없다. 바인딩 줄이 곧 허락이다.
  - 연결 등록 전에도 사용자의 브라우저로 로그인을 확인한다.
- 감당할 것:
  - 운영 비밀값 하나와 중계 주소 하나가 늘어난다. 둘 중 하나라도 비면 중계가 꺼지고 커넥터는 브라우저에 닿지 못한다. 기동은 멈추지 않는다.
  - 표식 하나만 따로 무효로 만들 수 없다. 바인딩을 떼거나 비밀을 바꾼다.
  - 호출 표식은 만료 전까지 쓸 수 있다. 확인 도구의 자식 프로세스 env 에만 실리고 저장되지 않는다.

- **적용 범위**: backend 의 `browser` 패키지(표식과 중계)와 `connector` 패키지(설치와 확인 호출에 표식 싣기). 계약은 [사용자 브라우저](../flow.md) 의 「중계」 가 갖는다.
