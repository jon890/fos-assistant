## ADR-20261015 / memory-hybrid-selection: 색인 층은 매 turn 질문으로 키워드와 의미 점수를 섞어 고르고, 임베딩은 별도 서비스가 만든다

- **status**: `accepted`
- Date: 2026-10-15
- [ADR-015](ADR-015-memory-는-층을-나눠-싣는다.md) 의 「제목만 싣는 층」 을 고치는 방식을 바꾼다. 층을 나눠 싣고 나머지를 도구로 읽는다는 결정은 그대로다.
  색인 층의 순서는 번호 순이 아니라 질문과의 관련도 순이 되고, 관련도가 높은 몇 건은 본문까지 싣는다.
  [ADR-20261008 / memory-facts](../../../docs/adr/ADR-20261008-memory-facts.md) 의 개인 사실 구역은 바꾸지 않는다. 지금처럼 질문과 무관하게 싣는다.
- 구현은 #310 2단계의 단계 1 이다. 이 ADR 이 머지될 때는 아직 만들지 않았다.

### 결정

**매 turn 사용자 질문으로 기억을 찾고 위의 몇 건을 컨텍스트에 싣는다.** 모델이 `memory_search` 를 부를지에 기대지 않는다.

| 무엇 | 정한 것 |
| --- | --- |
| 찾는 대상 | 지금 색인 층에 오를 항목. 권한 조건은 지금처럼 점수를 매기기 전에 `MemoryQueries` 가 데이터베이스에서 건다 |
| 키워드 점수 | 앱 안의 BM25. 제목과 본문을 음절 bi-gram 으로 쪼갠다. 민감 항목은 제목만 쓴다 |
| 의미 점수 | 질문과 항목의 임베딩 코사인. 벡터는 데이터베이스에 두고 앱이 전수 계산한다 |
| 합치는 방법 | 두 순위를 RRF(k=60) 로 합친다. 라벨이 쌓이면 정규화한 가중합으로 옮길 수 있다 |
| 관련 없음 | 키워드 일치가 없고 코사인이 임계값 아래면 점수를 주지 않는다. 그런 질문에는 아무것도 본문으로 싣지 않는다 |
| 싣는 자리 | 개인 사실 구역 뒤에 「질문과 관련된 기억」 구역(`MEMORY_SEARCH`)을 두고 상위 몇 건을 본문까지 싣는다. 건수와 글자 예산은 설정값이다. 민감 항목은 본문을 싣지 않는다 |
| 나머지 색인 | 점수가 있는 항목을 점수 순으로, 그 뒤에 나머지를 번호 순으로 싣는다. 예산과 몫은 지금과 같다 |
| `memory_search` | 같은 점수로 본문까지 찾고 관련도 순으로 낸다 |
| 기록 | `execution_context_source` 의 선택 근거 칸에 규칙 이름, 순위, 세 점수를 남긴다([ADR-20261015 / memory-eval-gate](ADR-20261015-memory-eval-gate.md)) |

**임베딩은 별도 서비스가 만들고 앱은 OpenAI 호환 `POST /v1/embeddings` 하나만 부른다.**
어느 제품(TEI, Ollama 등)을 띄울지와 그 주소는 운영 저장소가 정한다. 둘 다 이 API 를 받으므로 바꿔도 코드가 그대로다.
모델은 BGE-M3 로 시작하고, 구조가 같은 KURE-v1 과 우리가 지은 질문 50개에서 100개로 견준다. 질문 임베딩 지연이 예산을 넘으면 더 작은 모델로 내린다.
벡터 줄마다 모델 이름과 차원, 만든 글의 지문을 함께 저장한다. 모델이나 글이 바뀐 줄은 다시 만든다.

**임베딩이 실패해도 답한다.** 질문 임베딩이 시간 안에 오지 않거나 서비스가 응답하지 않으면 키워드 점수만으로 고른다. 그 실행의 선택 근거에 키워드만 쓴 규칙 이름이 남는다.

**민감 항목은 임베딩하지 않는다.** 본문을 암호문으로 저장하는 [ADR-055](ADR-055-민감-memory-본문은-저장할-때-암호화하고-key-는-환경-변수로-받는다.md) 의 취지와 어긋나기 때문이다. 민감 항목은 제목 키워드로만 찾는다.

**기억 본문을 외부 임베딩 API 로 보내지 않는다.** 임베딩 서비스는 자체 서버의 로컬 모델이다.

**벡터 DB 를 두지 않는다.** 가족 규모(수천 건 이하)에서는 애플리케이션의 전수 코사인으로 충분하다.

### 맥락

2026-10-15 사용자는 2단계를 「질문에 맞는 기억을 찾아 컨텍스트에 싣는 것」 부터 하기로 정했다(#310 댓글).
지금 색인 층은 질문과 무관하게 번호 순으로 담기고(`ContextAssembler`), `memory_search` 는 제목 부분 일치뿐이다. 본문에만 있는 사실은 찾지 못한다.

조사(agent memory 사례 조사, 2026-10-15)에서 얻은 근거다.

- 의미와 키워드를 합치는 하이브리드가 표준이다. Mem0(2026-04), Hindsight, Graphiti 가 그렇다. Hindsight 는 네 갈래를 RRF 로 합친다.
- 한국어 검색 수치가 단단한 공개 모델은 BGE-M3(MIRACL ko nDCG@10 69.9)와 KURE-v1 이다. 접두사가 필요 없고 MIT 라이선스다.
- 전수 코사인은 5,000건 × 1024차원에서 질의당 0.92ms, 벡터 20.5MB 였다(개발 머신 단일 스레드). 병목은 질문 임베딩이고, BGE-M3 급은 CPU 에서 0.12초에서 0.24초로 추정했다. 서버에서 다시 잰다.
- MySQL ngram FULLTEXT 는 토큰 크기를 서버 시작 때만 정하고 한 글자 검색어를 처리하지 못한다.
- Spring AI 의 ONNX 임베딩 모델은 평균 풀링만 해서 BGE-M3(CLS 풀링)에 그대로 쓰면 틀린다.

서버는 GPU 가 없고 메모리 여유가 크지 않다. BGE-M3 FP32 는 약 2.2GB 다.

### 대안 기각

- **앱 프로세스 안에서 ONNX Runtime 으로 임베딩한다.** 네이티브 메모리 2GB 이상과 크래시 위험이 앱과 묶이고, 모델을 바꿀 때 앱을 다시 배포해야 한다.
- **외부 임베딩 API 를 쓴다.** 가족의 기억 본문이 밖으로 나간다(2026-10-15 사용자 결정).
- **벡터 DB 나 pgvector 를 더한다.** 이 규모에서 얻는 것이 없고 운영할 저장소가 하나 는다.
- **MySQL ngram FULLTEXT 로 키워드 검색을 한다.** 토큰 크기를 바꾸려면 서버를 다시 띄워야 하고 한 글자 질의를 놓친다.
- **cross-encoder 재순위를 첫 구현에 넣는다.** CPU 에서 후보 20건에 12초에서 24초로 추정된다. 1차 검색 정밀도를 본 뒤 정한다.
- **개인 사실 구역도 질문으로 고른다.** 변경이 커지고, 오기억 노출을 줄이는 직접 수단은 대체 처리다. 대체가 노출을 줄이는지 본 뒤 정한다.
- **모델이 `memory_search` 를 부르게 둔다.** ADR-015 가 기록한 대로 도구를 부를지 판단하는 것이 기대만큼 되지 않는다.

### 결과

얻는 것

- 본문에만 있는 사실도 질문과 맞으면 도구 호출 없이 실린다.
- 「관련 기억 없음」 을 허용해, 질문과 무관한 기억이 본문으로 실리지 않는다.
- 임베딩 서비스가 죽어도 대화는 키워드 검색으로 이어진다.

감당할 것

- 자체 서버에 서비스가 하나 늘고 메모리를 쓴다. 운영 구성은 운영 저장소가 갖는다.
- 질문마다 임베딩 한 번만큼 첫 응답이 늦어진다. 지연 예산 안에서만 기다린다.
- 「질문과 관련된 기억」 구역이 바뀌면 지시문 지문이 바뀌어 prompt cache 적중이 떨어진다.
- 처음 켤 때 모든 항목을 임베딩하는 데 시간이 든다(5,000건에 수십 분으로 추정). 백그라운드로 채우고, 벡터가 없는 항목은 키워드 점수로만 경쟁한다.
- 민감 항목의 본문 의미 검색은 되지 않는다.

### 적용 범위

#310 2단계의 단계 1 이다.

| 무엇 | 내용 |
| --- | --- |
| 바뀌는 표 | 새 `memory_embedding`(항목 번호, 모델 이름, 차원, 글 지문, float32 벡터, 만든 시각). 항목이 지워지면 함께 지운다 |
| 바뀌는 클래스 | `ContextAssembler`(질문을 받는 조립, `MEMORY_SEARCH` 구역), `ContextSource`(`MEMORY_SEARCH`), 새 `EmbeddingClient` 와 그 OpenAI 호환 구현, 새 키워드 점수와 RRF 를 맡는 선별기, 임베딩을 채우는 백그라운드 작업, `MemoryTitleSearch` 를 대신하는 본문 검색, 조립을 부르는 `ChatTurnRunner` 와 `AgentRunner` 와 `ProactiveCheckInput` |
| 바뀌는 설정 | 임베딩 서비스 주소와 모델 이름과 지연 예산, 「질문과 관련된 기억」 구역의 건수와 글자 예산, 관련도 임계값 |
| 완료 조건 | 조립 측정의 recall@5 와 오기억 노출이 기준 파일보다 나빠지지 않고 놓침 범주의 recall@5 가 오른다. 서버에서 잰 질문 임베딩 p95 가 지연 예산 안이다. 임베딩 서비스를 끈 상태에서 키워드만으로 답하는 테스트가 있다. `memory_search` 의 권한 경계 테스트(`MemorySearchTest`, `MemorySearchMysqlTest`)가 그대로 통과한다 |

`memory_search` 결과가 관련도 순이 되면 지금의 번호 커서(`after_id`)로는 다음 페이지를 이을 수 없다. 페이지를 넘기는 방식은 단계 1 의 계획에서 도구 계약과 함께 정한다.
