## ADR-20261103 / memory-encryption: 모든 기억의 제목과 본문을 주인의 데이터 key 로 암호화하고, 그룹 key 를 `user_data_key` 의 줄로 둔다

- **status**: `accepted`
- Date: 2026-11-03
- [ADR-055](ADR-055-민감-memory-본문은-저장할-때-암호화하고-key-는-환경-변수로-받는다.md) 의 「민감 본문만 환경 변수 key 로 암호화한다」, 「제목과 일반 본문은 평문이다」, AAD 와 `content_key_id` 를 이 결정이 대체한다. 암호문 모양 `v1.<IV>.<암호문과 태그>` 와 AES-256-GCM 은 그대로다.
- [ADR-20261008 / data-encryption](ADR-20261008-data-encryption.md) 의 KEK, 데이터 key, 본문 세 층을 기억에도 쓴다. 그 ADR 의 「데이터 key 는 사용자마다 하나」 에 그룹마다 하나인 줄을 더한다.
- 스펙과 설계는 [`docs/features/memory/spec.md`](../../../docs/features/memory/spec.md), [`design.md`](../../../docs/features/memory/design.md) 가 갖는다.

### 결정

**`memory` 와 `memory_revision` 의 제목과 본문을 모두 주인의 데이터 key 로 암호화한다.**
`USER` 범위는 그 사용자의 데이터 key, `GROUP` 범위는 그 그룹의 데이터 key 다. 민감도와 상관없다.

| 무엇 | 값 |
| --- | --- |
| 암호화하는 컬럼 | `title`, `content`. 같은 데이터 key 로 따로 암호화한다 |
| key 번호 컬럼 | 새 컬럼 `data_key_id BIGINT NULL`(`user_data_key.id`). 비어 있으면 평문이거나 옛 key 의 줄이다 |
| AAD | `memory:<memory_id>:<title 또는 content>:<USER 또는 GROUP>:<주인 번호>`. revision 은 자기 `memory_id` 로 같은 값을 만든다 |
| 그룹 key | `user_data_key` 에 `group_id` 컬럼을 더한 줄. `user_id` 와 `group_id` 가운데 하나만 찬다. 감싸기 AAD 는 `user_data_key:group:<그룹 번호>` |
| 새 줄 | 빈 글로 넣고 같은 트랜잭션에서 번호로 AAD 를 만들어 암호문으로 고친다. DB 에 평문이 쓰이지 않는다 |
| 읽기 | 읽어 온 엔티티에 복호화 도구를 붙이고 제목이나 본문을 처음 꺼낼 때 푼다 |
| 이미 있는 줄 | 기동 작업이 줄마다 쓰기 잠금으로 다시 읽어 데이터 key 로 다시 쓰고, 같은 트랜잭션에서 다시 풀어 평문 해시를 비교한다. 실패한 줄은 번호만 로그에 남기고 기동을 잇는다 |

| 상태 | 동작 |
| --- | --- |
| KEK 가 없다(`required` 가 거짓) | 평문으로 저장하고 경고한다. 대화 메시지와 같다 |
| KEK 는 있는데 데이터 key 를 풀지 못한다 | 저장과 수정을 `MEMORY_ENCRYPTION_UNAVAILABLE`(409)로 거절한다. 평문으로 내려 저장하지 않는다 |
| 줄을 풀지 못한다 | 그 줄만 제목이 「읽지 못함」 이고 본문이 빈 글이다. 목록은 실패하지 않는다. 실행에 싣지 않는다 |
| 이관이 끝나지 않은 옛 key 줄 | PR1 동안은 옛 환경 변수 key 로 읽는다. 새로 옛 key 로 암호화하지 않는다 |

**이 결정을 배포한 뒤 직전 이미지로 되돌리지 않는다.** 직전 이미지는 `data_key_id` 를 몰라 제목과 본문의 암호문을 그대로 화면과 답에 낸다. 배포 직전에 DB 백업을 떠 두고, 문제가 생기면 앞으로 고친다.

### 맥락

일반 기억 23건은 평문이고, 민감 기억 28건은 환경 변수 key 로 암호화돼 있다(2026-11-03 운영 수치).
기억에는 다른 사용자의 개인 정보도 쌓인다. 제목에도 개인 정보가 들어간다.
사용자는 모든 기억을 암호화하고, 그다음 민감 구분을 없애기로 정했다(스펙 DECISION1 부터 DECISION5).
ADR-055 가 「모든 본문 암호화」 를 버린 까닭은 검색이 본문을 읽지 못한다는 것이었다. 지금 검색은 권한 조건만 SQL 로 걸고 점수는 앱에서 매긴다. 그래서 앱에서 풀면 검색이 그대로 돈다.

### 대안 기각

- **ADR-055 의 환경 변수 key 하나로 모든 기억을 암호화한다**: 코드가 가장 적다. 그러나 사용자 한 명의 기억만 지울 수 없고(crypto-shredding), KEK 와 다른 비밀 경로가 하나 더 남는다.
- **그룹 key 를 새 테이블에 둔다**: 테이블을 늘리지 않는다는 사용자 결정(2026-11-01)과 부딪힌다. 감싸기와 다시 감싸기, 캐시가 같은 줄 모양을 쓰므로 한 테이블로 충분하다.
- **그룹 기억을 그룹 관리자의 사용자 key 로 암호화한다**: 관리자가 바뀌거나 정리되면 그룹 기억을 읽지 못한다.
- **옛 `content_key_id` 에 데이터 key 번호를 적는다**: 글 key id 와 숫자 번호가 한 컬럼에 섞여, 이관 전후의 줄을 질의로 나눠 셀 수 없다.
- **AAD 를 주인으로만 묶는다(ADR-055 방식)**: 새 줄을 한 번에 쓸 수 있다. 그러나 같은 주인의 다른 기억이나 제목과 본문 사이로 암호문을 옮겨도 열린다. 대화 메시지는 줄 번호까지 묶는다.
- **AAD 에 revision 번호까지 묶는다**: revision 을 남길 때마다 지금 줄의 글을 다시 암호화해야 한다. 한 기억의 revision 끼리 바꿔 넣어도 같은 주인이 보던 글이라 얻는 것이 작다.
- **JPA 변환기(`AttributeConverter`)로 암호화한다**: 변환기는 줄 번호와 주인을 보지 못해 AAD 를 만들 수 없다.
- **이관을 SQL 마이그레이션으로 한다**: key 가 DB 밖에 있어 SQL 이 암호화하지 못한다.
- **임베딩 벡터도 암호화한다**: 원문이 아니고, 검색마다 모든 벡터를 풀어야 한다(스펙 DECISION6).

### 결과

- 얻는 것:
  - DB 덤프와 백업만으로는 기억의 제목과 본문을 읽지 못한다. revision 도 같다.
  - 사용자의 데이터 key 줄을 지우면 그 사용자의 기억도 함께 읽을 수 없게 된다.
  - 암호문을 다른 기억, 다른 컬럼, 다른 주인의 줄로 옮기면 풀리지 않는다.
- 감당할 것:
  - **KEK 를 잃으면 기억을 되찾을 수 없다.** 대화 메시지와 같다. KEK 백업은 운영 저장소가 맡는다.
  - 제목과 본문을 질의로 찾을 수 없다. 검색과 임베딩은 엔티티를 읽어 앱에서 푼다. 질의가 `title`, `content` 를 직접 고르면 암호문이 나간다. 틀려도 평문이 새지 않는 쪽으로 틀린다.
  - 새 기억은 넣고 고치는 쓰기 두 번이다.
  - 그룹 key 줄은 그룹 삭제 흐름이 없어 지우는 길이 없다. 그 흐름을 만들 때 함께 지운다.
  - 임베딩 벡터와 Hermes 의 실행 기록에 남는 글은 평문이다.
  - 제안 중복 키와 임베딩 지문은 제목과 본문 평문의 해시로 남는다. 짐작한 원문 전체가 맞는지 확인할 수 있다. 민감 구분을 없애는 다음 PR 에서 주인 key 로 만든 HMAC 으로 바꾼다(사용자 결정 2026-11-03).
  - 같은 기억 안에서는 지금 줄과 revision 사이, revision 끼리 암호문을 바꿔 넣으면 풀린다. 모두 같은 주인이 보던 글이다.
  - 옛 환경 변수 key 읽기는 이관을 운영에서 확인할 때까지 남는다.
