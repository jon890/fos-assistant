## ADR-20261015 / memory-eval-gate: 기억 선별을 바꾸기 전에 측정을 세 층으로 두고 조립 측정을 악화 금지 게이트로 건다

- **status**: `accepted`
- Date: 2026-10-15
- [ADR-20261008 / memory-facts](../../../docs/adr/ADR-20261008-memory-facts.md) 의 「예산과 길이 상한은 합성 측정과 운영 집계를 보고 고친다」 에 측정의 층과 게이트를 정한다.
  `execution_context_source` 에 선택 근거 칸을 더해 [ADR-071](ADR-071-여러-출처의-문맥은-항목마다-출처와-권한과-신선도를-지닌-묶음으로-조립한다.md) 의 「실행마다 실은 항목의 참조를 남긴다」 를 넓힌다. 제목과 본문을 남기지 않는다는 원칙은 그대로다.

### 결정

**#310 의 2단계(질문 기반 선별, 연결과 대체, 정비 루프)는 측정을 먼저 만든 뒤에 들어간다.** 측정은 세 층이다.

| 층 | 무엇을 재는가 | 모델 호출 | 언제 도는가 |
| --- | --- | --- | --- |
| 조립 측정 | 필요한 기억이 실렸는가(recall@k, 회수율), 옛 값과 방해 항목이 본문으로 실렸는가(오기억 노출), 권한 밖 항목이 묶음에 들었는가 | 없음 | 매 CI(`./gradlew test`) |
| 답 판정 | 실린 기억이 답에 반영됐는가, 기억이 있을 때와 없을 때 답이 어떻게 다른가 | 답 모델과 판정 모델 | 월 단위, 합성 입력만. 기본은 꺼짐 |
| 운영 집계 | 실린 뒤 읽혔는가, 실린 뒤 고쳐졌는가, 되돌렸는가, 한 번도 실리지 않은 항목, 제안 수락률 | 없음 | 운영 데이터베이스에서 읽기만 |

**조립 측정은 지금 값을 기준 파일로 커밋하고, 나빠지면 CI 를 실패시킨다.**
기준은 운영 기본값 모드의 전체 recall@5 와 전체 오기억 노출률 둘이다. recall@5 가 기준보다 낮거나 오기억 노출률이 기준보다 높으면 실패다.
기준 파일은 사례 묶음의 버전과 묶여 있다. 버전이 다르면 실패하고, 기준 파일을 다시 만드는 Gradle 속성을 안내한다.
권한 경계 노출 0 의 실패 조건은 그대로 둔다.

**조립 측정에 기준선 모드 두 개를 더한다.** 「기억 없음」 과 「전체 투입」 이다.
「전체 투입」 은 그 에이전트가 볼 수 있는 항목을 예산 없이 모두 본문으로 싣는다. recall 의 위쪽 끝과 오기억 노출의 위쪽 끝, 그때의 글자 수를 함께 보인다.
게이트는 이 두 모드에 걸지 않는다. 비교 기준으로 보고서에만 낸다.

**사례 묶음에 취향, 대체, 놓침 사례를 더한다.**
취향은 선호를 무시하면 답이 어긋나는 질문이다(PrefEval). 대체는 옛 값을 오답지로 둔 사례이고, 새 항목이 어느 옛 항목을 대체하는지 사례에 적는다(PersonaMem). 놓침은 지금 구조가 싣지 못하는 사례다. 본문에만 있고 제목에는 없는 사실, 예산에서 빠지는 항목이 여기 든다.

**`execution_context_source` 에 선택 근거를 남긴다.** 칸은 고른 규칙의 이름과 버전(`selector`), 그 `source` 안의 순위, 키워드와 의미와 최종 점수다.
지금 조립은 점수가 없으므로 이름과 순위만 채운다. 점수 칸은 질문 기반 선별이 들어올 때 채운다.
`selector` 는 enum 이 아니라 문자열 컬럼이다. 규칙이 늘거나 바뀌어도 스키마를 바꾸지 않는다(2026-10-16 사용자 결정, 판단의 분류를 컬럼이나 enum 으로 굳히지 않는다).
**사용 신호는 이 표의 칸으로 두지 않는다.** 이 표는 넣기만 하는 표이고, 「읽혔다」, 「고쳐졌다」, 「관련 없다고 눌렀다」 는 실행 뒤에 온다.
지금 기록에서 낼 수 있는 사용 신호(`MEMORY_READ` 줄, 판 기록, 되돌리기, 다시 생성)는 운영 집계 쿼리로 낸다. 사용자가 누르는 단추는 [ADR-20261015 / memory-maintenance](../../../docs/adr/ADR-20261015-memory-maintenance.md) 가 `decision_feedback_event` 의 사건으로 받는다.

**답 판정 하네스는 OpenAI 호환 chat API 를 직접 부른다.** Hermes 를 거치지 않는다.
주소, 답 모델, 판정 모델, 한 번 실행의 호출 상한이 설정값이고 key 는 환경 변수로 받는다. 설정이 없으면 돌지 않는다.
실제 판정 모델과 월 예산은 사용자가 정한다. 이 결정은 하네스의 틀과 대역 모델 테스트까지만 정한다.
판정 질문은 자유 서술 점수가 아니라 「예, 아니오」 질문으로 쪼갠다(PrefEval, Know/Act).

**측정에 쓰는 글은 모두 지어낸 것이다.** 실제 가족 대화와 실제 기억은 어느 층에도 넣지 않는다. 운영 집계는 기록 칸만 읽고 제목과 본문 칸을 읽지 않는다.

### 맥락

2026-10-15 사용자는 2단계 방향을 「기억 사이의 연결과 질문에 맞는 기억을 찾아 싣는 것」 으로 바꾸고, 그 판단을 수치로 하라고 정했다(#310 댓글).
지금 측정은 조립 측정 하나이고 실패 조건은 권한 경계 노출뿐이다. 개인 사실 구역을 켜자 본문 회수율은 8.3% 에서 81.3% 로, 오기억 노출률은 25% 에서 100% 로 올랐다(#323). 두 숫자가 같이 움직이는데 어느 쪽도 막지 않는다.

조사(agent memory 사례 조사, 2026-10-15)에서 근거를 얻었다.

- 검색 지표와 답의 품질은 어긋난다. LongMemEval 표 3 에서 키를 바꾸면 Recall@10 은 0.783 에서 0.814 로 오르는데 GPT-4o 정확도는 0.676 에서 0.512 로 내린다. 조립 측정만으로 답의 품질을 보증하지 못한다.
- 기억이 있어도 쓰이지 않는 것이 큰 실패 원인이다. Know/Act 는 Mem0 실패 722건을 이해 53.0%, 검색 30.7%, 적용 16.2% 로 나눴다. 「실렸는가」 와 「쓰였는가」 를 따로 재야 한다.
- 기억이 작으면 전체 투입이 강한 기준선이다. Mem0 논문 표 2 에서 J 는 전체 투입 72.90, Mem0 66.88 이다. 대신 p95 지연은 17.1초 대 1.44초다.
- 기억 전용 운영 지표를 공개한 제품은 찾지 못했다. 우리가 정의한다.

### 대안 기각

- **답 판정을 CI 에 넣는다.** 모델 호출이 흔들리고 돈이 든다. 공개 저장소의 CI 에 key 를 두게 된다. 월 단위로 따로 돌린다.
- **답 판정을 Hermes 를 거쳐 돌린다.** 실행 공간과 profile 이 있어야 하고 판정과 무관한 도구 호출이 섞인다. Hermes 의 시스템 지시는 재현하지 못하지만, 기억이 있을 때와 없을 때의 차이를 보는 데는 직접 호출로 충분하다.
- **사용 신호를 `execution_context_source` 의 칸으로 둔다.** 넣기만 하는 표에 나중에 값을 고쳐 쓰게 된다. 지금 이 표는 같은 위치에 두 번 쓰면 기본 키 위반으로 드러나게 만들어져 있다.
- **게이트를 범주마다 건다.** 범주마다 사례가 5개에서 8개라 사례 하나가 비율을 12%p 에서 20%p 까지 움직인다. 전체 값 두 개로 시작한다.
- **게이트 없이 보고서만 낸다.** 2단계의 완료 조건이 「지금보다 나빠지지 않음」 인데, 지금 값을 어디에도 고정하지 않으면 비교할 대상이 없다.

### 결과

얻는 것

- 질문 기반 선별, 연결, 대체가 들어올 때마다 같은 사례로 앞뒤를 비교한다. 나빠지면 머지 전에 드러난다.
- 운영에서 어느 규칙이 어떤 순위로 무엇을 실었는지 실행마다 남아, 지표 변화를 규칙 변화에 잇는다.
- 판정 모델과 예산만 정하면 답 판정을 바로 돌릴 수 있다.

감당할 것

- **사례를 더하거나 고치면 기준 파일도 같은 PR 에서 다시 만든다.** 그 PR 의 작성자가 다시 만들고, PR 본문에 앞뒤 값과 바뀐 까닭을 적는다. 리뷰는 값이 나빠진 경우 그 까닭이 사례 추가 때문인지 조립 변경 때문인지 본다. 절차는 [`docs/features/memory.md`](../../../docs/features/memory.md) 의 「기준 파일」 이 갖는다.
- 조립 측정의 recall@k 는 모델이 보는 순서로 센다. 지금 조립은 질문을 보지 않으므로 이 값은 「질문과 무관하게 앞에 놓인 것」 의 비율이다. 질문 기반 선별과 견줄 출발점으로만 읽는다.
- 판정기를 믿기 전에 사람이 대조한 표본으로 일치도를 한 번 잰다. 판정 모델이나 판정 질문이 바뀌면 이전 결과와 견주지 않는다.
- 운영 집계는 관찰 비교다. 「참고한 기억」 이 있는 답과 없는 답의 다시 생성 비율 차이는 무작위 배정이 아니라 인과를 말하지 못한다.

### 적용 범위

#310 2단계의 단계 0 이다. 사례 묶음과 지표와 게이트, 기준 파일 절차는 [`docs/features/memory.md`](../../../docs/features/memory.md) 의 「Memory 회수 측정」 이, 선택 근거 칸은 [`backend/docs/data-schema.md`](../data-schema.md) 의 「execution_context_source」 가 갖는다.
