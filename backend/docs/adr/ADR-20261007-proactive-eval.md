## ADR-20261007: 먼저 살펴보기 루프는 결정적 provider 로 실제 서비스를 replay 해 측정하고 안전 경계만 CI 를 막는다

- **status**: `accepted`
- Date: 2026-10-07

### 맥락

문제 찾기([ADR-093](ADR-093-문제-찾기는-살펴보기-결과의-문제-후보로-받고-control-plane-이-근거와-중복을-결정적으로-검사한다.md)), 가치 판단([ADR-20261007 / value-evaluation](../../../docs/adr/ADR-20261007-value-evaluation.md)), 행동 정책([ADR-20261007 / autonomy-policy](ADR-20261007-autonomy-policy.md)), 판단 피드백([ADR-20261007 / decision-feedback](ADR-20261007-decision-feedback.md))은 각자 단위 시험을 가진다.
그러나 단계를 이었을 때 올바른 문제를 고르고 알맞은 때에 행동하거나 침묵하는지는 어느 시험도 보지 않는다.
판단 provider 를 바꿨을 때 품질, 지연, 비용, 실패가 어떻게 달라지는지 견줄 자리도 없다.

CI 는 실제 모델과 Hermes 를 부를 수 없다. 같은 입력에 같은 결과가 나와야 실패를 믿을 수 있다.
문제 후보와 정책 판정을 보이는 화면이 아직 없어 후보 하나와 사용자 반응 하나를 직접 잇는 실제 표본은 없다.

### 결정

**실제 서비스를 그대로 쓰고 바깥 둘만 대역으로 둔다.**
대역 Hermes 가 fixture 의 결과 블록을 답하고, 결정적 provider 가 fixture 에 기록한 판단을 낸다.
살펴보기 turn, 문제 찾기, 판단 검사, 행동 정책, 자동 실행 시작, 판단 피드백 export 는 운영 코드다. 시험은 `ProactiveEvalGateTest` 이고 계약은 [`backend/proactive-eval.md`](../../../docs/backend/proactive-eval.md) 가 갖는다.

**provider 는 `DecisionProvider` port 의 구현으로만 바꾼다.**
같은 fixture 를 판단 기록 둘(`fixture-a`, `fixture-b`)과 실패 넷(준비 안 됨, timeout, 예외, 형식 오류)으로 다시 돌린다.
문제 찾기 결과가 provider 와 상관없이 같은지 함께 확인한다.

**안전 경계만 CI 를 막는다.**
승인이 필요한 후보의 자동 실행, 쓰기 허용 에이전트의 자동 실행과 읽기 전용 지시가 빠진 자동 실행, 오래되거나 확신이 낮은 근거의 자동 실행, 자동 실행 결과의 노출을 센다. 하나라도 0 이 아니면 실패한다.
시나리오마다 나온 행동 수준은 fixture 의 snapshot 과 비교해 회귀를 잡는다.

**품질은 비교만 하고 승자를 정하지 않는다.**
important miss, low-value promotion, duplicate suggestion, useful silence, ranking 일치, fallback, 호출 수, 기록한 지연과 비용을 provider 마다 나란히 보고서에 남긴다.
판단(순서)과 최종 행동 수준을 따로 센다.

### 버린 대안

- **순수 함수만 이어 붙여 replay 한다**: 빠르지만 `AutonomyPolicyService` 가 입력을 모으는 방식, 실행 키, 자동 실행 경로, export 의 묶기를 다시 쓰게 된다. 운영 코드와 어긋나도 시험이 모른다.
- **실제 모델을 CI 에서 부른다**: 비용과 비밀이 필요하고 같은 입력에 같은 답을 보장하지 못한다. 실패가 결함인지 모델의 흔들림인지 가리지 못한다.
- **품질 지표에 기준값을 걸어 CI 를 막는다**: 정답이 사람이 정한 합성 값뿐이라 기준값이 근거가 없다. 판단 기록 하나를 승자로 굳히게 된다.
- **평가 전용 표와 API 를 만든다**: 지금은 측정할 실제 표본이 없다. 판단 피드백 export 와 가치 평가의 저장된 입력으로 충분하다.

### 감당할 것

- 판단 기록은 합성이다. 실제 모델의 품질을 말해 주지 않는다. 실제 모델을 견주려면 같은 상태를 실제 adapter 로 replay 해 그 판단을 fixture 에 옮겨야 한다.
- 지연과 비용은 provider 마다 적은 기록값이다. 실제 시간과 사용량은 운영의 실행 기록에서 읽는다.
- 행동 정책은 `URGENCY` 를 자동 실행 조건으로 보지 않는다. 그래서 급하지 않은 후보도 비용이 낮다고 판단되면 읽기 전용 자동 실행을 받는다. 결과를 사용자에게 바로 알리지 않으므로 끼어들지는 않지만, 실행 자리와 비용은 쓴다.
- provider 가 실패하면 모든 후보가 `IGNORE` 다. 안전하지만 그 살펴보기의 중요한 후보도 놓친다.
- 시나리오 하나가 살펴보기 turn 을 실제로 돌리므로 시험 하나가 수십 초 걸릴 수 있다.
