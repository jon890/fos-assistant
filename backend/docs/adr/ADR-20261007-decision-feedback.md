## ADR-20261007 / decision-feedback: 판단 피드백은 제안 열쇠에 덧붙이는 사건으로 남기고 반응은 읽을 때 정한다

- **status**: `accepted`
- Date: 2026-10-07

### 맥락

문제 후보([ADR-093](ADR-093-문제-찾기는-살펴보기-결과의-문제-후보로-받고-control-plane-이-근거와-중복을-결정적으로-검사한다.md)), 가치 판단([ADR-20261007 / value-evaluation](../../../docs/adr/ADR-20261007-value-evaluation.md)), 행동 정책([ADR-20261007 / autonomy-policy](ADR-20261007-autonomy-policy.md))은 각자 자기 줄을 남긴다.
그러나 사용자가 그 결과에 어떻게 반응했는지, 실행이 어떻게 끝났는지는 각 기능의 상태 칸에 흩어져 있고 지난 상태는 덮어쓴다.
사용자마다 무엇을 가치 있게 여기는지 나중에 견주려면 「상황 → 후보 → 판단 → 정책 → 사용자 반응 → 실행 결과」 를 다시 읽을 수 있어야 한다.

지금 사용자에게 실제로 보이는 제안은 넷이다. 에이전트가 제안한 할 일, 에이전트가 제안한 Memory, 커넥터 쓰기의 승인 줄, 살펴보기의 다섯 칸 보고다.
문제 후보와 행동 정책의 `SURFACE`, `ASK_APPROVAL` 은 아직 화면이 없다.

### 결정

**사건 표 `decision_feedback_event` 하나에 덧붙이기만 한다.**
줄 하나가 제안 하나(`subject_key`)의 사건 하나다. 열쇠는 지금 화면의 `itemKey` 와 같은 모양이다(`follow_up:<공개 식별자>`, `memory:<번호>`, `connector_action:<공개 식별자>`, `proactive_check:<번호>`, `autonomy_decision:<번호>`).
같은 제안의 뒤따르는 사건은 같은 열쇠를 쓴다. 이 열쇠가 같은 결정의 후속 결과를 잇는 correlation key 다.

**사건 종류는 실제 화면과 API 흐름에 있는 것만 둔다.**
`SURFACED`, `ACCEPTED`, `DISMISSED`, `POSTPONED`, `EDITED`, `APPROVED`, `REJECTED`, `EXECUTION_SUCCEEDED`, `EXECUTION_FAILED` 아홉이다.
무응답(무시)은 사건이 아니다. 승인 줄의 만료와 실행 결과를 모르는 `UNKNOWN` 도 사건을 남기지 않는다.

**원문을 복제하지 않는다.**
할 일 제목, Memory 본문, 커넥터 인자와 결과, 모델이 쓴 글을 담는 칸이 없다.
판은 해시나 판 번호(`subject_version`)로, 고친 내용은 칸 이름(`changed_fields`)으로만 남긴다.
상황, 후보, 판단, 정책은 이미 있는 줄을 번호로 가리킨다. 제안을 낸 실행은 트리 루트(`origin_execution_id`)로 남겨 살펴보기 트리와 잇는다.

**반응은 저장하지 않고 읽을 때 정한다.**
replay 읽기 모델이 사건을 `ACCEPTED`, `DECLINED`, `DEFERRED`, `NO_RESPONSE`, `NOT_SURFACED` 로 읽는다. 규칙에는 버전을 둔다.
규칙을 고치면 지난 사건을 다시 읽으면 된다. 저장한 꼬리표를 고칠 일이 없다.

**잘못된 학습을 막는 규칙을 읽기 규칙에 둔다.**
무응답은 표본에서 뺀다. 거절은 그 제안 하나의 일회성 반응이고, 지금 화면의 숨기기는 미루기로 읽는다. 첫 반응을 나중의 그만둠이 덮지 않는다.
오래 가는 선호는 Memory 에만 남는다([ADR-012](ADR-012-memory-는-사람이-승인한-것만-남는다.md), [ADR-20261007 / memory-remember](../../../docs/adr/ADR-20261007-memory-remember.md)). 판단 피드백이 그 근거로 읽는 것은 사용자가 받아들인 Memory 제안뿐이다. 이 기록은 Memory 도 억제 규칙도 바꾸지 않는다.
예외는 하나다. 살펴보기 발견의 「관심 없음」 은 같은 점검 대화의 digest 기간 안에서만 같은 주제를 내린다([ADR-20261008 / check-finding-reaction](../../../docs/adr/ADR-20261008-check-finding-reaction.md)).

**기록은 사용자의 것이다.**
사용자 줄을 지우면 함께 지운다(FK `ON DELETE CASCADE`). 대화를 지우면 그 대화에 묶인 사건과, 그 사건이 가리키는 제안의 다른 사건을 같은 트랜잭션에서 지운다.
마지막 사건이 보관 기간(기본 365일)보다 오래된 제안은 하루 한 번 사건을 모두 지운다. 읽기 모델은 요청자의 것만 내고, 관리자도 남의 기록을 읽지 못한다.

**기록이 사용자의 동작을 막지 않는다.**
부르는 쪽 트랜잭션이 커밋된 뒤 새 트랜잭션으로 남긴다. 되돌려진 동작의 사건은 남지 않고, 기록이 실패해도 동작은 그대로다.
대화 삭제의 정리만 예외다. 지운 대화에 사건이 남지 않도록 같은 트랜잭션에서 지운다.

### 버린 대안

- **각 기능 표에 반응 칸을 더한다**: 상태를 덮어써 순서와 중간 반응(고친 뒤 받아들임)을 잃는다. 기능마다 칸이 달라 한 번에 읽지 못한다.
- **저장할 때 꼬리표(좋음, 싫음)를 붙인다**: 규칙을 고치면 지난 줄을 다시 써야 한다. 무응답을 싫음으로 굳히는 실수가 저장 단계에서 영구가 된다.
- **사용자 반응 시점의 제안 글과 문맥을 함께 저장한다**: 사용자가 대화를 지워도 학습 기록에 글이 남는다. 같은 글을 두 곳에 두지 않는다.
- **`attention_event` 를 넓혀 쓴다**: 그 표는 화면 지표이고 같은 상태의 사건을 한 줄로 합친다. 반응 순서를 남기지 못하고 보관 기간도 화면 지표에 맞춰져 있다.
- **새 개인화 모델을 지금 학습한다**: 표본이 없고, 문제 후보와 사용자 반응을 잇는 화면도 아직 없다. 「지금 원했는가」 의 표본 값만 읽기 모델에 둔다.

### 감당할 것

- 문제 후보와 정책 판정은 아직 사용자에게 보이지 않는다. 그래서 후보 하나와 사용자 반응 하나를 직접 잇는 표본은 아직 없다. 지금은 같은 살펴보기의 결정 안에 함께 묶일 뿐이다.
- 커밋 뒤에 남기므로 서버가 그 사이에 멈추면 사건 하나를 잃을 수 있다.
- 대화를 지운 뒤의 사건은 넣기 전에 대화 줄을 공유 잠금으로 읽어 버린다. 그 잠금 때문에 기록과 대화 삭제가 같은 대화에서 잠깐 서로를 기다릴 수 있다.
- 사용자가 직접 더한 할 일과 직접 고친 일은 제안이 아니므로 남기지 않는다. 「제안을 무시하고 나중에 사용자가 같은 일을 했다」 는 아직 읽지 못한다.
