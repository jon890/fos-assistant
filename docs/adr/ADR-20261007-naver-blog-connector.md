## ADR-20261007 / naver-blog-connector: 네이버 블로그 커넥터는 사용자의 Chrome 에 CDP 로 붙고, 임시저장은 승인한 뒤 백그라운드 작업으로 돈다

- **status**: `accepted`
- Date: 2026-10-07
- 바뀐 부분: 연결 칸의 CDP 주소와 CDP 주소마다의 작업 잠금은 [ADR-20261007 / user-browser](ADR-20261007-user-browser.md) 가 바꿨다. 커넥터는 바인딩 주인의 「내 브라우저」 에 Control Plane 중계로 붙고, 잠금은 블로그 아이디마다 하나다
- **결정**: 네이버 블로그 임시저장을 범용 커넥터 `naver-blog` 로 만든다. 블로그 전용 profile 과 전용 에이전트를 두지 않고, 사용자가 연결을 자기 에이전트에 붙인다([ADR-083](ADR-083-커넥터는-사용자가-한-번-연결하고-자기-에이전트에-여럿-붙여-그-에이전트가-도구를-직접-부른다.md)).

  | 항목 | 정한 것 |
  | --- | --- |
  | 자리 | `hermes/connectors/naver-blog/`. TypeScript 묶음 파일을 Bun 으로 실행한다([ADR-084](../../hermes/docs/adr/ADR-084-gmail-typescript-filters.md) 와 같은 방식) |
  | 계정에 닿는 길 | 사용자가 로그인해 둔 Chrome 의 원격 디버깅(CDP) 주소와 블로그 아이디를 연결 칸으로 받는다. 네이버 비밀번호와 쿠키는 받지 않는다. CDP 주소는 그 브라우저를 조작하는 권한이라 비밀 칸이다 |
  | 운영 값 | 없다. `operator_env` 와 `operator_secrets` 를 두지 않는다 |
  | 사진 | 대화에 첨부한 사진만 쓴다. 에이전트가 `vision_analyze` 로 읽고, 커넥터는 파일을 읽어 바이트를 CDP 로 편집기의 파일 입력에 넣는다. 사진 저장소(S3)와 아이폰 업로드 경로는 두지 않는다 |
  | 임시저장 | `save_draft` 하나를 승인받는다. 승인한 호출은 초안과 사진과 로그인을 확인한 뒤 분리된 작업 프로세스를 띄우고 작업 번호를 돌려준다. 결과는 읽기 도구 `draft_job` 이 알린다 |
  | 승인 | `WRITE`, `"outbound": false`, 상시 허락을 줄 수 있다. 임시저장 글은 그 계정 안에만 있고 지울 수 있다 |
  | 발행 | 도구가 없다. 발행 확인 단추를 누르는 코드도 없다 |
  | 미리보기 | 커넥터가 초안을 검사하고 HTML 을 돌려준다. 에이전트가 `artifact_write` 로 결과물 폴더에 쓴다. 사진은 같은 대화의 첨부 주소를 상대 경로로 부른다. 스티커는 에이전트가 `artifact_write` 의 주소 방식으로 네이버의 스티커 그림을 같은 폴더에 받아 두고 HTML 이 그것을 부른다 |
  | 문체 | 커넥터 스킬은 절차와 가상 예시만 갖는다. 사람마다의 문체와 카테고리 기준은 그 사용자의 비공개 profile 스킬로 둔다 |

- **맥락**: 지금은 블로그를 운영 저장소가 만든 전용 profile 이 맡는다. 그 profile 은 Control Plane 이 관리하는 도구 계약 밖에 있어 관리 화면에서 도구를 다시 저장하면 거절되고(#222), 터미널로 Python 스크립트를 돌려 네이버 편집기를 조작한다.
  사용자는 그 기능을 커넥터로 바꿔 블로그 주인의 기본 에이전트에 붙이고 전용 profile 을 정리하기로 정했다(2026-10-06). 사진은 대화에 첨부하고 에이전트가 읽어 글을 쓴다.
  아래 네 가지는 코디네이터를 거쳐 사용자가 정했다(2026-10-07).
  - 사진은 대화 첨부만 쓴다. 대화 첨부가 한 번에 30장까지라([ADR-020](../../backend/docs/adr/ADR-020-사진은-공유-디렉터리에-두고-에이전트가-파일로-읽는다.md)) 글 하나의 사진이 들어간다
  - 승인은 한 번이고 실제 입력은 백그라운드 작업으로 돈다
  - 사진은 경로가 아니라 바이트로 Chrome 에 넘긴다
  - 미리보기에는 실제 사진이 보여야 한다

  코드와 문서에서 확인한 제약이 결정의 모양을 정했다.
  - 승인한 호출은 대시보드가 MCP 서버를 새로 띄워 60초 안에 끝나야 한다([커넥터 연결](../../backend/docs/flow.md) 의 「커넥터 승인」). 사진 스무 장 넘게 올리고 스티커, 지도, 태그를 넣은 뒤 저장까지 60초 안에 끝난다는 실측이 없다
  - Hermes 가 쥔 MCP 연결의 도구 호출 제한 시간은 기본 300초다([`hermes/docs/hermes-contract.md`](../../hermes/docs/hermes-contract.md)). 읽기 도구가 50초쯤 기다리는 것은 들어간다
  - Chrome 은 Hermes 컨테이너 밖에서 돈다. 커넥터가 보는 첨부 경로를 Chrome 은 같은 경로로 보지 못한다. `DOM.setFileInputFiles` 는 브라우저 쪽 경로만 받는다
  - 첨부 경로에는 사용자 디렉터리 키(64자리 16진수)가 든다([ADR-091](ADR-091-사진-첨부는-사용자별로-저장하고-실행-공간에는-그-사용자만-붙인다.md)). 승인 카드는 그 덩어리를 가리고, 상시 허락을 닫은 도구는 가려진 인자가 있으면 승인하지 못한다([ADR-065](ADR-065-외부로-나가는-도구는-상시-허락을-닫는-선언을-둔다.md))
  - `artifact_write` 는 base64 를 받지 않고 파일 하나가 5MB 까지다([ADR-028](../../backend/docs/adr/ADR-028-결과물은-사용자의-대화-폴더에-mcp-도구로-쓴다.md)). 결과물 화면은 `img-src 'self' data:` 만 허용한다
  - 결과물 파일과 첨부는 같은 대화 주소 아래의 형제 경로다. 둘 다 그 대화의 주인만 받는다
  - 지금 블로그 profile 의 미리보기는 초안 폴더에 `stickers/<코드>.png` 가 있을 때만 스티커 그림을 그리는데, 그 파일을 놓는 단계가 없어 늘 이름표로 보였다(사용자 보고, 2026-10-07). 결과물 화면은 외부 그림을 막는다

- **대안 기각**:
  - **블로그 전용 profile 을 Control Plane 도구 계약에 넣는다(#222 의 첫 안)**: 전용 에이전트를 두지 않는다는 사용자 결정과 맞지 않는다. 터미널로 스크립트를 돌리는 구조도 그대로 남는다.
  - **커넥터를 운영 저장소에 둔다**: CDP 주소와 블로그 아이디를 사용자가 넣으면 운영 값 없이 돈다. 네이버 블로그는 공개된 서비스이고 계정은 사용자 자신의 브라우저 세션이다. [ADR-064](../../hermes/docs/adr/ADR-064-범용-커넥터는-이-저장소의-hermes-connectors-에-두고-저장소가-유지보수한다.md) 의 「여기 두는 커넥터」 에 든다.
  - **사진 저장소(S3)와 아이폰 업로드를 커넥터에 넣는다**: 연결에 S3 key 를 더 담아야 하고, 내려받은 사진을 에이전트가 읽을 자리를 실행 공간마다 새로 정해야 한다. 대화 첨부가 같은 일을 한다.
  - **승인한 호출 안에서 끝까지 기다린다**: 60초를 넘기면 대시보드가 504 로 끊고 줄이 `UNKNOWN` 이 된다. 탭에 반쯤 들어간 글이 남는다.
  - **커넥터 manifest 에 실행 제한 시간 칸을 두고 플랫폼의 60초를 늘린다**: Control Plane, 대시보드 plugin, 실행 중 줄 정리를 함께 바꿔야 한다. 다른 커넥터의 승인 대기와 동시 실행 한도를 길게 붙잡는다. 이 커넥터 하나를 위해 공통 계약을 바꾸지 않는다.
  - **입력 단계마다 도구를 나눠 따로 승인받는다**: 글 하나에 승인 카드가 다섯 장 넘게 나온다.
  - **사진 경로를 Chrome 쪽 경로로 바꿔 넘긴다**: 두 경로의 대응을 운영 값으로 받아야 한다. 범용 커넥터에 운영 값을 둘 수 없다.
  - **미리보기 사진을 커넥터가 줄여 HTML 에 data URL 로 넣는다**: 도구 결과가 모델 입력에 들어가므로 사진 바이트가 매 turn 의 토큰이 된다. 순수 JavaScript 로 JPEG 를 줄이는 의존성도 늘어난다.
  - **`artifact_write` 가 첨부를 결과물 폴더로 복사하게 넓힌다**: 사진마다 도구 호출 한 번이 들어 서른 장이면 서른 번이다. 같은 사진이 디스크에 두 벌 남는다.
  - **상시 허락을 닫는다**: 첨부 경로의 사용자 디렉터리 키가 가려져 승인할 수 없다. 사진 디렉터리를 식별자로 선언해도 `/` 가 든 값은 식별자 모양이 아니다([ADR-089](ADR-089-커넥터는-식별자-인자를-선언하고-승인-카드는-그-값을-길이로-가리지-않는다.md)). 임시저장은 계정 밖으로 나가지 않고 지울 수 있어 Gmail 의 초안 만들기와 같은 분류다.

- **결과**:
  - 얻는 것:
    - 블로그 주인이 기본 에이전트 하나에서 Memory 와 대화 맥락을 가진 채 글을 쓰고 임시저장한다. 전용 profile 과 그 profile 의 승인 끄기 설정이 필요 없어진다.
    - 승인 카드에 제목과 카테고리와 태그와 본문 전체가 글로 보인다. 사진은 본문 안에서 몇 번째 사진인지와 파일 이름으로 보인다.
    - 미리보기가 사진 바이트를 복사하지 않는다. 채팅에서 이미 받은 사진을 브라우저 캐시로 다시 쓴다.
  - 감당할 것:
    - **승인의 성공은 작업을 시작했다는 뜻이다.** 임시저장의 성공과 실패는 작업 상태 도구로만 안다. 스킬이 승인 결과를 받으면 바로 작업 상태를 보게 한다. 저장 단추를 누른 뒤 저장 수가 늘었는지 확인하지 못하면, 끊김이나 시간 초과도 포함해 작업은 `unknown` 으로 끝나고 다시 저장하지 않는다. 반대로 저장 수가 늘어난 것을 확인한 뒤 편집기 상태를 다시 읽다가 실패하면 성공으로 두고 읽은 내용 없이 알린다.
    - 작업 상태는 커넥터가 도는 컨테이너의 임시 디렉터리에 파일로 둔다. 승인한 호출을 실행하는 대시보드와 Hermes 가 쥔 MCP 서버가 같은 파일 시스템을 본다는 전제다. 배포 뒤 왕복으로 확인한다.
    - **바이트를 넣는 방식을 SmartEditor 가 받는지는 실제 계정으로만 확인된다.** 대역 검사는 CDP 명령의 순서만 본다. 받지 않으면 사진 단계가 실패하고 수동 등록용 묶음으로 돌아간다.
    - CDP 주소에 닿는 쪽은 그 브라우저의 네이버 계정으로 글을 쓰고 지울 수 있다. 이 커넥터는 그 주소를 비밀 칸으로 받을 뿐 중계의 접근 통제는 운영이 갖는다.
    - 커넥터가 사진 디렉터리로 받은 경로의 파일을 읽는다. 속은 모델이 다른 파일을 가리키지 못하게 확장자, 파일 머리의 이미지 서명, 크기, 링크 아님을 확인하고 그 디렉터리 밖을 거절한다. 다른 사용자의 첨부 디렉터리를 가리키는 것은 [ADR-20261007 / connector-owner-attachments](ADR-20261007-connector-owner-attachments.md) 이 막는다. 바인딩 설치가 주인의 첨부 디렉터리를 env 로 넣고, 커넥터는 그 아래의 사진만 읽는다.
    - 스티커 그림은 Control Plane 의 주소 방식 허용 호스트에 네이버 스티커 그림 호스트를 넣어야 보인다. 운영 설정 하나가 늘고, 그 호스트에서 받는 그림은 Control Plane 이 크기와 확장자를 검사한다. 스티커 그림 주소의 모양은 네이버가 바꿀 수 있고 그때는 이름표로 돌아간다
    - 미리보기는 결과물 파일이 `<폴더>/index.html` 한 단계 아래에 있고, 첨부 파일 이름이 `<첨부 번호>.<확장자>` 라는 플랫폼 모양에 기댄다. 그 모양은 [결과물 파일](../../backend/docs/flow.md) 의 「같은 대화의 첨부 사진을 부를 때」 가 갖는다.
    - 브라우저에 로그인하는 일은 사람이 한다. 로그인이 풀리면 작업이 `login_required` 로 끝난다.
    - 한 브라우저에서 작업은 하나씩 돈다. 앞 작업이 끝나기 전의 저장 요청은 거절한다. 잠금은 CDP 주소마다 둔다.
    - 작업 프로세스는 대시보드가 정리하는 프로세스 묶음 밖에서 돌도록 새 세션으로 띄운다. 작업이 살아 있는지는 작업 프로세스가 5초마다 작업 파일에 쓰는 갱신 시각으로 본다. pid 로 프로세스를 찾지 않으므로 대시보드와 Hermes 의 MCP 서버가 PID 네임스페이스를 달리해도 살아 있는 작업을 끝내지 않는다. 그 대신 작업 프로세스가 죽었다는 판정이 최대 30초 늦어진다.

- **적용 범위**: `hermes/connectors/naver-blog/`, [네이버 블로그 커넥터](../../hermes/connectors/naver-blog/README.md), [결과물 파일](../../backend/docs/flow.md) 의 첨부 참조 계약. 블로그 전용 profile 의 정리 순서는 운영 저장소가 갖는다.
