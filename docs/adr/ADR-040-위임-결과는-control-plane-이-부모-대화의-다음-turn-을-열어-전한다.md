## ADR-040: 위임 결과는 Control Plane 이 부모 대화의 다음 turn 을 열어 전한다

- **status**: `accepted`
- Date: 2026-09-30
- [ADR-017](ADR-017-무엇을-할지는-hermes-가-정하고-control-plane-은-경계만-갖는다.md) 의 「결과는 모델이 `agent_status` 로 다시 묻는다」 를 대체한다. 조율 주체와 경계에 대한 ADR-017 의 결정은 그대로 둔다.

### 결정

**맡긴 자식 실행이 끝나면 Control Plane 이 부모 대화의 다음 turn 을 열어 그 결과를 전한다.**
부모는 맡긴 뒤 기다리지 않는다. 남은 일을 계속하고, 할 일이 끝나면 turn 을 마친다.

| 항목 | 정한 것 |
| --- | --- |
| 깨우는 대상 | 대화 turn 의 루트 실행이 직접 맡긴 위임 실행. 자식이 다시 맡긴 손자 실행은 깨우지 않는다 |
| 깨우는 결과 | `SUCCEEDED`, `FAILED`(기동 정리의 `ORPHANED` 포함). `CANCELLED` 는 깨우지 않는다. 사용자나 부모가 멈춘 것이다 |
| 부모 turn 이 도는 중 | 결과를 쌓아 두고, 그 대화의 turn 이 끝난 뒤 쌓인 결과를 모아 한 번 깨운다 |
| 이미 받은 결과 | 부모가 `agent_status` 나 `agent_stop` 으로 끝난 결과를 받았으면 전한 것으로 적고 깨우지 않는다 |
| 연속 상한 | 사용자 질문 하나 뒤로 자동 turn 은 10번까지다. 넘으면 깨우지 않고 알림 줄만 남긴다. 사용자가 다시 질문하면 새로 센다 |
| 화면 | 알림 줄(`SYSTEM` 메시지)을 먼저 남기고 그 아래 부모의 답을 붙인다. 열린 대화 창은 대화 단위 SSE 로 받는다 |

### 맥락

ADR-017 은 `agent_delegate` 가 기다리지 않고 실행 번호를 돌려주게 했다.
Hermes 의 MCP 도구 호출에는 제한 시간(기본 300초)이 있고, 기다리는 도구는 실제로 끊겼기 때문이다([`hermes/delegation.md`](../hermes/delegation.md) 의 「기다리는 도구는 실제로 끊긴다」).
결과를 언제 다시 물을지는 모델에게 맡겼다.

2026-09-30 운영에서 가계부 에이전트에게 맡긴 일의 결과를 받으려고 부모가 `agent_status` 를 27번 연달아 불렀다.
3분 2초가 걸렸고, 부를 때마다 LLM 호출이 한 번씩 들었다.
도구 호출 자체는 수십 ms 였고 시간과 비용은 모두 모델의 반복 판단에서 나왔다.

Hermes 에는 도는 실행에 지시를 더하는 `POST /v1/runs/{run_id}/steer` 가 있다([`hermes/runs-api.md`](../hermes/runs-api.md) 의 「도는 실행에 지시를 더하는 `steer`」).
`steer` 는 run 이 `running` 일 때만 받는데, 위임 결과는 대개 부모 turn 이 끝난 뒤에 도착한다. 그때는 넣을 run 이 없다.
그래서 부모를 깨우는 것은 새 turn 을 여는 것이다.
처음에는 그런 API 가 없다고 적었고 2026-10-01 에 정정했다. 결정은 그대로다.
부모 turn 이 도는 중에 도착한 결과를 `steer` 로 넣을지는 따로 정한다.
실행 기록과 대화를 Control Plane 이 이미 가지므로 완료를 알아채고 turn 을 여는 자리도 Control Plane 이다.

### 대안 기각

- **`agent_status` 가 끝날 때까지 기다렸다 답한다(long polling)**: 도구 제한 시간 안에서만 기다릴 수 있어, 오래 걸리는 일에서는 결국 여러 번 부른다. 부를 때마다 LLM 호출이 든다.
- **모두 끝났을 때 한 번만 깨운다**: 부모가 앞선 결과로 다음 일을 맡기는 조율을 하지 못한다. 먼저 끝난 결과를 기다리게 된다.
- **Hermes 내장 `delegate_task` 로 맡긴다**: 같은 profile 안에서만 된다. 가계부처럼 다른 profile 의 에이전트에게는 맡기지 못한다.
- **짧게 기다렸다가 그 안에 끝나면 바로 준다**: 짧은 일에서 turn 하나를 아끼지만 기다리는 동안 부모가 멈춘다. 먼저 이 방식 없이 쓰고 판단한다.

### 결과

- 얻는 것
  - 기다리는 동안 부모의 LLM 호출이 없다. 오래 걸리는 일이어도 비용은 깨울 때마다 한 번이다.
  - 부모가 여러 자식을 맡기고 다른 일을 이어 가며, 결과가 도착하는 대로 다음 일을 맡길 수 있다.
- 감당할 것
  - 사용자가 보내지 않은 turn 이 대화에 생긴다. `chat_message` 에 `SYSTEM` 역할이 생기고 화면이 그것을 구분해야 한다.
  - 깨울 결과와 연속 횟수는 DB 에 둔다. 대화 잠금은 JVM 메모리에만 있어 서버가 다시 뜨면 사라지므로, 기동할 때 쌓인 결과를 다시 확인한다.
  - 자동 turn 도 보통 turn 과 같은 비용이 실행 기록에 남는다. 상한 10번이 비용의 상한이다.
  - 서버 한 대를 전제로 한다. 대화 잠금과 깨우기 판정이 같은 JVM 에 있다.
