## ADR-022: 다시 생성과 수정은 같은 session 에 판으로 쌓는다

- **status**: `accepted`
- **결정**: 다시 생성은 대화의 마지막 답에만, 수정은 대화의 마지막 사용자 메시지에만 연다.
  둘 다 같은 Hermes session 에 새 turn 으로 보내고,
  새 메시지가 이전 메시지를 `replaces_message_id` 로 가리킨다.
  화면은 가장 최근 판을 보이고 이전 판으로 넘겨 볼 수 있게 한다.

### 맥락

ChatGPT 는 어느 메시지든 고치고, 고친 지점부터 대화를 새로 나눈다.
그러려면 모델이 기억하는 대화를 그 지점으로 되감아야 한다.

이 저장소는 대화의 맥락을 갖지 않는다.
`conversation.hermes_session_id` 가 가리키는 Hermes session 이 갖는다.
Hermes session 을 특정 지점에서 나누거나 되감는 경로가 있는지는 확인하지 못했다.

그래서 되감지 않는 쪽으로 정한다.
다시 생성하면 모델은 앞선 답을 본 채로 다시 쓴다.
수정하면 모델은 고치기 전 질문과 그 답을 본 채로 고친 질문에 답한다.
**그 사실을 숨기지 않는다.** 실행 입력의 `instructions` 에 이것이 다시 생성이거나 수정이라고 적는다.

### 대안 기각

- **수정하면 그 지점까지를 담은 새 대화를 만든다.**
  앞 대화를 새 session 에 다시 넣어야 한다.
  원래 session 이 가진 도구 결과와 요약은 옮길 수 없어 맥락이 같지 않고, 입력 토큰이 그만큼 는다.
- **Hermes session 을 나누는 방법을 먼저 조사한다.**
  이 기능 하나 때문에 화면 개선 전체가 조사를 기다리게 된다.
  나눌 방법이 확인되면 이 ADR 을 대체한다.
- **마지막 turn 밖에서도 연다.**
  중간 메시지를 고쳐도 모델은 그 뒤의 대화를 모두 기억한다.
  사용자는 고친 지점부터 새로 시작했다고 믿지만 실제로는 그렇지 않다.

### 결과

- 얻는 것: Hermes 를 고치지 않고 다시 생성과 수정을 쓴다. 이전 판이 사라지지 않는다.
- 감당할 것:
  - 판마다 실행 한 번이다. 비용이 판 수만큼 든다.
  - 같은 대화에서 도는 실행이 있으면 다시 생성과 수정을 거절한다.
    둘이 같은 session 에 겹쳐 들어가면 어느 답이 어느 질문의 것인지 모델도 모른다.
  - 첨부가 달린 메시지는 수정 대상이 아니다. 다시 생성은 원래 메시지의 첨부를 그대로 쓴다.
