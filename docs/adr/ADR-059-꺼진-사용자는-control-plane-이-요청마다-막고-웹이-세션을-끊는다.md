## ADR-059: 꺼진 사용자는 Control Plane 이 요청마다 막고 웹이 세션을 끊는다

- **status**: `accepted`
- **결정**: Control Plane 은 웹 토큰을 받는 요청마다 그 메일 주소의 허용 목록 줄이 꺼져 있는지 확인한다.
  꺼져 있으면 사용자를 찾거나 만들지 않고 401 과 오류 코드 `ACCESS_REVOKED` 로 답한다.
  웹은 그 코드를 받으면 세션 쿠키를 지우고 로그인 화면으로 보낸다.
- **맥락**: 허용 목록은 로그인할 때만 확인했다.
  웹은 세션에서 메일 주소를 꺼내 요청마다 짧은 수명의 토큰을 새로 만들고, Control Plane 은 그 서명만 검증했다.
  그래서 관리자가 사용자를 꺼도 그 사용자의 웹 세션이 만료될 때까지 모든 사용자 API 가 열려 있었다.
  웹 세션의 기본 수명은 30일이다.
  서비스 토큰 발급은 ADR-056 에서 따로 막았지만 그것은 열린 API 가운데 하나였다.
- **대안 기각**:
  - 웹이 세션을 읽을 때마다 로그인 판정을 다시 묻는다: 판정이 웹에만 있으면 웹 토큰을 받는 경로를 Control Plane 이 스스로 지키지 못한다.
    요청마다 왕복도 하나 늘어난다.
  - 허용 목록에 켜진 줄이 있어야만 통과시킨다: 로그인 판정과 답이 같아지지만, 줄 없이 생긴 사용자가 모두 막힌다.
    줄은 화면에서 지워지지 않고 꺼지기만 하고, 웹은 로그인 판정을 통과한 세션에만 토큰을 만든다.
    줄이 없는 주소가 이 경로에 닿으려면 서명 key 를 가져야 하고, key 를 가진 쪽은 켜진 주소로도 토큰을 만들 수 있다.
    얻는 보안이 없는데 검사용 사용자 전부에 허용 목록 줄을 만들어야 한다.
  - 403 으로 답한다: 화면이 권한 없음으로 읽어 오류만 보이고 세션이 남는다.
    Spring Security 가 토큰 없는 요청에 내는 403 과도 구분되지 않는다.
  - 기존 `UNAUTHENTICATED` 401 을 그대로 쓴다: 그 코드는 세션이 없을 때 웹이 스스로 만드는 답과 같다.
    세션을 지울지 판단하려면 꺼진 것만 가리키는 코드가 있어야 한다.
  - `app_user` 와 `allowed_person` 을 한 쿼리로 합쳐 읽는다: 두 표는 외래 키 없이 메일 주소로만 이어지고 소유하는 패키지가 다르다.
    허용 목록 조회는 유일 키를 쓰는 조회 한 번이라 합쳐서 줄어드는 비용이 작다.
    같은 트랜잭션에서 차례로 읽는다.
  - 판정을 몇 초 동안 캐시한다: 사용자가 둘뿐인 지금은 조회 비용이 문제가 되지 않는다.
    캐시를 두면 끈 뒤에도 그 시간만큼 열려 있다.
- **결과**:
  - 얻는 것: 관리자가 끄면 그 사용자의 다음 요청부터 막힌다. 다시 켜면 다시 로그인해 쓴다.
    꺼진 주소로는 `app_user` 도 새로 생기지 않는다.
  - 감당할 것:
    - 판정은 요청이 시작될 때 한 번만 한다. 이미 열린 SSE 응답과 오래 걸리는 요청은 끝날 때까지 이어진다.
      이미 시작한 실행도 멈추지 않는다.
    - 줄이 없는 사용자는 이 검사가 막지 않는다. 사용자를 막으려면 줄을 지우지 않고 끈다.
    - 웹 토큰을 받는 경로만 해당한다. profile 토큰과 agent 토큰 경로는 그대로다.
      서비스 토큰은 ADR-056 대로 주인이 켜져 있는지 따로 확인한다.
    - 요청마다 허용 목록 조회가 한 번 늘어난다.
    - 관리자가 자기 줄을 끄면 그 자리에서 막힌다. 다른 관리자가 없으면 화면으로는 다시 켜지 못한다. 이 결정 전에도 다음 로그인부터는 같았다.
- **적용 범위**: `ControlPlaneJwtFilter` 가 해석하는 경로 전체. 화면 쪽 처리는 [`web/docs/code-architecture.md`](../../web/docs/flow.md) 의 「꺼진 사용자의 세션」 이 갖는다.
