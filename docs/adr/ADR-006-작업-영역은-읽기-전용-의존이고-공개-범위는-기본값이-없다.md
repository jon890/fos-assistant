## ADR-006: 작업 영역은 읽기 전용 의존이고 공개 범위는 기본값이 없다

- Status: Accepted
- Date: 2026-09-17

### 맥락

가족 구성원마다 여러 일을 오가며 이 비서를 쓴다.
공부, 집안일, 구직처럼 서로 다른 영역마다 지켜야 할 규칙과 말투가 다르고,
그 규칙을 코드가 아니라 별도 저장소 `fos-agents` 의 `AGENTS.md` 로 관리하고 있다.

`fos-agents` 의 ADR-019 는 그 저장소가 외부 agent runtime 과 메시지 전달 채널에
직접 의존하지 않기로 결정했다. 다만 이 결정에는 예외가 있다.

> agent skill의 정본과 노출 경로는 이 결정의 범위가 아니다.
> 이는 현재 사용하는 agent 도구와의 호환 구조이며,
> 실행 runtime의 cron·메시지·HUD 의존성과 구분한다.

즉 `fos-agents` 는 자신의 정의를 어떤 실행기가 읽어 가는 것은 허용하지만,
그 실행기의 코드나 API 계약을 자신이 알거나 그것에 맞춰 바뀌는 것은 허용하지 않는다.
의존 방향이 뒤집히면 이 예외가 무너진다.

또한 이 마운트가 담을 디렉터리 중에는 건강 기록이나 구직 전략처럼
가족 중 한 사람만 보아야 하는 것이 있다. 공개 범위를 정하지 않고 등록할 방법을 열어 두면
그 실수 한 번이 곧 다른 구성원에게 그 내용을 보여주는 사고가 된다.

### 결정

의존은 `fos-assistant → fos-agents` 방향으로만 흐른다.

- `fos-assistant` 는 `fos-agents` 의 디렉터리를 읽기 전용으로 마운트해 `AGENTS.md` 만 읽는다.
- `fos-agents` 에는 어떤 코드도 넣지 않는다. 그 저장소가 이 비서나 Hermes 를 알 필요가 없다.
- 마운트 경로는 홈서버 compose 에서 정하고, 컨테이너 안에서도 읽기 전용으로 연다.

작업 영역(workspace)의 공개 범위(`visibility`)는 기본값을 두지 않는다.

- 등록할 때 `PRIVATE` 과 `FAMILY` 중 하나를 반드시 명시해야 하고, 생략하면 등록이 거절된다.
- 마운트를 훑어 디렉터리를 자동으로 영역으로 등록하지 않는다. 관리자가 하나씩 등록한다.
- 남의 개인 영역은 조회와 실행 모두 존재하지 않는 것과 같은 오류로 응답한다.
  존재 자체를 알리는 것도 누출이기 때문이다.

### 거절한 대안

- 마운트 아래 디렉터리를 스캔해 자동으로 영역을 등록하는 방식은 편리하지만,
  새 디렉터리가 하나 생기는 순간 그 내용이 기본으로 가족 전체에 열리거나,
  반대로 기본이 `PRIVATE` 이어도 다음 등록자가 이유 없이 그대로 두면 같은 위험이 남는다.
  등록을 명시적인 관리자 동작으로 두면 실수의 자리가 그 한 번의 입력으로 좁혀진다.
- `fos-agents` 에 실행 API 나 웹훅을 두고 이 비서가 그것을 호출하는 방식은
  `fos-agents` 가 실행 계약을 갖게 되어 ADR-019 의 결정과 충돌한다.

### 결과

- 영역을 늘릴 때마다 관리자가 `POST /api/v1/admin/workspaces` 로 코드와 공개 범위를 명시해야 한다.
- `fos-agents` 저장소는 이 기능을 위해 한 줄도 바뀌지 않는다.
- 마운트가 읽기 전용이므로, 이 비서가 그 저장소의 내용을 고치거나 되쓰는 경로는 애초에 없다.
