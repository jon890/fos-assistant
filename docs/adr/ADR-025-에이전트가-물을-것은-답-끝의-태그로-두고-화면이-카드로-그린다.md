## ADR-025: 에이전트가 물을 것은 답 끝의 태그로 두고 화면이 카드로 그린다

- **status**: `accepted`
- **결정**: 에이전트가 사용자에게 물을 것이 있으면 답 끝에 `<ask>` 태그 블록을 둔다.
  web 이 그 블록을 선택 카드로 그리고, 고른 답을 평범한 다음 메시지로 보낸다.
  형식 안내는 Control Plane 이 대화 실행마다 instructions 의 Memory 뒤에 붙인다.

### 맥락

블로그 초안처럼 사용자에게 사실을 확인받아야 이어 갈 수 있는 일이 있다.
지금까지는 에이전트가 답 글에 질문을 쓰고, 사용자가 그 답을 입력창에 직접 타이핑했다.
무엇을 답해야 하는지 글에서 찾아야 했고, 선택지가 있어도 매번 글로 옮겨 적어야 했다.

Hermes 는 run 을 멈추고 사람을 기다리는 수단으로 명령 승인(`waiting_for_approval`)을 가진다.
그러나 그것은 위험한 명령을 허락하는 자리이고, 내용을 묻는 자리가 아니다.
묻는 일은 대화 한 번의 일이라 run 을 멈출 필요가 없다.

### 대안 기각

- **run 을 멈추고 답을 기다린다.** 기다리는 동안 동시 실행 한도와 스레드 한 칸을 잡는다.
  시간이 지나면 거절되고 성공으로 끝나 실패가 드러나지 않는다. 묻는 일에 그 비용을 쓸 까닭이 없다.
- **Control Plane 의 MCP 서버에 `ask_user` 도구를 둔다.** 도구 호출은 인자가 schema 로 정해져 형식이 가장 덜 깨진다.
  그러나 질문을 저장하고 화면이 가져가는 경로가 따로 필요해 작업이 두세 배로 는다. 태그로 부족하다는 것이 드러나면 옮긴다.
- **답 끝에 JSON 코드 블록을 둔다.** 한국어 본문 안의 따옴표와 줄바꿈을 escape 해야 하고, 한 글자만 틀려도 전체를 읽지 못한다.
  태그는 escape 가 거의 필요 없고 한 줄씩 읽어 어긋난 곳을 찾기 쉽다.
- **형식을 필요한 스킬에만 적는다.** 모든 실행에 안내가 실리지 않는다.
  그러나 형식을 그리는 것이 이 저장소라, 형식이 바뀌면 스킬 저장소도 함께 고쳐야 한다.

### 결과

- 얻는 것:
  - 모든 에이전트가 같은 형식으로 묻고, 사용자는 고르거나 직접 입력해 한 번에 답한다
  - 기다리는 상태가 없어 시간 제한과 그 실패가 없다. 카드를 무시하고 입력창에 답해도 된다
- 감당할 것:
  - 대화 실행마다 형식 안내 약 640자가 instructions 에 실린다. Memory 의 글자 상한과는 따로 센다
  - 모델이 형식을 어길 수 있다. 어긋난 블록은 카드 대신 원문을 코드 블록으로 보인다
  - 태그는 에이전트가 만든 믿지 않는 글이다(ADR-009). HTML 로 읽지 않고 정해 둔 줄 모양만 글자로 골라낸다
  - 도구가 읽어 온 남의 글에 `<ask>` 블록이 있고 에이전트가 그것을 그대로 옮기면, 남이 만든 입력 칸이 그려진다.
    입력한 글은 에이전트에게 보내는 메시지로만 가고, 화면이 그 글로 다른 일을 하지 않는다.
    글로 된 질문과 받는 곳이 같아 새로 열리는 길은 없다고 보고 받아들인다. 가족이 쓰는 비서라 비밀번호를 묻는 일이 없다
  - 안내 문구(`AskFormat`)와 화면의 파서(`web/src/lib/ask.ts`)가 같은 형식과 길이 상한을 말해야 한다
