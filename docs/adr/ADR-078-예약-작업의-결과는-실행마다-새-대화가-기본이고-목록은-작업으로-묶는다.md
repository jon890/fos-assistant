## ADR-078: 예약 작업의 결과는 실행마다 새 대화가 기본이고 목록은 작업으로 묶는다

- **status**: `accepted`
- **매일 깨우기 예외**: 아래 대화 방식과 `conversation.task_id` 는 `task.kind = TURN` 에만 적용한다.
  `CHECK` 는 [ADR-085](ADR-085-매일-깨우기는-예약-작업을-다시-쓰고-다섯-칸-보고를-지금-화면에-올린다.md)의 사용자별 점검 대화를 이어 쓰며 작업으로 묶지 않는다.
- **결정**: 예약 작업은 결과를 남길 대화 방식(`conversation_mode`)을 갖는다. 기본은 `NEW_PER_RUN` 으로, 발화마다 새 대화를 연다. 사용자가 고르면 `SINGLE` 로 작업 하나에 대화 하나를 두고 발화마다 그 대화에 turn 을 더한다.
  작업이 만든 대화는 `conversation.task_id` 로 작업을 가리킨다. 대화 목록은 이 칸이 찬 대화를 날짜 묶음에서 빼고 작업 이름 아래로 묶어 보인다.
- **맥락**: 발화마다 같은 대화를 쓰면 Hermes session 이 계속 길어져 실행마다 입력 토큰이 는다. 압축에 기대게 된다.
  발화마다 새 대화를 쓰면 입력이 늘지 않지만, 대화 목록이 작업 결과로 찬다. 사용자는 직접 연 대화를 찾기 어렵다.
  사용자가 2026-10-04 에 기본은 새 대화, 목록은 작업으로 묶는 쪽을 골랐다. 앞 결과를 알아야 하는 작업만 `SINGLE` 을 고른다.
- **대안 기각**:
  - **늘 `SINGLE`.** 월 1회 작업도 1년이면 열두 번의 답이 한 session 에 쌓인다. 비용이 늘고 모델이 지난 달의 변경안을 이번 달 것과 섞는다.
  - **작업 대화를 목록에서 숨기고 작업 화면에서만 보인다.** 승인 요청 알림이 그 대화로 데려가는데, 목록에서는 그 대화가 보이지 않아 다시 찾아갈 길이 없다.
  - **대화에 작업을 가리키는 칸 대신 작업 실행 줄로만 잇는다.** 목록을 그릴 때마다 실행 줄을 조인해야 하고, `SINGLE` 대화는 실행 줄이 여럿이라 묶음 기준이 흔들린다.
- **결과**:
  - 얻는 것:
    - 직접 연 대화와 작업이 만든 대화가 목록에서 섞이지 않는다.
    - 작업 대화도 보통 대화라 승인 카드, 중지, 다시 생성, 이어서 묻기가 그대로 된다.
  - 감당할 것:
    - `conversation` 에 칸이 하나 는다. 작업을 지워도(보관) 대화와 그 칸은 남는다.
    - `chat` 은 작업 이름을 모른다. 목록이 작업 이름을 보이려고 `chat` 에 port 를 두고 작업 패키지가 구현한다([ADR-068](../../backend/docs/adr/ADR-068-최상위-패키지는-한-방향-층-순서를-따르고-거꾸로-가는-의존은-port-나-이동으로-끊는다.md)).
    - `SINGLE` 대화에 사용자가 직접 질문하면 그 turn 이 도는 동안 발화가 기다린다.
