## ADR-052: Memory 는 collection, 종류, 꺼내는 방식, 민감도, 판, 출처를 가진다

- **status**: `accepted`
- **결정**: 새 표 계층을 만들지 않고 `memory` 표에 칸을 더한다.
  한 줄이 속한 `collection`, 종류(`entry_type`), 에이전트가 닿는 방식(`retrieval`), 민감도(`sensitivity`), 판 번호(`revision`), 출처 한 개(`source_type`, `source_ref`, `source_date`)다.
  고치거나 지울 때 그 전의 값을 `memory_revision` 에 남긴다. 지운 항목도 마지막 값이 남는다.
  **민감 항목(`SENSITIVE`)은 항상 싣는 방식(`ALWAYS`)으로 둘 수 없다.** 저장할 때 거절한다.
  이미 있는 Memory 는 모두 `core` collection 의 `MEMORY` 이고 판은 1 이다. `always_inject` 가 참이던 줄은 `ALWAYS`, 거짓이던 줄은 `SEARCH` 가 된다.
- **맥락**: 지금의 Memory 는 짧은 사실 한 줄만 담고, 모든 에이전트가 요청자의 Memory 전체를 받는다.
  사용자에 대한 지식은 이 표 밖에도 있다. 다른 서비스가 판을 쌓아 가며 고치는 긴 문서, 날짜가 붙은 원문 기록, 영역별 현재 상태 정리가 그렇다.
  같은 사실이 여러 곳에 다른 날짜로 적혀 있어 어느 것이 지금 값인지 사람이 견줘야 했다.
  이것을 Memory 로 모으려면 표가 네 가지를 더 말할 수 있어야 한다.
  - 어느 영역의 지식인가. 건강 기록을 커리어 에이전트가 받을 까닭이 없다
  - 긴 문서와 원문을 사실 한 줄과 구분할 수 있는가. 문서는 이름으로 찾고 판을 쌓는다
  - 언제 무엇으로 바뀌었는가. 다른 서비스가 문서의 판 번호를 자기 결과의 기준으로 쓴다
  - 어디서 온 값인가. 들여온 항목을 묶어 되돌리려면 출처가 있어야 한다
- **대체된 부분**: [ADR-055](ADR-055-민감-memory-본문은-저장할-때-암호화하고-key-는-환경-변수로-받는다.md) 가 「민감 항목의 본문은 아직 평문으로 저장한다」 를 대체한다. 민감 본문은 암호화해 저장한다. [ADR-015](ADR-015-memory-는-층을-나눠-싣는다.md) 가 둔 `always_inject` 한 칸을 `retrieval` 세 값으로 넓힌다. 층을 나눠 싣는다는 결정은 그대로다.
- **대안 기각**:
  - 문서와 출처를 다른 표로 둔다: 범위 판정, 승인 상태, 에이전트 접근 판정을 표마다 다시 만들어야 한다. 판정이 두 벌이 되면 한쪽이 빠진다. 한 표에 두고 종류 칸으로 나눈다.
  - `collection` 을 enum 으로 둔다: 그룹마다 쓰는 영역이 다르고 더할 때마다 배포해야 한다. 문자열 key 로 두고 목록은 `memory_collection` 이 갖는다.
  - `always_inject` 를 그대로 두고 보관 여부를 칸 하나 더 둔다: 불 값 둘은 「항상 싣는데 보관함」 같은 뜻 없는 조합을 만든다. 값 셋 가운데 하나로 둔다.
  - 판을 남기지 않고 `updated_at` 만 둔다: 다른 서비스가 「그 문서의 몇째 판으로 분석했는가」 를 적어 둔다. 시각으로는 그 대조를 할 수 없다.
  - 지울 때 판까지 지운다: 잘못 지운 것을 되살릴 길이 없고, 들여온 묶음을 되돌린 흔적도 사라진다.
  - 중요도, 신뢰도, 항목별 접근 목록, 항목 사이의 관계 표: 지금 그것으로 판정하는 자리가 없다. 쓰는 자리가 생길 때 더한다.
  - 민감 항목도 항상 싣게 허용하고 조립할 때 거른다: 항상 층은 고른 항목의 본문이 곧 프롬프트다. 저장할 때 막으면 조립이 한 번 틀려도 본문이 나가지 않는다.
- **결과**:
  - 얻는 것: 영역마다 에이전트 접근을 정할 수 있다([ADR-053](ADR-053-에이전트는-허용된-collection-의-memory-만-받는다.md)). 긴 문서와 원문이 같은 권한 판정 아래 들어온다. 모든 수정과 삭제의 전 값이 남는다.
    기존 줄의 뜻이 바뀌지 않는다. `core` 를 받는 에이전트는 이 결정 앞과 같은 글을 받는다.
  - 감당할 것: **지워도 본문이 `memory_revision` 에 남는다.** 완전히 없애는 길은 따로 만들어야 한다. 그때까지 화면의 삭제는 「목록과 주입에서 뺀다」 는 뜻이다.
    `always_inject` 를 한 배포 동안 남긴다. 쓸 때마다 `retrieval` 과 맞추고 읽을 때는 `retrieval` 만 본다. 옛 판으로 되돌린 동안 옛 코드가 고친 줄은 두 칸이 어긋나므로, 다시 올리기 전에 `always_inject` 로 `retrieval` 을 맞춘다. 맞출 것은 [`data-schema.md`](../data-schema.md) 의 「옛 판으로 되돌렸다가 다시 올릴 때」 가 갖는다.
    판에는 그때의 종류, 문서 이름, 승인 상태까지 남기고 출처는 남기지 않는다. 본문이 같은 수정도 판을 하나 만든다.
    민감 항목의 본문은 아직 평문으로 저장한다. 그래서 암호화를 넣기 전에는 민감 항목을 들여오지 않는다.
- **적용 범위**:

  | 칸 | 값 | 뜻 |
  | --- | --- | --- |
  | `collection` | 소문자 key. 기본 `core` | 영역. 그룹의 목록은 `memory_collection` 이 갖는다 |
  | `entry_type` | `MEMORY`, `DOCUMENT`, `SOURCE` | 사실 한 줄, 이름으로 찾는 긴 글, 출처로 남긴 원문 |
  | `document_key` | `DOCUMENT` 만 | 같은 주인과 collection 안에서 하나다 |
  | `retrieval` | `ALWAYS`, `SEARCH`, `ARCHIVE` | 본문을 매번 싣는다, 제목만 색인에 싣는다, 색인에도 싣지 않는다 |
  | `sensitivity` | `NORMAL`, `SENSITIVE` | 민감 항목은 허용받은 에이전트만 받는다 |
  | `revision` | 1 부터 | 고칠 때마다 1 씩 는다. 승인과 거절은 올리지 않는다 |
  | `source_type`, `source_ref`, `source_date` | 비어도 된다 | 출처 한 개. 다른 항목을 가리킬 때는 `memory:<번호>` |

  `SOURCE` 와 `ARCHIVE` 는 색인에 싣지 않고 `memory_read` 로도 읽지 못한다. 사람이 화면에서 찾아 볼 때만 읽는다.
- **다음**: collection 탭, 문서 편집과 판 이력, 출처 표시, 다른 서비스가 문서를 읽는 경로는 화면과 API 를 넓힐 때 만든다.
  민감 항목 본문의 암호화와 완전 삭제는 민감 항목을 들여오기 전에 정한다. 검색(BM25, 벡터)은 항목 수가 색인 층의 자리를 넘을 때 「에이전트에게 보이는 항목을 고르는 질의」 뒤에 붙인다.
  `always_inject` 칸은 다음 배포에서 지운다.
