## ADR-20261101 / artifact-vault: 사용자가 보관한 결과물은 chat_artifact 의 보관 사본 행에 암호화해 두고 대화와 따로 남긴다

- **status**: `accepted`
- Date: 2026-11-01
- 이슈 #530 의 2026-10-13 사용자 결정(앱 안의 사용자별 암호화 보관함, 보관 주인은 대화 요청자, 대화를 지워도 보관본 유지, 사용자당 5GiB)을 구현 범위로 옮긴다. 2026-11-01 사용자 결정(테이블은 최대한 늘리지 않고 기존 테이블을 쓴다)에 따라 새 테이블을 만들지 않는다.
- [ADR-027](ADR-027-에이전트가-만든-html-은-대화별-폴더에-두고-스크립트-없이-보인다.md) 의 「결과물은 대화와 함께 사라진다」 에 사용자가 고른 보관본이라는 예외를 더한다.

### 결정

**보관본은 `chat_artifact` 의 행이다.** `vault_user_id` 가 채워진 행이 보관 사본이고, `message_id` 는 비어 있다.
컬럼은 `vault_user_id`, `vault_key_id`, `vault_body`, `vault_fingerprint` 네 개를 더한다. 평문 바이트 수는 기존 `byte_size` 를 쓴다.

**사진과 스타일을 부르는 HTML 은 묶음으로 보관한다(PR 2).** 묶음은 사용자가 고른 파일의 뿌리 행 하나와, 그 뿌리를 `vault_bundle_id` 로 가리키는 보관 사본 행들이다. 새 테이블 없이 컬럼 `vault_bundle_id` 하나만 더한다.
파일마다 행 하나라 본문을 파일 하나씩 풀고, 미리보기는 부르는 파일 하나만 읽는다.

| 규칙 | 내용 |
| --- | --- |
| 주인 | 대화 요청자다. 보관은 대화 주인만 하고, 읽기와 지우기는 `vault_user_id` 인 사용자만 한다. 남의 번호와 없는 번호는 같은 `ARTIFACT_NOT_FOUND` 로 답한다. 에이전트 주인에게는 자동으로 보이지 않는다 |
| 암호화 | 본문은 주인의 사용자별 데이터 key 로 암호화해 `vault_body` 에만 둔다([ADR-20261008 / data-encryption](../../backend/docs/adr/ADR-20261008-data-encryption.md) 와 같은 경로). 사진은 바이트라 `crypto` 의 `BinaryCipher` 로 암호화한다. chat 모듈은 key 원문을 받지 않고 암호문과 key 번호만 받는다. 암호화가 꺼져 있거나 key 를 쓸 수 없거나 태그가 맞지 않으면 평문으로 두지 않고 일부도 주지 않는다. 암호문의 자리는 주인, 대화 번호, 경로, 지문으로 묶고 묶음 안 파일은 뿌리 행 번호까지 묶어, 다른 줄이나 다른 묶음으로 옮기면 풀리지 않는다 |
| 대상 | HTML, CSS, 사진(PNG, JPEG, GIF, WebP)을 보관한다. 형식은 결과물을 내주는 형식과 같다. HTML 과 CSS 가 부르는 파일은 묶음에 함께 넣는다 |
| 묶음 | 제한된 parser 가 본문을 고쳐 쓰지 않고 불러오는 자리(사진, 스타일, 프레임, `url()`, `@import`, `image-set()`)의 주소만 꺼내 그 파일의 폴더 기준으로 푼다. 링크(`<a href>`)와 돌지 않는 스크립트는 보지 않는다. 부르지 않는 파일은 넣지 않는다 |
| 묶음 거절 | 외부 주소, `data:` 주소, `/` 로 시작하는 주소, 대화 폴더 밖 주소, 빠진 파일, 받지 않는 형식(글꼴 등), 상한 초과는 묶음 전체를 거절한다. 일부만 보관하지 않는다. 링크를 따라 다른 대화의 파일을 가리키면 빠진 파일과 같다 |
| 상한 | 파일 하나 5MiB, 묶음 하나 100MiB, 1,000파일이다(`assistant.artifact-vault.*`). 한 번에 파일 하나만 메모리에 올리고 넣은 행은 영속성 컨텍스트에서 바로 뗀다. 동시에 도는 보관은 2개까지이고 넘으면 기다리지 않고 `ARTIFACT_VAULT_UNAVAILABLE` 로 거절한다 |
| 원본 만료와의 경쟁 | 장벽을 두지 않는다. 훑을 때 파일마다 SHA-256 을 남기고, 저장하는 트랜잭션 안에서 다시 읽어 비교한다. 사이에 원본 정리가 지웠거나 바뀌었으면 묶음 전체를 거절하고 트랜잭션이 되돌린다. 보관은 바이트를 데이터베이스로 옮기는 일이라 끝난 뒤에는 원본이 지워져도 상관없다 |
| 중복 | 같은 사용자의 같은 대화, 경로, 본문 바이트는 한 건이다(`vault_fingerprint` 유일). 묶음의 지문은 부르는 파일마다 경로와 SHA-256 을 더해 만들고, 부르는 파일이 없으면 한 파일의 지문과 같다. 묶음 안 파일의 지문은 묶음 지문과 경로로 만든다. 내용이 바뀌면 새 보관본이다. 지문은 사용자 사이에 비교하지 않는다 |
| 용량 | 사용자당 5GiB(`assistant.artifact-vault.user-quota-bytes`)다. 넘으면 새 보관만 `ARTIFACT_VAULT_FULL` 로 거절하고 자동 삭제하지 않는다. 확인과 저장은 사용자별 잠금 안의 한 트랜잭션이다. Control Plane 이 한 인스턴스라는 전제이며 늘면 데이터베이스 잠금으로 바꾼다 |
| 대화 삭제 | 대화를 지워 정리해도 보관 사본 행은 남는다. 정리는 `vault_user_id` 가 빈 행만 지운다. 원본 정리와 만료 표시 작업도 보관 사본 행을 건드리지 않는다 |
| 지우기 | 본문이 행에만 있어 본문을 지우면 읽을 수 없고 재시작으로 되살아나지 않는다. 별도 파일이 없어 파일과 DB 가 어긋나는 일도 없다. 개별 파일 삭제를 사용자 key 삭제로 처리하지 않는다. 묶음은 뿌리 번호로만 지우고 안의 파일 행을 함께 지운다. 뿌리 행은 본문, key 번호, 경로, 크기를 비우고 지운 시각과 지문만 남긴 지우기 이력이 된다(PR 3) |
| 자동 보관 | turn 이 끝날 때 요청자가 켰으면 그 답에 묶인 결과물을 수동 보관과 같은 길로 보관한다(PR 3). 완료한 turn 만이고 주인은 대화 요청자다. 지우기 이력과 지문이 같으면 다시 만들지 않는다. 사용자가 직접 보관하면 이력을 지우고 다시 만든다. 기본값은 꺼짐이고 사용자 확인을 기다린다 |
| 작업 기록 | 결과물 행 자신의 `auto_vault_state`, `auto_vault_error`, `auto_vault_attempts` 다. 조건부 update 로만 상태를 옮겨 같은 완료가 두 번 와도 한 번 돈다. 재시작하면 `RUNNING` 을 `PENDING` 으로 되돌리고 `PENDING` 을 주기마다 훑는다. 일시 장애는 다음 훑기에 다시 시도하고, 세 번 시도해도 보관하지 못하면 실패로 둔다 |
| 읽기 | 본문 응답에 스크립트가 돌지 않는 머리글(`sandbox` CSP)과 `nosniff`, `no-store` 를 붙인다. 화면은 같은 격리의 iframe 으로 미리 본다. 묶음 HTML 은 보관본 안의 파일 주소(`/{id}/files/<경로>`)로 열어 상대 주소가 같은 보관본 안으로 풀리고, 파일마다 뿌리 행의 주인을 다시 확인한다. 묶음 안 파일의 번호로는 읽지 못한다. 묶음 내려받기는 zip 이고, 모든 파일이 풀리는지 먼저 확인한 뒤 쓴다 |

### 대안과 기각

- 새 표 `artifact_vault_item` 과 암호화 파일 저장소: 사용자 결정(새 테이블 금지)과 맞지 않고 파일과 DB 가 어긋나는 복구 작업이 따른다. 파일 하나가 5MiB 이하라 DB 컬럼에 두는 비용이 작다.
- 묶음을 뿌리 행의 본문 하나(zip 같은 묶음 형식)로 두기: 100MiB 묶음이 한 칸에 약 133MB 로 들어가고, 사진 하나를 미리 보려 해도 묶음 전체를 풀어야 한다.
- HTML 의 주소를 보관할 때 고쳐 쓰기: 원본과 다른 본문을 보관하게 되고 정규식 치환은 놓치는 자리가 생긴다. 상대 주소가 그대로 보관본 안으로 풀리도록 파일 주소를 둔다.
- 보관 중 원본 정리를 막는 장벽: 원본 정리와 보관 사이에 잠금을 나누어야 한다. 다시 읽고 비교해 되돌리면 같은 보장을 잠금 없이 얻는다.
- 기존 `chat_artifact` 행에 표시만 다는 방식: 대화 정리가 행을 지우고 CSS 는 행이 없으며 같은 경로의 덮어쓰기가 보관본을 바꾼다. 그래서 보관 시점의 사본을 별도 행으로 둔다.
- 기존 실행 공간(`/files`)에 복사: 실행 공간의 주인은 에이전트 주인이라 요청자의 개인 보관함이 되지 못하고, 셸이 전체를 읽는다.

### 결과와 남은 일

- 보관 사본은 `LONGTEXT` 컬럼에 암호문(base64url)으로 들어가므로 평문보다 약 4/3 커진다. 5MiB 한 파일은 약 7MB 다. 목록은 본문 컬럼을 읽지 않는다.
- 100MiB 묶음은 한 트랜잭션에 약 133MB 를 넣는다. 행 하나는 약 7MB 라 한 문장의 크기는 파일 하나의 상한을 넘지 않는다.
- 원본을 읽는 길은 기존 결과물 읽기(`ArtifactService.find`/`open`)와 같다. 경로 검사와 읽기 사이의 링크 경쟁은 [#359](https://github.com/jon890/fos-assistant/issues/359) 의 위험 수용을 그대로 따른다. 보관본을 읽는 길에는 파일 경로가 없다.
- 대화를 지울 때 「보관본도 함께 지우기」 선택지는 이 결정에 들어 있지 않다.
- 지우기 이력은 지문(해시)과 대화 번호, 지운 시각만 남긴다. 파일 이름과 본문, key 번호, 묶음 안 파일 행은 남기지 않는다. 그 대화를 정리하면 이력도 지운다. 지문은 같은 대화·경로·본문일 때만 같으므로, 지운 뒤 파일을 고친 답은 새 보관본으로 자동 보관한다.
- 자동 보관의 작업 기록과 지우기 이력을 사건 기록 표(`decision_feedback_event`)에 두는 안은 기각했다. 그 표는 판단 피드백의 계약 버전을 가진 덧붙이기 전용 기록이라 상태를 옮길 수 없고, 재시작 복구가 상태를 다시 읽어야 한다. 새 표도 만들지 않는다(2026-11-01 사용자 결정).
- 자동 보관 설정은 `app_user.artifact_auto_vault` 이고 비어 있으면 코드의 기본값을 따른다.
- 대화 화면은 HTML 결과물만 묶어 보이므로 사진 하나를 보관하는 단추는 아직 없다. API 는 사진 하나도 받는다.
