## ADR-20261013 / unknown-retry-key: 결과를 모르는 승인 실행은 커넥터가 선언한 오류 코드와 재시도 식별자 하나만 에이전트까지 전한다

- **status**: `accepted`
- Date: 2026-10-13
- [ADR-092](ADR-092-승인한-실행의-실패는-커넥터가-선언한-오류-코드와-복구-어휘와-정수-세부만-에이전트까지-전한다.md) 의 「`outcome_unknown` 은 객체 항목을 쓸 수 없다」 를 개정한다. 실패 줄의 복구 계약은 그대로다.
  UNKNOWN 을 자동으로 다시 보내지 않는다는 [ADR-050](../../backend/docs/adr/ADR-050-커넥터-쓰기는-control-plane-이-승인-줄을-저장하고-승인한-인자로-한-번만-실행한다.md) 의 규칙은 바꾸지 않는다.

### 결정

**`connector.json` 의 `errors` 에서 `outcome_unknown` 인 코드는 객체 `{category, retry_key}` 로 쓸 수 있다.
승인한 실행이 그 코드로 끝나면 대시보드 plugin 이 504 본문에 코드와 `retry_key` 가 가리키는 값 하나를 싣고, Control Plane 이 다시 검증해 `UNKNOWN` 줄에 저장하고 자동 turn 입력에 싣는다.**

| 항목 | 정한 것 |
| --- | --- |
| 선언 | `outcome_unknown` 인 객체 항목은 `category` 와 `retry_key` 만 갖는다. `recovery` 와 `details` 는 지금처럼 거절한다 |
| `retry_key` | 다시 보낼 때 같은 값을 넣는 칸의 이름이다. `^[A-Za-z][A-Za-z0-9_]{0,31}$` 이다. 인자 이름과 같게 쓰도록 대문자를 받는다 |
| 값을 찾는 곳 | 도구 오류 객체의 칸을 먼저 보고, 맞는 값이 없으면 도구 결과 맨 위의 칸을 본다 |
| 값의 형식 | `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$` 인 글만 옮긴다. UUID 가 들어간다. 공백과 `@`, 따옴표, 숫자 값, 객체는 그 칸만 버리고 코드는 남긴다 |
| 코드 | 글로 선언한 `outcome_unknown` 코드도 504 본문에 `code` 를 싣는다. 시간 초과처럼 도구가 답하지 않은 504 에는 없다 |
| 504 본문 | `{"detail", "code", "retry": {<retry_key>: <값>}}`. 상태는 그대로 504 라 옛 Control Plane 은 지금처럼 본문 없이 `UNKNOWN` 으로 읽는다 |
| 다시 검증 | Control Plane 은 같은 형식으로 다시 본다. `retry` 가 칸 하나짜리 객체가 아니거나 형식이 틀리면 식별자만 버린다. 코드 형식이 틀리면 둘 다 버린다 |
| 선언과 대조 | 카탈로그가 `unknown_errors: {<코드>: <retry_key 또는 null>}` 로 `outcome_unknown` 선언을 싣는다. Control Plane 은 받은 코드가 그 커넥터의 선언에 없으면 둘 다 버리고, 식별자 칸 이름이 선언과 다르면 식별자만 버린다. 카탈로그를 읽지 못하면 싣지 않는다 |
| 저장 | 마이그레이션 없이 `UNKNOWN` 줄의 `result_text` 에 `{"kind": "connector_unknown", "code", "retry"}` 를 넣는다. 사용자 데이터 key 로 봉인한다. `error_code` 는 비워 둔다 |
| 에이전트 입력 | 머리줄에 `오류 코드: <코드>` 와 `재시도 식별자: <이름>=<값>` 을 붙인다. 「다시 실행하지 말라」 는 줄은 그대로 두고, 식별자가 있으면 커넥터 스킬이 안내할 때만 그 식별자로 한 번 다시 부를 수 있다는 줄을 더한다 |
| 다시 보내기 | Control Plane 은 다시 보내지 않는다. 에이전트가 도구를 다시 부르면 그것은 새 호출이라 보통 호출과 같은 정책 판정을 거친다 |

다시 보낸 호출의 승인은 이렇게 갈린다.

| 그 도구에 남은 허락 | 다시 보낸 호출 |
| --- | --- |
| 없음 | 새 승인 줄과 승인 카드가 생긴다 |
| 대화 허락 | `UNKNOWN` 으로 끝난 줄이 함께 준 대화 허락은 결과를 기록할 때 거둔다. 다른 줄이 준 허락이 남아 있으면 묻지 않고 실행된다 |
| 상시 허락(`grant`) | 묻지 않고 실행된다. 같은 식별자는 커넥터 쪽에서 한 번만 기록되므로 중복 쓰기가 되지 않는 것이 커넥터의 책임이다 |
| 금융 도구 | 이 길을 쓰지 않는다. 금융 실행은 ticket 과 실행 줄로 결과를 판정한다 |

### 맥락

fos-agents 의 career 면접 기록 도구는 Backend 의 5xx 를 `CAREER_OUTCOME_UNKNOWN` 과 `attemptId` 로 돌려준다.
그 스킬은 같은 `attemptId` 로 다시 보내 저장 여부를 확인하라고 안내한다. Backend 는 `attemptId` 를 Idempotency-Key 로 써서 같은 요청에 저장한 응답을 다시 준다.

승인 경로에서는 그 안내를 따를 수 없었다.

- 대시보드 plugin 이 `outcome_unknown` 코드를 받으면 `{"detail"}` 만 담은 504 로 답했다.
- Control Plane 은 504 의 본문을 읽지 않고 `UNKNOWN` 으로 두었다. `result_text` 는 비어 있었다.
- 자동 turn 입력에는 「실행 여부를 알 수 없다. 다시 실행하지 말고 사용자에게 확인을 부탁한다」 만 실렸다.

에이전트가 새 `attemptId` 로 다시 보내면 Backend 가 같은 답변을 두 번 기록할 수 있다.

### 대안 기각

- **고정 허용 목록(`attemptId`, `idempotency_key` 같은 이름)을 plugin 에 둔다**: 커넥터를 고치지 않아도 되지만 plugin 이 서비스마다 다른 칸 이름을 알아야 한다. [`hermes/AGENTS.md`](../../hermes/AGENTS.md) 의 「plugin 은 어느 서비스도 모른다」 와 어긋나고, 목록에 든 이름을 다른 뜻으로 쓰는 커넥터의 값이 그대로 나간다.
- **ADR-092 의 `details` 를 `outcome_unknown` 에도 열고 글 값을 받는다**: 세부 칸은 정수와 boolean 만 받는다는 결정이 무너진다. 글 칸 하나로 원문 메시지를 옮길 수 있다.
- **도구 오류 객체를 그대로 504 본문에 싣는다**: career 의 오류에는 사용자의 답변을 되풀이하는 칸이 없지만, 다른 커넥터가 그렇게 만든다는 보장이 없다.
- **Control Plane 이 식별자로 한 번 자동 재전송한다**: 커넥터가 그 식별자로 중복을 막는지 Control Plane 은 알 수 없다. ADR-050 의 「UNKNOWN 은 다시 실행하지 않는다」 를 지킨다.

### 결과

- 얻는 것:
  - career 처럼 식별자로 중복을 막는 커넥터는 결과를 모를 때 에이전트가 같은 식별자로 확인 호출을 할 수 있다.
  - 결과를 모르는 실패도 어느 코드로 끝났는지 에이전트가 안다.
- 감당할 것:
  - 옛 대시보드 plugin 은 `outcome_unknown` 의 객체 항목을 거절해 그 커넥터를 카탈로그에서 뺀다. plugin 을 먼저 배포하고, 커넥터의 `connector.json` 에 `retry_key` 를 선언하는 변경은 그 뒤에 배포한다.
  - 식별자는 승인 줄 응답의 `resultText` 에도 그대로 나간다. 화면은 이 칸을 그리지 않는다.
  - 다시 보낸 호출에 상시 허락이 있으면 사람이 다시 보지 않는다. 같은 식별자로 한 번만 기록하는 것은 커넥터가 지킨다.
  - 형식 검증과 선언 대조는 대시보드 plugin 이 잘못된 칸을 실어 보내는 경우를 막는다. 값은 식별자 형식이라 문장이나 개인 정보를 담지 못한다.
