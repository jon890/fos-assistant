## ADR-062: 범용 커넥터는 이 저장소의 `hermes/connectors/` 에 두고 저장소가 유지보수한다

- **status**: `accepted`
- Date: 2026-10-02
- [ADR-043](ADR-043-커넥터는-plugin-의-connector-json-으로-선언하고-control-plane-은-범용-흐름만-갖는다.md) 의 「커넥터는 plugin 이 선언한다」 를 그대로 두고, 그 plugin 가운데 누구나 쓸 수 있는 것을 어디에 두는지 정한다.

### 결정

**누구나 자기 계정으로 쓸 수 있는 서비스의 커넥터는 이 저장소의 `hermes/connectors/<커넥터 이름>/` 에 하나씩 두고, 이 저장소가 유지보수하며 외부 기여를 받는다.**

| 항목 | 정한 것 |
| --- | --- |
| 여기 두는 것 | 공개된 서비스에 사용자 자신의 자격 증명으로 붙는 커넥터. 메일, 일정, 저장소 호스팅 같은 것이다 |
| 여기 두지 않는 것 | 한 집이나 한 조직만 쓰는 서비스의 커넥터, 운영 값(주소, 계정)이 있어야 도는 커넥터. 그 서비스의 저장소가 갖는다 |
| 디렉터리 이름 | `connector.json` 의 `id` 와 같다 |
| 커넥터 하나가 갖출 것 | `connector.json`(`schema: 2`), `.mcp.json`, `.claude-plugin/plugin.json`, MCP 서버, 스킬 하나 이상, 대역으로 도는 검사, 설정 안내 문서, 소유자 |
| Control Plane 과 웹 | 여전히 어느 서비스도 모른다. 서비스 이름은 `hermes/connectors/` 와 문서와 검사에만 있다 |
| 계약 검사 | `hermes/tests/` 의 공통 검사가 `hermes/connectors/` 아래 디렉터리를 모두 찾아 본다. 커넥터를 더하면 검사 대상이 된다 |
| 소유자 | `.github/CODEOWNERS` 에 커넥터 디렉터리마다 한 줄을 둔다 |
| 설치 | 운영자가 대시보드의 커넥터 목록에 그 디렉터리를 올린다. 저장소에 있다는 것만으로 켜지지 않는다 |

커넥터를 만드는 방법과 PR 에 필요한 것은 [커넥터 만들기](../connector-authoring.md) 가 갖는다.

### 맥락

제품의 목적은 범용 커넥터를 이어 자기만의 agentic workflow 를 만드는 것이다([`prd.md`](../prd.md)).
지금까지 붙은 커넥터는 다른 저장소에 있는 것 하나였고, 이 저장소에는 검사용 커넥터만 있었다.
이 저장소를 받아 띄운 사람은 쓸 수 있는 커넥터가 없었다.

커넥터는 외부 서비스의 글을 모델에게 주고 그 서비스에 쓰기도 한다.
도구마다 위험도를 고르고 쓰기에 승인을 거는 일을 만든 사람의 판단에 맡기고 있다([ADR-049](ADR-049-커넥터-도구-호출은-profile-plugin-의-hook-이-control-plane-에-물어-판정한다.md)).
기여를 받으려면 그 판단을 검토할 기준과 기계로 보는 검사가 한곳에 있어야 한다.

### 대안 기각

- **커넥터마다 저장소를 따로 둔다**: 계약(`connector.json`, 대시보드 plugin 의 검증)이 바뀔 때 커넥터가 함께 바뀌지 않는다. 받아 띄운 사람이 저장소 여럿을 찾아 맞춰야 한다.
- **`hermes/plugins/` 아래에 둔다**: 그 자리는 Hermes 가 읽는 plugin 이다. 커넥터는 대시보드 plugin 이 읽는 다른 종류의 디렉터리이고, `hermes/plugins/` 는 서비스 이름을 두지 않는 검사 대상이다.
- **저장소에 있는 커넥터를 자동으로 켠다**: 실행 파일과 운영 값은 운영자가 정한다. 운영자가 고른 것만 목록에 오른다는 전제(ADR-049)를 지킨다.
- **외부 서비스에 닿는 검사를 CI 에 둔다**: 계정과 비밀이 CI 에 있어야 하고 남의 서비스 상태로 검사가 흔들린다.

### 결과

- 얻는 것: 저장소를 받은 사람이 바로 쓸 커넥터가 있다. 새 커넥터가 따를 본보기와 검사가 한곳에 있다. 계약을 바꾸는 PR 이 커넥터까지 함께 고친다.
- 감당할 것:
  - **대역 검사는 외부 API 가 바뀐 것을 알지 못한다.** 검사는 우리가 흉내 낸 응답으로 돈다. 실제 계정으로 도는지는 그 커넥터의 소유자가 손으로 확인한다. 커넥터 문서가 그 확인 절차를 갖는다. 서비스가 깨졌다는 것은 사용자의 연결 확인 실패나 도구 오류로 처음 드러난다.
  - 소유자가 떠난 커넥터는 고칠 사람이 없다. 그때는 그 디렉터리를 지운다. 운영 목록에 없는 커넥터는 켜지지 않으므로 지워도 다른 것이 깨지지 않는다.
  - 커넥터의 위험도 분류는 여전히 만든 사람의 판단이다. 검사는 선언과 서버의 도구가 맞는지와 형식을 볼 뿐이다. 분류가 맞는지는 리뷰가 본다.
  - 커넥터 MCP 서버의 의존성은 운영자가 준 실행 파일의 환경에 있어야 한다. 그래서 커넥터는 대시보드 plugin 이 이미 요구하는 `mcp` SDK 밖의 의존성을 더하지 않는 쪽을 따른다.
