## ADR-20261016 / code-rules: 규칙의 까닭과 예외는 번호 문서가, 실행 조건은 검사 코드가 갖는다

- **status**: `accepted`
- Date: 2026-10-16
- [ADR-042](ADR-042-코드-품질-규칙은-도구-설정이-갖고-기존-위반은-기준-파일에-둔다.md)의 규칙 설명 소유권과 [ADR-20261009 / docs-per-module](ADR-20261009-docs-per-module.md)의 문서 배치 예외를 보완한다.

### 맥락

실행 가능한 조건은 도구에 모였지만 까닭과 예외는 Javadoc, 설정 주석, 모듈 지침과 리뷰 기준에 흩어졌다.
같은 규범을 여러 곳에서 고치면 적용 범위와 예외가 달라진다.
규칙을 찾는 고정 번호와 목록을 두되 실행 조건을 문서에서 다시 구현하지 않는다.

### 결정

| 소유자 | 갖는 내용 |
| --- | --- |
| `docs/code-rules/INDEX.md` | 고정 번호, 규칙 한 문장, 검사 이름과 소스 연결 |
| `docs/code-rules/rule-N.md` | 현재 규범, 까닭, 예외, 이 저장소의 실제 사례 |
| ArchUnit, Checkstyle, ESLint와 검사 script | 정확한 실행 조건, 선택 범위, 상한, 실패 메시지, 구현 설명과 suppression |
| 모듈 AGENTS | 모듈 입구, 읽기 순서, 실행 명령과 선택할 규칙 번호 |
| ADR | 당시 선택과 대안, 결과 |
| 아키텍처·스키마·기능 문서 | 책임, 흐름, 데이터 의미, 검사 실행과 기준 갱신 절차 |
| 리뷰 기준 | 자동 검사 밖의 검토를 위한 번호 참조와 리뷰 게시 절차 |

번호는 고정하고 폐지한 번호를 재사용하지 않는다.
규칙을 없애더라도 파일과 번호는 폐지 근거를 가리키게 남긴다.
자동 검사 없이 리뷰로 판단하는 조건은 목록의 검사 칸에 `리뷰`라고 밝힌다.
규칙 문서와 검사를 같은 PR에 넣고 목록 자체도 검사한다.
ArchRule 상수와 freeze 설명, 기준 파일의 열쇠는 바꾸지 않는다.
기존 위반을 줄여 가는 ADR-042의 계약과 도구별 실행 경계도 유지한다.

문서 경로는 루트 `docs/code-rules/INDEX.md`와 양의 정수 번호의 `rule-N.md`만 허용한다.
모듈별 사본이나 하위 주제 디렉터리는 만들지 않는다.
`test/unit/doc-files.test.ts`가 이 예외를 좁게 허용하고 `test/unit/rule-index.test.ts`가 파일·번호·문장·검사 연결 및 코드의 역참조를 확인한다.

### 대안 기각

- 문서만 먼저 둔다: 검사와 다른 약속이 늘고 누락을 알 수 없다.
- 모든 실행 조건을 문서에 복제한다: 적용 범위와 수치가 두 군데서 달라진다.
- 모든 도구를 하나의 새 검사로 합친다: 기존 기준 파일과 회귀 검사를 불필요하게 다시 만든다.

### 결과

리뷰는 번호로 까닭과 예외를 찾고 도구는 기존 조건 그대로 실행한다.
새 규칙이나 패키지 이동은 이 도입에 섞지 않고 해당 변경에서 번호 문서와 검사를 함께 고친다.
규칙 파일이 늘어나는 비용은 번호 목록 검사와 문서 경로 제한으로 관리한다.
