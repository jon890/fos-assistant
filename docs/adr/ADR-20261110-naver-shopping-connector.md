## ADR-20261110 / naver-shopping-connector: 네이버 쇼핑은 내 브라우저로 화면의 상태 JSON 을 읽고, 쇼핑 도구는 사람이 연 대화에서만 부른다

- **status**: `accepted`
- Date: 2026-11-10
- **decision-type**: `architecture`
- **areas**: `security, operations`
- **현재 규칙의 원본**: [네이버 쇼핑 플러그인](../features/naver-shopping.md), 스펙 [`docs/features/naver-shopping/spec.md`](../features/naver-shopping/spec.md)(사용자 확인 2026-11-10), 설계 [`design.md`](../features/naver-shopping/design.md)
- [ADR-20261007 / user-browser](ADR-20261007-user-browser.md) 의 사용자 브라우저와 중계를 그대로 쓴다. [ADR-080](ADR-080-먼저-살펴보기는-점검-대화의-turn-하나로-돌고-읽기-경계를-control-plane-이-강제한다.md) 의 살펴보기 읽기 경계 옆에 도구 단위의 경계를 하나 더한다.

### 결정

**네이버 쇼핑 플러그인은 「내 브라우저」 의 새 탭에서 검색 결과와 상품 화면을 열고, 페이지에 실린 상태 JSON 을 고정 식으로 꺼내 읽는다.**
네이버 검색 API 는 쓰지 않는다. 장바구니와 주문은 이 결정의 범위 밖이다.

| 항목 | 정한 것 |
| --- | --- |
| 검색 | 사람이 요청할 때 검색어 하나로 첫 페이지 한 번. 다음 페이지와 내리기는 없다. 처음 실린 상품을 40개까지 |
| 여는 주소 | 스마트스토어·브랜드스토어 상품과 가격비교 묶음 주소만 탭을 연다. 그 밖의 주소는 링크만 돌려준다 |
| 읽는 방식 | 탭에서 부르는 식은 플러그인 소스의 상수뿐이다. 누르기, 입력, 이동 식은 없다. 칸 위치는 표 하나에 모으고 비면 결과를 지어내지 않는다. 옵션 드롭다운을 여는 누르기 하나는 [ADR-20261113 / purchase-checkout](ADR-20261113-purchase-checkout.md) 이 예외로 둔다 |
| 사람이 해야 하는 화면 | 로그인, 캡차, 기기 인증이면 아무것도 누르지 않고 그 탭을 남긴 채 그 종류의 오류로 끝난다 |
| 위험도 | 세 도구 모두 `READ` 다. 최근 검색어와 최근 본 상품 같은 네이버 계정의 기록은 바뀔 수 있다 |

**쇼핑 도구는 사람이 연 대화에서만 부른다.** 도구 선언의 범용 칸 `attended_only` 가 그 표시이고 판정은 Control Plane 이 한다.

| 항목 | 정한 것 |
| --- | --- |
| 사람이 없는 실행 | 예약 작업 turn, 먼저 살펴보기 turn(매일 깨우기와 사건 감지 포함), 그 트리가 맡긴 일의 결과를 전하는 turn |
| 표식 | turn 을 열 때 실행 줄의 `agent_execution.unattended` 에 적고 바꾸지 않는다. 판정은 호출한 실행의 트리 루트 줄을 본다 |
| 판정 | `attended_only` 도구를 사람이 없는 실행이 부르면 위험도와 상관없이 `ATTENDED_ONLY` 로 거절하고 승인 줄을 만들지 않는다 |
| 읽지 못한 선언 | 대시보드는 boolean 이 아닌 값을 거절해 그 플러그인을 카탈로그에서 뺀다. Control Plane 은 boolean 이 아닌 값을 참으로 읽는다 |

**플러그인 선언 검사가 도구 검색 제약을 지킨다.** 도구 이름은 영어 낱말 둘 이상의 snake_case, 새 플러그인의 설명은 영어 요지 문장으로 시작하고, 플러그인 사이에 같은 도구 이름을 두지 않는다.

### 맥락

사용자는 피클처럼 사용자마다 띄운 브라우저로 쇼핑 화면을 다루고 결제는 사람이 하는 흐름을 원했다(spec DECISION1, DECISION2).
네이버 쇼핑에는 구매 API 가 없고, 쇼핑 검색 API 는 네이버페이로 바로 살 수 있는지를 주지 않아 어차피 상품 화면을 열어야 한다. 가족마다 개발자센터 앱을 등록하게 할 수도 없다(spec DECISION6).
네이버 이용약관은 사전 허락 없는 매크로와 캡차 우회를 금지한다. 사용자는 계정 정지 위험을 알고 진행을 정했다. 그래서 봇 동작을 사람이 요청한 한 번으로 줄이고 캡차는 사람에게 넘긴다.

Hermes v0.21.6 의 도구 검색은 등록 이름과 설명을 `[A-Za-z0-9]+` 로 잘라 색인해 한국어 설명으로는 도구가 걸리지 않는다.
쇼핑처럼 도구가 늘 분야는 영어 키워드가 없으면 목록 예산을 넘었을 때 모델이 도구를 찾지 못한다.

예약 작업 발화의 실행 번호(`task_run.execution_id`)는 turn 이 끝날 때만 채워져 도는 중의 판정에 쓸 수 없고, `connector` 가 `task` 를 읽으면 최상위 패키지 순환이 생긴다. 실행 줄은 `connector` 가 이미 읽는다.

### 대안 기각

- **네이버 검색 API, 사용자가 키 등록**: 정지 위험이 없지만 바로 구매 여부를 몰라 상품 화면을 또 열어야 하고, 가족마다 앱 등록이 필요하다
- **네이버 검색 API, 운영자 키**: 플러그인의 운영 값을 금지한 결정(ADR-064)을 뒤집고 모든 사용자가 한 키 한도를 나눈다
- **화면 글(DOM)을 긁는다**: 배치가 바뀌면 바로 깨지고 가격과 옵션을 글에서 다시 숫자로 읽어야 한다
- **아래로 내려 40개를 채운다**: 내려서 실리는 상품은 처음 상태 JSON 에 없어 다른 출처(DOM, 응답 가로채기)을 섞어야 한다. 칸 위치 가설이 두 벌이 된다
- **플러그인이 실행 종류를 보고 거절한다**: 플러그인은 실행의 종류를 알 길이 없고 판정은 Control Plane 이 한다(ADR-049)
- **`task_run` 으로 예약 작업을 가린다**: 도는 동안 실행 번호가 비어 있고 패키지 순환이 생긴다
- **기존 플러그인 설명도 영어 요지로 바꾼다**: 토스증권은 manifest SHA 가 바뀌어 열린 금융 승인이 무효가 되고, Gmail 과 블로그는 모델 지시문이 바뀌어 따로 확인해야 한다. 늘리지 않는 예외 목록으로 둔다

### 결과

- 얻는 것:
  - 키 등록 없이 사용자가 네이버에서 보는 가격과 판매처로 상품을 찾는다
  - 모델이 준 주소로 로그인된 브라우저가 아무 사이트나 열지 않는다
  - 예약 작업과 살펴보기가 사람 없이 쇼핑 화면을 반복해 열지 않는다. 같은 칸으로 뒤의 구매·예매 도구도 막는다
  - 새 플러그인의 도구가 영어 키워드로 검색된다
- 감당할 것:
  - **상태 JSON 의 칸 위치는 실제 네이버 화면으로 확인하지 않은 가설이다.** 배포 뒤 사용자가 실제 계정 확인으로 맞추고, 그 전에는 `PAGE_CHANGED` 로 실패할 수 있다
  - 네이버 화면 구조가 바뀌면 플러그인이 실패한다. 결과를 지어내지 않는 대신 실패가 잦을 수 있다
  - 계정 정지 위험은 남는다. 사람이 요청한 한 번과 캡차 넘기기로 줄일 뿐이다
  - 사람이 해야 하는 화면에서 남긴 탭은 사람이 닫을 때까지 남는다. 화면 넘기기 단계가 정리한다
  - 배포 순서상 새 대시보드와 옛 Control Plane 이 겹치는 동안 `attended_only` 가 판정되지 않는다. 이 플러그인은 그 전에 붙은 바인딩이 없다
