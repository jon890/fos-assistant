## ADR-20261119 / file-space-put: 에이전트가 「내 파일」 에 넣는 파일은 Control Plane 이 실행 공간과 대화 폴더에서 읽어 보관함에 넣는다

- **status**: `accepted`
- Date: 2026-11-19
- **decision-type**: `architecture`
- **areas**: `security, data`
- **현재 규칙의 원본**: 설계 [`docs/features/workspace/design.md`](../features/workspace/design.md), 스펙 [`spec.md`](../features/workspace/spec.md) 의 REQ1~REQ8(사용자 확인 2026-11-19), [`workspace.md`](../features/workspace.md) 의 「보관한 결과물」
- [ADR-20261101 / artifact-vault](ADR-20261101-artifact-vault.md) 의 「대상」 과 「상한」 의 파일 하나 값을 넓히고, 보관함에 들어오는 길에 에이전트의 넣기 도구를 더한다. 주인, 암호화, 묶음, 중복, 용량, 지우기 규칙은 그대로다

### 결정

**에이전트는 MCP 도구 `file_space_put` 에 경로만 넘긴다. Control Plane 이 읽기 전용으로 붙인 실행 공간이나 그 대화의 결과물 폴더에서 파일을 읽어, origin 실행의 요청자의 보관함에 암호화해 넣는다.**

| 규칙 | 내용 |
| --- | --- |
| 주인과 대화 | 서명한 `_fos_ctx` 의 origin 실행에서 정한다([ADR-037](../../backend/docs/adr/ADR-037-hermes-하위-에이전트-session-의-주인은-만들-때-등록한-줄로-정한다.md)). 도구 인자에 대화 식별자를 두지 않는다 |
| 읽는 곳 | `/workspace/` 로 시작하는 경로는 origin 실행의 에이전트가 쓰는 실행 공간(`Agent.sandboxOwner()`)에서, 그 밖은 그 대화의 결과물 폴더에서 읽는다. 실행 공간은 링크를 따라가지 않는 기존 읽기를, 대화 폴더는 실제 경로가 그 폴더 안인지 보는 기존 규칙을 그대로 쓴다. 대화 폴더가 화면에 내주는 형식은 넓히지 않는다 |
| 받는 형식 | 그림, HTML, CSS, 표(CSV, TSV, XLSX), 문서(PDF, MD, TXT, DOCX, PPTX)다. 확장자로 정하고 이진 형식은 머리 바이트를 함께 본다. 목록은 `VaultFileType` 이 갖는다 |
| 상한 | 파일 하나 25MiB(`assistant.artifact-vault.max-file-bytes`)다. 자동 보관과 「보관」 단추도 같은 값을 쓴다. 묶음과 사용자 용량은 그대로다 |
| 대화 쪽 사본 | 두지 않는다. 답 아래의 파일 줄은 보관 뿌리 행을 가리킨다(`vault_origin`, `vault_message_id`). 실행 공간에서 온 것과 대화 폴더에서 온 것은 `vault_origin` 으로 구분해 같은 상대 경로가 섞이지 않게 한다 |
| 제목과 설명 | `vault_meta` 칸에 주인의 데이터 key 로 암호화한 JSON 으로 둔다 |
| 사람이 없는 실행 | 예약 작업에서는 쓴다. 먼저 살펴보기 트리에서는 `artifact_write` 와 같이 쓰기 도구를 허용한 점검에서만 쓴다([ADR-082](ADR-082-먼저-살펴보기의-쓰기-도구는-관리자가-에이전트마다-켜고-커넥터-쓰기는-승인-카드로-보낸다.md)) |

### 맥락

2026-11-19 운영에서 「그 이미지를 내 파일공간에 가져다 놔줄래?」 라는 요청에 에이전트가 `artifact_write` 를 세 번 불러 모두 실패했다. 그 도구는 글 본문과 HTTPS 주소의 사진만 받는데 에이전트가 파일 경로를 넘겼다.
표와 문서 파일은 에이전트가 실행 공간에만 만들어 보관함에 들어올 길이 없었다.

에이전트의 작업 폴더는 사용자별 Docker 실행 공간 안에 있다([ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md)). Control Plane 은 그 루트를 읽기 전용으로 붙여 화면에 쓰고 있다([ADR-20261009 / workspace-explorer](ADR-20261009-workspace-explorer.md)).

### 대안 기각

- **모델이 본문을 도구 인자로 넘긴다.** 이진 파일을 base64 로 옮겨야 하고 수 MB 부터 모델의 출력 한도에 걸린다. 출력 토큰도 파일 크기만큼 든다.
- **fos-ctx 가 파일을 읽어 올린다(이미지 기능과 같은 길).** 그림은 Hermes 프로세스의 캐시 폴더에 생기지만 작업 폴더의 파일은 Docker 실행 공간 안에 있어 플러그인이 같은 경로로 읽지 못한다. Hermes 쪽 계약에 새로 기대는 것도 는다.
- **실행 공간의 파일을 대화 폴더로 복사한 뒤 기존 보관을 쓴다.** 암호화하지 않은 사본이 30일 동안 하나 더 생기고, 대화 폴더가 내주는 형식을 표와 문서까지 넓혀야 한다.
- **넣은 파일의 표시를 새 표에 둔다.** 새 표를 만들지 않기로 했고(2026-11-01 사용자 결정) 보관 행의 칸 둘로 충분하다.
- **제목과 설명을 평문 칸에 둔다.** DB 에서 바로 찾을 수 있다. 그러나 제목이 대화 내용을 드러낼 수 있어 본문과 같은 key 로 암호화한다. 찾기는 그 사용자의 것을 풀어서 한다(스펙 DECISION8).

### 결과

- 얻는 것:
  - 에이전트가 만든 엑셀, PDF, 문서가 대화를 연 사람의 「내 파일」 에 암호화돼 남는다.
  - Hermes 플러그인과 profile 설정을 바꾸지 않는다.
  - 경로와 링크, 형식과 크기의 규칙이 이 저장소의 코드와 테스트에 있다.
- 감당할 것:
  - 그룹에 공개한 에이전트를 다른 사용자가 쓰면, 그 사용자가 에이전트에게 주인의 작업 폴더 파일을 자기 「내 파일」 에 넣게 할 수 있다. 그 에이전트의 셸이 같은 파일을 읽어 답에 옮길 수 있는 것과 같은 경계다([ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md)). 그룹 공개를 고를 때 감당하는 범위에 든다.
  - 실행 공간 읽기는 `SecureDirectoryStream` 으로 링크를 따라가지 않고, 없으면 꺼진다(fail-closed). 링크 바꿔치기 경쟁(#359)을 막은 내력은 [ADR-20261009 / workspace-explorer](ADR-20261009-workspace-explorer.md) 와 같다.
  - 25MiB 파일 하나를 넣을 때 서버 메모리를 100MiB 안팎 쓰고, 암호문 한 줄이 약 34MB 다. 운영 DB 가 한 번에 받는 크기는 배포 전에 운영 저장소에서 확인한다.
  - 주인만 읽는 파일과 하드 링크가 둘 이상인 파일은 넣지 못한다.
- **확인 방법**: `/mcp` 를 서명한 호출로 부르는 통합 테스트가 주인, 형식, 크기, 링크 거절, 실패 결과를 본다. 배포 뒤 실제 에이전트로 한 번 왕복한다.
