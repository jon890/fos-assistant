# ADR-085: 매일 깨우기는 예약 작업을 다시 쓰고 다섯 칸 보고를 지금 화면에 올린다

- **status**: `accepted`
- **결정**: 사용자가 에이전트마다 매일 깨우기를 켜고, 시각과 IANA 시간대를 고른다. 기본은 꺼짐이다.
  에이전트 상세의 「먼저 살펴보기」 절에서 다음 실행 시각과 마지막 결과도 본다.

  **일정은 기존 예약 작업을 다시 쓴다.** `task.kind` 를 `TURN`, `CHECK` 로 나눈다.
  `TURN` 은 기존 대화 turn 이고 `CHECK` 는 같은 발화기가 `ProactiveCheckService.start(SCHEDULED)` 를 부른다.
  사용자와 에이전트마다 `CHECK` 설정은 하나이며 DB 유일 제약으로 동시 저장도 막는다.
  `CHECK` 는 지시문을 갖지 않고 에이전트의 `proactive-check` 스킬을 따른다.
  일반 예약 작업 목록과 사용자당 작업 10개 상한에서는 뺀다.

  **깨우기는 점검 대화를 이어 쓴다.** [ADR-076](../../backend/docs/adr/ADR-076-예약-작업은-control-plane-이-갖고-발화한-실행은-대화-turn-경로로-돈다.md)의 발화와 복구를 쓰되,
  [ADR-078](ADR-078-예약-작업의-결과는-실행마다-새-대화가-기본이고-목록은-작업으로-묶는다.md)의 새 대화와 `conversation.task_id` 규칙은 `TURN` 에만 적용한다.
  `CHECK` 는 [ADR-080](ADR-080-먼저-살펴보기는-점검-대화의-turn-하나로-돌고-읽기-경계를-control-plane-이-강제한다.md)의 사용자별 점검 대화와 session 을 그대로 쓴다.
  목표 메모가 없는 지금 session 을 새로 열면 이전 조사와 비교할 맥락이 사라지므로, 같은 session 은 지금처럼 14회까지 쓴다.

  **사용자 대화를 위한 실행 한 자리를 남긴다.** 매일 깨우기의 turn 자리와 그 위임 자식에도 예비 자리를 적용한다.
  자리가 없거나 점검 대화가 바쁘면 `QUEUED` 로 두고 다음 tick 에 다시 본다.
  놓친 발화는 `SKIP` 이며, 같은 예정 시각은 기존 `(trigger_id, scheduled_for)` 유일 제약으로 한 번만 처리한다.
  사용자가 열지 않은 보고가 있으면 Hermes 를 부르지 않고 `UNREAD_REPORT` 로 건너뛴다.
  모델 없이 끝난 깨우기는 하루 48회 실행 상한에서 뺀다([ADR-079](../../backend/docs/adr/ADR-079-예약-작업은-사용자당-10개-최소-간격-15분-하루-48번으로-제한한다.md)의 예외).
  외부 공고와 동향의 변화를 Control Plane 이 알지 못하므로 `NO_CHANGE` 선행 판정은 하지 않는다.
  그 판정은 목표의 `next_check_after` 가 생기는 다음 단계로 미룬다.

  **조용한 시간에도 실행하며 알림만 억제한다.** 기본은 사용자가 고른 시간대의 22시부터 07시까지다.
  이 시간의 결과는 점검 대화에서 읽는다. 조용한 시간에 깨우기를 건너뛰자는 조사 보고서 대신 이슈 #166 의 사용자 결정을 따른다.
  새 근거가 없는 `NOTHING_NEW` 는 예약 실행에서 대화 메시지와 무소식 알림을 남기지 않는다.
  모델이 발견을 냈어도 검사를 통과한 새 발견이 하나도 없고 질문과 출처 장애도 없으면 같은 무소식으로 다룬다.
  출처 장애와 질문은 정상 무변화로 숨기지 않는다.

  **다섯 칸 보고는 검사한 결과다.** [ADR-081](../../backend/docs/adr/ADR-081-살펴보기-결과는-답-끝의-구조화-블록으로-받고-control-plane-이-검사해-그린다.md)의 결과 블록을 버전 2로 넓힌다.
  버전 1도 읽어 요약과 검사한 발견에서 같은 보고 형식으로 바꾼다.
  분야 스킬과 Control Plane 을 순서대로 배포할 수 있게 한다.

  | 칸 | 내용 | 상한과 검사 |
  | --- | --- | --- |
  | `changed` | 무엇이 바뀌었나 | 3줄 |
  | `done` | 무엇을 했나 | 3줄 |
  | `evidence` | 근거 | 검사를 거친 발견의 원문 주소 3개 |
  | `needsApproval` | 남은 승인 | 모델 값을 버리고 그 실행 트리의 실제 승인 대기 카드 공개 식별자를 채운다 |
  | `next` | 다음에 볼 것 | 2줄 |

  보고는 `proactive_check.report_json` 에 저장한다.
  트리 전체의 입력, 캐시 입력, 출력 토큰도 함께 남긴다. 측정이 부족하므로 새로운 토큰 상한 수치는 정하지 않는다.

  **「지금 볼 것」 에 다섯째 카드 「보고」 를 둔다.** [ADR-074](../../web/docs/adr/ADR-074-지금-화면은-원래-기록을-읽어-만든-view-이고-정해진-카드-넷만-그린다.md)의 네 카드에 `reports` 를 더한다.
  모델이 쓴 보고는 `LATER` 이며 카드와 사이드바 건수에 세지 않는다.
  실제 승인 대기는 기존 「내 차례」 카드에서 센다.
  「보고 열기」 로 요청자 소유의 보고를 열면 `report_opened_at` 을 남긴다.
  사용자가 점검 대화를 열거나 그 대화에 메시지를 보내도 그 대화의 열지 않은 보고를 모두 연 것으로 남긴다.
  보고를 대화에서 직접 읽은 사용자의 깨우기가 `UNREAD_REPORT` 로 계속 건너뛰지 않게 하기 위해서다.

  **할 일은 제안만 한다.** 읽기 도구의 허용 여부나 관리자 쓰기 도구 허용과 관계없이 `follow_up_propose` 를 받는다.
  사람이 받아들여야 `OPEN` 이 되고, 에이전트는 `PROPOSED` 만 만든다.
  점검 대화는 최근 7일 안에 만든 열린 제안 3개 상한을 적용한다.
  더 오래된 제안은 지우지 않고 「내 차례」 에 남긴다. 보통 대화의 상한은 그대로다.

  **조회와 끄기는 Hermes 장애 중에도 가능하다.** 준비 상태 조회에 실패해도 저장된 설정을 주고 `READINESS_UNKNOWN` 으로 켜기를 막는다.
  끄기 트랜잭션은 Hermes 를 호출하지 않고 `PAUSED` 를 커밋한다. 응답도 준비 상태를 조회하지 않는다.
  다시 켜려면 화면을 새로 열어 확인한다. 켜기와 실제 실행은 준비 상태를 확인하지 못하면 거절한다.
  복구 뒤 꺼진 일정의 새 발화를 만들지 않고, 대기 중인 발화도 시작 전에 작업 상태를 확인한다.

  **격리 준비 전에는 셸, 파일, 코드 실행 도구가 켜진 에이전트를 매일 깨우지 않는다.** 켜기 저장과 발화 때 모두 검사한다.
  [ADR-082](ADR-082-먼저-살펴보기의-쓰기-도구는-관리자가-에이전트마다-켜고-커넥터-쓰기는-승인-카드로-보낸다.md)가 기각한 살펴보기 전용 에이전트는 만들지 않는다.
  `assistant.proactive-check.isolated-execution-enabled` 의 기본값 `false` 로 제한한다.
  [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md)의 사용자별 실행 공간을 운영에 반영하고,
  이미 셸 계열 도구가 켜진 profile 에도 실행 공간 설정과 기존 스킬 점검을 마친 뒤 실제 사용자별 격리 실행을 확인하고 운영 설정을 켠다.
  설정은 전역이므로 일부 profile 만 격리했으면 기본값 `false` 를 유지한다. local 로 남은 에이전트의 깨우기까지 열지 않는다.
  코드가 머지되거나 실행 공간 환경 값만 준비된 것으로 이 제한을 풀지 않는다. 확인과 설정 변경 절차는 `fos-home-infra` 가 갖는다.
  이후 profile 별 실행 공간 설정을 조회할 계약이 생기면 전역 설정 대신 요청자의 실행 공간을 확인하는 판정으로 바꾼다.
- **맥락**: 매일 깨우기는 #166 이고, 사용자 설정과 기본 꺼짐, 화면 위치와 조용한 시간은 사용자가 정했다.
  기존 발화와 점검 실행을 이어 한 번의 조사 결과를 같은 대화에서 읽고 논의할 수 있게 한다.
- **대안 기각**:
  - 별도 깨우기 스케줄러와 상태 표를 만든다. 기존 발화, 한도와 기동 복구를 다시 구현해야 한다.
  - 보고를 「내 차례」 에 섞는다. 읽을 거리와 사람이 처리할 일을 구분하기 어렵다.
  - 격리 준비 전에 관리자 쓰기 허용만으로 매일 깨운다. 사람이 보지 않는 실행에서 웹 결과가 셸 명령으로 이어질 수 있다.
- **적용 범위**: 매일 일정과 다섯 칸 보고, 보고 카드와 할 일 제안이다.
  목표, 피드백 저장, 신호 발화와 결과물 작업 공간은 이 단계에서 만들지 않는다.
  실행 계약은 [`backend/docs/flow.md`](../../backend/docs/flow.md), 표는 [`backend/docs/data-schema.md`](../../backend/docs/data-schema.md)와 [`backend/docs/data-schema.md`](../../backend/docs/data-schema.md)가 갖는다.
