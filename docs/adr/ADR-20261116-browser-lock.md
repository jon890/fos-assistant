## ADR-20261116 / browser-lock: 「내 브라우저」 는 에이전트와 사람 가운데 하나가 쥐고, 사람이 쥔 동안 중계가 에이전트를 거절해 넘기기로 끝낸다

- **status**: `accepted`
- Date: 2026-11-16
- **decision-type**: `architecture`
- **areas**: `security, operations`
- **현재 규칙의 원본**: 설계 [`docs/features/browser-cowork/design.md`](../features/browser-cowork/design.md) 의 「PR2 에이전트가 쥔 탭」, 「PR3 사람 잠금」, 「PR3 회수 중 에이전트 도구와 넘기기」, 「PR3 승인과 회수」, 스펙 [`spec.md`](../features/browser-cowork/spec.md) 의 REQ4~REQ7(사용자 확인 2026-11-16)
- [ADR-20261007 / user-browser](ADR-20261007-user-browser.md) 의 브라우저와 중계 위에 잠금을 더하고, [ADR-20261111 / connector-handoff](ADR-20261111-connector-handoff.md) 의 넘기기 어휘에 `human_browser` 하나와 탭 없는 넘기기를 더한다

### 결정

**에이전트는 자기가 연 탭만 쥐고, 사람은 「직접 할게요」 로 브라우저 전체를 쥔다. 사람이 쥔 동안 중계가 에이전트의 모든 요청을 거절하고, 플러그인은 그 거절을 「사람이 브라우저를 쓰는 중」 넘기기 결과로 바꾼다.**

| 항목 | 정한 것 |
| --- | --- |
| 에이전트가 쥔 탭 | 중계로 열린 `devtools/page` 연결이 있는 탭, 중계로 만든 지 30초 안의 탭, 쥔 탭이 연 탭(다섯 단계까지). JVM 메모리에 둔다. 사람 화면은 그 탭에 입력을 보내지 않는다 |
| 사람 잠금 | `user_browser.human_held_at`. 엔티티는 읽기만 하고 회수와 돌려주기는 조건부 갱신으로만 쓴다. `RUNNING` 에서만 잠그고 끄기와 상태 맞추기가 비운다 |
| 잠금이 풀리는 때 | 「돌려주기」, 브라우저 끄기, 그 사용자의 화면이 모두 닫힌 뒤 `idle-timeout`(10분) |
| 중계의 거절 | HTTP 창구는 423. WebSocket 은 연결을 받은 뒤 close code 4423 으로 닫고, 회수하는 순간 열린 연결도 4423 으로 닫는다 |
| 플러그인 | 423 과 4423 을 `<플러그인>_BROWSER_IN_USE` 와 넘기기 `{need: "human_browser", tab?}` 로 바꾼다. `isError` 없는 결과다 |
| 탭 없는 넘기기 | 알림 본문에서 `tab` 을 빼고 서명할 글의 `tab` 자리는 빈 글이다 |
| 승인한 실행 중 회수 | 브라우저를 쓰는 금융·구매 승인 줄이 `EXECUTING` 이면 회수를 거절한다(`BROWSER_APPROVAL_RUNNING`) |
| 회수 중 승인 | 브라우저를 쓰는 플러그인의 승인을 쓰지 않고 `CONNECTOR_BROWSER_HELD` 로 거절한다. 줄은 기다림 그대로다 |

### 맥락

사람과 에이전트가 같은 탭을 함께 건드리면 서로의 누르기가 섞인다([ADR-20261007 / user-browser](ADR-20261007-user-browser.md) 의 감수 항목). 사용자는 ego lite 처럼 잠금 주인이 늘 하나인 방식을 원했다(spec DECISION2).
에이전트가 브라우저에 닿는 길은 플러그인의 코드와 중계 하나뿐이다. 그래서 중계가 막으면 모든 플러그인이 같이 멈춘다.
회수한 동안 부른 도구가 오류로 끝나면 Hermes 의 같은 서버 연속 실패 정지에 걸린다. 넘기기 결과는 그 정지에 들지 않고, 사람이 돌려준 뒤 다음 메시지로 잇는 검증된 길이다(spec DECISION3).

### 대안 기각

- **판정 hook 이 도구 호출을 막는다**: hook 의 막기는 모델에게 오류 글로 간다. 넘기기 결과가 아니라 카드가 뜨지 않고, 이미 도는 도구는 멈추지 못한다
- **에이전트 도구가 잠금이 풀릴 때까지 기다린다**: 기다리는 동안 실행과 동시 실행 한도를 잡는다(spec 범위 밖의 「실행을 멈춰 사람을 기다리기」)
- **WebSocket handshake 를 상태 코드로 거절한다**: Bun 의 `WebSocket` 은 handshake 실패의 상태 코드를 주지 않아 닿지 않음과 나누지 못한다
- **잠금을 메모리에 둔다**: Control Plane 이 다시 뜨면 사람이 쥔 브라우저를 에이전트가 다시 건드린다. 잠금은 사람이 돌려주기 전까지 이어져야 한다
- **잠금 칸을 엔티티로 저장한다**: 활동 기록과 자동 중지가 오래된 엔티티를 저장해 잠금을 되돌린다. 버전을 올리면 그 저장들이 실패해 끄기와 켜기가 흔들린다(rule-68)
- **새 테이블**: 잠금은 브라우저 줄과 수명이 같다(테이블을 늘리지 않는다, 2026-11-01)

### 결과

- 얻는 것:
  - 사람이 「직접 할게요」 를 누르면 어느 대화의 에이전트든 다음 브라우저 요청에서 바로 멈추고, 그 대화에 카드가 뜬다
  - 돈과 좌석이 걸린 승인한 실행은 끝날 때까지 끊기지 않는다
  - 잠금은 플러그인 이름을 모르므로 뒤의 플러그인과 범용 에이전트 브라우저에도 그대로 쓴다
- 감당할 것:
  - 회수는 원고 저장처럼 오래 도는 일반 쓰기도 끊는다. 승인 실행 중 회수 막기는 금융·구매만 본다
  - 승인이 잠금을 본 직후와 실행을 커밋하기 전 사이에 회수가 들어오면 둘 다 지나간다. 그 실행은 중계에서 423 을 받아 넘기기로 끝난다
  - 회수한 자리는 메모리라 Control Plane 이 다시 뜨면 보고 있던 대화에도 알림이 하나 생긴다
  - 10분 풀림은 점검 간격(1분)만큼 늦을 수 있다
  - plugin 을 먼저 올리는 동안 새 fos-ctx 가 보낸 `human_browser` 를 옛 Control Plane 이 거절해 카드가 뜨지 않는다. 모델은 결과의 안내 글을 받는다
