## ADR-20261128 / agent-browser: 에이전트는 Control Plane 내장 도구로 요청자의 「내 브라우저」 를 쓰고, 바꾸는 동작은 먼저 살펴보기에서도 승인 카드로만 한다

- **status**: `accepted`
- Date: 2026-11-28
- **decision-type**: `architecture`
- **areas**: `security`, `browser`
- **현재 규칙의 원본**: [에이전트의 내 브라우저 조작 스펙](../features/agent-browser/spec.md)과 [설계](../features/agent-browser/design.md), `McpController` 의 먼저 살펴보기 도구 목록
- **결정**:
  - 에이전트가 「내 브라우저」 를 직접 다루는 길은 Control Plane MCP 의 내장 도구다. 플러그인과 중계 주소를 거치지 않는다. 도구는 MCP 요청자(origin 실행의 사용자)의 브라우저만 고르고, 사용자 스위치와 관리자 전체 스위치가 모두 켜진 동안만 쓴다.
  - 탭이나 화면을 바꾸는 동작은 늘 Control Plane 승인 카드로 한다. 사람이 승인하면 서버가 승인한 인자로 한 번 실행한다.
  - **먼저 살펴보기도 같은 도구를 쓴다.** [ADR-080](ADR-080-먼저-살펴보기는-점검-대화의-turn-하나로-돌고-읽기-경계를-control-plane-이-강제한다.md) 의 읽기 경계에 예외를 하나 둔다. 사용자가 켠 브라우저에서 그 사용자가 카드로 승인한 동작은 살펴보기 트리에서도 실행된다. [ADR-082](ADR-082-먼저-살펴보기의-쓰기-도구는-관리자가-에이전트마다-켜고-커넥터-쓰기는-승인-카드로-보낸다.md) 의 쓰기 설정은 이 도구에 걸리지 않는다. 목록과 화면 읽기는 승인 없이 받는다.
  - 이 결정은 [ADR-20261007 / user-browser](ADR-20261007-user-browser.md) 가 「나중에 따로 정한다」 로 미룬 「모델이 로그인된 세션으로 사이트를 다니는 길」 을 정한다. Hermes 내장 browser 도구는 지금처럼 끈다.
- **맥락**:
  - 플러그인이 없는 사이트에서도 탭 정리, 로그인한 화면 읽기, 양식과 초안 채우기를 맡기려 한다(스펙 DECISION1).
  - 바인딩 중계 주소는 플러그인 프로세스에 표식을 준다. 로컬 플러그인 프로세스는 다른 사용자의 비밀과 같은 OS 계정에서 돈다(`docs/code-architecture.md` 의 「경계 없음」 1). 범용 도구를 그 길로 주면 그 구멍으로 닿는 범위가 모든 사이트로 넓어진다.
  - Control Plane 이 직접 CDP 를 부르면 Hermes 쪽 어느 프로세스도 브라우저 주소나 표식을 갖지 않는다. 판정과 기록도 한 곳에서 한다. 남는 경계는 MCP 토큰과 서명이고, 「경계 없음」 1 의 프로세스는 이를 만들 수 있다. 그 길로도 바꾸는 동작은 사람의 승인을 거친다.
  - 먼저 살펴보기는 사람이 보지 않는 실행이다. 웹 결과의 글이 모델을 속일 수 있다. 사용자는 살펴보기에서도 브라우저 조작을 맡기되, 승인한 것만 실행되기를 원했다(스펙 DECISION3, DECISION10).
- **대안 기각**:
  - **Hermes 에 설치하는 플러그인으로 낸다.** 설치와 바인딩, 재시작을 거쳐야 하고, 범용 브라우저 권한이 같은 OS 계정의 프로세스에 표식으로 남는다. 사용자는 기본 도구를 플러그인과 따로 관리하기로 했다(스펙 DECISION6).
  - **Hermes 내장 browser 도구를 사용자 브라우저에 붙인다.** 실행마다 사용자를 고를 자리가 없고 Control Plane 이 호출을 판정하지 못한다.
  - **먼저 살펴보기에서는 쓰기 설정이 켜진 에이전트만 받는다.** 쓰기 설정은 셸과 파일처럼 Control Plane 이 막지 못하는 도구의 위험을 관리자가 받아들이는 장치다. 브라우저 동작은 승인 카드가 하나씩 막으므로 그 설정에 묶을 까닭이 없다. 묶으면 사용자가 원한 살펴보기의 탭 정리 제안이 카드조차 뜨지 않는다.
  - **승인 뒤 모델이 다시 도구를 불러 실행한다.** 승인한 것과 다른 탭이나 조작을 고를 길이 생긴다.
- **결과**:
  - 얻는 것:
    - 브라우저 판정과 기록이 Control Plane 한 곳에 있다.
    - 살펴보기와 예약 작업도 같은 도구를 쓰고, 바꾸는 동작은 사람이 승인해야만 일어난다.
  - 감당할 것:
    - 읽기는 승인 없이 되므로 로그인한 화면의 내용이 모델 입력에 들어간다. 그 내용이 웹 검색 같은 다른 도구로 나가는 것은 Control Plane 이 막지 못한다. 사용자가 켠 동안만, 그 사용자 브라우저만 읽는 것으로 범위를 줄인다.
    - 승인 카드가 쌓이면 살펴보기가 사람에게 일을 늘린다. 카드는 기존 만료 규칙을 따른다.
- **확인 방법**: `McpBrowserTabToolsTest` 가 스위치, 남의 카드 승인, 살펴보기 트리의 수락을 본다. `BrowserTabControlTest` 가 합성 사용자 둘의 브라우저가 섞이지 않는 것을 본다.
