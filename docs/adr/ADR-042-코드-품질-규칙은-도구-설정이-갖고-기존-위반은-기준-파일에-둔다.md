## ADR-042: 코드 품질 규칙은 도구 설정이 갖고 기존 위반은 기준 파일에 둔다

- **status**: `accepted`
- **결정**: 코드 품질 규칙을 문장이 아니라 도구 설정으로 둔다.
  구조는 ArchUnit, 코드 규칙은 Checkstyle, Java 포맷은 Spotless 와 palantir-java-format, 화면 코드의 규칙은 eslint, 화면 코드의 포맷은 Prettier 가 검사한다.
  도구 버전은 모두 정확한 값으로 고정한다.
  지금 있는 위반은 저장소에 커밋하는 기준 파일에 적고 새 위반만 실패시킨다.
  기준은 허용 목록이 아니라 줄여 갈 목록이다. 기준마다 GitHub 이슈를 열어 줄여 간다.
  포맷은 Java 와 web 모두 `origin/main` 에서 바뀐 파일만 검사하고 고친다.
  Prettier 는 설정 파일 없이 기본값을 쓴다.
  진입점은 `scripts/quality.sh check` 와 `scripts/quality.sh fix` 하나이고 CI 가 `check` 를 돌린다.
- **맥락**:
  - 패키지 경계와 층 방향이 `docs/code-architecture.md` 와 `backend/AGENTS.md` 에 문장으로만 있었다.
    `mcp` 와 `orchestration` 이 서로를 import 한 것(PR #56 이 끊음)과 `agent` 와 `skill` 이 서로를 참조한 것(PR #50 리뷰)이 리뷰에서야 드러났다.
  - 2026-09-30 에 import 로 측정했을 때 그때 있던 최상위 패키지 12개가 모두 한 순환 묶음에 있었다. 기반 패키지 `shared` 를 빼도 패키지 사이 간선 48개가 모두 순환에 속했다.
    바이트코드로 얼린 기준은 간선 38개다. 쓰지 않는 import 는 간선이 되지 않아 `hermes` 로 들어가는 간선이 순환에서 빠졌다.
    이것을 먼저 모두 풀고 규칙을 켜는 것은 설계를 바꾸는 일이라 규칙 도입보다 훨씬 크다.
  - Java 파일 337개 가운데 1,755줄이 120자를 넘었고 import 순서도 파일마다 달랐다.
  - 여러 워커가 같은 파일을 나란히 고친다. 저장소 전체를 한 번에 포맷하면 진행 중인 모든 브랜치가 충돌한다.
  - 테스트와 준비 메서드 약 900개가 한국어 문장 이름이라 Checkstyle 의 메서드 이름 규칙을 테스트에 걸 수 없었다.
  - web 의 eslint 는 `package.json` 에 스크립트만 있고 패키지와 설정 파일이 없어 `pnpm lint` 가 돌지 않았다. 처음에는 규칙 위반을 막는 것이 목표라 Prettier 를 넣지 않기로 했으나, 코디네이터가 화면 코드의 서식을 한 모양으로 두려고 바뀐 파일만 검사하는 Prettier 를 더하기로 정했다.
- **대안 기각**:
  - **기존 위반을 모두 고친 뒤 규칙을 켠다.** 순환을 푸는 것은 패키지 설계 변경이다. 그동안 새 위반이 계속 들어온다.
  - **저장소 전체를 한 번 포맷한다.** 진행 중인 브랜치가 모두 충돌하고 `git blame` 이 포맷 커밋을 가리킨다. 사용자가 바뀐 파일만 고르는 쪽을 골랐다.
  - **google-java-format 기본 모양.** 들여쓰기가 2칸이다. 바뀐 파일만 포맷하면 4칸 파일과 2칸 파일이 오래 섞인다.
  - **google-java-format AOSP 모양.** 4칸이지만 줄을 넘긴 인자를 한 줄에 하나씩 늘어놓아 스트림과 람다가 세로로 길어진다.
  - **ArchUnit 의 `slices().should().beFreeOfCycles()` 를 그대로 얼린다.** 기본 설정은 순환을 100개까지만 찾는다. 이 저장소처럼 촘촘한 그래프에서는 어느 순환이 먼저 잡히는지에 따라 얼린 목록이 달라질 수 있다. 같은 입력에 같은 결과를 내려고 조건을 직접 쓴다.
  - **순환에 속한 클래스 의존을 하나씩 얼린다.** 패키지가 모두 한 순환 묶음이라 패키지를 넘는 새 의존이 모두 실패한다. 최근 PR 12개 가운데 11개가 걸렸을 것이다. 사용자가 패키지 간선 단위를 골랐다. 순환에 속한 패키지 간선 하나가 위반 하나이고, 순환을 늘리는 새 간선만 실패한다. `shared` 는 그래프에서 빼고 `shared` 가 도메인을 쓰는 것을 따로 막는다.
  - **테스트 메서드 이름을 한국어로 두고 그 규칙만 뺀다.** 파일 단위 기준으로 두면 그 파일에 한국어 이름을 새로 더해도 막지 못한다. 영문 이름에 `@DisplayName` 으로 한국어 문장을 붙인다.
- **결과**:
  - 얻는 것:
    - 경계를 넘는 새 의존과 새 순환이 리뷰 전에 테스트에서 실패한다
    - 규칙마다 이름이 있어 문서가 그 이름을 가리킨다
    - 같은 입력이면 같은 결과가 난다. 도구 버전과 기준 파일이 저장소에 있다
    - 사람이 판단하지 않아도 되는 포맷과 자동 수정은 `fix` 가 끝낸다
  - 감당할 것:
    - 파일을 처음 고치는 PR 은 그 파일 전체가 포맷된다. 기능 변경과 포맷을 다른 커밋으로 나눈다
    - 기준 파일은 스스로 줄지 않는 것이 있다. 위반을 고치면 기준 파일도 함께 고친다. ArchUnit 기준은 고친 위반이 남아 있으면 테스트가 실패해 알린다
    - 기준마다 연 이슈를 닫을 때까지 챙긴다. 얼려 두고 그대로 두지 않는다
    - 기준 파일에 든 위반은 규칙을 어긴 채 남는다. 기준은 되돌릴 목록이지 허용 목록이 아니다
    - CI 의 품질 검사는 `origin/main` 이력이 있어야 돈다
    - palantir-java-format 은 한글 한 글자를 한 칸으로 센다. 한글이 많은 줄은 화면에서 120칸보다 넓게 보인다
- **적용 범위**: `backend/` 의 Java 코드와 테스트, `web/` 의 화면 코드. 규칙 목록과 기준 파일을 갱신하는 방법은 `backend/AGENTS.md` 와 `web/AGENTS.md` 가 갖는다.
