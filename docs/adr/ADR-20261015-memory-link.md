## ADR-20261015 / memory-link: 기억 사이의 연결은 링크 표에 두고, 옛 값은 지우지 않고 「대체함」 링크로 주입에서 뺀다

- **status**: `accepted`
- Date: 2026-10-15
- #310 의 처음 계획에 있던 `fact_kind` 로 값을 가르는 대체와, 저장할 때 ADD/UPDATE/NOOP 를 고르는 대체를 이 결정이 대신한다. 변하는 정도의 분류는 두지 않고, 정비 루프의 안전 규칙에 필요한 값 하나만 [ADR-20261015 / memory-maintenance](ADR-20261015-memory-maintenance.md) 가 둔다.
- 2026-10-16 사용자 결정(판단의 분류를 테이블 컬럼이나 enum 으로 굳히지 않는다, #310 댓글)에 따라 링크 종류는 Control Plane 이 다르게 동작해야 하는 둘만 둔다.
- [ADR-20261008 / memory-facts](ADR-20261008-memory-facts.md) 의 「같은 사실의 옛 값과 새 값이 함께 실릴 수 있다. 값 대체는 #310 의 2단계가 다룬다」 를 이 결정이 푼다.
- 구현은 #310 2단계의 단계 2 다. 이 ADR 이 머지될 때는 아직 만들지 않았다.

### 결정

**기억 사이의 연결을 `memory_link` 테이블의 줄로 둔다.** 그래프 DB 를 쓰지 않는다.

| 종류 | 뜻 | 방향 |
| --- | --- | --- |
| `SUPERSEDES` | 대체함. 새 값이 옛 값을 대신한다. 옛 항목을 주입에서 빼므로 사람 승인을 거친다 | 새 항목 → 옛 항목 |
| `RELATED` | 그 밖의 연결. 한 단계 이웃으로 함께 실린다 | 방향 없음. 번호가 작은 쪽을 `from` 에 둔다 |

- 「이 목표의 일부」, 「같은 여행」 처럼 연결의 뜻은 `RELATED` 줄의 자유 글 `label` 에 적는다. 모델이나 사람이 쓰고, Control Plane 은 `label` 로 판정하지 않는다

- 줄마다 누가 만들었는지(`AUTO`, `AGENT`, `HUMAN`)와 상태(`PROPOSED`, `ACTIVE`, `REVOKED`)를 둔다. 끊을 때 지우지 않고 `REVOKED` 로 바꾼다
- 양 끝은 `ACCEPTED` 항목이어야 한다. `PROPOSED` 항목과 링크를 맺으면 승인되지 않은 글이 주입 경로에 간접으로 들어온다
- `USER` 항목과 `GROUP` 항목 사이, 주인이 다른 `USER` 항목 사이에는 맺지 않는다. 두 범위가 한 항목처럼 섞이지 않는다는 [ADR-071](../../backend/docs/adr/ADR-071-여러-출처의-문맥은-항목마다-출처와-권한과-신선도를-지닌-묶음으로-조립한다.md) 의 원칙을 지킨다

**대체는 지우지 않고 표시한다. 「대체됨」 은 `memory` 의 상태가 아니라 `ACTIVE` 인 `SUPERSEDES` 링크로만 판정한다.**
대체된 항목은 조립의 모든 층과 `memory_search`, `memory_read` 에서 빠진다. `/memory` 에는 「대체됨」 으로 보이고 판 기록은 그대로 남는다.
대체를 되돌리는 것은 그 링크를 `REVOKED` 로 바꾸는 것 하나다. 상태가 두 곳에 있지 않아 어긋날 일이 없다.

**누가 대체를 정하는가.**

| 경우 | 처리 |
| --- | --- |
| 사용자가 대화에서 직접 정정했고 모델이 옛 번호를 `memory_id` 로 준다 | 지금처럼 그 항목을 고친다. 옛 값은 판 기록에 남는다. 이것이 「바로 대체」 이고 링크를 만들지 않는다 |
| 새 항목이 저장된 뒤 코드가 비슷한 옛 항목을 찾았다 | `PROPOSED` 인 `SUPERSEDES` 링크를 만들고 승인 카드로 묻는다. 받아들이면 `ACTIVE` 다 |
| 에이전트가 대체라고 추정했다 | 같은 승인 카드다 |

대체 후보는 코드가 찾는다. 같은 주인의 `ACCEPTED` 항목 가운데 임베딩 코사인이 높고 숫자, 날짜, 고유명사 값이 다른 쌍이다.
**LLM 이 쓰기 때 UPDATE 나 DELETE 를 고르지 않는다. LLM 이 이웃 기억을 덮어쓰지 않는다.**

**조립은 실린 항목에서 한 단계만 이웃을 더한다.** 개인 사실 구역과 「질문과 관련된 기억」 구역에 본문으로 실린 항목의 `ACTIVE` 인 `RELATED` 이웃을 그 구역의 남은 예산 안에서 본문으로 싣고(`MEMORY_LINK`), 넘치면 색인에 제목으로 둔다. 이웃도 같은 권한 조건을 지나야 한다.

**`RELATED` 는 자동으로 맺고 바로 `ACTIVE` 다.** 임베딩 코사인 상위 k 안에 서로 드는 쌍만 맺고 항목마다 링크 수 상한을 둔다. 주입에 미치는 영향이 한 단계 이웃뿐이라 작다.
에이전트가 맺는 `RELATED` 도 같은 조건(양 끝이 같은 주인의 `ACCEPTED` 항목, 상한)을 지나면 `ACTIVE` 다. 그 뜻은 `label` 에 남는다.

**외부 글을 읽은 대화에서 온 저장 제안에는 그 사실을 남긴다.** `memory_capture` 에 「같은 대화에서 외부 글을 읽었는가」 를 적고 승인 카드에 보인다. 바로 저장 조건 4 가 이미 계산하는 값이다.

### 맥락

2026-10-15 사용자는 기억을 세세한 종류로 쪼개기보다 기억 사이의 연결을 먼저 하고, 옛 값은 세부 종류 대신 「대체함」 연결로 처리하기로 정했다(#310 댓글).
개인 사실 구역을 켜자 오기억 노출률이 25% 에서 100% 로 올랐다(#323). 같은 사실의 옛 값과 새 값이 둘 다 `ACCEPTED` 로 실리기 때문이다.

조사(agent memory 사례 조사, 2026-10-15)에서 얻은 근거다.

- Mem0 는 2026-04 에 UPDATE 와 DELETE 를 버리고 ADD 만 한다. 두 번째 LLM 단계가 느렸고 덮어쓰기가 원래 사실의 핵심 정보를 지웠다고 밝혔다.
- Graphiti 는 지우지 않고 무효화 시각을 채우며, 무효화 계산은 코드가 한다. LangMem 은 삭제가 기본으로 꺼져 있다.
- Supersede 연구는 LongMemEval 지식 갱신 하위 집합에서 전체 투입 92% 가 스스로 유지한 기억에서 77% 로 떨어진다고 보고한다. 병목이 기억 유지 관리라는 것이다.
- Mem0, Supermemory, Hindsight, ReMe 는 행 단위 링크와 한 단계 확장으로 연결을 구현했다. 그래프 변형의 이득은 시간 추론과 개방 도메인에 몰려 있고 다중 홉은 오히려 내렸다(Mem0 논문).
- 「딸 알레르기: 땅콩 있음」 과 「땅콩 없음」 은 코사인이 높다. 임베딩으로 중복을 찾아 자동 병합하면 정보가 사라진다. 임베딩은 후보를 찾는 데만 쓴다.

### 대안 기각

- **`memory` 에 `SUPERSEDED` 상태를 둔다.** 주입에서 빼는 조건은 단순해지지만, 상태와 링크가 둘 다 대체를 말하게 되어 되돌릴 때 두 곳을 함께 고쳐야 한다. 수천 건 규모에서 `NOT EXISTS` 조건의 비용은 작다.
- **`valid_from`, `valid_until` 컬럼을 둔다.** 언제 바뀌었는지는 링크가 만들어진 시각이 말한다. 기간이 있는 상태인지는 모델의 판단에 맡기고, 정비 루프는 자동 보관을 허락한 항목만 보관한다.
- **그래프 DB 를 둔다.** 두 단계 이상 탐색과 커뮤니티 요약이 그래프 엔진의 몫인데, 이 규모에서 얻는 것이 작고 운영할 저장소가 하나 는다.
- **저장 때 LLM 이 비슷한 항목을 보고 ADD/UPDATE/NOOP 를 고른다.** Mem0 가 물러난 구조이고, 사람 승인 없이 기존 사실이 바뀐다.
- **연결 종류를 enum 으로 늘린다(`PART_OF`, `EXTENDS`, `DERIVES` 등).** 모델이 좋아지면 연결의 뜻은 더 세분화된다. Control Plane 이 종류마다 다르게 동작하지 않는다면 그 분류는 `label` 의 자유 글로 받는다(2026-10-16 사용자 결정).
- **사용자가 직접 정정한 경우에도 새 항목과 링크를 만든다.** 지금의 `memory_id` 고치기가 이미 판 기록과 되돌리기를 갖고 있다. 같은 일을 두 길로 하게 된다.

### 결과

얻는 것

- 옛 값이 새 값과 함께 본문으로 실리는 일이 사람이 받아들인 만큼 준다.
- 옛 값과 그 이력이 남아 되돌릴 수 있다.
- 찾은 기억과 연결된 사실(같은 목표의 다른 일, 관련 사실)이 함께 실린다.

감당할 것

- 승인 카드를 받아들이기 전까지는 옛 값과 새 값이 함께 실린다.
- 자동 `RELATED` 링크가 틀리면 엉뚱한 이웃이 실린다. 링크 정밀도는 운영 집계로 표본 확인하고, 상한과 임계값을 그 수치로 고친다.
- 조립과 `memory_search`, `memory_read` 의 권한 조건에 「대체되지 않음」 이 하나 는다. 저장소 밖 쿼리라 실제 MySQL 테스트에 직접 더해야 한다.

#310 2단계의 단계 2 다.

| 무엇 | 내용 |
| --- | --- |
| 바뀌는 테이블 | 새 `memory_link`(번호, `from_memory_id`, `to_memory_id`, `type`(`SUPERSEDES`, `RELATED`), 자유 글 `label`, `origin`, `status`, `score`, 만든 실행 번호, 만든 시각, 끊은 시각. `from`, `to`, `type` 이 유일하다). `memory_capture` 에 외부 글을 읽었는지 적는 컬럼 |
| 바뀌는 클래스 | `MemoryQueries`(대체되지 않은 항목 조건), `ContextAssembler`(한 단계 확장, `MEMORY_LINK`), `ContextSource`, 새 링크 서비스와 대체 후보 탐지, `McpMemoryRemember` 와 `MemoryCaptureService`(외부 글 기록), `/memory` 화면과 승인 카드(대체 받아들이기, 대체됨 표시, 되돌리기) |
| 완료 조건 | 대체 사례의 오기억 노출률이 기준 파일보다 내려가고 기준 파일을 새 값으로 다시 만든다. 대체된 항목이 조립, `memory_search`, `memory_read` 에서 빠지는 테스트가 있다. 링크를 끊으면 다시 실린다. `USER` 와 `GROUP` 사이 링크와 `PROPOSED` 항목 링크를 거절하는 테스트가 있다 |
