## ADR-056: 다른 서비스는 사용자에 묶인 서비스 토큰으로 문서를 읽기만 한다

- **status**: `accepted`. 아직 구현 전이다.
- **결정**: Hermes 실행 밖에서 도는 서비스는 **서비스 토큰**으로 Memory 문서를 읽는다.
  토큰 하나는 사용자 한 사람에 묶이고, 받는 collection 목록과 collection 마다의 민감 허용을 갖는다.
  판정은 [ADR-053](ADR-053-에이전트는-허용된-collection-의-memory-만-받는다.md) 의 세 조건(범위, collection, 민감도) 그대로다.
  읽는 것은 그 사용자의 `USER` 범위이고 `ACCEPTED` 인 `DOCUMENT` 뿐이다. **쓰지 못한다.**
  토큰은 그 사용자 본인만 발급하고 폐기한다. 관리자도 다른 사용자의 토큰을 발급하지 못한다.
  발급할 때 만료를 고른다. 화면의 기본값은 90일이고 만료 없음도 고를 수 있다.
  원문은 발급 응답에서 한 번만 내고 SHA-256 해시만 저장한다.
- **맥락**: Memory 본문은 Hermes 실행 안에서만 읽혔다. 주입과 `memory_read` 가 그 길이고, 요청자는 origin 실행에서 정한다([ADR-032](ADR-032-mcp-토큰은-profile-을-증명하고-실제-사용자는-부모-실행에서-정한다.md)).
  같은 문서를 터미널에서 도는 스크립트도 읽어야 한다. 그 스크립트에는 origin 실행이 없다.
  웹의 짧은 수명 JWT 는 Next.js 서버만 만든다. 브라우저도 그 토큰을 갖지 않는다.
  [ADR-052](ADR-052-memory-는-collection-종류-꺼내는-방식-민감도-판-출처를-가진다.md) 가 판 번호를 둔 까닭이 「다른 서비스가 그 문서의 몇째 판으로 분석했는가를 적어 둔다」 였다. 그래서 응답은 본문과 판 번호를 함께 낸다.
- **대체된 부분**: 없다. ADR-053 의 「다음」 이 적어 둔 「사용자 하나와 collection 목록에 묶인 서비스 토큰」 을 정한다.
- **대안 기각**:
  - `agent_token` 을 함께 쓴다: 그 토큰은 profile 만 증명하고 사용자 칸을 일부러 지웠다(ADR-032). 사용자 칸을 되살리면 그 결정이 막은 「공유 profile 의 토큰이 한 사용자의 권한으로 도는 일」 이 다시 열린다. 표를 따로 둔다.
  - 스크립트에 `ASSISTANT_JWT_SECRET` 을 준다: 그 secret 으로는 어느 사용자의 토큰이든 만든다. 문서 하나를 읽으려고 모든 사용자의 권한을 넘기지 않는다.
  - 관리자가 발급한다: 관리자가 다른 사용자의 민감 문서를 읽는 토큰을 만들 수 있게 된다. `USER` 범위는 주인만 본다는 약속과 어긋난다.
  - 토큰이 쓸 수도 있게 한다: Memory 는 사람이 승인한 것만 남는다([ADR-012](ADR-012-memory-는-사람이-승인한-것만-남는다.md)). 쓰는 길은 [ADR-057](ADR-057-문서는-사람이-화면에서-직접-쓰고-고친다.md) 이 정한다.
  - 만료를 두지 않는다: `agent_token` 과 같아 가장 단순하다. 그러나 이 토큰은 노트북의 설정 파일에 놓인다. 잊힌 토큰이 저절로 죽어야 한다.
  - 만료를 필수로 둔다: 읽는 쪽이 주기마다 멈춘다. 사용자가 위험을 알고 고르게 한다.
  - 민감 허용을 토큰에 불 값 하나로 둔다: ADR-053 이 에이전트에서 같은 것을 기각했다. collection 마다 둔다.
  - `GROUP` 문서도 읽게 한다: 같은 이름의 문서가 개인과 그룹에 함께 있을 때 어느 것을 낼지 정해야 한다. 읽을 일이 생길 때 정한다.
  - 꺼내는 방식(`retrieval`)으로도 거른다: 그 칸은 에이전트의 실행에 어떻게 실을지를 정한다. 서비스의 읽기는 실행이 아니다.
  - Hermes 실행 안의 스크립트를 위해 에이전트에 `identity` 와 민감 허용을 주는 경로를 함께 만든다: 그 경로는 관리자 화면과 API 가 필요하다. 스크립트는 세 실행 환경 모두에서 같은 서비스 API 를 부르면 되므로 이번에 만들지 않는다.
- **결과**:
  - 얻는 것: 실행 밖의 서비스가 사용자의 문서를 본문과 판 번호로 읽는다. 읽는 범위는 토큰이 받은 collection 으로 한정된다.
    토큰이 새어도 그 토큰이 받은 collection 의 문서만 읽히고, 쓰거나 지우지 못한다.
    마지막으로 쓰인 시각과 만료 시각이 남아 쓰지 않는 토큰을 사용자가 알아본다.
  - 감당할 것: **토큰을 가진 쪽은 실행 없이 본문을 읽는다.** 요청자를 origin 실행에서 정하는 보호가 이 길에는 없다. 토큰을 두는 자리가 곧 경계다.
    **여러 사용자가 함께 쓰는 Hermes profile 의 환경에 이 토큰을 두지 않는다.** 그 profile 로 도는 누구의 실행이든 그 토큰으로 주인의 문서를 읽는다. 주인만 쓰는 profile 에만 둔다.
    허용 목록에서 뺀 사용자의 토큰은 저절로 죽지 않는다. 만료와 폐기로만 죽는다.
    커리어 에이전트가 주입이나 `memory_read` 로 이 문서를 읽는 길은 열리지 않는다. 그 에이전트의 collection 은 여전히 `core` 뿐이다.
- **적용 범위**:

  읽기. 경로는 `GET /api/v1/service/memory-documents/{collection}/{documentKey}` 이고 `Authorization: Bearer <서비스 토큰>` 을 받는다.

  | 응답 | 언제 |
  | --- | --- |
  | 200 `{collection, documentKey, title, content, revision, updatedAt}` | 읽을 수 있다. `content` 는 평문이고 `revision` 은 지금 값의 판 번호다. `Cache-Control: no-store` 를 붙인다. 만료가 있는 토큰이면 `X-Service-Token-Expires-At` 머리말에 만료 시각을 적는다 |
  | 401, 본문 없음 | 토큰이 없다, 틀렸다, 폐기됐다, 만료됐다. **넷을 구분하지 않는다** |
  | 403, 본문 없음 | `Origin` 머리말이 있다. 브라우저에서 부르는 길이 아니다 |
  | 404 `MEMORY_NOT_FOUND` | 그 이름의 문서가 없다, 토큰이 그 collection 을 받지 않는다, 민감 문서인데 그 collection 의 민감 허용이 없다, 승인 전이다, `DOCUMENT` 가 아니다. **모두 같은 응답이다** |
  | 409 `MEMORY_ENCRYPTION_UNAVAILABLE` | 읽을 수 있는 민감 문서인데 그 key 가 없다([ADR-055](ADR-055-민감-memory-본문은-저장할-때-암호화하고-key-는-환경-변수로-받는다.md)) |

  토큰 관리. 웹의 JWT 로 부르고, 늘 요청자 자신의 토큰만 다룬다.

  | 경로 | 하는 일 |
  | --- | --- |
  | `POST /api/v1/service-tokens` | `{label, expiresInDays, collections: [{collection, allowSensitive}]}` 를 받아 발급한다. `expiresInDays` 가 `null` 이면 만료가 없다. 응답에만 원문 `token` 이 있다 |
  | `GET /api/v1/service-tokens` | 요청자의 토큰 목록. 원문과 해시는 내지 않는다. `expiresAt`, `lastUsedAt`, `revokedAt` 을 낸다 |
  | `DELETE /api/v1/service-tokens/{id}` | 폐기한다. 줄은 지우지 않는다. 남의 토큰과 없는 토큰은 같은 404 `SERVICE_TOKEN_NOT_FOUND` 다 |

  화면은 만료까지 14일 이하로 남은 토큰과 만료된 토큰에 표시를 단다.
  저장 모양은 `service_token`(사용자, 해시, 이름, 발급·만료·마지막 사용·폐기 시각)과 `service_token_collection`(토큰, collection, 민감 허용)이다.

- **다음**: 관리자가 에이전트의 collection 과 민감 허용을 고치는 경로는 에이전트가 이 문서를 읽어야 할 때 만든다.
  허용 목록에서 뺀 사용자의 토큰을 함께 폐기하는 일은 사용자를 지우는 흐름을 만들 때 넣는다.
