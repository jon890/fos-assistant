## ADR-004: 구독제에서도 API 가격으로 환산해 보인다

- Status: Accepted
- Date: 2026-09-17

처음에는 구독형 바인딩의 비용을 비워 두기로 했고, 사용량 화면은 그 자리에 `구독 (미산정)` 을 적었다.
쓰는 사람이 원한 것은 구독료와 견줄 숫자였다. 그래서 이 결정을 고쳐 쓴다.

### 맥락

지금 연결한 credential 은 구독형이다.
구독형은 실행 한 번에 얼마가 청구되는지 알 수 없다. 달마다 같은 구독료가 나간다.

그렇다고 금액 칸을 비워 두면 화면에 토큰 수만 남는다.
구독료가 쓴 만큼에 견줘 비싼지 싼지를 토큰 수로는 판단할 수 없다.

같은 모델을 API 로 샀다면 얼마였을지는 계산할 수 있다.
Hermes 가 models.dev 카탈로그를 이미 홈서버에 들고 있고, 그 카탈로그에 모델별 단가가 있다.

가격은 바뀐다.
지난 실행의 금액이 오늘 가격표로 다시 계산되면 기록이 흔들린다.

### 결정

`agent_execution` 한 줄에 실행 하나를 적는다.
사용자, 대화, profile, provider, 모델, 상태, 오류 코드,
입력 토큰, cached 입력 토큰, 출력 토큰, 합계 토큰, 소요 시간을 남긴다.

금액은 구독형이든 API 형이든 똑같이 환산해 적는다.
가격표는 models.dev 카탈로그를 읽고, 계산은 실행이 끝나는 시점에 한 번만 한다.

| 칸 | 뜻 |
| --- | --- |
| `cost_mode` | 그 바인딩이 실제로 어떻게 청구되는지. `SUBSCRIPTION` 이면 구독료가 나간다 |
| `estimated_cost_micros` | 통화 단위의 100만분의 1 단위 정수. 가격을 찾지 못하면 비워 둔다 |
| `cost_currency` | 통화 |
| `pricing_version` | 계산에 쓴 가격표와 그것을 받아 온 시점. 예를 들면 `models.dev@2026-09-17` |

`cost_mode` 는 남지만 금액을 계산할지 말지를 더 이상 정하지 않는다.
어떻게 청구되는지를 적을 뿐이다.

**이 금액은 청구액이 아니다.** 구독제에서 실제로 나가는 돈은 구독료다.
화면은 비용 열의 이름과 한 줄 설명으로 그것을 밝힌다.

산정 규칙은 아래와 같다.

- 캐시된 입력 토큰에는 `cache_read` 단가를, 나머지 입력에는 `input` 단가를 적용한다.
  카탈로그에 `cache_read` 가 없는 모델은 캐시 토큰도 `input` 단가로 센다.
  할인한다는 근거가 없는데 깎으면 실제보다 적게 나온다.
- 문맥 길이 구간이 있는 모델은 입력 토큰이 경계를 넘을 때 그 구간의 단가를 쓴다.
  경계값은 카탈로그의 `tiers[].tier.size` 가 준다.
- 가격을 찾지 못하면 금액과 `pricing_version` 을 모두 비워 둔다.
  0 으로 채우지 않는다. 0 은 공짜라는 뜻이라 사실과 다르다.
- 카탈로그를 읽지 못해도 기동은 계속한다. 가격을 모르는 것이 비서를 못 돌릴 이유는 아니다.

금액을 정수로 두는 이유는 데이터베이스에서 반올림이 일어나지 않게 하기 위해서다.
`pricing_version` 을 남기는 이유는 가격이 바뀌어도 지난 기록을 다시 계산하지 않기 위해서다.

실패한 실행도 남긴다.
실패는 토큰 수를 보고하지 않으므로 금액은 비어 있다.
무엇이 실패했는지는 사용량 화면에서 보여야 한다.

### 가격표를 두는 곳

Hermes profile 디렉터리를 컨테이너에 붙이지 않는다.
그 디렉터리에는 `.env` 와 `auth.json` 이 함께 있어서, 통째로 붙이면 credential 까지 컨테이너에 들어간다.

배포할 때 카탈로그 파일만 중립 경로로 복사하고 그쪽을 읽기 전용으로 붙인다.
경로는 `ASSISTANT_PRICING_CATALOG` 환경 변수가 정한다.

`pricing_version` 의 시점은 그 파일의 수정 시각에서 가져온다.
카탈로그를 다시 복사하면 그 다음 실행부터 새 시점이 적힌다.

### 거절한 대안

- 구독형은 금액을 비워 두는 방식은 구독료와 견줄 숫자를 주지 못하므로 쓰지 않는다.
- 조회할 때마다 가격표로 계산하는 방식은 가격이 바뀌면 지난 달 합계가 달라지므로 쓰지 않는다.
- 금액을 부동소수로 두는 방식은 합계에서 오차가 쌓이므로 쓰지 않는다.
- 단가를 코드에 적어 두는 방식은 쓰지 않는다.
  홈서버에 이미 있는 카탈로그와 어긋나고, 모델이 늘 때마다 손으로 따라가야 한다.

### 결과

사용량 화면은 실행마다 환산 금액을 보이고 이번 달 합계를 함께 보인다.
그 합계를 구독료와 나란히 놓으면 구독이 이득인지 판단할 수 있다.

가격을 찾지 못한 실행은 금액 자리에 그 사실을 보이고 합계에서 빠진다.
합계 옆에 빠진 건수를 적어, 합계가 실제보다 작다는 것을 읽는 사람이 알 수 있게 한다.

바인딩의 provider 와 카탈로그의 provider 이름이 다를 수 있다.
`openai-codex` 바인딩이 쓰는 모델은 카탈로그에서 `openai` 아래에 있다.
별칭 표를 코드에 두고, 표에 없는 provider 는 그 이름 그대로 찾는다.

Runs API 의 `usage` 는 실행 하나의 합계만 준다.
한 실행 안에서 모델이 바뀌면 그 구분은 지금 기록에 남지 않고, 환산도 바인딩의 모델 하나로 한다.
필요해지면 `post_llm_call` plugin 으로 호출 단위 기록을 더한다.
