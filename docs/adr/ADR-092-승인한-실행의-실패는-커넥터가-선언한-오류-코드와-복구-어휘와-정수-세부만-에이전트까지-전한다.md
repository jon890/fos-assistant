## ADR-092: 승인한 실행의 실패는 커넥터가 선언한 오류 코드와 복구 어휘와 정수 세부만 에이전트까지 전한다

- **status**: `accepted`
- Date: 2026-10-07
- [ADR-043](../../backend/docs/adr/ADR-043-커넥터는-plugin-의-connector-json-으로-선언하고-control-plane-은-범용-흐름만-갖는다.md) 의 「오류는 공통 어휘로 바꾼다」 를 승인한 실행의 실패에서만 넓힌다. 공통 어휘는 그대로 두고 그 옆에 칸을 더한다.
  [ADR-050](../../backend/docs/adr/ADR-050-커넥터-쓰기는-control-plane-이-승인-줄을-저장하고-승인한-인자로-한-번만-실행한다.md) 의 실패 결과 저장을 바꾼다.

### 결정

**`connector.json` 의 `errors` 항목은 공통 어휘 글 대신 객체 `{category, recovery, details}` 를 쓸 수 있다.
승인한 실행이 그 코드로 실패하면 대시보드 plugin 이 코드와 복구 어휘와 선언한 세부 칸을 Control Plane 에 넘기고, Control Plane 이 다시 검증해 승인 줄에 저장하고 자동 turn 입력에 싣는다.**

| 항목 | 정한 것 |
| --- | --- |
| 오류 코드 | `errors` 의 키는 `^[A-Z][A-Z0-9_]{0,63}$` 이다. 표에 있는 코드만 넘긴다. 표에 없는 코드는 지금처럼 `unavailable` 이고 코드도 넘기지 않는다 |
| `category` | 공통 어휘 다섯 가운데 하나다. 글 항목의 값과 같은 뜻이다 |
| `recovery` | 선택. 복구 어휘 `recheck`, `reconnect`, `fix_input`, `retry_later` 가운데 하나다. 커넥터는 글을 쓰지 않는다. 모델에게 줄 안내 글은 Control Plane 이 어휘마다 정한다 |
| `details` | 선택. 도구 오류 객체에서 옮길 칸 이름의 목록이다. 넷까지, 이름은 `^[a-z][a-z0-9_]{0,31}$` 이고 겹치지 않는다 |
| 세부 값 | 절댓값 10억 이하의 정수와 boolean 만 옮긴다. 글, 실수, 배열, 객체, null 은 그 칸만 버린다 |
| `outcome_unknown` | 객체 항목을 쓸 수 없다. 실행 경로가 504 로 답하는 코드라 실패로 기록되지 않는다 |
| 경로 | 승인한 실행(`execute`)의 실패 답에만 싣는다. 선택지와 확인 도구의 `call` 은 공통 어휘만 준다 |
| 다시 검증 | Control Plane 은 plugin 과 같은 규칙으로 다시 본다. 세부 칸이 넷을 넘으면 세부를 모두 버리고, 모르는 복구 어휘는 버린다 |
| 저장 | 마이그레이션 없이 `FAILED` 줄의 `result_text` 에 `{"kind": "connector_error", "code", "details", "recovery"}` 를 넣는다. `error_code` 는 공통 어휘 그대로다. 읽는 쪽은 `kind` 가 `connector_error` 인 JSON 만 해석한다 |
| 에이전트 입력 | 머리줄의 `오류: <공통 어휘>` 뒤에 `오류 코드: <코드>` 와 `세부: <이름>=<값>, ...` 를 붙이고, 복구 어휘가 있으면 다음 줄에 `복구: <안내>` 를 붙인다. 실패 줄의 글은 `<external-data>` 본문으로 싣지 않는다 |

### 맥락

Gmail 의 `apply_labels_to_query` 는 승인 당시 대상 수와 다시 검색한 수가 다르면 아무것도 바꾸지 않고 `GMAIL_TARGET_COUNT_CHANGED` 와 `actual_count` 를 낸다.
필터 쓰기는 scope 가 모자라면 `GMAIL_FILTER_SCOPE_REQUIRED` 를 낸다.
승인 경로에서 이 둘은 각각 `invalid_input`, `forbidden` 으로만 에이전트에 닿았다.

정보가 사라진 곳은 둘이다.

- 대시보드 plugin 의 `_connector_call_answer` 가 오류 객체에서 코드로 공통 어휘만 찾고 나머지를 버렸다.
- Control Plane 의 `ConnectorActionService.record` 가 실패한 줄의 `result_text` 를 null 로 저장했다.

그래서 에이전트는 수가 바뀐 것인지 인자가 틀린 것인지 몰랐고, Gmail 스킬은 읽기 도구로 모든 쪽을 다시 세는 우회를 적어 두었다.
필터 권한 문제도 읽기 도구를 한 번 더 불러야 일반 403 과 구분됐다.

오류 객체를 통째로 넘기면 외부 API 의 오류 원문, 요청 번호, 커넥터가 정한 임의의 중첩 값이 모델 입력과 DB 에 들어간다.
커넥터마다 무엇이 안전한지는 만든 사람이 알고, 저장과 입력의 모양은 Control Plane 이 정해야 한다.

### 대안 기각

- **오류 객체를 그대로 넘긴다**: Google 의 오류 메시지나 요청 번호가 섞일 수 있다. Gmail 서버는 지금 원문을 싣지 않지만, 다른 커넥터가 그렇게 만든다는 보장이 없다.
- **커넥터가 복구 안내 글을 manifest 에 적는다**: 저장소가 리뷰하는 글이긴 하지만 모델에게 주는 지시가 커넥터마다 달라지고, 공개 커넥터가 생기면 지시 주입 통로가 된다. 어휘 넷이면 지금 필요한 복구를 모두 고를 수 있다.
- **세부 값에 짧은 글을 허용한다**: 글 칸 하나로 원문 메시지를 옮길 수 있다. 지금 필요한 세부는 수(`actual_count`)뿐이다. 글이 필요한 커넥터가 생기면 값마다 선언한 enum 으로 넓힌다.
- **새 칸 `error_detail` 을 Flyway 로 더한다**: 칸의 뜻은 분명해지지만 운영 마이그레이션이 하나 생긴다. 실패 줄의 `result_text` 는 지금까지 늘 비어 있었고, `kind` 로 성공 결과 글과 구분하면 같은 일을 한다.
- **`error_code` 칸에 커넥터 코드를 넣는다**: 화면과 알림이 공통 어휘로 읽는 칸이다. 커넥터 코드를 넣으면 모든 읽는 쪽이 두 종류의 값을 알아야 한다.

### 결과

- 얻는 것:
  - 대상 수가 바뀐 실패가 지금 수와 함께 에이전트에 닿는다. 에이전트는 다시 세지 않고 지금 수를 알리고 다시 조회를 제안한다.
  - 필터 권한 부족과 일반 403 이 코드로 구분된다. 연결을 다시 등록하라는 안내가 읽기 도구를 거치지 않고 바로 나온다.
  - 다른 커넥터는 `errors` 항목 하나를 객체로 바꾸면 같은 길을 쓴다. Control Plane 은 커넥터를 모른다.
- 감당할 것:
  - `errors` 의 키 형식이 새로 엄격해졌다. 대문자, 숫자, 밑줄 밖의 글자가 든 코드를 선언한 커넥터는 카탈로그에서 빠진다. 저장소의 커넥터는 모두 맞는다. 저장소 밖 커넥터를 운영에 둔다면 배포 전에 확인한다.
  - 옛 대시보드 plugin 은 객체 항목을 거절해 그 커넥터를 카탈로그에서 뺀다. plugin 과 커넥터를 한 배포로 올린다. 옛 Control Plane 은 새 칸을 읽지 않으므로 그동안 지금처럼 공통 어휘만 전한다.
  - 실패 줄의 `result_text` 가 JSON 이다. 승인 줄 응답에도 그대로 나간다. 화면은 이 칸을 그리지 않는다.
  - 승인 없이 에이전트가 직접 부른 도구의 오류는 이 길을 거치지 않는다. Hermes 가 MCP 결과를 그대로 모델에 준다. 원문을 싣지 않는 것은 커넥터 서버의 책임이고 [`hermes/connectors/README.md`](../../hermes/connectors/README.md) 가 정한다.
