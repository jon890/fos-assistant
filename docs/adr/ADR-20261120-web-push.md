## ADR-20261120 / web-push: 알림을 그대로 웹 푸시로 보내고 기기는 사용자 줄의 JSON 칸에 두며 암호화는 JDK 로 한다

- **status**: `accepted`
- Date: 2026-11-20
- **decision-type**: `architecture`
- **areas**: `security`, `data`, `operations`
- **현재 규칙의 원본**: 설계 [`docs/features/attention/design.md`](../features/attention/design.md), 스펙 [`spec.md`](../features/attention/spec.md)(사용자 확인 2026-11-20), 칸의 뜻은 [`backend/docs/data-schema.md`](../../backend/docs/data-schema.md) 의 `app_user`
- [ADR-070](ADR-070-알림은-control-plane-의-notification-표가-원장이고-웹은-사용자-단위-SSE-로-받는다.md) 의 알림 원장에 바깥 채널 하나를 더한다. [ADR-072](ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md) 가 남긴 열린 질문 셋에 답한다. 먼저 알리기의 판정은 여전히 화면 안에서만 보인다

### 결정

**`notification` 표에 알림이 커밋되면 Control Plane 이 그 사용자가 등록한 브라우저 기기로 같은 제목과 본문을 웹 푸시로 보낸다.**

| 항목 | 정한 것 |
| --- | --- |
| 무엇을 보내나 | 알림의 제목과 본문 그대로. 사용자가 끈 묶음과 조용한 시간만 거른다 |
| 사람의 승인 | 보낼 때마다 묻지 않는다. 글은 코드에 정한 문구이고, 모델이 쓴 글이나 도구 인자 원문이 아니다 |
| 서명 키 | VAPID 비밀 키는 데이터베이스 밖의 파일에 두고 그 경로를 환경 변수로 받는다. 웹에는 공개 키만 준다 |
| 기기와 설정 | 새 테이블 없이 `app_user` 의 JSON 칸 둘. 전용 쿼리로만 읽고 쓰며 쓰는 쪽이 사용자 줄을 잠근다. 같은 주소가 두 사용자에게 남지 않게 등록을 서버 안에서 하나씩 돌리고, 보낼 때도 겹침을 다시 본다 |
| 암호화와 서명 | RFC 8291 과 RFC 8292 를 JDK 암호 API 로 직접 구현한다 |
| 보낼 주소 | 허용한 푸시 서비스 호스트(정확히 같거나 `.` 경계 접미사)의 443 포트 `https` 주소만 등록받고, 보낼 때 다시 검사한다. redirect 는 따르지 않는다 |
| 실패 | 알림을 만든 일과 떨어져 커밋 뒤에 돈다. 404·410 은 기기를 지우고 일시 실패만 두 번 다시 보낸다 |

### 맥락

알림은 웹을 열어야만 보였다. ADR-072 는 바깥 채널을 열기 전에 credential 자리, 알림에 담을 내용, 외부로 나가는 글의 승인을 정하라고 남겼고, 사용자가 2026-11-20 에 휴대폰 알림을 고르며 이 셋을 정했다(스펙 DECISION3·DECISION5·DECISION16).
가족 모두가 아이폰과 PC 브라우저로 받는다. 아이폰은 홈 화면에 추가한 웹 앱에서만 웹 푸시를 받는다.
테이블을 늘리지 않는다는 사용자 결정(2026-11-01)이 있고, 사용자는 몇 명뿐이다.

### 대안 기각

- **기기를 새 테이블(`push_device`)에 둔다**: 주소의 유일 제약을 DB 가 지키지만 테이블이 는다. 사용자가 몇 명이라 전체를 `LIKE` 로 찾아도 몇 줄이고, 사용자 줄을 잠그고 전용 쿼리로 쓰는 관례(주문 상한 컬럼)가 이미 있다. 사용자가 JSON 칸을 골랐다(2026-11-20)
- **Java 웹 푸시 라이브러리를 쓴다**: 널리 쓰인 라이브러리는 관리가 멈췄고 BouncyCastle 과 별도 HTTP 클라이언트를 끌고 온다. 필요한 암호(P-256 ECDH, HKDF, AES-GCM, ES256)는 JDK 에 모두 있고 RFC 8291 부록의 예시 값으로 결과를 검증할 수 있다
- **푸시 글에 제목만 넣거나 「새 알림 1건」 만 넣는다**: 사용자가 잠금 화면에 제목과 본문까지 보여도 된다고 정했다. 본문에는 이미 대화 내용, 금액, 도구 인자 원문을 넣지 않는 규칙이 있다
- **보낼 때마다 사람이 승인한다(ADR-065 의 outbound 처럼)**: 받는 사람이 자기 자신이고 글이 고정 문구라 승인할 내용이 없다. 승인하면 알림의 목적이 사라진다
- **푸시 서비스 주소를 검사하지 않는다**: Control Plane 이 사용자가 준 주소로 POST 하므로 내부망 주소를 넣으면 서버가 그곳을 부른다
- **조용한 시간에 미룬 푸시를 아침에 몰아 보낸다**: 사용자가 고르지 않았다(스펙 DECISION8)

### 결과

- 얻는 것:
  - 새 알림 종류가 생기면 묶음 하나만 정하면 푸시로도 온다
  - 의존과 배포가 늘지 않는다. 키가 없으면 보내기만 꺼진 채 기동한다
- 감당할 것:
  - 기기 주소의 유일함을 DB 가 아니라 서버 안의 등록 잠금과 보낼 때의 겹침 검사가 지킨다. 서버 한 대 전제(ADR-070)에 기댄다. 서버를 늘리거나 사용자 수가 크게 늘면 새 테이블을 다시 검토한다
  - `data-schema.md` 의 「본체와 1:N 이면 새 테이블」 기준의 예외다. 예외와 근거를 그 문서에 적는다
  - 암호화 코드를 우리가 유지한다. 예시 값 테스트가 깨지면 보내기가 모두 실패한다
  - 허용 호스트 밖의 새 브라우저 푸시 서비스는 설정에 더해야 등록된다
  - 푸시는 사라질 수 있다. 원장은 여전히 `notification` 표다
- **확인 방법**: RFC 8291 예시 값 단위 테스트, 가짜 푸시 서버 통합 테스트, 등록과 옮기기의 통합 테스트, 배포 뒤 실제 기기 확인. 테스트 이름은 구현 PR 이 더한다
