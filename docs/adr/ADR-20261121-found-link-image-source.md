## ADR-20261121 / found-link-image-source: 비서가 찾은 주소의 사진은 fos-ctx 가 결과에서 뽑아 알린 주소일 때만 받는다

- **status**: `accepted`
- Date: 2026-11-21
- **decision-type**: `architecture`
- **areas**: `security`
- **현재 규칙의 원본**: 설계 [`docs/features/agent-found-image/design.md`](../features/agent-found-image/design.md), 스펙 [`spec.md`](../features/agent-found-image/spec.md) 의 REQ2, REQ3, DECISION4, DECISION5, DECISION18, DECISION19, DECISION25(사용자 확인 2026-11-21), [`fos-ctx` README](../../hermes/plugins/fos-ctx/README.md) 의 「찾은 주소를 알린다」
- 비서가 찾은 주소를 받지 않기로 한 [ADR-20261120 / link-image-source](ADR-20261120-link-image-source.md) 의 그 항목만 대체한다. 내부망 차단, 금지 목록, 받는 것, 남기는 것은 그 ADR 그대로다

### 결정

**fos-ctx 의 결과 hook 이 웹 검색과 페이지 읽기의 결과에서 주소를 뽑아 서명한 호출 맥락과 함께 Control Plane 에 알린다. Control Plane 은 그 주소의 해시를 대화 행에 남기고, 모델이 `link:` 로 가리킨 주소가 사용자 메시지에 없으면 이 해시에 있을 때만 사용자가 보낸 링크와 같은 검사로 받는다.**

| 항목 | 정한 것 |
| --- | --- |
| 찾은 주소 | 요청자의 그 대화에서 돈 `web_search` 결과의 주소와 `web_extract` 가 읽은 본문 안의 주소. 비서가 읽기 도구에 적어 넣은 주소 자체와, 본문이 되풀이한 그 페이지 자신의 주소는 아니다 |
| 누가 뽑나 | Hermes 안의 fos-ctx. 뽑기만 하고 판정은 Control Plane 이 한다 |
| 누구의 대화인가 | 요청 본문이 정하지 못한다. 서명한 호출 맥락의 origin 실행에서 읽는다 |
| 남기는 것 | 정해진 꼴로 바꾼 주소의 해시. 주소 원문은 남기지 않는다. 대화마다 상한이 있고 오래된 것부터 버린다 |
| 같은 주소 | 사용자 메시지의 링크 판정과 같은 규칙에, 결과만으로 정해지는 변환(엔티티 풀기, `//`, 상대 주소)을 더한다 |
| 받기 | [ADR-20261120 / link-image-source](ADR-20261120-link-image-source.md) 의 받기와 검사를 그대로 쓴다 |

### 맥락

사용자가 링크를 직접 보내야만 상품 사진이 참고로 들어가, 「찾아서 적용해 줘」 가 되지 않았다(스펙 「목표」).
모델이 고른 주소를 그대로 열면 페이지의 글에 조종된 모델이 대화 내용을 주소에 붙여 바깥으로 보낼 수 있다. 그래서 「남이 쓴 결과에 실제로 있던 주소」 인지 모델이 아닌 쪽이 확인해야 한다.
Control Plane 이 받는 도구 사건의 결과는 500자로 잘려 그 확인에 쓸 수 없다.

### 대안 기각

- Control Plane 이 도구 사건의 결과에서 주소를 읽는다: 잘린 글이라 검색 결과의 뒤쪽 주소가 빠지고, 읽은 본문의 사진 주소는 거의 남지 않는다.
- fos-ctx 가 프로세스 메모리에 찾은 주소를 기억하고 받기 직전에 확인한다: 대화의 앞선 답에서 찾은 주소(스펙 DECISION4)는 Hermes 를 다시 띄우면 사라진다. 판정이 두 곳으로 나뉜다.
- 주소 원문을 대화나 실행 사건에 남긴다: 판정에는 있었는지만 필요하다. 검색한 주소가 대화마다 쌓이고 암호화할 칸이 는다.
- 찾은 주소를 담는 새 표를 만든다: 대화마다 한 덩어리로 읽고 대화와 함께 지우면 되어 칸 하나로 충분하다.
- 모델이 고른 주소를 내부망 검사만 거쳐 연다: 지어낸 주소가 통과해 위 맥락의 위험이 그대로 남는다.

### 결과

- 얻는 것: 비서가 찾은 상품 사진이 사용자가 보낸 링크와 같은 길로 들어간다. 판정과 받기가 Control Plane 한 곳에 남는다.
- 감당할 것: 서버가 여는 주소의 범위가 「사용자가 보낸 링크」 에서 「비서가 읽은 웹 결과의 주소」 로 넓어진다. 나쁜 페이지가 본문에 심은 주소가 그 대화 내내 후보가 된다. 받는 것은 공개 주소의 사진뿐이고 내부망 판정과 금지 목록에 기댄다. 웹 도구마다 결과 hook 이 Control Plane 을 한 번 더 부른다. Hermes 를 올려 두 도구의 결과 모양이 바뀌면 주소가 뽑히지 않아 기능이 조용히 멈추므로 계약 테스트가 지킨다. 검색 서비스를 결과가 Hermes 를 거치지 않는 것으로 바꾸면 검색 결과의 주소는 남지 않는다.
- 확인 방법: 주소 판정의 단위 테스트, 알리기와 받기의 통합 테스트(다른 대화와 다른 사용자의 주소는 받지 않는다), fos-ctx 의 뽑기 테스트와 상류 결과 모양의 계약 테스트. 실제 상품을 찾아 그리는 왕복은 배포 뒤 운영에서 확인한다.
