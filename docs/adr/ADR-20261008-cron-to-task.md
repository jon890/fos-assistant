## ADR-20261008 / cron-to-task: Hermes cron 자동화는 예약 작업으로 옮기고, 결과는 assistant 안에서만 받는다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-076](../../backend/docs/adr/ADR-076-예약-작업은-control-plane-이-갖고-발화한-실행은-대화-turn-경로로-돈다.md) 의 예약 작업이 Hermes cron 을 대신한다. 예약 작업에 모델 단계 칸과 「보고할 것 없음」 완료를 더한다.

### 결정

**Hermes 기본 profile 의 cron 으로 돌던 자동화를 assistant 예약 작업으로 옮긴다. 결과는 대화와 알림으로만 받고, 외부 채널 전달은 두지 않는다.**

| 항목 | 정한 것 |
| --- | --- |
| 자동화를 갖는 곳 | Control Plane 의 예약 작업(`task.kind = TURN`). Hermes cron 은 옮긴 뒤 지운다 |
| 실행 profile | 작업의 에이전트가 가리키는 profile. 기본 profile 에서 돌지 않는다 |
| 결과를 받는 곳 | 그 발화의 대화와 assistant 알림. HTML 리포트는 결과물 파일로 그 대화에 묶는다 |
| 외부 전달 | 두지 않는다. 채팅 서비스와 메신저 전달, 공개 페이지 게시는 예약 작업이 하지 않는다 |
| 작업마다 다른 모델 | 작업의 `modelTier`(`FAST`, `BALANCED`, `DEEP`). 비우면 새 대화의 기본 규칙을 따른다 |
| 보고할 것이 없는 날 | 에이전트가 답 전체를 `[SILENT]` 로 끝내면 알림을 만들지 않고, 실행마다 새 대화면 그 대화를 목록에서 숨긴다 |

규칙의 자세한 모양은 [예약 작업](../features/schedule.md) 의 「모델 단계」 와 「보고할 것 없음」 이 갖는다.

### 맥락

Hermes cron 은 기본 profile 에서 돌았다.
셸이 사용자별 실행 공간에 격리되지 않았고([ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md)), 실행 기록과 비용이 Control Plane 에 남지 않았다.
작업을 만들고 멈추는 일도 Hermes 명령으로만 할 수 있었다.

옮길 때 Hermes cron 에만 있던 기능이 셋 드러났다.

- 작업마다 모델과 강도를 정했다. 같은 에이전트에서 가벼운 작업과 무거운 작업을 다르게 돌렸다.
- 답이 `[SILENT]` 이거나 비면 전달하지 않았다. 새 글이 없는 날은 아무것도 오지 않았다.
- 결과를 외부 채팅 채널과 메신저로 보냈다.

앞의 둘은 예약 작업에 칸과 규칙을 더해 받는다. 외부 전달은 받지 않기로 사용자가 정했다(2026-10-08).

### 대안 기각

- **Hermes cron 을 그대로 두고 named profile 로만 옮긴다**: 실행 기록, 비용, 승인 카드가 Control Plane 을 지나지 않는다. 작업 관리가 두 곳으로 나뉜다.
- **예약 작업에 외부 전달 대상을 둔다**: 웹훅과 메신저 토큰을 어디에 둘지 새로 정해야 한다. 비밀값을 DB 에 두지 않는 규칙과 맞추려면 profile 파일과 설치 절차가 늘어난다. 결과를 assistant 안에서 받기로 했으므로 만들지 않는다.
- **보고할 것이 없는 날을 알림 설정 `ON_FAILURE` 로 대신한다**: 새 결과가 있는 날의 알림도 사라지고 빈 대화가 매일 목록에 쌓인다.
- **보고할 것이 없는 대화를 지운다**: 그 발화가 무엇을 보고 그렇게 판단했는지 다시 볼 수 없다. 실행 기록이 지워진 대화를 가리키게 된다.
- **표시 대신 답이 비었는지로 판정한다**: turn 이 실패해 답이 비는 경우와 구분하지 못한다. 에이전트가 명시적으로 고른 경우만 조용히 끝낸다.
- **모델과 effort 를 작업마다 직접 적는다**: 모델 이름이 작업에 묶여 그룹의 단계 정의를 바꿔도 따라가지 않는다. 숨긴 모델 판정도 작업마다 다시 해야 한다.

### 결과

- 얻는 것:
  - 자동화가 실행 공간 격리, 실행 기록, 비용, 승인 카드를 대화와 같은 경로로 받는다.
  - 사용자가 작업을 화면에서 만들고 멈추고 고친다.
  - 새 결과가 없는 날 알림과 사이드바가 조용하다.
- 감당할 것:
  - 외부 채널로 받던 결과는 assistant 를 열어야 본다.
  - 공개 페이지로 게시하던 리포트는 결과물 파일의 보관 기간(30일)이 지나면 볼 수 없다.
  - `[SILENT]` 판정은 에이전트가 지시를 따르는 데 기댄다. 표시와 함께 다른 글을 쓰면 보통 완료로 알린다.
  - 숨긴 대화는 작업의 실행 기록에서만 열린다. 사용자가 그 대화에 질문을 보내면 다시 목록에 보인다.
