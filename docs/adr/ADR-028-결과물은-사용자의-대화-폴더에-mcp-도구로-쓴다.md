## ADR-028: 결과물은 사용자의 대화 폴더에 MCP 도구로 쓴다

- **status**: `accepted`
- **결정**: 기존 `fos-assistant-memory` MCP 서버에 `artifact_write` 를 더해 이 서버가 등록된 profile 의 에이전트가 결과물을 쓰게 한다.
  MCP 토큰이 정한 사용자가 주인인 대화만 받고, Control Plane 이 그 대화의 결과물 폴더에 대신 쓴다.
  Hermes 의 `file`, `terminal` toolset 을 닫은 profile 은 그대로 둔다.

### 맥락

가족용 에이전트에게 `test/index.html` 을 만들게 했지만 파일 생성 도구가 없어 만들지 못했다.
[ADR-027](ADR-027-에이전트가-만든-html-은-대화별-폴더에-두고-스크립트-없이-보인다.md) 은 결과물을 보이는 길을 정했지만,
일반 파일 도구가 없는 profile 에서 결과물을 쓰는 길은 없었다.

[ADR-020](ADR-020-사진은-공유-디렉터리에-두고-에이전트가-파일로-읽는다.md) 의 「감당할 것」은
그 profile 이 이미 `terminal` 과 `file` 도구를 갖고 있다고 전제한다.
가족용 profile 에는 이 전제가 맞지 않는다.
사진 첨부의 저장 결정은 유지하고, 결과물 쓰기에 필요한 권한은 이 결정으로 별도로 정한다.

Hermes v0.21.0 의 `HERMES_WRITE_SAFE_ROOT` 는 프로세스 환경값이다.
profile 별 쓰기 범위를 정하지 못하며, 읽는 범위를 대화 폴더로 제한하는 기능도 아니다.
근거와 MCP 계약은 [`tools-and-skills.md`](../hermes/tools-and-skills.md#결과물-쓰기-도구) 에 있다.

### 사용자가 정하는 범위

**대화의 공개 식별자를 받되, 쓰기 권한은 토큰과 대화 주인으로 판정한다.**
실행 입력의 `[결과물 폴더]` 단락에 대화의 `publicId` 를 적는다.
도구 인자로 받은 UUID 는 내부 대화 번호로 바꾼 뒤 기존 폴더 배치를 그대로 쓴다.
없는 대화, 지운 대화, 남의 대화는 같은 오류로 거절한다.
같은 사용자의 다른 대화에 쓰는 것은 허용한다.

MCP 호출에는 실행을 가리키는 값이 없다.
도구가 현재 turn 을 추측하거나 대화 UUID 를 실행에 연결된 권한 증명으로 취급하지 않는다.
이 선택은 [ADR-017](ADR-017-무엇을-할지는-hermes-가-정하고-control-plane-은-경계만-갖는다.md) 의 역할 분담을 따른다.
무엇을 쓸지는 Hermes 가 정하고, 쓸 수 있는 사용자의 폴더는 Control Plane 이 정한다.

### 저장 방식과 경로

| 방식 | 인자 | 확장자 |
| --- | --- | --- |
| 본문 | `content` 문자열을 UTF-8 로 저장 | `html`, `css` |
| 주소 | `source_url` 을 Control Plane 이 내려받아 저장 | `png`, `jpg`, `jpeg`, `gif`, `webp` |

두 방식은 한 호출에 하나만 받으며 파일 하나의 상한은 5MB 다.
base64 는 받지 않는다. 같은 경로에 쓰면 파일을 바꾼다.
실패한 쓰기는 기존 파일을 훼손하지 않아야 한다.

경로 판정은 읽기와 같이 `ArtifactStore` 한 곳에 둔다.
상대 경로만 받고, 대화 폴더 밖을 가리키거나 허용하지 않은 확장자면 거절한다.
부모 폴더를 만들기 전에도 이미 있는 부모의 링크를 검사해 밖에 폴더를 만들지 않는다.
만든 뒤 실제 부모 경로가 대화 폴더 안인지 다시 보고, 대상이 심볼릭 링크면 거절한다.

### URL 다운로드의 경계

**허용 호스트와 공개 IP 를 모두 만족하는 HTTPS 주소만 연결한다.**
허용 목록은 설정으로 받고 기본값은 비워 둔다.
Hermes 소스는 FAL 응답의 URL 을 그대로 전달하고, 확인한 FAL 응답 예시에는 호스트가 비어 있다.
실제 출력 호스트를 확정할 근거가 없어 기본값을 추정하지 않는다.
목록이 비어 있으면 주소 방식만 거절하며 본문 방식은 계속 쓸 수 있다.

DNS 로 푼 주소에 사설, loopback, link-local 등 공개 인터넷에서 쓸 수 없는 주소가 있으면 거절한다.
검사한 IP 로 직접 연결해 DNS 재바인딩을 막고 원래 호스트로 TLS 인증서를 검사한다.
redirect 를 따라가지 않는다.
확장자에 맞는 이미지 `Content-Type`, 5MB 본문 상한, 연결과 읽기 제한 시간을 함께 적용한다.

### 대안 기각

| 대안 | 기각 이유 |
| --- | --- |
| `file`, `terminal` toolset 을 연다 | 결과물 폴더보다 넓은 파일과 명령 실행 권한을 준다 |
| `HERMES_WRITE_SAFE_ROOT` 를 좁힌다 | 프로세스 전체에 적용되어 profile 별 대화 폴더를 제한하지 못한다 |
| profile 마다 gateway 를 둔다 | 결과물 하나를 위해 실행 프로세스와 설정 관리가 늘어난다 |
| turn 별 쓰기 권한 표를 만든다 | MCP 에 실행 식별자가 없어 전달 계약과 만료, 저장 상태를 새로 관리해야 한다 |
| 폴더를 사용자별로 바꾼다 | 대화별 탐색, 주인 확인, 답 연결과 보관 계약을 바꾼다 |
| base64 를 받는다 | 도구 입력과 모델 문맥이 커진다. 문자열과 URL 로 필요한 쓰기를 처리한다 |

### 결과

- 얻는 것: 일반 파일 도구가 없는 에이전트도 HTML 과 CSS 를 만들고 이미지 URL 을 결과물로 저장한다.
  대화별 폴더와 `ArtifactService.recordTurn` 으로 HTML 을 답에 묶는 흐름을 재사용한다
- 감당할 것:
  - 같은 사용자의 다른 대화 폴더에 쓸 수 있다. 그 파일은 그 대화의 turn 에서 바뀐 HTML 을 찾을 때만 답에 묶인다
  - SSRF 방어와 허용 호스트 설정을 계속 관리해야 한다. 공급자의 호스트 변경은 설정 검토가 필요하다
  - DNS 조회는 전용 daemon 스레드 최대 4개에서 실행하며 대기 작업은 받지 않는다.
    모두 사용 중이면 새 요청을 바로 실패로 돌린다.
    `InetAddress` 조회가 차단되면 취소만으로 작업이 끝난다고 보장할 수 없으므로,
    호출자는 30초 제한으로 실패하고 남은 조회는 이 스레드 안에만 머문다
  - 기존 파일을 바꾸면 이전 답에서 열어도 최신 내용을 본다. 동시 쓰기는 마지막으로 성공한 파일 교체가 남는다
  - JDK 21 에는 디렉터리 핸들로 새 하위 폴더를 만드는 API 가 없다. 그 폴더에 직접 쓸 수 있는 로컬 프로세스는 이미 파일 도구로 쓸 권한이 있으므로, 새 폴더 생성과 최종 파일 교체 중 부모를 바꿔치기하는 공격은 이번 위협 모델에서 제외한다
  - `SecureDirectoryStream` 을 지원하면 최종 쓰기와 교체에 사용한다. 지원하지 않는 환경에서는 링크를 전후로 검사하고 같은 폴더의 임시 파일을 `ATOMIC_MOVE` 로 교체한다
  - MCP 서버가 등록된 profile 에 저장 도구를 열어도 이미지 생성 권한이 생기는 것은 아니다.
    `image_gen` 을 에이전트마다 켜는 설정 화면은 별도 계획이 맡는다
  - HTML 을 스크립트 없이 보이는 규칙과 30일 보관은 ADR-027 을 따른다
