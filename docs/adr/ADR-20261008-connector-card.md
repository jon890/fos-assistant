## ADR-20261008: 커넥터 아이콘은 plugin 안의 파일을 카탈로그에 실어 같은 출처의 이미지로만 그리고, 링크는 https 만 받는다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-043](ADR-043-커넥터는-plugin-의-connector-json-으로-선언하고-control-plane-은-범용-흐름만-갖는다.md) 의 `connector.json` 에 화면용 선택 칸 둘을 더한다.

### 결정

**`connector.json` 은 선택 칸 `icon` 과 `link` 를 갖는다. 아이콘은 plugin 디렉터리 안의 SVG 나 PNG 파일이고, 대시보드 plugin 이 그 내용을 카탈로그에 실어 보낸다. Control Plane 은 다시 검증해 data URL 로 화면에 넘기고, 화면은 그것을 `<img>` 로만 그린다.**

| 항목 | 정한 것 |
| --- | --- |
| `icon` | plugin 디렉터리 기준 상대 경로 하나. 확장자는 `.svg` 나 `.png`. 링크가 아니고 plugin 안의 파일이며 32 KiB 이하다 |
| `link` | 커넥터 소개나 그 서비스의 주소. `https://` 이고 호스트가 있으며 사용자 정보(`user@`)가 없다. 500자 이하다 |
| 운반 | 카탈로그가 `icon: {media_type, data}`(base64)와 `link` 를 낸다. 브라우저는 외부 주소를 부르지 않는다 |
| 대시보드의 검증 | 경로, 크기, 형식 가운데 하나라도 틀리면 그 커넥터를 카탈로그에 내지 않는다. 다른 `connector.json` 칸과 같은 규칙이다 |
| Control Plane 의 검증 | 같은 규칙으로 다시 본다. 틀리면 그 칸만 null 로 두고 커넥터는 그대로 낸다. 장식 칸 때문에 쓰던 연결이 사라지지 않게 한다 |
| 화면 | 아이콘은 `<img>` 로만 그린다. `<object>`, `<iframe>`, 인라인 SVG 로 넣지 않는다. 아이콘이 없으면 기본 아이콘이다. 링크는 새 탭으로 열고 `rel="noopener noreferrer"` 다 |

**실제 경계는 `<img>` 다.** 브라우저는 `<img>` 로 그린 SVG 의 스크립트를 돌리지 않고 외부 자원을 부르지 않는다.
아래 SVG 검사는 그 경계 앞의 두 번째 선이다. 대소문자를 가리지 않는다.

- UTF-8 글이고, 앞의 BOM, 공백, XML 선언(`<?xml ... ?>`), 주석(`<!-- ... -->`)을 앞에서부터 차례로 건너뛴 뒤 `<svg` 가 오고 그다음 글자가 공백, `>`, `/` 가운데 하나다. 이 앞부분은 정규식이 아니라 한 번 훑는 반복으로 본다. 주석이 많은 파일에서 정규식의 되추적이 시간과 스택을 다 쓰기 때문이다
- `<!DOCTYPE`, `<!ENTITY`, `<script`, `<foreignObject`, `<iframe`, `<embed`, `<object`, `<set`, `<animate`, `@import`, `javascript:`, `&#`, `\` 가 없다. 문자 참조와 CSS escape 로 아래 규칙을 비켜 가지 못하게 `&#` 와 `\` 를 통째로 받지 않는다
- `on` 으로 시작하는 이벤트 속성(공백 뒤 `on<글자>=`)이 없다
- `href` 와 `xlink:href` 의 값, `url(...)` 의 대상은 공백과 따옴표 다음에 `#` 으로 시작하는 문서 안 참조뿐이다
- 공백과 대소문자는 ASCII 기준으로 본다. 대시보드(Python)와 Control Plane(Java)이 같은 입력에 같은 답을 내게 하기 위해서다

PNG 는 파일 처음 8바이트가 PNG 서명이어야 한다.

### 맥락

사용자가 커넥터를 설명, 아이콘, 링크가 있는 카드로 보고 싶어 했다(2026-10-08).
커넥터는 이 저장소 밖의 plugin 일 수 있다. 그 plugin 이 준 SVG 를 그대로 화면에 넣으면 스크립트가 같은 출처에서 돈다.
아이콘 주소를 외부 URL 로 받으면 화면을 열 때마다 브라우저가 그 서버를 불러 누가 언제 보는지가 새어 나간다.

### 대안 기각

- **아이콘을 외부 URL 로 받는다**: 위 맥락대로 화면을 연 사실이 외부로 나가고, 그 주소의 내용이 바뀌어도 검증하지 못한다.
- **Control Plane 에 아이콘 전용 경로(`/api/v1/connectors/{id}/icon`)를 둔다**: 그 주소를 직접 열면 SVG 가 문서로 열려 스크립트 검사에만 기대게 된다. 경로와 응답 머리, web 의 중계 경로가 하나씩 더 생긴다. 아이콘은 수십 KB 이하라 목록 응답에 싣는 비용이 작다.
- **SVG 를 정리(sanitize)해 고쳐 쓴다**: 고친 결과가 맞는지 다시 검사해야 하고, 정리기의 빈틈이 곧 보안 구멍이다. 거절하고 커넥터 작성자가 단순한 SVG 를 쓰게 한다.
- **요약과 긴 설명 칸을 따로 둔다**: 지금 `description` 이 이미 한두 문장이다. 쓸 곳이 생길 때 더한다.

### 결과

- 얻는 것: 커넥터마다 무엇이고 어디의 서비스인지 화면에서 알아본다. 브라우저는 우리 출처 밖을 부르지 않는다.
- 감당할 것:
  - 아이콘 검사 규칙이 대시보드 plugin(Python)과 Control Plane(Java) 두 곳에 있다. 규칙을 바꾸면 두 곳과 이 표를 함께 고친다.
  - 카탈로그와 연결 목록 응답이 커넥터마다 아이콘 크기만큼 커진다. 상한 32 KiB 가 그 상한이다.
  - 대시보드는 카탈로그를 읽을 때마다 아이콘 파일을 읽고 검사한다. 커넥터가 많아지면 이 비용을 다시 본다.
  - 금지 목록은 모든 SVG 기능을 알지 못한다. 새 우회가 보이면 목록을 넓히고, 화면은 `<img>` 밖으로 아이콘을 넣지 않는다.
  - 상표 로고 파일을 복사하지 않는다. 이 저장소의 커넥터 아이콘은 직접 그린 단순한 도형이다.
  - 새 칸을 모르는 옛 대시보드 plugin 은 두 칸을 내지 않고, Control Plane 은 없는 칸을 null 로 읽는다. 순서 없이 배포해도 된다.
