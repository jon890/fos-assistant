## ADR-013: 실행 사건은 우리 모델로 정규화해 저장한다

- **status**: `accepted`
- **결정**: Hermes 가 스트림으로 보내는 사건을 우리가 정한 `execution_event` 로 옮겨 적는다.
  Hermes 의 원래 사건 이름을 화면이 직접 읽지 않는다.
  받은 payload 를 통째로 저장하지 않고 필요한 칸만 고른다.

### 맥락

[ADR-008](ADR-008-스트리밍은-보여주기용이고-저장은-실행-결과로-한다.md) 이
스트림은 보여주기용이고 저장은 실행 결과로 한다고 정했다.
그래서 지금 스트림으로 온 사건은 화면을 지나가고 사라진다.

실행이 끝난 뒤에 무엇을 했는지 다시 볼 수 없다.
포지션 추천 하나가 15분 넘게 돌며 도구를 여러 번 불렀는데,
끝나고 나면 답 한 덩어리와 토큰 합계만 남는다.
어느 도구가 오래 걸렸는지, 어디서 실패해 다시 했는지 알 방법이 없다.

`ChatService.forward` 가 지금 하는 일이 그 사정을 보여준다.
`type.contains("delta")` 와 `type.startsWith("tool.")` 로 사건 이름을 직접 검사한다.
Hermes 가 이름을 바꾸면 화면이 조용히 아무것도 보여주지 않게 된다.
[ADR-001](ADR-001-hermes를-런타임으로-두고-core를-고치지-않는다.md) 이
Hermes core 를 고치지 않기로 했으므로, 이름이 바뀌는 것을 막을 방법이 우리에게 없다.

### 대안 기각

- **Hermes 의 원래 payload 를 그대로 쌓는다.**
  옮겨 적는 코드가 필요 없지만 저장할 양을 우리가 정하지 못한다.
  도구가 읽어 온 문서 전체가 사건에 실려 오면 그것이 그대로 데이터베이스에 들어간다.
  무엇이 들어올지 모르는 것을 그대로 저장하지 않는다.
- **화면이 Hermes 의 사건 이름을 직접 읽는다.**
  지금 하는 방식이다.
  런타임을 바꾸거나 Hermes 가 이름을 바꾸면 화면을 함께 고쳐야 한다.
- **저장하지 않고 스트림만 유지한다.**
  요구가 바로 「실행이 끝난 뒤에도 다시 본다」 이다.

### 결과

얻는 것

- 실행이 끝난 뒤에도 도구와 하위 에이전트의 흐름을 다시 볼 수 있다.
- 화면이 우리 사건 이름만 안다. Hermes 가 이름을 바꿔도 옮겨 적는 한 곳만 고친다.
- 어느 도구가 얼마나 걸렸는지가 남아, 느린 자리를 숫자로 찾을 수 있다.

감당할 것

- Hermes 가 새 사건을 보내기 시작하면 우리가 옮겨 적기 전까지 그것은 저장되지 않는다.
  모르는 사건은 버리고, 버렸다는 사실만 로그로 남긴다.
- 실행 하나에 사건이 여러 줄 쌓인다. 실행 기록보다 훨씬 빨리 는다.
  얼마나 쌓이는지 보고 지우는 규칙이 필요해지면 그때 정한다.
- 실시간 스트리밍은 그대로 둔다.
  화면에 흘리는 경로와 저장하는 경로가 같은 스트림을 두 가지로 쓴다.
  ADR-008 의 결정은 그대로 유효하다. 저장하는 답은 여전히 실행 결과에서 가져온다.
