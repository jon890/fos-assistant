## ADR-033: 사용자가 에이전트를 만들고, 공개해도 만든 사람이 관리한다

- **status**: `accepted`
- **결정**: 모든 사용자가 화면에서 자기 에이전트를 만든다. Control Plane 이 그 에이전트의 Hermes profile 을 만들고 지운다.
  에이전트의 **주인과 공개 범위는 서로 다른 값이다.** 가족용(`GROUP`)으로 공개해도 만든 사람이 주인으로 남아 성격과 도구와 스킬을 계속 관리한다. `ADMIN` 은 모든 에이전트를 관리한다.
  공개와 되돌리기는 주인이 승인 없이 한다. 셸·파일 toolset 이 켜진 에이전트는 공개하지 못한다는 규칙과 `ADMIN` 등급 toolset 은 `ADMIN` 만 켠다는 규칙은 그대로다([ADR-029](ADR-029-에이전트-도구는-control-plane-이-등급으로-판정하고-hermes-설정-api-로-쓴다.md)).
- **맥락**:
  - 지금 에이전트는 `ADMIN` 만 만든다. profile 은 관리자가 운영 쪽에서 만들고 MCP 와 플러그인도 손으로 붙인다. 사용자가 자기 일에 맞는 에이전트를 만들고 스킬을 올려 쓰게 하려면 이 경로가 사용자 손에서 끝나야 한다.
  - 지금 코드는 공개 범위를 `GROUP` 으로 바꾸면 `owner_user_id` 를 비운다. 그러면 편집 판정(`AgentService.isEditableBy`)에 `ADMIN` 만 남아, 만든 사람이 공개하는 순간 자기 에이전트를 고치지 못한다.
  - 편집 판정은 성격, 도구, 스킬이 모두 같은 메서드 하나를 부른다. 판정을 복사하면 한쪽만 바뀐다.
  - 가족이 함께 쓰는 서비스이고 AI 계정도 가족이 함께 쓴다([ADR-002](ADR-002-profile은-나누고-ai-계정은-가족이-함께-쓴다.md)).
- **대안 기각**:
  - **공개하면 관리를 `ADMIN` 에게 넘긴다.** 지금 코드의 동작이다. 사용자가 만든 에이전트를 공개하는 순간 만든 사람이 스킬 하나도 고치지 못한다.
  - **공개와 공개 중 스킬 변경을 `ADMIN` 이 승인한다.** 2026-09-28 에 한때 정했던 원칙이다. 가족끼리는 승인 절차가 쓰는 속도만 늦춘다고 보아 버렸다(2026-09-29 사용자 결정).
  - **만든 사람의 credential 로 돌린다.** 공개하면 다른 가족의 사용도 만든 사람의 구독에서 나가고, credential 을 profile 사이에 옮겨 적는 절차와 갱신 문제가 생긴다. 새 profile 은 가족 공용 credential 로 돈다.
  - **지우면 에이전트 행도 지운다.** 대화, 실행, 사용량이 `agent_id` 로 에이전트 이름을 찾아 보인다. 지움 표시만 하고 행은 남긴다.
- **결과**:
  - 얻는 것:
    - 에이전트를 만들고 공개하는 것이 사용자의 화면 조작으로 끝난다. 그 사이에 홈서버를 만지지 않는다
    - 공개한 에이전트도 만든 사람이 계속 고친다
    - 권한 규칙이 두 줄로 줄어든다. 관리는 만든 사람이 하고 `ADMIN` 은 예비 열쇠를 갖는다. 가족용은 모두 대화하지만 각자의 기억과 대화는 서로 보이지 않는다([ADR-032](ADR-032-mcp-토큰은-profile-을-증명하고-실제-사용자는-부모-실행에서-정한다.md))
  - 감당할 것:
    - **공개한 에이전트의 성격과 스킬은 다른 가족 대화에서 모델에게 주는 지시가 된다.** 그 에이전트에 web toolset 이 켜져 있으면 그 지시가 대화 내용을 바깥 주소로 보내게 할 여지가 있다. 가족이라는 신뢰 경계 안에서 받아들인다
    - 사용자당 에이전트 수에 상한을 둔다. profile 하나마다 Hermes 안에 서비스가 하나 등록되고 디스크를 쓴다. 상한은 설정값이고 `ADMIN` 은 걸리지 않는다
    - Control Plane 이 만든 profile 만 지운다. 관리자가 운영에서 만들어 등록한 에이전트는 지워도 끄기만 하고 profile 을 남긴다. 둘을 구분하는 값을 에이전트 행에 둔다
    - 새 profile 에 MCP 를 등록하고 profile 플러그인을 켜는 일을 Control Plane 이 한다. 운영 쪽 대시보드 플러그인에 그 경로가 먼저 있어야 한다
    - 이 결정 전에 `GROUP` 으로 만든 에이전트는 주인이 비어 있다. 그대로 `ADMIN` 만 관리한다
