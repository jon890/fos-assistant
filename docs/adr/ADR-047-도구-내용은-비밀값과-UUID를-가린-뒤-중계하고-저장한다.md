## ADR-047: 도구 내용은 비밀값과 UUID를 가린 뒤 중계하고 저장한다

- **status**: `accepted`
- **결정**: Hermes 도구 사건을 읽을 때 비밀값과 UUID를 가린다.
  SSE, 실행 기록, 대화의 작업 과정은 가린 값만 받는다.
  관리자도 원문을 받지 않는다.
  [ADR-038](ADR-038-도구의-명령-원문은-관리자에게만-보내고-사용자에게는-사람-말로-보인다.md) 의 역할별 공개 규칙은 가린 값에 적용한다.
- **대체한 것**: [ADR-038](ADR-038-도구의-명령-원문은-관리자에게만-보내고-사용자에게는-사람-말로-보인다.md) 의 원문 저장과 관리자 원문 보기를 대체한다.
- **맥락**:
  - 도구 입력과 결과에 토큰, UUID, 도구 선언이 섞여 작업 과정에 노출됐다.
  - 화면에서만 숨기면 실행 기록과 API 응답에 원문이 남는다.
  - Control Plane은 커넥터 manifest의 `secret: true` 실제 값을 보관하거나 조회하지 않는다.
    짧고 평범한 비밀값은 모양 검사로 식별할 수 없다.
- **처리 계약**:
  - 일반 도구는 비밀 키의 값과 토큰 모양을 `[가림]`으로 바꾼다.
    같은 실행 스트림의 같은 UUID는 같은 `[항목 N]`으로 바꾸고, 다른 UUID는 구분한다.
  - 연결용 에이전트는 도구 내용 전체를 `[연결 도구 내용 가림]`으로 바꾼다.
  - 승인 카드의 인자도 같은 규칙으로 가린다. 다만 상시 허락을 닫은 도구의 승인 줄은 가려지는 글이 있으면 승인하지 못한다([ADR-064](ADR-064-외부로-나가는-도구는-상시-허락을-닫는-선언을-둔다.md)). 가림이 사람이 승인할 글을 감추는 데 쓰이지 않게 한다.
    도구 이름, 성공 여부, 걸린 시간은 남긴다.
    manifest의 비밀값이 자유 문장에 실려도 원문을 전달하지 않는다.
  - 가린 뒤 기존 저장 상한인 500자로 자른다.
    손상된 JSON은 전체를 가리고, 65,536자를 넘는 설명도 전체를 가린다.
    자세한 규칙은 [Runs API 계약](../backend/conversation.md#도구-내용-가리기)에 둔다.
- **대안 기각**:
  - **관리자에게 원문을 준다.** 관리자 화면과 API에도 비밀값이 노출될 수 있다.
  - **커넥터 비밀값을 복사해 비교한다.** Control Plane이 비밀 원문을 갖지 않는 계약을 바꾼다.
  - **모양 검사만 쓴다.** 짧은 비밀값이나 새 토큰 형식을 모두 식별할 수 없다.
- **결과**:
  - V41은 이미 저장된 도구 사건에도 같은 규칙을 적용한다.
    실행별 사건 순서로 UUID 번호를 정하고, 연결용 에이전트의 내용은 전체를 가린다.
    가리기 전 원문은 복원할 수 없어 배포 전에 데이터베이스를 백업해야 한다.
  - 가린 값은 복원할 수 없다. 원문을 조사해야 하면 Hermes 쪽 기록을 확인한다.
  - 긴 인코딩 문자열과 UUID가 업무 정보여도 가려질 수 있다.
    금액, 날짜, 짧은 식별자, 일반 문장은 유지한다.
  - 일반 도구의 모양 검사에는 탐지 한계가 있다.
    새로운 비밀 키와 토큰 형식이 추가되면 규칙과 검사를 함께 보완한다.
  - 답 본문과 하위 에이전트의 목표는 이번 도구 내용 계약의 대상이 아니다.
  - 32자를 넘는 스킬 이름은 토큰 모양이라 `skill_view` 도구 내용에서 가려진다.
    스킬 사용 기록은 가린 내용을 읽지 않는다.
    사건을 읽는 자리가 가리기 전 미리보기에서 이름을 꺼내 Hermes 스킬 이름 규칙으로 검증하고, 맞는 이름만 사건의 별도 칸으로 넘긴다.
    이름이 `...` 로 끝나면 길이 상한에서 잘린 것으로 보고 넘기지 않는다.
    그 칸은 SSE와 실행 기록에 싣지 않고, 연결용 에이전트의 실행에서는 채우지 않는다.
