## ADR-027: 에이전트가 만든 HTML 은 대화별 폴더에 두고 스크립트 없이 보인다

- **status**: `accepted`
- **결정**: 대화마다 결과물 폴더를 하나 두고 실행 입력으로 그 자리를 에이전트에게 알린다.
  turn 이 끝나면 Control Plane 이 그 폴더에서 이번 turn 에 바뀐 HTML 을 찾아 답 메시지에 묶는다.
  화면은 그 HTML 을 앱과 같은 출처의 경로로 받아, 스크립트를 막은 iframe 에 띄운다.
  파일은 대화의 주인만 받고, 30일이 지나면 지운다.

### 맥락

블로그 초안처럼 에이전트가 HTML 파일을 만들어 두는 일이 생겼다.
지금은 그 파일이 Hermes 컨테이너 안의 경로에만 있어 사용자가 대화에서 볼 수 없다.
초안 HTML 은 사진을 함께 보여야 쓸모가 있다. 확인해 보니 초안에는 스크립트와 외부 CSS, 폰트가 없었다.

사진 첨부가 이미 같은 모양을 쓴다. Control Plane 과 Hermes 가 한 디렉터리를 서로 다른 마운트 지점으로 보고,
실행 입력에는 Hermes 쪽 경로를 적는다(ADR-020).

### 대안 기각

- **스크립트를 허용하고 다른 출처로 띄운다.** 다른 출처에서는 로그인 쿠키가 가지 않아
  HTML 이 상대 경로로 부르는 사진을 주인 확인 뒤에 줄 수 없다. 서명한 URL 을 따로 만들어야 한다.
  지금 쓰는 초안에는 스크립트가 없어 그 비용을 낼 까닭이 없다.
- **같은 출처에서 스크립트를 허용한다.** 에이전트가 만든 HTML 의 스크립트가 로그인한 사용자의 권한으로
  이 앱의 API 를 부를 수 있다. 받아들이지 않는다.
- **에이전트가 답에 파일 경로를 적게 하고 그것을 읽는다.** 모델이 적는 형식은 흔들린다.
  turn 이 끝난 뒤 폴더에서 바뀐 파일을 찾는 것이 모델의 말투와 무관하다.
- **HTML 본문을 데이터베이스에 넣는다.** 사진이 함께 있어야 하고 크기가 크다. 사진 첨부처럼 파일로 둔다.
- **turn 이 끝날 때 답 본문의 폴더 절대 경로를 결과물 열기 링크나 파일 이름으로 바꾼다.**
  답은 흘러나오는 동안 이미 화면에 보인다. 끝난 뒤에 바꾸면 사용자가 본 글과 저장된 글이 달라진다.
  저장은 실행 결과로 한다는 [ADR-008](ADR-008-스트리밍은-보여주기용이고-저장은-실행-결과로-한다.md) 과도 어긋난다.
  운영에서 답에 적힌 경로의 절반은 에이전트 작업 공간의 상대 경로였다. 결과물 폴더가 아니어서 바꿀 대상을 찾지 못한다.
  에이전트의 스킬과 스크립트가 경로를 출력하지 않게 고치는 것이 먼저이고, 그쪽은 에이전트 저장소가 맡는다.
  실행 입력의 단락을 바꾼 뒤에도 답에 폴더 경로가 계속 적히면 다시 검토한다.

### 결과

- 얻는 것: 에이전트가 만든 HTML 을 대화에서 사진과 함께 바로 본다. 모델이 파일 경로를 어떻게 적든 상관없다.
- 감당할 것:
  - iframe 은 `sandbox` 에 `allow-scripts` 를 주지 않는다. 응답에도 같은 뜻의 `Content-Security-Policy` 를 붙인다.
    iframe 없이 그 주소를 직접 열어도 스크립트가 돌지 않게 하려는 것이다
  - `allow-same-origin` 은 준다. 빼면 문서의 출처가 비어 상대 경로 사진 요청에 로그인 쿠키가 가지 않을 수 있다.
    스크립트가 돌지 않으므로 같은 출처여도 문서가 앱의 API 를 부르지 못한다
  - 받는 확장자를 정해 둔다. SVG 는 스크립트를 품을 수 있어 받지 않는다
  - 대화 폴더 밖을 가리키는 경로는 심볼릭 링크를 따라간 실제 경로로 판정해 거절한다
  - 스크립트가 필요한 결과물이 생기면 다른 출처와 서명한 URL 을 새 ADR 로 정한다
  - Control Plane 이 오래된 파일을 지우려면 그 폴더를 쓰기로 붙여야 한다. 붙이는 일은 `fos-home-infra` 가 소유한다
  - 초안을 만드는 스킬이 사진을 절대 경로가 아닌 상대 경로로 가리켜야 화면에서 사진이 보인다
