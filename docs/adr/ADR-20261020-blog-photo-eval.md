## ADR-20261020 / blog-photo-eval: 블로그 사진 이해는 운영 왕복으로 평가하고 규칙으로 판정한다

- **status**: `accepted`
- Date: 2026-10-20

### 맥락

사용자가 앞 메시지에 사진을 올리고 다음 메시지에서 글로만 블로그 글을 부탁하면, 에이전트가 사진을 보지 않고 사진을 설명해 달라고 되물었다.
2026-10-20 운영 기록에서 그 대화의 사진은 67장이었다. 블로그를 요청한 실행은 15개였고, 그동안 `attachment_inspect` 는 한 번, 사진 한 장에만 불렸다.
모델의 vision 판정, provider 의 이미지 거절, 배포 누락은 모두 아니었다.
원인은 모델이 실행 입력의 안내와 스킬을 읽고 도구를 부르느냐에 있었다.

기존 검사는 이 틈을 보지 못한다.

- 가짜 Hermes 의 e2e 는 입력의 모양과 기록만 본다. 모델이 도구를 부를지 판단하지 않는다
- Memory 의 답 판정(`memoryJudgeEval`)처럼 모델을 직접 부르면 Hermes 의 시스템 지시, 스킬을 읽는 과정, 도구 루프를 재현하지 못한다
- 운영의 단계 사건은 실행 입력에 실은 사진(`embedded`)과 원고가 참조한 사진(`draftReferenced`)만 남긴다. 지난 사진을 조회했는지는 어디에도 남지 않는다

### 결정

1. **평가는 운영 Control Plane, Hermes, 모델, 스킬을 그대로 거친다.**
   관리자 계정의 평가 전용 대화에서 합성 사진과 일반화한 지시문을 보낸다. 평가 스크립트는 `test/model-eval/blog/` 에 두고, 접속 값과 토큰을 만드는 방법은 운영 저장소가 갖는다.
   CI 와 배포 job 에서는 돌지 않는다. 사진 안내나 블로그 스킬, 사진 입력을 바꾼 PR 을 배포한 뒤 사람이 돌린다.
2. **판정은 규칙으로 한다.** 판정 모델을 쓰지 않는다.
   합성 사진마다 그 사진에만 있는 글자를 정답으로 심는다. 지시문은 그 글자를 말하지 않는다.
   미리보기 본문에 그 글자가 있으면 그 사진을 읽은 것으로 본다. 지시문은 주소와 지도를 빼고 카테고리를 미리 줘서, 스킬이 사실을 되물을 까닭을 없앤다.
3. **시나리오마다 새 대화에서 3번 돌려 3번 모두 통과해야 통과다.** 이번 실패처럼 가끔만 사진을 건너뛰는 경우도 잡으려는 것이다.
4. **Control Plane 이 조회와 참조를 본문 없는 단계 사건으로 남긴다.**
   `referenced` 는 실행 입력에 지난 사진 참조를 실을 때, `inspected` 는 `attachment_inspect` 요청을 처리할 때마다 한 줄씩 남긴다.
   평가는 이 사건으로 「조회하지 않았다」 와 「조회했지만 읽지 못했다」 를 가른다. 운영에서도 같은 사건으로 원고에 쓴 사진과 조회한 사진의 차이를 셀 수 있다.
5. 평가 스크립트는 승인 카드를 누르지 않는다. 임시저장은 일어나지 않는다. 통과한 대화는 지우고 실패하거나 판정하지 못한 대화는 원인을 보도록 남긴다.

### 대안 기각

- **모델 직접 호출**: 머지 전에 돌릴 수 있지만 이번 실패의 원인인 Hermes 의 지시와 도구 루프를 재현하지 못한다. 별도 API key 와 예산도 필요하다.
- **판정 모델**: 글의 질까지 볼 수 있지만 결과가 실행마다 흔들리고, 판정기를 믿기 전에 사람이 대조해 일치도를 재야 한다. 사진을 읽었는지는 정답 글자로 충분히 가린다.
- **배포마다 자동 실행**: 사진과 관계없는 배포에도 구독 토큰을 쓴다.
- **조회 기록을 DB 테이블에 저장**: 영구히 남고 API 로 읽을 수 있지만, 마이그레이션과 첨부를 지울 때 함께 지울 범위를 새로 설계해야 한다. 로그 보존 기간이 모자라면 그때 올린다.
- **실행 기록의 도구 인자에서 첨부 번호를 가리지 않기**: 변경은 가장 작지만 커넥터 호출 뒤의 가림 규칙([ADR-038](ADR-038-도구의-명령-원문은-관리자에게만-보내고-사용자에게는-사람-말로-보인다.md), [ADR-071](../../backend/docs/adr/ADR-071-여러-출처의-문맥은-항목마다-출처와-권한과-신선도를-지닌-묶음으로-조립한다.md))에 예외가 생기고, Hermes 의 인자 미리보기 문자열 모양에 기대게 된다.

### 결과

- 얻는 것: 사진 안내, 블로그 스킬, 사진 입력을 바꾼 뒤 실제 모델이 지난 사진을 조회하고 원고에 반영하는지를 숫자로 본다. 고치기 전의 기준값과 고친 뒤의 값을 같은 시나리오로 비교한다.
- 얻는 것: `inspected` 와 `referenced` 사건으로 운영에서도 지난 사진을 조회하지 않은 원고 turn 을 셀 수 있다.
- 감당할 것: 평가는 배포한 뒤에만 돈다. 머지 전에 회귀를 막지 못한다.
- 감당할 것: 한 번 돌릴 때마다 구독 토큰을 쓴다. 네 시나리오를 3번씩 돌리면 실행이 서른 개를 넘는다.
- 감당할 것: 평가 스크립트는 관리자 신원의 토큰으로 운영 API 를 부른다. 토큰은 짧게 만들고 운영 저장소 밖에 두지 않는다.
- 감당할 것: 단계 사건은 로그 보존 기간이 지나면 사라진다. 평가는 실행 직후의 로그를 읽는다.
- 감당할 것: 정답 글자 판정은 표현이 다른 정답을 놓칠 수 있다. 사진마다 허용 표기를 함께 둔다.

### 적용 범위

평가의 시나리오, 판정, 실행 방법은 [`docs/features/naver-blog-connector.md`](../features/naver-blog-connector.md) 의 「블로그 사진 평가」 가, 단계 사건의 칸은 [`docs/features/attachment.md`](../features/attachment.md) 의 「본문 없는 단계 사건」 이 갖는다.
