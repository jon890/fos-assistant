## ADR-20261009 / adr-per-module: ADR 은 지키는 코드의 모듈에 두고, 여러 모듈에 걸친 것과 작성 규칙만 루트에 둔다

- **status**: `accepted`
- Date: 2026-10-09
- [ADR-20261007 / numbering-scheme](ADR-20261007-numbering-scheme.md) 의 ADR 제목 머리와 「기존 파일을 다시 이름 붙이지 않는다」 를 개정한다. 파일 이름과 식별자는 그대로 두고 자리만 옮긴다.

### 결정

ADR 은 그 결정을 지키는 코드가 있는 모듈의 `docs/adr/` 에 둔다.
층이 `backend` 하나면 `backend/docs/adr/`, `frontend` 하나면 `web/docs/adr/`, `hermes` 하나면 `hermes/docs/adr/` 다.
층이 둘 이상이거나 `공통` 이면 루트 `docs/adr/` 에 둔다.
루트 `docs/adr/INDEX.md` 가 둘 곳과 작성 규칙, 여러 모듈에 걸친 결정의 목록을 갖는다. 모듈 목록에는 층 칸을 두지 않는다.

결정 전체가 대체되거나 퇴역한 ADR 은 같은 디렉터리의 `archive/` 로 옮기고 목록의 「보관」 표에 둔다.
일부만 대체된 ADR 은 옮기지 않는다.
코드 주석이 옮길 ADR 을 지금의 근거로 가리키면 그 주석을 대체한 ADR 로 먼저 바꾼다.
이 결정으로 ADR-006 과 ADR-016 을 `backend/docs/adr/archive/` 로, ADR-058 을 `docs/adr/archive/` 로 옮겼다.

파일을 옮겨도 파일 이름과 식별자는 바꾸지 않는다.
날짜 ADR 의 제목 머리는 날짜만이 아니라 `## ADR-YYYYMMDD / <슬러그>: <제목>` 으로 쓴다. 같은 날의 ADR 이 제목 머리에서도 구분된다.

`test/unit/adr-index.test.ts` 가 디렉터리마다 아래를 확인한다.

- 파일 집합과 목록의 링크 집합이 같다.
- 파일의 status 와 상태 칸의 첫 낱말이 같다.
- `superseded` 와 `retired` 는 `archive/` 에 있고 나머지는 없다.
- 목록이 정렬 규칙을 따른다.
- 파일 이름의 식별자와 제목 머리의 식별자가 같다.
- 루트 목록의 층 칸은 둘 이상이거나 `공통` 이다.

`test/unit/doc-links.test.ts` 가 Markdown 문서 사이의 상대 링크와, 링크 바로 뒤에 「」 로 적은 절이 있는지 확인한다.

### 맥락

ADR 이 한 디렉터리에 121개 쌓였고 목록 한 파일에 모든 PR 이 줄을 더했다.
9월 1일 이후 merge 572번 가운데 107번이 `docs/adr/INDEX.md` 를 손으로 합쳤다. 저장소에서 가장 많이 손으로 합친 파일이다.
그런데 목록과 파일이 맞는지 확인하는 시험이 없어, 지금 일치는 손으로 지킨 결과였다.

층 칸으로 나누면 backend 60, web 5, hermes 6, 루트 50 이다.
문서를 모듈마다 두는 방향에 맞춰 ADR 도 그 모듈 곁에 두면, 그 모듈을 고치는 사람이 결정을 함께 찾는다.

문서끼리의 상대 링크 1,486개와 링크 뒤의 「」 절 282줄은 어떤 시험도 확인하지 않았다.
`doc-references.test.ts` 는 코드와 프롬프트가 문서를 가리키는 방향만 보고, 숫자 ADR 의 한글 파일 이름은 경로 정규식에서 빠졌다.
파일을 옮기면 가장 많이 깨지는 곳이라 이동과 함께 검사를 둔다.

코드와 마이그레이션은 ADR 을 식별자로만 가리킨다. 마이그레이션 SQL 34개가 주석에서 ADR 을 가리키지만 파일 경로는 없다.
그래서 파일을 옮겨도 Flyway 체크섬과 코드 주석은 바뀌지 않는다. 식별자를 새로 매기면 고칠 수 없는 마이그레이션 주석이 옛 식별자를 가리키게 된다.

### 대안 기각

- 루트 `docs/adr/` 하나에 두고 일치 검사만 더한다: 고칠 것은 가장 적다.
  하지만 목록 충돌이 그대로이고, 모듈 문서와 결정이 떨어져 있다.
- 목록을 스크립트로 생성한다: 층과 상태 설명을 120개 파일로 옮겨야 하고, 생성한 목록을 커밋하면 여전히 충돌한다.
- 여러 층에 걸친 ADR 을 주된 모듈 하나에 둔다: 주된 모듈의 판정이 사람마다 달라 시험으로 확인할 수 없다. 층 칸이 둘 이상이면 루트라는 규칙은 목록만 보고 확인된다.
- 파일 이름에 모듈을 넣어 다시 매긴다: 마이그레이션 주석이 옛 식별자를 가리킨 채 남는다.

### 감당할 것

여러 층에 걸친 결정이 루트에 50개 남는다. 목록 충돌은 모듈 수만큼 나뉠 뿐 사라지지 않는다.
ADR 끼리의 링크 가운데 모듈을 넘는 것은 `../../../docs/adr/` 처럼 길어진다.
옮기기 전에 열린 브랜치가 `docs/adr/` 에 새 ADR 을 더하면, 합칠 때 그 ADR 을 층에 맞는 디렉터리와 목록으로 옮긴다. 위 시험이 잘못 둔 것을 잡는다.
