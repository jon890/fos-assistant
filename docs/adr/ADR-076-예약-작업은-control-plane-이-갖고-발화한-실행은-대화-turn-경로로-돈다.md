## ADR-076: 예약 작업은 Control Plane 이 갖고 발화한 실행은 대화 turn 경로로 돈다

- **status**: `accepted`
- **매일 깨우기 개정**: [ADR-085](ADR-085-매일-깨우기는-예약-작업을-다시-쓰고-다섯-칸-보고를-지금-화면에-올린다.md)에 따라 `task.kind = CHECK` 는 기존 발화기로 점검 turn 을 연다.
  아래 일반 예약 turn 은 `TURN` 이다. `CHECK` 의 지시문과 점검 대화, 사용자 예비 자리는 ADR-085 를 따른다.
- **결정**: 「정한 시각에 이 에이전트로 이 일을 한다」 는 예약 작업과 그 시각(trigger)을 Control Plane 의 표가 갖는다. Hermes 의 `cronjob` 도구와 kanban 을 쓰지 않는다.
  시각이 오면 Control Plane 이 작업 주인의 권한으로 대화 turn 하나를 연다. 그 turn 은 사람이 보낸 turn 과 같은 경로를 지난다. 대화 잠금, 사용자 실행 한도([ADR-069](ADR-069-사용자-전체-실행-한도는-turn-자리와-실행-줄을-사용자-잠금-하나에서-센다.md)), 실행 기록([ADR-011](ADR-011-실행은-시작할-때-기록하고-끝날-때-갱신한다.md)), Memory 조립, 커넥터 도구 판정과 승인([ADR-050](ADR-050-커넥터-쓰기는-control-plane-이-승인-줄을-저장하고-승인한-인자로-한-번만-실행한다.md))이 그대로 걸린다.
  사람 없이 도는 turn 만을 위한 판정이나 허락은 두지 않는다. 쓰기 도구는 승인 줄을 남기고 [ADR-070](ADR-070-알림은-control-plane-의-notification-표가-원장이고-웹은-사용자-단위-SSE-로-받는다.md) 의 승인 요청 알림으로 사람을 부른다.
  작업은 주인 한 사람의 것이다. 그룹 공용 작업은 두지 않는다. 작업 사이의 의존과 분기는 두지 않는다. 여러 단계가 필요하면 그 turn 안에서 에이전트가 위임으로 한다.
- **맥락**: 사용자가 「매달 1일에 커리어 프로필 변경안을 만들어 줘」 처럼 사람이 없는 동안 도는 일을 맡기려 한다.
  Hermes `cronjob` 은 관리자 등급이라 꺼져 있다([ADR-029](ADR-029-에이전트-도구는-control-plane-이-등급으로-판정하고-hermes-설정-api-로-쓴다.md)). Hermes 안에서 돌아 Control Plane 이 실행 시작을 기록하지 못하고, 실행마다 Memory 를 다시 조립하지 못하며, 커넥터 승인과 이을 자리가 없다.
  Hermes kanban 은 Runs API 밖이고, 토큰 하나가 보드 전체를 연다. 둘 다 누가 무엇을 할 수 있는지를 Control Plane 이 강제하지 못한다.
- **대안 기각**:
  - **Hermes `cronjob` 을 켠다.** 위 까닭으로 기록과 권한과 승인이 모두 Control Plane 밖으로 나간다.
  - **예약 실행을 위한 별도 실행 경로를 만든다.** 대화 잠금, 사용자 한도, 실행 기록, 중지, 승인 결과 전달을 다시 붙여야 하고, 빠뜨린 하나가 사람 없이 도는 실행의 우회로가 된다.
  - **workflow engine 을 둔다.** 작업 사이 의존과 재시도 그래프를 저장하면 무엇을 할지를 Control Plane 이 정하게 된다. 무엇을 할지는 Hermes 가 정한다([ADR-001](ADR-001-hermes를-런타임으로-두고-core를-고치지-않는다.md)).
  - **작업 실행에 쓰기 도구를 미리 허락한다.** 사람이 보지 않은 쓰기가 생긴다. 작업 범위의 미리 허락은 기간과 대상 도구를 정하는 다음 단계에서 따로 정한다.
- **결과**:
  - 얻는 것:
    - 예약 실행도 사용량 화면의 실행 트리와 대화에 그대로 남는다.
    - 사람이 없는 동안의 쓰기가 사람이 있을 때와 같은 승인을 거친다.
    - 대화 화면이 예약 실행을 보고 멈추는 데 따로 만들 것이 없다.
  - 감당할 것:
    - 대화 잠금과 사용자 실행 한도가 프로세스 메모리에 있어 **Control Plane 한 대 전제**가 하나 는다.
    - 사용자가 다른 대화로 한도를 다 쓰고 있으면 예약 실행이 기다리다 건너뛴다.
    - 작업 하나가 대화 목록에 대화를 하나씩 더한다. 목록은 작업으로 묶어 보인다([ADR-078](ADR-078-예약-작업의-결과는-실행마다-새-대화가-기본이고-목록은-작업으로-묶는다.md)).
- **적용 범위**: 흐름과 갈리는 지점은 [`backend/task.md`](../backend/task.md) 가, 칸은 [`backend/schema/task.md`](../backend/schema/task.md) 가 갖는다. 실패의 다시 하기와 일시 정지, 작업 범위 미리 허락, 에이전트의 작업 제안, webhook 은 다음 단계다.
