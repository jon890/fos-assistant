## ADR-20261110 / agent-introduction: 에이전트의 한 줄 소개를 사람이 쓰는 칸으로 다시 두고, 할 수 있는 일은 읽을 때 모은다

- **status**: `accepted`
- Date: 2026-11-10
- **decision-type**: `architecture`
- **areas**: `product, data`
- **현재 규칙의 원본**: [에이전트 팀](../features/agent-team.md) 의 「소개와 할 수 있는 일」, 스펙 [`docs/features/agent-team/spec.md`](../features/agent-team/spec.md)(사용자 확인 2026-11-10), 설계 [`design.md`](../features/agent-team/design.md)
- [ADR-036](../../backend/docs/adr/ADR-036-추천-질문은-사용자의-대화-이력으로-모델이-만들고-메모리에만-둔다.md) 의 「에이전트의 한 줄 소개도 없앤다」 를 대체한다. 추천 질문을 모델이 만든다는 나머지 결정은 그대로다.

### 결정

**에이전트마다 한 줄 소개, 아이콘, 색을 `agent` 의 컬럼으로 둔다.** 주인과 `ADMIN` 이 고치고, 답과 목록의 이름표와 위임 도구 `agent_list` 가 쓴다.
**할 수 있는 일은 저장하지 않는다.** 연결과 바인딩이 모두 `READY` 인 플러그인 이름과 올린 스킬 이름을 읽을 때 모은다.

### 맥락

- ADR-036 은 사람이 적은 소개가 아무도 고치지 않으면 낡는다는 까닭으로 소개를 없앴다.
- 에이전트 팀 기능은 기본 비서가 전문 에이전트에게 맡기는 구조다. 맡기는 쪽이 에이전트를 이름만 보고 고르면 「쇼핑 담당」 과 「기차 담당」 을 가리지 못한다. 사람에게도 답마다 어느 에이전트가 썼는지 보여야 한다(스펙 REQ1, REQ2).
- 낡는 문제는 둘로 나눠 줄인다. 바뀌는 부분(붙은 서비스와 스킬)은 저장하지 않고 읽을 때 모으고, 사람이 쓰는 부분은 60자 한 줄로 묶는다. 소개가 비면 할 수 있는 일로 대신 보인다.

### 버린 대안

| 대안 | 버린 까닭 |
| --- | --- |
| 모델이 소개를 만든다 | 실행 비용이 들고 문장이 바뀐다. 스펙 DECISION3 에서 사용자가 사람이 쓰는 쪽을 골랐다 |
| 소개를 Hermes 의 `SOUL.md` 에 둔다 | Hermes 가 읽지 않는 화면 값이고, 목록을 그릴 때마다 profile 을 읽어야 한다 |
| 할 수 있는 일을 저장한다 | 연결을 붙이고 뗄 때마다 함께 고쳐야 하고, 빠뜨리면 낡는다 |

### 감당할 것

- 그룹 공개 에이전트의 소개는 다른 사용자가 쓴 글이 `agent_list` 로 모델 입력에 들어간다. 이름이 이미 같은 길로 들어가고 소개는 60자로 묶는다.
- 플러그인 이름은 카탈로그 캐시에서 읽어 보관 시간만큼 늦게 바뀔 수 있다.
