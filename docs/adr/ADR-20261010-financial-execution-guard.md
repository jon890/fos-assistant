## ADR-20261010 / financial-execution-guard: 금융 실행 내용은 승인 이력에 묶어 불변으로 저장한다

- **status**: `accepted`
- Date: 2026-10-10

### 결정

원래 모델 인자와 금융 실행 인자를 구분하고 실행 원문, 표시 summary와 scope를 함께 검증한다.
실행 내용은 승인 줄의 PK와 FK를 사용하며 승인 줄을 지우면 함께 지운다.
연결·바인딩과 두 revision은 준비 당시 값으로 보존한다.
실행 내용과 표시 값은 저장한 뒤 바꾸지 않는다.

세 본문은 [사용자 데이터 암호화](../../backend/docs/adr/ADR-20261008-data-encryption.md)의 TextCipher를 재사용한다.
사용자·행·칸을 AAD에 묶고 같은 key 식별자만 허용한다.
읽는 방식은 현재 설정이 아니라 저장된 key 식별자로 정한다.
암복호화 실패와 원문 해시 불일치는 읽기·저장을 거절한다.
key 값과 권한 원문을 DB나 로그에 남기지 않는다.

누락·추가·중복 키와 타입 오류를 원래 JSON 소비 함수에서 거절한다.
summary와 실행 args를 대조하고 모든 정규화 전후 값을 보존한다.
언어별 해시와 정상·거절 입력은 공통 vector로 맞춘다.
정확한 JSON 계약은 [커넥터 도구 정책과 승인](../features/connector-policy.md)의 「금융 실행 내용의 저장과 검증」이,
표와 컬럼은 [저장 모델](../../backend/docs/data-schema.md)의 「connector_action_execution」이 갖는다.

### 맥락과 대안

원래 인자만 승인하면 준비 중 보충하거나 절삭한 실행 값과 사용자가 본 값이 달라질 수 있다.
실행 내용과 표시 값을 불변으로 보존하고 원문 해시를 별도로 두어 그 차이를 검증한다.
표시 문자열이나 clientOrderId로 중복 의도를 계산하면 같은 의도를 새 요청으로 읽을 수 있어,
중복 의도 키는 사용자·연결·도구와 정규화한 주문 필드로 계산한다.

### 적용 범위

현재 구현은 저장 모델, strict 검증과 공통 vector, 최소 보호 선언 읽기와 일회성 ticket 발급·claim이다.
금융 호출과 DESTRUCTIVE의 기존 차단, 매회 승인 및 상시 허락 금지는 유지한다.
준비 API, 운영 금융 승인·지원 확인과 실제 주문 실행은 아직 구현하지 않았다.
이 결정은 해당 경로를 열거나 기존 차단 결정을 대체하지 않는다.

### 권한 검증과 HTTP 경계

서명 인증을 DB와 HTTP보다 먼저 수행하고, 짧은 읽기 트랜잭션에서 현재 공개 맥락만 복사한다.
DB 연결과 잠금 없이 fresh 카탈로그 HTTP를 한 번 읽은 뒤 새 쓰기 트랜잭션을 시작한다.
첫 사용자 잠금, 승인 줄, 실행 내용 순으로 잠그며 현재 ID와 profile, 두 revision, 공개 칸을 다시 대조한다.
mutable JSON이나 entity를 HTTP 경계로 넘기지 않는다.
읽기와 쓰기에서 persistence context를 공유하거나 HTTP 동안 사용자 잠금을 유지하는 대안은 쓰지 않는다.
서명과 실제 DB 상태, 저장 원문을 함께 검증한 권한만 한 번 소비하고 실제 커밋 뒤 응답한다.

기존 실행 중 승인 줄의 등록·해제·떼기 보호는 유지한다.
이 세 서비스의 실제 거절은 권한 맥락을 바꾸지 않지만, 반영 완료의 resync는 PENDING과 revision을 커밋할 수 있다.
따라서 HTTP 대기 중 그 실제 반영 완료가 먼저 커밋하는 경로로 최신 맥락 재검증을 확인한다.
금융 철회 정책을 넓히거나 기존 WRITE 보호를 약화하는 일은 이번 구현에 포함하지 않는다.
