## ADR-054: 에이전트 기본 모델과 모델 숨김은 Control Plane DB 가 갖는다

- **status**: `accepted`
- **결정**: 대화가 모델을 고르지 않았을 때 도는 모델을 Control Plane 의 DB 가 정한다.
  1. **에이전트 기본 모델.** `agent` 표가 기본 provider, 모델, effort 를 갖는다. 값이 있으면 `/v1/runs` 에 명시해 보낸다. 값이 없으면 지금처럼 보내지 않아 Hermes profile 의 값으로 돈다.
  2. **단계 정의.** 세 단계의 mapping 은 DB 의 `model_tier_definition` 만 읽는다. 환경 변수로 주던 초기값은 기동할 때 정의 행이 없는 그룹에 한 번 옮기고, 그 뒤 운영 설정에서 지운다.
  3. **모델 숨김.** 그룹이 숨긴 provider 와 모델을 `model_hidden` 표가 갖는다. 숨긴 것만 적는다. 적히지 않은 provider 와 모델은 새로 생긴 것까지 모두 보인다.

  DB 값과 profile 의 값이 다르면 **DB 값을 쓴다.** profile `config.yaml` 의 `model.default` 는 Hermes 가 기동에 요구하는 값으로만 남는다.
  코드와 마이그레이션에는 모델 이름을 넣지 않는다. 값은 관리자가 화면에서 정한다.
- **해석 순서**: 실행마다 아래 순서로 정한다. 정한 값은 실행 줄에 복사한다.

  | 대화의 선택 | 쓰는 값 |
  | --- | --- |
  | `CUSTOM` | 대화에 적힌 값. 모델을 비웠으면 에이전트 기본 모델이고, effort 는 대화가 고른 값이 먼저다. 모델을 고르고 effort 를 비웠으면 에이전트 기본 effort 를 얹지 않는다 |
  | `TIER` | 그 단계의 정의. mapping 이 비었으면 에이전트 기본 |
  | 선택 없음 | 내 기본 단계, 그룹 기본 단계, 에이전트 기본 차례 |
  | `DEFAULT` | 에이전트 기본 |

- **맥락**:
  - [ADR-030](ADR-030-모델과-effort-는-대화가-고르고-기본값은-hermes-profile-이-갖는다.md) 은 기본값을 profile 에 두었다. 그래서 기본 모델을 바꾸려면 홈서버의 파일을 고치고 gateway 를 다시 띄워야 했다. 화면에서는 값을 볼 수만 있었다.
  - 단계 초기값은 배포 환경 변수에 있었다. 화면에는 그 값이 저장된 정의처럼 보였지만 DB 에는 행이 없었다. 사용자가 「기본 모델을 고정해도 저장되지 않는다」 고 알렸고, 확인해 보니 저장이 실패한 것이 아니라 저장할 자리가 없었다(2026-10-02).
  - 내 기본 단계는 사용자 줄에 저장하고 실행할 때마다 읽는다. 대화에는 적지 않으므로 화면이 그 단계를 보여 주지 않으면 저장되지 않은 것처럼 보인다. 이번에 단계 단추가 적용되는 기본 단계를 표시한다.
  - Hermes 목록에는 쓰지 않으려는 provider 와 모델도 함께 나온다. 사용자는 새 모델을 바로 쓰는 편이라 허용 목록 대신 숨김 목록을 고른다(2026-10-02 사용자).
- **대체된 부분**: ADR-030 의 「기본값은 Hermes profile 이 갖는다」 와 대안 기각 「전역 기본 모델과 effort 를 우리 DB 에 둔다」 를 뒤집는다. 그때의 까닭은 값이 둘이 되어 어느 쪽이 맞는지 판단해야 한다는 것이었다. 이 결정은 DB 값이 이긴다고 정하고, 화면이 지금 적용되는 값과 profile 의 값을 함께 보여 준다.
  ADR-030 의 나머지(모델과 effort 는 대화가 고른다, 목록은 저장하지 않고 Hermes 에 묻는다, 막힌 provider 를 다른 모델로 넘기지 않는다)는 그대로다.
- **검증 시점**:
  - 에이전트 기본 모델은 **저장할 때** 그 에이전트의 목록과 숨김으로 검증한다. 실행할 때는 목록을 다시 읽지 않고 저장된 값을 그대로 보낸다. 목록 조회가 실패한 날에 모델을 고르지 않은 대화 전체가 멈추지 않게 하려는 것이다.
  - 숨김은 목록, 대화의 직접 선택 저장, 단계 정의 저장, 에이전트 기본값 저장, 실행 직전에 같은 규칙으로 건다. 요청에 모델을 싣는 실행의 판정은 DB 의 숨김 목록만 읽는다.
  - **숨김은 실제로 도는 모델까지 강제한다.** 요청에 모델을 싣지 않는 실행은 Hermes 가 profile 의 기본 모델로 돌린다. 그룹에 숨김이 하나라도 있으면 실행 직전에 그 profile 의 기본 provider 와 모델을 숨김과 견준다. 숨긴 모델이면 Hermes 에 제출하지 않고 `MODEL_HIDDEN` 으로 거절한다.
    - profile 의 기본값은 모델 목록(`GET /api/model/options`)에 함께 온다. 고르는 창과 단계 실행이 이미 쓰는, profile 마다 10분 들고 있는 목록에서 읽는다. 실행마다 Hermes 를 부르지 않는다.
    - 숨김이 없는 그룹과 요청에 모델을 싣는 실행은 목록을 읽지 않는다. 에이전트 기본 모델을 정해 둔 에이전트가 여기 해당한다.
    - 그 profile 의 목록을 한 번도 읽지 못해 판정할 수 없으면 실행을 `HERMES_UNAVAILABLE` 로 거절한다. 목록과 실행은 같은 Hermes 주소에 묻는다.
    - 대화 없이 도는 추천 질문 실행도 같은 판정을 지난다. Memory 제안 실행은 방금 판정을 지난 원래 실행의 값을 그대로 쓰므로 다시 판정하지 않는다.
  - **이미 숨긴 모델을 가리키는 대화와 정의는 다른 모델로 바꾸지 않는다.** 그 실행을 `MODEL_HIDDEN` 으로 거절하고 실행 줄을 `FAILED` 로 남긴다. 화면은 다른 모델을 고르라고 알린다.
  - 저장한 뒤 Hermes 목록에서 빠진 모델도 바꾸지 않는다. Hermes 가 그 실행을 거절하고, 관리 화면이 목록에 없는 기본 모델이라고 알린다.
- **대안 기각**:
  - **그룹에 기본 모델 하나를 둔다.** 에이전트마다 맡은 일이 달라 기본 모델도 다르다. 운영에서 이미 profile 마다 값이 달랐다.
  - **Control Plane 이 profile 의 `config.yaml` 을 고쳐 쓴다.** 값이 한곳에 남지만 바꿀 때마다 gateway 를 다시 띄워야 하고, 돌던 실행이 끊긴다.
  - **기동할 때 profile 의 값을 DB 로 복사한다.** 에이전트마다 Hermes 를 불러야 해서 Hermes 가 멈춘 날 기동이 흔들린다. 값이 없는 에이전트는 지금과 똑같이 돌므로 관리자가 화면에서 정할 때 옮기면 된다.
  - **단계 초기값을 마이그레이션으로 넣는다.** 모델 이름이 공개 저장소에 들어간다.
  - **숨긴 모델로 가는 실행을 기본 모델로 바꿔 보낸다.** 사용자가 고른 모델과 실제 모델이 조용히 달라진다. ADR-030 이 막힌 provider 에서 넘기지 않기로 한 것과 같은 까닭이다.
  - **허용 목록을 둔다.** 새 모델이 나올 때마다 관리자가 열어야 쓸 수 있다.
- **결과**:
  - 얻는 것: 기본 모델과 단계 정의를 화면에서 바꾸고 다음 실행부터 쓴다. 배포 설정과 홈서버 파일을 고치지 않는다. 쓰지 않을 모델이 선택지에서 빠진다.
  - 감당할 것:
    - 에이전트 기본값을 정하지 않은 에이전트는 profile 의 값으로 돈다. 그 값이 숨긴 모델이면 모델을 고르지 않은 실행이 `MODEL_HIDDEN` 으로 실패한다. 모델 선택 창이 「기본 모델을 지금 쓸 수 없어요」 로 알리고, 관리 화면의 「모델」 절이 그 에이전트에 경고를 보인다. 관리자가 그 에이전트의 기본 모델을 정하거나 숨김을 풀어 해소한다. 숨김 저장은 이 경우에도 거절하지 않는다.
    - profile 의 기본값은 들고 있는 목록으로 판정한다. 홈서버에서 profile 의 기본 모델을 바꾸면 최대 10분 동안 옛 값으로 판정한다. Hermes 가 목록을 다시 주지 못하는 동안에는 들고 있던 옛 목록으로 판정한다.
    - Hermes 가 목록에 기본 모델을 주지 않으면 판정할 값이 없어 통과시킨다. 기본 provider 만 주지 않으면 모델 이름이 같은 숨김 항목으로 판정하고, provider 전체를 숨긴 항목은 견주지 못한다.
    - 숨김을 쓰는 그룹에서 에이전트 기본 모델이 없는 에이전트는 Control Plane 이 다시 뜬 뒤 목록을 한 번 읽을 때까지 Hermes 의 목록 응답에 기댄다. 에이전트 기본 모델을 정하면 이 의존이 없다.
    - provider 를 비운 단계 정의는 에이전트마다 provider 가 달라 저장할 때 숨김을 판정하지 못한다. 실행할 때 그 에이전트의 목록으로 판정한다.
    - 숨김은 그룹 전체에 걸리는데 숨길 대상의 목록은 에이전트마다 다르다. 관리 화면은 연 에이전트의 목록을 보여 주고, 그 목록에 없는 숨김 항목을 따로 보여 준다.
    - 실행 줄의 effort 출처에 `AGENT_DEFAULT` 가 생긴다. 단계를 거친 실행은 그 단계의 mapping 이 비어 에이전트 기본값으로 돌았어도 `REQUESTED` 로 남는다.
    - 실행 줄은 Hermes 에 보낸 값과 그 값을 누가 정했는지를 함께 맞게 적는다. Memory 제안 실행은 원래 실행의 단계와 effort 출처를 이어받고, 추천 질문 실행은 보낸 에이전트 기본값을 실행 줄에 적는다.
- **다음**: 환경 변수의 단계 초기값을 운영 설정에서 지운 뒤 그 속성과 옮기는 코드를 지운다.
