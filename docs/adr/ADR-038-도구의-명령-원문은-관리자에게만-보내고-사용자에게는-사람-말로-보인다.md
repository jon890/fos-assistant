## ADR-038: 도구의 명령 원문은 관리자에게만 보내고 사용자에게는 사람 말로 보인다

- **status**: `accepted`
- **결정**: 도구 사건의 `detail` 은 `ADMIN` 역할에게만 응답에 싣는다. `MEMBER` 역할에게는 비워서 보낸다.
  대화 화면으로 흐르는 `tool` 사건과 실행 나무 조회가 모두 해당한다. 화면에서 숨기는 것이 아니라 Control Plane 이 응답에서 뺀다.
  예외는 `web_search` 와 `vision_analyze` 다. 이 둘의 `detail` 은 검색어와 사진에 던진 질문이라 누구에게나 싣는다.
  도구 이름은 화면이 사람 말 문장으로 옮겨 보인다. 표에 없는 도구는 일반 문구로 보인다.
- **맥락**:
  - Hermes 는 `tool.started` 의 `preview` 에 도구 인자의 앞부분을 싣는다. Control Plane 은 그것을 `execution_event.detail` 에 옮겨 적고([ADR-013](ADR-013-실행-사건은-우리-모델로-정규화해-저장한다.md)) 화면이 그대로 보였다.
  - 2026-09-29 블로그 초안 대화에서 도구 호출 70건이 `terminal`, `read_file` 같은 이름과 함께 셸 명령, 파이썬 코드, 컨테이너 안의 절대 경로, 브라우저 탭 식별자, 환경 변수 이름으로 보였다. 여러 줄 명령은 첫 줄과 개수만 남아 읽는 사람에게 뜻이 없었다.
  - 가족이 쓰는 화면이다. 사용자는 에이전트가 무엇을 하는지를 알고 싶고 어떤 명령을 쳤는지는 알 필요가 없다. 문제를 조사하는 사람은 관리자다.
  - `web_search` 의 검색어와 `vision_analyze` 의 질문은 모델이 사람 말로 쓴 글이고, 그 대화의 주인만 본다. 무엇을 찾고 무엇을 봤는지 알려 줘 사용자가 답을 믿을지 판단하는 데 쓰인다.
- **대안 기각**:
  - **화면에서만 숨긴다.** 응답에는 그대로 실려 개발자 도구로 보인다. 내부 경로와 식별자를 가리려는 목적을 이루지 못한다.
  - **저장할 때부터 버린다.** 관리자가 실패를 조사할 근거가 사라진다. 실제로 이번 조사도 저장된 명령으로 원인을 찾았다.
  - **모든 도구의 `detail` 을 숨긴다.** 검색어와 사진 질문까지 사라져 사용자에게 작업 과정이 도구 이름 목록만 남는다.
  - **숨길 도구를 적는다.** 새 도구가 생기면 기본으로 보이게 된다. 보일 도구를 적어야 새 도구가 기본으로 숨는다.
- **결과**:
  - 얻는 것:
    - 사용자의 작업 과정에 명령 원문과 내부 경로가 나가지 않는다
    - 관리자는 같은 화면에서 명령 원문까지 본다. 저장 모양은 그대로다
  - 감당할 것:
    - 관리자와 사용자가 같은 실행을 다르게 본다. 사용자가 보낸 화면 캡처로 조사할 때는 관리자 화면에서 다시 연다
    - 누구에게나 보일 도구 목록과 사람 말 문장 표를 Control Plane 과 화면이 각각 갖는다. 새 도구가 생기면 필요한 쪽을 고친다
    - Hermes 가 `web_search` 나 `vision_analyze` 의 `preview` 모양을 바꾸면 그 두 도구의 공개 여부를 다시 판단한다
    - 하위 에이전트 사건의 목표(`goal`)는 도구 사건이 아니라 모두에게 싣는다. 모델이 사람 말로 쓴 목표라는 전제다. 명령이나 내부 경로가 목표로 실려 오는 것이 보이면 같은 판정을 넓힌다
