## ADR-073: 할 일은 에이전트가 제안하고 사람이 받아들인 것만 챙긴다

- **status**: `accepted`. 제안 도구 `follow_up_propose` 와 제안 억제는 아직 구현 전이다.
- **결정**: **할 일**은 사용자가 해야 하거나 끝나기를 기다리는 일 한 줄이다. 코드 이름은 `follow_up` 이다.
  할 일은 `follow_up` 표에 사용자 한 사람의 것으로 둔다. 상태는 `PROPOSED`, `OPEN`, `DONE`, `DROPPED`, `REJECTED` 다.

  1. **에이전트는 제안만 한다.** Control Plane MCP 도구 `follow_up_propose` 가 `PROPOSED` 줄을 만든다. 사람이 받아들이면 `OPEN` 이 된다.
  2. **주인은 MCP 호출의 요청자다.** 서명한 `_fos_ctx` 로 찾은 origin 실행의 `user_id` 가 주인이고, 그 실행의 대화가 할 일의 대화다(ADR-032). 도구 인자로 사용자나 대화를 받지 않는다.
  3. **받아들이기, 거절, 고치기(제목, 기한, 기다리는 중), 끝냄, 그만둠은 사람이 누른다.** 웹 JWT 로만 부른다. 사람은 같은 폼으로 할 일을 직접 더할 수 있고, 그 줄은 바로 `OPEN` 이다.
  4. **받아들이기 전의 할 일은 `NOW` 가 되지 못한다.** 지금 화면에 제안으로만(`LATER`) 보이고 건수에 세지 않는다([ADR-072](ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md)).
  5. **같은 제안을 되풀이하지 않는다.** 제목을 정규화한 지문(`title_key`)으로 같은 사용자의 `PROPOSED` 나 `OPEN` 줄을 찾으면 새 줄을 만들지 않는다. 같은 대화에서 30일 안에 거절한 제목은 다시 제안하지 못한다. 한 대화에 열린 제안은 3개까지다.
  6. **할 일은 실행하지 않는다.** 할 일에서 Hermes 실행이나 커넥터 호출로 넘어가는 길을 만들지 않는다.
  7. **할 일은 대화의 `instructions` 에 싣지 않는다.** 문맥 묶음의 `FOLLOW_UP` 항목으로 지금 화면과 먼저 알리기만 읽는다([ADR-071](ADR-071-여러-출처의-문맥은-항목마다-출처와-권한과-신선도를-지닌-묶음으로-조립한다.md)).

  **기다리는 중**은 할 일의 `waiting` 칸이다. 사용자가 남이나 에이전트가 끝내기를 기다리는 일에 켠다.
  대화 대기열의 **대기 메시지**와 다르다. 대기 메시지는 응답 중에 보낸 사용자 글이고 다음 turn 에 합쳐 보낸다(ADR-048).
- **맥락**: #160 의 MVP 대상은 실행 상태와 「사용자가 명시한 추적 목표」(#160 원문의 표현)다. 2026-10-04 에 사용자가 그 목표를 「할 일」 로 부르기로 했다.
  같은 날 등록 방법도 정했다. 에이전트가 대화 중에 제안하고 사람이 받아들인다. Memory 제안과 같은 모양이다.
  #158 의 「생각에서 동작으로」 루프의 첫 단계다. 짧은 생각에서 후속 작업 후보를 뽑는 데까지 한다.
  그 후보를 자동으로 실행하는 단계는 이 결정의 범위 밖이다.
  할 일은 상태와 기한을 가진 작업 항목이다. 사람이 승인한 지식인 Memory(ADR-012)와 성질이 다르다.
- **대안 기각**:
  - **Memory 의 한 종류로 둔다.** Memory 에는 상태와 기한이 없다. 항상 층이나 색인으로 대화마다 실려 할 일이 지식처럼 쓰이고, #97 이 막은 새 층이 사실상 생긴다.
  - **Hermes kanban 에 둔다.** kanban 은 profile 이 실행할 작업 보드다([`hermes/kanban.md`](../hermes/kanban.md)). 사용자가 챙길 목록이 아니고, Runs API 로 부를 수 없다. 할 일을 실행 단위와 섞으면 자동 실행으로 넘어가는 길이 열린다.
  - **에이전트가 바로 `OPEN` 으로 만든다.** 사람이 보지 않은 것이 주의를 끄는 목록에 들어간다. 잘못 뽑은 후보가 바로 알리기 대상이 된다.
  - **사람만 직접 등록한다.** 손이 많이 가 사용자가 고르지 않았다. 다만 받아들이는 폼이 있어 직접 더하는 길은 비용이 작아 함께 둔다.
- **결과**:
  - 얻는 것:
    - 대화에서 나온 후속 작업이 대화가 끝나도 남고, 지금 화면에서 다시 보인다.
    - 사람이 받아들인 것만 알리기 대상이 되어 잘못 뽑은 후보가 주의를 빼앗지 않는다.
    - 할 일이 실행으로 이어지지 않아 실행 한도와 승인 경로가 그대로다.
  - 감당할 것:
    - 할 일의 제목은 모델이 쓴 글이다. 화면은 평문으로만 그린다(ADR-009).
    - 제목에 개인 내용이 들어갈 수 있다. 본문 암호화는 하지 않는다. 주인만 읽고, 로그와 실행 사건에 제목을 남기지 않는다.
    - Hermes plugin `fos-ctx` 가 새 도구를 서명 필수 도구로 알아야 한다. plugin 을 먼저 배포한다.
    - 그룹이 함께 챙기는 할 일은 없다. 개인 경험이 안정된 뒤 정한다(#158).
- **적용 범위**: 표의 칸, 도구의 입력과 응답, 제안 억제 규칙, API 는 [`backend/follow-up.md`](../backend/follow-up.md) 가 갖는다.
