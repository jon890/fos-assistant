## ADR-089: 커넥터는 식별자 인자를 선언하고 승인 카드는 그 값을 길이로 가리지 않는다

- **status**: `accepted`
- Date: 2026-10-06
- [ADR-065](ADR-065-외부로-나가는-도구는-상시-허락을-닫는-선언을-둔다.md) 의 「가려진 인자」 에 예외 하나를 더한다. [ADR-047](../../backend/docs/adr/ADR-047-도구-내용은-비밀값과-UUID를-가린-뒤-중계하고-저장한다.md) 의 가림 규칙은 승인 카드 밖에서 그대로다.

### 결정

**`connector.json` 의 도구 선언에 `identifiers` 를 둔다. 거기 적은 인자의 값은 승인 카드에서 길이와 모양만으로 가리지 않는다.**

| 항목 | 정한 것 |
| --- | --- |
| 선언 | `tools.<이름>.identifiers` 는 인자 이름의 배열이다. 없으면 빈 배열이다 |
| 쓸 수 있는 곳 | `approval` 이 `required` 인 도구에만 선언한다. 이름은 `^[A-Za-z_][A-Za-z0-9_]{0,30}$` 이고 겹치지 않는다. 32자 이상인 이름은 키 이름 자체가 긴 덩어리로 가려지므로 받지 않는다. 비밀 키로 읽히는 이름(`token`, `secret`, `password` 로 끝나는 이름 등)은 받지 않는다. 어기면 그 커넥터를 카탈로그에 내지 않는다 |
| 가리키는 칸 | 도구 인자 객체의 맨 위 칸만이다. 중첩된 칸은 가리키지 않는다 |
| 면제하는 값 | 그 칸의 값이 문자열이거나 문자열 배열이고, 문자열마다 `^[A-Za-z0-9_-]{1,256}$` 일 때다. 이 모양을 벗어나면 지금처럼 가린다 |
| 면제하는 규칙 | 32자 이상의 16진수, base64, base64url 덩어리를 가리는 규칙만이다. 알려진 비밀 접두사(`sk-`, `ghp_` 와 같은 무리, `github_pat_`, `xox?-`)는 식별자 칸에서도 가린다 |
| 카탈로그 | 대시보드 plugin 이 기본값을 채운 `identifiers` 를 도구마다 낸다. Control Plane 은 승인 줄을 읽을 때와 승인할 때의 카탈로그로 본다. 승인 줄에는 저장하지 않는다 |
| 계약 검사 | `hermes/connectors/` 의 커넥터는 선언한 이름이 서버의 그 도구 입력 스키마에 있어야 한다 |
| 승인 카드 | 가려진 칸이 남아 승인할 수 없으면, 어느 칸이 가려졌는지와 거절한 뒤 할 일을 카드에 보인다 |

### 맥락

운영의 Gmail 대화에서 에이전트가 필터 하나를 지우려 했다. Gmail 필터 id 는 `ANe1Bm` 으로 시작하는 긴 영숫자라 승인 카드가 base64url 덩어리로 보고 `[가림]` 으로 바꿨다.
`delete_filter` 는 상시 허락을 닫은 도구라, 가려진 글이 있으면 승인할 수 없다(ADR-065). 사용자는 필터를 지울 방법이 없었다.

가림은 글의 모양이 정한다. 모양만으로는 식별자와 key 를 구분하지 못한다.
그 칸이 무엇인지는 도구를 만든 사람이 안다. Control Plane 은 도구의 뜻을 모른다(ADR-043).

### 대안 기각

- **긴 토큰 규칙을 약하게 한다**: 32자를 늘리거나 영숫자 덩어리를 빼면 다른 도구의 인자에 섞인 진짜 key 가 화면과 응답에 나온다.
- **인자 이름으로 추측한다**(`_id` 로 끝나면 남긴다): 모델이 이름을 고르지는 않지만 서버를 만든 사람이 `session_id` 에 세션 토큰을 받을 수 있다. 선언 없이 이름으로 정하면 그 판단을 아무도 하지 않는다.
- **도구의 입력 스키마(`format` 같은 표시)를 읽는다**: Control Plane 은 MCP 서버의 스키마를 받지 않고 카탈로그만 읽는다. 스키마를 카탈로그로 옮기면 계약이 훨씬 커진다. 선언 한 칸으로 같은 일을 한다.
- **식별자 칸의 값은 모양과 상관없이 남긴다**: 속은 모델이 그 칸에 긴 base64 본문이나 공백이 섞인 글을 넣을 수 있다. 식별자 모양(영숫자, `_`, `-`)과 256자 상한을 두면 공백이 섞인 본문이나 긴 글은 그 칸에 넣어도 가려져 승인되지 않는다. 모양에 맞아 남긴 글은 화면에 그대로 보이므로 사람이 읽는다.
- **중첩된 칸까지 경로로 가리킨다**: Gmail 의 쓰는 도구는 모두 맨 위 칸에 id 를 받는다. 쓰는 곳이 생기면 그때 넓힌다.
- **`READ` 도구에도 받는다**: 승인 카드가 없는 도구라 뜻이 없다. 실행 사건의 가림(ADR-047)은 이 선언을 보지 않는다.

### 결과

- 얻는 것: 필터 지우기처럼 긴 id 를 받는 도구를 승인할 수 있다. 선언하지 않은 칸의 가림은 그대로다.
- 감당할 것:
  - 식별자 칸에 모델이 진짜 비밀을 넣으면 주인의 승인 카드에 보인다. 알려진 접두사는 여전히 가리고, 이 화면은 주인만 읽는다.
  - 어느 칸이 식별자인지는 만든 사람이 판단한다. 계약 검사는 그 이름이 서버에 있는지만 본다. 리뷰가 분류를 본다.
  - 옛 대시보드 plugin 은 `identifiers` 를 모르는 칸으로 읽어 그 커넥터를 카탈로그에서 뺀다. plugin 과 backend 를 한 배포로 올린다(ADR-065 와 같다). 옛 backend 는 이 칸을 읽지 않으므로 그동안 지금처럼 가린다.
