## ADR-20261008: 네이버 블로그 연결은 CDP 주소 칸을 바로 빼고, 기존 연결은 옮기는 코드 없이 다시 확인해 넘어간다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-20261007 / user-browser](ADR-20261007-user-browser.md) 의 「커넥터에 건네기」 를 네이버 블로그에 적용하는 이행 방식이다. [ADR-20261007 / naver-blog-connector](ADR-20261007-naver-blog-connector.md) 의 연결 칸을 바꾼다.

### 결정

**네이버 블로그 커넥터의 연결 칸 `cdp_url` 을 한 번에 뺀다. 연결 칸은 `blog_id` 하나이고, 브라우저는 설치가 주는 중계 주소로만 닿는다.**

| 항목 | 정한 것 |
| --- | --- |
| 칸 | `cdp_url` 을 받던 배포와 새 배포가 겹치는 기간을 두지 않는다. 두 칸을 함께 받으면 사용자가 서버 안 주소를 계속 넣을 수 있다 |
| 기존 연결 | 옮기는 코드를 두지 않는다. 대시보드는 보관 파일을 읽을 때 지금 manifest 에 없는 칸을 버린다. 보관 파일을 쓰는 검사는 그대로 엄격하다 |
| 사용자가 할 일 | 「내 브라우저」 에서 네이버에 로그인한 뒤 「연결 다시 확인」 을 누른다. 확인이 붙은 바인딩을 다시 설치한다 |
| 재시작 | 다시 설치가 서버 정의를 한 번 바꾸므로 그 바인딩은 한 번 재시작 대기가 된다. 관리자가 공유 gateway 를 재시작하고 반영 완료를 누른다 |
| 남는 값 | 보관 파일의 옛 `cdp_url` 값은 쓰이지 않고 남는다. 사용자가 블로그 아이디를 다시 등록하면 보관 파일이 새로 쓰여 사라진다. profile `.env` 의 옛 줄은 다시 설치가 지운다 |

### 맥락

일반 사용자는 서버 안의 CDP 주소를 알 수 없고 알아서도 안 된다(2026-10-08 사용자 결정).
지금 이 커넥터를 쓰는 연결은 몇 개뿐이고, 그 주소는 운영자가 넣은 임시 값이다.
보관 파일의 칸 값은 비밀 칸이라 Control Plane 이 원문을 갖지 않는다. 옮기는 코드를 Control Plane 에 둘 수 없다.

### 대안 기각

- **한 배포 동안 두 칸을 모두 받는다**: 겹치는 동안 커넥터가 두 경로를 다 가져야 하고, 끝내는 시점을 다시 정해야 한다. 연결 몇 개를 위해 들일 비용이 아니다.
- **대시보드가 보관 파일을 새 모양으로 다시 쓴다**: 쓰기 검사를 우회하는 경로가 생긴다. 읽을 때 버리는 것으로 같은 효과를 얻는다.
- **사용자에게 연결을 지우고 다시 등록하게 한다**: 붙인 바인딩과 상시 허락이 함께 사라진다.

### 결과

- 얻는 것:
  - 서버 안 주소가 사용자 화면과 보관 파일의 새 값에서 사라진다.
  - 이행 코드가 없어 지울 코드도 남지 않는다.
- 감당할 것:
  - 배포 뒤 사용자가 로그인과 연결 확인을 할 때까지 그 연결의 도구는 브라우저에 닿지 못한다. 배포 전에 「내 브라우저」 에서 미리 로그인해 두면 끊기는 시간이 짧다.
  - 연결 확인 뒤 관리자의 재시작과 반영 완료가 한 번 필요하다.

- **적용 범위**: `hermes/connectors/naver-blog/`, 대시보드 plugin 의 보관 파일 읽기. 절차는 [네이버 블로그 커넥터](../connectors/naver-blog.md) 의 「기존 연결 옮기기」 가 갖는다.
