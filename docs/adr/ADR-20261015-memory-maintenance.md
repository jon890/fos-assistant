## ADR-20261015 / memory-maintenance: 기억 정비는 신호를 쌓아 규칙으로 처리하고, 처음 4주는 제안만 기록한 뒤 정밀도를 보고 자동으로 바꾼다

- **status**: `accepted`
- Date: 2026-10-15
- [ADR-20261007 / decision-feedback](../../backend/docs/adr/ADR-20261007-decision-feedback.md) 의 사건 종류에 「참고한 기억」 의 단추 사건을 더한다. 사건 종류를 화면과 API 에 있는 것만 둔다는 원칙에 따라 단추와 같은 PR 에서 더한다.
- [`docs/features/proactive.md`](../features/proactive.md) 의 「이 기록은 개인화 모델이 아니다. Memory 를 바꾸지 않는다」 는 그대로다. 판단 피드백은 기억 내용과 주입을 직접 바꾸지 않고, 정비 규칙의 입력 신호로만 읽힌다.
- 2026-10-16 사용자 결정(판단의 분류를 테이블 컬럼이나 enum 으로 굳히지 않는다, #310 댓글)에 따라, 처음 적은 `fact_kind`(`TRAIT`, `STATE`, `EVENT`)를 자동 보관을 허락하는 표시 하나로 줄였다.
- 구현은 #310 2단계의 단계 3 과 단계 4 다. 이 ADR 이 머지될 때는 아직 만들지 않았다.

### 결정

**사용자 반응을 「참고한 기억」 의 항목마다 받는다.** 항목마다 「관련 없음」 과 「틀림」 두 단추를 둔다.
누르면 `decision_feedback_event` 에 사건을 하나 덧붙인다. 열쇠는 `memory:<번호>` 이고 그 답의 실행 번호를 함께 적는다. 기억 내용은 바뀌지 않는다.
「틀림」 은 `/memory` 의 그 항목으로 가는 길을 함께 보인다. 고치는 것은 사람이다.

**기억 항목에 자동 보관을 허락하는 표시(`archivable`) 하나만 둔다.** 기본값은 거짓이다. 거짓인 항목(알레르기, 생일처럼 변하지 않는 사실과 모르는 것)은 자동 보관하지 않는다.
`memory_remember` 가 선택 인자로 받는다. 모델이 기간이 있는 상태나 지난 일이라고 판단하면 참으로 주고, 사람이 `/memory` 에서 고친다.
항목이 어떤 종류인지(성향, 상태, 사건 등)는 컬럼으로 나누지 않는다. 안전 규칙에 쓰는 값은 이 표시 하나뿐이다.

**정비 루프는 신호를 항목에 쌓고 정해진 규칙으로 후보를 만든다.** LLM 이 기억을 고쳐 쓰지 않는다.

| 신호 | 어디서 읽는가 |
| --- | --- |
| 실린 횟수와 마지막으로 실린 때 | `execution_context_source` |
| 읽힌 횟수 | `execution_context_source` 의 `MEMORY_READ` 줄 |
| 정정과 되돌리기 | `memory_revision`, `memory_capture` |
| 「관련 없음」, 「틀림」 | `decision_feedback_event` |
| 먼저 살펴보기 제안의 반응 | `decision_feedback_event` 의 제안 사건과, 그 제안이 근거로 쓴 기억 |

| 동작 | 자동으로 하는가 |
| --- | --- |
| 정확히 같은 글(지문 일치)의 정리 | 자동 |
| 오래 실리지 않고 부정 신호가 쌓인 `archivable` 항목의 보관(`ARCHIVE`) | 자동. 되돌릴 수 있다 |
| `archivable` 이 거짓인 항목의 보관 | 하지 않는다. 후보로만 보인다 |
| `SUPERSEDES` 링크 | 후보만 만든다. 사람이 받아들인다([ADR-20261015 / memory-link](ADR-20261015-memory-link.md)) |
| 검색 설정(가중치, 임계값, 건수) 바꾸기 | 조립 측정 게이트와 답 판정을 지금 설정보다 나쁘지 않게 지날 때만 |

**모든 정비 동작은 `memory_maintenance_event` 에 남기고 한 번에 되돌릴 수 있다.** 줄에는 동작 종류, 대상 번호, 규칙 버전, 근거(그때의 신호 값을 담은 JSON), 모드, 사람의 확인 결과를 남긴다. 동작 종류는 Control Plane 이 되돌리는 방법이 달라 구조로 두고, 근거는 규칙이 바뀌어도 스키마가 그대로이게 JSON 으로 둔다. 제목과 본문은 남기지 않는다.

**처음 4주는 제안 모드로 돈다.** 동작을 적용하지 않고 후보와 근거만 기록한다. 사람이 후보를 「맞음」, 「아님」 으로 확인하고, 확인한 정밀도가 기준을 넘은 동작만 자동으로 바꾼다. 동작마다 따로 바꾼다.
자동으로 바꾼 뒤에는 하루치 처리를 알림 한 줄로 요약한다. 적용 뒤 정정률이나 다시 생성 비율이 나빠지면 이전 규칙 버전으로 돌린다.

**먼저 살펴보기는 같은 기억 조립과 같은 기록을 쓴다.** 살펴보기 실행도 질문 기반 선별과 한 단계 연결로 목표와 최근 사건을 함께 꺼낸다.
제안에는 근거로 쓴 기억의 참조를 남긴다. 수락, 숨김, 미룸은 그 기억의 신호로만 쌓인다. 거절 한 번을 영구 선호로 저장하지 않는다는 #374 의 원칙을 지킨다.
할 일의 `relatedGoal` 확인(#284)은 그 항목이 `ACCEPTED` 이고 대체되지 않았는지만 Control Plane 이 본다. 목표와의 연결은 `RELATED` 링크와 그 `label` 로 남고, 무엇을 목표로 볼지는 모델이 판단한다.

### 맥락

2026-10-15 사용자는 정비 루프를 처음 4주 제안 모드로 기록만 하고 정밀도를 확인한 뒤 자동으로 바꾸기로, 변하지 않는 사실은 자동 보관하지 않기로, proactive 반응은 신호로만 쌓고 기억 내용을 직접 바꾸지 않기로 정했다(#310 댓글).

조사(agent memory 사례 조사, 2026-10-15)에서 얻은 근거다.

- 자동 유지는 신호를 항목에 쌓고 규칙으로 처리하는 형태가 선례가 많다. MemoryOS 는 방문 횟수와 최근성으로 heat 를 매기고, ExpeL 은 인사이트에 찬반 횟수를 센다.
- LLM 이 덮어쓰게 두면 정보를 잃는다는 보고가 반복된다(A-MEM 의 이웃 덮어쓰기, SSGM 의 의미 표류, Mem0 블로그).
- 같은 시간 감쇠를 모든 기억에 쓰면 오래돼도 중요한 사실이 밀려난다. ScrubJay 는 유형별 감쇠의 이득이 시간 추론에 한정된다고 보고한다. Generative Agents 의 감쇠 계수 0.995 를 일 단위로 쓰면 반감기가 약 138일이다.
- 기억 전용 운영 지표를 공개한 제품이 없어, 정밀도를 사람이 확인하는 기간이 필요하다.
- 검색기를 데이터 없이 직접 바꾸면 무너진다. RMM 에서 리랭커 없이 검색기를 강화학습하면 정확도가 31.0 으로 내렸다.

### 대안 기각

- **처음부터 자동으로 적용한다.** 자동 보관은 주입과 검색에서 사라진다는 뜻이라 사실상 잊는 것이다. 정밀도를 모르는 채 시작하면 잃은 사실을 사용자가 알아채기 어렵다.
- **LLM 이 기억을 요약하고 고쳐 쓰는 정비(dreaming)를 둔다.** 사람 승인 지점이 없고 이력이 흐려진다.
- **모든 기억에 같은 시간 감쇠를 둔다.** 가족 정보는 오래돼도 중요하다.
- **`fact_kind`(`TRAIT`, `STATE`, `EVENT`) 분류를 둔다.** 처음 계획이었다. 정비 루프가 쓰는 것은 「자동 보관해도 되는가」 하나뿐이고, 종류를 enum 으로 굳히면 모델이 더 잘게 판단해도 그 구조에 묶인다(2026-10-16 사용자 결정).
- **단추 사건을 새 테이블에 둔다.** 판단 피드백과 기억 단추는 둘 다 「사용자가 이 제안이나 이 기억에 어떻게 반응했는가」 다. 정비 규칙이 한 곳에서 읽는다.
- **proactive 반응이 기억 주입을 바로 바꾼다.** 거절 한 번이 그 기억을 밀어낸다. #374 의 원칙과 어긋난다.

### 결과

얻는 것

- 쓰이지 않는 상태와 지난 일이 쌓여 색인을 밀어내는 일이 준다.
- 사용자가 틀린 기억을 답 아래에서 바로 알릴 수 있다.
- 모든 자동 처리를 기록으로 감사하고 되돌린다.

감당할 것

- 4주 동안 사람이 후보를 확인해야 한다. 확인하지 않으면 자동으로 바뀌지 않는다.
- 기준 정밀도와 확인 표본 수는 단계 3 의 계획에서 정한다. 표본이 작으면 정밀도가 흔들린다.
- 모델이 장기 사실에 `archivable` 을 참으로 주면 그 사실이 보관 후보가 된다. 기본값을 거짓으로 두어 모를 때는 보관하지 않고, 보관은 되돌릴 수 있다.
