## ADR-20261120 / generated-image-draft: 만든 그림은 사진 첨부 사본으로 블로그 원고에 넣는다

- **status**: `accepted`
- Date: 2026-11-20
- **decision-type**: `architecture`
- **현재 규칙의 원본**: 설계 [`docs/features/generated-image/design.md`](../features/generated-image/design.md) 의 「PR4」, 스펙 [`spec.md`](../features/generated-image/spec.md) 의 REQ18, REQ19(사용자 확인 2026-11-19), [`content-draft.md`](../features/content-draft.md)
- 원고의 사진 판정과 두 지문은 바꾸지 않는다. [ADR-20261119 / generated-image](ADR-20261119-generated-image.md) 의 그림 행을 그대로 둔다

### 결정

**모델이 `content_draft_image` 에 그림 제목을 주면 Control Plane 이 그 그림의 사진 첨부(`chat_attachment`) 사본을 같은 대화에 만들고 첨부 번호와 파일 이름을 돌려준다. 원고와 초안은 그 사본을 보통 사진처럼 가리킨다.**

| 항목 | 정한 것 |
| --- | --- |
| 사본의 표시 | `chat_attachment.source_artifact_id` 에 그림 행 번호를 적고 `message_id` 는 비운다 |
| 보관 기간과 삭제 | 사진 첨부의 규칙을 그대로 따른다. 그림 파일이 지워져도 사본은 남는다 |
| 사진 목록 | 메시지에 묶지 않아 화면과 사진 순번, 사진 참조 목록에 나오지 않는다. 보내지 않은 사진의 장수와 메시지 묶기에서 뺀다 |
| 되풀이 | 같은 그림의 쓸 수 있는 사본이 있으면 그것을 돌려준다. 그림 파일이 지워졌으면 사본이 있어도 거절한다 |
| 그림 파일이 지워졌다 | 사본을 만들지 않고 `IMAGE_SOURCE_GONE` 이다 |

### 맥락

원고는 사진 첨부 번호만 가리키고, 미리보기와 원고 저장, 승인 카드, 네이버 임시저장 worker 가 모두 그 번호로 같은 사진 폴더의 파일을 읽는다. worker 는 모든 사진이 한 폴더에 있어야 하고, 원고 snapshot 의 두 지문은 Java 와 TypeScript 가 같은 값으로 다시 계산한다.
만든 그림은 대화 결과물 폴더의 `chat_artifact` 행이라 이 길 밖에 있다. 초안 미리보기(`render_draft`)는 원고 저장보다 먼저 돌아 그때 이미 사진 파일 이름이 있어야 한다.

### 대안 기각

- 원고의 사진 자리에 그림 행을 가리키는 새 종류를 둔다: 원고 스키마, 두 지문의 golden 값, Java 재계산, worker 의 사진 폴더 규칙을 함께 바꾸고, worker 가 결과물 폴더를 읽게 운영 마운트도 바꿔야 한다.
- `content_draft_write` 의 `assetId` 에 `generated:<제목>` 을 받아 저장할 때 사본을 만든다: 원고를 저장하기 전에 도는 초안 미리보기가 그림의 파일 이름을 몰라 그림을 보이지 못한다.
- 그림을 만들 때 처음부터 사진 첨부로 둔다: 대화의 사진 순번과 사진 참조 목록에 그림이 섞여 사용자가 부르는 사진 번호가 바뀐다. 원고에 넣지 않는 그림까지 두 벌이 된다.
- 사본을 그 답 메시지에 묶는다: 그림을 만든 turn 안에서 넣으면 답 메시지가 아직 없다. 묶으면 화면과 사진 순번에서 따로 빼야 하는 곳이 더 많다.

### 결과

- 얻는 것: 원고, 미리보기, 승인 카드, worker 가 고칠 것 없이 그림을 쓴다. 넣은 그림은 사진과 같은 보관 규칙으로 원고에 남는다(REQ19).
- 감당할 것: 원고에 넣은 그림은 결과물 폴더와 사진 폴더에 두 벌이 있다. 사본을 만들고 원고를 저장하지 않으면 사본이 보관 기간까지 남는다. 사진 첨부를 「메시지에 묶인 것」 으로 읽는 새 코드는 사본을 따로 생각해야 한다.
- 확인 방법: Control Plane 의 MCP 통합 테스트가 사본의 바이트와 원고 snapshot 입력, 사진 목록에서 빠지는지를 본다. 실제 네이버 임시저장은 배포 뒤 운영에서 그림 한 장을 원고 미리보기에 넣어 확인한다.
