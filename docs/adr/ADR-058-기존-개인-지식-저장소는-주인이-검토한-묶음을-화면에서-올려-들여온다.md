## ADR-058: 기존 개인 지식 저장소는 주인이 검토한 묶음을 화면에서 올려 들여온다

- **status**: `retired`. 2026-10-07 사용자 결정으로 원본과 아카이브를 퇴역하고 도구와 가져오기 API 를 제거했다.

### 2026-10-07: 원본과 아카이브 퇴역, 이관 도구 제거

#101 의 Memory 목적지 대조는 끝내지 못했다.
사용자 결정으로 원본과 아카이브를 퇴역하고 이관 도구를 닫는다.
이 저장소의 이관 스크립트, 기억 가져오기 API 와 서비스, 전용 시험과 이관 구현 계획서를 제거한다.
웹의 가져오기 화면과 호출 코드, 전용 시험과 프록시도 같은 변경에서 함께 제거한다.

이미 들인 기억과 문서, 판 이력은 유지한다.
`source_type` 의 `brain` 값과 그 표시, `source_ref`, `source_date` 는 출처 기록으로 남긴다.
DB 표와 칸, 유일 제약은 바꾸지 않으며 마이그레이션도 만들지 않는다.
신원 항목을 포함한 추가 이관 기능은 만들지 않는다. 앞으로 문서는 ADR-057 의 작성·수정 경로로 관리한다.

아래는 이관을 추진할 당시의 결정 기록이다. 현재 사용할 API 나 도구의 안내가 아니다.

### 이관 당시의 결정

- **결정**: 이 서비스 밖에 쌓아 둔 개인 지식 저장소를 Memory 로 옮기는 일은 **일회성 이관 절차**가 맡는다.
  절차는 넷으로 나뉘고 한 명령이 분류부터 저장까지 몰아서 하지 않는다.

  | 단계 | 누가 어디서 | 하는 일 | 쓰는 곳 |
  | --- | --- | --- | --- |
  | 분석 | 주인의 기기, 지식 저장소의 분석기 | 파일마다 분류와 상태를 제안하고 보고서를 만든다 | 없다. 보고서 파일뿐이다 |
  | 검토 | 주인 | 보고서를 읽고 항목마다 들일지, 어디에 무엇으로 들일지 결정 파일에 적는다 | 없다 |
  | 묶기 | 주인의 기기, 이 저장소의 스크립트 | 들이기로 한 항목의 본문을 읽어 묶음 파일 하나로 만든다 | 없다. 묶음 파일뿐이다 |
  | 들이기 | 주인이 로그인한 `/memory` 화면 | 묶음을 올려 대조 결과를 보고, 확인하면 저장한다 | Memory |

  **쓰는 길은 들이기 하나이고 주인의 웹 로그인으로만 열린다.** 새 토큰을 만들지 않는다. 서비스 토큰은 계속 읽기만 한다([ADR-056](ADR-056-다른-서비스는-사용자에-묶인-서비스-토큰으로-문서를-읽기만-한다.md)).
  들인 항목은 요청자가 주인인 `USER` 범위이고 곧 `ACCEPTED` 다. 결정 파일을 적고 화면에서 확인한 것이 승인이다.
  분류와 상태는 제안이다. 사람이 결정 파일에 적은 것만 묶인다. `CONFLICT` 는 자동으로 합치지 않는다.
  같은 출처는 두 번 들이지 않는다. 출처는 `source_type`, `source_ref`, `source_date` 에 적고 `source_ref` 로 판정한다.
  신원 문서는 마지막에 들인다. 암호화와 문서 읽기 경계와 `identity` 권한을 운영에서 확인한 뒤에만 연다.
- **맥락**: 사용자에 대한 장기 지식의 기준 원본을 이 서비스로 옮기려 한다. 지금은 개인 저장소 둘의 `wiki/` 와 `raw/` 에 흩어져 있다.
  [ADR-057](ADR-057-문서는-사람이-화면에서-직접-쓰고-고친다.md) 은 문서를 사람이 화면에서 붙여 넣게 했다. 문서 하나에는 맞지만 수십 개를 옮기기에는 맞지 않고, 붙여 넣으면 출처와 날짜가 남지 않는다.
  Memory 는 사람이 승인한 것만 남는다([ADR-012](ADR-012-memory-는-사람이-승인한-것만-남는다.md)). 이관도 그 원칙 안에 있어야 한다.
  `memory` 표는 출처 칸 셋과 종류 `SOURCE`, 꺼내는 방식 `ARCHIVE` 를 이미 갖는다([ADR-052](ADR-052-memory-는-collection-종류-꺼내는-방식-민감도-판-출처를-가진다.md)). 만드는 길만 없었다.
  분석기는 지식 저장소 쪽에 이미 있다. 원본과 대상에 쓰지 않고 보고서만 만든다.
- **대체된 부분**: 없다. ADR-057 의 「다른 곳에 있는 문서를 옮길 때 사람이 붙여 넣어야 한다」 를 일회성 이관에 한해 넓힌다. 평소의 문서 쓰기는 ADR-057 그대로다.
- **대안 기각**:
  - 서비스 토큰에 쓰기를 더한다: 늘 켜져 있는 쓰기 길이 생긴다. 토큰이 새면 문서가 바뀐다. 이관은 한 번 하는 일이다.
  - 수명이 짧은 이관 전용 토큰과 명령을 만든다: 쓰기 권한을 가진 토큰 종류가 하나 는다. 민감 본문이 명령 인자와 셸 이력에 남을 수 있다. ADR-057 이 관리 명령을 기각한 까닭과 같다.
  - 분석기가 곧바로 저장한다: 분류 규칙이 틀리면 틀린 항목이 승인된 채 들어온다. 제안과 저장 사이에 사람이 있어야 한다.
  - 들인 항목을 `PROPOSED` 로 두고 화면에서 하나씩 승인한다: 문서는 승인 전 상태를 두지 않는다(ADR-057). 수십 개를 두 번 검토하게 된다. 결정 파일과 화면의 확인이 그 검토다.
  - 분석기를 이 저장소로 옮긴다: 분석 규칙은 그 지식 저장소의 폴더와 메타데이터 모양을 안다. 이 저장소는 보고서의 모양만 안다.
  - `CONFLICT` 를 최신 날짜로 자동으로 합친다: 날짜가 새롭다고 맞는 사실은 아니다. 사람이 원본을 고치거나 어느 쪽을 들일지 적는다.
  - 대조를 본문 해시로 한다: 민감 본문은 암호문이라 저장된 값으로 견줄 수 없고, 해시를 따로 두면 본문의 지문이 평문 칸에 남는다. 출처와 문서 이름과 제목으로 견준다.
- **결과**:
  - 얻는 것: 기존 지식이 출처와 날짜를 가진 채 들어온다. 어느 파일에서 왔는지 항목마다 남는다.
    같은 묶음을 다시 올려도 이미 들어온 항목은 다시 저장되지 않는다.
    쓰는 길이 주인의 화면 하나라 서비스 토큰의 경계가 그대로다.
  - 감당할 것: **묶음 파일은 민감 본문을 평문으로 담는다.** 저장소 밖의 임시 자리에만 만들고, 들이기가 끝나면 지운다. 커밋하지 않고 로그에 내지 않는다.
    묶음은 브라우저와 웹 서버를 지나 Control Plane 으로 간다. 문서를 화면에서 쓸 때와 같은 길이다.
    한 번에 올리는 묶음에 상한이 있다. 넘으면 나눠 올린다.
    들인 뒤 원본을 고쳐도 따라오지 않는다. 이관은 한 번이고, 그 뒤의 기준 원본은 이 서비스다.
    이미 들인 출처의 본문이 원본에서 바뀌었는지는 알려 주지 않는다. `DUPLICATE` 로만 답한다.
    분류 규칙이 놓친 민감 정보는 사람이 검토에서 잡아야 한다.
- **적용 범위**:

  보고서와 결정 파일과 묶음. 셋 다 주인의 기기에만 있고 저장소에 넣지 않는다.

  | 파일 | 만드는 쪽 | 담는 것 |
  | --- | --- | --- |
  | 보고서 | 지식 저장소의 분석기 | `schema_version` 1 과 만든 시각 `generated_at`. 항목마다 `namespace`, `source_ref`, `source_date`, `title`, `collection`, `entry_type`, `retrieval`, `sensitivity`, `document_key`, `classification`, `verdict`, `hold`. 민감 항목의 본문과 요약은 없다 |
  | 결정 파일 | 이 저장소의 스크립트가 틀을 만들고 주인이 고친다 | 어느 보고서의 결정인지 적는 `reportGeneratedAt`. 항목마다 `decision`(`PENDING`, `IMPORT`, `SKIP`)과 고쳐 쓸 수 있는 `collection`, `entryType`, `documentKey`, `title`, `sensitive`, `retrieval`. `CONFLICT` 항목을 들이려면 `conflictResolution` 을 `KEEP_THIS` 로, 보류 까닭(`hold`)이 있는 항목을 들이려면 `holdCleared` 를 참으로 적는다 |
  | 묶음 | 이 저장소의 스크립트 | `schemaVersion` 1 과 만든 시각 `createdAt` 과 항목 목록. 항목마다 `sourceRef`, `sourceDate`, `collection`, `entryType`, `documentKey`, `title`, `content`, `sensitive`, `retrieval` |

  분류는 `IMPORT_MEMORY`, `IMPORT_DOCUMENT`, `IMPORT_SOURCE`, `SKIP`, `REVIEW_REQUIRED` 이고 상태는 `NEW`, `DUPLICATE`, `CONFLICT`, `STALE` 이다.
  묶는 스크립트는 `PENDING` 이 하나라도 남았으면 멈춘다. 결정 파일의 `reportGeneratedAt` 이 보고서의 `generated_at` 과 다르면 다른 보고서의 결정으로 보고 멈춘다. 보류 까닭이 있는 항목은 사람이 `holdCleared` 를 적어야 묶인다. `REVIEW_REQUIRED` 항목은 결정 파일에 종류를 적어야 묶인다. 표준 출력에는 개수만 낸다.

  분류의 기본 제안. 사람이 결정 파일에서 고친다.

  | 원본 | 들이는 자리 |
  | --- | --- |
  | 일반 선호와 일하는 방식 | `core`, `MEMORY` |
  | 커리어 선호와 개인 경력 판단 | `career`, `MEMORY` 또는 `DOCUMENT` |
  | 배우고 싶은 것 | `learning`, `DOCUMENT` |
  | 건강 | `health`, `DOCUMENT` |
  | 재무 | `finance`, `DOCUMENT` |
  | 생활과 주거 목표 | `home` 또는 `core` |
  | 지원서 공통 프로필과 개인 신원 | `identity`, `DOCUMENT`, `SENSITIVE`. 마지막에 들인다 |
  | 지난 상담 원문 | 그 주제의 collection, `SOURCE`, `ARCHIVE` |
  | 커밋, 작업 디렉터리, 계획 같은 작업 기록 | 들이지 않는다 |
  | 공개한 공부 글 | 들이지 않는다. 공부 글 저장소에 남는다 |

  들이기. 모두 웹의 JWT 로 부르고 요청자가 주인이 된다.

  | 경로 | 하는 일 |
  | --- | --- |
  | `POST /api/v1/memory-imports/preview` | 묶음을 받아 항목마다 대조 결과를 낸다. 저장하지 않는다 |
  | `POST /api/v1/memory-imports` | 같은 묶음을 받아 `NEW` 인 항목만 한 트랜잭션으로 저장하고 항목마다 결과를 낸다 |

  | 항목의 결과 | 언제 | 저장 |
  | --- | --- | --- |
  | `NEW` | 아래 어느 것에도 걸리지 않는다 | 한다 |
  | `DUPLICATE` | 요청자의 항목 가운데 `source_type` 이 `brain` 이고 `source_ref` 가 같은 것이 있다 | 하지 않는다 |
  | `CONFLICT` | 출처는 다른데 같은 collection 에 같은 `documentKey` 의 문서가 있다. 또는 같은 collection 에 같은 제목의 `MEMORY` 가 있다 | 하지 않는다. 사람이 화면에서 고치거나 결정 파일의 이름을 바꾼다 |
  | `REJECTED` | 칸이 틀렸다, collection 이 그 그룹에 없다, 본문이 12,000자를 넘는다, 종류에 맞지 않는 `retrieval` 이다(문서는 `SEARCH`, 원문은 `ARCHIVE`, 기억은 `ALWAYS` 나 `SEARCH`, 민감 항목은 `ALWAYS` 가 아니다), 같은 묶음의 앞 항목과 출처나 문서 이름이 같다, 신원 항목인데 아직 열지 않았다 | 하지 않는다. 항목마다 까닭의 코드를 낸다 |

  요청 전체를 거절하는 경우. 아무것도 저장하지 않는다.

  | 응답 | 언제 |
  | --- | --- |
  | 400 `VALIDATION_FAILED` | 항목이 없다, 100개를 넘는다, `schemaVersion` 이 1 이 아니다 |
  | 409 `MEMORY_ENCRYPTION_UNAVAILABLE` | 새로 들일 민감 항목이 있는데 암호화 key 가 없다. 미리보기도 같다 |
  | 409 `MEMORY_IMPORT_RETRY` | 들이는 사이에 같은 출처나 같은 이름의 줄이 먼저 들어왔다. 다시 올리면 그 항목이 `DUPLICATE` 나 `CONFLICT` 로 나온다 |
  | 413 `MEMORY_IMPORT_TOO_LARGE` | 요청 본문이 2MB 를 넘는다. 웹 서버 라우트가 Control Plane 을 부르기 전에 거절한다 |

  | 상한 | 값 |
  | --- | --- |
  | 묶음 하나의 항목 수 | 100 |
  | 항목 하나의 본문 | 12,000자. 문서와 같다 |
  | 요청 본문의 크기 | 2MB. 웹 서버 라우트가 먼저 거절한다 |

  들인 줄은 `source_type` 이 `brain`, `source_ref` 가 `<namespace>/<저장소 안의 경로>`, `source_date` 가 보고서의 날짜다.
  `MEMORY` 는 묶음이 적은 `retrieval` 을, `DOCUMENT` 는 `SEARCH` 를, `SOURCE` 는 `ARCHIVE` 를 갖는다.
  같은 주인의 같은 출처가 두 줄이 되지 않게 `owner_user_id`, `source_type`, `source_ref` 에 유일 제약을 둔다.
  민감 항목은 [ADR-055](ADR-055-민감-memory-본문은-저장할-때-암호화하고-key-는-환경-변수로-받는다.md) 대로 암호화한다. key 가 없으면 그 요청을 `MEMORY_ENCRYPTION_UNAVAILABLE` 로 거절하고 아무것도 저장하지 않는다.
  로그에는 사용자 번호와 결과별 개수만 남긴다. 제목과 본문과 `source_ref` 는 남기지 않는다.

  신원 항목을 여는 조건. 셋을 운영에서 관측한 뒤에만 연다.

  | 조건 | 관측할 결과 |
  | --- | --- |
  | 민감 본문 암호화 | 지어낸 본문으로 만든 민감 문서의 `content` 가 `v1.` 으로 시작하고 `content_key_id` 가 채워져 있다. key 의 보관 사본이 있다 |
  | 문서 읽기 경계 | 토큰 없는 요청과 폐기한 토큰과 끈 사용자의 토큰이 모두 401 이다. 민감 허용이 없는 토큰은 민감 문서에 404 다 |
  | `identity` 권한 | `identity` 를 받는 에이전트가 없다. `identity` 를 받는 서비스 토큰이 주인이 아는 것뿐이다 |

- **다음**: 그룹 공용 지식의 이관, 이미 들인 출처의 본문이 바뀌었는지 알려 주는 일, 들인 원문(`SOURCE`)을 보는 화면은 필요할 때 정한다.
  이관이 끝난 뒤 묶는 스크립트와 들이기 경로를 남길지는 그때 정한다.
