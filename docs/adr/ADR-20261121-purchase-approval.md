## ADR-20261121 / purchase-approval: 구매는 매번 승인받고 결제 직전에 승인 금액을 확인한다

- **status**: `accepted`
- Date: 2026-11-21
- **decision-type**: `domain-policy`
- **areas**: `connector`
- [ADR-20261113 / purchase-checkout](ADR-20261113-purchase-checkout.md) 의 구매 상한, 설정, 금액 검사 시점 가운데 상한과 관련된 결정을 대체한다. 동작의 상세는 [네이버 쇼핑 스펙](../features/naver-shopping/spec.md)과 [설계](../features/naver-shopping/design.md)가 갖는다

### 맥락

사용자가 사겠다고 해도 구매 상한의 기본값이 0 이어서 승인 카드가 뜨지 않았다. 네이버 쇼핑에서 결제를 마치려면 사용자가 직접 결제 비밀번호를 입력해야 한다. 2026-11-21 사용자 결정으로 한 건과 하루 상한을 없앤다.

### 결정

사람이 연 대화에서 주문서 준비가 성공하면 상품과 예상 합계를 담은 승인 카드를 띄운다. 사용자가 매번 승인하면 플러그인이 주문서를 한 번 채운다. 최종 결제 금액이 승인한 예상 합계보다 1원이라도 크면 멈추고 두 금액을 알린다. 같거나 작으면 결제 화면을 넘기고 사용자가 직접 결제한다.

사람이 해야 하는 화면을 만나면 기존과 같이 `WAITING` 으로 두고 같은 승인으로 이어 간다. 금융 주문에는 [ADR-20261015 / financial-user-limits](ADR-20261015-financial-user-limits.md) 를 적용한다.

### 결과

준비부터 결제 화면 넘기기까지 상한 검사와 하루 합계를 거둔다. 설정 API와 화면 입력 칸을 지우고, 새 마이그레이션으로 `app_user` 에서 관련 컬럼을 지운다. 이전 서버 버전으로 되돌리려면 옛 버전이 읽는 스키마도 복원해야 한다.

`CheckoutApprovalTest` 는 주문서 준비가 승인을 기다리는지, 승인 뒤 같은 금액 또는 더 작은 금액을 결제 단계에 넘기는지, 더 큰 금액에서 멈추는지 확인한다. 배포 후 실제 대화에서 상품을 사 달라고 하여 승인 카드가 뜨는지 확인하고 결제는 진행하지 않는다.
