## ADR-20261008: 바로 저장은 사용자가 쓴 문장을 그대로 옮긴 본문만 받고, 민감해 보이는 글과 오래된 대화는 제안으로 내린다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-20261007 / memory-remember](ADR-20261007-memory-remember.md) 의 「바로 저장 조건」 2 와 5, 「감당할 것」 의 민감도 항목과 `execution_question` 이전 실행 항목을 개정한다.
  사용자가 직접 말한 사실은 기억해 달라고 하지 않아도 바로 저장한다는 결정과 나머지 조건(루트 실행, 사람이 보낸 turn, 대화 단위 바깥 도구 검사)은 그대로다.

### 결정

**바로 저장의 근거를 모델이 준 `evidence` 가 아니라 저장할 본문 자체로 확인한다.**
`evidence` 인자는 판정에 쓰지 않는다. 앞선 도구 정의로 부르는 모델이 인자 오류를 받지 않게 스키마에는 남긴다.

바로 저장(`ACCEPTED`)은 기존 조건에 아래를 모두 더해 만족할 때만 한다. 하나라도 어긋나면 제안(`PROPOSED`)으로 내린다. 거절하지 않는다.

1. **본문은 이번 질문 원문의 문장 단위 구간과 같다.** NFC 로 맞추고 연속 공백을 하나로 줄여 비교한다.
   - 구간의 앞은 글의 처음, 줄바꿈, 문장부호나 콜론 뒤의 공백, 「기억해 줘」 같은 요청 구절 뒤의 공백 가운데 하나다.
   - 구간의 끝은 글의 끝, 줄바꿈, 뒤에 공백이나 글 끝이 오는 문장부호(물음표 제외), 공백 뒤의 요청 구절 가운데 하나다.
   - 본문에 물음표가 있으면 구간으로 보지 않는다. 묻는 말은 사실이 아니다.
   - 낱말 경계는 구간의 끝으로 보지 않는다. 「좋아하지 않아」 에서 「좋아하지」 만 떼거나 「3.5」 에서 「3」 만 떼면 뜻이 바뀐다.
2. **제목은 본문 안에 그대로 든 글이다.** 제목은 다음 실행의 색인에 실려 본문 없이 읽힌다. 본문만 맞추고 제목으로 뜻을 뒤집는 길을 막는다.
3. **제목이나 본문에 민감해 보이는 낱말이나 숫자열이 없다.** 건강, 금융, 신원과 신념의 낱말과 여섯 자리 이상의 숫자열, 메일 주소를 Control Plane 이 찾는다.
   찾으면 모델이 `sensitive` 를 거짓으로 주었어도 제안으로 내린다. 민감도는 모델이 준 값 그대로 둔다. 사람이 제안 카드에서 본문을 읽고 정한다.
4. **그 대화에 사람의 질문 없이 Hermes 로 보낸 루트 실행이 하나도 없다.** `execution_question` 이 생기기 전의 실행도 센다.
   그런 실행이 있는 오래된 대화에서는 바로 저장하지 않는다.

기존 항목 고치기(`memory_id`)와 같은 내용의 제안 받아들이기도 같은 판정을 거친다.
되돌리기, 판 기록, USER 범위, collection 허용, 옛 커넥터 에이전트 격리, 한 실행 3개 상한, 중복과 거절 뒤 재제안 억제는 그대로다.

### 맥락

이슈 #283 이 ADR-20261007 / memory-remember 의 판정에서 세 틈을 짚었다. 실제로 난 사고가 있다는 주장은 아니다.

- **근거는 맞고 본문은 다르다.** 판정은 `evidence` 가 질문 원문에 있는지만 보았다. 본문이 그 구절과 같은 뜻인지는 보지 않았다.
  「매운 음식을 못 먹는다」 에서 「매운 음식」 을 근거로 주고 본문을 「매운 음식을 좋아한다」 로 주면 바로 저장됐다.
  기존 시험도 근거 「다른 사람은 홍길동이야」 로 본문 「다른 사람은 김철수다」 를 바로 저장하고 있었다.
- **민감도는 모델이 정한다.** 계좌번호나 병명을 `sensitive=false` 로 주면 일반 항목으로 바로 저장됐다.
- **오래된 대화는 맡긴 일의 결과 turn 을 보지 않았다.** 대화의 첫 `execution_question` 보다 앞선 실행을 세지 않아, 기능 도입 전에 받은 바깥 글이 같은 session 이력에 남은 대화에서 바로 저장이 열렸다.

뜻이 같은지와 민감한지를 모델에게 다시 물어 판정하면 그 답도 모델의 주장이다. 바깥 글이 모델을 움직이면 같은 길로 통한다.
그래서 Control Plane 이 기록과 글자만으로 판정할 수 있는 조건으로 바꾼다.

2026-10-08 사용자가 기억해 달라는 구절을 바로 저장의 조건으로 삼지 않기로 정했다.
2026-10-06 의 결정(기억해 달라고 하지 않은 사실도 대화 안에서 남는다)을 지킨다.
본문이 사용자의 문장 그대로여야 하므로, 요청 구절이 없어도 저장되는 것은 사용자가 이번 메시지에 직접 쓴 문장뿐이다.

### 대안 기각

- **`evidence` 와 본문의 낱말이 겹치는지 본다.** 한국어는 「못」, 「-지 않다」 처럼 부정이 낱말 하나로 붙는다. 낱말이 모두 겹쳐도 부정 하나가 빠지면 뜻이 뒤집힌다.
- **모델에게 본문이 근거와 같은 뜻인지 다시 묻는다(entailment).** 판정이 다시 모델의 주장이 된다. 실행마다 모델 호출도 늘어난다.
- **명시적 요청 구절이 있을 때만 바로 저장한다.** 이슈가 권한 보수적인 기본값이다. 2026-10-08 사용자가 고르지 않았다. 본문이 사용자의 문장 그대로여야 하는 조건으로 뜻이 뒤집히는 길은 이미 닫힌다.
- **민감해 보이면 `SENSITIVE` 로 올려 암호화 저장한다.** 민감 항목은 카드와 목록에 본문이 실리지 않고 고쳐서 받아들이기도 막힌다. 사람이 본문을 보고 판단할 길이 없어진다. 낱말 검사는 잘못 걸리는 경우도 많다.
- **`evidence` 인자를 스키마에서 지운다.** 도구 목록을 다시 읽기 전의 Hermes 연결이 옛 정의로 부르면 인자 오류가 난다. 판정에서만 뺀다.
- **오래된 대화의 기능 도입 전 실행은 계속 보지 않는다.** 그 실행에 맡긴 일의 결과 turn 이 있었는지 지금 기록으로 가릴 수 없다. 이슈의 완료 조건인 「오래된 session 맥락이 바로 저장 경계를 열지 못한다」 를 지키지 못한다.

### 결과

얻는 것

- 바로 저장된 본문은 사용자가 이번 메시지에 쓴 문장 그대로다. 모델이 뜻을 바꿔 쓴 본문, 근거 구절만 빌린 본문은 제안으로 내려가 사람이 본다.
- 색인에 실리는 제목이 본문과 다른 뜻을 말하지 못한다.
- 민감해 보이는 글은 모델이 일반으로 주어도 사람이 한 번 본다.
- 기능 도입 전 이력이 남은 대화도 바깥 글이 바로 저장을 열지 못한다.

감당할 것

- 모델이 사용자의 말을 다듬어 본문을 쓰면(「홍길동이야」 를 「홍길동이다」 로) 제안 카드가 된다. 도구 설명과 지침에 「본문은 사용자의 문장을 고치지 않고 옮긴다」 를 적어 줄인다. 받아들이기는 그 자리에서 한 번 누르면 된다.
- 문장부호 없이 「ㅎㅎ」 나 이모지로 끝나는 문장은 구간의 끝을 찾지 못해 제안이 된다.
- 민감 낱말 목록은 잘못 걸리는 경우가 있다(「장애물」 의 「장애」). 그때는 제안 카드가 되고 저장 결과는 같다. 목록은 운영에서 걸린 사례를 보고 고친다.
- 질문 원문 안의 문장이라도 사용자가 다음 문장에서 부정하거나 가정으로 말한 것이면 그대로 저장된다. 사용자의 글 그대로이고 대화에 「기억했어요」 와 [되돌리기] 가 보인다.
- 기능 도입 전 실행이 있는 대화와 질문 줄 저장에 한 번이라도 실패한 대화는 그 뒤로 제안만 남긴다. 새 대화를 열면 바로 저장이 다시 열린다.

### 적용 범위

낱말 목록 자체는 코드가 갖는다.
