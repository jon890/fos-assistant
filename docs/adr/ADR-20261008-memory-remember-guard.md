## ADR-20261008 / memory-remember-guard: 바로 저장은 모델이 다듬은 본문도 받고, 부정이 뒤집힌 글과 민감해 보이는 글과 오래된 대화만 제안으로 내린다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-20261007 / memory-remember](ADR-20261007-memory-remember.md) 의 「바로 저장 조건」 2 와 5, 「감당할 것」 의 민감도 항목과 `execution_question` 이전 실행 항목을 개정한다.
  사용자가 직접 말한 사실은 기억해 달라고 하지 않아도 바로 저장한다는 결정과 나머지 조건(루트 실행, 사람이 보낸 turn, 대화 단위 바깥 도구 검사)은 그대로다.

### 결정

**`evidence` 인자를 바로 저장의 근거로 쓰지 않는다.** 앞선 도구 정의로 부르는 모델이 인자 오류를 받지 않게 스키마에는 남긴다.
**본문이 질문 원문과 글자 그대로 같을 것을 요구하지 않는다.** 모델이 요약하거나 다듬은 본문도 바로 저장한다.

그 대신 Control Plane 이 글자와 기록만으로 잡을 수 있는 경우를 제안(`PROPOSED`)으로 내린다. 거절하지 않는다.

1. **부정이 한쪽에만 있다.** 부정 표지(「못」, 「안」, 「않」, 「없」, 「아니」 와 그 활용형)가 질문 원문과 본문 가운데 한쪽에만 있으면 뜻이 뒤집혔을 수 있다.
   「매운 음식을 못 먹는다」 를 본문 「매운 음식을 좋아한다」 로 남기는 것과, 「매운 음식 좋아해」 를 「매운 음식을 못 먹는다」 로 남기는 것이 모두 걸린다.
2. **제목이나 본문이 민감해 보인다.** 건강, 금융, 신원과 신념의 낱말과 여섯 자리 이상의 숫자열, 메일 주소를 Control Plane 이 찾는다.
   모델이 `sensitive` 를 거짓으로 주었어도 제안으로 내린다. 민감도는 모델이 준 값 그대로 두고 사람이 제안 카드에서 본문을 읽고 정한다.
3. **그 대화에 사람의 질문 없이 Hermes 로 보낸 루트 실행이 하나라도 있다.** `execution_question` 이 생기기 전의 실행도 센다.
   기능 도입 전 이력이 남은 오래된 대화에서는 바로 저장하지 않는다.

**오판은 사람이 그 자리에서 알아채고 고친다.** 대화의 「기억했어요」 줄에 제목과 함께 저장한 본문 전문을 보이고, [고치기] 와 [되돌리기] 를 그 줄에 둔다.

기존 항목 고치기(`memory_id`)와 같은 내용의 제안 받아들이기도 같은 판정을 거친다.
되돌리기, 판 기록, USER 범위, collection 허용, 옛 커넥터 에이전트 격리, 한 실행 3개 상한, 중복과 거절 뒤 재제안 억제는 그대로다.

### 맥락

이슈 #283 이 ADR-20261007 / memory-remember 의 판정에서 세 틈을 짚었다. 실제로 난 사고가 있다는 주장은 아니다.

- **근거는 맞고 본문은 다르다.** 판정은 `evidence` 가 질문 원문에 있는지만 보았다. 본문이 그 구절과 같은 뜻인지는 보지 않았다.
  「매운 음식을 못 먹는다」 에서 「매운 음식」 을 근거로 주고 본문을 「매운 음식을 좋아한다」 로 주면 바로 저장됐다.
- **민감도는 모델이 정한다.** 계좌번호나 병명을 `sensitive=false` 로 주면 일반 항목으로 바로 저장됐다.
- **오래된 대화는 맡긴 일의 결과 turn 을 보지 않았다.** 대화의 첫 `execution_question` 보다 앞선 실행을 세지 않아, 기능 도입 전에 받은 바깥 글이 같은 session 이력에 남은 대화에서 바로 저장이 열렸다.

`evidence` 대조는 근거 구절이 사용자의 말이라는 것만 보이고 본문이 그 말과 같은 뜻이라는 것은 보이지 못했다. 허가 근거로 남겨 두면 이 틈이 그대로다.

2026-10-08 사용자가 두 번 방향을 정했다.
처음에는 본문이 질문 원문의 문장과 글자 그대로 같을 때만 바로 저장하는 안을 골랐다.
같은 날 다시, ChatGPT 처럼 자동으로 기억하고 다음 대화에서 알고 있는 사용성을 더 중요하게 본다고 정했다.
모델이 다듬은 본문을 제안으로 돌리면 대부분의 기억이 카드가 된다. 그래서 글자 대조를 빼고, 결정적으로 잡히는 뒤집힘과 민감 정보와 바깥 글만 사람에게 돌린다.

뜻이 같은지와 민감한지를 모델에게 다시 물어 판정하지 않는다. 그 답도 모델의 주장이라 바깥 글이 모델을 움직이면 같은 길로 통한다.

### 대안 기각

- **본문이 질문 원문의 문장 단위 구간과 같아야 바로 저장한다.** 뜻이 뒤집히는 길을 가장 확실히 닫는다. 모델이 「홍길동이야」 를 「홍길동이다」 로만 바꿔도 제안이 된다. 2026-10-08 사용자가 사용성을 이유로 거뒀다.
- **`evidence` 와 본문의 낱말이 겹치는지 본다.** 부정 하나가 빠지면 낱말이 모두 겹쳐도 뜻이 뒤집힌다. 부정 표지를 따로 보는 편이 단순하고 같은 경우를 잡는다.
- **모델에게 본문이 질문과 같은 뜻인지 다시 묻는다(entailment).** 판정이 다시 모델의 주장이 된다. 실행마다 모델 호출도 늘어난다.
- **명시적 요청 구절(「기억해 줘」)이 있을 때만 바로 저장한다.** 이슈가 권한 보수적인 기본값이다. 사용자가 고르지 않았다. 기억해 달라고 하지 않은 사실도 대화 안에서 남는 것이 2026-10-06 의 결정이다.
- **민감해 보이면 `SENSITIVE` 로 올려 암호화 저장한다.** 민감 항목은 카드와 목록에 본문이 실리지 않고 고쳐서 받아들이기도 막힌다. 사람이 본문을 보고 판단할 길이 없어진다. 낱말 검사는 잘못 걸리는 경우도 많다.
- **`evidence` 인자를 스키마에서 지운다.** 도구 목록을 다시 읽기 전의 Hermes 연결이 옛 정의로 부르면 인자 오류가 난다. 판정에서만 뺀다.
- **오래된 대화의 기능 도입 전 실행은 계속 보지 않는다.** 그 실행에 맡긴 일의 결과 turn 이 있었는지 지금 기록으로 알 수 없다. 이슈의 완료 조건인 「오래된 session 맥락이 바로 저장 경계를 열지 못한다」 를 지키지 못한다.

### 결과

얻는 것

- 사용자가 말한 사실은 모델이 다듬어 써도 대화 안에서 곧바로 남는다.
- 부정이 빠지거나 생긴 본문, 민감해 보이는 글, 바깥 글이 섞였을 수 있는 대화는 사람이 한 번 본다.
- 저장한 본문 전문이 답 아래에 보여 틀린 기억을 그 자리에서 고치거나 되돌린다.

감당할 것

- 본문이 질문과 무관해도(모델이 지어낸 사실) 부정과 민감 낱말에 걸리지 않으면 바로 저장된다. 바깥 글이 섞인 대화는 제안이므로 이 경우는 모델 자체의 오판이다. 화면에 본문 전문이 보여 사람이 되돌린다.
- 부정 표지 검사는 문장을 나누지 않는다. 질문의 다른 문장에 있는 부정(「오늘은 바쁘지 않아. 아들 이름은 홍길동이야」)도 걸려 제안이 된다. 「잘 먹는 건 아니야」 처럼 부정이 두 번 겹친 말을 부정 하나로 옮기면 걸리지 않는다.
- 반대로 질문과 본문 양쪽에 부정이 있으면 서로 다른 사실의 부정이어도 통과한다. 질문 「숙제는 못 했어. 매운 음식 좋아해」 에 본문 「매운 음식을 못 먹는다」 가 오면 바로 저장된다. 질문이 길수록 부정이 들어 있을 가능성이 커진다. 문장 단위 대조는 사용성을 이유로 거둔 방향이라 두지 않고, 화면의 본문 전문으로 사람이 고친다.
- 「싫다」, 「모른다」, 「별로」 처럼 부정 표지 없이 뜻이 반대인 말은 보지 않는다.
- 「안」 은 낱말로 떨어져 있거나 몇몇 동사 앞에 붙은 것만 본다. 「안경」, 「안녕」 을 부정으로 보지 않으려는 것이다. 그 밖에 붙여 쓴 부정은 놓친다.
- 제목은 부정과 관계를 보지 않는다. 색인에는 제목만 실리므로 제목이 본문과 다른 뜻이면 다음 실행이 잘못 읽을 수 있다. 화면의 「기억했어요」 줄이 제목과 본문을 함께 보여 사람이 고친다.
- 민감 낱말 목록은 잘못 걸리는 경우가 있다(「장애물」 의 「장애」). 「장애물」 처럼 잘못 걸리면 제안 카드가 되고 저장 결과는 같다. 목록은 운영에서 걸린 사례를 보고 고친다. 생일과 기념일이 숫자열로 걸리지 않게 `1990-03-05` 같은 날짜 모양은 숫자열 검사에서 뺀다.
- 기능 도입 전 실행이 있는 대화와 질문 줄 저장에 한 번이라도 실패한 대화는 그 뒤로 제안만 남긴다. 새 대화를 열면 바로 저장이 다시 열린다.

### 적용 범위

판정 순서와 부정 표지의 모양, 민감 낱말의 갈래, 도구 계약은 [`backend/memory.md`](../backend/memory.md) 의 「에이전트가 기억을 남기는 길」 이 갖는다.
낱말 목록 자체는 코드가 갖는다.
