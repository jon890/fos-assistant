## ADR-20261008: 관리자가 에이전트의 Memory collection 을 한 번에 바꾸고, 바꾼 것은 누가 언제를 표에 남긴다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-053](../../backend/docs/adr/ADR-053-에이전트는-허용된-collection-의-memory-만-받는다.md) 의 「다음」 에 적은 관리 경로를 정한다. 판정 규칙은 바꾸지 않는다.

### 결정

**`ADMIN` 이 관리자 영역의 에이전트 상세에서 그 에이전트가 받는 collection 과 collection 마다의 민감 허용을 본다. 저장은 받는 목록 전체를 한 번에 보내 바꾼다. 줄이 바뀔 때마다 `agent_memory_collection_change` 에 무엇이 바뀌었는지와 누가 언제 바꿨는지를 한 줄씩 남긴다.**

| 항목 | 정한 것 |
| --- | --- |
| 누가 | `ADMIN` 만. 에이전트 주인도 바꾸지 못한다. 그룹 에이전트는 다른 사용자가 만든 것일 수 있어, 주인이 고르게 하면 ADR-053 이 막으려던 일이 다시 열린다 |
| 고를 수 있는 collection | 그 그룹의 `memory_collection` 목록. 지금 받는 줄은 목록에서 빠졌어도 그대로 둘 수 있다 |
| `core` 와 빈 목록 | 뺄 수 있다. 모두 빼면 그 에이전트는 Memory 를 받지 않는다. 화면은 그 사실을 경고로 보인다 |
| 옛 커넥터 에이전트 | 바꾸지 못한다. 줄이 있어도 받지 않으므로([ADR-045](../../backend/docs/adr/ADR-045-커넥터-에이전트는-자기-mcp-서버만-받고-memory-와-control-plane-도구를-받지-않는다.md)) 바꾸는 것이 뜻이 없다 |
| 자동 부여 | 하지 않는다. 사용자가 그 분야의 문서를 가졌어도 관리자가 붙이기 전에는 받지 않는다 |
| 빠진 영역 안내 | 셈 대상 사용자의 「실릴 수 있는 항목」 을 collection 마다 센다. 받지 않는 collection 에 항목이 있거나, 받지만 민감 허용이 꺼진 collection 에 민감 항목이 있으면 그 수를 보인다. 제목은 보이지 않는다 |
| 셈 대상 | 주인이 있으면 주인의 `USER` 항목과 주인 그룹의 `GROUP` 항목. 주인이 없는 그룹 에이전트는 관리자 그룹의 `GROUP` 항목만 |
| 기록 | 붙임, 뗌, 민감 허용 바꿈마다 한 줄. 붙임과 바꿈은 바꾼 뒤의 민감 허용을, 뗌은 떼기 전의 값을 적는다. 지우지 않는다 |

「실릴 수 있는 항목」 은 `ACCEPTED` 이고 `SOURCE` 와 `ARCHIVE` 가 아닌 항목이다. 실행의 세 조건 가운데 collection 과 민감도만 빼고 같은 조건이다.

### 맥락

- ADR-053 이 판정을 표로 옮긴 뒤 표를 바꾸는 길이 없었다. 새 에이전트는 `core` 만 받고, 분야 에이전트에 분야 collection 을 붙이려면 운영 데이터베이스를 직접 고쳐야 했다.
- 분야 에이전트가 `core` 만 받아 사용자가 그 분야에 남긴 문서가 문맥에 오지 않는 경우가 평가에서 나왔다. 관리자가 무엇이 빠졌는지 볼 곳이 없었다.
- 민감 허용은 건강과 재무와 신원 기록에 닿는 권한이다. 떼고 나면 표에 흔적이 남지 않아, 그 사이 누가 그 권한을 열었는지 알 수 없다.

### 대안 기각

- **바뀐 줄만 하나씩 보내는 API.** 화면은 목록 전체를 그리므로 전체를 보내는 쪽이 단순하다. 도구 선택의 `PUT` 과 같은 모양이다.
- **기록을 로그로만 남긴다.** 로그는 보관 기간이 지나면 사라진다. 민감 허용을 언제 열었는지는 그보다 오래 필요하다.
- **`agent_memory_collection` 에 마지막 변경자와 시각 칸을 둔다.** 줄을 떼면 그 칸도 함께 사라진다. 이 결정이 남기려는 것이 바로 떼기 전의 허용이다.
- **사용자의 문서를 보고 collection 을 자동으로 붙인다.** 그 사용자가 문서를 가졌다는 것이 그 에이전트가 읽어도 된다는 뜻은 아니다. ADR-053 의 「새 collection 은 누구에게도 열리지 않은 채 시작한다」 를 지킨다.
- **안내에 항목 수 대신 있음만 보인다.** 관리자가 고를 때 수가 판단에 쓰인다. 제목과 본문은 보이지 않으므로 수가 드러내는 것은 그 영역에 무엇이 있다는 사실뿐이다.
- **Memory 목록의 빠짐 표시를 에이전트마다 보인다.** ADR-053 이 이 경로와 함께 정하기로 했다. 이번에는 하지 않는다. 사용자의 목록 화면이 에이전트를 고르게 되면 화면과 조립이 함께 복잡해진다. 관리자는 이 절에서 받지 않는 수를 본다.

### 결과

- 얻는 것: 관리자가 운영 데이터베이스를 고치지 않고 에이전트의 Memory 범위를 정한다. 민감 허용을 열고 닫은 이력이 줄을 뗀 뒤에도 남는다.
- 감당할 것: 두 관리자가 같은 에이전트를 동시에 저장하면 나중 저장이 이긴다. 저장은 에이전트 행을 잠가 한 번에 하나씩 돌고, 기록에는 두 저장이 모두 남는다.
  바꾼 값은 다음 실행부터 쓰인다. 이미 돌고 있는 실행의 문맥은 바뀌지 않는다.
