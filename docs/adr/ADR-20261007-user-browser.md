## ADR-20261007: 사용자마다 브라우저 하나를 Control Plane 이 관리하고, 커넥터는 바인딩이 준 중계 주소로만 닿는다

- **status**: `accepted`
- Date: 2026-10-07
- [ADR-20261007 / naver-blog-connector](ADR-20261007-naver-blog-connector.md) 의 「사용자가 CDP 주소를 연결 칸에 넣는다」 를 바꾼다.
  [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 의 실행 공간과 같은 방식(본문을 검사하는 Docker socket proxy)으로 컨테이너를 만들되, 정책과 proxy 는 따로 둔다.

### 결정

**사용자마다 브라우저 하나를 둔다. Control Plane 이 그 브라우저의 상태를 표 하나로 갖고, 컨테이너를 만들고 멈추고 지운다.**
로그인 세션(쿠키와 저장소)은 사용자별 프로필 디렉터리에만 남고 데이터베이스에 들어가지 않는다.

| 항목 | 정한 것 |
| --- | --- |
| 단위 | 사용자 하나에 브라우저 하나(`user_browser`, `user_id` 유일). 여러 사용자가 한 브라우저를 함께 쓰지 않는다 |
| 실행 | 켤 때마다 컨테이너를 새로 만들고, 멈출 때 지운다. 남는 것은 프로필 디렉터리뿐이다. 이미지를 바꾸면 다음 켜기부터 새 이미지가 뜬다 |
| 컨테이너를 만드는 쪽 | Control Plane. 브라우저 전용 Docker socket proxy 를 거친다. proxy 는 생성 요청 본문을 검사하고 운영 저장소가 소유한다 |
| 망 | 브라우저 전용 망. 인터넷은 열고, 그 망에서 브라우저에 닿는 것은 Control Plane 하나다. Hermes 와 셸 실행 공간은 브라우저에 직접 닿지 못한다 |
| 로그인 화면 | 웹의 「내 브라우저」 화면이 CDP screencast 를 그린다. 화면은 SSE 로 받고 입력은 POST 로 보낸다. 웹은 CDP 를 직접 받지 않는다 |
| 커넥터에 건네기 | 커넥터는 `connector.json` 의 `owner_browser_env` 로 env 이름 하나를 선언한다. 바인딩 설치가 그 env 에 **바인딩 주인의 브라우저로 가는 Control Plane 중계 주소**를 넣는다. 주소에는 그 바인딩만의 접근 표식이 들어간다 |
| 자동 중지 | 화면도 중계 연결도 없이 정한 시간(기본 10분)이 지나면 멈춘다. 중계로 접속이 오면 다시 켠다 |
| 동시 수 | 전체에서 동시에 켜 둘 수 있는 수를 운영 값으로 받는다(기본 2). 넘으면 켜기를 거절하고 다른 브라우저를 멈추지 않는다 |
| 삭제 | 사용자가 「브라우저 지우기」 를 누르면 컨테이너와 프로필 디렉터리를 지운다. 로그인이 모두 풀린다. 사용자를 끄면 브라우저를 멈추고 프로필은 남긴다 |
| 관리자 | 모든 브라우저의 상태를 보고 멈추거나 지울 수 있다. 남의 화면은 열지 못한다 |

#### 상태

| 상태 | 뜻 | 다음 상태 |
| --- | --- | --- |
| `STOPPED` | 컨테이너가 없다. 프로필만 있다 | `STARTING` |
| `STARTING` | 컨테이너를 만들고 CDP 가 답하기를 기다린다 | `RUNNING`, `FAILED` |
| `RUNNING` | CDP 가 답한다 | `STOPPING` |
| `STOPPING` | 컨테이너를 멈추고 지운다 | `STOPPED`, `FAILED` |
| `FAILED` | 켜거나 멈추다 실패했다. 실패 코드를 남긴다 | `STARTING`, `STOPPING` |

상태 전이는 그 줄의 낙관적 잠금으로 하나씩만 일어난다. 기동할 때와 주기 점검에서 표와 실제 컨테이너를 맞춘다.
컨테이너가 사라졌는데 `RUNNING` 이면 `STOPPED` 로, 표에 없는 브라우저 컨테이너는 지운다.

#### 중계

중계는 Control Plane 안에서 돈다. Hermes 가 닿는 내부 주소에서만 받는다.

- 경로는 `/internal/browser-gateway/<접근 표식>/` 아래다. 접근 표식은 바인딩마다 다르고, 바인딩을 떼면 쓸 수 없다. 표식을 만드는 방법은 [ADR-20261008 / browser-gateway-token](../../backend/docs/adr/ADR-20261008-browser-gateway-token.md) 이 바꿨다(처음에는 무작위 값과 해시 표였다)
- `/json/version` 과 `/json/list`, `/json/new`, `/json/close`, `/json/activate` 와 `/devtools/` 의 WebSocket 만 넘긴다. 응답의 WebSocket 주소는 중계 주소로 바꿔 쓴다
- 브라우저가 멈춰 있으면 켠 뒤 넘긴다. 동시 수가 차 있으면 503 이다
- Chrome 에는 컨테이너 IP 주소로 보낸다. Chrome 의 Host 검사를 중계가 지나므로 커넥터가 IP 주소만 받던 제약이 사라진다
- CDP 메서드는 거르지 않는다. 커넥터는 이 저장소가 검토한 코드이고, 무엇을 누르는지는 커넥터가 정한다

#### 로그인 화면

- 열면 브라우저를 켜고 지금 탭의 `Page.startScreencast` 를 시작한다. 프레임은 JPEG 로 SSE 에 싣고, 받은 프레임마다 ack 한다
- 입력은 마우스, 휠, 키, 글자 넣기(`Input.insertText`), 주소 열기(http 와 https 만), 뒤로, 새로고침, 탭 고르기다. 이 밖의 CDP 명령은 웹에서 보낼 수 없다. 휴대폰의 터치는 웹이 마우스와 휠로 바꿔 보낸다
- 한글은 휴대폰과 PC 의 입력기가 조합을 끝낸 글자를 `insertText` 로 넣는다
- 한 브라우저에 화면은 하나만 연다. 새로 열면 앞의 화면이 닫힌다
- 프레임과 입력 내용은 저장하지도 로그에 남기지도 않는다. 입력 요청의 본문은 실행 기록과 접근 로그에서 뺀다

### 맥락

네이버 블로그 커넥터는 사용자가 로그인해 둔 Chrome 의 CDP 주소를 연결 칸으로 받는다.
지금은 운영자가 사용자마다 호스트에 Chrome 을 손으로 띄우고, 중계를 따로 두고, 사람이 SSH 터널과 `chrome://inspect` 로 들어가 로그인한다.
사용자가 늘면 이 일을 운영이 감당하지 못한다. 사용자는 사용자마다 브라우저를 하나 두고 Control Plane 이 관리하며, 웹의 원격 화면으로 직접 로그인하기로 정했다(이슈 #245).

조사에서 확인한 제약이다.

- 셸 실행 공간의 socket proxy 는 이미지를 하나만 받고, entrypoint 를 비우고, 포트 공개와 정지 요청을 막고, 켜진 컨테이너 수를 셸과 함께 센다. 같은 정책에 브라우저를 섞으면 셸의 제약이 함께 풀린다
- 셸 실행 공간의 망에서는 지금의 CDP 중계에 닿지 않는다. Hermes 가 브라우저에 닿으려면 망을 더 열거나 중계가 있어야 한다
- 웹은 Next.js 라우트로 Control Plane 을 부르고 SSE 를 그대로 흘린다. WebSocket upgrade 를 받는 자리가 없다
- Chrome 의 CDP 창구는 `Host` 가 IP 나 `localhost` 가 아니면 거절한다
- 커넥터 MCP 서버는 Hermes 프로세스의 자식이라 셸 실행 공간 밖에서 돈다. 바인딩 설치가 넣는 env 는 profile `.env` 를 거치지 않고 서버 정의에 들어간다([ADR-20261007 / connector-owner-attachments](ADR-20261007-connector-owner-attachments.md))
- Hermes 내장 browser 도구는 profile `config.yaml` 의 `browser.cdp_url` 로 외부 Chrome 에 붙을 수 있다. 그러나 실행 도구(`agent-browser`)가 운영 이미지에 없고, 모델이 로그인된 세션으로 아무 사이트나 다니게 된다

### 대안 기각

- **셸 실행 공간의 proxy 정책에 브라우저 이미지를 더한다**: 이미지, entrypoint, 켜진 수, 망 규칙이 셸과 섞인다. 셸 컨테이너가 브라우저 이미지로 뜨는 길도 생긴다. 같은 proxy 코드를 브라우저 정책으로 하나 더 띄운다.
- **Hermes(대시보드 plugin)가 브라우저 컨테이너를 만든다**: 브라우저의 상태와 동시 수, 사용자의 화면 권한이 Control Plane 에 있다. Hermes 에 브라우저를 만들 권한을 주면 Hermes 쪽 자식 프로세스가 뚫렸을 때 브라우저도 만든다.
- **운영 저장소에 브라우저 관리 서비스를 따로 둔다**: 상태와 권한이 두 곳으로 나뉜다. 화면 중계도 사용자 인증을 다시 해야 한다.
- **커넥터나 Hermes 를 브라우저 망에 붙여 컨테이너에 바로 닿게 한다**: 브라우저가 멈추면 주소가 죽고 다시 켤 길이 없다. Hermes 에서 모든 사용자의 브라우저가 보인다.
- **noVNC 로 화면을 연다**: 이미지에 X 서버와 VNC 서버를 더해 메모리가 늘고, WebSocket 이 필요해 웹 앞에 중계를 새로 둬야 한다. 휴대폰에서 화면이 작고 한글 입력이 VNC 키 코드로 잘 넘어가지 않는다. 브라우저의 주소 창과 대화상자가 보인다는 장점은 로그인에 꼭 필요하지 않다.
- **WebRTC 원격 화면(neko 등)**: 화질과 지연은 가장 낫지만 구성 요소가 가장 많다. 로그인 한 번에 들일 비용이 아니다.
- **CDP 를 웹까지 그대로 연다**: 웹 쪽 코드가 `Runtime.evaluate` 로 무엇이든 할 수 있다. 화면 경로는 정한 입력만 받는다.
- **사용자가 비밀번호를 화면에 넣고 시스템이 대신 로그인한다**: 비밀번호가 시스템을 거친다. 사용자는 원격 화면에서 직접 로그인하기로 정했다.
- **Hermes 내장 browser 도구를 같은 브라우저에 붙인다(이번 결정에서)**: 이미지에 실행 도구가 없고, 붙이면 모델이 로그인된 세션으로 아무 사이트에서나 사용자처럼 움직인다. 위의 중계와 접근 표식은 그 길을 막지 않으므로 나중에 따로 정한다.
- **멈출 때 컨테이너를 남긴다**: 다시 켜기가 빠르다. 그러나 이미지 교체가 반영되지 않고 표와 실제 상태가 어긋날 자리가 는다.

### 결과

- 얻는 것:
  - 운영자가 사용자마다 Chrome 과 중계를 띄우지 않는다. 사용자가 「내 브라우저」 화면에서 켜고 로그인한다.
  - 비밀번호는 사용자가 원격 화면에 직접 친다. 모델과 커넥터, 대화와 DB 를 거치지 않는다.
  - 커넥터의 브라우저는 바인딩 주인의 것으로 정해진다. 모델이나 요청 본문이 다른 사용자의 브라우저를 고르지 못한다.
  - Hermes 와 셸은 브라우저 망에 닿지 않는다. 브라우저에 닿는 길은 접근 표식이 있는 중계 하나다.
- 감당할 것:
  - **키 입력은 웹과 Control Plane 을 지나 브라우저로 간다.** 저장하거나 로그에 남기지 않는 것으로 막는다. 원격 화면이라면 어느 방식이든 같다.
  - Control Plane 이 처음으로 Docker(브라우저 proxy)를 부르고, WebSocket 을 받는다. `spring-boot-starter-websocket` 이 의존성에 더해진다.
  - 브라우저 하나가 수백 MB 를 쓴다. 동시 수와 자동 중지로 상한을 둔다. 동시 수가 차면 커넥터 작업이 `unavailable` 로 실패한다.
  - 컨테이너 안의 Chrome 은 Docker 의 기본 seccomp 와 capability 제한 안에서 Chrome 자체 sandbox 없이(`--no-sandbox`) 돈다. 경계는 컨테이너다.
  - 화면의 주소 열기는 `http`, `https` 만 받는 것으로 막는다. 사설망 주소로 가는 것은 브라우저 망 정책이 막는다.
  - 화면은 페이지 영역만 보인다. 주소 창, 탭 줄, 브라우저 대화상자는 화면이 따로 그린다. 파일 고르기와 인쇄는 지원하지 않는다.
  - 사람이 보는 화면과 커넥터 작업이 같은 브라우저를 동시에 쓰면 서로 탭을 건드릴 수 있다. 커넥터는 자기 탭만 열고 닫으며, 화면은 작업 중인 탭을 고를 수 있다.
  - 네이버가 headless Chrome 이나 컨테이너의 접속 위치를 다르게 볼 수 있다. 새 기기 확인이 뜨면 사용자가 화면에서 푼다.
  - QR 로그인은 세션 쿠키만 준다. 끌 때 컨테이너를 지우므로, 프로필에 써 둔 Chrome 의 「이전 세션 이어서 열기」 설정에 기대어 다음 기동으로 로그인을 잇는다.
  - 프로필 디렉터리의 위치, 이미지, 망, 자원 값, 동시 수는 운영 값이다. 운영 저장소가 proxy 정책과 함께 갖는다.

- **적용 범위**: backend 의 새 기능 패키지 `browser`, 커넥터 바인딩 설치, 대시보드 plugin 의 manifest 검증과 바인딩 설치, `hermes/connectors/naver-blog/`, 웹의 「내 브라우저」 화면. 계약은 [사용자 브라우저](../backend/user-browser.md) 가 갖는다.
