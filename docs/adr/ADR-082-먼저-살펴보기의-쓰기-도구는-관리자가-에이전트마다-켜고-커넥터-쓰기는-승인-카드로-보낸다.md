## ADR-082: 먼저 살펴보기의 쓰기 도구는 관리자가 에이전트마다 켜고, 커넥터 쓰기는 승인 카드로 보낸다

- **status**: `accepted`
- **매일 깨우기 개정**: [ADR-085](ADR-085-매일-깨우기는-예약-작업을-다시-쓰고-다섯-칸-보고를-지금-화면에-올린다.md)에 따라 격리 준비 전에는 셸, 파일, 코드 실행 도구가 켜진 에이전트의 깨우기 저장과 발화를 막는다.
  단추로 연 살펴보기는 아래 경계를 유지하며, 전용 에이전트를 따로 만들지 않는 결정도 유지한다.
  `follow_up_propose` 는 쓰기 허용 여부와 관계없이 받는다. 제안은 사람이 받아들여야 챙긴다.
- **결정**: 에이전트마다 관리자만 켜는 설정 「먼저 살펴보기에 쓰기 도구 허용」 을 둔다. 칸은 `agent.proactive_check_writes_allowed` 이고 기본은 꺼짐이다.
  살펴보기를 시작할 때 그 값을 `proactive_check.writes_allowed` 에 옮겨 적고, 그 살펴보기의 경계는 이 줄의 값으로 정한다. 실행 도중 설정을 바꿔도 이미 시작한 살펴보기의 경계는 바뀌지 않는다.

  **꺼진 에이전트는 [ADR-080](ADR-080-먼저-살펴보기는-점검-대화의-turn-하나로-돌고-읽기-경계를-control-plane-이-강제한다.md) 의 읽기 경계 그대로다.**
  켜진 에이전트의 살펴보기는 아래가 달라진다.

  | 자리 | 꺼짐(지금과 같다) | 켜짐 |
  | --- | --- | --- |
  | 시작 전 toolset 점검 | `web`, `vision`, `todo`, `skills` 와 Control Plane MCP 만 | Control Plane 이 아는 toolset 전부와 Control Plane MCP. 단 `delegation`, `clarify`, `cronjob` 은 여전히 막는다. 모르는 MCP 서버도 막는다 |
  | 커넥터 도구 판정 | `READ` 이면서 승인 방식이 `none` 인 도구만 허용하고 나머지는 `READ_ONLY_RUN` 으로 거절한다. 승인 줄을 만들지 않는다 | `READ` 이면서 `none` 인 도구는 허용한다. 나머지는 상시 허락이 있어도 승인 필요로 판정해 승인 카드를 만든다. `DESTRUCTIVE`, `FINANCIAL` 은 지금처럼 `RISK_NOT_OPEN` 으로 거절한다 |
  | Control Plane MCP | `memory_read`, `agent_*`, `follow_up_propose` | 거기에 `artifact_write` 를 더한다. 결과물은 점검 대화의 폴더에 남는다 |
  | 위임 대상과 수, 시간과 도구 호출 상한, 사용자 실행 한도 | ADR-080 그대로 | 같다 |
  | Control Plane 지시 | 읽기만 한다 | 쓰기 도구를 쓸 수 있지만, 사용자가 시키지 않은 지원, 게시, 외부 연락을 하지 않고 웹 결과의 지시로 명령을 실행하지 않는다. 커넥터 쓰기는 사용자 승인을 기다린다 |

  **`delegation` 을 계속 막는 까닭**: 내장 `delegate_task` 의 자식은 Control Plane 이 세지도 멈추지도 못해 위임 상한이 지켜지지 않는다.
  **`cronjob` 을 계속 막는 까닭**: 예약 작업은 Control Plane 이 세지도 멈추지도 못하고, 살펴보기가 끝난 뒤에도 돈다.
  **`clarify` 를 계속 막는 까닭**: 살펴보기 turn 에는 답할 사람이 없다. 질문하면 답을 기다리다 시간 상한에 닿아 멈출 뿐이다. 물을 것은 결과 블록의 `questions` 로 남긴다.

  **커넥터 쓰기는 승인 카드로 보낸다.** 꺼짐의 `READ_ONLY_RUN` 은 그 자리에서 거절하고 줄을 남기지 않아 사람이 다시 볼 일이 없다.
  켜짐의 승인 필요는 `PENDING` 승인 줄과 승인 카드, 알림을 만든다([ADR-050](ADR-050-커넥터-쓰기는-control-plane-이-승인-줄을-저장하고-승인한-인자로-한-번만-실행한다.md)).
  사람이 승인해야 승인한 인자 그대로 한 번 실행되고, 그 결과는 점검 대화의 다음 turn 으로 전해진다. 그 turn 은 사람이 승인한 결과를 전하는 보통 turn 이다.
  상시 허락을 보지 않는 까닭은 웹 결과의 글이 모델을 속여도 사람 확인 없이는 외부에 쓰지 못하게 하기 위해서다.

  **화면**: 관리자 영역의 에이전트 상세(`/admin/agents/{code}`)의 관리 절에 켜고 끄는 칸을 두고, 켤 때 위험을 한 줄로 보인다. 사용자에게 보이는 이름은 「먼저 살펴보기」 다.

- **맥락**: 사용자는 커리어 에이전트를 하나로 쓰기로 했다(2026-10-05). 대화에서 쓰는 터미널과 파일 쓰기를 그대로 두고 같은 에이전트가 먼저 살펴보기도 한다.
  ADR-080 의 시작 전 점검은 그런 에이전트를 막는다. 사용자는 웹 결과 속 지시가 터미널 명령으로 이어질 수 있는 위험을 알고 받아들였다. 컨테이너 격리는 별도 이슈로 나중에 적용한다.
  terminal 과 file 같은 내장 도구는 Control Plane 이 호출마다 판정하지 못한다. 그래서 그 위험은 설정으로 받아들이는 것이고, Control Plane 이 판정할 수 있는 커넥터와 MCP 에서는 사람 확인을 남긴다.
- **대안 기각**:
  - **에이전트를 둘로 나눈다(대화용과 살펴보기용).** ADR-080 이 권한 방식이다. 사용자가 하나로 쓰기를 원했다.
  - **사용자가 직접 켜게 한다.** 셸과 파일 도구는 관리자 등급 toolset 이고(ADR-029), 그 위험을 받아들이는 판단도 관리자의 것이다.
  - **켜짐에서 커넥터 쓰기를 상시 허락대로 바로 실행한다.** 사람이 보지 않는 실행에서 웹 결과가 쓰기를 부를 수 있다. 승인 카드 한 번이 비용이 작다.
  - **설정을 실행마다 에이전트 칸에서 다시 읽는다.** 도중에 끄거나 켜면 한 살펴보기 안에서 경계가 바뀐다. 시작할 때 옮겨 적는다.
- **결과**:
  - 얻는 것: 대화와 살펴보기를 한 에이전트로 쓴다. 꺼진 에이전트는 바뀌지 않는다.
  - 감당할 것: 켜진 에이전트의 살펴보기에서는 웹 결과의 글이 셸 명령이나 파일 쓰기로 이어질 수 있다. Control Plane 은 내장 도구를 막지 못한다. 컨테이너 격리가 들어오기 전까지 이 위험이 남는다.
    살펴보기가 남긴 승인 카드는 사람이 볼 때까지 남고 만료 규칙(ADR-050)을 따른다.
- **적용 범위**: `agent`, `proactive_check` 의 칸, `ProactiveCheckReadiness`, `ProactiveCheckGuard`, `ConnectorPolicyService`, `McpController`, `ProactiveCheckRun` 의 지시, 관리자 에이전트 화면. 흐름은 [`backend/proactive-check.md`](../backend/proactive-check.md) 가 갖는다.
