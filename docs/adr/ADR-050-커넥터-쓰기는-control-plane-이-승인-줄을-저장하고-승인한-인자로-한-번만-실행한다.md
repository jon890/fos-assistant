## ADR-050: 커넥터 쓰기는 Control Plane 이 승인 줄을 저장하고 승인한 인자로 한 번만 실행한다

- **status**: `accepted`
- Date: 2026-10-01
- [ADR-049](ADR-049-커넥터-도구-호출은-profile-plugin-의-hook-이-control-plane-에-물어-판정한다.md) 의 판정이 「승인 필요」 일 때의 처리를 정한다. 결과를 대화에 전하는 방법은 [ADR-040](ADR-040-위임-결과는-control-plane-이-부모-대화의-다음-turn-을-열어-전한다.md) 의 깨우기를 넓혀 쓴다.

### 결정

**승인이 필요한 호출은 hook 이 그 자리에서 막고, Control Plane 이 인자와 함께 승인 줄로 저장한다. 사용자가 승인하면 Control Plane 이 저장한 인자 그대로 한 번만 실행한다.**

| 항목 | 정한 것 |
| --- | --- |
| 승인 요청 | hook 의 판정 요청이 인자를 싣고 오고, Control Plane 이 `connector_action` 한 줄에 `PENDING` 으로 저장한다. hook 은 승인 요청 번호가 든 글로 그 호출을 막는다. run 은 기다리지 않고 남은 일을 한 뒤 끝난다 |
| 승인하는 사람 | 그 연결의 주인뿐이다. 관리자도 남의 동작을 승인하지 못한다 |
| 실행 | Control Plane 이 대시보드 plugin 의 실행 경로로 저장한 인자를 보낸다. 대시보드가 커넥터 MCP 서버를 자식으로 한 번 띄워 도구 하나를 부른다. credential 은 Hermes 쪽을 떠나지 않는다 |
| 한 번만 | `PENDING` 에서 `EXECUTING` 으로 가는 전이를 행 잠금 아래에서 한다. 실행을 시작했으나 결과를 모르면 `UNKNOWN` 으로 두고 다시 실행하지 않는다 |
| 인자 | hook 이 직렬화한 글자 그대로 저장하고 그 SHA-256 을 함께 둔다. 실행은 저장한 글로만 한다 |
| 결과 | 요청이 나온 대화에 알림 줄을 남기고 자동 turn 을 열어 모델에게 전한다 |
| 거절 | 알림 줄만 남긴다. 자동 turn 을 열지 않는다 |
| 만료 | 24시간이다. 지나면 `EXPIRED` 로 바꾸고 알림 줄을 남긴다 |
| turn 중지 | 승인 요청은 남는다. 중지는 run 을 멈춘 것이다 |
| 상시 허락 | `approval: required` 인 도구에만 만든다. 기간은 1시간, 오늘, 30일이다. 무기한은 없다 |
| 승인 카드 | Control Plane 의 데이터로만 그린다. 모델의 답에 든 글로 만들지 않는다 |

### 맥락

Hermes 에는 도는 실행에 사람의 답을 끼워 넣어 그 도구 호출을 이어 가는 길이 FOS 의 요구에 맞는 모양으로 없다.
내장 승인은 실행을 `waiting_for_approval` 로 멈추고 기본 300초 뒤 거절한다. 사람이 늦으면 일이 사라진다.
도구 호출 자체에도 제한 시간이 있어, 기다리는 도구는 실제로 끊긴 적이 있다([ADR-017](ADR-017-무엇을-할지는-hermes-가-정하고-control-plane-은-경계만-갖는다.md)).

연결용 에이전트는 대개 위임을 받아 돈다. 그 실행에는 다시 열 대화가 따로 없다.
대시보드 plugin 은 이미 커넥터 MCP 서버를 자식으로 띄워 도구 하나를 부르는 코드를 갖고 있다.

### 대안 기각

- **승인한 뒤 모델이 같은 도구를 다시 부르게 한다**: 모델이 인자를 바꿔 부를 수 있어 「승인한 인자 그대로」 를 지키기 어렵다. 위임 자식 실행에는 다시 열 대화가 없다.
- **hook 이 승인이 올 때까지 기다린다**: callback 은 기본 30초, 도구는 기본 300초에서 끊긴다. 기다리는 동안 run 의 스레드가 묶이고, 제한을 넘긴 callback 은 그 profile 의 hook 을 한동안 억제한다.
- **결과를 모르는 실행을 다시 돌린다**: 쓰기가 두 번 들어갈 수 있다. 사람이 그 서비스 화면에서 확인하는 쪽이 낫다.
- **거절했을 때도 자동 turn 을 연다**: 사용자가 하지 말라고 한 일에 LLM 호출을 한 번 더 쓴다. 다음 질문 때 모델이 이력의 알림 줄로 본다.
- **상시 허락에 무기한을 둔다**: 한 번 누른 허락이 잊힌 채 남는다. 가장 긴 기간을 30일로 두고 다시 묻는다.
- **승인 카드를 모델의 `<ask>` 글로 그린다**: 남이 만든 글을 에이전트가 옮기면 남이 만든 승인 카드가 그려진다([ADR-026](ADR-026-에이전트가-물을-것은-답-끝의-태그로-두고-화면이-카드로-그린다.md)).

### 결과

- 얻는 것: 승인한 것과 실행한 것이 같고 한 번만 실행된다. 사용자가 몇 시간 뒤에 승인해도 일이 이어진다. 승인, 거절, 만료와 실행 결과가 한 표에 남는다.
- 감당할 것:
  - 승인 뒤의 실행은 Hermes 가 쥔 MCP 연결이 아니라 대시보드가 새로 띄운 프로세스에서 돈다. 커넥터 서버가 프로세스 안의 상태에 기대면 결과가 다를 수 있다. 그래서 커넥터의 도구 하나는 상태 없이 돌아야 한다.
  - 대시보드는 Control Plane 을 믿고 실행한다. 서비스 토큰이 새면 이 경로로 쓰기를 할 수 있다. [ADR-029](ADR-029-에이전트-도구는-control-plane-이-등급으로-판정하고-hermes-설정-api-로-쓴다.md) 가 이미 진 것과 같은 종류의 위험이다.
  - `UNKNOWN` 은 사람이 확인해야 한다.
  - 승인 요청이 많으면 사람이 읽지 않고 누른다. 상시 허락과 위험도 기본값으로 수를 줄인다.
  - 인자 원문이 승인 줄에 저장된다. 주인만 보고, 관리자 목록과 로그에는 싣지 않는다.
  - 서버 한 대를 전제한다. 만료 정리와 기동 정리가 그 전제에 기댄다.
