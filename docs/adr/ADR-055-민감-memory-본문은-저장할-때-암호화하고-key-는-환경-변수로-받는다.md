## ADR-055: 민감 Memory 본문은 저장할 때 암호화하고 key 는 환경 변수로 받는다

- **status**: `accepted`.
- **결정**: `sensitivity` 가 `SENSITIVE` 인 줄의 본문을 AES-256-GCM 으로 암호화해 `content` 칸에 넣는다.
  `memory` 와 `memory_revision` 두 표가 모두 해당한다. 어느 key 로 암호화했는지는 새 칸 `content_key_id` 가 적는다. 이 칸이 비어 있으면 평문이다.
  key 는 환경 변수로 받는다. key 마다 id 가 있고, 새로 쓰는 본문은 `active-key-id` 가 가리키는 key 로 암호화한다.
  **key 가 없으면 기동은 되고, 민감 항목의 저장과 읽기만 거절한다.** 평문으로 내려 저장하는 길은 없다.
  `NORMAL` 항목과 제목은 암호화하지 않는다.
- **맥락**: [ADR-052](ADR-052-memory-는-collection-종류-꺼내는-방식-민감도-판-출처를-가진다.md) 는 민감 본문이 평문이라 「암호화를 넣기 전에는 민감 항목을 들여오지 않는다」 고 정했다.
  이제 신원 문서(연락처, 주소, 병역, 학력, 재직 기간이 든 지원서 공통 프로필)를 `identity` collection 에 민감 문서로 두려 한다.
  본문은 지운 뒤에도 `memory_revision` 에 남으므로, 판에 남는 본문도 같은 방식으로 지켜야 한다.
  지금까지 `SENSITIVE` 를 만드는 화면과 API 가 없어 운영 데이터에 민감 줄은 없다.
- **대체된 부분**: [ADR-052](ADR-052-memory-는-collection-종류-꺼내는-방식-민감도-판-출처를-가진다.md) 의 「결과」 가운데 「민감 항목의 본문은 아직 평문으로 저장한다. 그래서 암호화를 넣기 전에는 민감 항목을 들여오지 않는다」 를 이 결정이 대체한다. ADR-052 의 나머지는 그대로다.
- **대안 기각**:
  - 모든 Memory 본문을 암호화한다: JPA 변환기 하나로 끝나 코드가 가장 적다. 그러나 이미 있는 줄을 모두 옮겨야 하고, 항상 층과 색인 뒤에 붙일 검색이 본문을 읽지 못한다. 지킬 것은 민감 본문이다.
  - key 를 홈서버 파일로 둔다: 디렉터리 설정과 마운트가 하나 는다. 이미 환경 변수로 받는 비밀이 있어 같은 길을 쓴다.
  - `ASSISTANT_JWT_SECRET` 에서 key 를 유도한다: 새 비밀이 없다. 그러나 그 secret 을 바꾸면 저장한 본문을 읽지 못한다. 수명이 다른 두 비밀을 묶지 않는다.
  - key 가 없으면 기동하지 않는다: 반쪽 상태가 없다. 그러나 이 저장소는 공개 저장소이고 민감 항목을 쓰지 않는 설치도 떠야 한다. 운영 설정보다 backend 를 먼저 배포해도 멈추지 않아야 한다.
  - key 가 없으면 평문으로 저장하고 나중에 암호화한다: 평문이 데이터베이스와 백업에 한 번 남으면 되돌릴 수 없다.
  - 데이터베이스의 암호화 기능을 쓴다: 운영은 MySQL 이고 검사는 H2 다. 같은 SQL 로 돌지 않는다.
  - 암호문을 다른 칸이나 다른 표에 둔다: 본문을 읽는 질의와 판을 남기는 코드가 칸 둘을 함께 다뤄야 한다. 한 칸에 두고 `content_key_id` 로 구분한다.
- **결과**:
  - 얻는 것: 데이터베이스 dump 와 백업이 새어 나가도 민감 본문은 key 없이 읽지 못한다. 지운 항목의 판도 같다.
    key 를 바꿀 때 옛 key 를 목록에 남겨 두면 옛 줄을 그대로 읽는다.
    암호문은 주인에 묶인다. 데이터베이스에서 암호문을 다른 사용자의 줄로 옮기면 열리지 않는다.
  - 감당할 것: **key 가 데이터베이스와 같은 호스트에 있다.** 호스트가 뚫리면 이 암호화는 본문을 지키지 못한다.
    **key 를 잃으면 민감 본문을 되찾을 수 없다.** key 의 백업은 운영 저장소 `fos-home-infra` 가 맡는다.
    제목은 평문이다. 색인과 목록이 제목을 읽기 때문이다. 민감한 값을 제목에 적지 않는다.
    민감 본문을 데이터베이스 질의로 찾을 수 없다. 검색을 붙일 때 민감 항목은 제목으로만 찾는다.
    옛 key 로 쓴 줄을 새 key 로 다시 쓰는 일은 아직 없다. key 목록에서 옛 key 를 빼면 그 줄을 읽지 못한다.
    **민감 항목을 넣은 뒤에는 이 결정 앞의 판으로 되돌리지 않는다.** 옛 코드는 `content_key_id` 를 모른다. 옛 코드가 암호화한 줄을 고치면 `content` 는 평문이 되고 옛 key id 가 남아, 다시 올린 뒤 그 줄을 읽지 못하고 기동할 때의 보정도 그 줄을 찾지 못한다.
    본문을 내는 자리는 모두 `MemoryService` 를 거쳐야 한다. 엔티티의 `content()` 를 그대로 내면 민감 줄은 암호문이 나간다. 틀려도 평문이 새지 않는 쪽으로 틀린다.
- **적용 범위**:

  | 무엇 | 값 |
  | --- | --- |
  | 알고리즘 | `AES/GCM/NoPadding`, key 256비트, IV 12바이트를 줄마다 새로 뽑는다, 인증 태그 128비트 |
  | `content` 에 적는 모양 | `v1.<IV>.<암호문과 태그>`. 두 조각은 채움 문자 없는 base64url 이다 |
  | 덧붙이는 인증 값(AAD) | `USER:<owner_user_id>` 또는 `GROUP:<group_id>` 의 UTF-8 |
  | `content_key_id` | `VARCHAR(32) NULL`. 소문자, 숫자, 하이픈. 비어 있으면 평문 |
  | 설정 `assistant.memory.encryption.active-key-id` | 새로 쓸 때 쓰는 key 의 id. 환경 변수 `ASSISTANT_MEMORY_ENCRYPTION_ACTIVE_KEY_ID` |
  | 설정 `assistant.memory.encryption.keys` | `<id>:<base64 32바이트>` 를 쉼표로 이은 목록. 환경 변수 `ASSISTANT_MEMORY_ENCRYPTION_KEYS` |

  | 상태 | 동작 |
  | --- | --- |
  | 두 설정이 모두 비어 있다 | 기동한다. 민감 항목의 저장과 수정은 `MEMORY_ENCRYPTION_UNAVAILABLE`(409)로 거절한다 |
  | 값의 모양이 틀렸다(base64 가 아니다, 32바이트가 아니다, `active-key-id` 가 목록에 없다, 한쪽만 있다) | 기동에서 멈춘다 |
  | 암호화한 줄의 key 가 목록에 없다 | 그 본문을 읽는 요청을 `MEMORY_ENCRYPTION_UNAVAILABLE` 로 거절한다. 목록 조회는 실패하지 않는다. 목록은 민감 본문을 싣지 않는다 |
  | 민감도를 `NORMAL` 에서 `SENSITIVE` 로 고친다 | 새 판의 본문을 암호화한다. 물러난 판은 그때의 모양대로 남는다 |
  | 민감도를 `SENSITIVE` 에서 `NORMAL` 로 고친다 | 새 판의 본문을 평문으로 적는다. 물러난 판은 암호문으로 남는다 |
  | 평문으로 남은 민감 줄이 있다 | 기동할 때 두 표에서 찾아 암호화한다. key 가 없으면 줄 수만 경고 로그로 남긴다 |

- **다음**: 민감 본문의 완전 삭제는 이 결정에 넣지 않는다. 문서를 읽게 하는 데 필요하지 않고, 판에 남는 본문이 이제 암호문이라 급한 위험이 줄었다. 완전 삭제는 판 이력 화면과 함께 정한다.
  옛 key 로 쓴 줄을 새 key 로 다시 쓰는 명령은 key 를 처음 바꿀 때 만든다.
