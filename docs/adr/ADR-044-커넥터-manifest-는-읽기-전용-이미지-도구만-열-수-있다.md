## ADR-044: 커넥터 manifest 는 읽기 전용 이미지 도구만 열 수 있다

- **status**: `accepted`
- **결정**: `connector.json` 에 선택 칸 `toolsets` 와 `attachments` 를 둔다.
  `toolsets` 는 연결용 에이전트에 켤 내장 toolset 이름 목록이고, 받는 이름은 `vision` 하나다.
  `attachments` 가 참이면 그 연결용 에이전트의 대화가 사진을 받는다. 참이려면 `toolsets` 에 `vision` 이 있어야 한다.
  [ADR-039](ADR-039-외부-서비스-연결은-사용자별-전용-에이전트로-실행한다.md) 의 「셸, 파일, 스킬 수정 도구를 닫는다」 는 그대로다.
  허용 목록은 대시보드 plugin 과 Control Plane 이 각자 갖고 둘 다 검사한다. 목록 밖의 이름을 선언한 커넥터는 카탈로그에 나오지 않는다.
  연결용 에이전트의 API 도구 목록은 그 커넥터의 MCP 서버와 선언한 toolset 이다. Control Plane MCP 는 두지 않는다([ADR-045](ADR-045-커넥터-에이전트는-자기-mcp-서버만-받고-memory-와-control-plane-도구를-받지-않는다.md)).
  켜진 내장 도구가 선언과 정확히 같아야 `READY` 다.
- **대체된 부분**: `toolsets` 와 `attachments` 는 새 연결에 대해 [ADR-083](ADR-083-커넥터는-사용자가-한-번-연결하고-자기-에이전트에-여럿-붙여-그-에이전트가-도구를-직접-부른다.md) 이 대체한다. 붙인 에이전트의 도구와 사진 받기는 그 에이전트의 설정이 정한다. 붙인 에이전트에서는 이 선언을 쓰지 않는다. 사진을 읽는 커넥터를 붙였으면 주인이 그 에이전트의 `vision` 도구를 켠다. 옛 커넥터 에이전트가 지워질 때까지 그 에이전트에는 이 결정이 그대로 걸린다.
- **맥락**: 가계부 plugin 에 소비 화면 스크린샷을 읽어 등록하는 도구가 들어갔다.
  에이전트가 사진을 `vision_analyze` 로 읽은 뒤 그 서비스의 MCP 도구를 부르는 흐름이다.
  연결용 에이전트는 사진을 받지 않았고 내장 도구가 하나라도 켜져 있으면 `READY` 가 되지 못해 이 흐름을 실행할 수 없었다.
  사진은 대화 본문이 아니라 파일로 전해지므로([ADR-020](ADR-020-사진은-공유-디렉터리에-두고-에이전트가-파일로-읽는다.md)) 이미지 도구가 있어야 읽는다.
  Control Plane 은 서비스 이름을 모르므로([ADR-043](ADR-043-커넥터는-plugin-의-connector-json-으로-선언하고-control-plane-은-범용-흐름만-갖는다.md)) 가계부라는 이름으로 나눌 수 없다.
- **대안 기각**:
  - 연결용 에이전트 모두에 `vision` 을 켠다: 사진을 쓰지 않는 커넥터에도 도구와 사진 단추가 생긴다. 무엇이 필요한지는 그 plugin 이 안다.
  - `toolsets` 에 아무 내장 toolset 이름이나 받는다: manifest 한 줄로 셸과 파일 도구가 열려, 토큰이 든 profile 의 `.env` 를 모델이 읽을 수 있게 된다. ADR-039 가 막으려던 것이다.
  - `file` 도 함께 연다: 사진 경로를 읽는 데 필요할 수 있지만 같은 도구가 그 profile 의 `.env` 도 읽는다. `vision` 만으로 되는지 배포 뒤 확인하고, 안 되면 따로 결정한다.
  - 사진 받기를 `toolsets` 에서 미루어 정한다: 이미지 도구를 쓰지만 사용자의 사진은 받지 않는 커넥터를 표현하지 못한다. 그래서 `attachments` 를 따로 둔다.
  - 사진 받기를 요청마다 카탈로그에서 읽는다: `Agent.acceptsAttachments()` 가 대시보드를 부르게 되어 엔티티가 Hermes 에 기대고, 대시보드가 느릴 때 에이전트 목록이 느려진다. 그래서 `agent.connector_attachments` 열에 옮겨 둔다.
- **결과**:
  - 얻는 것: 사진을 쓰는 커넥터를 Control Plane 을 고치지 않고 붙인다. 사진 단추, 메시지 전송의 첨부 판정이 한 값을 본다.
  - 감당할 것: 허용 목록이 두 곳(대시보드 plugin, Control Plane)에 있어 이름을 더할 때 둘을 함께 고친다.
    manifest 가 바뀌어도 열의 값은 연결 확인과 관리자 반영 완료 때에만 따라가고, 선언한 toolset 이 실제로 켜진 것을 확인했을 때만 참이 된다.
    `vision_analyze` 는 이미지를 모델 provider 에 보낸다. 사진을 받는 커넥터를 운영 목록에 넣는 것은 그것을 받아들인다는 뜻이다.
    `file` 없이 `vision` 만으로 실행 입력의 사진 경로를 읽는지는 배포 뒤 실제 실행으로 확인해야 한다. 아직 확인하지 못했다.
