## ADR-20261008: 짧은 개인 기억은 본문까지 「개인 사실 구역」에 싣고, 답마다 참고한 기억을 사용자에게 보인다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-20261007 / memory-remember](ADR-20261007-memory-remember.md) 의 「꺼내는 방식은 `SEARCH` 로 둔다. 다음 실행의 색인에 제목이 실리고 본문은 `memory_read` 로 읽는다」 를 개정한다.
  `memory_remember` 가 남기는 항목의 `retrieval` 은 그대로 `SEARCH` 다. 그 가운데 짧은 항목은 본문까지 실린다.
  [ADR-015](ADR-015-memory-는-층을-나눠-싣는다.md) 의 「`SEARCH` 는 제목만 싣는다」 에 예외를 둔다. 층을 나눠 싣고 나머지는 도구로 읽는다는 결정은 그대로다.
  [ADR-071](ADR-071-여러-출처의-문맥은-항목마다-출처와-권한과-신선도를-지닌-묶음으로-조립한다.md) 의 `source` 목록에 `MEMORY_FACTS` 와 `MEMORY_READ` 를 더한다.

### 결정

**`ContextAssembler` 가 항상 층과 색인 층 사이에 「개인 사실 구역」을 하나 더 조립한다.**
요청자의 짧은 개인 사실을 본문까지 매 실행에 싣는다. 모델이 `memory_read` 를 부르지 않아도 이름, 관계, 선호를 안다.
#310 이 「사용자 프로필 구역」 이라 부른 것이다. 이 저장소에서 profile 은 Hermes 의 격리 단위를 뜻하므로 「개인 사실 구역」 이라 부르고 코드는 `MEMORY_FACTS` 로 쓴다.

| 무엇 | 정한 값 |
| --- | --- |
| 대상 | 지금 색인 층에 오를 항목(범위, collection, 민감 허용을 지난 `ACCEPTED`, `SEARCH`) 가운데 범위가 `USER`, 종류가 `MEMORY`, 민감도가 `NORMAL`, 본문이 200자 이하인 것 |
| 구역 예산 | 2,000자. 전체 Memory 상한(8,000자) 안에서 쓴다 |
| 담는 순서 | 색인 몫을 지금처럼 먼저 떼어 두고, 항상 층, 개인 사실 구역, 색인 층 순으로 담는다. 개인 사실 구역은 항상 층과 같은 자리를 나눠 쓰므로 색인을 밀어내지 못한다 |
| 넘칠 때 고르는 순서 | `updated_at` 이 최근인 것부터, 같으면 번호가 큰 것부터. 글로 옮길 때는 번호 순으로 늘어놓는다 |
| 한 줄의 모양 | `- [번호] 제목: 본문`. 번호를 남겨 바뀐 사실을 `memory_id` 로 고치게 한다 |
| 색인과의 관계 | 개인 사실 구역에 실린 항목은 색인에서 뺀다. 고르지 못한 후보는 색인에 제목으로 남는다 |
| `memory_read` | 실린 항목도 `retrieval` 이 `SEARCH` 라 지금처럼 읽힌다 |

**에이전트가 남긴 사실도 곧바로 대상이다.** 바로 저장한 항목은 다음 실행부터 개인 사실 구역에 실린다(2026-10-08 사용자 결정).

**`GROUP` 항목은 대상이 아니다.** 「지금 묻는 사람」 의 구역이고, 그룹 항목을 매번 싣고 싶으면 관리자가 `ALWAYS` 로 켜는 길이 이미 있다.

**답마다 그 실행이 본문을 받은 기억을 사용자에게 보인다.** 답 아래 접힌 줄 「참고한 기억 N개」 다.
재료는 그 실행의 `execution_context_source` 가운데 본문을 실은 항목(항상 층, 개인 사실 구역)과, 그 실행이 `memory_read` 로 읽을 수 있었던 항목이다.
제목만 실린 색인 항목은 넣지 않는다. 제목과 권한은 읽을 때 지금 값으로 다시 판정한다.
문구를 「쓴」 이 아니라 「참고한」 으로 둔다. 실렸어도 답에 쓰지 않은 항목이 섞이기 때문이다.

### 맥락

2026-10-08 사용자는 「자동으로 나를 기억하고 다음 대화에서 알고 있어 대화를 이어 가기 편해야 한다」 고 요구했다(#310).
ADR-20261007 / memory-remember 로 대화에서 바로 저장하는 길은 열렸지만, 남긴 항목은 `SEARCH` 라 다음 대화에 **제목만** 실렸다.
「딸 이름」 이라는 제목만 보고는 이름을 모른다. 모델이 `memory_read` 를 부르면 알지만, 부르지 않는 경우가 있고 부르면 API 콜이 늘어 입력 비용과 지연이 커진다([`backend/mcp-caller.md`](../backend/mcp-caller.md) 의 「입력 비용은 API 콜 수가 정한다」).
본문을 매번 싣게 하려면 사용자가 `/memory` 에서 항상 싣기를 켜야 했다. 사용자가 원한 「화면에 가지 않고 대화에서 끝나는 흐름」 과 어긋난다.

ADR-20261007 이 `SEARCH` 로 고정한 까닭은 에이전트가 많이 남겨도 실행마다 실리는 양이 늘지 않게 하는 것이었다.
개인 사실 구역은 예산이 고정이라 그 의도를 지킨다. 항목이 아무리 늘어도 실리는 양은 2,000자를 넘지 않는다.

상용 서비스(ChatGPT 의 저장된 기억, Claude 메모리)도 짧은 사실 목록을 매 대화에 싣는다.
그쪽은 무엇이 실렸는지 답마다 보여 주지 않는다. 우리는 실은 항목의 참조를 이미 실행마다 남기므로(ADR-071) 그것을 사용자에게 보인다.

### 대안 기각

- **`memory_remember` 가 짧은 항목을 `ALWAYS` 로 저장한다.** 사람이 정하던 「항상 싣기」 를 모델이 정하게 된다. 항상 층은 예산을 따로 두지 않아 항목이 늘면 색인 자리까지 밀어낸다.
- **LLM 이 기억을 한 장으로 요약한 프로필을 싣는다.** 요약할 때마다 사실이 조금씩 바뀌고 무엇이 언제 바뀌었는지 판 기록에 남지 않는다. collection 마다 받는 에이전트가 달라 요약 한 장을 여러 에이전트가 함께 쓰지 못한다. 실행마다 LLM 호출도 한 번 는다.
- **개인 사실 구역에 `GROUP` 항목도 싣는다.** 그룹 사실은 관리자가 쓰고 `ALWAYS` 로 켜는 길이 있다. 함께 담으면 사용자 사실이 그룹 사실에 밀려 빠질 수 있다.
- **넘칠 때 최근에 쓰인 순으로 고른다.** `last_used_at` 칸이나 실행 기록 집계가 필요하다. 지금은 최근에 남기거나 고친 순으로 시작하고 측정을 보고 정한다.
- **개인 사실 구역에 실은 항목을 색인에도 남긴다.** 같은 항목이 두 번 실려 글자만 는다. 번호는 개인 사실 줄에 이미 있다.
- **「참고한 기억」 에 색인 제목까지 넣는다.** 제목만 실린 항목은 수십 개라 목록이 길어지고, 본문을 받지 않은 항목을 「참고했다」 고 보이게 된다.

### 결과

얻는 것

- 사용자가 말한 짧은 사실이 다음 대화부터 도구 호출 없이 쓰인다. `memory_read` 왕복이 줄어 지연과 입력 비용이 준다.
- 색인 층이 짧아져 항목이 많아도 색인에서 빠지는 일이 준다.
- 사용자가 답마다 어떤 기억이 실렸는지 보고 `/memory` 에서 고친다.

감당할 것

- **틀린 사실 하나가 매 답에 실린다.** 바로 저장한 직후의 「기억했어요」 와 되돌리기, 답마다의 「참고한 기억」 으로 사용자가 빨리 보게 한다.
- **같은 사실의 옛 값과 새 값이 함께 실릴 수 있다.** 모델이 기존 번호를 몰라 새로 남기면 둘 다 `ACCEPTED` 다. 값 대체는 #310 의 2단계가 다룬다. 그때까지 개인 사실 줄의 번호로 모델이 고칠 수 있게 한다.
- turn 당 입력이 최대 2,000자(한국어로 대략 1,000~1,500 토큰) 는다. 개인 사실 구역이 바뀌면 지시문 지문이 바뀌어 prompt cache 적중이 떨어진다.
- 「참고한 기억」 은 실렸지만 답에 쓰지 않은 항목도 보인다. 문구로 그 차이를 밝힌다.
- `memory_read` 로 읽은 항목은 Control Plane 이 읽기에 성공할 때 `execution_context_source` 에 `MEMORY_READ` 줄로 덧붙여 남긴다. Hermes 의 도구 시작 사건은 이 도구의 인자를 싣지 않아 사건에서는 번호를 알 수 없다. 이 기록이 실패하면 그 읽기는 「참고한 기억」 에서 빠진다.
  [ADR-015](ADR-015-memory-는-층을-나눠-싣는다.md) 의 「어느 항목이 읽혔는지는 서버 로그에만 남기고 실행 기록 칸에는 남기지 않는다」 를 이 기록으로 넓힌다.
- 예산과 길이 상한은 합성 측정과 운영 집계를 보고 고친다([`backend/memory-eval.md`](../backend/memory-eval.md)).

### 적용 범위

조립 규칙과 「참고한 기억」 API 는 [`backend/memory.md`](../backend/memory.md) 의 「범위와 조립」 과 「답마다 참고한 기억」 이, 화면은 [`frontend/chat.md`](../frontend/chat.md) 의 「참고한 기억」 이 갖는다.
