## ADR-20261008 / default-toolsets: 기본 에이전트는 web 과 셸, 파일, 코드 실행을 켜고 시작하되 셸 계열은 실행 공간이 있을 때만 켠다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 의 도구 저장에 「local 로 돌리지 않는」 쓰기를 더한다. [ADR-029](../../backend/docs/adr/ADR-029-에이전트-도구는-control-plane-이-등급으로-판정하고-hermes-설정-api-로-쓴다.md) 의 등급 표는 바꾸지 않는다.

### 결정

**첫 로그인에 만든 기본 에이전트에 운영 설정 `assistant.people.default-toolsets` 의 도구를 켠다. 기본값은 `web`, `terminal`, `file`, `code_execution` 이다.**
셸·파일·사진 도구는 그 profile 이 실행 공간 정책에 등록됐을 때만 켠다. 등록되지 않았으면 그 도구를 빼고 나머지를 켜며 경고 로그를 남긴다.

| 항목 | 정한 것 |
| --- | --- |
| 켜는 때 | 첫 로그인의 트랜잭션이 커밋된 뒤 백그라운드 작업으로. 실행 공간 주인 키 `u<사용자 번호>` 가 이때 처음 생긴다. 첫 요청은 Hermes 호출을 기다리지 않는다 |
| 켜는 길 | 사람의 도구 저장과 같은 대시보드 `PUT /api/config`. 지금 켜진 도구에 기본 도구와 Control Plane MCP, 붙은 커넥터 서버 이름을 더해 보낸다 |
| 셸 계열이 있을 때 | 본문에 `require_sandbox: true` 를 싣는다. plugin 은 정책에 없는 profile 을 local 로 돌리지 않고 409 `sandbox_unavailable` 로 거절한다 |
| 409 를 받으면 | 셸·파일·사진 도구를 빼고 `require_sandbox` 없이 다시 쓴다. 지금 켜진 도구는 그대로 둔다. 지금 켜진 것에 셸 계열이 있으면 그 쓰기가 local 을 확정하므로 쓰지 않는다 |
| 빼는 경우 | 그룹 공개 에이전트의 셸·파일·사진 계열, 비밀 요청 칸이 있는 올린 스킬이 있을 때의 셸·파일·사진 도구, 옛 커넥터 에이전트 전체 |
| 등급 | 관리자 등급 도구도 운영 설정을 허락으로 보고 켠다. 켠 뒤에는 관리자 등급 그대로라 주인은 끄지 못한다 |
| 실패 | 로그만 남긴다. 로그인은 되돌리지 않는다. 관리자가 에이전트 도구 화면에서 다시 켠다 |
| 설정 검사 | 주인 등급이거나 실행 공간에서만 도는 도구만 받는다. 그 밖의 이름이 있으면 기동하지 않는다. `browser`, `session_search` 처럼 실행 공간 밖에서 도는 관리자 등급은 기본값이 될 수 없다 |

profile 을 만드는 틀(`hermes/profile-template/config.yaml.template`)과 만들 때의 금지 검사는 그대로다.
사용자가 화면에서 만드는 에이전트와 역할 profile 은 이 설정을 쓰지 않는다.

### 맥락

사용자는 모델에 자유도를 최대한 주어 스스로 추론하게 하기로 했다(2026-10-08).
격리된 실행 공간이 있으니 웹 검색, 코드 실행, 파일, 셸을 기본으로 켠다는 것이다.
막는 기본값보다 격리 안에서 여는 기본값을 앞에 둔다.

지금 기본 profile 의 API 도구는 `delegation` 과 `fos-assistant` 뿐이다(운영 실측).
`terminal`, `file`, `code_execution` 은 관리자 등급이라 에이전트 주인이 스스로 켜지 못한다.

사람의 도구 저장은 정책에 없는 profile 의 셸 도구를 local 로 둔다(ADR-086).
local 셸은 Hermes 프로세스의 사용자로 돌아 다른 profile 의 `.env` 와 커넥터 값 파일을 읽는다([커넥터 READ 데이터의 흐름](../read-data-flow.md) 의 RC-02).
관리자가 고른 일이면 감수할 수 있다. 하지만 사람이 고르지 않은 기본값이 그 길을 열면 안 된다.

### 대안 기각

- **profile 틀에 넣는다.** 틀을 쓰는 시점에는 사용자 번호가 없어 실행 공간 주인 키를 정하지 못한다. 틀은 실행 공간 정책을 보지 않으므로 셸이 local 로 열린다. 만들 때의 금지 검사도 그 도구를 거절한다.
- **관리자가 사람을 더할 때 켠다.** 위와 같다. `app_user` 가 첫 로그인에 생기므로 `u<사용자 번호>` 가 아직 없다. 에이전트도 아직 없어 `a<에이전트 번호>` 도 없다.
- **사람의 저장처럼 미등록 profile 은 local 로 켠다.** RC-02 를 모든 사용자의 기본 에이전트로 넓힌다.
- **셸 계열을 주인 등급으로 내린다.** 사용자가 만드는 모든 에이전트에서 주인이 셸을 켤 수 있게 된다. 이번 결정은 기본값만 바꾼다.
- **공개 저장소의 기본값은 비우고 운영만 켠다.** 실행 공간이 없는 새 설치에서는 셸 계열이 빠지고 web 만 켜지므로 같은 방향으로 둬도 안전하다. 사용자는 새 설치도 같은 방향으로 두기로 했다.
- **기존 기본 profile 에 켜는 일회성 관리자 동작을 만든다.** 관리자 도구 화면이 같은 일을 한다. 쓰고 버릴 코드를 남기지 않는다.

### 결과

- 얻는 것:
  - 새로 들어온 사용자의 기본 에이전트가 처음부터 웹 검색과 셸, 파일, 코드 실행을 쓴다.
  - 기본값이 셸을 local 로 여는 길이 없다. 실행 공간이 없으면 셸 계열이 빠진다.
  - 사람의 도구 저장과 같은 plugin 검사(커넥터 서버 이름, 비밀 요청 스킬, memory 금지)를 지난다.
- 감당할 것:
  - **연결이 붙은 기본 에이전트에서 READ 결과를 셸이 인터넷으로 보낼 수 있다.** [커넥터 READ 데이터의 흐름](../read-data-flow.md) 의 RF-08 이다. 지금까지는 관리자가 셸을 켠 에이전트에만 있던 길이 모든 기본 에이전트로 넓어진다. web 의 RF-09 는 2026-10-08 사용자 결정 #320 으로 이미 감당하기로 했다.
  - `execute_code` 는 [ADR-20261008 / execute-code-unattended](../../hermes/docs/adr/ADR-20261008-execute-code-unattended.md) 에 따라 실행 공간에서 승인 없이 돈다.
  - 같은 사용자의 에이전트끼리 `/workspace` 를 함께 쓴다. 웹 도구가 없는 에이전트가 쓴 파일도 기본 에이전트의 셸이 읽어 보낼 수 있다.
  - 에이전트 주인은 셸 계열을 스스로 끄지 못한다. 관리자 등급이기 때문이다. 끄려면 관리자에게 말한다.
  - 셸 계열이 켜진 기본 에이전트는 주인을 바꾸지 못한다(`AGENT_OWNER_CHANGE_REQUIRES_SHELL_OFF`).
  - **운영이 정책에 profile 을 등록하기 전에 첫 로그인하면 web 만 켜진다.** 등록한 뒤 관리자가 에이전트 도구 화면에서 셸 계열을 켠다. 등록하지 않은 채 관리자가 켜면 ADR-086 대로 local 로 켜지므로, 반드시 등록을 먼저 한다.
  - **plugin 을 Control Plane 보다 먼저 배포한다.** 옛 plugin 은 `require_sandbox` 를 몰라 400 으로 거절하고, 그때 Control Plane 은 아무 도구도 켜지 않고 경고만 남긴다. 사람의 도구 저장은 이 칸을 싣지 않아 영향이 없다.
  - 기존 기본 에이전트에는 적용되지 않는다. 관리자 도구 화면에서 켠다. 절차는 운영 저장소가 갖는다.

- **적용 범위**: `agent/application/AgentDefaultToolsets`, `PeopleProperties` 의 `defaultToolsets`, `people/application/FirstAgentCreator`, `HermesToolsetClient.writeApiServerInSandbox`, 대시보드 plugin 의 `PUT /api/config` 의 `require_sandbox`. 흐름은 [`backend/people.md`](../backend/people.md) 의 「첫 에이전트의 기본 도구」 가 갖는다.
