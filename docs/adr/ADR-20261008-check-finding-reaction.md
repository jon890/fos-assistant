## ADR-20261008 / check-finding-reaction: 살펴보기 발견의 반응은 판단 피드백 사건으로 받고, 「관심 없음」 은 digest 기간 안에서만 같은 주제를 내린다

- **status**: `accepted`
- Date: 2026-10-08

### 맥락

먼저 살펴보기의 발견에 사용자가 어떻게 반응했는지 남는 곳이 없었다.
점검 대화에서 「이건 관심 없다」 고 말해도 그 글은 Hermes session 의 대화 이력에만 남는다.
session 은 `session-max-checks` 번마다 바뀌고, 그 뒤의 살펴보기는 그 거절을 모른다.
되풀이 판정([ADR-081](../../backend/docs/adr/ADR-081-살펴보기-결과는-답-끝의-구조화-블록으로-받고-control-plane-이-검사해-그린다.md))은 같은 주제 키와 같은 원문 주소만 막으므로, 같은 주제의 다른 원문은 다시 「새로 알릴 것」 이 된다.

[ADR-20261007 / decision-feedback](../../backend/docs/adr/ADR-20261007-decision-feedback.md) 은 판단 피드백 기록이 Memory 도 억제 규칙도 바꾸지 않는다고 정했다.
거절을 일회성 반응으로 읽고, 오래 가는 선호는 Memory 에만 두려는 결정이다.

### 결정

**발견 하나를 제안 하나로 보고 판단 피드백 사건으로 받는다.**
열쇠는 `check_finding:<발견 번호>` 다. 「새로 알릴 것」 으로 그린 발견만 대상이다.
사용자의 단추는 「받아들임」 이 `ACCEPTED`, 「나중에」 가 `POSTPONED`, 「관심 없음」 이 `DISMISSED` 다.
그 살펴보기의 보고를 보였을 때 「새로 알릴 것」 발견마다 `SURFACED` 를 남긴다.
새 표와 칸은 두지 않는다.

**발견의 지금 반응은 그 발견의 마지막 사용자 사건이다.**
사용자가 마음을 바꾸면 다른 단추를 다시 누르고, 같은 단추를 다시 누르면 사건을 더 남기지 않는다.
replay 읽기 모델의 첫 반응 규칙은 그대로다. 지금 반응은 다음 살펴보기의 입력과 판정에만 쓴다.

**「관심 없음」 은 같은 점검 대화의 `digest-window` 안에서만 같은 주제를 내린다.**
그 기간 안에 지금 반응이 「관심 없음」 인 발견과 주제 키가 같으면, 원문 주소가 달라도 `changeSinceLast` 가 있어도 `REPEATED` 로 내린다.
기간은 그 발견을 알린 시각부터 센다. 지금의 되풀이 판정과 같은 발견 줄을 같은 기간으로 읽기 때문이다. 기간이 지나면 다시 알릴 수 있고, 오래 가는 선호가 되지 않는다. 화면은 이 기간을 단추 아래에 알린다.
「나중에」 와 「받아들임」 은 지금의 되풀이 규칙을 그대로 따른다.

**다음 살펴보기의 최근 발견 목록에 지금 반응을 싣는다.**
모델이 같은 주제를 다시 조사하지 않게 해 토큰을 아낀다. Control Plane 판정은 모델이 이 줄을 무시해도 같다.

### 버린 대안

- **반응을 `proactive_check_finding` 의 칸으로 둔다**: 순서와 마음을 바꾼 기록을 잃는다. 판단 피드백 기록과 같은 반응을 두 곳에 둔다.
- **「관심 없음」 을 Memory 제안으로 만든다**: 사용자가 단추 하나로 끝내려는 일에 검토할 기억을 하나 더 만든다. 발견 하나의 반응을 오래 가는 선호로 키운다.
- **「관심 없음」 도 원문 주소가 같을 때만 막는다**: 같은 주제의 다른 원문이 바로 다시 알려져 단추가 효과가 없다.
- **`changeSinceLast` 가 있으면 다시 알린다**: 모델이 마감 임박 같은 변화를 쉽게 적어 거절한 주제가 곧 돌아온다. 사용자가 다시 보고 싶으면 「관심 없음」 을 다른 단추로 바꾼다.
- **기간 없이 막는다**: 일회성 반응을 영구 억제 규칙으로 바꾼다. ADR-20261007 / decision-feedback 의 잘못된 학습을 막는 규칙과 어긋난다.

### 감당할 것

- ADR-20261007 / decision-feedback 의 「억제 규칙을 바꾸지 않는다」 에 예외가 하나 생긴다. 그 예외는 이 ADR 이 정한 기간과 범위에 한정한다.
- 「관심 없음」 으로 내린 발견도 `REPEATED` 라 문제 후보의 근거가 될 수 있다. 문제 후보는 아직 사용자에게 보이지 않는다.
- 반응은 점검 대화마다 따로다. 점검 대화를 지우면 반응도 함께 지워지고 다음 살펴보기는 처음처럼 알린다.

### 근거와 결과

기록 지점과 반응 읽기는 [판단 피드백](../backend/decision-feedback.md)이, 되풀이 판정과 입력은 [먼저 살펴보기](../backend/proactive-check.md)가 갖는다.
