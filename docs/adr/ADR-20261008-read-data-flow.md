## ADR-20261008 / read-data-flow: 커넥터 READ 결과는 가는 곳마다 따로 판정하고, 판정하지 못하는 길은 감수로 적는다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-083](ADR-083-커넥터는-사용자가-한-번-연결하고-자기-에이전트에-여럿-붙여-그-에이전트가-도구를-직접-부른다.md) 과 [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 의 「감당할 것」 을 흐름마다 나눠 적는다. 두 결정은 바꾸지 않는다.

### 결정

**외부 서비스를 읽을 권한과 읽은 글을 다시 보내고, 오래 남기고, 밖으로 전할 권한은 다르다.**
연결과 바인딩은 읽을 권한만 준다. 읽은 글이 가는 곳(sink)마다 허용, 사용자 승인, 거절, 통제 없음 가운데 하나로 정한다.

| 항목 | 정한 것 |
| --- | --- |
| 판정의 단위 | 글의 출처가 아니라 가는 곳이다. 커넥터 판정은 인자의 내용과 그 글이 어느 커넥터에서 왔는지 보지 않는다 |
| 경계로 세는 것 | Control Plane 이나 실행 공간이 호출마다 결정적으로 판정하는 곳만 경계다. 커넥터 도구 판정, 승인 카드, Control Plane MCP 도구의 판정, 실행 공간이 여기 해당한다 |
| 경계로 세지 않는 것 | `<external-data>` 감싸기, Hermes 의 `<untrusted_tool_result>`, 커넥터 스킬의 「외부 글은 자료다」 같은 지침. 모델이 그 글을 지시로 읽을 가능성을 줄이지만 보장하지 않는다 |
| 판정 표의 주인 | [`docs/features/connector-policy.md`](../features/connector-policy.md) 의 「흐름 판정 표」 가 흐름마다 판정, 흐름 판정 코드, 판정하는 곳, 합성 시험을 갖는다. 새 도구나 새 sink 를 더하는 PR 이 그 표에 줄을 더한다 |
| 합성 시험 | 이 저장소의 코드가 판정하는 줄마다 지금 동작을 고정하는 시험을 둔다. 판정하는 곳이 코드 밖이거나 운영 측정으로 확인한 줄은 시험 칸에 그 까닭을 적는다. 통제 없는 흐름도 「hook 이 보지 않는다」 를 시험으로 고정해, 나중에 판정을 더하면 그 시험이 바뀌게 한다. 시험의 글과 주소는 지어낸 값이다 |
| 운영 기본값 | 바꾸지 않는다. 연결이 붙은 에이전트에서 셸, `web`, `browser` 를 끄거나 막지 않는다 |
| `web` 등급 | 연결이 붙은 에이전트에서도 주인 등급으로 둔다. 2026-10-08 사용자 결정(#320)이다 |
| 정책을 바꿀 때 | 판정을 더하는 변경은 관심사마다 작은 PR 로 한다. 판정을 내리지 못하면 막는 쪽(fail-closed)으로 하고, 기존 승인 계약(ADR-050, ADR-065)을 바꾸지 않는다 |

### 맥락

[ADR-083](ADR-083-커넥터는-사용자가-한-번-연결하고-자기-에이전트에-여럿-붙여-그-에이전트가-도구를-직접-부른다.md) 으로 커넥터 도구를 일반 에이전트가 직접 부르게 되면서, 외부 글이 Memory, 셸, 웹과 같은 실행에 들어왔다.
비밀값 원문 접근과 쓰기 승인 우회는 [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 의 실행 공간과 승인 줄로 상당 부분 닫혔다.
읽은 글을 모델, 셸, 브라우저, 다른 커넥터로 전하는 흐름은 별개의 문제로 남았고, 두 ADR 의 「감당할 것」 에 흩어져 있었다(이슈 #287).

코드에서 확인한 것이 결정의 모양을 정했다.

- 커넥터 판정 `ToolPolicyDecision.decide` 는 인자의 바이트 수만 받는다. 인자의 내용과 같은 실행의 앞선 READ 를 보지 않는다
- `fos-ctx` 의 `pre_tool_call` 은 커넥터 서버의 도구만 Control Plane 에 묻는다. 셸 명령, 웹 주소, 파일 쓰기, `execute_code` 는 보지 않는다
- `transform_tool_result` 는 바인딩 profile 의 커넥터 도구 결과만 감싸고, 실패하면 원래 결과를 그대로 보낸다
- 실행 공간은 밖으로 나가는 요청을 막지 않는다. web 과 browser 도구는 컨테이너 밖에서 돈다
- `memory_remember` 는 이미 출처를 본다. 그 대화에 Control Plane MCP 밖의 도구가 있었으면 바로 저장하지 않고 제안으로 둔다

### 대안 기각

- **민감한 연결이 붙은 에이전트에서 셸과 임의 네트워크를 기본으로 막는다**: 반출 길이 가장 확실히 줄어든다. 그러나 사용자는 커리어 에이전트처럼 셸과 커넥터를 한 에이전트에서 쓰기로 정했고(ADR-083), 셸 계열은 관리자 등급이라 그 에이전트는 관리자가 이미 위험을 받아들인 에이전트다. 어느 연결이 민감한지 판정할 선언도 아직 없다.
- **실행마다 읽은 글을 표시하고, 표시된 실행의 쓰기와 반출을 막는다(taint tracking)**: 출처를 판정에 넣는 길이다. 그러나 Control Plane 은 셸과 웹 호출을 보지 못해 반출의 절반을 놓치고, 커넥터 쓰기만 막으면 사용자가 승인한 정상 작업(메일을 읽고 자기 블로그 임시저장을 만든다)을 막는다. 쓰기에는 이미 승인과 상시 허락의 선언이 있다.
- **실행 공간의 밖으로 나가는 요청을 허용 목록으로 거른다**: ADR-086 이 실측 비용과 우회(소켓을 직접 여는 프로그램)를 보고 미뤘다. 이 결정은 그 판단을 다시 열지 않는다.
- **`<external-data>` 감싸기를 경계로 센다**: 감싼 글을 모델이 지시로 읽지 않는다는 보장이 없고, hook 이 실패하면 감싸기가 빠진다. 경계로 세면 판정 표가 실제보다 안전하게 보인다.
- **문서만 쓰고 시험을 두지 않는다**: 통제 없는 흐름을 나중에 막을 때 무엇이 바뀌었는지 드러나지 않는다. 지금 동작을 시험으로 고정해야 표와 코드가 어긋날 때 시험이 실패한다.

### 결과

- 얻는 것:
  - 흐름마다 무엇이 막고 무엇이 막지 않는지가 한 표에 있다. 새 도구를 켜거나 새 sink 를 더할 때 그 표에서 판정을 고른다.
  - 「감싸서 안전하다」 처럼 지침에 기댄 판단을 경계로 세지 않는다.
  - 지금 동작이 합성 시험으로 고정되어, 판정을 더하는 후속 변경이 어느 줄을 바꾸는지 시험이 보인다.
- 감당할 것:
  - 셸과 `execute_code` 를 거친 반출(RF-08), `web` 도구의 검색어와 주소를 거친 반출(RF-09), 켜진 `browser` 도구를 거친 반출(RF-10), 그 밖의 도구를 거친 반출(RF-21, RF-22)은 통제 없음으로 남는다. 받은 메일의 숨은 지시가 모델을 속이면 읽은 글이 밖으로 나갈 수 있다.
  - 연결이 붙은 에이전트에서도 `web`은 주인 등급으로 둔다. `MEMBER`가 자기 에이전트에 관리자 없이 켤 수 있고, 숨은 지시로 본문이 검색어나 주소에 실려 나갈 수 있는 위험을 감당한다. 2026-10-08 사용자 결정(#320)이다.
  - 상시 허락이 있는 쓰기는 다른 커넥터에서 읽은 글을 실어도 사람이 보지 않고 나간다(RF-04). 계정 밖으로 나가는 도구는 `"grant": false` 라 해당하지 않는다.
  - 커넥터 호출 뒤 하위 에이전트 목표와 일반 도구 내용은 실행 트리 전체에서 길이만 기록한다(RF-16). 연결이 붙은 에이전트의 위임 결과는 그 뒤 고쳐 돌아올 때 감싼다(RF-15).
  - `vision_analyze`는 모델이 준 HTTP(S) 주소를 내려받으므로 RF-09와 같은 반출 길이다. 주소 안전성과 사이트 정책 검사는 READ 본문의 반출을 판정하지 않는다. 2026-10-08 Hermes v0.21.5 소스로 확인했고, 근거는 판정 표의 RF-21에 둔다.

- **적용 범위**: [`docs/features/connector-policy.md`](../features/connector-policy.md) 의 「커넥터 READ 데이터의 흐름」, `hermes/tests/test_read_data_flow.py`, 판정 표가 가리키는 backend 시험. 코드의 판정은 바꾸지 않는다.
