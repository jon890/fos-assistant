## ADR-014: 실제 청구액과 환산액을 나눠 적는다

- **status**: `accepted`
- **결정**: 실행 기록의 금액 칸을 둘로 나눈다.
  공개 API 가격으로 환산한 값과 실제로 청구되는 값을 따로 적는다.
  구독 경로로 도는 실행은 실제 청구액을 비운다.
  확인하지 못한 값을 확인한 값처럼 적지 않는다.

### 맥락

[ADR-004](ADR-004-구독제에서도-api-가격으로-환산해-보인다.md) 가
구독형 바인딩도 공개 API 가격으로 환산해 보이기로 했다.
구독료와 견줄 숫자를 주기 위한 것이었고 그 목적은 지금도 유효하다.

다만 지금은 칸이 `estimated_cost_micros` 하나뿐이라
환산한 값인지 실제로 빠져나가는 값인지 화면에서 구분되지 않는다.

실측이 그 차이를 크게 만들었다.
포지션 추천 한 번이 입력 3,460,816 토큰에 환산 14.15달러였다.
그 실행은 `openai-codex` 구독 경로로 돌아 실제 청구는 그 금액이 아니다.
같은 실행을 `openrouter` 로 옮기면 그 금액이 실제로 빠져나간다.
두 경우의 숫자가 한 칸에 같은 얼굴로 들어가면,
모델을 바꿀지 정하는 판단이 잘못된 근거 위에서 이뤄진다.

앞으로 에이전트 하나가 다른 에이전트를 부르면 이 문제가 커진다.
자식 실행의 토큰이 부모의 합계에 이미 포함되는지 아직 확인하지 못했다.
포함되는데 따로 더하면 비용이 두 번 세어진다.

### 대안 기각

- **칸 하나를 두고 화면에서 구분한다.**
  화면이 `cost_mode` 를 보고 해석하는 방식이다.
  합계를 낼 때마다 같은 해석을 다시 해야 하고, 한 곳이라도 빠뜨리면 섞인 합계가 나온다.
- **구독 경로는 금액을 아예 적지 않는다.**
  ADR-004 가 풀려던 문제로 되돌아간다. 구독료와 견줄 숫자가 사라진다.
- **자식 실행의 토큰을 부모에 더해 둔다.**
  Hermes 가 이미 합쳐 보고하는지 확인하기 전에는 두 번 세는 것이 된다.
  확인할 때까지는 실행마다 보고된 값을 그대로 두고, 합치는 것은 조회하는 자리에서 한다.

### 결과

얻는 것

- 「이번 달에 실제로 얼마가 나갔는가」 와 「API 로 돌렸다면 얼마였겠는가」 를 따로 답할 수 있다.
- 모델을 구독 경로에서 종량 경로로 옮길지 정할 때 견줄 두 숫자가 생긴다.
- 어느 에이전트가 비용을 쓰는지를 부모와 자식 관계로 나눠 볼 수 있다.

감당할 것

- 구독 경로에서는 실제 청구액이 비어 있다. 화면이 그 빈 칸을 0 이 아니라 「모름」 으로 그려야 한다.
  금액을 0 으로 채우지 않는 기존 규칙을 그대로 따른다.
- 실제 청구액을 채우려면 provider 의 청구 자료를 읽어야 한다. 그 경로는 아직 없다.
  당분간 그 칸은 종량 경로에서만 채워지고, 그것도 공개 가격으로 계산한 값이다.
- 자식 실행의 토큰이 부모에 포함되는지 실제 Hermes 로 확인하기 전까지
  부모와 자식을 더한 합계를 화면에 보이지 않는다.
