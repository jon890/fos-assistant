## ADR-20261009: 실행 공간 파일은 Control Plane 이 읽기 전용으로 붙여 주인에게만 보이고, 지우기는 운영의 권한 도우미에 맡긴다

- **status**: `accepted`
- Date: 2026-10-09
- [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 이 정한 사용자별 `/workspace` 를 사람이 화면에서 보는 길을 정한다. 실행 공간의 모양은 바꾸지 않는다.

### 결정

**Control Plane 이 실행 공간 루트를 읽기 전용으로 붙이고, 요청자의 사용자 디렉터리 `u<사용자 번호>` 만 보인다.**
목록, 미리보기, 내려받기는 이 마운트로 한다. 어느 디렉터리를 볼지는 웹 토큰의 사용자가 정하고 요청이 정하지 못한다.
주인 키의 규칙은 `Agent.sandboxOwner()` 와 같다. 주인이 없는 에이전트의 공간 `a<에이전트 번호>` 는 누구의 화면에도 목록으로 보이지 않는다.

**링크를 따라가지 않는다.** 경로의 조각마다 링크가 아닌 디렉터리인지 보고 연다. 마지막 조각이 심볼릭 링크면 링크로 보이고 열지 않는다.
하드 링크가 둘 이상인 파일, 일반 파일과 디렉터리가 아닌 것은 목록에만 보이고 본문을 주지 않는다.

**미리보기는 결과물과 같은 격리를 쓴다**([ADR-027](ADR-027-에이전트가-만든-html-은-대화별-폴더에-두고-스크립트-없이-보인다.md)).
HTML 은 같은 출처의 iframe 에 스크립트 없이 띄우고, 응답에 `Content-Security-Policy` 의 `sandbox` 를 붙인다. 주소를 직접 열어도 스크립트가 돌지 않는다.
HTML 이 아닌 미리보기는 본문을 `text/plain` 이나 정한 사진 형식으로만 준다. 내려받기는 `application/octet-stream` 과 `attachment` 로만 준다.

**지우기는 운영 저장소의 권한 도우미가 한다.** Control Plane 은 unix socket 으로 주인 키와 상대 경로 하나를 보낸다.
도우미는 그 주인의 디렉터리 아래에서 링크를 따라가지 않고 지우며, 경로만 감사 기록에 남긴다.
도우미의 socket 이 설정되지 않았으면 지우기를 열지 않고 화면은 지우기 단추를 그리지 않는다.

**관리자는 사용자별 용량만 본다.** 관리자 경로는 파일 이름과 본문을 주지 않는다.

### 맥락

실행 공간이 생긴 뒤 에이전트가 만든 파일이 `/workspace` 에 쌓이는데 사용자가 볼 길이 없었다. 실행 공간은 컨테이너가 멈춰도 남는다.

운영을 확인해 보니 두 가지가 정해져 있었다.

| 사실 | 뜻 |
| --- | --- |
| 실행 공간 안의 프로세스는 root 다. 사용자 디렉터리 자체는 Hermes 가 만든다 | 에이전트가 만든 파일과 하위 디렉터리는 root 소유다. Control Plane 은 root 가 아닌 사용자로 돈다 |
| 기본 권한으로 만든 파일은 누구나 읽는다 | Control Plane 이 읽기 전용 마운트로 대부분을 읽는다. 주인만 읽는 파일은 읽지 못한다 |
| root 가 만든 하위 디렉터리 안의 파일은 그 디렉터리의 주인만 지운다 | 쓰기 마운트로 붙여도 Control Plane 은 에이전트가 만든 하위 디렉터리를 지우지 못한다 |

에이전트가 만든 파일은 에이전트가 쓴 것이라 믿지 않는다. 경로 이름과 링크와 파일 종류를 에이전트가 정할 수 있다.
같은 사용자의 공간 안에서만 만들 수 있어도, 그 링크를 Control Plane 이 따라가면 Control Plane 이 붙인 다른 사용자의 디렉터리나 다른 마운트를 가리킬 수 있다.

### 대안 기각

- **목록과 읽기도 도우미가 맡는다.** 주인만 읽는 파일까지 보인다. 그러나 경로 판정과 머리글 같은 보안 규칙이 비공개 저장소로 가서 이 저장소의 시험이 그 규칙을 보지 못한다. 본문도 한 번 더 건너 전해진다.
- **도우미 없이 Control Plane 을 쓰기로 붙인다.** 에이전트가 만든 하위 디렉터리 안의 파일 대부분을 지우지 못한다. 사용자는 지우기 단추를 누르고 실패를 본다.
- **사용자의 실행 공간 컨테이너 안에서 지운다.** 컨테이너가 경계라 경로를 넘지 못한다. 그러나 Control Plane 은 Docker 에 닿지 않고, 컨테이너가 없거나 멈춰 있으면 지울 수 없다. 컨테이너를 찾는 열쇠는 Hermes 안의 값이다.
- **실행 공간을 root 가 아닌 사용자로 돌린다.** 소유 문제가 사라진다. 그러나 이미지 안에서 패키지를 까는 셸 명령이 실패하고 ADR-086 의 측정을 다시 해야 한다. 따로 검토할 후보로 남긴다.
- **HTML 미리보기에서 스크립트를 돌린다.** 출처 없는 sandbox 문서는 앱 쿠키를 보내지 않아 상대 경로 사진과 CSS 를 주인 확인 뒤에 줄 수 없다. 서명한 주소를 따로 만들어야 한다. 결과물과 같은 이유로 지금은 받지 않는다.
- **주인이 없는 에이전트의 공간을 관리자에게 탐색하게 한다.** 사용자가 정한 범위가 「본인만」 이다. 관리자는 용량만 본다.
- **관리자 용량을 미리 세어 표에 둔다.** 관리자가 가끔 여는 화면이라 요청할 때 세고, 큰 공간은 상한에서 멈춘다. 표를 두면 세는 작업과 그 기록의 낡음을 따로 다뤄야 한다.
- **지우기를 비동기 작업으로 돌린다.** 한 번에 경로 하나와 항목 10,000 개가 상한이라 요청 안에서 끝난다. 작업 상태를 둘 곳과 그 화면이 더 필요해진다.

### 결과

- 얻는 것:
  - 사용자가 자기 에이전트들이 함께 쓰는 공간을 보고, 미리 보고, 내려받고, 지운다.
  - 경로와 링크와 머리글의 규칙이 이 저장소의 코드와 시험에 있다.
- 감당할 것:
  - 주인만 읽는 파일은 목록에 「읽을 수 없음」 으로만 보인다.
  - 실행 공간 루트 전체가 Control Plane 에 읽기로 붙는다. 다른 사용자의 디렉터리를 고르지 않는 것은 Control Plane 의 코드가 지킨다.
  - 그룹에 공개한 에이전트를 다른 사용자가 쓰면 그 실행이 만든 파일도 에이전트 주인의 공간에 생기고 주인의 화면에 보인다. 실행 공간이 원래 그렇게 나뉘어 있다(ADR-086). 화면은 공간을 함께 쓰는 에이전트를 보이고 그룹에 공개한 것을 따로 표시한다.
  - 도는 실행이 쓰는 파일을 지우면 실행이 같은 파일을 다시 만들 수 있다. 잠글 길이 없어 확인 창에서 알린다.
  - 확인한 뒤 여는 사이에 에이전트가 파일을 FIFO 로 바꾸면 그 요청 하나가 끝나지 않을 수 있다. 같은 사용자의 공간에서만 일어난다.
  - **운영 이미지는 musl(Alpine)이라 `SecureDirectoryStream` 이 없고 대체 경로를 탄다.** 대체 경로는 조각마다 링크인지 본 뒤 경로로 열어, 확인과 열기 사이에 틈이 있다.
    에이전트가 자기 공간의 중간 디렉터리를 다른 사용자 디렉터리를 가리키는 링크로 바꾸는 경쟁을 되풀이해 그 틈에 맞으면, Control Plane 이 다른 사용자의 목록이나 본문을 읽어 이 사용자에게 보일 수 있다.
    연 뒤에 다시 확인하는 사후 확인으로 틈을 줄이지만 없애지는 못한다. 확인한 뒤 링크로 바꿨다가 사후 확인 전에 되돌리면 통과한다. Java 로는 연 채널의 파일을 다시 볼 수 없기 때문이다. 사용자가 가족 몇 사람이고 실행 공간에는 그 사용자의 에이전트만 있어 지금은 받아들인다.
    사용자가 늘면 backend 런타임 이미지를 glibc 로 바꾸고, 파일 공간은 `SecureDirectoryStream` 이 없으면 대체 경로 없이 꺼지게(fail-closed) 한다. 이미지를 바꾼 뒤 대체 경로를 지운다. 이슈 #359 가 이 일을 갖는다. 결과물 쓰기(`ArtifactFileWriter`)도 운영에서 같은 대체 경로를 탄다.
  - 도우미의 계약을 바꾸면 운영 저장소의 도우미와 함께 배포한다.
  - 관리자 용량은 요청할 때 세므로 공간이 크면 상한에서 멈추고 일부만 센 것으로 보인다.
