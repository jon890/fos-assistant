## ADR-053: 에이전트는 허용된 collection 의 Memory 만 받는다

- **status**: `accepted`
- **결정**: 에이전트의 실행이 받는 Memory 는 세 조건을 모두 지난 항목이다.
  1. 범위. `USER` 는 주인, `GROUP` 은 같은 그룹
  2. 그 에이전트가 받는 collection. `agent_memory_collection` 에 줄이 있는 collection 만이다
  3. 민감도. `SENSITIVE` 항목은 그 collection 의 줄에 `allow_sensitive` 가 참일 때만이다

  주입(항상 층 본문과 색인)과 `memory_read` 가 같은 조건을 쓴다. `memory_read` 는 origin 실행의 에이전트로 판정하고, 받지 않는 collection 의 항목과 허용받지 않은 민감 항목을 없는 항목과 **같은 응답**으로 답한다.
  허용은 에이전트 단위다. profile 단위가 아니다.
  **줄이 하나도 없는 에이전트는 아무것도 받지 않는다.** 에이전트를 찾지 못한 실행과 에이전트가 없는 실행도 같다.
  커넥터 에이전트는 줄이 있어도 받지 않는다([ADR-045](ADR-045-커넥터-에이전트는-자기-mcp-서버만-받고-memory-와-control-plane-도구를-받지-않는다.md)).
- **호환 정책**: 이미 있는 Memory 는 모두 `core` 로 간다([ADR-052](ADR-052-memory-는-collection-종류-꺼내는-방식-민감도-판-출처를-가진다.md)). 마이그레이션이 커넥터 에이전트가 아닌 모든 에이전트에 `core` 를 준다. 그래서 같은 사용자와 같은 에이전트가 받는 글이 이 결정 앞과 같다.
  새로 저장하는 에이전트는 저장할 때 `core` 를 민감 허용 없이 받는다. 그 밖의 collection 은 관리자가 에이전트마다 더한다.
- **맥락**: [ADR-012](ADR-012-memory-는-사람이-승인한-것만-남는다.md) 는 「에이전트별로 Memory 를 나눈다」 를 기각했다. 까닭은 에이전트가 둘뿐이고, 나누면 화면과 주입 규칙이 함께 복잡해지며, 주입한 양이 문제가 되는지를 먼저 측정한다는 것이었다.
  그 조건이 셋 다 바뀌었다.
  - 에이전트가 늘었다. 사용자가 직접 만들고([ADR-033](ADR-033-사용자가-에이전트를-만들고-공개해도-만든-사람이-관리한다.md)) 위임받아 도는 에이전트도 있다([ADR-017](ADR-017-무엇을-할지는-hermes-가-정하고-control-plane-은-경계만-갖는다.md))
  - 나누는 까닭이 양이 아니라 **내용**이 됐다. 건강, 재무, 신원 기록을 Memory 로 모으면 그것을 볼 일이 없는 에이전트도 요청자의 것이라는 이유만으로 받는다. 색인의 제목 한 줄도 개인 정보다
  - 그룹에 공개한 에이전트는 다른 사용자가 만든 것일 수 있다. 그 에이전트의 지침을 요청자가 쓰지 않았다
- **대체된 부분**: [ADR-012](ADR-012-memory-는-사람이-승인한-것만-남는다.md) 의 「대안 기각」 가운데 「에이전트별로 Memory 를 나눈다」 를 이 결정이 뒤집는다. ADR-012 의 나머지(사람이 승인한 것만 남는다, 범위는 `USER` 와 `GROUP`)는 그대로다.
- **대안 기각**:
  - profile 단위로 허용한다: 한 profile 을 여러 에이전트가 가리킬 수 있고 실행 줄이 에이전트를 적는다. 사람이 고르는 것도 에이전트다.
  - 줄이 없으면 `core` 를 받는 것으로 본다: 관리자가 `core` 를 뺄 수 없게 된다. 표가 말하는 것과 실제 판정이 달라진다. 그 대신 에이전트를 저장할 때 줄을 넣는다.
  - 에이전트를 만드는 경로마다 줄을 넣는다: 경로가 셋이다(첫 로그인, 사용자가 만들기, 관리자 등록). 하나를 빠뜨리면 그 경로로 만든 에이전트가 조용히 Memory 를 받지 못한다. 저장소의 저장이 내는 사건 하나로 넣는다.
  - 항목마다 접근 목록을 둔다: 항목을 적을 때마다 누가 볼지 정해야 한다. 영역 단위로 충분하다.
  - 민감 허용을 에이전트에 불 값 하나로 둔다: 신원을 허용받은 에이전트가 건강의 민감 항목까지 받는다. collection 마다 둔다.
  - 받지 않는 collection 의 `memory_read` 를 「권한 없음」 으로 답한다: 그 번호의 항목이 있다는 사실이 새어 나간다. 남의 항목과 같은 응답으로 숨긴다.
- **결과**:
  - 얻는 것: 영역이 다른 지식을 한 표에 모아도 에이전트가 받는 범위가 영역으로 한정된다. 다른 사람이 만든 그룹 에이전트가 요청자의 건강이나 신원 기록에 닿지 않는다.
    새 collection 은 누구에게도 열리지 않은 채 시작한다.
  - 감당할 것: 관리자가 에이전트마다 collection 을 정해야 한다. 정하지 않으면 그 에이전트는 `core` 밖의 것을 모른다.
    위임받은 에이전트는 자기 허용으로 판정한다. 부르는 쪽이 받는 것을 자식이 물려받지 않으므로, 필요한 맥락은 부르는 쪽이 `task` 에 담는다. 그 글은 판정을 지나지 않는다.
    Memory 목록 화면의 「자리가 없어 빠질 항목」 표시는 에이전트를 모르는 채 판정한다. collection 을 거르지 않은 조립을 기준으로 삼으므로, collection 을 적게 받는 에이전트에서는 실리는 항목에도 표시가 붙을 수 있다.
- **다음**: 관리자가 에이전트 화면에서 collection 과 민감 허용을 고치는 경로를 만든다. 그때 Memory 목록의 빠짐 표시를 에이전트마다 볼 수 있게 할지 함께 정한다.
  다른 서비스가 문서를 읽는 신원은 사용자 하나와 collection 목록에 묶인 서비스 토큰으로 두고, 같은 세 조건으로 판정한다. 이것은 [ADR-056](ADR-056-다른-서비스는-사용자에-묶인-서비스-토큰으로-문서를-읽기만-한다.md) 가 정했다.
