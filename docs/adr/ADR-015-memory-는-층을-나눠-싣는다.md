## ADR-015: Memory 는 층을 나눠 싣는다

- **status**: `accepted`
- **결정**: Memory 를 전부 주입하지 않는다.
  항상 싣는 층과 제목만 싣는 층으로 나누고, 제목만 실은 항목의 본문은
  에이전트가 요청할 때 준다.
  그 요청은 Control Plane 이 여는 MCP 도구로 받고, 권한은 Control Plane 이 강제한다.
  **항상 층만으로 기본 대화가 성립해야 한다.** 도구는 보조다.

### 맥락

[ADR-003](ADR-003-memory-권한은-주입으로-강제한다.md) 이
요청자가 볼 수 있는 항목을 `instructions` 로 넣기로 했고,
「memory 가 많아지면 도구 방식으로 옮긴다」 와
「그때도 권한 검사는 도구 구현이 아니라 Control Plane 이 맡는다」 를 함께 적었다.
이 ADR 은 그 조건을 구체화한다.

전부 주입하면 실행마다 그 양이 실린다.
`career` profile 의 `MEMORY.md` 가 10,192 바이트로 자란 상태였고,
「오늘 날씨 좋다」 같은 한 문장에도 그것이 함께 실렸다.
비운 뒤 입력이 12,388 에서 9,551 로 줄었다.

한편 같은 profile 의 스킬은 다른 방식으로 실린다.

| 층 | 크기 |
| --- | --- |
| 스킬 색인. 프롬프트에 항상 실린다 | 579자 |
| 스킬 본문 합계. 에이전트가 요청할 때 읽는다 | 59,211 바이트 |

102배 차이다.
Hermes 와 Claude Code 의 스킬이 모두 이 구조이고,
색인 한 줄로 「이런 것이 있다」 를 알린 뒤 필요할 때 본문을 읽는다.

Memory 도 같은 성질을 갖는다.
이름과 시간대와 말투 선호는 짧고 거의 모든 대화에 쓰인다.
경력 상세나 지원 이력은 길고 특정 대화에서만 쓰인다.
둘을 같은 방식으로 실을 이유가 없다.

### 대안 기각

- **Hermes 의 내장 memory toolset 을 다시 켠다.**
  가장 간단하지만 ADR-003 과 정면으로 충돌한다.
  내장 memory 는 profile 단위라 개인과 가족 공용을 나누지 못하고,
  LLM 이 그 파일 전체에 닿는다.
  `career` 에서 그 toolset 을 끄면서 도구 정의 3,178 바이트도 함께 뺐다.
- **층을 나누지 않고 전부 주입한 채로 둔다.**
  항목이 적을 때는 문제가 없다.
  다만 나중에 나누려면 화면과 주입 규칙과 표를 함께 고쳐야 하고,
  그때는 이미 쌓인 항목을 어느 층에 둘지 사람이 다시 판단해야 한다.
- **에이전트가 요청하는 길만 두고 항상 층을 없앤다.**
  가장 적게 싣지만 에이전트가 도구를 부르지 않으면 아무것도 모르는 상태가 된다.
  도구를 부를지 판단하는 것이 기대만큼 되지 않는다는 관측이 있다.
  그래서 항상 층만으로 기본 대화가 되게 하고 도구를 보조로 둔다.

### 결과

얻는 것

- 항목이 늘어도 실행마다 실리는 양이 그만큼 늘지 않는다.
- 어느 항목이 실제로 쓰이는지 알 수 있다.
  도구 호출이 실행 기록에 남으므로, 그것을 보고 항상 층으로 올릴 것을 고를 수 있다.
- 권한 경계가 그대로다. 도구를 주지만 그 도구가 우리 것이고 응답을 우리가 고른다.

감당할 것

- Control Plane 이 MCP 서버를 열어야 한다.
  그 서버가 누구의 요청인지 알 수 있어야 하므로 인증을 설계해야 한다.
  실행마다 다른 사용자의 것이므로, 서버 하나가 모든 요청을 같게 다루면 경계가 무너진다.
- 왕복이 늘어 응답이 느려진다.
  에이전트가 본문을 읽으려면 한 번 더 오간다.
- 어느 항목을 항상 층에 둘지 사람이 정해야 한다.
  기본값은 제목만 싣는 쪽이다. 잘못 올리면 안 쓰이는 것이 매번 실린다.
- 에이전트가 도구를 부르지 않으면 제목만 아는 상태로 답한다.
  그래서 항상 층만으로 기본 대화가 성립하는지를 테스트로 고정한다.

### 적용 범위

`memory` 표에 `always_inject` 와 `title` 을 둔다.

| 칸 | 뜻 |
| --- | --- |
| `always_inject` | 참이면 본문까지 매 실행에 싣는다. 기본값은 거짓 |
| `title` | 제목 한 줄. 색인에 실린다 |

`always_inject` 의 기본값을 거짓으로 둔다.
사람이 명시해야 항상 실린다.
[ADR-006](ADR-006-작업-영역은-읽기-전용-의존이고-공개-범위는-기본값이-없다.md) 이
공개 범위에 기본값을 두지 않기로 한 것과 같은 이유다.
기본값이 「싣는다」 쪽이면 아무도 정하지 않은 항목이 계속 실린다.
