## ADR-081: 살펴보기 결과는 답 끝의 구조화 블록으로 받고 Control Plane 이 검사해 그린다

- **status**: `accepted`
- **결정**: 먼저 살펴보기([ADR-080](ADR-080-먼저-살펴보기는-점검-대화의-turn-하나로-돌고-읽기-경계를-control-plane-이-강제한다.md))의 답은 끝에 `<fos-check-result>` 블록 하나를 둔다. 블록 안은 JSON 이다.
  Control Plane 이 그 블록을 읽어 검사하고, 대화에 남길 글은 Control Plane 이 정한 모양으로 다시 쓴다. 모델이 쓴 글은 그대로 대화에 싣지 않는다.
  칸과 상한은 [`backend/proactive-check.md`](../backend/proactive-check.md) 의 「결과 계약」 이 갖는다.

  **발견 하나마다 원문 주소, 확인 시각, 이 사용자에게 중요한 이유, 사실과 추정, 다음 행동이나 논의할 질문을 담는다.**
  아래를 모두 갖춘 발견만 「새로 알릴 것」 으로 그린다. 하나라도 빠지면 「참고」 로 내리고 까닭을 붙인다.

  | 조건 | 빠지면 붙는 까닭 |
  | --- | --- |
  | `sourceUrl` 이 `http` 나 `https` 주소다 | 원문 없음 |
  | `checkedAt` 이 이번 살펴보기를 시작한 무렵부터 지금 사이다. 시계 차이 허용 폭은 [`backend/proactive-check.md`](../backend/proactive-check.md) 의 「검사」 가 갖는다 | 이번에 확인하지 않음 |
  | `freshness` 가 `CURRENT` 다. 마감한 공고는 `CLOSED`, 오래된 동향은 `STALE` 이다 | 마감, 오래됨, 신선도 모름 |
  | 이유, 사실 하나 이상, 다음 행동이나 질문이 있다 | 근거 부족 |
  | 같은 주제 키와 원문으로 이미 알리지 않았거나, 달라진 점을 적었다 | 이미 알린 것 |

  **같은 근거로 같은 제안을 되풀이하지 않는다.** 발견마다 분야 지침이 정한 주제 키(`topicKey`)를 받는다.
  같은 점검 대화에서 `digest-window` 안에 「새로 알릴 것」 으로 낸 발견과 주제 키와 원문 주소가 같으면, 무엇이 달라졌는지(`changeSinceLast`)를 적지 않은 한 「참고」 로 내리고 까닭을 「이미 알린 것」 으로 붙인다.
  새 원문이면 같은 주제여도 알린다. 마감이 다가왔거나 적합성이 바뀌었으면 `changeSinceLast` 에 적고 다시 알린다.

  **할 말이 없으면 침묵한다.** `outcome` 이 `NOTHING_NEW` 이고 발견, 질문, 읽지 못한 출처가 모두 비면 단추로 연 살펴보기는 「살펴봤지만 새로 알릴 것이 없어요」 알림 줄 하나만 남긴다.
  단추를 눌렀는데 아무것도 남지 않으면 실패한 것과 구분되지 않기 때문이다.
  다만 질문(`questions`)이나 읽지 못한 출처(`sourceFailures`)가 있으면 침묵하지 않고 그 절들을 그린다. 출처 장애가 「변화 없음」 으로 보이거나 사용자에게 물을 것이 사라지지 않게 하기 위해서다(#188). 매일 깨우기는 무소식 알림 줄도 남기지 않는다(ADR-080 「다음 단계」).

  **블록이 없거나 읽지 못하면 결과를 그리지 않는다.** 「결과를 정리하지 못했어요」 알림 줄을 남기고 `outcome = INVALID_RESULT` 로 적는다.
  검사를 거치지 않은 주장이 추천으로 보이지 않게 하기 위해서다.

  **할 일 후보는 결과 안의 문장으로만 낸다.** 「할 일」 표를 만들거나 고치지 않는다.

  **「새로 알릴 것」 이 없으면 요약(`summary`)과 할 일 후보(`followUpCandidates`)를 그리지 않는다.** 원문 검사를 거치지 않은 글이 추천으로 보이지 않게 하기 위해서다. 질문과 참고, 확인하지 못한 출처는 그대로 그린다.

  **모델이 쓴 글은 모두 외부 데이터에서 온 신뢰하지 않는 글로 다룬다.**
  그릴 때 Markdown 의 링크와 이미지와 강조 문법을 이스케이프하고, 링크는 검사를 통과한 `sourceUrl` 하나만 만든다.
  검색 결과에 「이전 지시를 무시하라」 같은 글이 있어도 그 글은 화면에 평문으로 보일 뿐 실행되지 않는다. 실행을 막는 것은 ADR-080 의 읽기 경계다.

  **발견은 `proactive_check_finding` 에 남긴다.** 다음 살펴보기가 지난번에 알린 것을 다시 알리지 않도록 최근 발견의 제목과 주소를 입력에 싣는 데 쓴다.
  지금 화면([ADR-074](ADR-074-지금-화면은-원래-기록을-읽어-만든-view-이고-정해진-카드-넷만-그린다.md))과 할 일([ADR-073](ADR-073-할-일은-에이전트가-제안하고-사람이-받아들인-것만-챙긴다.md))로 이을 때도 이 줄을 원래 기록으로 쓴다.

- **맥락**: 이슈 #165 의 결과 계약은 원문 없는 주장, 마감 공고, 오래된 동향을 새 추천으로 단정하지 않는 것이다.
  지침만으로 지키면 Control Plane 에서 검사할 수 없고, 합성 데이터로 시험할 수도 없다.
  모델이 쓴 글을 그대로 대화에 남기면 검색 결과의 글이 링크나 이미지 문법으로 사용자를 속이는 자리가 된다([ADR-009](ADR-009-에이전트의-답은-신뢰하지-않는-글로-그린다.md)).
  [ADR-072](ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md) 는 「왜 보였는가」 를 모델이 쓴 글이 아니라 코드로 남기기로 했다. 같은 원칙으로 출처와 신선도를 칸으로 받는다.
- **대안 기각**:
  - **모델이 쓴 답을 그대로 남긴다.** 출처와 신선도를 검사할 자리가 없다. 같은 지침이어도 답마다 모양이 달라 「지금」 화면으로 잇기 어렵다.
  - **MCP 도구로 결과를 제출하게 한다.** 도구 호출이 실패하거나 빠지면 답과 제출이 어긋난다. 답 끝의 블록은 실행 결과와 한 덩어리로 온다.
    질문을 답 끝의 태그로 받는 [ADR-026](ADR-026-에이전트가-물을-것은-답-끝의-태그로-두고-화면이-카드로-그린다.md) 과 같은 방식이다.
  - **검사에 걸린 발견을 지운다.** 사용자가 왜 빠졌는지 모르고, 모델이 같은 것을 다시 찾는다. 참고로 내려 까닭과 함께 보인다.
- **결과**:
  - 얻는 것: 결과 계약을 합성 fixture 로 시험한다. 분야마다 지침은 달라도 결과 모양과 검사는 하나다.
  - 감당할 것: 분야 지침이 이 블록 모양을 지켜야 한다. 모양을 바꾸면 `version` 을 올리고 Control Plane 이 두 판을 함께 읽는 기간을 둔다.
    마감과 오래됨은 모델이 적은 `freshness` 를 믿는다. Control Plane 이 원문을 다시 열어 보지 않는다.
