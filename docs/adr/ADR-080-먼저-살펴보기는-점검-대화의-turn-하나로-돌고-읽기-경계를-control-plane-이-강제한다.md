## ADR-080: 먼저 살펴보기는 점검 대화의 turn 하나로 돌고 읽기 경계를 Control Plane 이 강제한다

- **status**: `accepted`
- **결정**: 사용자가 스킬을 부르지 않아도 에이전트가 맥락을 보고 제안이나 질문을 내거나 침묵하는 실행을 「먼저 살펴보기」 라 부른다. 코드 이름은 `proactive_check`, 패키지는 `proactive` 다.

  **한 번의 살펴보기는 그 사용자와 에이전트의 「점검 대화」 에서 도는 turn 하나다.**
  점검 대화는 `conversation.purpose = CHECK` 인 대화이고 사용자와 에이전트마다 지우지 않은 것 하나를 이어 쓴다.
  없거나 사용자가 지웠으면 다음 살펴보기가 새로 만든다.
  결과가 그 대화에 남아 사용자가 바로 이어서 논의한다.

  **분야는 지침으로만 늘린다.** 에이전트에 이름이 `proactive-check` 인 스킬이 켜져 있으면 그 에이전트는 살펴보기를 할 수 있다.
  살펴보기 turn 은 그 스킬을 읽고 따르라는 입력으로 돈다. 사용자는 스킬을 부르지 않는다.
  커리어 지침은 커리어 패키지가 그 이름의 스킬로 소유하고, Control Plane 은 권한과 실행과 대화 통합만 맡는다.

  **깨우는 길은 `ProactiveCheckService.start` 하나다.** 지금은 화면의 「지금 살펴보기」 단추만 부른다(`trigger = MANUAL`).
  매일 깨우기는 같은 진입점을 `SCHEDULED` 로 부르게 된다. 아래 「다음 단계」 가 남은 것을 적는다.

  **버튼으로 연 살펴보기는 turn 자리다**([ADR-069](ADR-069-사용자-전체-실행-한도는-turn-자리와-실행-줄을-사용자-잠금-하나에서-센다.md)).
  사용자가 누른 것이라 자리가 없으면 기다리지 않고 `USER_BUSY` 로, 점검 대화에 도는 turn 이 있으면 `CONVERSATION_BUSY` 로 곧바로 거절한다.

  **이 실행은 읽기만 한다.** 관리자가 에이전트마다 쓰기 도구를 허용하면 그 에이전트는 [ADR-082](ADR-082-먼저-살펴보기의-쓰기-도구는-관리자가-에이전트마다-켜고-커넥터-쓰기는-승인-카드로-보낸다.md) 의 경계를 따른다. 실행마다 Hermes toolset 을 줄일 수 없으므로 경계를 네 곳에 둔다.

  | 경계 | 막는 것 |
  | --- | --- |
  | 시작 전 점검 | 에이전트의 켜진 toolset 이 `web`, `vision`, `todo`, `skills` 와 Control Plane MCP 밖이면 시작하지 않는다. 화면이 끌 toolset 이름을 보인다 |
  | 커넥터 도구 판정 | 살펴보기 트리 안의 커넥터 호출은 위험도가 `READ` 이고 승인 방식이 `none` 인 도구만 허용하고, 나머지는 `READ_ONLY_RUN` 으로 거절한다. 상시 허락이 있어도 쓰기는 거절하고 승인 줄을 만들지 않는다 |
  | Control Plane MCP | 살펴보기 트리 안에서는 `memory_read`, `agent_list`, `agent_delegate`, `agent_status`, `agent_stop` 만 받는다. `artifact_write` 는 거절한다 |
  | 위임 | 맡길 수 있는 곳은 요청자의 커넥터 에이전트뿐이고, 한 번의 살펴보기에서 맡기는 수에 상한을 둔다 |

  `skills` toolset 에 함께 든 `skill_manage` 는 fos-ctx 의 `pre_tool_call` 이 이미 모든 실행에서 막는다.

  **살펴보기 트리만 위임 결과를 한 turn 안에서 기다린다.** `agent_status` 의 `wait_seconds` 는 살펴보기 트리에서만 기다린다. 살펴보기는 끝난 뒤 자동 turn 을 열지 않으므로 [ADR-040](ADR-040-위임-결과는-control-plane-이-부모-대화의-다음-turn-을-열어-전한다.md) 의 「부모는 기다리지 않는다」 의 예외다. 기다리는 동안 같은 profile 의 다른 MCP 호출이 기다린다([`hermes/fos-ctx.md`](../hermes/fos-ctx.md)). 그 밖의 실행은 ADR-040 그대로다.

  **한 번의 살펴보기에 상한 셋을 강제한다.** 시간과 도구 호출 수는 Control Plane 이 넘는 순간 그 turn 을 중지하고, 위임 수는 맡길 때 거절한다.
  값은 `assistant.proactive-check` 설정이 갖는다. 사용량과 비용은 기존 실행 줄에 그대로 남고, 살펴보기 한 번의 상태와 셈은 `proactive_check` 에 남는다.

  **살펴보기가 끝나면 그 트리의 위임 결과로 자동 turn 을 열지 않는다.**
  끝날 때 도는 자식을 멈추고, 그 트리의 위임 결과를 전했다고 적는다.
  자동 turn 은 이 경계 밖에서 도는 보통 turn 이라, 열면 읽기 경계가 끝난 뒤의 turn 에서 사라진다.

  **살펴보기는 지난 결과와 사용자의 반응을 읽고 시작한다.**
  Memory 문맥(보통 turn 과 같다), 점검 대화의 session, 최근에 알린 발견과 그 뒤의 사용자 메시지 수, 지난 살펴보기 뒤의 변화 신호를 싣는다.
  변화 신호는 Memory 문맥의 해시가 지난 살펴보기와 같은지, 지난 살펴보기 뒤 사용자가 보낸 메시지 수, 지난 살펴보기 시각이다.
  바뀐 것이 없고 새 후보도 없으면 조사를 줄이고 `NOTHING_NEW` 로 끝내라고 지시한다. 사람이 누른 살펴보기는 모델을 건너뛰지 않는다.
  사용자가 점검 대화에서 밝힌 지속적인 선호나 거절은 그 turn 의 기존 Memory 제안과 수락 경로로 남긴다([ADR-012](ADR-012-memory-는-사람이-승인한-것만-남는다.md)). 새 기억 층을 두지 않고, 답하지 않은 것을 선호로 남기지 않는다.

  **점검 대화의 Hermes session 은 살펴보기 횟수로 바꾼다.**
  같은 session 으로 돈 살펴보기가 `session-max-checks`(기본 14)에 닿으면 다음 살펴보기는 새 session 으로 시작한다.
  session 이 바뀌어도 지난 결과를 다시 알리지 않도록, 살펴보기마다 최근에 알린 발견의 제목과 원문 주소를 입력에 싣는다.
  한 session 안에서 문맥이 커지는 것은 Hermes 의 압축 교체가 맡는다.

- **맥락**: 지금까지 에이전트는 사용자가 묻거나 스킬을 불러야 움직였다.
  사용자는 에이전트가 자기 맥락을 보고 할 일을 먼저 제시하는 비서를 원한다(#165). 첫 분야는 커리어다.
  `/v1/runs` 는 toolset 을 받지 않고 toolset 은 profile 설정이다([`hermes/runs-api.md`](../hermes/runs-api.md), [`hermes/tools-and-skills.md`](../hermes/tools-and-skills.md)).
  그래서 「이 실행에서만 쓰기 도구를 뺀다」 는 Hermes 에서 할 수 없다.
  내장 `delegate_task` 의 자식은 Control Plane 이 세지 못해([ADR-062](ADR-062-native-하위-에이전트-사용량은-재조회-작업-줄을-원장으로-넓혀-합계에-더한다.md)) 위임 상한을 강제할 수 없다.
  먼저 알리기([ADR-072](ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md))는 판정이 실행을 시작하지 않는다고 정했다. 이 결정은 사람이 누른 실행만 연다. 사람 확인 없이 여는 실행은 매일 깨우기에서 다시 정한다.
  맥락을 기억해 다음 제안에 반영하지 않으면 같은 제안을 되풀이하며 토큰만 쓴다(2026-10-04 사용자 원칙). 그래서 지난 결과와 사용자의 반응과 변화 신호를 살펴보기마다 싣는다.
- **대안 기각**:
  - **누를 때마다 새 대화를 만든다.** 단순하지만 모델이 지난번에 알린 것을 모르고, 매일 깨우기가 붙으면 대화 목록이 쌓인다.
  - **지금 보던 대화 안에서 돌린다.** 매일 깨우기 때 어느 대화에 둘지 다시 정해야 하고, 일반 대화의 맥락이 살펴보기 입력에 섞인다.
  - **대화 없이 실행만 돌리고 결과를 따로 둔다.** 결과를 이어서 논의할 자리가 없다. 할 일 제안 도구([ADR-073](ADR-073-할-일은-에이전트가-제안하고-사람이-받아들인-것만-챙긴다.md))는 대화가 없는 실행을 거절한다.
  - **toolset 을 살펴보기 동안 바꿨다가 되돌린다.** profile 설정이라 같은 profile 의 다른 실행에도 걸린다. 되돌리기 전에 실패하면 설정이 남는다.
  - **커넥터 manifest 에 일반 에이전트용 지침 칸(`agent_skills`)을 둔다.** 패키지와 지침이 어긋나지 않지만 대시보드 plugin, Control Plane, 커리어 패키지를 함께 고쳐야 한다. 다음 단계로 둔다.
  - **백그라운드 실행 줄로 센다.** 사람이 누른 실행을 예비 자리 때문에 조용히 건너뛰면 단추가 아무 일도 하지 않은 것처럼 보인다.
- **결과**:
  - 얻는 것: 분야를 더하는 일이 그 분야의 에이전트에 `proactive-check` 스킬을 두는 것으로 끝난다.
    읽기 경계가 모델의 판단이 아니라 시작 전 점검과 판정 자리에서 지켜진다. 검색 결과의 글이 모델을 속여도 쓰기와 외부 연락이 나가지 않는다.
  - 감당할 것: 살펴보기를 쓰는 에이전트는 허용된 toolset 만 켜 두어야 한다. 셸이나 브라우저를 쓰는 에이전트는 살펴보기 전용 에이전트를 따로 둔다.
    개인 이력 원문을 검색어로 보내지 않는다는 규칙은 지침과 Control Plane 지시로만 지킨다. 내장 `web` 도구의 인자를 Control Plane 이 호출 전에 보지 못한다.
    시간 상한은 `hermes.run-timeout` 보다 짧아야 한다. 길게 두려면 두 값을 함께 올린다.
- **다음 단계**:
  - **매일 깨우기.** 사용자가 에이전트마다 켜고 끄며 시각과 시간대를 고르는 설정이다. 기본은 꺼짐이다(#166).
    깨우는 시각은 예약 작업([ADR-076](ADR-076-예약-작업은-control-plane-이-갖고-발화한-실행은-대화-turn-경로로-돈다.md))의 시각 trigger 를 다시 쓴다. 예약 작업은 지금 대화 turn 을 여는 것만 하므로, 발화가 `ProactiveCheckService.start` 를 `SCHEDULED` 로 부르는 종류를 더한다. 아래를 함께 정한다.
    - 설정은 에이전트 상세의 「먼저 살펴보기」 절에 켜기, 시각과 시간대, 다음 실행, 마지막 결과로 둔다. 그 절은 지금 단추와 마지막 결과만 그린다
    - 중복 억제: 마지막 살펴보기 뒤로 정한 시간이 지나지 않았거나, 지난 결과를 사용자가 아직 열지 않았으면 건너뛴다
    - 짧게 끝내기: 변화 신호가 모두 그대로이고 분야의 새 후보도 없으면 모델을 돌리지 않고 `proactive_check` 줄만 남긴다
    - 조용한 시간: 그 시간에는 깨우지 않고 다음 시각으로 미룬다
    - 결과가 쌓이지 않게 하는 규칙: `NOTHING_NEW` 는 대화에 아무것도 남기지 않고 `proactive_check` 줄만 남긴다
    - 자리: 사람이 누르지 않은 실행이라 `USER_BUSY` 면 거절 대신 뒤로 미룬다. 백그라운드 예비 자리를 쓸지 정한다
    - 먼저 알리기([ADR-072](ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md))에 살펴보기 결과의 trigger 를 더해 지금 화면([ADR-074](ADR-074-지금-화면은-원래-기록을-읽어-만든-view-이고-정해진-카드-넷만-그린다.md))에 잇는다
  - **비용과 효과 요약.** 관리자 영역에 살펴보기마다의 트리 비용, 「새로 알릴 것」 하나당 비용, 받아들인 제안 수를 보인다. 받아들인 수는 할 일([ADR-073](ADR-073-할-일은-에이전트가-제안하고-사람이-받아들인-것만-챙긴다.md))이 구현된 뒤 그 줄로 센다
  - **커넥터 manifest 의 `agent_skills`.** 커넥터 plugin 이 일반 에이전트용 `proactive-check` 스킬을 선언하고 Control Plane 이 게시한다.
  - **할 일 제안.** 할 일의 `follow_up_propose` 가 들어오면 「할 일 후보」 를 그 도구로 제안하게 한다. 점검 대화가 있어 대화 없는 실행의 거절에 걸리지 않는다.
- **적용 범위**: `proactive` 패키지, `ChatService` 의 살펴보기 turn, 커넥터 도구 판정, Control Plane MCP, `agent_delegate`. 흐름은 [`backend/proactive-check.md`](../backend/proactive-check.md) 가 갖는다.
