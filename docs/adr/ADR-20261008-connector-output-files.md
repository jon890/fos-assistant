## ADR-20261008: 커넥터는 계산할 목록을 그 에이전트 실행 공간에 읽기 전용으로 붙는 파일로 내고, 계산은 스크립트가 한다

- **status**: `accepted`
- Date: 2026-10-08
- [ADR-086](ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 의 실행 공간에 커넥터 출력 디렉터리 하나를 더 붙인다. 경로를 설치가 정하는 방식은 [ADR-20261007 / connector-owner-attachments](ADR-20261007-connector-owner-attachments.md) 를 따른다.

### 결정

**합계와 통계 같은 계산은 집계 도구를 따로 두지 않는다. 커넥터의 목록 도구가 기간 전체를 파일로 쓰고 경로만 돌려주며, 모델은 `execute_code` 스크립트로 그 파일을 읽어 계산한다.**

| 항목 | 정한 것 |
| --- | --- |
| 선언 | `connector.json` 의 `owner_output_env` 에 env 이름 하나. `fields[].env`, `operator_env`, `owner_attachments_env` 와 겹치지 않는다. `.mcp.json` 의 서버 env 는 네 이름의 합과 같다 |
| 출력 루트 | 실행 공간 정책의 선택 키 `connector_output_root`. Docker 호스트와 Hermes 컨테이너에서 같은 절대 경로다 |
| 값 | 바인딩 설치가 `<connector_output_root>/users/<SHA-256(sandbox_owner)>/<profile>/<커넥터 id>` 를 만들고 서버 정의에 직접 넣는다. 모델, 요청 본문, manifest 는 경로를 정하지 못한다 |
| 값이 비는 경우 | 정책이 없거나, 그 키가 없거나, profile 이 정책에 등록되지 않았거나, `sandbox_owner` 가 없거나, 디렉터리를 링크 없이 만들지 못하면 빈 값이다. 붙이기는 막지 않는다. 커넥터는 파일 출력만 거절한다 |
| 실행 공간 | 그 키가 있으면 셸 저장이 `<connector_output_root>/users/<SHA-256(sandbox_owner)>/<profile>` 을 **같은 경로에 읽기 전용으로** 붙인다. 커넥터가 쓴 경로를 그대로 스크립트가 연다 |
| 볼 수 있는 범위 | profile 하나. 그 커넥터를 붙인 에이전트의 실행 공간만 본다. 같은 사용자의 다른 에이전트도 보지 못한다 |
| 승인 실행과 확인 도구 | 빈 값을 준다. 파일 출력은 승인 없이 도는 읽기 도구만 쓴다 |
| 떼기 | 설치한 그 디렉터리를 지운다. 에이전트를 지우면 바인딩을 모두 뗀 뒤 지우므로 함께 지워진다 |
| 수명 | 커넥터가 쓸 때마다 자기 디렉터리에서 24시간 지난 파일을 지운다. 다시 쓰지 않는 커넥터의 파일은 운영의 정기 정리가 24시간 뒤 지운다 |
| 목록 도구 | 도구를 늘리지 않는다. 기존 목록 도구에 `output: "file"` 같은 선택 칸을 두고, 결과로 경로, 건수, 기간, 칸 목록만 돌려준다 |
| 스킬 | 합계와 통계는 목록을 받아 스크립트로 계산한다. 모델이 직접 더한 값으로 답하지 않는다 |

### 맥락

사용자는 집계 도구를 늘리지 않고, 목록을 받아 격리된 환경의 스크립트로 계산하기로 정했다(2026-10-08).
가계부 한 달 지출은 70~126건이고 항목 하나가 약 530자라 한 달 목록이 약 67,000자다.
모델이 받은 목록을 코드에 옮겨 적으면 출력 토큰이 그만큼 더 들고 옮기다 틀린다.

사용자는 먼저 스크립트가 커넥터 도구를 직접 부르는 길을 골랐다. 운영 이미지(`v2026.9.24`)의 `execute_code` 는 이것을 지원하지 않는다.

- 스크립트가 RPC 로 부를 수 있는 도구는 `SANDBOX_ALLOWED_TOOLS` 일곱 개(`web_search`, `web_extract`, `read_file`, `write_file`, `search_files`, `patch`, `terminal`)로 고정이다(`tools/code_execution_tool.py`)
- RPC 처리기는 목록 밖 이름을 거절한다(`tools/code_execution_rpc.py` 의 `_handle_rpc_request`). docker 실행 공간의 원격 커널도 같은 목록으로 스텁을 만든다
- 목록이 모듈 상수라 늘리려면 core 를 고치거나 plugin 이 그 값을 바꿔야 한다([ADR-001](ADR-001-hermes를-런타임으로-두고-core를-고치지-않는다.md))

Hermes 는 50,000자를 넘는 MCP 결과를 profile 의 `cache/spillover` 에 저장하고 실행 공간에 읽기 전용으로 붙인다(`tools/tool_result_storage.py`).
그러나 그 turn 에 실행 공간 연결이 아직 없으면 Hermes 쪽 경로를 돌려준다. 목록을 먼저 부르고 계산하는 흔한 순서에서 그 경로는 실행 공간에서 열리지 않는다.
50,000자보다 작은 페이지는 그대로 모델에 들어간다.

### 대안 기각

- **스크립트가 커넥터 도구를 직접 부른다**: 위처럼 core 를 고쳐야 한다. 스크립트가 서비스 API 를 직접 부르게 하려면 커넥터 토큰을 실행 공간에 넣어야 해 ADR-086 의 경계를 깬다.
- **커넥터가 사용자의 `/workspace` 에 쓴다**: 같은 사용자의 모든 에이전트가 본다. 실행 공간이 쓸 수 있는 곳이라 셸이 링크를 바꿔 끼우면 실행 공간 밖에서 도는 커넥터의 쓰기가 다른 곳으로 간다. 그 방어를 커넥터마다 떠맡아야 한다.
- **Hermes 의 큰 결과 저장에 맡긴다**: 실행 공간 연결이 없을 때 열리지 않는 경로를 주고, 작은 결과는 그대로 모델에 들어간다.
- **목록 도구가 필요한 칸만 간결하게 돌려주고 모델이 옮겨 적는다**: 한 달 126건을 간결 형식으로 받아도 약 15,000자다. 같은 양을 코드로 다시 써야 해 출력 토큰과 지연이 늘고, 옮기다 틀린 값을 검증할 길이 없다.
- **집계 도구를 남긴다**: 사용자가 기각했다. 기준(사람, 키워드, 요일)이 늘 때마다 도구나 인자가 늘어난다.

### 결과

- 얻는 것:
  - 계산이 정수 산술로 정확하고, 기준을 새로 정해도 도구를 늘리지 않는다.
  - 모델 문맥에는 경로와 건수, 기간만 들어간다. 한 달 목록이 수만 자에서 수백 자가 된다.
  - 실행 공간이 그 디렉터리를 쓰지 못하므로 링크를 바꿔 끼워 커넥터의 쓰기를 돌릴 수 없다.
- 감당할 것:
  - 커넥터가 읽은 데이터가 그 에이전트의 실행 공간에 파일로 남는다. 24시간 뒤 정리는 커넥터의 다음 쓰기와 운영의 정기 정리에 기댄다. 실행 공간은 인터넷이 열려 있어 스크립트가 파일을 밖으로 보낼 수 있다. 모델이 받은 목록을 셸로 보내는 것과 같은 범위다.
  - 계산하려면 그 에이전트에 `code_execution` 이 켜져 있어야 하고 profile 이 실행 공간 정책에 등록돼 있어야 한다. 셸이 없는 에이전트는 합계를 답하지 못하고 그렇다고 말한다.
  - 정책에 키를 넣으면 셸 설정 지문이 바뀌어 다음 셸 저장에서 새 컨테이너가 생긴다. 옛 컨테이너 정리와 Docker socket proxy 의 bind 허용은 운영이 한다.
  - 정책에 키를 넣기 전에 붙인 커넥터는 빈 값을 갖는다. 연결 확인이나 반영 완료로 다시 설치해야 값이 들어간다.
  - Hermes 를 올릴 때 `SANDBOX_ALLOWED_TOOLS` 를 다시 본다. 커넥터 도구를 스크립트에서 부를 수 있게 되면 이 결정을 다시 검토한다.

- **적용 범위**: 대시보드 plugin 의 실행 공간 정책 검증, 셸 저장의 마운트, manifest 검증, 바인딩 설치와 떼기, 확인 도구와 승인 실행의 env. 계약은 [`hermes/README.md`](../../hermes/README.md) 의 「셸 실행 공간」, [커넥터 연결](../connectors.md) 의 「connector.json」, 만드는 쪽의 규칙은 [커넥터 만들기](../connector-authoring.md) 가 갖는다.
