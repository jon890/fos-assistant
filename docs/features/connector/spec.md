# 연결 반영을 사람이 확인하지 않아도 끝나게 한다

확인: 2026-11-20

## 목표

플러그인을 에이전트에 붙이거나 연결 값을 바꾸면, 관리자가 공유 gateway 를 재시작하고 「반영 완료」 를 누르지 않아도 몇 분 안에 그 에이전트에서 도구를 쓸 수 있다.
관리자 「반영 완료」 는 자동 반영이 실패했을 때만 쓰는 비상 수단으로 남는다.

## 범위

이번 범위는 지금 「재시작 대기」(`restart_required`, `plugin_updated`)가 되는 바인딩이다.
지금 동작과 남은 수동 단계는 [플러그인 연결](../connector.md) 의 「바인딩의 반영 맞추기」, 「관리자 반영 완료」, 「재시작」 과 [ADR-20261007 / connector-live-reload](../../adr/ADR-20261007-connector-live-reload.md) 가 갖는다.

| 재시작 대기가 되는 까닭 | 이번 변경 뒤 |
| --- | --- |
| 이미 있던 서버의 정의나 `.env` 값이 바뀌었다(값 교체, manifest 가 바뀐 뒤의 재설치) | 그 profile 의 그 서버만 한 주기 껐다 켜서 반영한다. 공유 gateway 를 재시작하지 않는다 |
| 뗀 기록에 남은 이름을 다시 붙였다 | 같다 |
| `fos-ctx` plugin 파일이 바뀌었다(`plugin_updated`) | 공유 gateway 가 다시 뜬 것을 Control Plane 이 알아채고 스스로 반영 맞추기를 돌린다. 재시작은 운영의 배포 단계와 정기 작업이 한다 |

범위 밖:

- Hermes core 를 고치는 것. profile, API server, plugin hook 만 쓴다(ADR-001)
- 사용자 요청에서 공유 gateway 를 재시작하는 것. 지금처럼 하지 않는다
- 새 이름 붙이기와 스킬만 바뀐 설치. 지금도 반영 예정 확인으로 자동이다
- 운영 저장소의 재시작 스크립트와 정기 작업 구현. 이 저장소는 그 작업이 쓸 조회와 계약만 만들고, 운영 쪽 변경은 `fos-home-infra` 요청 본문으로 넘긴다
- 옛 커넥터 에이전트의 설치(`mode: bind` 가 아닌 것)

## 도메인 규칙 변경

도메인 규칙 변경 없음: 바인딩 상태(`READY`, `PENDING`)의 뜻과 도구 허용 조건은 그대로이고, `PENDING` 에서 `READY` 로 가는 경로만 자동으로 바뀐다.
