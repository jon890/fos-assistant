# 서버 비밀값을 데이터베이스에 암호화해 두고 관리자 화면에서 바꾸기

확인: 2026-11-20

## 목표

관리자가 서버 비밀값을 홈서버 파일을 고치지 않고 관리자 화면에서 넣고 바꾸며, 바꾼 값이 다시 배포하지 않아도 반영된다.

지금 Control Plane 과 Hermes 의 비밀값은 홈서버 파일과 환경 변수에 있다([`code-architecture.md`](../../code-architecture.md) 의 「비밀값을 두는 곳」).
값을 넣거나 바꿀 때마다 홈서버에 들어가 파일을 만들고 컨테이너를 다시 띄워야 한다. 웹 푸시의 VAPID 비밀 키를 파일로 두려던 운영 변경은 머지 전에 홈서버 디렉터리부터 만들어야 했다.
사용자 본문은 이미 KEK 로 감싼 데이터 key 로 암호화한다([ADR-20261008 / data-encryption](../../../backend/docs/adr/ADR-20261008-data-encryption.md)). 이 기능은 같은 KEK 로 서버 비밀값도 암호화해 데이터베이스에 둔다.

## 범위

**옮기는 값**

| 값 | 지금 | 옮긴 뒤 | PR |
| --- | --- | --- | --- |
| 웹 푸시 VAPID 키(비밀 키와 공개 키)와 연락처 | 비밀 키 파일 경로와 공개 키, 연락처 환경 변수(웹 푸시 PR #817 의 설정) | 데이터베이스. 화면에서 서버가 새로 만든다 | PR1 |
| 브라우저 중계 서명 비밀 | Control Plane 환경 변수 | 데이터베이스. 화면에서 서버가 새로 만든다 | PR1 |
| profile API key | profile 마다 홈서버 파일 하나 | 데이터베이스. Control Plane 이 profile 을 만들 때 만들고 사람이 다루지 않는다 | PR2 |
| provider API key | profile `.env` 의 공급자 key 한 줄 | 데이터베이스에 공급자마다 여러 개. Hermes 의 공급자별 credential 목록에 맞춰 넣어 돌려 쓴다 | PR3 |

**파일과 환경 변수에 남기는 값**

| 값 | 남기는 까닭 |
| --- | --- |
| KEK | 데이터베이스의 비밀값을 푸는 key 다. 데이터베이스와 백업에 두지 않는다 |
| 데이터베이스 비밀번호 | 데이터베이스를 열기 전에 필요하다 |
| 웹과 Control Plane 이 나눠 가지는 HMAC 비밀값, 웹 로그인 비밀값 | 웹은 데이터베이스를 읽지 않고 이 값으로 Control Plane 을 부른다 |
| Hermes 대시보드 토큰 | Control Plane 이 Hermes 로 값을 써 주는 통로 자체를 여는 값이다 |
| 플러그인 보관 파일 key | Control Plane KEK 와 일부러 나눈 key 다([ADR-20261103 / connector-vault-key](../../../hermes/docs/adr/ADR-20261103-connector-vault-key.md)) |
| 금융 해시 key | 바꾸면 기존 해시가 모두 어긋나 바꿀 일이 없다 |
| 구독 로그인(OAuth `auth.json`) | 사람이 브라우저로 로그인해 Hermes 가 만드는 파일이다 |

**범위 밖**

- 플러그인 연결의 칸 값. 이미 사용자가 「외부 서비스 연결」 화면에서 넣고 Hermes 보관 파일에 암호화돼 있다
- 자기 계정을 쓰는(`DEDICATED`) 에이전트의 provider key. 이 기능은 그룹이 함께 쓰는 Hermes 루트 목록만 다룬다
- 비밀값의 바꾼 이력 화면과 이력 테이블. 마지막으로 바꾼 사람과 시각만 둔다
- 저장한 원문을 다시 보이는 것
- 클라우드 KMS. KEK 는 지금처럼 홈서버 파일이다

| REQ13 | Control Plane 은 데이터베이스의 key 들을 Hermes 루트의 그 공급자 credential 목록에 맞춰 넣는다. 함께 쓰는(`SHARED_HOUSEHOLD`) 모든 에이전트가 다음 실행부터 쓴다. 맞춰 넣기에 실패하면 화면에 「Hermes 에 반영되지 않았어요」 와 「다시 시도」 를 보이고, 성공할 때까지 화면을 다시 열어도 남는다. | REQ19 | PR3 이 처음 기동할 때 함께 쓰는(`SHARED_HOUSEHOLD`) profile 의 `.env` 에서 provider key 줄을 모두 지운다. 지운 공급자와 줄 수를 로그에 남긴다. 지운 뒤 화면에서 넣은 key 도 구독 로그인도 없는 공급자는 화면의 그 공급자 줄에 「옛 key 를 지웠어요. 여기서 key 를 넣어 주세요」 를 보인다 (PR3) | 배포 뒤 함께 쓰는 profile 의 `.env` 에 provider key 줄이 없고, 로그의 줄 수가 지운 수와 같다. key 가 없는 공급자 줄에 안내가 보인다 |
| REQ15 | key 마다 상태(사용 가능, 막힘과 풀리는 시각, 인증 실패)와 마지막으로 쓴 때를 보인다. 상태는 화면을 열 때 Hermes 에서 읽고, 읽지 못하면 그 칸만 「상태를 읽지 못했어요」 를 보인다 (PR3) | 막힌 key 에 「막힘」 과 풀리는 시각이 보인다. Hermes 대시보드를 멈추면 상태 칸만 「상태를 읽지 못했어요」 이고 별칭과 앞부분은 보인다 |
| REQ16 | 막힌 key 의 「다시 쓰기」 는 Hermes 의 그 key 막힘을 푼다 (PR3) | 「다시 쓰기」 를 누르면 그 key 가 「사용 가능」 이 되고 다음 실행에서 쓰인다 |
| REQ17 | 공급자에 넣은 새 key 가 Hermes 에 반영되거나 「다시 쓰기」 로 막힘을 풀면 Control Plane 의 그 공급자 막힘 기록(`provider_state`)도 지운다. 반영에 실패하면 지우지 않는다. 그 기록의 뜻(그 공급자의 계정이 전부 막힘)은 바꾸지 않는다 (PR3) | 공급자가 막혀 다른 모델로 넘어가던 중에 새 key 를 넣으면 다음 실행이 그 공급자로 간다 |
