# 비서 답변 품질: 최신 정보 검색과 출처, 조사 진행 표시, 맥락 유지

확인: 2026-11-20

처음 확인은 2026-11-18 이고, 2026-11-20 확인은 「답 모양」 요구를 더한 것이다.

확인 뒤 2026-11-18 에 사용자 결정으로 고친 것: 검색 서비스를 평가로 비교해 정한다(DECISION2), 지침을 한 벌의 글로 모든 대화 에이전트에 넣는다(DECISION9, DECISION14), 「오늘 날짜」 문항을 날짜로 따로 본다(DECISION10).

2026-11-20 에 「답 모양」 요구(REQ15부터 REQ20, DECISION20부터 DECISION30)를 더했다. 운영 답에서 출처가 한 덩어리로 보이고 제목이 본문과 같은 크기로 보인 것을 사용자가 짚었다(「채팅 응답 화면도 품질에 많은 영향을 미친다」, 「ChatGPT 와 비슷하게, 문단을 잘 나누고 제목, 표, Mermaid 다이어그램을 적극 활용하라」).

2026-11-21 에 사용자가 정한 지침 변경(DECISION31부터 DECISION34)을 결정 표에 더했다. 확인을 마치고 답하기, 판단 질문의 답 구조, 검색을 함께 부르기, 검색 서비스 한도다.

## 목표

가족이 최신 정보, 쇼핑·가격 비교, 여행·장소, 생활 지식을 물었을 때 비서가 검색해서 확인한 내용으로 답하고 출처 링크를 붙인다.
조사가 길어지면 찾은 것과 지금 하는 일을 중간에 보이고, 앞에서 한 말과 기억해 둔 사정을 잊지 않는다(사용자 2026-11-17, 2026-11-18).

됐다고 볼 기준(사용자 2026-11-18): 같은 질문을 ChatGPT 와 나란히 물어 비슷하다, 답에 출처 링크가 붙는다, 최신 정보 질문에 틀리지 않는다.
감수하는 것(사용자 2026-11-18): 조사형 질문은 몇 분 걸려도 된다, 구독 토큰을 더 써도 된다.

## 요구사항과 인수 조건

지침은 사용자 대화에서 시작된 실행(루트 실행과 Control Plane 이 맡긴 자식 실행)에 에이전트의 도구와 상관없이 같은 글로 넣는다. 「검색 도구가 켜진 실행」 은 그중 에이전트에 `web` toolset 이 켜진 것이다. 먼저 살펴보기와 예약 작업의 실행은 이 스펙으로 지침이 바뀌지 않는다(DECISION14). Hermes 가 스스로 띄운 하위 작업은 Control Plane 의 지침을 받지 않아 들지 않는다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 바뀌는 사실을 묻는 질문에는 검색해서 답한다 | 대화 실행의 지침에 「`web_search` 도구가 있으면 가격, 재고, 영업시간, 일정, 뉴스, 시세, 제품 사양과 출시, 제도와 법, 그 밖에 시간이 지나면 바뀌는 사실은 기억으로 답하지 않고 검색해 확인한다. 일반 상식, 글쓰기, 사용자의 개인 사정만으로 답할 수 있는 질문은 검색하지 않는다」 가 든다. 평가 세트의 검색이 필요한 질문의 답에 「출처」 링크가 붙는다. 지금 무료 서비스로 돌 때는 실행 사건에 `web_search` 도 한 번 이상 남는다. 지침은 도구가 켜졌는지에 따라 나눠 넣지 않는다(DECISION14) |
| REQ2 | 실행이 오늘 날짜를 안다 | 대화 turn 의 지침에 그 turn 을 시작한 날의 날짜와 요일(한국 시간)이 든다. 평가 세트의 「오늘 날짜」 질문에 검색 없이 그날 날짜로 답하고, 평가는 이 문항을 출처가 아니라 날짜가 맞는지로 본다. 날짜를 넣어도 같은 날 같은 기억이면 실행 기록의 지침 지문(`instructions_hash`)이 지금과 같은 뜻(공통 답변 지침과 Memory)을 유지한다 |
| REQ3 | 검색으로 확인한 내용에는 출처 링크를 붙인다 | 검색 결과를 쓴 답은 확인한 문장 옆에 마크다운 링크를 달고 답 끝에 「출처」 목록(제목과 링크)을 둔다. 「출처」 목록에는 `web_search` 와 `web_extract` 가 돌려준 주소만 쓰고 지어내지 않는다. 검색하지 않은 답에는 「출처」 목록이 없다. 플러그인이 돌려준 주소(상품 링크 등)와 사용자가 준 주소는 지금처럼 본문에 링크로 쓸 수 있고 「출처」 목록을 만들지 않는다. 답 아래의 원문 열람 목록은 그대로 둔다(DECISION16). 평가 세트에서 검색을 부른 답은 「출처」 목록에 링크가 하나 이상 있고 그 링크가 열린다 |
| REQ4 | 검색하지 못했으면 그 사실을 밝힌다 | 검색 도구가 켜진 실행에서 바뀌는 사실을 물었는데 검색이 실패했거나 결과가 없으면, 답 첫머리에 「검색으로 확인하지 못했다」 와 아는 정보의 기준 시점을 밝힌 뒤 아는 만큼 답한다. 검색 도구가 꺼진 에이전트도 같은 지침으로 바뀌는 사실은 확인하지 못했다고 밝힌다. 플러그인이나 브라우저 같은 다른 도구로 그 실행에서 확인한 사실에는 이 말을 붙이지 않는다(DECISION9) |
| REQ5 | 검색 서비스는 평가로 비교해 정하고, 페이지 본문 읽기가 실패하지 않는다 | 검색 서비스는 profile 설정 값 하나로 지금 무료 서비스와 OpenAI 내장 검색을 오간다. PR1 배포 뒤 평가 세트를 두 서비스로 각각 돌린 결과가 기능 파일에 숫자로 남고, DECISION10 의 기준에서 앞서는 쪽을 운영 profile 과 profile 틀의 값으로 둔다. 비슷하거나 내장 검색이 뒤지면 무료 서비스를 쓴다. 내장 검색을 쓰면 검색이 OpenAI 서버에서 돌아 검색어와 검색 횟수가 실행 사건에 남지 않고 화면에도 보이지 않는다(DECISION2). 어느 쪽이든 운영에서 `web_extract` 를 부른 평가 실행의 실패가 0 이다 |
| REQ6 | 모든 사용자의 기본 에이전트에 검색 도구가 켜져 있다 | 배포 뒤 모든 사용자의 기본 에이전트 도구 화면에서 `web` 이 켜져 있다. 기존 사용자의 것은 관리자가 에이전트 도구 화면에서 켠다(DECISION11). 역할 profile 과 사용자가 만든 에이전트의 도구는 바뀌지 않는다 |
| REQ7 | 품질 평가 세트를 운영에서 돌려 숫자를 낸다 | `test/model-eval/` 아래 평가가 아래 「평가 세트」 의 질문을 관리자 계정의 평가 전용 대화에서 운영 Control Plane 과 Hermes, 모델을 그대로 거쳐 돌리고, 질문마다 「출처」 링크 수, 열리는 링크 수, 걸린 시간, 실행 사건에 남은 검색과 본문 읽기 횟수를 표로 낸다. 「검색했는가」 는 두 검색 서비스를 같은 잣대로 보도록 답에 「출처」 링크가 붙었는지로 센다. CI 와 배포에서는 돌지 않는다. 고치기 전 기준값과 PR1 배포 뒤 값이 PR 본문이나 기능 파일에 숫자로 남는다. 사람 비교 8문항의 결과(비슷하다, 모자라다와 한 줄 까닭)를 사용자가 적을 자리가 평가 결과에 있다. PR1 은 배포 뒤 값이 DECISION10 의 기준을 넘어야 끝난 것이다. 못 미치면 고쳐 다시 돌린다 |
| REQ8 | 입력창에서 「깊이 조사」 를 골라 보낼 수 있다(PR2) | 검색 도구가 켜진 에이전트의 대화 입력창에 「깊이 조사」 단추가 보이고 휴대폰에서도 같다. 켜고 보낸 질문은 여러 출처를 찾아 교차 확인한 뒤 출처가 달린 보고서로 답한다. 고른 상태는 그 질문 하나에만 적용되고 다음 질문은 보통 답으로 돌아간다. REQ9 의 질문 카드에 답한 turn 은 같은 질문의 조사를 이어받는다. 답이 도는 중에는 단추를 켤 수 없고, 조사 답을 다시 생성하면 조사로 다시 돈다(DECISION18). 검색 도구가 꺼진 에이전트에서는 단추가 보이지 않고 API 도 거절한다. 모델 칸은 사용자가 고른 칸 그대로다 |
| REQ9 | 「깊이 조사」 는 조건이 모자라면 한 번만 되묻는다(PR2) | 조사에 필요한 조건(예산, 날짜, 지역처럼 결과를 크게 바꾸는 것)이 질문에 없으면 조사 전에 질문 카드로 한 번 묻는다. 답을 받으면 다시 묻지 않고 조사한다. 조건이 충분하면 묻지 않고 바로 조사한다. 사용자가 카드에 답하지 않고 입력창에 다른 글을 보내면 그 글은 보통 메시지로 돌고 조사는 시작하지 않는다. 카드에 건너뛰기 단추는 만들지 않는다(DECISION18) |

| REQ11 | 조사 중 찾은 것과 지금 하는 일이 보인다(PR2) | 검색 도구를 쓰는 실행이 도는 동안 작업 과정에 검색어, 읽은 사이트, 지금 단계 한 줄이 일어난 순서로 쌓인다. 내장 검색을 쓰는 동안에는 검색어가 오지 않아 읽은 사이트와 지금 단계, 중간 정리만 쌓인다. 읽은 사이트의 제목과 주소는 관리자가 아니어도 그 대화의 주인에게 보이고, 페이지 본문은 보이지 않는다(DECISION15). 지금 단계 한 줄은 비서가 건너뛰어도 보이도록 Control Plane 이 도구 사건에서 만든다. 「깊이 조사」 에서는 비서가 조사 중간에 「지금까지 찾은 것」 을 두세 줄로 정리한 글이 작업 과정에 올라온다. Hermes v0.23.2 에서도 보인다. 같은 대화를 연 다른 창과 휴대폰에도 보인다. 검색어, 읽은 사이트, 중간 정리는 실행 기록에 남아 답이 끝나거나 화면을 새로 고친 뒤에도 그 답의 접힌 작업 과정에서 다시 보인다. 새 테이블은 만들지 않는다(DECISION12) |

### 평가 세트

질문은 개인 사정이 없는 일반 질문이다. 날짜에 따라 정답이 바뀌므로 정답 글자를 심지 않고 검색 여부, 출처, 링크로 센다. ★ 는 사용자가 ChatGPT 와 나란히 보는 8문항이다.

「분수의 나눗셈」 과 「김치찌개」 는 검색하지 않아도 되는 질문이다. 검색 없이 답해도 통과이고, 불필요하게 오래 걸리지 않는지를 본다. 「오늘이 몇 월 며칠」 은 답에 그날 날짜가 들었는지로 본다. 나머지 열일곱 문항이 출처 기준의 대상이다.

### 배포 뒤 확인

확인할 것만 적는다. 실행 방법은 `fos-home-infra` 가 갖는다.

1. 모든 사용자의 기본 에이전트에 `web` 이 켜져 있다(REQ6)
2. 검색 한 번을 왕복시켜 답에 출처 링크가 붙는다(REQ3)
3. 평가 세트를 지금 무료 서비스와 내장 검색으로 각각 돌려 고치기 전 기준값과 비교한 숫자를 남기고, 앞서는 쪽을 운영 값으로 둔다(REQ5, REQ7)
4. 사용자가 ★ 8문항을 ChatGPT 와 나란히 보고 결과를 적는다(REQ7)
5. (PR2) 「깊이 조사」 한 번을 왕복시켜 되묻기, 조사 기록, 중간 정리, 10분 안의 보고서를 본다(REQ8~REQ11)
6. (PR3) 긴 대화 하나에서 압축이 실행 기록에 남는다(REQ12)
7. (PR5) 출처가 있는 답 하나를 넓은 화면과 휴대폰에서 보고, 같은 질문으로 답변 평가를 다시 돌려 형식 참고 칸을 본다(REQ15~REQ20)

| DECISION29 | 본문 모양과 Mermaid 가 드는 화면 | 마크다운 그리기를 함께 쓰는 세 화면(대화 답, 작업 과정 블록, 스킬 편집 미리보기). 작업 과정 블록만 글자 크기와 간격을 지금대로 둔다 | 작성자 | 사용자가 확인한 결정 블록이 「세 화면이 같은 규칙」 과 「작업 과정은 지금 크기 유지」 를 말했다. 화면마다 다른 규칙을 두면 같은 답이 화면마다 다르게 보인다 |
| DECISION30 | 형식 참고 칸을 세는 기준 | 문단은 빈 줄로 나뉜 원문 문단에서 목록, 표, 코드, 인용, 제목을 빼고 문장 끝(`.`, `?`, `!`)으로 센다. 같은 주소는 scheme 과 host 의 대소문자, 끝의 `/`, `#` 뒤를 무시하고 비교한다. 주소 노출은 코드 밖의 맨 주소와 링크 글자가 주소인 링크다 | 작성자 | 참고 칸이라 통과 기준에 들지 않는다(DECISION23). 평가 문항에는 사용자가 준 주소와 플러그인 주소가 없어 따로 빼지 않는다 |
| DECISION31 | 확인을 마치고 답하기 | 대화 실행의 공통 지침에 「확인을 마치고 답하기」 절을 더한다. 답하기 전에 무엇이 확인돼야 하는지 정하고, 근거가 없거나 하나뿐이면 반대 근거를 포함해 폭넓게 검색해 교차 확인한다. 도구로 확인할 수 있는 「미확인」 은 먼저 확인하러 간다. 「미확인」 은 답 하나에 한 번만 적고, 사용자만 줄 수 있는 사실은 하나만 묻는다. 맡긴 결과가 오면 합친 결론 하나로 답한다. 예약 작업과 먼저 살펴보기에는 넣지 않는다 | 사용자 2026-11-21 | 「근거를 찾을 수 없다면 최대한 웹 검색을 폭넓게 하여 여러 근거를 교차 분석해서 알려 줬으면 좋겠다. 이건 기본 시스템 프롬프트로 동작했으면 좋겠다」. 2026-11-21 쇼핑 대화에서 비서가 「재고·수입자·환불 조건 미확인」 을 다섯 답 내내 되풀이하고 확인하러 가지 않았다. 넣는 범위는 「최신 정보와 출처」 절과 같다(DECISION14) |
| DECISION32 | 판단을 묻는 질문의 답 구조 | 정품인지, 살 만한지 같은 판단 질문은 첫 줄에 판단과 확신 정도, 끝에 「현재 판단」 한 줄과 바로 할 행동 하나. 근거는 당사자와 관계없는 근거와 당사자 주장을 나눈 「항목 \| 확인 내용 \| 평가(확인·주장·미확인)」 표. 「셋 이상을 두 기준 이상으로 비교하면 표」 는 문장으로 이어 쓰고 싶을 때도 표로 쓰게 다듬는다. 모든 실행 공통 「답변 형식」 에 둔다 | 사용자 2026-11-21 | 같은 쇼핑 대화에서 판매처 4~5곳을 표 없이 문장으로 비교했다. 같은 질문에 ChatGPT 는 근거 약 9건을 날짜와 성격으로 나눈 표, 첫 줄 판단과 끝의 현재 판단으로 답했다. 답 모양 규칙이라 DECISION28 과 같은 자리다 |
| DECISION33 | 검색과 본문 읽기를 함께 부르기 | 서로 기대지 않는 검색은 한 차례에 5~8개 함께 부른다. 읽을 페이지도 주소마다 `web_extract` 를 따로 함께 부른다. `execute_code` 안에서 웹 도구를 반복문으로 부르지 않는다. 본문 읽기 제한 시간은 profile 틀의 `web.extract_timeout` 20초 | 사용자 2026-11-21 | Hermes v0.23.2 는 한 응답이 부른 도구를 최대 8개 동시에 돌린다. 운영의 최근 웹 도구 실행 43개는 차례당 평균 1.37개였고 응답 시간의 12% 만 검색이었다. 나머지 대부분은 모델 차례 왕복(4~9초)이다. key 없는 Exa 는 한 호출 안의 주소를 차례로 읽어 주소마다 따로 부른다. 한 페이지가 120초(Hermes 기본값)를 붙잡지 않게 제한 시간을 낮춘다. Hermes 는 이 제한을 첫 서비스에만 걸어, key 를 넣은 뒤 key 서비스가 시간 초과되면 무료 등급으로 다시 해 보는 시간이 더해진다(작성자 2026-11-21, DECISION34 의 다시 해 보기를 지키려고 그대로 둔다) |
| DECISION34 | 검색 서비스 429 한도 | key 없는 무료 등급의 한도를 넘으려고 유료 key 를 받을 자리를 마련한다. key 는 profile 의 `.env` 나 Hermes 의 관리용 `.env` 에 운영이 넣고 저장소와 Control Plane 데이터베이스에는 두지 않는다. 서비스를 고르는 값은 계속 비워 Hermes 자동 선택(key 가 있는 서비스 먼저)을 따르고, key 로 부른 호출이 실패하면 그 호출만 무료 등급으로 다시 해 본다(`web.keyless_rescue`) | 사용자 2026-11-21 | 「검색 서비스의 429 한도는 크게 늘린다」. Hermes 는 profile 마다 실행 범위를 따로 두어 프로세스 환경 변수의 key 를 보지 않는다([`hermes-contract.md`](../../../hermes/docs/hermes-contract.md#웹-검색-서비스)). 관리용 `.env` 는 모든 profile 에 덮어 적용되므로 Control Plane 이 profile 마다 key 를 나눠 넣는 기능을 새로 만들지 않아도 된다. 어느 서비스의 key 를 살지는 운영이 정한다 |
| DECISION35 | 국내에서 쓸 수 있는 출처와 진료기관 안내 | 국내 기관과 한국어 출처를 우선하고 해외 출처는 보충으로 쓴다. 건강 질문에서 진료가 필요하면 국내에서 지금 갈 수 있는 곳이나 찾는 방법을 확인해 안내한다 | 사용자 결정 2026-11-24 | 발열 답은 해외 출처만 제시했고, 경제 뉴스 답에도 영어 기사 비중이 높았다 |
| DECISION36 | 바로 할 수 있는 다음 행동 | 본문 끝에 구체적인 행동을 적는다. 목록 추천이면 하나나 한 코스를 고르고, 여행 계획에는 숙소 후보와 총예산을 적는다. 약 복용 안내에는 공식 출처로 확인한 체중당 용량과 복용 간격을 적고 필요한 정보가 없으면 먼저 묻는다 | 사용자 결정 2026-11-24 | 발열 답의 복용 정보, 강릉 여행 답의 숙소와 총예산, 서울 행사 답의 최종 추천이 부족했다 |
| DECISION37 | 달라진 수치의 비교 | 달라진 것, 시세, 지수는 이전 값과 지금 값, 변화량을 나란히 보여 준다. 종가가 확정된 경우 종가와 등락률을 먼저 제시한다 | 사용자 결정 2026-11-24 | 연말정산은 귀속 연도별 비교가 어려웠고, 환율은 전일 대비 변화가 빠졌으며, 경제 뉴스는 지수의 장중 값만 제시했다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: 여러 기능이 참조하는 RULE ID 를 바꾸지 않는다. 검색 도구의 등급과 기본 도구 규칙([ADR-20261008 / default-toolsets](../../adr/ADR-20261008-default-toolsets.md))은 그대로다. 기존 결정 중 바뀌는 것은 ADR-038 의 공개 목록 하나이고(DECISION15), PR2 가 그 ADR 을 함께 고친다.
