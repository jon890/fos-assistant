# 휴대폰의 기본 대화: 비서 한 명에게 맡기고, 맡긴 일은 카드로 다시 찾는다

## 목표

개발 도구를 모르는 사용자가 휴대폰에서 앱을 열면 대화방이나 에이전트를 고르지 않고 비서에게 바로 말을 건다.
쇼핑, 일정, 생활 정보처럼 성격이 다른 일을 한 대화에서 맡기고, 오래 걸리거나 사람의 확인이 필요한 일은 맡긴 일마다 카드로 진행 상태와 다음 행동을 다시 찾는다.

출처: 이슈 #901 의 본문과 댓글 두 개(「P1 기술 완료 기준」, 「오래 걸리는 일의 모바일 진행 안내」). 사용자가 동료와 회의에서 정한 방향이며 회의 원문은 없다(사용자 결정 2026-11-28).

이 문서의 **맡긴 일**은 대화방에서 비서에게 맡겼는데 그 답 안에서 끝나지 않은 일이다(DECISION1). **맡긴 일 카드**는 그 일 하나를 보이는 카드다. 사용자가 받아들여 챙기는 [할 일](../attention.md)(`follow_up`)과 다르다.

## 지금 동작(2026-11-28 main)

- `/` 는 기본 비서와 늘 이어지는 대화방을 열고, 홈 화면 앱의 시작 주소(`web/src/app/manifest.ts` 의 `start_url`)도 `/` 다([에이전트 팀](../agent-team.md) 의 「대화방」).
- 대화방은 날이 바뀐 첫 메시지에서 어제까지의 대화를 요약해 새 session 으로 잇는다(같은 문서의 「날이 바뀐 첫 메시지」). 맥락 길이는 이것으로 다룬다.
- 새 대화는 늘 비서와 시작하고 전문 에이전트는 비서가 맡긴다([비서 중심 대화 스펙](../assistant-hub/spec.md)). 2분 안에 끝나지 않은 맡김은 결과 도착 줄과 자동 답으로 따로 온다(같은 스펙 REQ2).
- 플러그인이 로그인, 보안 확인처럼 사람이 해야 하는 화면에서 멈추면 대화에 화면 넘기기 카드가 생긴다. 입력창 위 「할 일 N건」 은 그 대화의 묻는 카드, 열린 넘기기, 승인 카드를 옆 패널에 모은다([사용자 브라우저](../user-browser.md) 의 「대화 위 화면」).
- 사람이 보낸 turn 이 시작되면 그 대화의 열린 넘기기를 모두 닫는다(`ConnectorHandoffs#onTurnStarted`, [네이버 쇼핑 스펙](../naver-shopping/spec.md) DECISION24). 쇼핑이 로그인을 기다리는 중에 일정을 물으면 로그인 카드가 사라진다.
- 「다 했어요」 는 정해 둔 글을 다음 메시지로 보내는 단추라, 어느 넘기기를 마쳤는지 서버가 모른다.
- 「지금 볼 것」(`/now`) 의 「맡긴 일」 칸은 대화를 가리지 않고 도는 위임과 최근 끝난 위임을 보인다([지금 화면과 알림, 할 일](../attention.md) 의 「후보와 trigger」).
- 맡긴 일 하나를 단위로 상태를 보이는 카드는 없다. 진행은 답의 작업 과정 블록과 중간 안내(`interim`, 저장하지 않음)로만 보인다.

## 요구사항과 인수 조건

인수 조건은 넓은 화면과 휴대폰 폭(360px) 두 곳에서 브라우저 테스트로 확인한다. 쇼핑은 모의 네이버 사이트와 가짜 Hermes 로 확인한다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 휴대폰에서 처음 열거나 다시 열면 새 대화나 에이전트를 고르지 않고 대화방에서 바로 맡긴다. 대화방은 맨 아래가 보인다(DECISION6) | 360px 폭에서 `/` 를 열면 대화방의 마지막 메시지와 입력창이 보이고 고르는 화면이 없다 |
| REQ2 | 넘기기 카드는 사람이 같은 대화에 무관한 질문을 보내거나 화면을 새로 고쳐도 남는다. 시간이 지나도 저절로 닫지 않는다. 단추 대신 입력창으로 답해 그 플러그인의 다음 호출이 같은 대화에서 성공하면 그 카드가 닫힌다(DECISION3, DECISION13) | 쇼핑의 로그인 넘기기를 띄우고 「내일 일정 알려 줘」 를 보낸 뒤 새로 고쳐도 그 카드와 「내 브라우저 열기」 가 남는다. 일정 답은 지금처럼 온다. 입력창에 「로그인했어」 를 보내 쇼핑 도구가 다시 성공하면 그 카드만 닫히고, 일정 도구의 성공으로는 닫히지 않는다 |
| REQ3 | 넘기기 카드의 「다 했어요」 와 「그만할래요」 는 그 카드 하나만 닫는다. 「다 했어요」 는 그 일을 다시 잇고, 이을 때 계정, 맡긴 일, 남긴 탭이 아직 유효한지 본다. 탭이 없어졌으면 이어 가지 않고 처음부터 다시 맡기라고 안내한다(DECISION3, DECISION13, DECISION14) | 넘기기 두 개 중 하나에서 「다 했어요」 를 누르면 그 카드만 닫히고 그 쇼핑만 이어진다. 탭을 닫은 뒤 「다 했어요」 를 누르면 「화면이 닫혀 이어 갈 수 없어요. 다시 맡겨 주세요」 취지의 안내가 보인다 |
| REQ4 | 같은 카드의 「다 했어요」 가 두 번 와도(두 번 누름, 두 창) 이어 가기는 한 번만 돈다. 승인과 결제의 경계는 지금 그대로다(DECISION15) | 「다 했어요」 를 두 창에서 함께 눌러도 주문서 채우기가 한 번만 돈다. 결제 넘기기는 지금처럼 「결제했어요」 와 「사지 않을래요」 이고 결제 단추를 누르지 않는다 |
| REQ5 | 맡긴 일마다 카드가 하나 있고 그 일을 맡긴 답 바로 아래 한 자리에서 진행 중, 확인 필요, 완료 중 하나로 보인다. 상태가 바뀌어도 대화에 새 줄을 올리지 않고 카드를 고친다(DECISION1, DECISION2, DECISION5) | 2분을 넘길 쇼핑을 맡기면 답 아래 카드가 「진행 중」 으로 생긴다. 로그인이 필요해지면 같은 카드가 「확인 필요」 와 「내 브라우저 열기」 로 바뀌고, 끝나면 「끝났어요 · 결과 보기」 한 줄로 접히고 「결과 보기」 가 결과 답으로 간다. 실패하면 「실패했어요 · 다시 맡기기」 로 접힌다. 바로 끝나는 일정 질문에는 카드가 없다 |
| REQ6 | 입력창 위 「할 일 N건」 을 「맡긴 일 N건」 으로 넓혀 그 대화의 진행 중·확인 필요 카드를 모은다. 누르면 그 카드가 있는 자리로 가거나 옆 패널에서 바로 다룬다. PC 도 같다(DECISION2, DECISION7) | 카드가 화면 위로 밀린 긴 대화에서 「맡긴 일 2건」 을 누르면 두 카드가 보이고, 하나를 고르면 그 답 자리로 이동한다. 넓은 화면에서도 같은 줄과 이동이 있다 |
| REQ7 | 다시 열었을 때 확인 필요인 카드가 있으면 대화 위쪽에 짧은 안내가 보이고, 누르면 그 카드로 간다(DECISION6) | 로그인 대기 카드를 둔 채 앱을 닫았다 다시 열면 맨 아래가 보이고, 위쪽의 「확인할 일 1건」 을 누르면 그 카드로 이동한다 |
| REQ8 | 진행 중 카드는 시작 직후, 도구로 확인한 중간 결과가 생겼을 때, 확인이 필요해졌을 때, 끝났을 때 한 줄로 고쳐진다. 그 한 줄은 맡은 에이전트의 마지막 중간 안내이고 「비서 안내」 라벨이 붙으며, 안내가 없으면 도구 이름으로 정해 둔 문구다. 완료 알림은 더하지 않는다(DECISION4, DECISION16) | 가짜 Hermes 의 맡은 에이전트가 검색 도구를 돌린 뒤 중간 안내를 내면 카드의 한 줄이 그 글로 바뀌고 대화에는 새 줄이 생기지 않는다. 새로 고쳐도 마지막 한 줄이 남는다. 중간 안내 없이 검색만 돌면 「검색하고 있어요」 같은 정해 둔 문구가 보인다 |
