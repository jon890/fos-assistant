스펙 [`spec.md`](spec.md) 의 PR1(REQ1-REQ7), PR2(REQ8-REQ10), PR3(REQ11-REQ15), PR4(REQ16-REQ18), PR5(REQ19-REQ20)를 설계한다.

## 인터페이스와 데이터

### 틀을 고르는 규칙

| 경로 | 틀 |
| --- | --- |
| `/signin`, 로그인하지 않은 `/privacy` | 로그인 전 화면 |
| `/admin` 아래 | 관리자 틀(그대로) |
| `/settings`, `/agents`, `/connections`, `/browser`, `/files`, `/dev-docs` 와 그 아래, 로그인한 `/privacy` | 설정 틀 |
| 그 밖(`/`, `/new`, `/chat/{id}`, `/now`, `/tasks`, `/memory`, `/notifications` 등) | 사이드바 틀 |

`/privacy` 에 로그인했는지는 레이아웃이 `auth()` 로 읽어 `AppShell` 에 `hasSession` 으로 넘긴다. Auth.js 의 세션 확인은 Control Plane 을 부르지 않는다. `/privacy` page 는 레이아웃의 값을 받지 못하므로 스스로 `auth()` 를 불러, 로그인한 사용자에게는 「로그인 화면으로」 단추와 「로그인 전에」 문장을 그리지 않는다.

### 묶음 목록

`settings-area.ts` 가 한 배열로 갖고 `SettingsShell` 과 테스트가 같은 값을 읽는다.

| 묶음 | 줄(주소) |
| --- | --- |
| 비서 | 에이전트(`/agents`) |
| 연결 | 외부 서비스 연결(`/connections`), 내 브라우저(`/browser`) |
| 내 데이터 | 파일 공간(`/files`) |
| 도움말 | 개발 문서(`/dev-docs`), 데이터 보관 안내(`/privacy`) |

골라진 줄은 경로의 접두로 정한다. `/settings` 는 「에이전트」 다. 실행 상세는 설정 틀 밖에서 보인다.
`/settings` 에서 「에이전트」 의 골라진 표시는 넓은 화면에서만 보이게 `md:` 클래스로 둔다. 휴대폰의 목록 화면에는 지금 화면이 없기 때문이다. `aria-current` 는 `/settings` 에서 붙이지 않는다.

### 설정 틀의 배치

- 넓은 화면(768px 이상): 머리 한 줄(제목 「설정」, 오른쪽 「대화로」), 아래 왼쪽에 묶음 목록(`md:w-64`, 사이드바와 같은 폭), 오른쪽에 본문이다.
- 휴대폰: `/settings` 에서는 묶음 목록이 본문 자리를 채우고 본문은 CSS 로 숨긴다. 다른 주소에서는 목록을 숨기고 머리 왼쪽에 「설정」 으로 가는 뒤로 가기 단추를 둔다. 「대화로」 는 두 경우 모두 머리 오른쪽에 있다.

넓이를 CSS(`md:`)로만 나눠 첫 그림과 hydration 사이에 배치가 바뀌지 않게 한다. 그래서 휴대폰에서 `/settings` 를 열어도 「에이전트」 본문을 서버에서 한 번 읽는다. 목록 화면 한 번에 Control Plane 조회 한 번이 더 드는 정도라 그대로 둔다.

### 이름 메뉴

| 줄 | 동작 |
| --- | --- |
| 이름(메뉴 머리, 누를 수 없음) | `useShellAccount().displayName`. 없으면 그리지 않는다 |
| 설정 | `/settings` 로 간다 |
| 관리자 화면 | 역할 상태가 `admin` 일 때만. `/admin` 으로 간다. `data-testid="admin-entry"` 를 이 줄로 옮긴다 |
| 화면 밝기 | 「화면 밝기」 이름 아래 라디오 셋(밝게, 어둡게, 기기 설정). 지금 값에 체크가 보인다. `next-themes` 의 `setTheme` 을 부른다. 하위 메뉴는 360px 서랍에서 부모 메뉴를 덮으므로 쓰지 않는다 |
| 로그아웃 | 아래 「로그아웃」 의 순서로 `POST /signout` 을 보낸다 |

메뉴를 여는 단추는 사람 아이콘과 이름이고 낭독기 이름은 「계정 메뉴」 다. 이름을 아직 모르면 「계정」 을 보인다. 역할 상태가 `reading` 일 때도 단추는 그리고 「관리자 화면」 만 뺀다.
역할 상태가 `failed` 면 줄에 안내 글자(「계정 정보를 읽지 못했어요」), 「다시 읽기」 단추, 아이콘만 보이는 메뉴 단추를 형제로 둔다. 단추 안에 단추를 넣지 않는다.

### 로그아웃

1. 「로그아웃」 줄이 `fetch("/signout", { method: "POST" })` 를 보낸다. Route Handler 가 `signOut({ redirect: false })` 를 부르고 204 를 돌려준다. 던지면 서버 로그를 남기고 500 이다.
2. 204 면 `window.location.replace("/signin")` 으로 문서를 새로 연다. 클라이언트 라우터 캐시와 화면 상태가 함께 사라진다.
3. 응답이 204 가 아니거나 `fetch` 가 reject 되면(네트워크 끊김) 이름 줄 위에 「로그아웃하지 못했어요. 아직 로그인된 상태예요」 를 `role="alert"` 로 보이고 화면은 그대로다. 메뉴 항목은 고르는 순간 메뉴가 닫히므로 안내를 메뉴 밖에 둔다. 요청이 도는 동안 다시 보내지 않는다.

서버 동작을 쓰지 않는 까닭은 둘이다. 쿠키를 바꾼 서버 동작은 그 응답에서 지금 경로를 다시 그려 page 의 `redirect("/signin")` 과 문서 이동이 겹친다. 배포 뒤 열려 있던 탭은 서버 동작 식별자를 찾지 못해 reject 된다.
세션 쿠키는 SameSite=Lax 라 다른 사이트가 보낸 POST 에는 붙지 않는다. 지우기만 하는 요청이라 CSRF 토큰은 두지 않는다.

Auth.js 는 JWT 세션이라 쿠키를 지우면 그 브라우저만 풀린다. 다른 기기의 쿠키와 Control Plane 의 데이터는 그대로다.
로그아웃한 뒤 주소로 연 화면은 page 가 `auth()` 로 세션을 확인하고 `/signin` 으로 보낸다.
뒤로 가기는 브라우저가 bfcache 에서 문서를 그대로 꺼낼 수 있다. 브라우저마다 다르므로 기대지 않고, 화면 틀(`AppShell`)이 `pageshow` 의 `persisted` 가 참이면 `/api/auth/session` 으로 세션을 확인하고, 없거나 읽지 못하면 `location.reload()` 한다. 다시 읽은 page 가 세션 없음을 보고 `/signin` 으로 보낸다. 세션이 있으면 다시 읽지 않아 쓰던 글과 스크롤이 남는다. Playwright 는 bfcache 를 끈 채 Chromium 을 띄우므로, 테스트는 `persisted` 를 넣은 `pageshow` 를 직접 보내 세션이 있을 때와 없을 때를 본다.
같은 브라우저의 다른 탭은 다음 요청이나 이동에서 로그인 화면으로 간다. 열려 있는 다른 탭을 곧바로 닫거나 새로 고치는 일은 스펙 범위 밖이다.

계정 고르기는 `Google({ authorization: { params: { prompt: "select_account" } } })` 로 모든 로그인에 붙인다. 로그아웃 뒤에만 붙이려면 상태를 따로 기억해야 하고, 로그인 화면은 로그아웃 뒤에 주로 오므로 늘 붙인다.

### 작업 과정의 이름

**플러그인 도구의 이름은 Control Plane 이 붙여 보낸다.** 등록 이름(`mcp__<서버>__<도구>`)은 줄이고 글자를 바꿔 원래 이름을 되찾을 수 없다(`hermes/docs/hermes-contract.md` 의 「MCP 도구의 등록 이름」).
그래서 `ConnectorToolNameLookup` 이 카탈로그의 manifest 마다 `HermesToolName.of(mcpServer, 도구)` 를 계산해 같은 값을 찾는다.
선언한 도구에 없는 등록 이름도 서버 이름까지의 앞부분이 그 manifest 의 것이면 서비스 이름만 붙인다. 제목을 선언하지 않은 도구와 표준 플러그인(`schema: 3`)이 여기 든다.
바인딩을 보지 않으므로 그룹에 공개한 다른 사람의 에이전트와 끝난 지 오래된 답도 같은 이름을 받는다(spec DECISION24). 카탈로그를 읽지 못하면 이름을 붙이지 않고 화면은 「연결된 서비스」 로 보인다.
카탈로그는 이미 도구 판정과 에이전트 목록이 쓰는 캐시라 대시보드를 더 부르지 않는다.

| 응답 | 더하는 칸 |
| --- | --- |
| 대화 스트림의 `tool` 사건 | `connector: { service, title }`. 플러그인 도구가 아니면 null |
| 실행 트리의 도구 사건(`ExecutionEventView`) | 같은 `connector`. `agent_delegate` 사건에는 `delegatedAgentName`(아래 「맡기기 도구 줄」) |
| 메시지 조회의 `activity` | `uses`: 그 답이 쓴 도구와 도우미를 처음 쓴 차례로, 같은 것은 한 번만. 줄마다 `kind`(`TOOL`, `SUBAGENT`), `toolName`, `connector` |

`uses` 의 차례는 트리 안 사건의 `occurredAt`, 실행 번호, `sequence` 순이다. 자식 실행은 첫 사건의 때에 도우미 한 줄이다.
`toolCount` 와 `subagentCount` 는 그대로 두어 블록을 그릴지 정하는 데만 쓴다. 지금 저장된 사건으로 만들므로 이 PR 앞에 끝난 답도 같은 줄을 받는다.
도구 이름은 지금도 스트림과 실행 트리로 모든 사용자에게 가므로 `uses` 의 `toolName` 이 새로 내보내는 값은 아니다. 화면의 글자에는 그리지 않는다.

**종류의 이름과 문장은 화면이 정한다.** `tool-kind.ts` 의 표가 도구 이름(`mcp__` 를 뗀 이름)을 spec REQ14 의 종류로 묶는다.

| 도구 | 접힌 줄 | 펼친 줄과 도는 줄 |
| --- | --- | --- |
| 지금 문장 표의 도구 | 종류 이름 | 지금 문장 |
| `connector` 가 있는 도구 | 서비스 이름 | 「서비스 이름 · 도구 제목」, 제목이 없으면 서비스 이름 |
| `connector` 가 없는 `mcp__` 도구 | 「연결된 서비스」 | 지금 문장(「연결된 서비스를 썼어요」) |
| 그 밖 | 「그 밖의 도구」 | 지금 문장(「도구를 썼어요」) |
| 하위 에이전트 | 「도우미」 | 지금 문장(목표) |

**맡기기 도구 줄은 맡은 에이전트 이름을 쓴다**([비서 중심 대화 스펙](../assistant-hub/spec.md) DECISION30). `agent_delegate` 의 펼친 줄과 도는 줄은 이름을 알면 「<이름>에게 맡기고 있어요」, 「<이름>에게 맡겼어요」 이고 모르면 지금 문장이다. 모델이 준 인자는 쓰지 않는다.

| 자리 | 이름을 얻는 곳 |
| --- | --- |
| 도는 답 | Control Plane 이 맡긴 실행을 만들며 보내는 맡긴 줄(`delegation` 사건)의 에이전트 이름을, 그 답의 이름 없는 맡기기 도구 줄 가운데 먼저 시작한 줄에 붙인다 |
| 지난 답과 실행 상세 | `ExecutionTreeService` 가 실행 하나의 `agent_delegate` 시작·완료 사건을 차례로 짝짓고, 그 호출이 시작한 뒤 끝나기 전(앞뒤 2초 여유)에 시작한 맡긴 자식 실행의 에이전트 이름을 `delegatedAgentName` 칸에 넣는다. 거절돼 자식이 없는 호출은 null 이다 |

접힌 줄은 끝난 모양(`done`, `stopped`, `failed`)의 머리말 뒤에 이름을 셋까지 가운뎃점으로 잇고 넷째부터 「외 N」 이다. `done` 은 머리말이 없고, 이름이 하나도 없으면 「차례로 정리했어요」 다.

**도는 줄의 움직임은 글자 위를 지나가는 밝기다.** `activity-shimmer` 는 글자색을 그라데이션으로 칠해 옆으로 옮기고, `prefers-reduced-motion: reduce` 에서는 `animation: none` 이다.
낭독기가 읽는 글은 단추 이름과 따로 둔 `sr-only` 의 `aria-live="polite"` 다. 단추 안에 live 영역을 두면 걸린 시간이 바뀔 때마다 읽는다.

### 지금 볼 것 탭

| 탭 | 내용 | 이름 옆 표시 |
| --- | --- | --- |
| 할 것(처음 열린다) | 지금의 카드 화면(`NowScreen`). 서버가 그린다 | 할 것의 수(`nowCount`). 0 이면 없다 |
| 알림 | 지금의 알림 목록(`NotificationList`). 「모두 읽음」 은 탭 안 맨 위 오른쪽이다 | 읽지 않은 알림의 수. 99 를 넘으면 「99+」(`unreadBadge`) |

- 탭은 `radix-ui` 의 Tabs 로 그린다. 키보드의 좌우 이동과 `tablist` 역할을 새로 만들지 않는다. 감싸는 부품은 `components/ui/tabs.tsx` 다.
- **열린 탭은 주소가 정한다.** `NowTabs` 가 `useSearchParams()` 의 `tab` 이 `notifications` 이면 「알림」 을 연다. 탭을 바꾸면 `window.history.replaceState` 로 주소만 바꾸고 Next 가 그 값을 `useSearchParams` 에 반영한다. 서버를 다시 부르지 않고, 새로 고치거나 다른 화면에서 `/now` 로 와도 주소대로 열린다. page 는 `searchParams` 를 읽지 않고 서버 부품 `NowScreen` 을 `todo` prop 으로 넘긴다.
- 「알림」 탭의 목록은 그 탭을 처음 열 때 올라오고 그 뒤에는 내려가지 않는다. `/now` 를 열 때마다 알림 첫 쪽을 읽지 않으면서, 탭을 오가도 목록과 이어 읽은 자리가 남는다. 「할 것」 은 서버가 이미 그렸으므로 늘 올라와 있고 감춰지기만 한다. 두 탭 내용은 Radix 의 `forceMount` 로 올려 두므로 `hidden` 이 붙지 않는다. 감추는 것은 `tabs.tsx` 의 `data-[state=inactive]:hidden` 이 맡는다.
- 수는 낭독기가 탭 이름과 함께 읽는다. 숫자 배지는 `aria-hidden` 이고 옆의 `sr-only` 글(「3건」, 「읽지 않음 2개」)이 읽힌다.
- `/notifications` page 는 그리지 않고 `redirect("/now?tab=notifications")` 다. 로그인 확인은 `/now` page 가 한다. 웹 푸시의 열기 주소(`/n/<id>`)는 attention 기능이 따로 갖는다.

다시 읽는 때는 셋이다.

- 경로가 바뀔 때. 지금 `NowLink` 가 하던 것을 옮긴다
- `ATTENTION_CHANGED_EVENT`. 지금 화면 안의 숨기기, 미루기, 되돌리기
- `NOTIFICATIONS_CHANGED_EVENT`. 새 알림 사건이 오거나 알림 연결을 다시 열 때다(spec DECISION20). 승인 요청 알림이 왔는데 수가 그대로면 점과 숫자가 어긋난다

읽기마다 차례 번호를 붙여 늦게 온 앞선 답을 버리는 것은 지금 `NowLink` 의 방식 그대로다. 읽지 못하면 0 이다(`readNowCount`).
휴대폰 위 막대의 단추는 `Inbox` 아이콘의 `/now` 링크이고 알림 단추가 있던 자리(「새 대화」 왼쪽)에 둔다. 위 막대는 사이드바 틀에만 있으므로 관리자 틀과 설정 틀에는 단추가 없다.

| 지금 볼 것 | 「내가 확인하거나 답할 일과 새 알림이 모여요.」(새 문구) | 없음 |

상세 화면은 에이전트 하나(`/agents/{code}`), 예약 작업 하나와 새 예약 작업(`/tasks/{id}`, `/tasks/new`), 연결 하나(`/connections/{id}`), 에이전트 작업 폴더(`/files/workspace`)다. 설명 줄은 두지 않고 뒤로 가기와 제목만 같은 자리에 둔다. 문서 하나(`/dev-docs/...`)는 「개발 문서」 머리를 그대로 쓴다.

**에이전트 상세의 절은 폭을 스스로 갖지 않는다.** `PersonaEditor` 와 절 부품들이 `mx-auto max-w-2xl` 과 `h1` 을 각자 갖고 있어 틀 안에서 가운데로 좁게 모였다. 폭과 제목을 `AgentDetailBody` 가 정하게 옮긴다. 일반 화면은 `PageFrame` 으로, 관리자 영역은 지금과 같은 `max-w-2xl` 로 감싼다. 관리자 영역의 모양은 바뀌지 않는다(spec 범위 밖).

**두 틀의 왼쪽 끝을 맞춘다.** 설정 틀의 묶음 목록 폭을 사이드바와 같은 `md:w-64` 로 둔다. 본문 자리의 폭이 같아져 「예약 작업」 에서 「설정」 으로 옮겨도 제목의 왼쪽 끝이 같다. 사이드바를 접었을 때는 본문 자리가 넓어져 가운데 정렬된 틀이 함께 옮겨 간다. 접은 것은 사용자가 고른 배치라 그대로 둔다.

스킬 편집 화면(`/agents/{code}/skills/{name}`)과 「데이터 보관 안내」 는 REQ19 의 대상 목록에 없어 이 PR 은 고치지 않는다.

### 빈 목록, 실패, 읽는 중

| 상태 | 부품 | 모양 |
| --- | --- | --- |
| 빈 목록 | `EmptyState`(지금 부품) | 점선 상자 안에 제목 한 줄, 설명 한 줄, 있으면 시작 단추 |
| 불러오기 실패 | `LoadFailure` | 오류 색 상자(`role="alert"`) 안에 한 줄과 「다시 읽기」 단추 |
| 읽는 중 | `ListSkeleton` | 머리는 그대로이고 본문에 줄 높이의 뼈대 셋. `role="status"` 안에 화면 읽기 프로그램만 읽는 글자 「불러오는 중이에요」 를 둔다 |

- 브라우저가 읽는 화면은 「다시 읽기」 를 누르면 답이 올 때까지 뼈대로 돌아간다. 눌린 것이 보이고 거듭 눌러 요청이 여러 번 가지 않는다.
- `LoadFailure` 는 `onRetry` 를 받으면 그것을 부르고, 없으면 문서를 새로 연다(`window.location.reload()`). `router.refresh()` 는 빌드한 서버에서 응답이 화면에 반영되지 않은 일이 있어 쓰지 않는다. 서버가 읽는 화면(에이전트, 기억, 「할 것」 탭, 문서 하나)은 뒤쪽을, 브라우저가 읽는 화면(예약 작업, 외부 서비스 연결, 내 브라우저, 파일 공간, 「알림」 탭)은 앞쪽을 쓴다.
- 서버가 읽는 화면의 `loading.tsx` 는 `PageFrame` 을 `busy` 로 그린다. 제목과 설명은 `lib/page-head.ts` 의 실제 글자이고, 이름을 아직 모르는 상세 화면만 제목 자리에 뼈대를 둔다. 바깥에 지금 뼈대와 같은 `data-testid="page-skeleton"` 과 `aria-busy` 가 붙는다.
- 실패 문구는 화면마다 지금 문구를 그대로 쓴다. 서버가 준 사유가 있으면 그 문장이다. 「화면을 다시 열어 주세요」 로 끝나던 내 브라우저의 안내만 단추가 생겨 그 문장을 뺀다.
- 화면 안쪽의 작은 목록(에이전트 상세의 절, 기억의 필터 결과, 작업 폴더 탐색기)이 쓰는 안내는 그대로 둔다. 화면 하나의 안쪽 구성은 범위 밖이다(spec DECISION11).

## 실패와 일관성

- 역할을 읽지 못한 상태는 지금 `shellRoleState` 그대로다. 메뉴는 열리고 「관리자 화면」 만 빠진다(DECISION19).
- 설정 틀은 대화 목록과 알림 구독(`ConversationsProvider`, `NotificationsProvider`)을 끄지 않는다. 「대화로」 를 눌러 돌아갈 때 목록을 다시 읽지 않게 하려는 것이다. 관리자 틀만 지금처럼 끈다.
- 마지막 대화 경로는 지금처럼 `/chat/` 으로 들어갈 때마다 `sessionStorage` 에 적는다. 저장소를 막은 브라우저는 `/` 로 돌아간다.
- 단축키(`use-shortcuts.ts`)는 사이드바가 있는 틀에서만 켠다. 설정 틀에는 사이드바와 검색칸이 없다.
- 배포 순서: PR1, PR2 는 `web` 하나만 바뀐다. PR3 은 Control Plane 과 화면을 함께 배포한다. 화면만 먼저 나가면 `uses` 가 없는 끝난 답이 모두 「차례로 정리했어요」 로 보이고, Control Plane 만 먼저 나가면 더한 칸을 화면이 읽지 않을 뿐이다.
- 카탈로그를 읽지 못해 `connector` 가 비면 플러그인 도구는 「연결된 서비스」 로 보이고 실패하지 않는다(PR3).
