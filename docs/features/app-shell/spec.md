# 화면 틀과 메뉴 배치: 대화에 집중하도록 메뉴와 설정을 뒤로 보내고 작업 과정을 알아보기 쉽게 보인다

확인: 2026-11-20

## 목표

사용자가 웹과 휴대폰에서 화면을 열면 대화가 먼저 보이고, 설정과 관리 화면은 이름을 눌러 여는 메뉴와 「설정」 화면 한곳에서 찾는다.
자주 여는 「예약 작업」 과 「기억」 은 한 번에 닿는다.
답을 기다리는 동안과 답이 끝난 뒤에 비서가 무엇을 썼는지를 「웹 검색」, 「Gmail · 메일 읽기」 같은 사람 말로 안다.

지금은 아래와 같다(2026-11-19).

- 왼쪽 사이드바에 대화 목록, 화면 메뉴 여덟 줄(에이전트, 외부 서비스 연결, 예약 작업, 기억, 사용량, 「고급」 묶음의 파일 공간·내 브라우저·개발 문서), 맨 아래 이름·관리자·알림·밝기 단추가 한꺼번에 있다([`web/docs/code-architecture.md`](../../../web/docs/code-architecture.md) 의 「화면 틀」)
- 입력창 아래에 모델 단계 단추가 따로 떠 있고, 새 대화 화면의 인사 아래에 에이전트 카드가 가로로 늘어서 있다
- 「지금 볼 것」 과 알림 단추가 따로 있고 수도 따로 센다([`attention.md`](../attention.md))
- 끝난 답 위의 접힌 줄은 「필요한 것을 확인하고 답했어요」 같은 고정 문장이고, 연결한 서비스의 도구는 모두 「연결된 서비스를 썼어요」 로만 보인다([`execution.md`](../execution.md) 의 「작업 과정 블록」)
- 화면에 로그아웃 단추가 없다
- 화면마다 제목 자리, 폭, 주 단추 자리가 다르다

사용자는 휴대폰과 넓은 화면을 비슷하게 쓴다. 모든 요구사항은 두 폭에 같은 무게로 적용한다.

| REQ20 | 같은 화면들은 목록이 비었을 때, 불러오지 못했을 때, 읽는 중일 때 같은 모양의 안내를 쓴다(PR5). 빈 목록은 무엇이 여기 모이는지 한 줄과 있으면 시작 단추, 실패는 불러오지 못했다는 한 줄과 「다시 읽기」, 읽는 중은 머리 틀이 그대로인 뼈대다 | 대상 화면마다 빈 목록, 불러오기 실패, 읽는 중을 만들면 같은 자리에 같은 모양의 안내가 보인다 |
