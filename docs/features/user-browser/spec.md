# 사람이 도와야 하는 지점: 대화 위에서 「내 브라우저」 를 띄워 그 자리에서 마치고 에이전트가 이어 간다

확인: 2026-11-12

## 목표

에이전트가 「내 브라우저」 로 일하다가 스스로 넘을 수 없는 지점(로그인, 보안 확인, 기기 인증, 봇 탐지, 예상 밖 화면, 사람이 골라야 하는 선택, 승인)을 만나면 멈추고 사람에게 무엇을 해 달라는지 알린다.
사람은 새 창으로 넘어가지 않고 대화 위의 오른쪽 drawer(휴대폰은 전체 폭 시트)에서 그 화면을 보며 돕고, 끝나면(주소가 바뀐 것을 알아채 묻거나 「다 했어요」) 에이전트가 이어 간다.
플러그인 이름에 묶이지 않는 공통 흐름이다. 네이버 쇼핑, 네이버 블로그, 코레일 KTX 처럼 「내 브라우저」 를 쓰는 플러그인이 모두 같은 흐름을 쓴다.

지금의 화면 넘기기(카드, 「다 했어요」 글, 사람이 보낸 turn 이 카드를 닫는 규칙)는 [ADR-20261111 / connector-handoff](../../adr/ADR-20261111-connector-handoff.md) 와 [네이버 쇼핑 스펙](../naver-shopping/spec.md) 의 REQ7, REQ8 이 정했다. 이 스펙은 그 계약을 지키고 사람이 돕는 자리와 막힘의 종류를 넓힌다.

## 범위

이 스펙은 PR 셋으로 구현한다(DECISION10). 이 스펙을 처음 구현하는 PR 은 PR1 이다.

| PR | 담는 것 | 요구사항 |
| --- | --- | --- |
| PR1 | 웹만. 넘기기 카드에서 대화 위 drawer·시트로 「내 브라우저」 열기, 새 카드에 자동 열기, drawer 안 「다 했어요」, 주소가 바뀌면 끝났는지 묻기, 알림에서 들어오면 drawer 열기 | REQ1~REQ6 |
| PR2 | 넘기기 어휘에 봇 탐지(`bot_check`)와 예상 밖 화면(`unexpected_page`) 추가. 예상 밖 화면은 탭을 닫지 않고 넘긴다. 코레일 KTX 와 네이버 블로그도 넘기기 카드를 낸다 | REQ7, REQ8 |
| PR3 | 승인 카드와 묻는 카드를 같은 drawer 의 「할 일」 탭에 모은다 | REQ9, REQ10 |

범위 밖:

- 보안문자 자동 풀이와 봇 판별 우회(사용자 결정 2026-11-12)
- 실행을 멈춰 사람을 기다리기. 기다리는 동안 동시 실행 한도와 스레드를 잡는다([네이버 쇼핑 스펙](../naver-shopping/spec.md) 의 DECISION11)
- 「남긴 탭에서 이어 가기」 표식. 여러 단계 화면을 거치는 기능(네이버 쇼핑 주문서, KTX 예매)과 함께 그 스펙에서 넣는다(DECISION8)
- 플러그인이 끝 조건을 넣어 정확히 판정하는 끝 감지(DECISION2)
- 카드에 플러그인이 쓴 설명 글 더하기(DECISION7)
- 세 길(화면 넘기기, 묻는 카드, 승인 카드)을 하나의 새 개념과 저장 자리로 합치기(DECISION6)
- 검색을 공식 API 로 바꾸기(사용자 결정 2026-11-12, 접음)
- 웹 밖 알림(웹 푸시)
- `/browser` 화면 자체의 동작. 그 화면은 지금 그대로다

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 넘기기 카드의 「내 브라우저 열기」 가 대화 위에 「내 브라우저」 를 띄운다 | 넓은 화면(1024px 이상)에서 「내 브라우저 열기」 를 누르면 새 창이 열리지 않고 대화 오른쪽에 drawer 가 붙어 그 카드의 탭 화면이 보인다. 대화와 입력창은 그대로 쓸 수 있다. 1024px 보다 좁으면 같은 화면이 전체 폭 시트로 대화를 덮는다. drawer 머리에 카드 제목, 닫기, 「새 창으로 열기」(지금의 `/browser?tab=` 링크)가 있다. 화면 안의 누르기, 끌기, 글자 넣기, 확인 창은 `/browser` 와 같다. 화면 위의 도구 줄(주소 칸, 뒤로, 새로 고침, 탭 고르기, 크게 보기)도 `/browser` 와 같고, 도구 줄의 닫기는 drawer 닫기와 같다. 닫기를 누르면 drawer 만 닫히고 카드는 남는다. 「새 창으로 열기」 를 누르면 drawer 를 닫는다(새 창이 화면을 가져가기 때문이다). 다른 창이 화면을 가져가면 drawer 는 지금처럼 「다른 창에서 화면을 열었어요」 와 「다시 열기」 를 보인 채 남는다 |
| REQ2 | 보고 있는 대화에 새 카드가 생기면 drawer 를 저절로 연다 | 이 화면이 대화를 연 뒤에 생긴 넘기기(생긴 시각이 대화를 연 시각보다 늦은 것)의 카드가 나타나면 넓은 화면과 휴대폰 모두 그 카드의 drawer 가 저절로 열린다. 연결이 끊긴 동안 생겨 다시 이은 뒤 처음 보인 카드와 같은 대화를 연 다른 창의 turn 이 만든 카드도 같다. 대화를 처음 열거나 새로 고쳤을 때 이미 있던 카드는 카드만 보이고 저절로 열지 않는다. 다른 옆 패널(작업 과정, 결과물)이 열려 있으면 새 카드의 drawer 가 그 자리를 갈아 쓰고, drawer 가 닫히면 그 자리는 빈다(앞 패널을 되돌리지 않는다) |
| REQ3 | drawer 안에서 「다 했어요」 를 누른다 | drawer 아래의 「다 했어요」 를 누르면 drawer 가 닫히고, 카드의 「다 했어요」 와 같은 정해 둔 글이 그 대화의 다음 메시지로 간다. 그 뒤 카드가 닫히는 규칙은 지금과 같다(사람이 보낸 turn 이 열린 넘기기를 모두 닫는다). 에이전트가 다시 막혀 새 카드가 생기면 REQ2 로 drawer 가 다시 열린다 |
| REQ4 | 넘긴 탭의 주소가 바뀌면 끝났는지 묻는다 | drawer 를 열어 그 카드의 탭을 처음 보인 때의 주소를 기준으로 삼는다(drawer 를 다시 열면 기준도 다시 잡는다). 화면이 다른 탭(로그인 팝업 등)으로 옮겨 가도 넘긴 탭만 보고, 넘긴 탭의 주소가 기준과 다르거나(`#` 뒤 조각만 다른 것은 같은 주소로 본다) 넘긴 탭이 닫히면 drawer 아래에 「화면이 바뀌었어요. 다 마치셨나요?」 와 「다 했어요, 이어서 해 주세요」, 「아직이에요」 를 보인다. 「다 했어요, 이어서 해 주세요」 는 REQ3 의 「다 했어요」 와 같다. 「아직이에요」 는 물음을 거두고 그때의 주소를 새 기준으로 삼아, 주소가 다시 바뀌면 다시 묻는다. 묻기만 하고 저절로 보내지 않는다. 가리킨 탭이 처음부터 없으면(닫혔거나 브라우저를 다시 켬) 묻지 않고 「다 했어요」 만 남는다 |
| REQ5 | 알림에서 들어오면 drawer 를 연다 | 화면 넘기기 알림(`HANDOFF_REQUESTED`)을 누르면 그 대화로 가고, 그 대화에 열린 넘기기가 있으면 가장 최근 것의 drawer 가 열린다. 알림이 가리킨 넘기기가 닫혔어도 같은 대화에 다른 열린 넘기기가 있으면 그것을 연다. 열린 넘기기가 없으면 대화만 연다. 다른 종류의 알림은 지금과 같다 |
| REQ6 | 넘기기가 닫히면 drawer 도 닫힌다 | drawer 가 보이던 넘기기가 닫히면(사람이 입력창에 직접 답했거나 다른 창에서 「다 했어요」) 카드가 사라지면서 drawer 도 닫힌다. 넘기기가 여럿이면 각 카드의 「내 브라우저 열기」 가 drawer 를 그 카드의 탭으로 바꾼다. drawer 는 한 번에 하나다 |
| REQ7 | 봇 탐지와 예상 밖 화면도 넘긴다 | 플러그인이 봇 탐지 화면이나 예상 밖 화면을 만나면 탭을 닫지 않고 `need` 가 `bot_check`, `unexpected_page` 인 넘기기를 낸다. 카드 제목과 「다 했어요」 글은 어휘마다 정해 둔 글이다(예: 예상 밖 화면은 「「내 브라우저」에서 화면을 확인해 주세요」). 모르는 어휘는 지금처럼 Control Plane 이 받지 않는다. 네이버 쇼핑의 `*_PAGE_CHANGED` 는 예상 밖 화면 넘기기가 된다 |
| REQ8 | 코레일 KTX 와 네이버 블로그도 넘기기 카드를 낸다 | 두 플러그인이 로그인, 보안 확인, 봇 탐지, 예상 밖 화면에서 멈추면 결과에 `handoff` 칸을 넣어 네이버 쇼핑과 같은 카드, 알림, drawer 가 뜬다. 플러그인 이름을 Control Plane 과 fos-ctx 가 모르는 것은 그대로다 |
| REQ9 | 승인 카드를 「할 일」 탭에 모은다 | drawer 에 「할 일」 과 「내 브라우저」 두 탭이 있다. 「할 일」 에는 그 대화의 기다리는 승인과 열린 넘기기가 함께 보이고 승인·거절은 지금 승인 카드와 같은 규칙(묶음 승인, 상시 허락, 대화 허락, 가린 인자)으로 끝난다. 승인 카드가 새로 생기거나 승인 알림(`APPROVAL_REQUESTED`)으로 들어오면 「할 일」 탭이 열린다. 입력창 위에는 「할 일 N건」 한 줄 요약이 남는다 |
| REQ10 | 묻는 카드도 「할 일」 에 모은다 | 에이전트가 고를 것을 물은 카드(ADR-026)가 「할 일」 탭에도 보이고, 거기서 고른 답은 지금처럼 다음 메시지로 간다 |

| DECISION14 | 알림이 가리키는 넘기기 | 그 대화의 열린 넘기기 가운데 가장 최근 것 | 작성자 | 알림 응답에 넘기기 번호가 없다(`web/src/lib/notification.ts`). 「다 했어요」 한 번이 모두 닫으므로 어느 것을 먼저 열어도 결과가 같다. Control Plane 을 바꾸지 않아 PR1 이 웹만으로 끝난다 |
| DECISION15 | 주소 비교의 기준 | drawer 가 그 탭을 처음 보인 때의 주소. 가리킨 탭이 처음 목록에 없으면 묻지 않는다 | 작성자 | 넘길 때의 주소는 넘기기 칸에 없다. 웹만으로 얻을 수 있는 가장 이른 기준이다 |
| DECISION16 | 「새 창으로 열기」 를 남기는가 | drawer 머리에 남긴다 | 작성자 | 화면이 좁거나 drawer 안에서 다루기 어려운 사이트에서 지금 흐름으로 돌아갈 길이다 |
| DECISION17 | 「새 카드」 의 범위 | 생긴 시각이 이 화면이 대화를 연 시각보다 늦은 넘기기. 다시 이은 뒤 처음 보인 것과 다른 창이 만든 것도 포함 | 작성자 | DECISION3 의 「보고 있는 동안 생긴」 을 그대로 옮긴 기준이다. 넘기기 응답에 생긴 시각(`createdAt`)이 이미 있다 |
| DECISION18 | 여러 창이 화면을 다툴 때 | 창마다 자동으로 연다. 밀린 drawer 는 지금 화면처럼 「다른 창에서 화면을 열었어요」 와 「다시 열기」 를 보인다. 「새 창으로 열기」 는 drawer 를 닫는다 | 작성자 | 한 브라우저에 화면은 하나고 밀린 화면의 안내는 이미 있다(`user-browser.md` 「로그인 화면」 의 `replaced`). 새 창으로 옮긴 뒤 밀린 drawer 를 남길 까닭이 없다 |
| DECISION19 | 주소 변화의 판정 | 넘긴 탭 하나만 본다. drawer 를 열 때 기준을 잡고, 「아직이에요」 를 누르면 그때 주소로 기준을 바꾼다. `#` 뒤 조각만 다른 것은 같은 주소다. 넘긴 탭이 닫히면 바뀐 것으로 본다 | 작성자 | 묻기만 하고 보내지 않으므로(DECISION2) 넉넉히 묻는 쪽이 안전하다. 조각만 바뀌는 한 페이지 사이트에서 물음이 잦지 않게 한다 |
| DECISION20 | drawer 의 도구 줄 | `/browser` 와 같은 도구 줄을 둔다. 도구 줄의 닫기는 drawer 닫기다 | 작성자 | 사람이 그 화면에서 다른 탭이나 주소로 가야 풀리는 경우가 있다. 화면 부품을 하나로 유지한다 |
| DECISION21 | drawer 가 닫힌 뒤 옆 패널 | 비운다. 앞에 보던 패널을 되돌리지 않는다 | 작성자 | 지금 옆 패널을 바꿀 때와 같다. 실시간 작업 과정은 되돌릴 상태가 이미 지나 있다 |
