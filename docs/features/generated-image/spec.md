# 비서가 만든 이미지: 대화로 부탁한 그림이 답 안에 보이고 보관함에 남는다

확인: 2026-11-20

## 목표

사용자가 대화에서 「수채화 느낌의 고양이 그림 만들어 줘」 라고 하면 비서가 그림을 만들고, 그 그림이 답 안에 그림으로 보이며 「파일 공간」 의 「보관한 결과물」 에도 남는다.
가족 모두가 각자의 기본 비서에서 따로 설정하지 않고 쓴다.

지금은 「그림 만들기」 도구를 켜도 그 비서에 이미지 서비스 설정이 없으면 「이미지 생성 도구가 없다」 는 답이 나온다.
설정이 있는 비서에서도 답에는 파일 경로 글자만 보이고 그림은 보이지 않는다.

PR4 까지 만든 뒤 같은 부탁을 Codex 와 비교했더니 두 곳에서 뒤졌다(2026-11-20).
사용자가 보낸 상품 링크의 사진을 보지 못해 상품 이름만 보고 모양을 지어냈고, 그림 지시문이 성겨 장면마다 인물 수와 생김새가 바뀌고 구도가 어긋났다.
PR5 와 PR6 이 이 둘을 고친다.

## 범위

이 스펙은 PR 여섯으로 구현한다(DECISION7, DECISION33). 이 스펙을 처음 구현하는 PR 은 PR1 이고, 뒤의 PR 은 같은 스펙과 설계를 쓴다.

| PR | 담는 것 | 시작 조건 | 요구사항 |
| --- | --- | --- | --- |
| PR1 | 답 안에 그림 보이기, 크게 보기와 내려받기, 자세한 그림 지시문, 보관함에 남기기 | 없음. 이미지 서비스가 이미 설정된 관리자 비서로 확인한다 | REQ1~REQ10 |
| PR2 | 가족의 기본 비서에 「그림 만들기」 켜기, 이미지 서비스 자동 설정, 사람이 없는 실행에서 막기 | PR1 이 main 에 머지됐다 | REQ11~REQ14 |
| PR3 | 지금 대화의 사진과 그림을 바탕으로 고치기 | PR2 가 main 에 머지됐다 | REQ15~REQ17 |
| PR4 | 만든 그림을 블로그 원고의 사진 자리에 넣기 | PR3 이 main 에 머지됐다 | REQ18~REQ19 |
| PR5 | 사용자가 보낸 링크의 사진을 참고 그림으로 쓰기 | PR3 이 main 에 머지됐다 | REQ20~REQ23 |
| PR6 | 그림 지시문 틀(인물, 옷차림, 비율, 구도) | PR5 가 main 에 머지됐다 | REQ24~REQ26 |

범위 밖:

- 「파일 공간」 을 한 목록에서 쉽게 찾는 화면으로 바꾸는 일. 후속 스펙으로 따로 정한다(DECISION9)
- 사용자별 하루 장수 상한을 비롯한 구독 한도 보호 장치(DECISION6)
- 관리자 화면에서 이미지 서비스를 고르는 설정. 서비스는 ChatGPT 구독의 gpt-image-2 하나다(DECISION5)
- 예약 작업과 먼저 살펴보기에서 그림 만들기(DECISION14)
- 그림 자리의 실패 표시 칸과 「다시 만들기」 단추(DECISION15)
- 다른 대화의 사진이나 보관함의 그림을 바탕으로 고치기(DECISION19)
- 그룹 공개 비서에서 그림 만들기. 지금처럼 주인 혼자 쓰는 비서에서만 켜진다(DECISION21)
- 동영상 만들기
- 비서가 검색해 찾은 페이지의 사진을 참고 그림으로 쓰기. 사용자가 이 대화에 보낸 링크만 쓴다(DECISION34)
- 상품 페이지 안의 여러 사진 가운데 골라 쓰기. 대표 사진 하나만 쓴다(DECISION35)

## 요구사항과 인수 조건

인수 조건은 가짜 Hermes 와 테스트용 그림 파일로 확인한다.
실제 이미지 서비스로 한 장을 만들어 보는 확인은 PR 마다 배포 뒤 운영에서 사용자가 한다. 절차는 운영 저장소가 갖는다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 비서가 만든 그림은 그 답 안에 그림으로 보인다. 비서가 다른 에이전트에게 맡긴 실행이 만든 그림은 그 결과를 전하는 답에 보인다. 중지한 답도 답 글이 남았으면 그때까지 만든 그림이 보인다. 답 글에 파일 경로나 `MEDIA:` 글자가 보이지 않는다 | 그림을 만든 답을 열면 답 글 아래에 그림이 화면 폭에 맞춰 보이고, 답 글에 경로 글자가 없다. 대화를 다시 열어도 같다 |
| REQ2 | 한 답에서 여러 장을 만들면 만든 순서대로 나란히 보인다 | 두 장을 만든 답에 그림 두 장이 만든 순서로 보인다 |
| REQ3 | 그림을 누르면 화면 가득 크게 보이고, 그 화면에 「내려받기」 단추가 있다. 휴대폰 폭에서도 같고 두 손가락으로 확대할 수 있다 | 넓은 화면과 휴대폰 폭에서 그림을 누르면 크게 보기 화면이 열린다. 「내려받기」 로 받은 파일은 만든 원본과 바이트가 같고 파일 이름은 그림 제목이다 |
| REQ4 | 비서는 사용자의 짧은 부탁을 그대로 넘기지 않고, 그릴 대상과 구도, 화풍, 조명, 지킬 것을 담은 자세한 그림 지시문으로 바꿔 이미지 도구에 넘긴다 | 비서가 받는 지침에 이 규칙이 있다. 가짜 Hermes 가 지침을 따라 넘긴 지시문이 사용자의 부탁 글과 다르고 더 길다 |
| REQ5 | 그림 아래에 「그림 지시문 보기」 가 접힌 채 있고 누르면 비서가 이미지 도구에 넘긴 지시문이 펼쳐진다. 크게 보기 화면에서도 볼 수 있다 | 처음에는 지시문이 보이지 않고, 누르면 이미지 도구에 넘긴 지시문과 같은 글이 보인다 |
| REQ6 | 비서는 그림마다 짧은 한국어 제목을 붙인다. 제목은 크게 보기 화면, 내려받는 파일 이름, 보관함 목록에 쓴다. 같은 대화에서 제목이 겹치면 뒤에 번호를 붙인다. 비서가 제목을 주지 않으면 만든 날짜와 시각을 제목으로 쓴다 | 「수채화 고양이」 를 두 번 만들면 둘째 그림의 제목이 「수채화 고양이 2」 다 |
| REQ7 | 만든 그림은 원본 해상도 그대로 요청자의 「보관한 결과물」 에 자동 보관된다. 보관 상태(「보관 중」, 「보관 완료」, 「보관 실패」 와 까닭)는 그림 아래에 기존 결과물과 같은 글자로 보인다. 보관본이 없는 그림은 크게 보기 화면에 「보관」 단추가 보이고 누르면 직접 보관한다. 자동 보관을 껐을 때, 중지한 답일 때, 보관이 실패했을 때, 보관본을 지웠을 때가 여기 해당한다. 대화를 지워도 보관본은 남는다 | 자동 보관을 켠 사용자가 그림을 만든 답이 끝나면 「보관한 결과물」 에 그 그림이 있고 내려받은 파일이 원본과 바이트가 같다. 대화를 지운 뒤에도 열린다. 자동 보관을 끈 사용자는 「보관」 을 누른 뒤에만 있다 |
| REQ8 | 「보관한 결과물」 목록에서 그림은 제목과 작은 그림으로 보인다 | 보관함 목록의 그 줄에 제목과 작은 그림이 보이고, 누르면 그림 전체가 보인다 |
| REQ9 | 보관 기간 정리로 대화 쪽 원본이 지워진 그림은, 대화의 그 자리에 보관 기간이 지났다는 안내와 「보관함에서 보기」 링크가 보인다. 보관본이 없으면 안내만 보인다. 지시문은 대화에 그대로 남는다 | 원본을 지운 뒤 대화를 열면 그림 대신 안내와 링크가 보이고, 링크를 누르면 보관함의 그 그림이 열린다. 보관본까지 지우면 링크가 없다 |
| REQ10 | 만든 그림과 지시문은 그 대화의 주인만 본다. 이미지 서비스의 한도 소진이나 오류, 만들 수 없는 내용으로 이미지 도구가 실패하면 비서가 그림 없이 까닭과 다시 부탁하는 방법을 답 글로 알린다. 한도 소진으로 비서의 답 자체가 멈추면 지금의 실행 실패 표시가 그대로 보인다 | 다른 사용자가 그 그림의 주소를 열면 없는 대화와 같은 응답을 받는다. 이미지 도구가 실패한 답에는 그림 자리가 없고 답 글만 보이며 실행은 실패로 끝나지 않는다 |

| REQ12 | 「그림 만들기」 를 켜면 Control Plane 이 그 비서에 이미지 서비스 설정을 함께 넣는다. 홈서버에서 따로 설정하지 않는다. 설정을 넣지 못하면 켜기가 실패하고 화면이 알린다 | 이미지 서비스 설정이 없던 비서에 「그림 만들기」 를 켜면 그 profile 의 설정에 이미지 서비스가 들어 있다. 설정 쓰기가 실패하면 도구가 켜지지 않고 오류가 보인다 |
| REQ13 | 기본 비서의 실행 공간이 준비되지 않아 「그림 만들기」 를 켜지 못하면 Control Plane 이 그 사용자의 실행 공간 준비를 요청 밖에서 시작하고, 준비가 끝나면 「그림 만들기」 를 스스로 켠다. 관리자가 직접 켜지 않아도 된다. Control Plane 이 스스로 할 수 없는 준비 단계가 있으면 그 단계만 관리자에게 알림으로 남기고, 관리자가 그 단계를 마치면 이어서 켠다. 관리자가 일부러 끈 비서는 배포나 재시작, 이 준비 과정으로 다시 켜지지 않는다 | 실행 공간이 없는 사용자의 기본 비서는 준비가 끝난 뒤 「그림 만들기」 가 켜져 있고 그동안 대화는 그대로 된다. 준비가 실패하면 관리자 알림에 사용자와 까닭이 보인다. 관리자가 끈 비서는 Control Plane 을 다시 띄워도 꺼져 있다 |
| REQ14 | 사람이 없는 실행에서는 그림을 만들지 않는다. 사람이 없는 실행은 예약 작업 turn, 먼저 살펴보기 turn(단추로 연 것 포함), 그 실행이 맡긴 일의 결과를 전하는 turn 이다. 예약 작업 대화나 점검 대화라도 사람이 직접 보낸 메시지의 turn 에서는 만든다. 그 실행이 맡긴 하위 실행도 같다. 비서는 그 실행의 결과에 그림을 만들 수 없다고 적는다 | 사람이 없는 실행에서 이미지 도구 호출이 막히고 그림 파일이 생기지 않는다. 같은 비서가 사람이 연 대화에서는 그림을 만든다 |
| REQ15 | 지금 대화에 올린 사진과 그 대화에서 만든 그림을 바탕으로 고친 그림을 만든다. 바탕 한 장에 참고 사진 여러 장을 함께 쓸 수 있다. 결과는 새 그림이고 바탕 사진은 바뀌지 않는다 | 사진 세 장을 올리고 「1번 사진의 신발만 3번 사진의 것으로 바꿔 줘」 라고 하면 이미지 도구가 그 세 장을 입력으로 받고, 답에 새 그림이 REQ1 과 같이 보인다. 올린 사진의 바이트는 그대로다 |
| REQ16 | 바탕과 참고로 쓸 수 있는 것은 요청자가 지금 대화에 보낸 사진과 그 대화에서 만든 그림뿐이다. 다른 대화의 사진, 다른 사용자의 사진, 지웠거나 보관 기간이 지난 사진은 쓰지 못한다. 가리킨 사진 가운데 한 장이라도 쓸 수 없으면 그림을 만들지 않고 비서가 어느 사진을 왜 쓸 수 없는지 알린다 | 다른 대화의 첨부 번호나 지운 사진을 가리키면 이미지 도구에 사진이 전달되지 않고 비서가 쓸 수 없다고 답한다 |
| REQ17 | 고칠 때의 지시문은 바꿀 곳, 지킬 곳, 참고 사진의 어느 부분을 쓰는지를 적는다. 올린 사진은 그 대화에서 몇 번째 사진인지로, 만든 그림은 제목으로 가리킨다 | 비서가 받는 지침에 이 규칙이 있고, REQ15 의 실행에서 넘긴 지시문에 사진 번호와 바꿀 곳, 지킬 곳이 있다 |
| REQ18 | 지금 대화에서 만든 그림을 블로그 원고의 사진 자리에 넣을 수 있다. 원고 미리보기와 네이버 임시저장에 그 그림이 들어간다 | 그림을 만든 뒤 「이 그림을 글 맨 위에 넣어 줘」 라고 하면 원고 미리보기의 그 자리에 그림이 보이고, 가짜 네이버 저장에 그 그림 파일이 올라간다 |
| REQ19 | 보관 기간이 지나 대화 쪽 원본이 없는 그림은 원고에 넣지 못하고 비서가 까닭을 알린다. 이미 원고에 넣은 그림은 올린 사진과 같은 규칙으로 원고에 남는다 | 원본을 지운 그림을 넣어 달라고 하면 원고가 바뀌지 않고 비서가 넣을 수 없다고 답한다 |
