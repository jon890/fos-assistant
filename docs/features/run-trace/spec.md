# 실행 기록에 모델 호출마다의 시간과 토큰, 도구마다의 시간과 실패 원인을 남긴다

## 목표

관리자가 실행 하나를 열면 그 실행이 모델을 언제 몇 번 불렀고 한 번에 얼마나 걸렸는지, 도구가 각각 얼마나 걸렸고 실패한 도구가 무엇이었는지 본다.
그래서 「어느 호출이 왜 느렸는지」 를 외부 관찰 서비스 없이 우리 실행 기록만으로 안다(사용자 결정 2026-11-24: Langfuse 같은 외부 서비스 대신 우리 실행 기록에 더 남긴다).

지금은 아래와 같다(2026-11-24).

- 실행 줄에는 실행 한 번의 토큰 합계와 네 시각만 남는다([`backend/docs/data-schema.md`](../../../backend/docs/data-schema.md) 의 「agent_execution」). 합계는 Hermes 가 끝난 실행에만 주므로, 시간 제한에 걸려 끝난 실행은 토큰이 비어 있다
- 모델을 몇 번 불렀는지, 한 번에 얼마나 걸렸는지는 어디에도 없다. Runs API 의 `usage` 는 합계뿐이고 사건 스트림에도 모델 호출 사건이 없다([`hermes-contract.md`](../../../hermes/docs/hermes-contract.md) 의 「plugin hook」, 「실행 이벤트가 실제로 오는 형태」)
- 실행 상세의 도구 줄이 모두 0ms 로 보인다. Hermes v0.23.2 의 실행 대기열 경로는 `tool.completed` 의 `duration` 을 늘 0 으로 보내고(같은 문서), 화면은 값이 없을 때도 0 으로 그린다(`web/src/components/execution/execution-event-row.tsx`)
- 실패한 도구는 실패했다는 것만 남는다. v0.23.2 의 완료 사건에는 결과 `preview` 가 없어 오류 내용이 오지 않는다(상류 `gateway/platforms/api_server_runs.py`)
- 플러그인 도구를 부른 트리의 뒤쪽 도구는 「[도구 내용 가림: 0자]」 로 보인다. 플러그인 호출 뒤에는 내용의 길이만 남기는 규칙(#319)이 빈 내용에도 그 문구를 붙인다(`ToolDetailRedactor`)
- 실제 사례: 커리어 브리핑 실행 1981 은 모델 왕복 약 21번(한 번에 10~26초)과 collect 도구 78초로 5분을 넘겼다. 호출마다의 시간과 토큰이 없어 무엇을 망설였는지 보지 못했다

Hermes 는 core 를 고치지 않고도 이 값을 plugin hook 으로 준다(v0.23.2 소스로 확인, 2026-11-24).

| hook | 주는 것 |
| --- | --- |
| `post_api_request` | 모델 호출 하나의 시작·끝 시각, 첫 조각 시각, 실제 모델과 provider, 입력·출력·캐시 읽기·캐시 쓰기·reasoning 토큰, 끝난 이유, 그 응답이 부른 도구 수 |
| `api_request_error` | 실패한 모델 호출의 시각, 상태 코드, 오류 종류, 다시 시도한 횟수 |
| `post_auxiliary_call` | 문맥 압축, 제목 만들기, 사진 판독 같은 보조 모델 호출. 모양은 `post_api_request` 와 같고 `aux_task` 가 붙는다 |
| `post_tool_call` | 도구 하나의 걸린 시간(ms), 성공·실패, 오류 종류와 오류 글 |

hook 은 요청과 응답의 본문(대화 내용, 시스템 프롬프트)도 함께 받는다. 이 스펙은 본문을 plugin 밖으로 보내지 않는다(REQ6).

## 범위

이 스펙은 PR 셋으로 구현한다(DECISION4).

| PR | 담는 것 | 시작 조건 | 요구사항 |
| --- | --- | --- | --- |
| PR1 | 도구의 걸린 시간과 실패한 도구의 오류 요약. plugin 이 도구 결과를 Control Plane 에 보내는 길을 이 PR 이 처음 만든다 | 없음 | REQ1-REQ3, REQ6, REQ7 |
| PR2 | 모델 호출 기록. plugin 의 모델 호출 hook, Control Plane 의 받는 길과 저장 | PR1 이 main 에 머지됐다 | REQ4-REQ8, REQ10 |
| PR3 | 관리자 실행 상세에 모델 호출 기록을 보인다 | PR2 가 main 에 머지됐다 | REQ9 |

PR2 가 PR3 보다 먼저 배포되므로 화면을 만드는 동안에도 기록이 쌓인다.

**하지 않는 것.**

- 외부 관찰 서비스(Langfuse 등)로 보내는 것(사용자 결정 2026-11-24)
- 모델에 보낸 글과 받은 글, 시스템 프롬프트를 남기는 것(DECISION1)
- 성공한 도구의 결과를 남기는 것(DECISION2)
- 사용자에게 모델 호출 기록을 보이는 것, 관리자가 남의 실행 상세를 여는 것(DECISION3, [`admin-area/spec.md`](../admin-area/spec.md) DECISION10)
- 이 기능이 생기기 전의 실행을 다시 계산하는 것. 옛 실행의 도구 시간은 「모름」 이고 모델 호출 기록은 없다(DECISION7)
- 모델 호출마다의 토큰을 사용량 합계와 금액에 더하는 것. 합계와 금액은 지금처럼 실행 줄의 값으로 낸다(DECISION8)
- Hermes core 를 고치는 것

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 도구 줄은 실제로 걸린 시간을 보인다. 걸린 시간을 알 수 없으면 「모름」 을 보이고 0ms 로 보이지 않는다 | Hermes v0.23.2 모양(완료 사건의 `duration` 이 0)으로 1.2초 걸린 도구를 흘리면 실행 상세(`/executions/{id}`, `/admin/executions/{id}`)와 대화의 「자세히 보기」 패널의 그 도구 줄에 약 1.2초가 보인다. 시작 사건이 없거나 시각을 알 수 없는 완료 사건의 줄은 「모름」 이다. 이 기능 전의 실행은 「모름」 이다 |
| REQ2 | 실패한 도구에는 오류 요약을 남긴다. 요약은 200자까지이고 도구 내용과 같은 가림 규칙(ADR-047)을 거친다. 플러그인 도구와 플러그인 호출 뒤의 도구는 오류 종류만 남긴다 | 비밀값 모양의 글과 UUID 가 든 오류로 실패한 일반 도구의 줄을 관리자 실행 상세에서 열면 가린 오류 요약이 200자 안으로 보인다. 플러그인 도구가 실패하면 오류 종류(예: 시간 초과)만 보이고 오류 글은 저장되지 않는다. 성공한 도구에는 오류 요약이 없다 |
| REQ3 | 오류 요약 글은 관리자 영역에서만 보인다. 도구의 걸린 시간과 실패 표시는 지금처럼 모든 사용자에게 보인다 | `MEMBER` 역할로 자기 실행 트리를 읽으면 응답의 오류 요약 칸이 `null` 이고 실패 표시와 걸린 시간은 있다. `ADMIN` 은 `/admin/executions/{id}` 에서 오류 요약을 본다 |
| REQ4 | 모델 호출 하나마다 기록 한 줄을 남긴다. 칸은 시작·끝 시각(걸린 시간), 첫 조각까지 시간, 실제 모델과 provider, 입력·출력·캐시 읽기·캐시 쓰기·reasoning 토큰, 끝난 이유, 그 응답이 부른 도구 수다. 실패한 호출과 보조 호출(문맥 압축, 제목 만들기, 사진 판독 등)도 종류를 붙여 남긴다. 실패한 호출은 상태 코드와 오류 종류, 다시 시도한 횟수를 남긴다 | 가짜 Hermes 로 모델 호출 셋(정상 둘, 429 한 번)과 문맥 압축 하나가 있는 실행을 돌리면 그 실행에 기록 네 줄이 위 칸과 함께 남는다. 시간 제한에 걸려 실패로 끝난 실행에도 그때까지의 호출 기록이 남는다 |
| REQ5 | 모델 호출 기록은 그 호출을 한 실행에 붙는다. 최상위 session 의 호출은 그 실행, 다른 에이전트에게 맡긴 실행(`agent_delegate`)의 호출은 그 자식 실행, Hermes 내장 하위 에이전트의 호출은 그 하위 에이전트를 만든 실행에 붙고 어느 도우미의 호출인지 남는다 | 세 경우를 한 트리에서 돌리면 각 호출 기록이 위 실행에 붙고, 내장 하위 에이전트의 호출에는 그 하위 에이전트의 session 이 남는다. 다른 사용자의 실행에는 붙지 않는다 |
| REQ6 | 모델에 보낸 글과 받은 글, 시스템 프롬프트, 도구 인자와 결과의 원문은 plugin 밖으로 나가지 않는다. 오류 글은 REQ2 의 요약만 나간다 | plugin 이 Control Plane 에 보내는 본문에 대화 내용, 프롬프트, 도구 인자 칸이 없다. 가짜 hook 인자의 본문 자리에 넣은 표식 글이 Control Plane 의 저장값과 로그 어디에도 없다 |
| REQ7 | 기록을 보내는 일이 실행을 늦추거나 실패시키지 않는다. 보내지 못한 기록은 버리고 실행은 그대로 끝난다 | Control Plane 의 받는 길이 5초 늦게 답하거나 500 을 돌려줘도 hook 은 기다리지 않고, 실행이 같은 결과로 끝난다. plugin 로그에는 실패 종류만 남는다 |
| REQ8 | 모델 호출 기록은 `MEMBER` 역할에게 보내지 않는다 | `MEMBER` 역할로 자기 실행 트리를 읽으면 응답에 모델 호출 기록이 없다. 대화 스트림과 대화의 「자세히 보기」 패널에도 없다 |
| REQ9 | 관리자 실행 상세에 모델 호출 기록을 보인다. 모양은 DECISION6 이 정한다 | (결정 라운드 2 뒤 채운다) |
| REQ10 | 모델 호출마다의 토큰은 사용량 합계와 금액에 더하지 않는다 | 모델 호출 기록이 있는 실행과 없는 실행의 월 합계, 실행 한 줄의 토큰과 금액이 이 기능 전과 같은 규칙으로 나온다 |

## 결정

| ID | 결정 | 답 | 누가 | 근거 |
| --- | --- | --- | --- | --- |
| DECISION1 | 모델 호출마다 남길 것 | 숫자만 넓게. REQ4 의 칸을 남기고, 실패한 호출과 보조 호출도 종류를 붙여 남긴다. 본문은 남기지 않는다 | 사용자 2026-11-24 | 「왜 느렸는지」 는 시간, 토큰, 다시 시도, 압축으로 대부분 설명된다. 본문을 남기지 않으면 개인정보와 비밀값의 경계가 지금과 같다 |
| DECISION2 | 도구마다 남길 것 | 걸린 시간을 채우고 모르면 「모름」. 실패한 도구에 오류 요약 200자를 지금 가림 규칙으로 남긴다. 성공한 도구의 결과는 남기지 않는다 | 사용자 2026-11-24 | 실패 원인을 보는 것이 목적이다. 결과 본문까지 남기면 가림 규칙이 지키는 경계가 넓어진다 |
| DECISION3 | 누가 어디서 보나 | 모델 호출 기록은 관리자 영역에만 그리고 `MEMBER` 역할 응답에서 뺀다. 도구의 걸린 시간과 실패 표시는 지금처럼 모두에게 보인다. 오류 요약 글은 도구 원문처럼 관리자 영역에서만 보인다 | 사용자 2026-11-24 | 관리자 전용 값 규칙(ADR-063)과 도구 원문 규칙(ADR-038)을 그대로 따라 새 경계가 생기지 않는다 |
| DECISION4 | PR 순서 | 도구 먼저. PR1 도구 시간과 오류 요약, PR2 모델 호출 기록(plugin, 받는 길, 저장), PR3 관리자 화면 | 사용자 2026-11-24 | 작고 위험이 낮은 고침이 먼저 들어가고, 저장이 화면보다 먼저 배포되어 기록이 일찍 쌓인다 |
| DECISION5 | 값을 얻는 곳 | 모델 호출과 도구 오류는 fos-ctx plugin 의 hook(`post_api_request`, `api_request_error`, `post_auxiliary_call`, `post_tool_call`)으로 받는다. 도구 시간은 hook 의 값을 쓰고, hook 의 기록이 없으면 Hermes 사건의 시작·완료 시각 차이로 채운다 | 작성자 | Hermes core 를 고치지 않는 원칙(AGENTS.md). 사건 스트림에는 모델 호출 사건과 오류 내용이 없다. 시작·완료 사건에는 `tool_call_id` 와 소수점 초 시각이 있다. 오류 요약에 hook 이 필요하므로 PR1 이 plugin 에서 Control Plane 으로 보내는 길을 처음 만든다 |
| DECISION6 | 저장 자리 | `execution_event` 의 새 사건 종류와 칸으로 적는다. 새 테이블을 만들지 않는다 | 작성자 | 테이블을 늘리지 않는다(사용자 결정 2026-11-01). 이 표에 이미 `duration_ms`, `model`, 토큰 칸이 있고, 실행 하나에 딸린 사건 기록이라는 수명이 같다 |
| DECISION7 | 옛 실행 | 다시 계산하지 않는다. 옛 도구 줄은 「모름」, 모델 호출 기록은 없다 | 작성자 | 옛 사건에는 `tool_call_id` 가 저장되지 않아 병렬 도구의 짝을 확실히 지을 수 없다. 모델 호출 값은 어디에도 남아 있지 않다 |
| DECISION8 | 사용량 합계와의 관계 | 호출마다의 토큰은 보이기만 하고 합계와 금액은 실행 줄 값으로 낸다 | 작성자 | 하위 에이전트 사건의 토큰과 같은 규칙이다(data-schema 「execution_event」). 두 출처를 더하면 두 번 센다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: 실행 기록 보존(rule-49), 도구 내용 가림(ADR-047), 도구 원문의 관리자 전용(ADR-038), 관리자 전용 값(ADR-063)을 그대로 따른다.
