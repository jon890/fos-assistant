# 터미널 기본: 모든 에이전트가 격리된 실행 공간에서 셸, 파일, 코드 실행을 쓴다

확인: 2026-11-20

## 목표

사용자가 어느 에이전트와 대화하든 그 에이전트가 셸, 파일, 코드 실행을 쓸 수 있다.
셸은 언제나 격리된 실행 공간 안에서만 돈다. Hermes 프로세스 안(local)에서 도는 셸은 없다.

지금은 아래와 같다.

- 기본 비서만 실행 공간이 있을 때 `terminal`, `file`, `code_execution` 을 켜고 시작한다([ADR-20261008 / default-toolsets](../../adr/ADR-20261008-default-toolsets.md)).
- 셸 계열은 관리자 등급이라 관리자만 켜고 끈다(`AgentToolPolicy`, [ADR-029](../../../backend/docs/adr/ADR-029-에이전트-도구는-control-plane-이-등급으로-판정하고-hermes-설정-api-로-쓴다.md)).
- 사용자가 만든 에이전트와 역할 profile 은 셸이 꺼진 틀로 만든다(`hermes/profile-template/config.yaml.template`, `AgentLifecycleService`).
- 실행 공간 정책은 profile 이름마다 한 줄씩 등록하는 목록이다. 관리자 화면의 도구 저장은 목록에 없는 profile 에서 셸을 local 로 켠다(`hermes/plugins/dashboard-profile-api/toolconfig.py`). 그 셸은 다른 profile 의 `.env`, 플러그인 값 파일, 전체 첨부에 닿는다([ADR-086](../../adr/ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md)).
- 그룹 공개 에이전트에는 셸 계열을 켜지 못한다. 실행 공간이 주인 기준이라 그룹 사용자가 주인의 `/workspace` 를 함께 쓰기 때문이다.
- 셸 계열이 켜진 에이전트는 주인을 바꾸지 못한다(`AGENT_OWNER_CHANGE_REQUIRES_SHELL_OFF`).
- 사람이 없는 실행(먼저 살펴보기, 매일 깨우기, 사건 실행)은 셸, 파일, 코드 실행 호출을 막는다([ADR-082](../../adr/ADR-082-먼저-살펴보기의-쓰기-도구는-관리자가-에이전트마다-켜고-커넥터-쓰기는-승인-카드로-보낸다.md), [ADR-20261105 / event-watch](../../adr/ADR-20261105-event-watch.md)). 매일 깨우기는 격리 스위치(`isolated-execution-enabled`)로도 막혀 있다([ADR-085](../../adr/ADR-085-매일-깨우기는-예약-작업을-다시-쓰고-다섯-칸-보고를-지금-화면에-올린다.md)).

## 범위

셸, 파일, 코드 실행(`terminal`, `file`, `code_execution`, 아래 「셸 계열」)을 모든 에이전트의 기본으로 켜고, 격리 전 이유로 남은 제한을 없앤다.

**범위 밖이다.**

- `browser`, `computer_use`, `session_search` 처럼 실행 공간 밖에서 도는 관리자 등급 도구. 등급과 그룹 공개 금지를 그대로 둔다
- 사진 계열(`vision`, `image_gen`, `video_gen`)의 등급. 지금 규칙을 그대로 둔다
- 밖으로 나가는 망의 제한. 지금처럼 열어 두고 기록한다(ADR-086)
- 비밀값을 요청하는 옛 스킬이 있는 에이전트의 셸 금지(DECISION8)
- fos-ctx 가 막는 셸 위험 명령, 승인 경로 쓰기, `computer_use`([ADR-20261008 / execute-code-unattended](../../../hermes/docs/adr/ADR-20261008-execute-code-unattended.md)). 셸 자체가 아니라 승인할 사람이 없는 위험 동작을 막는 장치라 그대로 둔다
- 사건 실행의 위임 도구 차단. 셸 계열만 푼다
- 같은 사용자의 에이전트끼리 `/workspace` 를 함께 쓰는 것, 컨테이너 수 상한, 디스크 한도. 지금 운영 방식을 그대로 둔다

이 스펙은 PR 다섯으로 구현한다(DECISION11). 첫 PR 은 local 셸의 빈틈을 막는다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 셸 계열 도구는 격리된 실행 공간에서만 돈다 | 정책에 없는 profile 에 셸 계열을 켜는 관리자 저장이 local 로 켜지지 않고 거절된다. 어떤 경로의 도구 저장도 profile 의 `terminal.backend` 를 local 로 쓰지 않는다. 배포 뒤 셸 계열이 켜진 에이전트는 모두 docker 실행 공간이거나, 정책 밖이면 셸 계열이 꺼져 있다 |
| REQ2 | 정책 목록에 없는 profile 도 기본 실행 공간으로 바로 격리된다 | 정책에 기본 줄이 있으면 목록에 없는 profile 의 셸 저장이 docker 실행 공간으로 쓰이고, 그 셸이 그 사용자의 `/workspace` 만 본다. 목록에 있는 profile 은 자기 줄의 마운트와 망을 쓴다 |
| REQ5 | 모든 에이전트가 셸 계열을 켠 채 만들어지고 주인이 끌 수 있다 | 기본 비서, 사용자가 만든 에이전트, 역할 profile 을 만든 직후 셸 계열이 켜져 있다. `MEMBER` 역할의 주인이 확인 창 없이 끄고 다시 켠다 |
| REQ3 | 그룹 공개 에이전트는 에이전트 전용 공간에서 셸을 쓴다 | 그룹 공개 에이전트에 셸 계열을 켤 수 있다. 그 셸은 주인의 `/workspace` 파일을 보지 못하고, 그 에이전트를 쓰는 그룹 사용자끼리 같은 공간을 본다. 그 에이전트가 대화에서 「내 파일」 로 내준 파일은 요청한 사람의 「내 파일」 에 들어간다. 작업 폴더 화면에는 에이전트 공간이 보이지 않는다. `PRIVATE` 로 되돌리면 주인 공간으로 돌아간다 |
| REQ7 | 셸이 켜진 에이전트도 주인을 바꿀 수 있다 | 셸 계열이 켜진 에이전트의 주인을 바꾸면 다음 실행의 셸이 새 주인의 `/workspace` 를 보고, 옛 주인의 파일은 보이지 않는다 |
| REQ4 | 사람이 없는 실행도 셸 계열을 쓴다 | 먼저 살펴보기, 매일 깨우기, 사건 실행에서 셸 계열 호출이 막히지 않고 실행 기록에 남는다. 셸 계열이 켜진 에이전트에서도 매일 깨우기가 시작된다 |
| REQ6 | 사람이 없는 실행이 셸 계열을 쓰면 사용자에게 알린다 | N 은 셸, 파일, 코드 실행 호출을 모두 센 수다. 결과(지금 화면의 보고, 알림)가 있으면 거기에 「셸 명령 N개를 실행했다」 와 실행 기록 링크가 붙는다. 결과가 남지 않는 실행이라도 셸 계열을 썼으면 같은 내용의 알림 하나가 생긴다. 조용한 시간에는 지금 규칙대로 미룬다. 쓰지 않았으면 아무것도 보이지 않는다 |
| REQ8 | 이미 있는 에이전트에도 셸 계열이 켜진다 | PR3 배포 뒤 기존 `PRIVATE` 에이전트, PR4 배포 뒤 기존 그룹 공개 에이전트에 셸 계열 셋이 모두 켜진다. 비밀값 요청 스킬이 있는 에이전트와 옛 커넥터 에이전트는 꺼진 채 남는다. 한 번 켠 뒤 주인이 끈 것은 다시 켜지지 않는다 |
| REQ9 | 화면 문구가 바뀐 규칙과 맞는다 | 도구 화면에 셸 계열의 관리자 확인 창과 「관리자만」 표시가 없다. 연결 붙이기 확인 창은 「격리하지 않은 profile 이면 비밀값을 읽는다」 는 문장 없이 「읽은 내용을 인터넷으로 보낼 수 있다」 만 알린다 |

| DECISION13 | 화면 문구 | 셸 계열의 관리자 확인 창과 관리자 등급 표시를 없앤다. 연결 붙이기 확인 창의 셸 위험 문구에서 「격리하지 않은 profile」 경우를 뺀다. 스크립트 스킬 올리기의 「셸을 켜 주세요」 는 주인이 직접 켜는 말로 둔다 | 작성자 | DECISION1, DECISION6 이 정한 동작을 그대로 옮긴 문구다(`web/src/lib/agent-connection.ts`, `agent-tools-section.tsx`, `skill-package-upload.tsx`) |
| DECISION14 | 사진 계열이 켜진 에이전트 | 주인 바꾸기의 실행 공간 다시 쓰기(DECISION9)는 사진 계열을 포함한 실행 공간 도구 전체에 적용한다. 그룹 공개 금지는 사진 계열에 그대로 둔다 | 작성자 | 사진 계열도 같은 실행 공간 설정을 쓴다(`AgentToolPolicy.SANDBOX_TOOLSETS`). 에이전트 전용 공간에는 사진 첨부를 붙이지 않아(DECISION4) 그룹 공개에서 사진 도구가 동작하지 않는다. 사진 계열의 규칙은 「범위」 에서 범위 밖이다 |
| DECISION15 | 만들 때 실행 공간을 준비하지 못할 때 | 셸 계열 없이 만들고 경고 로그를 남긴다. 만들기는 실패시키지 않는다. 주인이 화면에서 다시 켠다 | 작성자 | 기본 도구 쓰기 실패의 지금 규칙([ADR-20261008 / default-toolsets](../../adr/ADR-20261008-default-toolsets.md))과 같다. DECISION3 의 기본 줄이 있으면 정책이 없거나 틀릴 때만 생긴다 |
| DECISION16 | 주인 없는 에이전트(역할 profile 일부) | 셸 계열을 켜고 끄는 사람은 `ADMIN` 이다. 실행 공간은 지금처럼 `a<에이전트 번호>` 다 | 작성자 | 주인 등급 도구는 주인과 `ADMIN` 이 켠다(ADR-029). 주인이 없으면 `ADMIN` 만 남는다. `a<에이전트 번호>` 는 그룹 공개의 에이전트 전용 공간과 같은 뜻이다 |
