# 기억 요약과 상세 두 층

확인: 2026-11-20

## 목표

비서가 사용자의 사정을 늘 알고, 일을 맡길 때 사용자가 자기 상황을 다시 설명하지 않게 한다.
개인 기억마다 「늘 보이는 짧은 요약 한 줄」 과 「도구로 꺼내 보는 상세」 를 두어, 요약은 매 실행에 들어가고 상세는 비서가 필요할 때 읽는다.

지금은 본문이 200자 이하인 개인 기억만 매 실행에 본문까지 들어가고(개인 사실 구역, 2,000자), 나머지는 제목만 보인다.
그 구역이 기억 20개로 거의 찼고, 이직·가계부·여행처럼 사용자 사정이 답을 바꾸는 질문에서 비서가 알고 있는 것을 쓰지 않았다(2026-11-20 사용자).

## 범위

이번 범위:

- 사용자(`USER`) 범위의 기억(`MEMORY` 종류)에 요약 줄을 둔다. 요약 줄이 있는 기억은 요약이 매 실행에 들어가고, 없는 기억은 상세에만 있다
- 지금의 개인 사실 구역을 「요약 구역」 으로 바꾼다. 예산과 기억 전체 상한은 관리자가 화면에서 바꾼다
- 비서가 기억을 남기고 고칠 때 요약 줄도 함께 쓰고, 겹치는 기억을 하나로 합친다
- 비서가 상세를 언제 꺼내는지의 지침과 그 평가 사례
- 배포 때 지금 기억을 새 구조로 옮긴다
- 기억 화면(`/memory`)과 관리자 「기억」 화면(`/admin/memory`)
- 정비 루프가 고친 요약 문장을 제안하고, 사용자가 받아들여야 바뀐다

범위 밖:

- 그룹(`GROUP`) 기억. 지금처럼 관리자가 항상 넣기(`ALWAYS`)를 켜거나 제목만 보인다
- 문서(`DOCUMENT`)와 출처 원문(`SOURCE`). 문서는 지금처럼 제목만 보이고 `memory_read` 로 읽는다. 상세만 있는 기억과 같은 자리다
- 질문과 관련된 기억 구역(최대 3건, 1,500자)의 값. 그대로 둔다
- 비서가 기억 전체를 한 장으로 다시 쓰는 요약. [ADR-20261008 / memory-facts](../../adr/ADR-20261008-memory-facts.md) 가 기각한 그대로다. 요약은 기억마다 한 줄이고 고친 이력에 남는다
- 사용자마다 다른 예산. 예산은 그룹에 하나다

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 사용자 범위의 기억 하나는 요약 줄(선택, 한 줄 200자 이하)과 상세(지금의 본문)를 함께 가진다. 요약 줄도 제목, 본문과 같이 주인 key 로 암호화하고, 고치면 고친 이력에 남는다 | 요약 줄을 쓰고 고치고 지운 기억의 판 기록에 이전 요약이 남는다. DB 에 요약 평문이 없다(암호화 필수 설정에서). 그룹 기억과 문서에 요약을 넣으려는 요청은 `VALIDATION_FAILED` 다 |
| REQ2 | 매 실행에 요청자의 요약 줄이 있는 기억 가운데 꺼내는 방식이 `SEARCH` 인 것을 요약 구역에 `- [번호] 제목: 요약` 꼴로 넣는다. 그 에이전트가 받는 collection 의 기억만 넣는다. 상세는 요약 구역에 넣지 않고, 질문과 관련된 기억 구역의 후보로 남겨 질문에 맞으면 자동으로 넣는다 | 요약 줄이 있는 기억은 질문과 상관없이 매 실행의 지시문에 요약으로 들어가고, 받지 않는 collection 의 기억은 들어가지 않는다. 질문과 맞는 기억은 요약과 함께 상세도 질문 관련 구역에 들어간다. 요약 줄이 없는 기억은 색인에 제목만 있고 `memory_search` 로 찾힌다. `ALWAYS` 인 기억은 지금처럼 항상 층에 본문이 들어가고, `ARCHIVE` 인 기억은 요약이 있어도 들어가지 않는다 |
| REQ3 | 요약 구역이 예산을 넘으면 요약이나 상세를 최근에 고친 기억부터 넣고, 넘친 줄은 잘라 넣지 않고 뺀다. 뺀 기억은 색인에 제목으로 남는다. 예산은 지시문에 들어가는 한 줄 전체의 글자로 센다 | 예산을 넘긴 사례에서 지시문에 잘린 요약이 없고, 빠진 기억이 색인에 있으며, 실행 기록에 빠진 요약 수가 남는다 |
| REQ4 | 요약 구역 예산과 기억 전체 상한은 그룹 설정이다. 기본은 4,000자와 10,000자이고, 허용 범위는 요약 1,000~20,000자, 전체 4,000~40,000자, 요약은 전체를 넘지 못한다. `ADMIN` 만 바꾸고 다음 실행부터 쓰인다. 기억 전체 상한은 지금 설정 파일의 8,000자를 대신한다 | 관리자 API 로 바꾼 값이 다음 실행의 조립에 쓰인다. 범위를 벗어난 값과 `MEMBER` 역할의 요청은 거절된다. 설정 줄이 없는 그룹은 기본값으로 돈다 |
| REQ5 | `memory_remember` 가 요약 줄을 받는다. 새 기억을 만들 때와 `memory_id` 로 고칠 때 모두 받고, 바로 저장할지 제안으로 둘지는 지금의 바로 저장 판정을 그대로 따른다. 요약 줄도 제목, 본문과 함께 부정 표지와 민감해 보이는 글의 검사를 받는다. `memory_id` 로 고치며 요약 줄을 주지 않으면 지금 요약을 두고, 빈 글을 주면 요약을 지운다 | 사람이 보낸 질문이고 바깥 글을 읽지 않은 대화에서 남긴 요약은 다음 실행부터 요약 구역에 있다. 바깥 글을 읽은 대화에서 남긴 요약과 요약에만 민감해 보이는 글이 있는 요약은 제안 카드이고, 받아들이기 전에는 요약 구역에 없다. 상세만 고친 호출 뒤에도 요약이 그대로다 |
| REQ6 | `memory_remember` 가 대신할 옛 기억 번호 목록을 받아 겹치는 기억을 하나로 합친다. 새 기억이 저장되면 옛 기억은 「대신함」 이 되어 실행에서 빠진다. 제안으로 내려가면 받아들일 때 대신한다. 새 기억을 되돌리거나 지우면 옛 기억이 다시 쓰인다. 대화의 「기억했어요」 줄과 제안 카드는 「n개를 합쳤어요」 와 옛 제목들을 보인다 | 합친 직후 옛 기억이 요약 구역, 색인, 검색, `memory_read` 에서 빠지고 `/memory` 목록에는 남는다. 「되돌리기」 뒤 다음 실행에 옛 기억이 다시 들어간다. 대신할 수 있는 번호는 요청자의 승인된 사용자 기억 가운데 풀리고 대체되지 않았으며 받는 collection 의 것이다. 그 밖의 번호(남의 기억, 그룹 기억, 없는 번호 등)가 섞이면 새 기억은 저장하고 그 번호만 건너뛰며, 결과 글은 까닭 없이 「대신하지 못함」 만 알린다 |
| REQ7 | 비서는 사용자 사정이 답을 바꾸는 질문(일 맡기기, 이직·경력, 돈·가계부, 여행·일정)이면 답하기 전에 관련 요약 줄의 번호로 상세를 읽고, 진행 중인 일은 `memory_search` 로 찾는다. 사용자가 「기억 정리해 줘」 라고 하면 주제별로 합친다 | 기억 평가의 합성 사례에 세 질문(이직, 가계부, 여행)을 더해, 상세에만 있는 사실이 답에 쓰인다. 상세가 질문 관련 구역으로 자동으로 들어갔거나 `memory_read` 로 읽었으면 통과로 센다. 기존 기억 회수 측정의 악화 금지 게이트를 통과한다. 배포 뒤 실제 대화 한 번으로 같은 것을 확인한다 |
| REQ8 | 배포 때 본문이 200자 이하인 사용자 기억(승인됨, `MEMORY` 종류, 꺼내는 방식 `SEARCH`, 대체되지 않음, 풀림)은 모두 본문을 요약 줄로 복사한다. 상세는 그대로다. 지금 2,000자 예산에서 밀려 있던 짧은 기억도 복사한다 | 이관 뒤 대상 기억의 요약 줄이 본문과 같고, 같은 사용자와 에이전트의 지시문에서 요약 구역에 든 기억 번호 집합이 이관 전 개인 사실 구역의 집합을 모두 포함한다. 대상 밖 기억(긴 본문, 제안, 보관, 대체됨)은 요약 줄이 비어 있다. 이관은 두 번 돌아도 결과가 같다 |
| REQ9 | `/memory` 의 「알고 있는 것」 을 두 묶음으로 보인다. 「늘 아는 것」 은 매 실행에 들어가는 기억이다. 요약 줄이 있는 기억은 제목과 요약 줄을 보이고 누르면 상세가 펼쳐진다. 항상 넣기(`ALWAYS`)인 기억(관리자가 켠 그룹 기억 포함)도 이 묶음에 「본문이 늘 들어감」 으로 보이고 요약 사용량에는 세지 않는다. 「찾아 보는 것」 은 나머지 기억이고 제목만 보인다. 맨 위에 요약 사용량(예: 3,120 / 4,000자)을 보이고, 예산에서 빠진 기억에 「요약에 못 들어감」 표시를 단다. 사용량과 표시는 collection 을 거르지 않은 주인 기억 전체로, 들어가는 한 줄 전체의 글자로 센다. 대신한 옛 기억은 두 묶음 아래 접힌 「대신한 기억」 묶음에 두고 줄마다 새 기억으로 가는 링크를 둔다. 고치기 양식은 요약 줄과 상세를 따로 받고 요약 줄을 비울 수 있다 | 화면 테스트에서 두 묶음, 사용량, 표시, 「대신한 기억」 묶음과 링크가 보인다. 요약 줄을 비워 저장하면 그 기억이 「찾아 보는 것」 으로 옮고 다음 실행의 요약 구역에서 빠진다 |
| REQ10 | 관리자 메뉴에 「기억」(`/admin/memory`)을 둔다. 요약 구역 예산, 기억 전체 상한, 하루 요약 제안 수, 요약 제안 모델 단계를 바꾼다. 사람마다 요약 사용량과 빠진 줄 수를 숫자로만 보이고 남의 기억 제목은 보이지 않는다 | `ADMIN` 은 값을 바꾸고 저장한 값이 다시 열 때 보인다. `MEMBER` 역할에게는 메뉴가 없고 주소로 열어도 거절된다. 화면과 응답에 남의 기억 제목과 요약이 없다 |
| REQ11 | 정비 루프가 하루 한 번, 요약 줄이 있고 상세가 요약보다 나중에 바뀐 기억을 후보로 찾아 비서가 쓴 새 요약 문장을 제안한다. 모델 입력은 그 기억의 상세와 지금 요약 줄뿐이다. 사용자마다 하루 상한(기본 3건, 0 이면 끈다)까지만 만들고, 모델 호출이 실패하면 문장 없는 「요약 다시 보기」 후보로 남긴다. 받아들이기 전에는 기억이 바뀌지 않고, 받아들이면 요약이 바뀌고 고친 이력에 남는다 | 정비 후보 절에 새 요약 문장과 「받아들이기」, 「아님」 이 보인다. 받아들이기 전 기억의 판 번호가 그대로다. 후보를 만든 뒤 기억이 다시 바뀌었으면 받아들이기가 거절되고 지금 값이 보인다. 상세만 있는 기억과 자동 보관 허락이 켜진 기억은 후보가 되지 않는다. 하루 상한을 넘는 후보는 다음 날로 넘어간다. 문장 없는 후보에는 「고치기」 링크와 「아님」 만 있다. 「아님」 을 누른 기억은 상세가 다시 바뀌어야 다시 후보가 된다 |
| REQ12 | 요약 제안의 기본 모델 단계는 평가로 고른다. 상세가 바뀐 기억과 기대 요약의 평가 세트를 만들어 단계별(INSTANT, MEDIUM, HIGH)로 돌리고, 사실 누락, 사실 바뀜, 상세 안 지시문 무시, 길이 상한, 한국어 자연스러움을 채점한다 | PR3 본문과 이 스펙의 결정 표에 단계별 점수와 호출 비용, 고른 단계와 까닭이 있다. 평가 세트는 지어낸 기억으로 만든다. 고른 단계가 `/admin/memory` 의 기본값이다 |

## 설계

기술 설계는 technical-design 단계에서 [`design.md`](design.md) 를 이번 변경으로 새로 쓴다. 지금 그 파일은 직전 변경(기억 암호화)의 설계다.
스펙이 정한 제약만 적는다.

- 테이블을 늘리지 않는다. 요약 줄은 `memory` 와 `memory_revision` 의 칸, 예산과 상한, 하루 제안 수와 모델 단계는 `group_setting` 의 새 키, 요약 제안은 `decision_feedback_event` 의 정비 사건이다
- 정비 루프의 요약 제안은 [ADR-20261015 / memory-maintenance](../../adr/ADR-20261015-memory-maintenance.md) 에서 LLM 이 기억을 고쳐 쓰지 않기로 한 결정을 바꾼다. PR3 이 그 ADR 을 갱신한다
- 요약 구역은 [ADR-20261008 / memory-facts](../../adr/ADR-20261008-memory-facts.md) 의 개인 사실 구역(대상, 예산 2,000자)을 바꾼다. PR1 이 그 ADR 을 갱신하고 `AGENTS.md` 용어 표의 「개인 사실 구역」 을 「요약 구역」 으로 바꾼다
- 요약 제안 평가는 실제 모델을 거친다. 답변 품질 평가([`answer-quality.md`](../answer-quality.md))와 같은 틀로 코디네이터가 운영에서 돌리고, 저장소에는 평가 세트와 채점 기준, 결과 수치만 둔다
- 지금 기억의 합치기(20개를 12~14개로)는 배포 뒤 사용자가 대화에서 시킨다. 코드로 일괄 합치지 않는다
