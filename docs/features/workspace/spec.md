# 파일 공간: 에이전트가 내준 파일을 「내 파일」 한곳에서 쉽게 찾는다

확인: 2026-11-19

## 목표

사용자가 에이전트가 만들어 준 파일(그림, 문서, 표)을 「파일 공간」 의 「내 파일」 한곳에서 찾는다.
언제 만들었는지, 어느 대화에서 나왔는지, 종류, 이름과 낱말로 찾아 열어 보고, 내려받고, 그 대화로 돌아가고, 지운다. 휴대폰에서도 같다.
대화에서 「내 파일 공간에 가져다 놔 줘」, 「파일 공간에서 그 그림 찾아 줘」 라고 하면 에이전트가 그 말을 알아듣고 넣거나 찾아 준다.

지금은 아래와 같다.

- 「파일 공간」 이 「실행 공간」 과 「보관한 결과물」 두 탭으로 나뉘어 있다. 저장 위치와 주인, 암호화가 달라서다([`workspace.md`](../workspace.md))
- 「보관한 결과물」 은 이름, 크기, 보관한 시각만 보인다. 어느 대화에서 나왔는지 알 수 없고 검색과 종류별 보기가 없다
- 「실행 공간」 은 폴더를 하나씩 여는 탐색기이고 에이전트의 작업 파일(스크립트, 로그)이 결과 파일과 섞여 있다
- 답에 묶여 보관되는 것은 HTML 뿐이다. 그림과 스타일은 HTML 이 부를 때만 묶음으로 따라간다. 표와 문서 파일은 실행 공간에만 생긴다
- 에이전트에게 「파일 공간」 에 닿는 도구가 없다. 2026-11-19 운영에서 「그 이미지를 내 파일공간에 가져다 놔줄래?」 라는 요청에 에이전트가 `artifact_write` 를 세 번 불러 모두 실패했다. 이 도구는 글과 HTTPS 주소의 사진만 받는데 에이전트가 파일 경로를 넘겼다. 에이전트는 복사했다고 사실과 다르게 답했고 「파일공간이 어느 서비스인가요?」 라고 되물었다

## 범위

**「보관한 결과물」 이 「내 파일」 이 되고, 에이전트가 사용자에게 내준 파일은 모두 여기 한곳에 남는다**(DECISION6).
저장 방식은 지금의 보관함 그대로다. 대화를 연 사람의 것으로 암호화해 두고 대화를 지워도 남는다([ADR-20261101 / artifact-vault](../../adr/ADR-20261101-artifact-vault.md)).
「실행 공간」 은 「에이전트 작업 폴더」 로 이름을 바꿔 「내 파일」 뒤에 둔다. 대화별 결과물 폴더는 지금처럼 30일 뒤 지워지는 원본이고 이 화면에 드러나지 않는다.

이 스펙은 PR 셋으로 구현한다(DECISION16). 이 스펙을 처음 구현하는 PR 은 PR1 이고, 뒤의 PR 은 같은 스펙과 설계를 쓴다.

| PR | 담는 것 | 시작 조건 | 요구사항 |
| --- | --- | --- | --- |
| PR1 | 에이전트가 「내 파일」 에 넣는 도구, 넓힌 파일 종류와 파일 하나 25MiB, 제목과 한 줄 설명, 「파일 공간」 을 알아듣는 지침, 실패를 성공처럼 말하지 않기 | 없음 | REQ1~REQ8 |
| PR2 | 「내 파일」 화면(최신순 한 목록, 종류 고르기, 검색, 나온 대화로 돌아가기, 에이전트 작업 폴더를 뒤로, 자동 보관 스위치 없애기, 휴대폰) | PR1 이 main 에 머지됐다 | REQ9~REQ18 |
| PR3 | 에이전트가 「내 파일」 에서 찾기, 에이전트 작업 폴더의 「내 파일로 가져오기」 | PR2 가 main 에 머지됐다 | REQ19~REQ21 |

같이 진행 중인 이미지 기능 스펙(`docs/features/generated-image/spec.md`, 브랜치 `jon890/generated-image-spec`)과는 이렇게 나눈다.
그 스펙은 에이전트가 만든 그림을 답 안에 보이고 보관함에 자동으로 남기는 일을 갖는다. 이 스펙은 그림이 아닌 파일과, 사용자가 넣어 달라고 한 파일을 넣는 도구, 모든 파일을 찾는 화면을 갖는다.
그 스펙이 정한 그림의 제목 규칙을 이 스펙이 모든 종류에 같게 적용한다(DECISION20).
그 스펙이 「보관한 결과물」, 「보관함에서 보기」 라고 쓴 화면 글자는 PR2 에서 「내 파일」, 「내 파일에서 보기」 가 된다(DECISION17).

범위 밖:

- 「내 파일」 의 파일을 대화로 다시 가져가는 단추와, 에이전트가 「내 파일」 의 내용을 읽는 것(DECISION11, DECISION14). 에이전트는 넣고, 찾아서 링크를 붙이는 데까지만 한다
- 에이전트가 「내 파일」 의 파일을 지우는 것. 지우기는 사용자가 화면에서만 한다(DECISION11)
- 가족 사이에 파일을 함께 보는 기능(DECISION15)
- 파일 본문의 낱말로 찾기(DECISION8)
- 「파일 공간」 밖의 서비스 화면과 개념(할 일, 지금 화면, 알림 등)을 에이전트에게 알려 주는 일. 후속 스펙으로 따로 정한다(DECISION12)
- 25MiB 를 넘는 파일을 「내 파일」 에 두는 것(DECISION9)
- 엑셀, 워드, 파워포인트, PDF 의 화면 미리보기. 내려받기만 된다(DECISION18)
- 대화별로 묶어 보는 보기, 파일 이름 바꾸기, 사용자가 폴더를 만들어 정리하기(DECISION3, DECISION7)
- 이미 에이전트 작업 폴더에 쌓인 파일을 「내 파일」 로 한꺼번에 옮기기. PR3 의 「내 파일로 가져오기」 로 하나씩 가져온다(DECISION6)
- 대화를 지울 때 「내 파일」 의 파일도 함께 지우는 선택지. 지금도 없다([`workspace.md`](../workspace.md))

| REQ12 | 목록 위의 검색 칸에 낱말을 넣으면 제목, 한 줄 설명, 파일 이름, 나온 대화의 제목에 그 낱말이 든 파일만 보인다. 영문 대소문자를 구분하지 않고 낱말의 일부만 맞아도 찾는다. 고른 종류와 함께 적용한다. 본문의 낱말은 찾지 않는다 | 설명에만 「여행」 이 든 파일과 대화 제목에만 「여행」 이 든 파일이 「여행」 검색에 모두 나온다. 「표」 를 함께 고르면 그 가운데 표만 남는다 |
| REQ13 | 줄에 보이는 대화 제목을 누르면 그 대화에서 나온 파일만 보이고, 「대화 열기」 로 그 대화로 간다. 그 대화를 지웠으면 대화 자리에 「지운 대화」 가 보이고 누를 수 없다. 지운 대화의 제목으로는 찾지 못한다. 「작업 폴더에서 가져옴」 도 누를 수 없다 | 대화 제목을 누르면 그 대화의 파일만 남고 「대화 열기」 가 그 대화를 연다. 대화를 지운 뒤에도 파일은 목록에 있고 「지운 대화」 로 보인다 |
| REQ14 | 줄을 누르면 미리보기가 열린다. 넓은 화면은 목록 옆 패널, 좁은 화면은 전체 폭 시트다. 그림은 그대로, HTML 은 스크립트 없이, CSV 와 TSV 는 표로, MD 와 TXT 와 CSS 는 원문 그대로 고정폭 글로 보인다. XLSX, DOCX, PPTX, PDF 는 「미리보기가 없어요」 와 내려받기가 보인다. 모든 파일은 내려받을 수 있고 묶음은 지금처럼 zip 으로 받는다. 내려받는 파일 이름은 제목에 원래 확장자를 붙인 것이다 | 형식마다 위와 같이 보인다. 내려받은 파일이 넣은 원본과 바이트가 같다 |
| REQ15 | 줄과 미리보기에서 파일을 지운다. 확인을 한 번 거친다. 지우면 「내 파일」 에서 바로 사라지고 다시 열 수 없다. 대화 쪽 원본과 에이전트 작업 폴더의 원본은 건드리지 않는다. 지운 파일은 자동으로 다시 생기지 않는다. 자동으로 남은 결과물은 대화 쪽 원본이 남아 있는 동안 대화의 「보관」 단추로 다시 넣고, 넣기 도구로 넣은 파일은 에이전트에게 다시 넣어 달라고 하면 다시 들어간다 | 지운 파일이 목록에 없고 그 주소가 없는 파일과 같은 응답을 준다. 같은 결과물을 묶은 다른 답이 끝나도 다시 생기지 않는다. 넣기 도구로 같은 파일을 다시 넣으면 생긴다 |
| REQ16 | 「결과물 자동 보관」 스위치를 없앤다. 완료한 답에 묶인 결과물은 모두 「내 파일」 에 남는다. 꺼 두었던 사용자도 PR2 배포 뒤의 답부터 남는다. 꺼 둔 동안의 결과물은 자동으로 넣지 않는다. 대화의 「보관」 단추와 보관 상태 글자는 그대로 둔다 | 화면에 스위치가 없다. 자동 보관을 꺼 두었던 사용자의 새 답이 끝나면 그 결과물이 「내 파일」 에 있다 |
| REQ17 | 「내 파일」 위에 쓴 용량과 전체 용량이 한 줄로 보인다. 가득 차면 새 파일이 들어오지 않는다는 안내와 지워서 비우라는 말이 보인다 | 파일을 넣고 지우면 쓴 용량이 따라 바뀐다. 가득 찬 사용자에게 안내가 보인다 |

| DECISION19 | 넣은 파일의 대화 쪽 규칙과 자동으로 묶는 범위 | 넣기 도구로 넣은 파일은 대화 쪽에 사본을 두지 않고 답 아래 줄이 「내 파일」 의 파일을 가리킨다. turn 이 끝날 때 자동으로 답에 묶는 것은 지금처럼 HTML 과(이미지 기능 뒤) 그림이고 그 규칙(대화 쪽 원본 30일, 「보관」 단추)은 그대로다. 그 밖의 종류는 넣기 도구로 넣은 것만 「내 파일」 에 남는다 | 작성자 | 넣는 일은 「내 파일」 로 바로 가는 것이라 암호화하지 않은 사본을 대화 폴더에 하나 더 둘 까닭이 없다. 대화 폴더의 모든 파일을 자동으로 묶으면 중간 파일이 「내 파일」 에 섞여 DECISION2 와 어긋난다. 기존 규칙은 [`attachment.md`](../attachment.md) 의 「결과물 파일」 이 갖는다 |
