# 휴대폰과 PC 로 받는 알림(웹 푸시)

확인: 2026-11-20

## 목표

가족 사용자 각자가 비서의 알림을 웹을 열어 두지 않아도 아이폰과 PC 브라우저의 시스템 알림으로 받는다.

지금 알림은 `notification` 표에 쌓여 웹 안의 알림 목록과 「지금 볼 것」 에만 보인다([`attention.md`](../attention.md) 의 「알림」). 예약 작업 결과, 승인 대기, 사건 감지 보고가 모두 웹을 열어야 보인다.

## 범위

**넣는 것**

- 사용자가 기기마다 「이 기기에서 알림 받기」 로 등록하고, 그 사용자에게 알림이 생길 때마다 등록한 모든 기기로 웹 푸시를 보낸다
- 아이폰은 홈 화면에 추가한 웹 앱으로 받는다. 그래서 웹 앱 설정 파일(manifest), 아이콘, 서비스 워커와 홈 화면 추가 안내를 함께 만든다
- 설정의 「알림」 화면: 기기 목록(이름 고치기, 지우기), 알림 묶음별 켜고 끄기, 조용한 시간

**범위 밖**

- 할 일 기한 알림. 할 일 기한은 지금처럼 「지금 볼 것」 화면에서만 보인다(「기한이 다가왔어요」, 「기한이 지났어요」)
- 먼저 알리기의 판정(「지금 볼 것」 의 카드)을 밖으로 보내는 것. 밖으로 가는 것은 `notification` 표의 알림뿐이다. [ADR-072](../../adr/ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md) 의 8번(판정은 화면 안에서만 보인다)은 그대로다
- 조용한 시간에 미룬 푸시를 아침에 몰아 보내는 것
- 웹 푸시 밖의 채널(메신저, 메일, 문자)과 Android 전용 확인. Android 브라우저도 같은 표준으로 받지만 이번 확인 대상은 아이폰과 PC 다
- 원인이 끝난 알림(승인을 처리함)의 푸시를 기기에서 거둬들이는 것
- 알림을 새로 만드는 규칙과 알림 종류. 이 기능은 이미 생기는 알림을 밖으로도 보낼 뿐이다

**PR 나눔**

| PR | 내용 | 요구사항 |
| --- | --- | --- |
| PR1 | 기기 등록과 보내기. 웹 앱 틀(manifest, 아이콘, 서비스 워커)과 아이폰 안내, 누르면 열기, 로그아웃과 끊긴 구독 정리. 이 PR 이 배포되면 등록한 기기로 모든 알림이 온다 | REQ1-REQ9 |
| PR2 | 「알림」 화면의 묶음별 켜고 끄기, 조용한 시간, 기기 이름 고치기와 지우기 | REQ10-REQ13 |

PR1 과 PR2 사이에는 조용한 시간과 끄기 없이 모든 알림이 온다.
PR1 은 운영 코드 상한 때문에 backend(기기 저장과 보내기)와 web(화면, 서비스 워커, 홈 화면 앱) 두 PR 로 나눴다(사용자 2026-11-20). 휴대폰과 PC 로 알림이 오는 것은 web PR 이 배포된 뒤다.

| REQ4 | 웹 앱을 홈 화면에 추가하면 지금 앱 이름과, 단색 바탕에 앱 이름 첫 글자를 둔 아이콘으로 보인다 (PR1) | 아이폰 홈 화면에 앱 이름과 첫 글자 아이콘이 보이고, 누르면 주소창 없는 화면으로 열린다 |
| REQ5 | 사용자에게 알림이 하나 생기면 그 사용자가 등록한 모든 기기로 푸시를 보낸다. 푸시의 제목과 본문은 그 알림의 제목과 본문 그대로다. 다른 사용자의 기기로는 가지 않는다. 그 기기에서 앱을 보고 있어도 시스템 알림을 띄운다 (PR1) | 예약 작업이 끝나면 작업 주인의 아이폰과 PC 에 「「아침 뉴스」 실행을 마쳤어요」 가 뜬다. 같은 그룹의 다른 사용자 기기에는 뜨지 않는다. 가짜 푸시 서비스 테스트에서 받는 주소가 그 사용자의 기기 주소뿐이다 |
| REQ6 | 푸시를 누르면 웹 알림을 누른 것과 같다. 그 알림을 읽음으로 바꾸고 같은 곳(그 대화, 예약 작업, 외부 서비스 연결 등)을 연다. 갈 곳이 없는 알림은 「지금 볼 것」 의 알림 목록을 연다. 앱이 이미 열려 있으면 그 창을 앞으로 가져와 옮긴다. 그 기기의 로그인이 풀렸으면 로그인 화면을 거친 뒤 같은 곳으로 가고 읽음이 된다 (PR1) | 승인 대기 푸시를 누르면 그 대화가 열리고 웹 알림 목록에서 그 줄이 읽음이다 |
| REQ7 | 보내기는 알림을 만든 일의 성공과 속도를 바꾸지 않는다. 알림이 저장된 뒤에 보내고, 보내기가 실패해도 알림과 원인은 그대로 남는다 (PR1) | 가짜 푸시 서비스가 오류를 내도 승인 줄과 알림이 저장되고 웹 목록에 보인다 |
| REQ8 | 푸시 서비스가 그 구독이 없다고 답하면 그 기기를 목록에서 자동으로 지운다. 일시적인 실패(서버 오류, 너무 많은 요청)는 짧게 다시 시도한 뒤 그 푸시를 버린다. 보낸 결과는 로그에만 남기고 기기 주소와 키를 로그에 쓰지 않는다 (PR1) | 가짜 푸시 서비스가 410 을 답하면 다음 목록 조회에 그 기기가 없다. 500 이면 정한 횟수만 다시 보내고 멈춘다 |
| REQ9 | 로그아웃하면 그 브라우저의 구독을 지운다. 다른 사용자가 같은 브라우저에서 등록하면 그 구독은 마지막에 등록한 사용자에게로 옮겨지고 앞 사용자의 목록에서 사라진다. 관리자가 그 사용자의 접근을 끄면(허용 목록에서 끄기) 그 사용자의 기기를 모두 지운다. 다시 켜도 기기는 돌아오지 않고 다시 등록해야 한다 (PR1) | 로그아웃한 PC 로 그 사용자의 알림이 오지 않고 목록에서도 사라진다. A 가 등록한 PC 에서 B 가 등록하면 그 PC 에는 B 의 알림만 오고 A 의 목록에 그 PC 가 없다 |

| REQ13 | 기기 목록에서 기기 이름을 고치고 기기를 지운다. 지운 기기로는 더 보내지 않는다. 남의 기기는 보이지도 고쳐지지도 않는다 (PR2) | 아이폰 줄을 지우면 그 아이폰에 푸시가 오지 않는다. 다른 사용자의 기기 번호로 요청하면 없는 기기와 같은 404 다 |

### 알림 묶음

| 묶음 | 들어가는 알림 종류(`NotificationKind`) |
| --- | --- |
| 승인과 넘겨받기 | `APPROVAL_REQUESTED`, `APPROVAL_EXPIRED`, `HANDOFF_REQUESTED` |
| 예약 작업 | `TASK_SUCCEEDED`, `TASK_FAILED`, `TASK_SKIPPED` |
| 살펴보기 보고 | `EVENT_CHECK_REPORTED` |
| 연결 문제 | `EVENT_WATCH_FAILED` |
| 관리자 할 일 | `CONNECTOR_REINSTALLED`, `DEFAULT_TOOLS_PENDING` |

새 알림 종류(예: 「터미널 기본」 의 셸 사용 알림)는 더할 때 묶음 하나에 넣는다. 묶음이 없는 종류는 테스트가 막는다.

## 도메인 규칙 변경

도메인 규칙 변경 없음: 알림을 만드는 규칙(ADR-070)과 먼저 알리기의 판정(ADR-072)은 바꾸지 않는다. 이미 생기는 알림을 밖으로도 보낼 뿐이다.
