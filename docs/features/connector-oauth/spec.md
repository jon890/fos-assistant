# 플러그인 계정 연결 단추(OAuth)

## 목표

사용자가 「외부 서비스 연결」 화면에서 「GitHub 으로 연결」 같은 단추를 눌러 그 서비스에 로그인하고 권한을 허락하면, 토큰을 직접 만들어 붙여 넣지 않아도 연결이 만들어진다.

지금은 연결의 비밀 칸을 사람이 붙여 넣는다.
커리어 플러그인의 GitHub token 칸(`github_token`)은 사용자가 GitHub 에서 저장소 하나만 쓰는 token 을 만들어 넣어야 하고, 넣지 않으면 GitHub 도구가 돌지 않는다. 운영 커리어 에이전트가 GitHub 프로필 변경안을 만들 때 이 칸이 비어 공개본을 읽지 못했다(2026-11-20).
Gmail 도 OAuth 클라이언트 ID, secret, refresh token 을 사용자가 직접 만들어 붙여 넣는다([`hermes/connectors/gmail/assistant.json`](../../../hermes/connectors/gmail/assistant.json)).

이 기능은 한 플러그인 전용이 아니라 연결 기능의 공통 장치다. 플러그인이 선언에 OAuth 를 적으면 그 플러그인의 연결 화면에 단추가 생긴다.

## 범위

**이번에 하는 것**

- 플러그인 선언(`assistant.json`)에 OAuth 제공자와 권한을 적는 모양. 계약은 [`hermes/connectors/README.md`](../../../hermes/connectors/README.md) 의 「assistant.json」 에 더한다
- 「외부 서비스 연결」 화면의 연결 단추, 서비스 로그인에서 돌아오는 흐름, 그 결과로 연결을 만드는 것
- 받은 토큰을 지금처럼 Hermes 쪽 보관 파일에만 두는 것
- 만료하는 토큰을 우리 쪽이 갱신하고 플러그인이 지금 유효한 토큰을 받아 가는 통로
- 갱신이 끊겼을 때의 「다시 연결 필요」 와 알림, 연결 해제 때 서비스 쪽 토큰 취소
- OAuth 앱의 client ID 와 client secret 을 관리자 「서버 비밀값」 화면에 두는 것. 그 화면은 서버 비밀값 기능(`docs/features/secret-store/`, 진행 중)이 만든다
- 첫 서비스는 GitHub(GitHub App), 다음은 Google(Gmail 플러그인 전환)

**선행 조건**

구현은 서버 비밀값 기능의 PR1a(`server_secret` 저장소와 관리자 화면)가 머지된 뒤 시작한다(사용자 2026-11-20).

**PR 나눔**

| PR | 내용 | 요구사항 |
| --- | --- | --- |
| PR1 | 공통 장치와 GitHub. 선언 계약, 서버 비밀값의 OAuth 앱 줄, 단추 흐름, 토큰 통로와 갱신, 다시 연결 필요와 알림, 해제 때 취소 | REQ1-REQ9, REQ11 |
| PR2 | Google 과 Gmail 플러그인 전환 | REQ10 |
| 저장소 밖 | 커리어 플러그인 선언에 GitHub OAuth 를 더하고 토큰 통로를 쓰게 고친다. 그 플러그인의 저장소에서 PR1 머지 뒤 한다 | REQ6 의 소비자 |

PR1 이 운영 코드 크기 상한을 넘으면 plan 이 단계별 PR 로 나눈다. 나눠도 GitHub 이 먼저다.

**범위 밖**

- 운영의 OAuth 앱 등록과 돌아오는 주소 설정. 운영 저장소 `fos-home-infra` 와 사람이 한다. 무엇을 요청할지는 아래 「운영 요청」 이 갖고, 값과 절차는 기술 설계가 요청 본문으로 정리한다
- GitHub 과 Google 밖의 서비스. 같은 선언 모양으로 나중에 더한다
- 원격 MCP 플러그인의 단추 연결. 원격 플러그인은 값을 profile `.env` 에 복사하는 예외 경로라([`code-architecture.md`](../../code-architecture.md) 「플러그인 비밀값을 두는 곳」) 만료 토큰을 받아 갈 통로가 없다
- 붙여 넣은 값의 OAuth 전환. 기존 연결을 단추 연결로 자동으로 바꾸지 않는다

## 운영 요청

기술 설계가 요청 본문으로 정리해 `fos-home-infra` 에 넘긴다. 이 저장소에는 값을 적지 않는다.

- 커리어 플러그인용 GitHub App 등록: 저장소 내용 읽기·쓰기 권한, 사용자 토큰 만료 켜기, 돌아오는 주소 등록
- Google OAuth 앱 하나 등록: Gmail scope 두 개(`gmail.modify`, `gmail.settings.basic`), 동의 화면, 돌아오는 주소 등록. 「테스트」 상태는 refresh token 이 7일 뒤 만료되므로 「프로덕션」 으로 게시한다. 심사를 받지 않으면 로그인 때 「확인되지 않은 앱」 경고가 뜬다
- 배포 뒤 관리자가 서버 비밀값 화면에 각 앱의 client ID 와 client secret 을 넣는다

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 플러그인은 `assistant.json` 에 OAuth 제공자(`github` 나 `google`), 권한(Google 은 scope 목록), 단추로 채울 비밀 칸을 선언할 수 있다. 제공자 목록과 그 서비스의 주소는 이 저장소의 코드가 갖고 플러그인은 이름만 적는다. 선언이 틀리면 그 플러그인의 단추만 빠지고 경고 로그를 남기며, 입력 칸으로는 계속 연결된다 (PR1) | OAuth 를 선언한 플러그인이 카탈로그에 단추 사용 가능으로 나온다. 모르는 제공자를 적은 플러그인은 단추 없이 입력 칸만 보이고 로그에 그 플러그인 이름과 까닭이 있다 |
| REQ2 | 관리자 「서버 비밀값」 화면에 OAuth 앱 줄이 있다. GitHub 은 GitHub OAuth 를 선언한 플러그인마다 한 줄, Google 은 한 줄이다. 줄마다 client ID 와 client secret 을 넣는다. 원문 표시와 저장 규칙은 서버 비밀값 기능을 따른다 (PR1, Google 줄은 PR2) | 커리어 플러그인이 카탈로그에 있으면 「GitHub 앱(커리어)」 줄이 보인다. client secret 을 넣으면 「입력됨」 과 앞부분만 보이고 응답에 원문이 없다 |
| REQ3 | 그 플러그인의 OAuth 앱 값이 모두 있으면 연결 화면에 「GitHub 으로 연결」 단추가 기본으로 보이고, 단추가 채우는 비밀 칸은 「직접 입력」 아래 접혀 있다. 단추가 채우지 않는 칸은 단추 위에 입력 칸으로 보인다. 값이 없으면 단추를 보이지 않고 입력 칸만 보인다. 그때 `ADMIN` 에게만 「서버 비밀값에서 GitHub 앱을 설정하면 단추로 연결할 수 있어요」 와 그 화면 링크를 보인다 (PR1) | 앱 값을 넣기 전에는 `MEMBER` 역할 사용자에게 지금과 같은 입력 화면이, 관리자에게는 안내와 링크가 보인다. 넣은 뒤에는 두 사람 모두 단추를 본다 |
| REQ4 | 단추를 누르면 그 서비스의 로그인·허락 화면으로 간다. GitHub 은 App 설치 화면으로 가서 저장소를 고르고 허락까지 한 번에 한다. Google 은 요청한 권한을 모두 허락해야 한다. 허락하고 돌아오면 Control Plane 이 토큰을 받아 지금 등록과 같은 확인 도구를 부르고, 통과하면 연결이 쓸 수 있는 상태가 된다. 토큰 원문은 Hermes 보관 파일에만 있고 데이터베이스, 로그, 응답, 화면에 없다 (PR1) | GitHub 으로 연결한 뒤 연결 화면에 「연결됨」 과 「단추로 연결함」 이 보이고, 그 연결을 붙인 에이전트가 GitHub 도구를 부른다. 데이터베이스와 로그를 찾아도 토큰 원문이 없다 |
| REQ5 | 사용자가 서비스 화면에서 거절하거나 닫거나, 돌아온 요청의 상태 값이 맞지 않거나 10분이 지났거나 다른 사용자가 시작한 것이거나, Google 에서 요청한 권한 일부만 허락했으면 아무것도 저장하지 않고 연결 화면에 까닭과 「다시 시도」 를 보인다. 관리자의 앱 설정이 틀려 토큰을 받지 못하면 「관리자 설정 문제로 연결하지 못했어요」 를 보이고 관리자에게 알린다(REQ7). 확인 도구가 실패해도 저장하지 않고 같은 자리에 공통 오류의 까닭과 「다시 시도」 를 보인다 (PR1) | GitHub 화면에서 「취소」 를 누르면 연결 화면으로 돌아와 「연결하지 않았어요」 가 보이고 연결 줄이 생기지 않는다. 다른 사용자의 로그인으로 같은 돌아오는 주소를 열면 거절된다 |
| REQ6 | 단추로 만든 연결의 플러그인 프로세스는 env 로 로컬 주소 하나를 받고, 도구를 부를 때 그 주소에서 지금 유효한 토큰을 받는다. 우리 쪽이 도구 호출과 상관없이 만료 전에 미리 갱신하고, GitHub 처럼 refresh token 이 바뀌면 새 값을 보관 파일에 둔다. 갱신은 바인딩을 재시작 대기로 만들지 않는다. 플러그인 프로세스의 env 에 refresh token 과 client secret 이 없다. 그 주소는 그 바인딩의 연결 토큰만 준다 (PR1) | 연결 뒤 8시간이 지나도 붙은 에이전트의 GitHub 도구가 재시작 없이 돈다. 플러그인 프로세스 env 에 refresh token 과 client secret 이름이 없다. 다른 사용자 바인딩의 주소 표식으로 부르면 거절된다 |
| REQ7 | 서비스가 갱신을 거절하면(사용자가 서비스에서 허락을 거뒀거나 refresh token 이 만료됨) 연결을 「다시 연결 필요」 로 바꾸고 그 사용자에게 알림 하나를 남긴다. 같은 끊김에는 알림을 한 번만 남기고, 누르면 그 연결 화면을 연다. 연결 화면에는 「GitHub 으로 다시 연결」 단추가 보인다. 그동안 연결은 준비 안 됨으로 다뤄져 도구 호출을 미리 막는다. 서비스가 잠시 답하지 않는 것은 끊김이 아니다. 그때는 상태를 바꾸지 않고 그 호출만 「잠시 뒤 다시」 오류로 끝낸다. 서비스가 앱 자격(client ID, client secret)을 거절하면 사용자 연결은 그대로 두고 그 호출만 같은 오류로 끝내며, 관리자에게 그 앱 설정을 확인하라는 알림 하나와 서버 비밀값 링크를 남긴다 (PR1) | GitHub 설정에서 앱 허락을 거둔 뒤 다음 갱신 때 연결이 「다시 연결 필요」 가 되고 알림이 하나 생긴다. 그 뒤 도구가 여러 번 실패해도 알림은 늘지 않는다. 다시 연결하면 「연결됨」 으로 돌아온다. 서버 비밀값의 client secret 을 틀린 값으로 바꾸면 사용자 연결 상태는 그대로이고 관리자에게만 알림이 생긴다 |
| REQ8 | 단추로 만든 연결을 해제하면 서비스 쪽 허락(토큰) 취소를 시도한다. GitHub App 설치는 지우지 않고 지울 수 있는 설정 화면 링크를 보인다. 취소가 실패해도 해제는 지금처럼 끝내고, 「GitHub 설정에서 앱 허락을 직접 거둬 주세요」 와 그 서비스의 설정 화면 링크를 보인다 (PR1) | 해제 뒤 GitHub 설정의 허락한 앱 목록에서 그 앱이 사라지고, 화면에 앱 설치를 지울 수 있다는 안내와 링크가 보인다. GitHub 이 답하지 않게 막고 해제하면 연결은 해제되고 안내와 링크가 보인다 |
| REQ9 | 붙여 넣기 연결은 그대로 둔다. 기존 연결은 바꾸지 않고 계속 돈다. 사용자는 「직접 입력」 으로 연결하거나 단추로 다시 연결해 방식을 바꿀 수 있다. 바꾸면 앞 방식의 값은 보관 파일에서 사라진다 (PR1) | 기존에 붙여 넣은 연결이 배포 뒤에도 같은 상태로 돈다. 붙여 넣은 연결에서 단추로 다시 연결하면 화면에 「단추로 연결함」 이 보이고 보관 파일에 붙여 넣은 칸 값이 없다 |
| REQ10 | Gmail 플러그인은 Google OAuth(`gmail.modify`, `gmail.settings.basic`)를 선언하고, 단추로 연결한 Gmail 연결은 REQ6 의 통로로 토큰을 받는다. 기존 세 칸(클라이언트 ID, secret, refresh token)은 「직접 입력」 으로 남고 그 연결은 지금처럼 돈다 (PR2) | 단추로 Gmail 을 연결하면 메일 찾기 도구가 돌고 1시간 뒤에도 재시작 없이 돈다. 붙여 넣은 기존 Gmail 연결도 배포 뒤 그대로 돈다 |
| REQ11 | 연결은 지금처럼 사용자마다 자기 계정으로 만든다. `ADMIN` 과 `MEMBER` 역할 모두 단추를 쓸 수 있고, 다른 사용자의 연결을 만들거나 바꾸지 못한다 (PR1) | `MEMBER` 역할 사용자가 단추로 자기 GitHub 을 연결할 수 있다. 다른 사용자의 연결 번호로 시작 요청을 보내면 거절된다 |

| DECISION5 | 붙여 넣기 방식 | 단추와 붙여 넣기를 둘 다 남긴다. OAuth 앱이 설정돼 있으면 단추가 기본이고 「직접 입력」 은 접어 둔다. 기존 붙여 넣기 연결은 그대로 돈다 | 사용자 2026-11-20 | 기존 Gmail 연결을 끊지 않고 OAuth 앱 설정 전에도 플러그인을 쓴다 |
| DECISION6 | 해제 때 서비스 쪽 토큰 | 취소를 시도하고 실패해도 해제는 끝낸다. 실패하면 직접 거두는 안내와 설정 화면 링크를 보인다 | 사용자 2026-11-20 | 해제는 「그만 쓰겠다」 는 뜻이라 서비스 장애로 막지 않는다 |
| DECISION7 | 갱신이 끊겼을 때 | 연결을 「다시 연결 필요」 로 바꾸고 알림 하나. 같은 끊김에 한 번 | 사용자 2026-11-20 | 가끔 쓰는 연결은 쓰려는 순간에야 끊긴 것을 알면 그 대화가 막힌다 |
| DECISION8 | OAuth 앱 미설정 화면 | 단추를 숨기고 입력 칸만. 관리자에게만 서버 비밀값 안내와 링크 | 사용자 2026-11-20 | 관리자가 사실상 한 명이고 그가 설정하면 모두에게 단추가 생긴다 |
| DECISION9 | 앱을 플러그인끼리 나눠 쓸지 | GitHub 은 플러그인마다 앱 하나, Google 은 앱 하나를 모든 Google 플러그인이 나눠 쓴다 | 사용자 2026-11-20 | GitHub App 권한은 앱 단위로만 정해지고, Google 은 연결할 때 scope 로 좁혀진다 |
| DECISION10 | 제공자 정보를 두는 곳 | 제공자 목록(GitHub, Google)과 로그인·토큰·취소 주소, 갱신과 취소 방식은 이 저장소 코드가 갖는다. 플러그인은 제공자 이름과 Google scope 만 선언한다. [ADR-043](../../../backend/docs/adr/ADR-043-커넥터는-plugin-의-connector-json-으로-선언하고-control-plane-은-범용-흐름만-갖는다.md) 이 정한 「Control Plane 은 서비스 이름과 주소를 모른다」 는 결과에 OAuth 제공자 예외를 새 ADR 로 적는다 | 사용자 2026-11-20 | 토큰 주소로 client secret 이 간다. 비밀이 가는 곳은 선언이나 입력이 아니라 리뷰된 코드가 정한다. GitHub 의 취소는 표준 방식이 아니라 서비스별 코드가 어차피 필요하다 |
| DECISION11 | 선언이 틀렸을 때 | 단추만 빠지고 경고 로그. 플러그인은 입력 칸으로 카탈로그에 남는다 | 작성자 | 「아이콘과 링크」 의 「그 칸만 null」 규칙과 같다. 붙여 넣기 연결이 선언 실수로 끊기지 않는다 |
| DECISION12 | 돌아오는 요청의 검사 | 상태 값은 시작한 사용자와 플러그인에 묶고 10분 뒤 만료하며 한 번만 쓴다. 서비스가 지원하면 PKCE 를 함께 쓴다. 새 테이블을 만들지 않는다 | 작성자 | CSRF 와 다른 사용자 계정이 섞이는 것을 막는 OAuth 의 표준 방법이다. 테이블을 늘리지 않는다(사용자 2026-11-01) |
| DECISION13 | 「다시 연결 필요」 로 바꾸는 때 | 서비스가 갱신을 거절했을 때(`invalid_grant` 같은 응답)만. 네트워크 실패와 5xx 는 상태를 두고 그 호출만 실패 | 작성자 | 잠깐의 장애로 연결이 끊긴 것처럼 보이고 알림이 쌓이지 않게 한다 |
| DECISION14 | 갱신과 바인딩 반영 | 갱신은 바인딩을 다시 설치하지 않고 재시작 대기를 만들지 않는다. 다시 연결(새 허락)은 지금 등록과 같은 반영 규칙을 따른다 | 작성자 | 갱신이 몇 시간마다 재시작 대기를 만들면 연결이 사실상 쓸 수 없다. 토큰을 통로로 받는 까닭이다 |
| DECISION15 | 연결 방식 표시 | 연결 화면에 「단추로 연결함」 이나 「직접 입력함」 을 보인다 | 작성자 | 해제 안내(REQ8)와 다시 연결 단추(REQ7)가 방식마다 다르다 |
| DECISION16 | 같은 사용자가 두 번 동시에 연결할 때 | 나중에 돌아온 것이 이긴다. 지금 다시 등록과 같은 잠금을 쓴다 | 작성자 | 지금 등록 흐름([connector.md](../connector.md) 「동시 요청과 잠금」)과 같다 |
| DECISION17 | 갱신하는 때 | 도구를 부르지 않아도 만료 전에 미리 갱신한다. 끊김은 다음 갱신 때 알아챈다 | 작성자 | DECISION7 의 「쓰려는 순간에야 알면 막힌다」 를 지키려면 쓰지 않는 연결도 갱신해야 한다. 오래 쓰지 않아 refresh token 이 만료되는 일도 막는다 |
| DECISION18 | 단추가 대신하는 칸 | 선언이 단추로 채울 비밀 칸을 지정한다. 나머지 칸(예: 저장소 이름)은 단추 화면에도 입력 칸으로 보이고 단추를 누르기 전에 채운다. 입력 칸이 하나도 없는 「단추 전용」 플러그인은 두지 않는다 | 작성자 | 붙여 넣기를 남기기로 한 DECISION5 와 맞다. 커리어 플러그인은 토큰 밖의 칸을 가진다 |
| DECISION19 | 「다시 연결 필요」 동안의 동작 | 연결이 지금의 준비 안 됨(`PENDING`)과 같이 다뤄진다. 도구 호출을 미리 막고 「외부 서비스 연결에서 연결을 확인해 주세요」 를 보인다. 「연결 다시 확인」 은 갱신을 한 번 더 시도한다 | 작성자 | 지금 연결 화면과 에이전트 화면의 준비 안 됨 규칙([connector.md](../connector.md) 「화면」)을 그대로 쓴다 |
| DECISION20 | 단추 흐름의 실패 표시 | 확인 도구 실패를 포함해 단추 흐름의 모든 실패는 돌아온 연결 화면에 까닭과 「다시 시도」 로 보인다 | 작성자 | 서비스 화면에서 돌아오는 페이지라 등록 창이 없다. REQ5 의 다른 실패와 한 모양으로 둔다 |
| DECISION21 | GitHub 저장소 고르기와 해제 | 단추는 GitHub App 설치 화면(설치와 허락을 한 번에)으로 보낸다. 연결 화면에 「GitHub 에서 저장소 바꾸기」 링크를 둔다. 해제 때는 허락만 취소하고, 설치가 남으면 「GitHub 설정에서 앱 설치도 지울 수 있어요」 와 링크를 보인다 | 사용자 2026-11-20 | 허락을 거두면 설치만 남아도 우리 쪽은 그 저장소에 접근하지 못한다. 설치를 지우려면 앱 private key 가 더 필요하다 |
| DECISION22 | Google 에서 권한 일부만 허락했을 때 | 요청한 권한을 모두 허락해야 연결한다. 일부만 허락하면 연결을 만들지 않고 「요청한 권한을 모두 허락해야 연결돼요」 와 「다시 시도」 를 보인다 | 사용자 2026-11-20 | 플러그인이 요청하는 권한은 이미 가장 작게 골랐다. 하나라도 빠지면 일부가 고장 난 채로 연결된다 |
| DECISION23 | 관리자 OAuth 앱 설정이 틀렸을 때 | 사용자 연결 상태는 두고 그 호출은 「잠시 뒤 다시」 오류로 끝낸다. 관리자에게 「GitHub 앱(커리어) 설정을 확인해 주세요」 알림 하나와 서버 비밀값 링크를 보낸다. 처음 연결이 이 이유로 실패하면 사용자에게 「관리자 설정 문제로 연결하지 못했어요」 를 보인다 | 사용자 2026-11-20 | 사용자가 고칠 수 없는 일은 고칠 수 있는 사람에게 알린다 |
