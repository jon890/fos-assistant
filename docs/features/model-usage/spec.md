# 새 모델을 관리자가 바로 쓰게 하고, 단계를 고를 때 모델 이름을 보인다

확인: 2026-11-19

## 목표

새 모델이 나왔을 때 그룹이 낡은 모델에 머물지 않게 한다(사용자 2026-11-19).
관리자는 모델 목록을 화면에서 다시 읽어 새 모델을 바로 고를 수 있고, 새 모델이 생기면 알림을 받는다.
그룹의 모든 사용자는 모델 단계를 고를 때 그 단계가 어떤 모델과 강도로 도는지 함께 본다.

## 조사로 확인한 사실

2026-11-19 에 코드와 Hermes v0.23.2 의 공개 tag 소스로 확인했다. 운영 왕복으로는 확인하지 않았다.

| 무엇 | 확인한 것 | 근거 |
| --- | --- | --- |
| 대화와 예약 작업이 저장하는 것 | 모델 이름이 아니라 단계만 저장한다. 단계가 어느 모델인지는 실행할 때마다 그룹 설정에서 읽는다. 관리자가 단계의 모델을 바꾸면 기존 대화와 예약 작업도 다음 실행부터 새 모델로 돈다 | [`model-usage.md`](../model-usage.md) 의 「모델 선택」, `ModelTierService` |
| Control Plane 의 걸러내기 | 모델을 이름으로 빼지 않는다. 그룹 목록에서 빠지는 경우는 켜진 profile 가운데 하나에 그 모델이 없을 때와 그룹이 숨겼을 때다 | `GroupModelCatalogService` |
| Hermes v0.23.2 의 Codex 목록 | 고정 목록에 gpt-6.2 가 없다. ChatGPT 계정의 Codex 목록이 준 모델은 이름을 가리지 않고 그대로 올린다. 저장해 둔 목록은 오래돼도 그대로 주고 뒤에서 다시 채우며, 계정 조회가 실패하면 옛 목록이 남는다 | `hermes_cli/codex_models.py` 의 `DEFAULT_CODEX_MODELS`, `_ranked_slugs`, `hermes_cli/models.py` 의 `cached_provider_model_ids` |
| 다시 읽기 | `refresh=true` 를 붙인 조회만 계정에 실제로 묻는다. Control Plane 은 목록에 없는 모델을 저장하려 할 때만 다시 읽는데, 관리자 화면은 목록에 있는 모델만 고르게 해서 그 길에 닿지 못한다 | [Hermes 계약](../../../hermes/docs/hermes-contract.md) 의 「`/api/model/options` 는 provider 와 모델 목록을 함께 준다」, `GroupModelCatalogService.refreshedCatalogFor` |
| v0.23.2 가 gpt-6.2 를 돌릴 때 | 6.2 를 옛 모델로 보고 강도 `max` 를 `xhigh` 로 낮춰 보낸다. 6.2 의 강도 처리는 개발 브랜치에만 있고 정식 릴리스는 v0.23.2 가 최신이다 | `agent/reasoning_effort.py` 의 `codex_supported_efforts` |
| 운영의 그룹 설정 | 숨김 목록에 gpt-6.2 계열이 없고, 관리자 목록의 gpt-6 계열에도 gpt-6.2 가 없다 | 코디네이터 2026-11-19 |

gpt-6.2 가 목록에 없는 원인은 정하지 못했다. 계정의 Codex 목록이 아직 주지 않는 경우와 Hermes 가 저장해 둔 목록이 낡은 경우가 남아 있다.
REQ1 의 「목록 새로 읽기」 를 누른 결과로 둘을 구분한다.

## 범위

| 순서 | 담는 것 | 요구사항 |
| --- | --- | --- |
| PR1 | 이 스펙과 설계, 관리자 화면의 「목록 새로 읽기」, 단계를 고르는 곳의 모델 이름과 강도 표시, 관련 문서와 ADR 갱신 | REQ1, REQ2, REQ3, REQ4, REQ5 |
| PR2 | 새 모델 알림 | REQ6, REQ7 |

범위 밖:

- 단계의 모델을 스스로 옮기는 일. 관리자가 직접 옮긴다(DECISION2)
- 단계에 어떤 모델을 둘지 정하는 일. 제품 코드와 마이그레이션에 모델 이름을 넣지 않는다. gpt-6.2 가 목록에 보이면 관리자가 화면에서 고른다(DECISION9)
- 단계에 둔 모델이 목록에서 사라졌을 때의 알림(DECISION6)
- 실행 기록과 사용량 화면의 모델, 토큰, 금액을 `MEMBER` 역할에게 보이는 일(DECISION4)
- Hermes 버전 올리기와 Hermes 설정에 모델을 직접 적는 일. 「목록 새로 읽기」 를 눌러도 gpt-6.2 가 없으면 그 결과를 근거로 따로 정한다(DECISION1)
- 관리자 화면에서 모델 이름을 문자열로 입력받는 일

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 관리자가 그룹 모델 설정 화면에서 모델 목록을 다시 읽는다 | `/admin/models` 에 「목록 새로 읽기」 단추가 있다. 누르면 Control Plane 이 켜진 profile 마다 Hermes 에 `refresh=true` 로 목록을 다시 묻고, 화면의 단계별 모델 선택지와 숨김 후보가 새 목록으로 바뀐다. 가짜 Hermes 가 다시 읽기에만 새 모델을 주면, 누르기 전에는 선택지에 없고 누른 뒤에는 있으며 그 모델로 단계를 저장할 수 있다. 읽는 동안 단추는 막히고 진행 중임이 보인다. 다시 읽은 뒤에는 단추 옆에 마지막으로 다시 읽은 시각이 보인다 |
| REQ2 | 다시 읽기는 관리자만 하고, 잦은 요청과 실패에도 기존 목록을 지킨다 | `MEMBER` 역할의 요청은 거절되고 Hermes 를 부르지 않는다. 같은 profile 을 마지막으로 다시 읽은 지 30초 안에 또 누르면 Hermes 를 부르지 않고 들고 있는 목록을 돌려주며, 화면은 새로 묻지 않았다는 안내와 마지막으로 다시 읽은 시각을 보인다. 대화 실행이 그 30초 안에 다시 읽었을 때도 같다. 한 profile 이라도 다시 읽기에 실패하면 화면에 실패 안내가 보이고 화면의 선택지는 누르기 전 목록 그대로다. 다시 읽기에 성공한 profile 의 목록은 Control Plane 이 새 값으로 들고 있는다(DECISION13) |
| REQ3 | 입력창의 모델 단계 선택을 세로 목록으로 바꾸고 줄마다 모델과 강도를 보인다 | 모델 단추를 누르면 관리자가 채운 단계가 정해진 차례의 세로 목록으로 열린다. 줄마다 단계 이름 아래에 `<모델> · <강도>` 가 보이고, 지금 단계의 줄에 체크 표시가 있다. 강도는 저장된 값(`medium`, `xhigh` 등)을 그대로 보인다(DECISION14). 강도가 비어 있는 단계는 모델만 보인다. 줄을 누르면 그 단계가 저장되고, 방향키로 옮길 때의 저장과 겹친 저장의 처리, 저장 중 보내기 막기는 지금과 같다. 화면 폭 360px 에서 다섯 줄의 단계 이름이 잘리지 않고, 긴 모델 이름은 줄임표로 끝난다. 닫힌 단추는 지금처럼 단계 이름만 보인다 |
| REQ4 | 모델 이름과 강도는 역할과 상관없이 단계를 고르는 곳에 보인다 | `MEMBER` 역할이 받는 단계 목록 응답에 단계마다 `model` 과 `reasoningEffort` 가 있고 `provider` 는 `null` 이다. `MEMBER` 역할로 연 입력창의 목록에 모델과 강도가 보인다. provider 이름은 어느 역할의 입력창에도 보이지 않는다. 실행 기록, 사용량, 대화 안 작업 과정의 응답과 화면은 바뀌지 않는다 |
| REQ5 | 예약 작업 화면의 모델 단계 선택에도 모델과 강도를 보인다 | 예약 작업을 만들고 고치는 화면의 「모델 단계」 선택지가 관리자가 채운 단계는 `<단계 이름> · <모델> · <강도>` 로, 비운 단계는 지금처럼 단계 이름만으로 보인다. 맨 위의 「기본값」 선택지는 지금 그대로다(DECISION12). 저장되는 값과 고를 수 있는 단계는 지금과 같다 |
| REQ6 | 그룹 모델 목록에 처음 보는 모델이 생기면 관리자에게 알린다 | Control Plane 이 하루에 한 번 그룹 모델 목록을 읽어 앞서 본 목록과 비교한다. 처음 보는 모델이 있으면 그 그룹의 `ADMIN` 역할 사용자마다 알림 하나를 만들고, 모델은 provider 와 모델 이름의 짝으로 구분하고, 알림은 새 모델마다 provider 의 표시 이름과 모델 이름을 담는다(DECISION15). 한 번의 확인에서 찾은 모델은 알림 하나에 모은다. 알림을 누르면 `/admin/models` 가 열린다. `MEMBER` 역할에게는 알림이 가지 않는다 |
| REQ7 | 새 모델 알림은 되풀이하지 않고 숨긴 모델을 알리지 않는다 | 한 번 알린 모델은 목록에서 빠졌다가 다시 나타나도 알리지 않는다. 그룹이 숨긴 모델과 숨긴 provider 의 모델은 알리지 않고 본 것으로 적는다. 관리자가 나중에 숨김을 풀어도 알리지 않는다. 관리자가 「목록 새로 읽기」 로 먼저 본 모델도 다음 확인에서 알린다(DECISION16). 기능이 처음 도는 날의 목록은 기준으로만 저장하고 알림을 만들지 않는다. 목록을 읽지 못한 날은 알림도 기준 변경도 없고 다음 날 다시 확인한다 |

### 배포 뒤 확인

PR1 을 운영에 배포한 뒤 코디네이터가 확인하고 결과만 남긴다.

- 관리자가 「목록 새로 읽기」 를 눌렀을 때 gpt-6.2 계열이 선택지에 나타나는가. 나타나지 않으면 계정의 Codex 목록이 주지 않는 것으로 보고 범위 밖의 후속(Hermes 설정, 버전 올리기)을 따로 정한다
- 나타나면 관리자가 단계를 gpt-6.2 로 옮긴 뒤 그 단계로 대화 한 번을 왕복시켜, 실행 기록의 실제 모델이 gpt-6.2 인지 본다
- `MEMBER` 역할 사용자의 휴대폰에서 입력창의 단계 목록에 모델과 강도가 보이는가

| DECISION10 | 새 모델 알림을 받는 사람 | 그 그룹의 `ADMIN` 역할 사용자 모두 | 작성자 | 단계 정의를 저장할 수 있는 사람이 `ADMIN` 뿐이다 |
| DECISION11 | 알림이 보는 목록 | 관리자가 단계에서 고르는 그룹 모델 목록(켜진 profile 의 교집합, 숨김 제외)이다. 평소 읽기로 보고 `refresh=true` 는 붙이지 않는다 | 작성자 | 알려도 고를 수 없는 모델은 알리지 않는다. Hermes 는 평소 읽기에도 저장한 목록을 뒤에서 다시 채우므로 하루 한 번 확인에는 평소 읽기로 충분하다 |
| DECISION12 | 예약 작업 화면에서 비운 단계와 「기본값」 선택지 | 비운 단계는 지금처럼 단계 이름만으로 남기고, 「기본값」 은 모델을 붙이지 않고 그대로 둔다 | 작성자 | 이번 범위는 이름 표시다. 예약 작업이 고를 수 있는 단계를 바꾸지 않는다. 「기본값」 은 발화할 때의 사용자 기본 단계와 그룹 기본 단계로 정해져, 만드는 시점에 보인 모델이 실제와 달라질 수 있다 |
| DECISION13 | 일부 profile 만 다시 읽기에 실패했을 때 성공한 profile 의 목록 | 버리지 않고 새 값으로 들고 있는다. 그 화면의 선택지는 바꾸지 않고 실패 안내를 보인다 | 작성자 | 실행 때의 다시 읽기가 이미 profile 마다 따로 갱신한다(`ModelOptionsService.refreshedOptionsForAgent`). 그룹 목록은 교집합이라 한 profile 의 새 모델만으로는 선택지가 늘지 않는다 |
| DECISION14 | 강도의 표기 | 저장된 값을 그대로 보인다. 우리말로 옮기지 않는다 | 작성자 | 사용자가 「강도(medium, high)도 함께」 로 답했다(2026-11-19). 관리자 화면의 선택지와 같은 표기라 가족이 본 값을 관리자에게 그대로 말할 수 있다 |
| DECISION15 | 새 모델을 구분하는 기준 | provider 와 모델 이름의 짝이다. 알림에 provider 의 표시 이름을 함께 적는다 | 작성자 | 단계 정의가 provider 와 모델의 짝을 저장한다. 같은 이름이 다른 provider 에 생기면 고를 수 있는 것이 늘어난다. 알림은 관리자만 받으므로 provider 를 보여도 DECISION4 와 어긋나지 않는다 |
| DECISION16 | 숨긴 모델과 「목록 새로 읽기」 로 먼저 본 모델 | 숨긴 모델은 알리지 않고 본 것으로 적는다. 「목록 새로 읽기」 는 본 목록을 바꾸지 않는다 | 작성자 | 관리자가 스스로 숨김을 푼 모델은 새 소식이 아니다. 단추를 누른 관리자 말고 다른 관리자도 알림을 받아야 한다 |
| DECISION17 | DECISION9 의 강도 `max` 를 지키는 방법 | 관리자가 지키는 운영 약속이다. 화면과 저장은 막지 않는다 | 작성자 | 막으려면 제품 코드에 모델 이름을 넣어야 한다. 고르면 화면에는 `max` 로 보이고 실제로는 `xhigh` 로 돈다는 점을 [Hermes 계약](../../../hermes/docs/hermes-contract.md) 에 적는다 |

## 도메인 규칙 변경

도메인 규칙 변경 없음: 여러 기능이 참조하는 RULE ID 문서를 바꾸지 않는다. 역할에 따라 응답에서 빼는 값의 표([`chat.md`](../chat.md) 의 「역할에 따라 응답에서 빼는 값」)는 기능 문서의 계약이라 구현 PR 에서 함께 고친다.
