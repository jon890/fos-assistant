# 도구 실패 뒤 다른 방법을 해 보고 묻기

확인: 2026-11-20

REQ7 과 DECISION12 는 2026-11-21 사용자 결정으로 더했다.

## 목표

비서가 도구 한 번이 실패했다고 바로 「사진을 올려 달라」 처럼 사용자에게 넘기지 않는다.
같은 목표에 닿는 다른 방법을 두 번까지 해 보고, 그래도 안 될 때만 무엇을 해 봤는지 알리고 사용자에게 묻는다(사용자 2026-11-20).

사용자 원문: 「이렇게 한번 실패하면 바로 턴이 끝나버리는데. 다른 방법을 더 시도해보는 harness 설정은 없을까?」
사용자가 고른 방향(2026-11-20): 우리 도구의 실패 결과에 「다음에 해 볼 방법」 을 넣는다. 공통 답변 지침에 「도구가 실패하면 다른 방법을 해 본 뒤에만 사용자에게 묻는다」 를 더한다.

## 범위

두 PR 로 나눠 순서대로 한다(DECISION4). PR 마다 그 단계의 설계와 구현을 함께 담는다.

| PR | 담는 것 | 요구사항 |
| --- | --- | --- |
| PR1 | 공통 지침의 「도구가 실패했을 때」, fos-ctx 와 Control Plane MCP 도구의 실패 글, 그림 참고 사진을 받지 못했을 때 먼저 알리기 | REQ1, REQ2, REQ3, REQ5, REQ6, REQ7 |
| PR2 | 링크 사진 받기가 같은 페이지의 다른 사진 후보를 차례로 보기 | REQ4, REQ6 |

범위 밖:

- Hermes core 의 재시도 규칙을 바꾸기. 지침과 우리 도구의 결과 글만 고친다(AGENTS.md 「지켜야 할 것」)
- Hermes 내장 도구(`web_search`, `web_extract`, `image_generate` 의 본체)의 실패 글. Hermes 가 만드는 글이라 공통 지침으로만 다룬다
- 플러그인의 복구 어휘를 넓히기. 지금처럼 승인한 실행의 실패에만 둔다(DECISION3)
- 실패 결과에 프로그램이 읽는 다음 방법 코드를 더하기(DECISION3)
- 비서가 찾은 사진 주소를 링크 사진 받기에 넘기기. [ADR-20261120 / link-image-source](../../adr/ADR-20261120-link-image-source.md) 를 그대로 둔다(DECISION1)
- 사진 서버가 Content-Type 을 틀리게 보낸 사진을 바이트로 알아보기. 따로 진행 중인 작업이 한다
- 새 화면과 평가 세트의 실패 문항(DECISION4). 단 REQ7 의 그림 참고 사진 사례 하나는 평가 세트에 넣는다(DECISION12)
- 비서가 찾은 사진을 그림 참고로 받기. [비서가 찾은 사진 스펙](../agent-found-image/spec.md) 이 맡는다. 그 스펙이 이 문서의 「비서가 찾은 주소는 받지 않는다」(배경 표, DECISION1, DECISION12)를 바꿨다(2026-11-21). 검색과 페이지 읽기 결과에 나온 주소는 받고, 받지 못했을 때 먼저 알리는 REQ7 은 그대로다

## 요구사항과 인수 조건

「다른 방법」 은 실패한 호출과 다른 도구를 부르거나, 같은 도구를 다른 인자로 부르는 것이다. 「두 번까지」 는 사용자가 바란 일 하나에 대해 처음 실패한 뒤 해 보는 다른 방법의 수다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 공통 지침이 도구 실패 뒤 다른 방법을 해 보게 한다(PR1) | 모든 실행의 공통 지침 「도구 호출」 아래에 「도구가 실패했을 때」 가 들고, 그 글이 아래를 말한다. 실패 글에 다음 방법이 있으면 그것부터 해 본다. 같은 목표에 닿는 다른 방법을 두 번까지 해 본 뒤에만 사용자에게 묻는다. 같은 도구를 같은 인자로 다시 부르지 않는다. Control Plane 도구가 연속 두 번 실패했으면 세 번째는 다른 서버의 도구(Hermes 내장 도구나 플러그인)로만 하고, 없으면 사용자에게 묻는다. 새 시간 상한은 두지 않고 지금 실행 시간 상한을 따른다(DECISION2). 「잠시 뒤 다시」 류의 일시적 실패도 같은 호출을 다시 하지 않고, 다른 도구가 있으면 그것으로 해 보고 없으면 잠시 뒤 다시 해 달라고 바로 알린다(DECISION10). 지침 글을 검사하는 단위 테스트가 이 문장들이 든 것을 본다 |
| REQ2 | 바로 물어야 하는 실패에서는 다른 방법을 찾지 않는다(PR1) | 공통 지침이 아래 실패에서는 다른 방법을 찾지 않고 지금처럼 바로 사용자에게 알리라고 말한다. 승인 대기(`[승인 대기]` 판정 글), 로그인·보안문자·기기 인증처럼 사람 손이 필요한 화면(`HUMAN_ACTION_REQUIRED`), 사용자가 거절한 것, 결과를 알 수 없는 실행(`UNKNOWN`), 결제와 구매 상한, 연결이 끊겼거나 다시 연결이 필요한 플러그인. 보안·정책으로 막힌 주소나 도구(내부망 주소, 이 연결에 등록되지 않은 도구, 위험 명령, 코드 실행으로 플러그인 부르기)는 다른 도구로 같은 대상을 다시 노리지 않고 바로 알린다. 막히지 않은 다른 대상으로 같은 일을 하는 것(예: 위험 명령 대신 안전한 명령)은 다른 방법으로 해도 된다(DECISION9). 이 실패들에 대한 지금 지침과 플러그인 설명의 「다시 부르지 않는다」 는 그대로다(DECISION2) |
| REQ3 | 우리 도구의 실패 글이 다음에 해 볼 방법을 준다(PR1) | fos-ctx 와 Control Plane MCP 도구가 모델에게 돌려주는 실패 글마다 끝에 「다음 방법: …」 한 줄이 있거나, REQ2 에 드는 실패면 「사용자에게 바로 알린다」 는 한 줄이 있다. 사용자에게 넘기라고만 시키는 글(예: 「사진을 직접 올려 달라고 한다」 만 있는 글)이 남지 않는다. 다른 방법이 없는 실패는 다음 방법 줄에 「다른 방법이 없으니 무엇을 해 봤는지 알리고 사용자에게 묻는다」 를 쓴다. 결과 모양(`isError`, `{"error": …}`)과 Hermes·화면 계약은 바꾸지 않는다(DECISION3). 실패 글을 모아 두 줄 가운데 하나가 있는지 보는 단위 테스트가 backend 와 fos-ctx 에 하나씩 있다 |
| REQ4 | 링크 사진 받기가 같은 페이지의 다른 사진 후보를 본다(PR2) | 사용자가 보낸 주소가 웹 페이지면 Control Plane 이 `og:image`, `twitter:image`, 상품 정보(JSON-LD `Product` 의 `image`)의 차례로 후보를 받아 보고, 처음 받아진 사진을 쓴다. 후보는 그 페이지 글에서만 나오고 내부망 차단, 금지 목록, 넘기기 횟수, 크기와 제한 시간은 지금 규칙을 그대로 따른다([ADR-20261120 / link-image-source](../../adr/ADR-20261120-link-image-source.md)). 모든 후보가 안 되면 지금처럼 실패하고, 실패 글은 REQ3 의 꼴로 사진을 올려 달라고 묻게 한다. 받기 객체의 단위 테스트가 첫 후보가 사진이 아니고 둘째 후보가 사진인 페이지에서 둘째 사진을 받는 것을 본다 |
| REQ5 | 다 해 보고도 못 하면 무엇을 해 봤는지 알리고 묻는다(PR1) | 공통 지침이 다른 방법을 다 해 보고도 못 했으면 답에 해 본 것을 한 줄로 적고 사용자에게 묻거나 부탁하라고 말한다. 다른 방법으로 해냈는데 결과가 처음 뜻과 달라졌으면(예: 기억을 고치지 못해 새로 남겼다, 대표 사진 대신 상품 정보의 사진을 썼다) 답에 그 사실을 한 줄 알린다. 결과가 같으면 적지 않는다(DECISION11). 새 화면은 없다. 해 보는 동안의 도구 호출과 실패는 지금처럼 작업 과정 블록에 보인다(DECISION4) |
| REQ6 | 배포 뒤 실제 사례로 확인한다 | PR1 배포 뒤 다른 방법이 있는 실패 하나(예: 「memory_id 없이 새로 남긴다」 를 주는 기억 고치기 실패)를 왕복시켜 비서가 묻기 전에 다른 방법을 부른 것이 실행 사건에 남는다. PR2 배포 뒤 `og:image` 로 사진을 받지 못하는 공개 상품 페이지 링크로 그림 한 장을 만들어 본다. 결과는 기능 파일에 적는다(DECISION4) |
| REQ7 | 그림의 참고 사진을 받지 못하면 비슷하게 그려 넣지 않고 먼저 알린다(PR1) | 그림을 만들 때 참고 사진을 받지 못하면(링크 사진 받기 실패, 비서가 찾은 주소처럼 넘길 수 없는 주소, 이 대화에 없는 가리킴) 비서가 설명만으로 비슷하게 그려 넣지 않는다. 먼저 그 사진을 쓰지 못한다는 것과 대안(사용자가 사진을 올리거나 링크를 보내기)을 알린다(DECISION12). 공통 지침의 「도구가 실패했을 때」 가 이것을 말하고, fos-ctx 가 그림 만들기를 막는 실패 글이 REQ3 의 끝 줄 꼴로 이 다음 방법을 준다. 답변 품질 평가 세트에 이 사례 문항이 하나 있고 그 문항은 답이 사진이나 링크를 보내 달라고 하는지 본다. 지침과 실패 글을 검사하는 단위 테스트가 이 문장을 본다 |
