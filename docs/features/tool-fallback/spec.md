# 도구 실패 뒤 다른 방법을 해 보고 묻기

## 목표

비서가 도구 한 번이 실패했다고 바로 「사진을 올려 달라」 처럼 사용자에게 넘기지 않는다.
같은 목표에 닿는 다른 방법을 정해진 횟수까지 해 보고, 그래도 안 될 때만 사용자에게 묻는다(사용자 2026-11-20).

사용자 원문: 「이렇게 한번 실패하면 바로 턴이 끝나버리는데. 다른 방법을 더 시도해보는 harness 설정은 없을까?」
사용자가 고른 방향(2026-11-20): 우리 도구의 실패 결과에 「다음에 해 볼 방법」 을 넣는다. 공통 답변 지침에 「도구가 실패하면 다른 방법을 해 본 뒤에만 사용자에게 묻는다」 를 더한다.

## 범위

미정. DECISION4 로 정한다.

범위 밖:

- Hermes core 의 재시도 규칙을 바꾸기. 지침과 우리 도구의 결과 글만 고친다(AGENTS.md 「지켜야 할 것」)
- Hermes 내장 도구(`web_search`, `web_extract`, `image_generate` 의 본체)의 실패 글. Hermes 가 만드는 글이라 공통 지침으로만 다룬다
- 플러그인의 복구 어휘를 넓히기. DECISION3 으로 정한다

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 공통 지침이 도구 실패 뒤 다른 방법을 해 보게 한다 | 모든 실행의 공통 지침 「도구 호출」 절에 DECISION2 의 횟수, 같은 도구를 같은 인자로 다시 부르지 않기, 바로 물어야 하는 실패의 목록이 든다 |
| REQ2 | 바로 물어야 하는 실패에서는 다른 방법을 찾지 않는다 | 승인 대기, 로그인·보안문자 같은 사람 손이 필요한 화면, 사용자가 거절한 것, 결과를 알 수 없는 실행(`UNKNOWN`), 결제와 구매 상한에 걸린 것은 지금처럼 바로 사용자에게 알린다 |
| REQ3 | 우리 도구의 실패 글이 다음에 해 볼 방법을 준다 | DECISION3 이 정한 도구의 실패 글마다 「다음에 해 볼 방법」 이 있거나, 바로 물어야 하는 실패라는 표시가 있다. 사용자에게 넘기라고만 시키는 글이 남지 않는다 |
| REQ4 | 링크 사진 받기 실패 사례가 고쳐진다 | DECISION1 로 정한다 |
| REQ5 | 다 해 보고도 못 하면 무엇을 해 봤는지 알리고 묻는다 | DECISION4 로 정한다 |
| REQ6 | 고쳐졌는지 확인한다 | DECISION4 로 정한다 |
