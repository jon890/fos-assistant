# 커리어 Backend 를 가족 비서로 옮기기

확인: 2026-11-21

## 목표

커리어 일(공고 추천, 공부 추천, 면접 연습, 지원 준비, 후보자 맥락 문서와 프로필 원고)을 커리어 Backend 와 노트북 Claude Code 없이 가족 비서의 대화와 예약 작업으로 한다.
운영할 서비스와 데이터베이스를 하나씩 줄이는 것이 주 목적이다(사용자 2026-11-21).

지금은 fos-agents 저장소의 `career-os/services/career-backend`(NestJS 와 MySQL)가 커리어 데이터를 갖는다.
비서에 붙인 커리어 플러그인(`fos-career`)의 MCP 도구와 비서용 스킬 사본 둘(공고 추천, 읽을거리 수집)이 이 Backend 를 부른다.
노트북의 Claude Code 전용 스킬은 홈서버로 동기화하는 비공개 작업본(`applications/`, `library/`, `state/`)을 쓴다.

## 범위

**이번에 하는 것**

- Backend 가 가진 다섯 묶음을 비서의 저장 수단으로 옮긴다: 공고 추천, 공부 추천과 게시 기록, 면접 연습, 후보자 맥락 문서, 프로필 원고
- 공고, 분석, 회사 평가, 공부 자료, 면접 복습 상태처럼 줄이 많은 표 데이터는 커리어 에이전트 주인의 에이전트 작업 폴더에 파일(SQLite, JSON)로 두고, 스크립트가 실행 공간에서 그 파일을 읽고 쓴다
- 후보자 맥락 문서 4개(현재 경력, 역할 선호, 지원 상태, 학습 관심사)와 프로필 원고(원티드, LinkedIn, GitHub)는 기억 문서로 둔다
- 노트북 전용 지원 준비 스킬 넷(지원 패키지, 이력서 PDF, 이력서 검토, 공고별 면접 질문 준비)을 비서용 스킬로 옮긴다
- 공고 추천과 공부 추천의 매일 실행을 비서의 예약 작업으로 돌리고 Hermes cron 의 커리어 작업을 지운다
- 커리어 Backend, 그 데이터베이스, Backend 를 부르는 플러그인 도구, 노트북 전용 스킬, 프로필 갱신 스킬(`sync-profile`), 비공개 작업본 동기화와 그 release 를 내린다
- 실행 공간이 받는 env 목록에서 Backend 주소와 token 파일을 뺀다(fos-assistant `hermes/plugins/dashboard-profile-api/sandbox.py`)

**이번에 하지 않는 것**

- 지금 Backend 와 작업본에 쌓인 데이터를 옮기지 않는다. 사람이 쓴 문서도 처음부터 다시 쓴다
- 월별 Claude Code 사용량 기록을 비서로 옮기지 않는다. 노트북 파일에만 쌓고, 비서 사용량 쪽에서 따로 정한다
- 비서 Control Plane 에 새 테이블이나 여러 플러그인이 쓰는 범용 표 저장을 만들지 않는다
- 공고나 추천 목록을 보는 새 화면을 만들지 않는다. 목록은 리포트 파일로 본다
- 지원 상태를 할 일로 챙기는 기능을 만들지 않는다. 지원 상태는 기억 문서로 둔다
- 작업 폴더의 커리어 데이터를 백업하지 않는다
- 공고 추천과 공부 추천의 판정 규칙(하루 추천 수, 제외 규칙, 분석 재사용 기준)을 바꾸지 않는다
- 가족 확장은 다음 기능이다. 사용자는 가족마다 자기 비공개 커리어 에이전트를 만들어 자기 작업 폴더와 기억으로 쓰기를 바란다(사용자 2026-11-21). 그 기능은 새 에이전트의 profile 에 실행기 경로를 주는 방법(운영이 profile 마다 더할지, 플러그인을 붙이면 자동으로 줄지)을 정한다

**PR 나눔**

단계마다 운영에서 쓸 수 있게 끝낸다. 앞 단계가 운영에서 왕복 확인된 뒤 다음 단계를 시작한다.

| 단계 | 저장소 | 내용 | 요구사항 |
| --- | --- | --- | --- |
| 1 | fos-agents | 공고 추천과 공부 추천의 실행기를 작업 폴더 SQLite 로 전환하고 비서용 스킬 둘과 예약 작업 지시문을 고친다 | REQ1, REQ2, REQ3, REQ4 |
| 2 | fos-agents | 면접 연습을 실행 공간 스크립트로, 맥락 문서와 원고를 기억으로 바꾼다. Backend 를 부르는 MCP 도구와 Backend token 칸을 지운다 | REQ5, REQ6, REQ7 의 플러그인 부분 |
| 3 | fos-agents | 지원 준비 스킬 넷을 비서용으로 옮기고 노트북 전용 스킬, `sync-profile`, 작업본 동기화를 지운다. 사용량 기록을 노트북 파일로 바꾼다 | REQ8, REQ9 |
| 4 | 운영 저장소 | 예약 작업 둘을 만들고 한 번 왕복시킨다. Hermes cron, Backend 서비스, 커리어 DB, 작업본 release, 실행 공간 env 의 Backend 값을 지운다 | REQ2, REQ7 |
| 5 | fos-agents, fos-assistant | fos-agents 의 Backend 코드와 문서를 지운다. fos-assistant 는 이 스펙과 설계를 함께 넣고 실행 공간 env 목록에서 Backend 값을 뺀다 | REQ7, REQ10 |

단계 하나가 운영 코드 크기 상한을 넘으면 plan 이 그 단계를 더 나눈다.

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 커리어 에이전트가 Backend 없이 공고를 수집하고 분석해 추천 리포트를 만든다 | Backend 를 부르지 않는 실행기로 대화에서 공고 추천을 부르면 작업 폴더의 커리어 SQLite 가 갱신되고 HTML 리포트가 「내 파일」 에 생긴다 |
| REQ2 | 공고 추천과 공부 추천이 매일 비서 예약 작업으로 돈다 | 두 예약 작업의 발화가 돌고 결과가 대화와 알림으로 온다. 운영 Hermes cron 에 커리어 작업이 없다 |
| REQ3 | 수집 이력, 공고 버전, 분석, 회사 평가, 제외 규칙, 추천 대기 큐가 실행 사이에 이어진다 | 두 번째 실행이 바뀌지 않은 공고의 분석을 다시 계산하지 않고, 제외한 공고와 이미 추천한 공고를 다시 추천하지 않는다 |
| REQ4 | 공부 추천이 소스와 커서, 후보 판정, 추천 기록, 게시 기록을 이어 간다 | 두 번째 수집이 앞 커서 뒤부터 읽고, 고른 추천과 사용자가 게시한 링크 기록이 다음 실행에서 보인다 |
| REQ5 | 면접 연습이 주제별 복습 상태, 연습 기록, 개인 질문을 대화 사이에 이어 간다 | 다른 대화에서 연습해도 앞 연습의 복습 대상과 저장한 개인 질문이 다시 나온다 |
| REQ6 | 후보자 맥락 문서와 프로필 원고를 기억 문서로 읽고 고친다 | 기억 화면에서 「역할 선호」 를 고치면 다음 공고 추천이 바뀐 기준으로 분석을 다시 계산한다. 에이전트가 원고를 읽어 GitHub, 원티드 반영 도구에 쓴다 |
| REQ7 | 커리어 Backend 와 DB, Backend 를 부르는 플러그인 도구가 사라진다 | 운영에 Backend 서비스와 커리어 DB 가 없다. 플러그인 선언에 Backend token 칸이 없고 도구는 GitHub, 원티드, 연결 확인뿐이다 |
| REQ8 | 지원 준비(지원 패키지, 이력서, 이력서 검토, 공고별 면접 질문 준비)를 비서 대화에서 한다 | 커리어 에이전트에서 각 스킬을 부르면 결과가 작업 폴더의 지원 폴더에 남고 HTML 결과가 「내 파일」 에 생긴다. 이력서 PDF 는 실행 공간에 도구가 있으면 PDF, 없으면 HTML 로 나온다 |
| REQ9 | 노트북 전용 커리어 스킬과 작업본 동기화가 없어지고 사용량 기록은 노트북 파일에 쌓인다 | fos-agents 에 Claude Code 전용 커리어 스킬, `sync-profile`, `career-workspace` 동기화 코드가 없다. 노트북 사용량 작업이 Backend 를 부르지 않고 파일에 쓴다 |
| REQ10 | 실행 공간이 Backend 값을 받지 않는다 | fos-assistant 의 실행 공간 env 허용 목록과 문서에 `CAREER_BACKEND_URL`, `CAREER_BACKEND_TOKEN_FILE` 이 없고, 그 값을 준 셸 설정은 거절된다 |

| DECISION21 | 같은 날 다시 부를 때 | 지금 규칙을 그대로 둔다. 공부 추천은 서울 날짜로 하루 한 번만 저장하고, 공고 추천은 이미 추천한 공고를 다시 넣지 않는다 | 작성자 | 판정 규칙을 바꾸지 않는다(fos-agents `career-os/docs/flow.md` 의 하루 한 번 저장) |
| DECISION22 | 리포트가 「내 파일」 에 쌓이는 방식 | 실행마다 날짜가 든 새 파일로 넣는다. 지난 리포트는 사용자가 지운다 | 작성자 | 「내 파일」 은 넣은 파일을 따로 보관하고 덮어쓰지 않는다. 지난 추천을 찾아볼 수 있다 |
| DECISION23 | 에이전트가 맥락 문서와 프로필 원고를 고칠 때 | 고친 안을 기억 제안으로 남기고 사람이 기억 화면에서 받아들인다. 받아들이기 전까지 다음 실행은 옛 문서를 쓴다 | 사용자 2026-11-21 | 비서 기억 규칙(docs/features/memory.md 「바로 저장 판정」)을 바꾸지 않는다 |
| DECISION24 | 예약 작업의 알림 | 두 작업 모두 알림을 「항상」 으로 둔다. 실행기 실패는 결과 글 첫 줄에 적어 알리고, 추천할 것도 실패도 없는 날은 「보고할 것 없음」 으로 조용히 끝낸다 | 사용자 2026-11-21 | 답 글에 실패를 적어도 발화는 성공으로 남아 「실패할 때만」 알림이 오지 않는다(docs/features/schedule.md) |

## 도메인 규칙 변경

도메인 규칙 변경 없음: 공고 추천, 공부 추천, 면접 복습의 판정 규칙(fos-agents `career-os/docs/prd.md`)은 그대로 두고 저장 자리만 바꾼다.
