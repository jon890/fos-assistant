# 비서 중심 대화: 사용자는 비서와만 이야기하고 전문 에이전트는 비서가 부른다

확인: 2026-11-21

## 목표

사용자는 늘 기본 비서와만 대화하며 일을 시킨다.
쇼핑, 커리어 같은 전문 에이전트는 사용자가 직접 고르지 않고, 비서가 필요할 때 불러 맡긴 뒤 그 결과를 비서가 정리해 답한다.
사용자가 에이전트를 고르는 자리를 없애 화면과 흐름의 갈래를 줄인다.

2026-11-21 사용자 원문: 「항상 비서랑 질문을 주고받고 내 일을 처리하고. 비서가 전문화된 에이전트를 호출만 할 수 있도록 해 줘. 나는 새 대화에서 전문화된 에이전트를 바로 부르지 말고. 항상 비서를 거쳐 가는 형태로 만들자. 최대한 복잡도를 줄이자.」

이 문서의 **비서**는 요청자의 기본 비서([에이전트 팀](../agent-team.md) 의 「대화방」 이 정하는 에이전트)다. **전문 에이전트**는 비서가 아닌 에이전트 모두다. 그룹 공개 에이전트와 관리자가 만든 역할 profile 의 에이전트도 든다.

## 지금 동작(2026-11-21 main)

- `/` 는 기본 비서와 이어지는 대화방을 연다([에이전트 팀](../agent-team.md) 의 「대화방」).
- 새 대화 화면 `/new` 는 위쪽 이름표 목록과 `@` 로 대화할 에이전트를 고른다. 주소 `/new?agent=<code>` 로 처음 고를 에이전트를 받는다. 고르지 않으면 목록의 첫 에이전트가 골라져, 운영에서 「네이버 쇼핑 담당」 이 처음 골라진 적이 있다([대화와 대기열](../chat.md) 의 「새 대화 화면」, `web/src/components/chat/agent-switcher.tsx`).
- 에이전트 상세와 외부 서비스 연결 화면의 「대화하기」 가 그 에이전트를 고른 새 대화를 연다([에이전트와 스킬](../agent-skill.md) 의 「에이전트 화면」, [플러그인 연결](../connector.md) 의 「연결 뒤 에이전트 고르기」).
- 메시지가 있는 대화의 `@` 는 고른 에이전트에게 모델 판단 없이 바로 맡기고, 그 답을 맡은 에이전트 이름표로 보인다. 비서는 끼지 않는다([에이전트 팀](../agent-team.md) 의 「지난 `@` 맡김」).
- 비서는 `agent_delegate` 로 맡기고 곧바로 `RUNNING` 을 받는다. 비서의 그 답이 먼저 끝나고, 결과가 오면 Control Plane 이 자동 답을 하나 더 연다([에이전트와 스킬](../agent-skill.md) 의 「위임 결과가 도착했을 때」). 2026-11-21 운영의 쇼핑 대화에서 「맡겼어」 답과 결과 답의 내용이 겹쳤다. 결과를 기다리는 길(`agent_status` 의 `wait_seconds`)은 먼저 살펴보기에만 있다.
- 맡긴 실행은 Hermes 사건 스트림을 열지 않아 도구 사건이 남지 않는다([실행 기록](../execution.md) 의 「사건 옮겨 적기」). 실행 트리와 대화의 작업 과정에서 맡은 에이전트가 무엇을 검색했는지 볼 수 없다.
- 입력창 맨 앞의 `/` 는 대화 에이전트의 켜진 스킬만 띄운다. 운영에서 커리어 에이전트와 새 대화를 열어 `/position-recommender` 를 보냈다.
- 연결을 처음 마치면 전문 에이전트 만들기를 제안하고, 거절하면 고른 에이전트(비서 포함)에 붙인다. 대화 안의 「이 에이전트에 붙이기」 승인 카드는 대화의 에이전트에 붙인다([서비스 개념 스펙](../service-concepts/spec.md) REQ15).
- 예약 작업은 작업마다 에이전트를 고른다([예약 작업](../schedule.md)).
- 「블로그 비서로 바꿔 줘」 에 비서는 `@` 나 새 대화에서 고르라고 안내하고 새 대화 링크를 붙인다([서비스 개념 스펙](../service-concepts/spec.md) DECISION8).

| REQ4 | 새 대화는 늘 비서와 시작한다. `/new` 에 에이전트 이름표 목록과 `@` 고르기가 없고, `?agent=` 주소는 무시된다. 에이전트 상세와 외부 서비스 연결 화면의 「대화하기」 가 없다. 관리자도 사용자 화면에서는 같다(DECISION3) | `/new` 와 `/new?agent=<전문 에이전트>` 모두 비서 이름표를 보이지 않는다(DECISION3). 보내면 비서와의 대화가 생긴다. 전문 에이전트로 새 대화를 만드는 요청은 서버가 거절한다. 에이전트 상세와 연결 화면에 「대화하기」 단추가 없다. 비서를 쓸 수 없으면(꺼짐) 입력창을 잠그고 「비서를 쓸 수 없어요. 관리자에게 알려 주세요」 를 보인다(DECISION15) |

| REQ6 | 메시지가 있는 대화의 `@` 맡기기를 없앤다. 비서 지시문에 「사용자가 맡길 수 있는 에이전트의 이름을 말하며 맡기라고 하면 그 에이전트에게 `agent_delegate` 로 맡긴다」 를 넣는다(DECISION5) | 입력창에서 `@` 를 쳐도 목록과 「맡기기」 칩이 뜨지 않는다. 보내기 요청의 `delegateTo` 는 서버가 거절한다. 지난 `@` 맡김의 줄과 답은 지금처럼 보인다. 실제 모델 평가 세트에 「쇼핑 담당한테 맡겨서 ○○ 찾아 줘」 문항이 있고 비서가 그 에이전트에 맡긴다 |
| REQ7 | 새 예약 작업은 비서로 만든다. 작업 화면과 에이전트의 예약 작업 도구(`task_`)에 에이전트 고르기가 없다. 이미 있는 다른 에이전트의 작업은 그대로 돈다. 그 작업을 고쳐 저장하면 비서로 바뀐다(DECISION8) | 작업 화면에 에이전트 칸이 없고 새 작업의 에이전트가 비서다. 배포 전부터 있던 쇼핑 담당 작업은 다음 발화에서도 쇼핑 담당으로 돌고 결과가 그 읽기 전용 대화에 쌓인다. 그 작업의 시각을 고쳐 저장하면 다음 발화부터 비서로 돌고 새 비서 대화에 쌓인다 |
| REQ8 | 「블로그 비서로 바꿔 줘」 처럼 다른 에이전트로 바꿔 달라고 하면 비서는 대화의 에이전트를 바꾸지 않고, 그 에이전트의 일은 자기가 맡겨 처리한다고 답한다. 링크를 붙이지 않는다. 쓸 수 없는 이름이면 맡길 수 있는 에이전트의 이름을 알린다(DECISION9) | 실제 모델 평가 세트의 에이전트 바꾸기 문항이 `/new?agent=` 링크 없이 맡기겠다는 답으로 통과한다. 서비스 개념 스펙 REQ4 와 DECISION8 이 이 결정으로 바뀌었다고 적혀 있다 |
| REQ9 | 연결은 전문 에이전트에만 붙인다. 연결 뒤 흐름은 「전문 에이전트 만들기」 와 「이미 있는 전문 에이전트에 붙이기」 둘이다. 대화 안의 붙이기 승인 카드는 늘 「그 서비스만 맡는 새 전문 에이전트를 만들어 붙이기」 하나를 승인받는다. 그 연결이 이미 붙은 전문 에이전트가 있으면 카드 없이 비서가 그 에이전트에게 맡긴다(DECISION25). 이미 비서에 붙은 연결은 그대로 둔다(DECISION7) | 연결을 마친 화면의 고르기 후보에 비서가 없다. 비서 상세의 연결 절에는 「붙이기」 가 없고 이미 붙은 연결의 떼기만 있다. 서버도 비서에 붙이는 요청을 거절한다. 비서 대화에서 「Gmail 쓸 수 있게 해 줘」 에 뜬 카드를 승인하면 「Gmail 담당」 같은 새 전문 에이전트가 생기고 그 연결이 붙는다. Gmail 이 붙은 전문 에이전트가 이미 있으면 카드가 뜨지 않고 맡긴 줄이 생긴다. 배포 전부터 비서에 붙은 연결은 그대로 쓰인다 |
| REQ10 | 비서 대화의 `/` 목록에 맡길 수 있는 전문 에이전트의 켜진 스킬이 「에이전트 · 스킬」 로 비서 스킬과 함께 보인다. 고르고 보내면 Control Plane 이 모델 판단 없이 그 에이전트에게 그 스킬 커맨드로 맡긴다. 맡긴 뒤 대화는 바로 비어 다음 질문을 받고, 결과가 오면 지금 위임 결과처럼 결과 도착 줄과 비서 답이 따로 생긴다(DECISION6, DECISION10, DECISION26) | `/` 목록에 「커리어 · position-recommender」 가 있다. 고르고 보내면 질문 아래 「나 → 커리어에게 맡김」 줄이 생기고, 커리어 에이전트의 실행이 그 스킬로 돈다. 끝나면 결과 도착 줄과 비서 답이 생긴다. 맡긴 일이 도는 동안 다른 질문을 보내면 바로 비서가 답하고, 결과 답은 끝난 뒤 그 아래에 생긴다. 목록은 요청자가 쓸 수 있고 켜진 에이전트의 것만 있다. 예약 작업 지시가 「에이전트 · 스킬」 꼴로 시작하면 발화 때 모델 판단 없이 그 에이전트에게 맡기고, 없는 에이전트나 꺼진 스킬이면 그 발화가 실패로 닫힌다(DECISION27) |

## 도메인 규칙 변경

도메인 규칙 변경 없음: `docs/domain/` 이 없고, 바뀌는 규칙(새 대화의 에이전트, `@`, `/`, 맡긴 일의 기다림)은 위 「함께 고칠 문서」 의 기능 파일이 갖는다.
