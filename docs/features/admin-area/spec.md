# 관리자 영역 재편: 메뉴를 세 묶음으로 나누고 첫 화면에 품질과 사용량 요약을 보인다

확인: 2026-11-20

## 목표

`ADMIN` 이 관리자 영역(`/admin`)을 열면 첫 화면에서 그룹 전체의 최근 실패한 실행과 이번 달 사용량을 한눈에 본다.
메뉴는 「살펴보기」, 「비서 설정」, 「사용자와 자원」 세 묶음으로 나뉘어 있어, 줄이 늘어도 찾는 화면이 어느 묶음에 있는지 안다.
관리자 화면마다 제목 자리와 폭, 빈 상태 안내가 같다.

지금은 아래와 같다(2026-11-20).

- 메뉴 여덟 줄(사용자, 에이전트, 모델, 도구, 사용량과 비용, 외부 서비스 연결, 브라우저, 파일 공간)이 묶음 없이 세로로 있다(`web/src/components/shell/admin-shell.tsx`)
- `/admin` 을 열면 `/admin/people` 로 바로 넘어간다(`web/src/app/admin/page.tsx`). 실패한 실행을 보려면 「사용량과 비용」 의 「실행 기록」 탭을 열어 목록을 훑어야 한다
- 휴대폰에서는 머리 아래에 메뉴가 가로로 미는 한 줄이다([`web/docs/code-architecture.md`](../../../web/docs/code-architecture.md) 의 「관리자 영역의 틀」)
- 「사용량과 비용」 의 실행 기록과 이번 달 값, 실행 상세는 관리자 본인의 실행만 센다(`backend/src/main/java/com/bifos/assistant/usage/summary/presentation/UsageController.java`). 가족이 겪은 실패와 가족이 쓴 비용을 관리자 영역 어디에서도 보지 못한다
- 화면마다 제목이 있거나 없고(`/admin/people` 와 `/admin/connections` 에만 `h1` 이 있다), 빈 목록과 실패 안내의 모양이 다르다
- 기억 두 층 스펙(브랜치 `jon890/memory-two-layer-spec`)이 `/admin/memory` 를, 에이전트 품질 스펙(브랜치 `jon890/agent-quality-spec`)이 관리자 품질 화면을 새로 만든다

## 범위

이 스펙은 PR 둘로 구현한다(DECISION7).

| PR | 담는 것 | 시작 조건 | 요구사항 |
| --- | --- | --- | --- |
| PR1 | 메뉴 세 묶음, 휴대폰 서랍, `/admin` 요약 화면 | 없음 | REQ1-REQ6 |
| PR2 | 관리자 화면들을 같은 머리 틀과 빈 상태 안내로 맞추기 | PR1 이 main 에 머지됐다. 화면 틀 스펙의 PR5(같은 머리 틀, [`app-shell/spec.md`](../app-shell/spec.md) REQ19 와 REQ20)가 main 에 머지됐다 | REQ7-REQ8 |

같이 진행 중인 스펙과는 이렇게 나눈다.

| 스펙 | 그 스펙이 갖는 것 | 이 스펙이 갖는 것 |
| --- | --- | --- |
| 에이전트 품질(브랜치 `jon890/agent-quality-spec`) | 품질 화면의 주소와 내용, 배포 뒤 확인 결과와 평가 점수가 무엇이고 어디 저장되는지 | 메뉴에서 품질 화면의 자리(「살펴보기」 의 두 번째 줄), 요약 화면의 「품질과 실패」 카드에서 그 결과를 보일 자리(REQ4) |
| 기억 두 층(브랜치 `jon890/memory-two-layer-spec`) | `/admin/memory` 의 내용 | 메뉴에서 「기억」 의 자리(「비서 설정」 의 마지막 줄) |
| 화면 틀([`app-shell/spec.md`](../app-shell/spec.md)) | 일반 화면과 설정 틀, 이름 메뉴의 「관리자 화면」 입구, 같은 머리 틀의 모양(REQ19, REQ20) | 관리자 영역의 틀과 메뉴, 그 머리 틀을 관리자 화면에도 쓰는 것(REQ7, REQ8) |

**하지 않는 것.**

- 별도 앱이나 별도 API 로 나누는 것. 같은 앱 안에서 `/admin` 아래만 다시 짠다(사용자 결정 2026-11-20)
- 화면 안의 기능, 순서, 문구를 바꾸는 것. 화면 하나를 다시 짜는 일은 화면마다 따로 스펙으로 정한다(DECISION6)
- 구독 요금제의 한도를 얼마나 썼는지(남은 양) 보이는 것. 지금 어디서도 읽지 않는 값이라 provider 가 무엇을 주는지 따로 조사한다(DECISION4)
- 관리자가 남의 실행 상세(도구 원본, 문맥 항목)를 여는 것. 요약 카드는 남의 실행을 세기만 하고 열지 않는다(DECISION10)
- 「사용량과 비용」 화면을 그룹 전체로 바꾸는 것. 그 화면은 지금처럼 본인 실행만 센다
- 관리자 화면의 주소를 바꾸는 것. 지금 주소는 그대로다(DECISION5)
- 관리자 입구. 화면 틀 스펙의 이름 메뉴 「관리자 화면」 하나 그대로다

## 요구사항과 인수 조건

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 관리자 메뉴는 세 묶음이다(PR1). 「살펴보기」: 요약, 품질, 사용량과 비용. 「비서 설정」: 에이전트, 모델, 도구, 기억. 「사용자와 자원」: 사용자, 외부 서비스 연결, 브라우저, 파일 공간. 묶음 이름은 메뉴 안의 작은 제목으로 보이고 누를 수 없다. 품질과 기억 줄은 그 화면이 main 에 들어온 PR 이 메뉴에 더한다. 그 전에는 줄이 없다(DECISION8). 실행 하나의 화면(`/admin/executions/{id}`)은 지금처럼 「사용량과 비용」 이 골라진 것으로 친다 | 넓은 화면의 메뉴에 묶음 제목 셋과 그 아래 줄이 위 순서로 보인다. 품질과 기억 화면이 없는 main 에서는 두 줄이 없다. `/admin/executions/{id}` 를 열면 「사용량과 비용」 줄이 골라져 있다 |
| REQ2 | 휴대폰 폭(`md` 미만)에서 관리자 메뉴는 서랍이다(PR1). 머리 맨 왼쪽의 메뉴 단추를 누르면 넓은 화면과 같은 묶음 목록이 왼쪽에서 열린다. 줄을 고르거나 바깥을 누르거나 `Esc` 를 누르면 닫힌다. 가로로 미는 메뉴 줄은 없앤다. 「관리자」 배지는 메뉴 단추 바로 오른쪽, 「사용 화면으로 돌아가기」 는 지금처럼 머리 오른쪽이다(DECISION13). 넓은 화면의 머리는 지금 그대로다 | 360px 에서 머리 아래에 가로 메뉴 줄이 없다. 메뉴 단추를 누르면 묶음 셋이 보이고, 「모델」 을 누르면 서랍이 닫히고 `/admin/models` 가 열린다. 키보드로 열고 `Esc` 로 닫힌다 |
| REQ3 | `/admin` 은 요약 화면이다(PR1). `/admin/people` 로 넘기지 않는다. 넓은 화면과 휴대폰 모두 관리자 영역의 첫 화면이 요약이다. 이름 메뉴의 「관리자 화면」 도 이 화면으로 온다. 요약 화면의 머리에는 제목 「요약」 과 설명 한 줄이 있다(DECISION14). 그 아래 「품질과 실패」 와 「이번 달 사용량」 카드 둘이 있고, 두 카드의 제목 옆에 「그룹 전체」 가 적혀 있다. 넓은 화면에서는 나란히, 휴대폰에서는 위아래로 보인다. 카드마다 자세히 보는 화면으로 가는 링크가 있다. 「품질과 실패」 는 품질 화면이 들어오기 전까지 「사용량과 비용」 의 실행 기록 탭을 「내 실행 기록」 이라는 글자로 열고, 「이번 달 사용량」 은 「사용량과 비용」 을 「내 사용량 자세히」 라는 글자로 연다. 그 화면이 본인 실행만 세어 카드 숫자와 다르다는 것을 링크 글자로 알린다(DECISION12) | `/admin` 을 열면 주소가 그대로이고 카드 둘이 보인다. 이름 메뉴의 「관리자 화면」 을 누르면 요약이 열린다. 카드의 링크를 누르면 해당 화면이 열린다 |
| REQ4 | 「품질과 실패」 카드는 그룹의 모든 사용자를 합쳐 최근 7일 동안 실패한 실행의 수와 가장 최근 것 세 건을 보인다(PR1, DECISION10). 실패의 기준과 세는 단위는 「사용량과 비용」 의 실행 기록과 같고, 7일은 서울 날짜로 오늘을 포함한 7일이다(DECISION9). 한 건마다 사람 이름, 에이전트 이름, 시각, 오류 코드가 보인다. 시각의 모양과 에이전트 이름이 없을 때의 대체 문구는 실행 기록과 같다. 관리자 본인의 실행만 누를 수 있고 누르면 그 실행의 화면(`/admin/executions/{id}`)이 열린다. 남의 실행은 누를 수 없고 상세를 열 길도 없다. 실패가 없으면 「최근 7일 동안 실패한 실행이 없어요」 를 보인다. 품질 스펙이 만들 배포 뒤 확인 결과와 평가 점수 추이는 같은 카드의 아래 자리에 들어간다. 그 데이터가 생기기 전에는 그 자리에 「아직 품질 확인 결과가 없어요」 를 보인다 | 관리자 본인 실패 둘과 다른 사용자 실패 셋을 지난 7일 안에 만들면 카드에 5 와 최근 세 건이 사람 이름과 함께 보인다. 본인 실행을 누르면 그 실행의 화면이 열리고, 다른 사용자의 줄은 링크가 아니다. 다른 사용자 실행의 번호로 `/admin/executions/{id}` 를 열어도 지금처럼 열리지 않는다. 서울 날짜로 7일 전(오늘 포함 7일 밖) 실패는 세지 않는다. 실패가 없으면 없다는 안내가 보인다. 품질 결과 자리에 「아직 품질 확인 결과가 없어요」 가 보인다 |
| REQ5 | 「이번 달 사용량」 카드는 그룹의 모든 사용자를 합친 이번 달 실행 수, 그중 구독 경로로 실행한 수, 예상 추가 사용 요금을 보인다(PR1, DECISION10). 달의 경계와 금액 계산은 「사용량과 비용」 요약 탭의 이번 달 값과 같은 규칙이고(`web/src/components/usage/monthly-summary.tsx`), 대상만 그룹 전체다. 금액을 확인하지 못한 것(가격을 찾지 못한 실행, 금액을 확인하지 못한 도우미, 도우미를 관측하지 못한 실행)이 하나라도 있으면 카드에 「금액을 확인하지 못한 실행이 있어 실제보다 적을 수 있어요」 한 줄을 더한다(DECISION11). 구독 한도의 남은 양은 보이지 않는다 | 관리자와 다른 사용자가 이번 달에 각각 실행하면 카드의 실행 수가 둘의 합이다. 관리자 한 사람만 실행한 그룹에서는 카드의 세 값이 같은 시각에 연 「사용량과 비용」 요약 탭의 이번 달 값과 같다. 가격을 찾지 못한 실행을 만들면 그 줄이 보이고, 없으면 보이지 않는다 |
| REQ6 | 요약 화면의 카드 하나를 읽지 못하면 그 카드 자리에만 「불러오지 못했어요」 와 「다시 읽기」 가 보이고 다른 카드는 그대로 보인다(PR1). 읽는 동안은 카드 모양의 뼈대가 보인다. `MEMBER` 역할 사용자가 `/admin` 을 열면 지금처럼 `/` 로 넘기고, 역할을 읽지 못했으면 지금처럼 넘기지 않고 안내를 보인다 | 실패 요약 읽기를 실패시키면 「품질과 실패」 카드에만 실패 안내가 보이고 「이번 달 사용량」 은 값이 보인다. 「다시 읽기」 를 누르면 다시 읽는다. `MEMBER` 역할로 `/admin` 을 열면 `/` 가 열린다 |
| REQ7 | 관리자 화면들은 화면 틀 스펙의 같은 머리 틀을 쓴다(PR2). 대상은 요약, 사용자, 에이전트, 모델, 도구, 사용량과 비용, 외부 서비스 연결, 브라우저, 파일 공간이다. 품질과 기억은 그 화면을 만드는 PR 이 처음부터 이 틀을 쓴다. 머리의 왼쪽에 제목과 한 줄 설명, 오른쪽에 그 화면의 주 단추(있을 때만)가 있고, 본문의 폭과 좌우 여백이 화면마다 같다. 에이전트 하나와 실행 하나의 화면은 같은 폭에 뒤로 가기와 제목이 같은 자리에 있다. 화면 안의 기능, 순서, 문구는 바꾸지 않는다. 표처럼 넓은 본문은 그 안에서 가로로 스크롤한다 | 대상 화면을 차례로 열면 제목의 왼쪽 끝과 본문의 폭이 모두 같다. 주 단추가 있는 화면은 단추가 머리 오른쪽 같은 자리에 있다. 360px 에서 제목과 단추가 겹치지 않는다 |
| REQ8 | 같은 화면들은 목록이 비었을 때, 불러오지 못했을 때, 읽는 중일 때 화면 틀 스펙 REQ20 과 같은 모양의 안내를 쓴다(PR2) | 대상 화면마다 빈 목록, 불러오기 실패, 읽는 중을 만들면 같은 자리에 같은 모양의 안내가 보인다 |
