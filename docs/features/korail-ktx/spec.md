# 코레일 KTX: 에이전트가 열차를 조회하고 승인하면 좌석을 확보하며, 결제는 사람이 한다

확인: 2026-11-10

## 목표

사용자가 대화에서 「내일 아침 서울에서 부산 가는 KTX 찾아 줘」 라고 하면, 에이전트가 「내 브라우저」 로 코레일 화면에서 열차를 한 번 조회해 보이고, 사용자가 고른 열차를 승인 뒤 좌석까지 확보한다.
결제는 사람이 「내 브라우저」 화면에서 직접 한다. 에이전트는 결제 단추를 누르지 않는다.

이 기능은 네이버 쇼핑([`../naver-shopping/spec.md`](../naver-shopping/spec.md))이 만드는 공통 기반의 두 번째 소비자다. 공통 기반은 사람이 연 대화에서만 부르는 도구(`attended_only`), 도구 이름의 영어 키워드와 이름 중복 검사, 화면 넘기기 카드와 「다 했어요」 다.

## 범위

이 스펙은 PR 둘로 구현한다(DECISION13). 이 스펙을 처음 구현하는 PR 은 PR1 이고, PR2 는 같은 스펙과 설계를 쓴다.

| PR | 담는 것 | 시작 조건 | 요구사항 |
| --- | --- | --- | --- |
| PR1 | 플러그인 틀, 연결 확인, 열차 조회. 계정 상태를 바꾸는 도구가 없다 | 쇼핑 PR1(`attended_only`, 선언 검사 강화)이 main 에 머지됐다 | REQ1~REQ5 |
| PR2 | 좌석 확보 승인 카드, 좌석 확보, 결제 화면 넘기기 | 쇼핑 PR2(화면 넘기기)가 main 에 머지됐다 | REQ6~REQ9 |

범위 밖:

- 반복 조회(취소표 감시)와 예약 조회(DECISION3)
- 결제 단추 누르기, 결제 정보 입력(DECISION4)
- 로그인, 캡차, 매크로 탐지 화면의 자동 풀이·우회(DECISION4)
- 확보한 좌석의 취소. 사람이 코레일에서 취소하거나 결제 기한이 지나 저절로 풀린다(DECISION7)
- 결제 기한 전 다시 알리기(DECISION6)
- KTX 계열이 아닌 열차(ITX, 무궁화 등), 왕복, 환승, 「다음」 페이지(DECISION8)
- 어른·어린이·경로가 아닌 할인(장애인, 국가유공자 등)(DECISION8)
- 좌석 지정(창가·통로, 호차), 예약대기 신청(DECISION10)
- 구매 상한(DECISION11)
- SRT 전용 플러그인이나 SRT 만의 범위. 코레일 화면에서 잡을 수 있는 SRT 열차는 범위 안이다(DECISION12)
- 먼저 살펴보기, 매일 깨우기, 예약 작업에서의 조회와 좌석 확보(DECISION5)

## 요구사항과 인수 조건

인수 조건은 가짜 코레일 화면(테스트용 HTML)과 가짜 중계 위에서 확인한다. 실제 코레일 계정과 운영 브라우저로 확인하는 절차는 플러그인 기능 파일(`docs/features/korail-ktx-connector.md`)이 갖고 사용자가 직접 돈다. PR 마다 그 PR 의 도구만큼 절차를 더한다.

| ID | 요구사항 | 관측할 인수 조건 |
| --- | --- | --- |
| REQ1 | 코레일 KTX 플러그인을 연결하고 에이전트에 붙인다 | 카탈로그에 `korail-ktx` 가 오르고, 사용자가 넣는 칸이 없다. 연결 확인 도구가 「내 브라우저」 에 닿는지와 코레일에 로그인했는지 보고, 로그인하지 않았으면 로그인 필요로 실패한다. 연결 화면의 「내 브라우저에서 로그인」 이 코레일 로그인 화면을 연다. 어느 에이전트에나 붙일 수 있다 |
| REQ2 | 열차를 한 번 조회한다 | 조회 도구가 출발역, 도착역, 날짜, 출발 시각(이 시각 이후), 인원(어른·어린이·경로 수), 좌석 종류(일반실·특실)를 받아 코레일 조회 화면에서 한 번 조회하고, 첫 화면에 나온 KTX 계열 열차와 코레일에서 잡을 수 있는 SRT 열차(DECISION12)마다 열차 종류·번호, 출발·도착 시각, 걸리는 시간, 고른 좌석 종류의 예약 가능 여부(가능·매진), 화면이 보인 어른 1인 운임을 돌려준다. 「다음」 을 누르지 않고 그런 인자도 없다. 자동 재시도를 하지 않는다. 조회는 새 탭에서 하고 정상으로 끝나면 그 탭만 닫는다. 결과는 대화에만 남고 서버에 저장하지 않는다 |
| REQ3 | 사람이 해야 하는 화면을 만나면 우회하지 않고 멈춘다 | 조회나 좌석 확보 중 로그인, 캡차, 매크로 탐지 화면을 만나면 아무것도 누르거나 입력하지 않고 탭을 남긴 채 그 종류(`login`, `captcha`, `bot_check`)를 담은 선언된 오류로 끝난다. 에이전트는 「내 브라우저」 에서 풀어 달라고 안내한다. 쇼핑 PR2 뒤에는 이 오류가 화면 넘기기 카드가 된다. 역 이름을 모르거나 예매할 수 없는 날짜면 화면을 더 움직이지 않고 그 까닭을 담은 오류로 끝난다 |
| REQ4 | 도구가 Hermes 도구 검색에 영어 키워드로 걸린다 | 도구마다 이름과 설명 첫 문장에 영어 동작·대상 낱말(예: search, train, ktx, korail, seat)이 있고, 쇼핑 PR1 의 선언 검사를 통과한다. 다른 플러그인과 도구 이름이 겹치지 않는다 |
| REQ5 | 조회는 사람이 연 대화에서만 돈다 | 먼저 살펴보기, 매일 깨우기, 예약 작업의 실행이 KTX 도구를 부르면 거절된다. 사람이 연 대화 안의 흐름(사람이 친 메시지, 「다 했어요」 단추 메시지, 승인 결과를 전하는 자동 turn, 그 대화의 위임 자식 실행)은 부를 수 있다(DECISION5) |
| REQ6 | 좌석 확보는 매번 승인 카드를 거친다 | 에이전트가 조회 결과의 열차 하나(조회가 준 열차 식별값)와 인원, 좌석 종류로 좌석 확보 준비를 부르면, 플러그인이 목록을 다시 조회하지 않고 그 열차의 코레일 운임 조회 화면 하나만 열어 인원 구성 전체 금액을 읽고, 서버가 만든 요약으로 카드가 뜬다(DECISION23, DECISION24). 카드는 열차 종류·번호, 날짜, 출발·도착역과 시각, 인원 구성, 좌석 종류, 운임 조회 화면이 보인 인원 구성 전체 금액을 보인다. 운임 조회 화면에서 사람이 해야 하는 화면을 만나면 카드 없이 REQ3 으로 멈춘다. 「승인하고 묻지 않기」 와 「이 대화에서 계속 허용」 이 없다. 상한 판정은 없다(DECISION11) |
| REQ7 | 승인하면 좌석을 자동 배정으로 확보하고 결제 단추는 누르지 않는다 | 승인 뒤 플러그인이 새 탭에서 그 열차를 다시 조회해 코레일 자동 배정으로 좌석을 잡는다. 결제 단추를 누르는 코드 경로가 없다. 같은 승인으로 두 번 잡지 않는다. 그 사이 로그인·캡차·매크로 탐지 화면을 만나면 그 승인을 끝내고 REQ3 으로 멈춘다. 사람이 풀고 이어 가면 에이전트가 다시 조회하고 새 승인 카드를 띄운다(DECISION25). 그 사이 매진이면 잡지 않고 매진을 알리며 예약대기를 신청하지 않는다. 결과를 모르면 다시 보내지 않고 그 승인을 끝낸 뒤, 「내 브라우저」 에 열린 탭을 확인해 달라는 화면 넘기기 카드를 띄운다(DECISION14) |
| REQ8 | 좌석을 잡으면 결제 화면을 넘긴다 | 잡은 뒤 화면이 보인 호차·좌석 번호, 결제할 금액, 결제 기한 시각을 읽어 결제 화면 넘기기 카드를 띄운다. 카드는 그 셋, 승인한 운임 합계(DECISION15), 「내 브라우저 열기」, 「다 했어요」 를 보인다. 기한이 지나면 코레일이 좌석을 저절로 취소한다는 안내를 적는다. 기한 전 다시 알리지 않는다(DECISION6). 「다 했어요」 뒤 결제가 됐는지 읽지 않는다(DECISION3) |
| REQ9 | 좌석 확보 준비는 사람이 연 대화에서만 시작한다 | 먼저 살펴보기, 매일 깨우기, 예약 작업의 실행이 좌석 확보 준비를 부르면 카드 없이 거절된다. 허용하는 흐름은 REQ5 와 같다 |

| DECISION15 | 운임의 출처 | 승인 카드의 금액은 운임 조회 화면이 보인 인원 구성 전체 금액, 결제 넘기기 카드의 금액은 잡은 뒤 화면이 보인 값이다. 둘이 달라도 멈추지 않고 결제 넘기기 카드에 둘을 나란히 보인다 | 작성자 | 상한이 없고(DECISION11) 결제는 사람이 금액을 보고 한다. 쇼핑의 결제 직전 재확인은 상한을 지키려는 것이다. 스펙 확인에서 사용자가 확인했다 |
| DECISION16 | 조회의 로그인 | 조회도 로그인한 브라우저로 한다. 로그인이 풀려 로그인 화면으로 넘어가면 REQ3 의 `login` 으로 멈춘다 | 작성자 | 같은 브라우저 하나만 쓰고(DECISION1), 좌석 확보는 로그인이 필요하다 |
| DECISION17 | 연결 확인의 로그인 판정 | 코레일 로그인 쿠키가 있는지만 본다. 화면을 열지 않는다. 만료된 세션은 다음 도구가 로그인 화면을 만나 REQ3 의 `login` 으로 드러난다 | 작성자 | 쇼핑 스펙 DECISION26 과 같다. 확인 때 화면을 움직이지 않아 매크로 탐지에 걸릴 일을 늘리지 않는다 |
| DECISION18 | KTX 계열만 고르는 법과 출발 시각 | 조회 조건에서 열차 종류를 KTX 계열로 골라 조회한다(코레일 화면이 SRT 를 같은 종류로 묶으면 함께 나온다). 코레일이 시 단위로만 고르게 하면 그 시로 조회하고, 사용자가 준 분보다 이른 열차는 플러그인이 결과에서 뺀다 | 작성자 | 전체를 조회한 뒤 KTX 만 남기면 첫 화면에 KTX 가 적거나 없다. 「이 시각 이후」 를 지킨다 |
| DECISION19 | 예약 가능 여부의 값 | 고른 좌석 종류를 지금 바로 그 인원만큼 잡을 수 있으면 `available`, 아니면(매진, 예약대기만, 입석만, 좌석 부족) `sold_out` 이다. 화면의 표시 글을 함께 싣는다 | 작성자 | 예약대기와 입석은 범위 밖이다(DECISION10). 좌석 확보에서야 실패하지 않게 한다 |
| DECISION20 | 잡은 뒤 일부 값을 읽지 못할 때 | 좌석을 잡았다고 화면이 보이면 읽은 값으로 결제 넘기기 카드를 띄우고, 못 읽은 칸은 「내 브라우저에서 확인」 으로 둔다. 잡았는지조차 모르면 DECISION14 다 | 작성자 | 잡은 좌석은 기한 안에 결제해야 해 카드를 늦추지 않는다 |
| DECISION21 | 역 이름 | 「서울역」 처럼 끝의 「역」 은 떼고 코레일 역 이름과 정확히 같을 때만 받는다. 비슷한 이름을 짐작하지 않고, 맞는 역이 없으면 오류로 끝내 에이전트가 사용자에게 다시 묻는다 | 작성자 | 다른 역으로 조회하거나 좌석을 잡는 일을 막는다 |
| DECISION22 | 매진으로 끝난 좌석 확보 | 탭을 닫고 승인을 끝낸다. 매진은 승인 결과로 에이전트 답에 알리고 화면 넘기기 카드를 띄우지 않는다 | 작성자 | 사람이 화면에서 할 일이 없다 |
| DECISION23 | 승인 카드의 금액 | 그 열차의 코레일 운임 조회 화면을 하나 더 열어 인원 구성 전체 금액(어린이·경로 할인 반영)을 카드에 보인다 | 사용자 2026-11-10 | 권장안(어른 1인 운임만)을 바꿨다. 화면 이동이 하나 느는 탐지 위험을 사용자가 감수했다 |
| DECISION24 | 승인 카드를 만들 때 다시 조회하는지 | 열차 목록을 다시 조회하지 않는다. 조회가 준 열차 식별값과 결과로 서버가 카드를 만들고, 운임 조회 화면만 연다(DECISION23). 카드가 뜬 뒤 매진되면 승인 뒤 좌석 확보에서 알린다 | 사용자 2026-11-10 | 승인 뒤 좌석 확보가 다시 조회한다(REQ7). 「운임 조회 화면만 연다」 는 DECISION23 과 맞추려고 작성자가 읽은 뜻이고 스펙 확인에서 사용자가 확인했다 |
| DECISION25 | 좌석 확보 중 사람 화면에서 멈춘 뒤 | 그 승인을 끝낸다. 사람이 풀고 이어 가면 에이전트가 다시 조회하고 새 승인 카드를 띄운다 | 사용자 2026-11-10 | 같은 승인을 두 번 실행하지 않는다. 쇼핑 스펙 DECISION33 과 같은 원칙이다 |
