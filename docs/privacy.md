# 개인정보 처리 안내

fos-assistant 는 사용자가 자기 서버에 직접 설치해 쓰는 오픈소스 개인 비서다.
이 문서는 Gmail 이나 네이버 블로그, 토스증권 같은 커넥터를 연결할 때 데이터가 어디로 가고 어디에 남는지를 설명한다.
Google OAuth 동의 화면이 이 문서를 개인정보처리방침으로 가리킨다.

## 누가 데이터를 갖는가

- 이 프로젝트의 개발자는 사용자의 데이터를 받거나 보관하지 않는다. 운영하는 중앙 서버가 없다.
- 데이터는 그 사용자가 설치한 서버 안에만 있다. 그 서버의 관리자가 데이터의 관리자다.

## Gmail 커넥터가 다루는 것

- 사용자가 자기 Google 계정으로 만든 OAuth client 와 refresh token 으로 그 계정에만 접근한다.
- 범위는 `https://www.googleapis.com/auth/gmail.modify` 와 `https://www.googleapis.com/auth/gmail.settings.basic` 이다. 메일 읽기, 초안 만들기, 라벨 관리, 보내기, 답장과 자동 분류 필터 관리를 한다. 휴지통으로 보내거나 영구 삭제하는 기능은 없다.
- 쓰기는 사용자가 화면에서 승인해야 실행된다. 라벨 생성·이름·색 변경과 초안은 상시 허락을 줄 수 있지만, 보내기와 답장, 메일의 라벨 변경, 필터 생성·삭제, 기존 메일 일괄 적용은 매번 승인한다.
- 읽은 메일 내용은 그 사용자의 대화에만 쓰이고, 그 서버의 대화 기록에 남는다.
- 대화에 쓰인 내용은 사용자가 그 서버에 설정한 AI 모델 공급자에게 요청의 일부로 전달된다. 어느 공급자를 쓸지는 설치한 사람이 정한다.
- OAuth 비밀값은 그 서버의 Hermes 쪽 두 곳에만 둔다. 연결마다 하나인 보관 파일과, 이 연결을 붙인 에이전트의 profile 설정 파일(`.env`)에 복사한 값이다. 데이터베이스와 로그에는 원문을 남기지 않는다.
- Google 에서 받은 데이터를 광고나 다른 목적에 쓰지 않고, 제3자에게 팔거나 넘기지 않는다.

## 네이버 블로그 커넥터가 다루는 것

- 네이버 계정의 비밀번호, 인증번호, 쿠키를 받지 않는다. 사용자가 로그인해 둔 Chrome 의 원격 디버깅 주소와 블로그 아이디만 받는다.
- 원격 디버깅 주소는 그 브라우저를 조작할 수 있는 값이라 비밀 칸으로 다룬다. Gmail 의 비밀값과 같은 두 곳(보관 파일과 붙인 에이전트의 profile `.env`)에만 두고, 데이터베이스와 로그에 원문을 남기지 않는다.
- 대화에 올린 사진은 사용자가 승인한 임시저장 작업에서만 그 브라우저를 거쳐 네이버로 간다. 임시저장 글은 그 계정 주인만 보고, 발행하는 기능은 없다.
- 미리보기는 사진을 복사하지 않고 같은 대화의 첨부를 부른다. 스티커 그림은 네이버의 공개 그림 주소에서 받아 그 대화의 결과물 폴더에 둔다.
- 임시저장 작업 동안 초안 사본이 그 서버의 임시 디렉터리에 잠깐 남고 작업이 끝나면 지워진다. 작업 상태 파일에는 본문과 사진 경로를 남기지 않고 24시간 뒤 지운다.
- 승인한 임시저장의 제목, 카테고리, 태그, 본문, 사진 파일 이름이 그 서버의 승인 기록에 남는다. 이것도 서버 관리자가 지운다.
- 「연결」 화면에서 연결을 해제하면 Gmail 과 같이 보관 파일과 profile 의 복사본이 지워진다. 네이버의 로그인은 그 브라우저에서 사용자가 직접 로그아웃한다.

## 토스증권 커넥터가 다루는 것

- 토스증권 Open API 의 `client_id` 와 `client_secret`, 읽을 계좌의 순번만 받는다. 비밀값은 Gmail 의 비밀값과 같은 두 곳(보관 파일과 붙인 에이전트의 profile `.env`)에만 두고, 데이터베이스와 로그에 원문을 남기지 않는다.
- 접근 토큰은 커넥터 프로세스의 메모리에만 두고 파일에 쓰지 않는다.
- 계좌번호 원문은 받지 않는다. 계좌를 고르는 화면과 도구 결과에는 끝 네 자리만 보인다.
- 보유 종목, 평가 금액, 주문 가능 현금, 주문 내역은 승인 없이 읽는다. 대화에 쓰이면 그 글이 모델 공급자에게 간다.
- 주문, 정정, 취소하는 기능은 없다.
- 「연결」 화면에서 연결을 해제하면 보관 파일과 profile 의 복사본이 지워진다. 토스증권 WTS 의 client 는 사용자가 직접 지운다.

## 커넥터가 계산용으로 쓰는 파일

- 합계 같은 계산을 위해 목록을 파일로 내는 커넥터는 그 서버의 커넥터 출력 디렉터리에 파일을 쓴다. 서버 관리자가 실행 공간 정책에 그 디렉터리를 정했을 때만 쓴다.
- 그 파일은 그 커넥터를 붙인 에이전트의 실행 공간에서만 읽기 전용으로 보인다. 같은 사용자의 다른 에이전트와 다른 사용자는 보지 못한다.
- 커넥터는 쓸 때마다 24시간 지난 파일을 지운다. 다시 쓰지 않으면 서버 관리자의 정기 정리가 지운다. 에이전트에서 그 연결을 떼거나 에이전트를 지우면 그 출력 디렉터리를 지운다.

## Google API 서비스 사용자 데이터 정책

Google API 에서 받은 정보의 사용과 전송은 [Google API Services User Data Policy](https://developers.google.com/terms/api-services-user-data-policy) 와 그 Limited Use 요건을 따른다.

## 연결을 끊고 지우는 법

- 비서의 「연결」 화면에서 Gmail 연결을 해제하면 붙인 모든 에이전트에서 떼어지고, 보관 파일과 그 에이전트들의 profile 에 복사한 OAuth 값이 모두 지워진다.
- 에이전트 화면에서 Gmail 연결을 떼면 그 에이전트의 profile 에 복사한 값만 지워진다. 보관 파일과 다른 에이전트의 복사본은 남는다.
- 예전 방식의 Gmail 연결 에이전트가 남아 있으면 그 에이전트의 profile 에도 값이 있다. 그 에이전트를 지우면 그 profile 이 거둬진다.
- Google 계정의 「보안」, 「서드 파티 앱 및 서비스」 에서 앱을 지우면 그 즉시 토큰이 무효가 된다.
- 대화를 지우면 화면에서 바로 사라지고, 몇 분 안에 그 서버의 정리 작업이 메시지와 첨부한 사진, 결과물 파일, 실행 기록의 본문, AI 런타임(Hermes)의 대화 기록을 지운다. 그 대화의 실행이 아직 돌고 있으면 끝난 뒤에 지운다.
- 지운 뒤에도 남는 것이 있다. 사용량 계산에 쓰는 실행 기록(토큰 수와 금액, 쓴 도구 이름)은 본문 없이 남는다. 이미 만든 데이터베이스 백업에는 지운 대화가 남아 있고, 그 백업을 언제 버리는지는 서버 관리자가 정한다. 승인 기록과 할 일, 알림의 글도 아직 함께 지우지 않는다.
- 승인한 쓰기(보내기, 답장, 초안, 라벨 생성·변경, 필터 생성·삭제, 기존 메일 일괄 적용)는 받는 사람, 제목, 본문, 검색어, 대상 수 같은 인자가 그 서버의 승인 기록에 남는다. 이것도 서버 관리자가 지운다.
- 승인과 거절, 실행 결과는 판단 피드백 기록에도 남는다. 이 기록에는 인자와 결과 글이 없고 인자의 해시만 있다. 그 대화를 지우면 함께 지워지고, 그렇지 않아도 365일이 지나면 지워진다.
