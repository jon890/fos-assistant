# 무엇을 만드는가

## 목적

**모델에도 어떤 제품에도 종속되지 않고, 자유로운 개인 누구나 자기 비서를 갖게 하려고 만든다.**
그러려고 여러 범용 커넥터를 연결해 자기만의 agentic workflow 를 만들 수 있게 한다.
대화로 일을 자동화하고, 그 맥락이 남는다.

그 개인들이 같은 목적으로 모여 함께 쓰는 단위를 **그룹**이라 부른다.
가족이 한 그룹이고, 친구들이 다른 그룹이다. 무엇으로 묶이는지는 그 사람들이 정한다.

바깥 서비스가 정해 준 비서를 쓰는 것이 아니다.
사람마다 자기 에이전트를 만들고, 그 에이전트가 자기만 볼 수 있는 자리에서 돌고,
여럿을 함께 돌려 하나의 일을 끝낸다.

그래서 네 가지를 지킨다.

- **자기 것이다.** 에이전트의 도구와 기억, 대화의 모델을 그 사람이 정한다
- **섞이지 않는다.** 남의 기억과 credential 이 자기 실행에 들어오지 않는다
- **지휘한다.** 하나가 끝나기를 기다리는 것이 아니라 여럿을 나눠 돌리고 합친다.
  무엇을 나눌지는 에이전트가 정하고, 누가 무엇을 볼 수 있는지는 우리가 정한다
- **남는다.** 한 번 알아낸 것을 다음 대화가 다시 묻지 않는다

**사람이 늘어도 같은 방식으로 는다.**
한 사람을 더하는 것이 관리자의 판단 하나로 끝나야 하고,
그 사람 때문에 다른 사람이 느려지거나 남의 것을 보게 되면 안 된다.

에이전트를 실제로 돌리는 것은 Hermes Agent 가 한다.
이 저장소는 그 앞에서 누가 무엇을 쓸 수 있는지 정하고, 화면을 만들고, 쓴 것을 기록한다.
근거는 [ADR-001](adr/ADR-001-hermes를-런타임으로-두고-core를-고치지-않는다.md) 에 있다.

**이 저장소는 누구나 자기 Hermes 에 붙여 쓰는 오픈소스다.**
사용자가 여러 에이전트를 정의하고 연결해 거느리는 Control Plane 을 만든다.
그래서 Hermes 에 설치할 plugin 과 profile 틀도 이 저장소가 갖고,
우리 운영의 값과 특정 서비스에만 쓰는 코드는 이 저장소에 두지 않는다.
근거는 [ADR-041](adr/ADR-041-hermes-에-설치하는-plugin-과-profile-틀은-이-저장소가-소유한다.md) 에 있다.

## 범위와 확인 방법

무엇을 하는지와 그것이 됐는지 무엇으로 아는지를 같은 줄에 둔다.

| 무엇을 한다 | 무엇으로 확인한다 |
| --- | --- |
| 이 저장소만 받아 자기 Hermes 에 연동한다 | `hermes/bundle.sh` 가 만든 묶음을 Hermes 에 설치하면 에이전트 만들기, 스킬 게시, MCP 호출 서명이 동작한다. 묶음에 우리 운영 값이 없다 |
| 사람을 더하는 것이 관리자의 판단 하나로 끝난다 | 관리 화면에서 주소를 더하면 그 사람이 로그인해 바로 대화를 시작한다. 그 사이에 홈서버를 만지지 않는다 |
| 사람마다 에이전트를 만들고 그 에이전트가 도구와 페르소나를 정한다 | 같은 사람이 에이전트를 골라 대화를 시작하면 그 에이전트의 도구로 돈다 |
| 사용자가 화면에서 자기 에이전트를 만들고 그룹에 공개한다. 공개해도 만든 사람이 관리한다 | 이름만 넣어 만든 에이전트로 바로 대화하고, 공개하면 그룹의 다른 사용자도 대화하되 각자의 기억과 대화는 서로 보이지 않는다. 그 사이에 홈서버를 만지지 않는다 |
| 에이전트를 관리하는 사람이 스킬을 올리고 고치고 지운다 | 올린 스킬을 다음 대화부터 에이전트가 알고 따른다. 그 사이에 홈서버를 만지지 않는다 |
| 대화창에서 `/스킬 이름` 으로 스킬을 바로 부른다 | 입력창에 `/` 를 치면 그 에이전트의 스킬이 보이고, 부른 스킬이 사용량 화면의 호출 이력에 남는다 |
| 대화마다 빠르게, 균형, 깊게를 고르고 고급에서 모델을 직접 고른다. 고르지 않은 대화에 적용하는 순서는 [모델 단계와 실행 기록](model-tiers.md) 의 「모델 선택」 이 정한다 | 다음 답부터 선택이 적용되고 실행 기록에 고른 단계와 실제 모델, 토큰, 시간이 보인다 |
| 자기 에이전트의 성격을 자기가 화면에서 쓰고 고친다 | 화면에서 성격을 고치면 그다음 대화부터 그 성격으로 답한다. 그 사이에 홈서버를 만지지 않는다 |
| 실행할 profile 을 요청자의 바인딩에서만 꺼낸다 | 요청 본문에 남의 profile 을 적어도 그것으로 돌지 않는다 |
| 기억을 사람이 승인한 것만 남긴다 | 에이전트의 제안은 `PROPOSED` 로 저장되고, 사람이 받아들이기 전에는 대화에 실리지 않는다 |
| 기억을 볼 수 있는 사람에게만 싣는다 | 남의 개인 기억은 실리지도 않고 도구로 읽히지도 않는다 |
| 기억을 영역으로 나누고 에이전트마다 받는 영역을 정한다 | 에이전트가 받지 않는 영역의 기억은 그 에이전트의 대화에 실리지도 않고 도구로 읽히지도 않는다. 영역을 나누기 전의 기억은 모든 에이전트가 전과 같이 받는다. 영역과 에이전트가 받는 영역을 고치는 화면과 경로는 아직 없다 |
| 기억을 고치거나 지워도 그 전의 값이 남는다 | 고친 뒤에도 앞선 판의 본문이 `memory_revision` 에 남고, 지운 항목의 마지막 값도 남는다. 앞선 판을 읽는 화면과 경로는 아직 없다 |
| 기억을 층으로 나눠 싣고 나머지는 도구로 읽게 한다 | 항목이 늘어도 대화 한 번의 입력이 그만큼 늘지 않는다 |
| 실행을 시작할 때 기록하고 끝날 때 갱신한다 | 실패하거나 끊긴 실행도 목록에 남는다 |
| 실행 하나가 무엇을 했는지 도구와 자식 실행의 트리로 보인다 | 화면에서 실행 하나를 열면 그 안에서 무엇이 불렸는지 보인다 |
| 구독제로 돌린 실행도 API 가격으로 환산해 보인다 | 관리자 화면에서 실제로 나간 돈과 환산액이 각각 따로 보인다. `MEMBER` 역할 사용자의 화면에는 금액과 모델 이름과 토큰 수를 그리지 않는다 |
| 비용을 에이전트와 모델과 날짜와 설정으로 나눠 본다 | 관리자가 무엇을 바꿨더니 얼마가 달라졌는지 화면에서 견줄 수 있다 |
| 여러 에이전트에 일을 나눠 돌리고 결과를 합친다 | 하나의 요청이 자식 실행 여럿을 만들고 그 기록이 한 트리에 남는다. 어느 에이전트에 맡길지는 Hermes 가 정하고, 맡긴 실행도 요청자의 권한으로만 돈다 |
| 에이전트가 답을 만드는 동안 무엇을 하는지 보인다 | 도는 동안 부른 도구와 하위 에이전트가 사람 말 한 줄씩으로 차례로 보이고, 끝난 답에서도 다시 펼쳐 볼 수 있다. 모델 이름과 토큰 수는 대화에 그리지 않는다 |
| 돌고 있는 답을 사람이 멈춘다 | 중지를 누르면 그 실행과 Control Plane 이 만든 자식 실행이 멈추고, 멈춘 자리까지의 답이 새로 고쳐도 남는다 |
| 마지막 답을 다시 받는다 | 다시 받으면 이전 판이 사라지지 않고 넘겨 볼 수 있다 |
| 대화를 찾고 이름을 바꾸고 지운다 | 지운 대화가 목록에서 사라져도 그 대화의 비용은 사용량에 남는다 |
| 대화에 사진을 올려 에이전트에게 보인다 | 입력창에서 올린 사진을 에이전트가 파일로 읽고 답한다. 근거는 [ADR-020](adr/ADR-020-사진은-공유-디렉터리에-두고-에이전트가-파일로-읽는다.md) 에 있다 |
| 에이전트가 만든 HTML 결과물을 대화에서 바로 본다 | 답 아래의 파일을 누르면 옆 패널에 그 페이지가 사진과 함께 보인다. 그 페이지의 스크립트는 돌지 않는다 |
| 사용자마다 그 에이전트로 자주 하는 일을 추천한다 | 새 대화 화면에서 에이전트를 고르면 자기 대화 이력에서 나온 추천이 보이고, 이력이 없으면 그 에이전트가 할 수 있는 일이 보인다. 누르면 바로 보낸다 |
| 외부 서비스에 쓰는 일은 사용자가 승인한 것만 실행한다 | 승인이 필요한 도구를 에이전트가 불러도 그 서비스에 요청이 가지 않고, 승인하면 승인한 인자 그대로 한 번만 실행된다 |
| 정한 시각에 내 권한으로 에이전트를 돌린다 | 화면에서 「매달 1일 9시」 같은 예약 작업을 만들면 그 시각에 새 대화가 열려 답이 남는다. 서버를 다시 띄워도 같은 회차는 한 번만 돈다. 그 실행이 쓰기 도구를 부르면 사람이 있을 때와 같이 승인을 기다리고 알림이 간다 |
| 승인을 기다리는 요청과 만료된 요청을 어느 화면에서든 안다 | 다른 대화나 다른 화면에 있어도 알림 단추에 읽지 않은 수가 보이고, 알림을 누르면 승인 카드가 있는 대화로 간다. 화면을 닫았다 열어도 읽지 않은 알림이 남는다 |
| 에이전트가 사용자의 맥락을 보고 먼저 제안이나 질문을 내거나 침묵한다. 분야는 그 에이전트의 지침으로 더한다 | 에이전트 화면에서 「지금 살펴보기」 를 누르면 점검 대화에 원문 주소와 확인 시각과 중요한 이유가 붙은 발견이나 질문이 남고, 없으면 새로 알릴 것이 없다는 한 줄만 남는다. 그 실행은 쓰기와 외부 연락을 하지 못한다. 사용자는 스킬을 부르지 않는다 |
| 맡긴 일의 결과를 부모 에이전트가 정리하지 못해도 결과를 잃지 않는다 | 결과 정리가 실패하거나 중지되거나 서버가 다시 떠도 그 알림 줄 아래에 「결과 다시 전달」 이 보이고, 누르면 저장된 결과로 답이 생긴다. 맡긴 일과 승인한 동작은 다시 실행되지 않는다 |
| 지금 봐야 할 것만 화면 안에서 먼저 알린다([ADR-072](adr/ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md)) | 실패하고 다시 보내지 않은 turn, 승인 대기, 오래 도는 맡긴 일, 기한이 다가온 할 일이 사이드바 「지금 볼 것」 의 건수에 든다. 숨긴 항목은 새 변화가 올 때까지 다시 세지 않는다 |
| 대화에서 나온 할 일을 에이전트가 제안하고 사람이 받아들인 것만 챙긴다([ADR-073](adr/ADR-073-할-일은-에이전트가-제안하고-사람이-받아들인-것만-챙긴다.md)) | 에이전트가 제안한 할 일은 받아들이기 전까지 건수에 들지 않는다. 같은 제안이 같은 대화에서 되풀이되지 않는다. 할 일이 실행을 시작하지 않는다 |
| 지금 화면이 실행 상태와 할 일에 따라 카드의 순서와 내용을 바꾼다([ADR-074](adr/ADR-074-지금-화면은-원래-기록을-읽어-만든-view-이고-정해진-카드-넷만-그린다.md)) | 실패가 생기면 실패 카드가 위로 오고, 해결하면 사라진다. 카드마다 왜 보였는지와 출처가 보인다. 새 대화 화면은 지금처럼 바로 뜨고 「확인할 것 N건」 은 그 뒤에 채워진다 |
| 여러 기록에서 모은 문맥이 출처와 권한과 신선도를 잃지 않는다([ADR-071](adr/ADR-071-여러-출처의-문맥은-항목마다-출처와-권한과-신선도를-지닌-묶음으로-조립한다.md)) | 오래된 결과를 다시 전하면 모델 입력에 끝난 시각과 「오래됨」 이 붙는다. 민감 항목의 본문은 지시문에 실리지 않는다. 실행마다 실은 기록의 참조가 남고 본문은 남지 않는다 |
| 첫 반응 시간을 제품 지표로 본다 | 관리자 사용량 화면에서 사용자 turn 의 첫 반응 시간과 제출까지의 시간을 날짜와 모델 단계별 중앙값과 90번째 백분위로 본다([모델 단계와 실행 기록](model-tiers.md) 의 「첫 반응 시간」) |

각 줄의 근거는 [`adr/INDEX.md`](adr/INDEX.md) 에 있다.
실제로 그렇게 도는지는 [`AGENTS.md`](../AGENTS.md) 의 「확인」 절이 적은 검사가 판정한다.

커넥터는 에이전트에게 외부 서비스의 도구를 쥐어 주어 그 에이전트의 역할을 넓힌다. 첫 커넥터는 가계부이고, 이 저장소가 갖는 첫 범용 커넥터는 Gmail 이다.
사용자는 커넥터마다 계정을 한 번 연결하고, 그 연결을 자기 비공개 에이전트 여럿에 붙인다. 한 에이전트에 연결을 여럿 붙일 수 있고, 붙인 에이전트가 그 도구를 같은 turn 에서 직접 부른다([ADR-083](adr/ADR-083-커넥터는-사용자가-한-번-연결하고-자기-에이전트에-여럿-붙여-그-에이전트가-도구를-직접-부른다.md)).
연결 전, 해제 후, 뗀 뒤에는 그 에이전트가 커넥터 도구를 부르지 못해야 한다.
커넥터를 하나 더 붙이는 일은 plugin 에 `connector.json` 을 두고 운영 목록에 한 줄을 더하는 것으로 끝나고, Control Plane 과 웹을 고치지 않는다.
누구나 자기 계정으로 쓸 수 있는 서비스의 커넥터는 이 저장소의 `hermes/connectors/` 에 두고 기여를 받는다([ADR-064](adr/ADR-064-범용-커넥터는-이-저장소의-hermes-connectors-에-두고-저장소가-유지보수한다.md)).
화면과 상태 계약은 [커넥터 연결](connectors.md)이 갖는다.

## 답하는 비서에서 먼저 챙기는 비서로

사용자가 모든 기록을 직접 훑은 뒤 묻는 대신, 비서가 지금 봐야 할 것만 골라 보인다.
목적은 정보를 줄이는 것이 아니라 주의를 지키는 것이다. 그래서 먼저 알리기의 기본값은 알리지 않음이다.

이 방향의 다음 후보는 아래이고 아직 정하지 않았다.

- 오늘과 다음 카드. 일정 커넥터가 생긴 뒤에 정한다
- 비용 이상 알림. 관리자 영역 안에서 따로 정한다
- 문맥 묶음에서 고른 중요 맥락 카드
- 할 일에서 Hermes 위임으로 이어지는 실행. 승인 정책을 먼저 정한다
- 그룹이 함께 보는 맥락과 할 일

## 범위 밖

- **Hermes core 를 고치지 않는다.** profile 과 API server 와 plugin hook 만 쓴다.
  근거는 [ADR-001](adr/ADR-001-hermes를-런타임으로-두고-core를-고치지-않는다.md) 에 있다.
- **Hermes 내장 memory 도구를 에이전트에 주지 않는다.**
  기억에 닿는 길을 Control Plane 하나로 둔다.
  근거는 [ADR-003](adr/ADR-003-memory-권한은-주입으로-강제한다.md) 에 있다.
- **사람이 보지 않은 것을 기억에 남기지 않는다.**
  근거는 [ADR-012](adr/ADR-012-memory-는-사람이-승인한-것만-남는다.md) 에 있다.
- **비밀값을 데이터베이스에 넣지 않는다.** profile key 는 홈서버 파일에만 있다.
- **대화를 담는 별도의 작업 영역을 두지 않는다.** 그 자리는 에이전트가 갖는다.
  한 번 만들었다가 지웠다.
  근거는 [ADR-010](adr/ADR-010-작업-영역을-제거하고-에이전트가-그-자리를-갖는다.md) 에 있다.
- **운영 절차를 이 저장소가 갖지 않는다.** 배포와 profile 설정은 `fos-home-infra` 가 갖는다.
- **성공을 수치로 정하지 않는다.** 쓰는 사람이 하나라 표본이 되지 않는다.
  위 표의 「무엇으로 확인한다」 가 그 자리를 대신한다.
- **지난 turn 으로 되감지 않는다.** 다시 생성은 마지막 답에만 열고, 보낸 메시지는 고치지 않는다.
  질문을 바꾸려면 중지하고 새로 보낸다. 근거는 [ADR-024](adr/ADR-024-메시지-수정을-없애고-중지한-뒤-다시-보낸다.md) 에 있다.
  대화의 맥락을 Hermes session 이 갖고 있어 이 저장소가 되감을 수 없다.
  근거는 [ADR-022](adr/ADR-022-다시-생성과-수정은-같은-session-에-판으로-쌓는다.md) 에 있다.
- **Hermes 가 스스로 띄운 하위 에이전트는 중지로 멈추지 않는다.**
  `delegate_task` 로 뜬 하위 에이전트는 Hermes 가 목록을 주지 않아 우리가 찾을 수 없다.
  그 사실은 [`hermes/delegation.md`](hermes/delegation.md) 의 「취소가 아래로 내려가지 않는다」 절이 갖는다.
- **대화를 데이터베이스에서 지우지 않는다.** 지우면 목록에서 숨긴다.
  실행 기록이 그 대화를 가리키고 비용이 거기서 나온다.
- **결과물의 스크립트를 돌리지 않는다.** 에이전트가 만든 HTML 은 읽기만 한다.
  근거는 [ADR-027](adr/ADR-027-에이전트가-만든-html-은-대화별-폴더에-두고-스크립트-없이-보인다.md) 에 있다.
- **먼저 알리기를 화면 밖으로 보내지 않는다.** 외부 채널은 credential 을 둘 곳, 실을 내용의 민감도, 외부로 나가는 글의 승인을 함께 정한 뒤에 연다.
  근거는 [ADR-072](adr/ADR-072-먼저-알리기의-기본값은-알리지-않음이고-control-plane-기록에서-정한-신호만-화면-안에-올린다.md) 에 있다.
- **먼저 알리기와 할 일이 실행을 시작하지 않는다.** 보이기만 하고, 동작은 사람이 단추를 눌러 기존 경로로 한다.
- **화면 구성을 모델이 만들지 않는다.** 지금 화면은 정해진 카드 넷의 순서와 내용만 바뀐다.
- **예약 작업으로 workflow engine 을 만들지 않는다.** 작업은 「시각이 오면 정한 에이전트로 turn 하나를 연다」 이다. 작업 사이의 의존과 분기, 그룹 공용 작업은 두지 않는다. 근거는 [ADR-076](adr/ADR-076-예약-작업은-control-plane-이-갖고-발화한-실행은-대화-turn-경로로-돈다.md) 에 있다.
- **누구나 가입하는 서비스로 열지 않는다.** 그룹에 사람을 더하는 것은 관리자가 한다.
  모르는 사람이 들어오면 credential 과 비용의 경계를 다시 정해야 한다.

## 아직 정하지 않은 것

- **그룹마다 credential 을 나눌지.** 지금은 한 그룹이 구독 하나를 함께 쓴다.
  근거는 [ADR-002](adr/ADR-002-profile은-나누고-ai-계정은-가족이-함께-쓴다.md) 에 있고,
  그 결정은 가족이라는 신뢰 경계를 전제로 한다.
  그룹이 가족이 아니면 한 사람의 실행이 다른 사람의 한도를 먹는다.
- **비용을 나눌지.** 지금은 누가 얼마를 썼는지 보이기만 하고 나누지 않는다.

아직 만들지 않은 것은 [`code-architecture.md`](code-architecture.md) 의
「아직 만들지 않은 것」 절이 갖는다.
이 문서는 만들 것을 정하고, 그 문서는 지금 어디까지 왔는지를 적는다.
