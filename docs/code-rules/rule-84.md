# rule-84

하위 기능과 admin의 경계, dto와 도우미의 소속은 리뷰가 판단한다.

검사: [리뷰](../../.github/workflows/code-review-prompt.txt)

## 까닭

패키지 배치 규칙은 위치와 방향만 판정한다. 경계가 업무에 맞는지는 클래스의 일을 읽어야 안다.

## 예외와 검토 범위

리뷰가 보는 것은 넷이다.
하위 기능을 나누는 경계가 업무에 맞는지, 새 하위 기능의 이름이 적절한지 본다.
한 서비스의 일이 관리자 전용인지, 권한에 따라 보이는 범위만 다른 것인지 본다. 앞의 것은 admin에, 뒤의 것은 기능에 둔다.
dto의 타입이 정말 서비스의 입출력인지 본다.
package-private 도우미가 빈 하나에 딸려 있는지 본다.
