# health-progress-intake

사용자가 「오늘 상태 기록해 줘」, 「증상 보고」, 「오늘 운동 기록」 처럼 재활 부위의 경과를 말하면 그 보고를 기억으로 남긴다.
진단과 처방을 하지 않고, 사용자가 말한 범위만 기록한다.
예약 실행은 없다. 사용자가 부를 때만 돈다.

## 읽는 것

- 이번 대화의 사용자 보고
- 기억의 지금 상태. 요약 구역에 줄이 있으면 `memory_read`, 없으면 `memory_search` 로 `재활 현재 상태`, `재활 경과` 를 찾는다

## 남기는 것

기록은 `memory_remember` 로만 남긴다. 파일이나 다른 서비스에 쓰지 않는다.

**날짜별 경과 한 건.** 보고 하나를 새 기억 한 건으로 남긴다.

- 제목: `재활 경과 YYYY-MM-DD`. 같은 날 두 번째 보고면 같은 날짜의 기존 항목을 `memory_id` 로 고쳐 합친다
- 요약: 그날의 핵심 변화 한 줄
- 본문: 아래 칸을 한 줄씩. 사용자가 말하지 않은 칸은 `말하지 않음` 으로 쓰고 값을 짐작해 채우지 않는다
  - 통증
  - 불안정감
  - 붓기와 열감
  - 움직이는 범위
  - 걷기와 계단
  - 한 운동과 활동
  - 다음 날 반응
  - 위험 신호
  - 출처: 사용자 보고

**지금 상태 한 건.** 새 보고가 지금 상태를 바꿀 때만 고친다. 제목은 `재활 현재 상태` 이고, 기존 항목이 있으면 그 번호를 `memory_id` 로 준다.
본문은 아래 셋을 나눠 쓴다.

- 확정 사실: 사용자가 직접 말했거나 이미 믿을 만한 기록에 있는 것
- 사용자 보고: 주관적인 증상, 오늘 반응, 느낀 안정감
- 확인 필요: 의학적 해석이나 의료진 확인이 필요한 것

## 안전과 개인정보

- 보고에 위험 신호(빠질 듯한 느낌, 찌르는 통증, 붓기와 열감 증가, 잠기거나 걸리는 느낌, 다음 날 악화)가 있으면 조용히 기록만 하지 않는다. 진료를 다시 받는 편이 안전할 수 있다고 답한다.
- 사용자 보고를 넘어 의학적 결론을 끌어내지 않는다.
- 플랫폼 ID, 병원 등록번호 같은 불필요한 식별자는 기억에 넣지 않는다.
- 기록한 뒤 무엇을 남겼는지 두세 줄로 알린다. 기억 저장이 승인 대기로 가면 그렇다고 알린다.
