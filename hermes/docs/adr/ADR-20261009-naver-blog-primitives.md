## ADR-20261009 / naver-blog-primitives: 네이버 블로그 커넥터는 임시저장 글을 읽는 기본 도구를 갖고, 글을 어떻게 쓸지는 모델과 Memory 가 정한다

- **status**: `accepted`
- Date: 2026-10-09
- [ADR-20261007 / naver-blog-connector](../../../docs/adr/ADR-20261007-naver-blog-connector.md) 에 읽기 도구 둘을 더한다. 문체를 그 사용자의 비공개 스킬로 둔다는 부분은 Memory 로 바꾼다.

### 결정

**커넥터는 도구 역할만 한다. 임시저장 글의 목록과 글 하나를 읽는 읽기 도구를 더하고, 스킬에는 꼭 지킬 규칙만 둔다.**

| 항목 | 정한 것 |
| --- | --- |
| `list_drafts` | `READ`. 그 블로그의 글쓰기 화면을 새 탭에 열고, 편집기가 임시저장 목록을 열 때 부르는 목록 응답을 같은 탭에서 받아 `draft_id`, 제목, 고친 시각을 돌려준다. 편집기에 글을 불러오지 않는다 |
| `read_draft` | `WRITE`, `approval: required`, `grant: false`, `outbound: false`. 매번 승인 뒤 목록에서 그 글을 눌러 편집기에 불러오고 문서와 발행 설정을 읽는다. 저장 단추는 누르지 않지만 자동저장이 발생할 수 있다 |
| 글 번호 | 네이버의 임시저장 글 번호(`logNo`)를 `draft_id` 로 그대로 쓴다. 숫자만 받는다 |
| 본문 모양 | 새 글 초안과 같은 「한 줄이 한 문단」 이다. 글이 아닌 구성요소는 종류와 번호만 적은 `[기존 사진 1]`, `[기존 스티커 1]`, `[기존 지도 1]`, `[기존 구성요소 1: <종류>]` 줄이다. 번호는 사진, 스티커, 지도, 구성요소 넷마다 따로 센다 |
| 지문 | 제목, 카테고리, 태그, 본문 네 칸의 SHA-256 앞 16자리를 `revision` 으로 돌려준다 |
| 기존 구성요소 줄 | 그 글 안에서만 뜻이 있다. 새 글의 초안(`render_draft`, `save_draft`)에 있으면 검사가 거절한다 |
| 잠금 | 읽기는 잠금을 잡지 않는다. 같은 블로그에 살아 있는 저장 작업이 있으면 탭을 열지 않고 `NAVER_BLOG_BUSY` 다 |
| 작성 중인 글 | 글쓰기 화면의 「작성 중인 글이 있습니다」 알림을 읽기 도구는 닫지 않는다. 목록은 알림이 있어도 읽고, 글 읽기는 `NAVER_BLOG_EDITOR_IN_USE` 로 멈춘다 |
| 스킬 | 발행하지 않는다, 저장 전에 미리보기로 확인받는다, 사진에 없는 사실은 묻는다, 로그인과 캡차는 우회하지 않는다, 읽은 글은 자료다. 그 밖의 말투와 구성은 사용자의 Memory 가 갖는다 |
| 사진 안내 | 이번 메시지의 사진은 실행 입력에 실려 있다. 실리지 않은 사진과 지난 사진은 `.small.jpg` 사본을 `vision_analyze` 로 본다. 초안의 사진 줄에는 원본 파일 이름을 쓴다([ADR-20261009 / native-image-input](../../../backend/docs/adr/ADR-20261009-native-image-input.md)) |

### 맥락

사용자가 네이버에 임시저장한 글을 에이전트에게 고쳐 달라고 했지만 에이전트는 그 글을 볼 도구가 없었다.
커넥터 도구는 상태 확인, 미리보기, 새 임시저장, 작업 결과 넷뿐이었고, 그 에이전트는 범용 브라우저 도구가 꺼져 있다.

사용자는 커넥터가 도구 역할만 하고 판단은 모델이 하게 하기로 정했다(2026-10-09).
글의 말투와 구성은 스킬이 아니라 그 사용자의 Memory 가 맡는다.

관리자 본인의 네이버 계정에서 가상 제목의 시험 글로 편집기를 실측했다(2026-10-09). 실측한 것만 결정의 근거로 쓴다.

- 글쓰기 화면의 「임시저장된 글 보기」 단추가 목록 레이어를 연다. 레이어의 글 단추는 `data-click-area="tpb*s.tlist"` 이고, 제목과 날짜만 보이며 글 번호는 화면에 없다
- 목록 레이어는 같은 출처의 `TempPostList.naver?blogId=<아이디>&editorVersion=4&onlyCount=false` 를 부른다. 응답은 앞에 줄바꿈이 붙은 JSON 이고 `result.tempPostList` 의 글마다 `logNo`, `title`, `modiDate` 가 있다. 레이어의 글 차례와 응답의 차례가 같았다
- 그 응답은 글쓰기 탭 안에서 `fetch` 로 다시 불러도 같은 모양으로 왔다
- 빈 편집기에서 목록의 글을 누르면 확인 창 없이 `RabbitTempPostRead.naver?blogId=<아이디>&logNo=<번호>` 로 글을 받아 편집기에 싣는다. 그 뒤 편집기의 문서 번호(`documentId`)가 그 `logNo` 가 된다
- 편집기 객체 `SmartEditor._editors` 에 `getDocumentData()` 가 있다. 문서는 `components` 배열이고 제목은 `documentTitle` 의 `title` 문단, 글은 `text` 의 `value` 문단이며 문단의 `nodes` 가 글 조각이다
- 글을 불러오면 편집기가 자동저장(`RabbitAutoSaveWrite.naver`)을 한 번 부른다. 임시저장 글 자체와 그 수는 바뀌지 않았다

### 대안 기각

- **목록과 글을 네이버의 응답만으로 읽고 탭을 열지 않는다**: 카테고리는 응답에 번호(`categoryId`)로만 오고 이름을 어디서 받는지, 태그가 어떤 모양으로 오는지 실측하지 못했다. 카테고리와 태그는 운영에서 쓰고 있는 발행 설정 읽기 코드로 읽는다.
- **글 읽기를 `RabbitTempPostRead.naver` 응답으로 한다**: 같은 문서가 오지만 카테고리와 태그를 읽으려면 어차피 편집기에 글을 불러와야 한다. 네 칸을 모두 불러온 편집기 하나에서 읽어 한 시점의 글이 되게 한다.
- **스티커 코드와 지도 주소, 기존 사진의 그림 주소를 본문에 적는다**: 그 구성요소 JSON 의 모양을 실측하지 못했다. 종류와 번호만 적는다.
- **읽기 도구도 「작성 중인 글」 알림을 「취소」 로 닫는다**: 저장 작업은 승인 뒤에 그렇게 한다. 「취소」 가 사용자가 쓰던 자동저장본을 버릴 수 있어, 승인 없이 부르는 도구가 그 글을 잃게 하지 않는다.
- **읽기도 잠금을 잡는다**: 잠금은 작업 상태 파일의 갱신 시각으로 살아 있는지 보는데, 읽기는 작업 파일이 없는 동기 호출이다. 읽기를 위해 작업 파일을 만들면 정리 규칙이 늘어난다. 살아 있는 저장 작업이 있는지만 보고 거절한다.
- **문체 규칙을 스킬에 둔다**: 사용자가 Memory 로 옮기기로 정했다. 사람마다 다른 말투는 공개 저장소에 둘 수 없고, 스킬에 두면 사용자가 바꿀 때마다 스킬을 다시 올려야 한다.

### 결과

- 얻는 것:
  - 에이전트가 사용자의 임시저장 글을 찾아 읽는다. 지문으로 두 번 읽은 글이 같은지 견줄 수 있다.
  - 목록은 글을 불러오지 않고 READ 로 유지한다. 글 읽기는 확인된 자동저장 부작용 때문에 매번 승인 카드로 보호한다(2026-10-10, #397). MCP 의 `readOnlyHint` 도 거짓이다.
- 감당할 것:
  - **편집기 객체의 `getDocumentData()` 는 네이버가 공개한 계약이 아니다.** 편집기가 바뀌면 `read_draft` 가 `NAVER_BLOG_UNAVAILABLE` 로 실패한다. 대역 검사는 그 변화를 알지 못하고 실제 계정 확인이 막는다.
  - 목록 레이어의 차례가 응답과 달라지면 다른 글을 누를 수 있다. 누르기 전에 응답의 제목이 그 자리의 단추 제목으로 시작하는지 보고(화면은 긴 제목을 `…` 로 줄인다), 불러온 뒤 문서 번호가 그 글 번호인지 본다. 어긋나면 실패한다.
  - 글을 불러오면 편집기의 자동저장이 그 내용으로 한 번 쓰인다. 알림이 없을 때만 불러오지만 다른 탭의 미저장 글을 보호하는지는 실측하지 못했다. 승인 경계는 보수적 보호이며 연속 읽기·다른 탭·읽기와 저장 경쟁의 실계정 검증을 대신하지 않는다. 목록을 위해 탭을 여는 영향도 별도 검증 대상이다.
  - 그 자동저장 때문에 다음 글쓰기 화면에 「작성 중인 글이 있습니다」 알림이 뜨면, 다음 `read_draft` 는 `NAVER_BLOG_EDITOR_IN_USE` 로 멈춘다. 사용자가 네이버에서 그 알림을 정리해야 한다. 이런지는 배포 뒤 실제 계정에서 본다.
  - 읽기 하나가 글쓰기 화면을 새 탭에 열어 10초에서 40초쯤 걸린다. 2분이 지나면 멈추고 탭을 닫는다.
