## ADR-20261025 / connector-operator-base-url: 공개 오픈소스 서비스의 커넥터는 운영자가 띄운 그 서비스의 기준 주소 하나만 운영 값으로 받는다

- **status**: `accepted`
- Date: 2026-10-25
- [ADR-064](ADR-064-범용-커넥터는-이-저장소의-hermes-connectors-에-두고-저장소가-유지보수한다.md) 의 「운영 값이 있어야 도는 커넥터는 여기 두지 않는다」 에 예외 하나를 더한다. 나머지는 그대로다.

### 결정

**서비스 자체가 공개 오픈소스라 누구나 띄울 수 있는 커넥터에 한해, 운영자가 띄운 그 서비스의 기준 주소 하나를 `operator_env` 로 받아 이 저장소에 둔다.**

| 항목 | 정한 것 |
| --- | --- |
| 받는 값 | 그 서비스의 기준 주소 env 하나. 비밀이 아니다 |
| 값의 모양 | `https://` 주소. 계정 정보와 쿼리, fragment 가 없다. 커넥터가 이 모양이 아니면 부르지 않고 설정되지 않았다는 코드로 끝낸다 |
| 여전히 막는 것 | `operator_secrets`, 그 밖의 `operator_env`. 사용자의 자격 증명은 지금처럼 `fields` 로만 받는다 |
| 허용 범위 | `hermes/tests/test_connectors_contract.py` 의 `OPERATOR_BASE_URL_ENV` 가 커넥터 id 와 env 이름을 함께 고정한다. 목록 밖이면 공통 검사가 실패한다 |
| 값을 두는 곳 | 운영 목록. 이 저장소의 코드와 문서, 검사에는 실제 주소를 적지 않는다. 검사는 자리표시 주소를 쓴다 |
| 첫 대상 | `financial-workbench`. [금융 워크벤치 커넥터](../../../docs/features/financial-workbench-connector.md) 가 갖는다 |

### 맥락

사용자는 자기 금융 온톨로지 워크벤치(공개 저장소 `jon890/fos-graphrag`)를 Hermes 에서 조회하기로 했다(2026-10-25).
토스증권 커넥터와 같은 에이전트에 붙여 보유 종목과 투자 근거를 함께 답하게 하려는 것이다.

워크벤치는 SaaS 가 아니다. 누구나 받아 띄우는 프로그램이라 주소가 운영자마다 다르다.
사용자는 워크벤치에서 발급한 개인 연동 토큰만 알고, 워크벤치가 어디 떠 있는지는 운영자가 안다.
ADR-064 는 주소 같은 운영 값이 필요한 커넥터를 그 서비스의 저장소에 두게 했고, 공통 검사는 `operator_env` 가 있으면 실패했다.

### 대안 기각

- **기준 주소를 사용자 입력 칸으로 받는다**: 규칙은 그대로 두지만 커넥터 MCP 서버는 실행 공간 밖에서 돈다. 사용자가 넣은 임의 주소로 서버가 홈서버 내부망을 부를 수 있는 SSRF 표면이 생긴다. 사용자가 워크벤치의 주소를 알아야 하는 것도 부담이다.
- **워크벤치 저장소에 커넥터를 두고 운영 목록에 올린다**: 가계부와 같은 방식이고 ADR-064 에 가장 맞는다. 그러나 홈서버가 다른 저장소를 plugin 출처로 신뢰하도록 운영을 바꿔야 한다. 커넥터 계약이 바뀔 때 함께 고쳐지지 않는다는 ADR-064 의 기각 사유도 그대로 남는다.
- **`operator_env` 를 모든 커넥터에 연다**: 운영 값 없이 도는 커넥터라는 이 저장소의 성격이 사라진다. 운영 값에 비밀을 넣는 길도 열린다.

### 결과

- 얻는 것: 공개 오픈소스 서비스의 커넥터가 계약과 함께 이 저장소에서 고쳐진다. 사용자는 토큰만 넣는다. 주소는 운영자가 정하므로 사용자가 내부망 주소를 넣을 길이 없다.
- 감당할 것:
  - 이 커넥터는 운영자가 주소를 넣기 전에는 돌지 않는다. 운영 목록에 값이 없으면 대시보드가 카탈로그에서 뺀다.
  - 허용 목록을 넓히는 일은 이 ADR 의 범위를 다시 판단하는 일이다. 커넥터를 더할 때 서비스가 공개 오픈소스인지, 받는 값이 기준 주소 하나인지 리뷰가 본다.
