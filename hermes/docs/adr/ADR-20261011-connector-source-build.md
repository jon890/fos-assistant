## ADR-20261011 / connector-source-build: 커넥터 실행 파일은 소스로 빌드하고 Git 으로 추적하지 않는다

- **Date**: 2026-10-11
- **status**: `accepted`
- **결정**: Gmail, 네이버 블로그, 토스증권 커넥터의 생성된 JavaScript 실행 파일은 Git 으로 추적하지 않는다. 소스와 lockfile, 빌드 도구 버전을 기준으로 검사와 패키징 때 빌드한다.
- **맥락**: 생성 파일을 커밋하면 같은 변경이 소스와 실행 파일에 중복되고, 서로 다른 기능을 합칠 때 실행 파일 충돌이 생긴다. 배포할 실행 파일은 검증한 소스에서 만들어야 한다.

### 부분 대체

[ADR-084](ADR-084-gmail-typescript-filters.md) 의 실행 파일 커밋 결정과 커밋 파일 대조 검사를 대체한다. 서버 언어와 실행 방식, 자격 증명과 승인 정책은 바꾸지 않는다.

### 검사와 배포 계약

커넥터의 타입 검사와 대역 시험 뒤 소스로 실행 파일을 빌드한다. 패키지 검사는 Docker 에서 만든 실행 파일과 같은 소스의 로컬 빌드 결과를 바이트 단위로 비교하고, 실제 stdio 도구 목록을 확인한다. 공식 API fixture 와 생성한 계약 자료는 계속 추적한다. ignore 규칙은 생성된 실행 파일 세 개만 대상으로 한다.

후속 Python 계약 검사도 실제 실행 파일을 사용하므로, 새 checkout 에서 패키지 검사가 성공하면 빌드한 실행 파일을 남긴다. 검사 전에 실행 파일이 있었다면 성공·실패 모두 원래 파일과 권한을 보존한다. 이 경우 후속 실행 전에 현재 소스로 다시 빌드해야 한다. 실패하면 검사 중 생성된 파일을 정리한다.

배포 묶음은 소스 커밋과 도구 버전, 파일의 지문과 권한을 포함한다. 소비자는 검증한 묶음을 사용한다. 환경값과 운영 실행 절차는 비공개 운영 저장소가 소유한다.

### 결과

소스 변경을 검토하면서 생성 파일 충돌을 처리할 필요가 줄어든다. 대신 실행 파일이 없는 checkout 에서는 stdio 실행 전에 빌드해야 한다. 빌드에 필요한 패키지 설치와 네트워크 접근은 검사·패키징 단계에서 끝내며, 커넥터 실행 중 설치는 하지 않는다.
