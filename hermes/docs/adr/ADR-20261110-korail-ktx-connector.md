## ADR-20261110 / korail-ktx-connector: 코레일 KTX 는 내 브라우저의 코레일 화면을 고정 단계로 눌러 한 번 조회하고, 약관 위험은 사용자가 감수한다

- **status**: `accepted`
- Date: 2026-11-10
- **decision-type**: `architecture`
- **areas**: `security, operations`
- **현재 규칙의 원본**: [코레일 KTX 플러그인](../../../docs/features/korail-ktx.md), 스펙 [`docs/features/korail-ktx/spec.md`](../../../docs/features/korail-ktx/spec.md)(사용자 확인 2026-11-10), 설계 [`design.md`](../../../docs/features/korail-ktx/design.md)
- [ADR-20261110 / naver-shopping-connector](../../../docs/adr/ADR-20261110-naver-shopping-connector.md) 의 `attended_only` 경계와 도구 이름 검사, [ADR-20261007 / user-browser](../../../docs/adr/ADR-20261007-user-browser.md) 의 사용자 브라우저와 중계를 그대로 쓴다.

### 결정

**코레일 KTX 플러그인은 「내 브라우저」 의 새 탭에서 코레일 조회 조건 화면을 열고, 고정 단계로 조건을 넣어 「열차 조회」 를 한 번 누른 뒤 목록을 고정 식으로 읽는다.**
좌석 확보는 이 결정의 범위 밖이다. PR2 는 backend 의 승인 틀에 걸쳐 루트 `docs/adr/` 에 따로 ADR 을 쓴다.

| 항목 | 정한 것 |
| --- | --- |
| 조회 | 사람이 요청할 때 한 번. 첫 화면의 열차만. 「다음」 과 자동 재시도가 없다. 반복 조회(취소표 감시)와 예약 조회를 하지 않는다 |
| 조작 | 자리는 플러그인 소스의 선택자 표로 CDP `DOM.performSearch` 가 찾고, 누르기와 글 넣기는 CDP `Input.*` 로 한다. 넣는 글은 확인을 통과한 인자뿐이다. 탭에서 부르는 식은 상수뿐이다 |
| 속도 | 사람 속도 간격과 조회 간격 제한을 두지 않는다(사용자가 탐지 위험을 알고 속도를 택했다) |
| 사람이 해야 하는 화면 | 로그인, 매크로 탐지(`CODE : -8xxx` 안내), 보안 문자면 아무것도 더 누르지 않고 그 탭을 남긴 채 그 종류의 오류로 끝난다 |
| 위험도 | 두 도구 모두 `READ`, `attended_only` 다. 조회는 코레일 계정의 조회 기록과 탐지 대상이 된다 |

### 맥락

- 코레일에는 공개 예매 API 가 없다. 공식 Open API 는 승차권 진위확인 하나이고, 비공식 앱 API 클라이언트는 2026-10 부터 막혔다는 보고가 있다
- 코레일은 매크로를 탐지해 로그인·조회 단계부터 막는다. 철도회원 약관상 1회 적발 30분, 2회 1개월 예매 제한, 3회 탈퇴 뒤 3년 재가입 불가다. 사용자는 이 위험을 알고 좌석 확보까지 열기로 했다
- 2026-11-10 에이전트 전용 브라우저로 공개 조회를 한 번 하자 첫 조회에서 「매크로, 개발자도구 등 미허가 도구 사용 시 이용이 제한될 수 있습니다」 와 `CODE : -8003` 이 뜨고 목록이 비었다. 같은 날 「내 브라우저」 에서 사람이 화면 중계로 한 조회에는 뜨지 않았다. 플러그인이 같은 브라우저를 CDP 로 다룰 때 뜨는지는 배포 뒤 실제 계정 확인의 첫 항목으로 본다
- 조회 화면은 클라이언트 렌더링이고 공지 층이 단추를 덮는다. 주소 하나로 결과를 받는 쇼핑과 달리 화면을 눌러야 한다

### 대안 기각

| 대안 | 기각 까닭 |
| --- | --- |
| 비공식 앱 API 를 부른다 | 막혔다는 보고가 있고, 약관 위반이 화면 조작보다 분명하다. 계정의 로그인 정보를 플러그인이 다뤄야 한다 |
| 탭에서 식으로 값을 넣고 단추를 누른다 | 클라이언트 렌더링 화면이 식으로 넣은 값을 상태에 반영하지 않을 수 있고, 식의 집합이 인자마다 달라져 「상수 식만」 검사가 무너진다 |
| 사람 속도 간격과 조회 간격 제한 | 권장안이었으나 사용자가 속도를 택했다. 한 요청에 한 번, 자동 재시도 없음은 남겼다 |
| 화면의 역 목록을 읽어 역을 고른다 | 화면 이동이 하나 늘고, 모델이 준 이름으로 비슷한 역을 짐작하게 된다. 플러그인 안의 역 표로 정확히 같을 때만 받는다 |
| 연결 확인이 화면을 열어 로그인을 본다 | 확인 때마다 화면을 움직여 탐지를 부른다. 로그인 전에도 쿠키가 있어 쿠키로는 로그인을 가리지 못하므로 `logged_in` 을 `unknown` 으로 답한다 |

### 결과

- 코레일 화면이 바뀌면 조회가 `KORAIL_PAGE_CHANGED` 로 끝난다. 자리 표의 상당 부분이 확인하지 않은 가설이라, 사용자의 첫 실제 계정 확인에서 고칠 가능성이 높다
- 플러그인 조회가 탐지에 걸리면 조회가 늘 `KORAIL_BOT_CHECK` 로 끝나 이 기능을 쓸 수 없다. 그때는 이 ADR 을 다시 연다
- 코레일 이름은 플러그인과 그 검사·문서에만 있다. `test/unit/connector-neutral.test.ts` 가 Control Plane, 웹, 대시보드 plugin 에 들어오는 것을 막는다
