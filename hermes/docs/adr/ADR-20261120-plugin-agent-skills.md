## ADR-20261120 / plugin-agent-skills: 플러그인의 에이전트용 스킬은 붙이기로 설치하고, 실행기가 필요한 스킬은 운영이 셸 env 를 준 profile 에만 둔다

- **status**: `accepted`
- Date: 2026-11-20
- **decision-type**: `architecture`
- **areas**: `security`, `operations`
- **현재 규칙의 원본**: 스펙 [`docs/features/agent-skill/spec.md`](../../../docs/features/agent-skill/spec.md)(DECISION1~DECISION5, DECISION7, DECISION16, DECISION17), 설계 [`docs/features/agent-skill/design.md`](../../../docs/features/agent-skill/design.md), 계약 [`hermes/connectors/README.md`](../../connectors/README.md) 의 「스킬」

### 결정

- **`assistant.json` 의 `agent_skills` 가 일반 에이전트용 스킬 디렉터리를 선언하고, 그 스킬은 플러그인 스킬과 같이 붙인 에이전트에 붙이기로 설치된다.** 새 버전, 떼기, 처음 붙일 때의 이름 겹침, 한도는 플러그인 스킬과 같다. 붙인 뒤 생긴 이름 겹침은 그 에이전트용 스킬만 빼고 바인딩은 그대로 둔다.
- **실행기를 부르는 스킬은 manifest 가 스킬마다 요구하는 셸 env 이름을 선언하고, 그 에이전트가 터미널을 켰고 셸 설정이 실행 공간이며 그 셸 설정이 이름을 모두 넘길 때만 설치한다.** 아니면 그 스킬만 빼고 붙인다. 조건이 바뀌면 설치 상태 판정이 어긋남으로 보고 정의 어긋남 점검이 자동으로 맞춘다.
- **assistant 는 연결 값이나 실행기를 실행 공간에 넣는 경로를 새로 만들지 않는다.** 실행기와 비밀 파일은 운영이 정책으로 붙인 것을 셸이 env 로 찾는다.

### 맥락

- fos-career 의 공고 추천과 읽을거리 수집은 플러그인의 실행기 번들을 셸에서 부르고, 실행기는 셸 환경의 Backend 주소와 token 파일로 커리어 Backend 를 직접 부른다(fos-agents `career-os/docs/adr/ADR-138`).
- 붙이기는 지금도 플러그인 스킬을 profile `skills/` 에 복사하지만, 그 디렉터리는 실행 공간에 붙지 않고 Hermes 는 본문의 `${CLAUDE_PLUGIN_ROOT}` 를 바꾸지 않는다.
- 운영은 커리어 역할 profile 의 실행 공간에만 플러그인 폴더, 비밀이 아닌 env, token 파일, Backend 망을 준다. 그 셸이 token 을 읽는 위험은 [ADR-086](../../../docs/adr/ADR-086-셸과-파일-도구는-사용자별-docker-실행-공간에서만-돈다.md) 의 「감당할 것」 에서 이미 받아들였다.

### 대안 기각

- **실행기를 스킬 `scripts/` 에 복사한다**: 실행기만으로 스킬 파일 상한을 넘고, 스킬마다 사본이 생긴다. 무엇보다 token 없이는 실행기가 Backend 를 부르지 못해 문제를 풀지 못한다.
- **assistant 가 연결 값을 실행 공간 env 에 넣는다**: 누구의 비서에서나 쓸 수 있다. 그러나 인터넷이 열린 셸에 token 이 들어가 웹 글의 숨은 지시로 새 나갈 수 있고, ADR-086 이 지켜 온 「assistant 는 실행 공간에 비밀을 넘기지 않는다」 를 이 기능 하나로 연다. 사용자마다 Backend 망 연결도 운영이 바꿔야 한다.
- **조건을 붙이기와 다시 설치 때만 본다**: 판정마다 할 일이 적다. 그러나 새 버전이 실행기 스킬을 더해도 사람이 다시 설치하기 전에는 깔리지 않는다.
- **조건을 못 채우면 붙이기를 거절한다**: 셸 없이 MCP 도구로 쓰던 바인딩이 끊긴다.
- **올린 스킬로 넣어 사용자가 고치게 한다**: 새 버전이 사용자 수정을 덮는지, 설명 60자와 개수 한도를 어떻게 할지 새 규칙이 필요하고 플러그인과 스킬 버전이 어긋난다.

### 결과

- 얻는 것: 플러그인 하나를 붙이면 그 플러그인의 비서용 스킬까지 함께 따라온다. 비밀 경계는 ADR-086 그대로다.
- 감당할 것: 실행기 스킬은 운영이 실행 환경을 준 profile(지금은 커리어 역할 profile)의 에이전트에서만 쓴다. 다른 사람의 비서로 넓히려면 운영 정책을 그 profile 에 더해야 하고, 그 셸도 token 을 읽는다. 조건이 바뀌어 다시 맞추는 동안 그 연결은 잠깐 「붙이는 중」 이다. 운영이 정책 env 를 바꾼 뒤에는 도구 저장이나 운영 일괄 반영으로 셸 설정이 바뀌어야 스킬이 깔린다.
