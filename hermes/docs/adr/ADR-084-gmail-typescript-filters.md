## ADR-084: Gmail 커넥터는 TypeScript 묶음 파일로 실행하고 필터 권한을 따로 받는다

- **status**: `accepted`
- **결정**: Gmail MCP 서버를 TypeScript 로 만들고 의존성까지 JavaScript 파일 하나로 묶어 커밋한다. Bun 으로 실행한다. 메일의 `gmail.modify` 에 필터의 `gmail.settings.basic` 을 더하며, 필터와 기존 메일 일괄 적용은 매번 승인받는다.
- **맥락**: 기존 커넥터는 라벨을 만들거나 앞으로 오는 메일을 자동 분류할 수 없었다. 사용자가 라벨과 필터를 함께 요청했고, 앞으로 커넥터를 TypeScript 로 유지하기로 했다. 승인 카드에 보이는 인자와 실행한 값이 같아야 하고 기존 연결 값도 계속 쓸 수 있어야 한다.

### 대체하는 결정

[ADR-066](ADR-066-gmail-커넥터는-직접-만든-mcp-서버와-gmail-modify-scope-하나로-돌고-휴지통은-서버가-막는다.md)의 Python 서버와 단일 scope 결정을 대체한다.
휴지통과 메일 삭제를 서버가 막는 결정, 환경 변수로 자격 증명을 받는 계약, 보내기 승인과 읽은 글을 자료로 다루는 계약은 유지한다.

### 권한과 승인

| 대상 | 결정과 근거 |
| --- | --- |
| 라벨 생성·이름·색 변경 | `gmail.modify` 로 된다. 메일을 숨기거나 밖으로 보내지 않는 쓰기이므로 승인 뒤 상시 허락을 줄 수 있다 |
| 필터 조회·생성·삭제 | `gmail.settings.basic` 이 필요하다. 쓰기는 앞으로 오는 메일을 숨길 수 있어 매번 승인한다. 삭제는 메일 삭제가 아니라 다시 만들 수 있는 설정 변경이다 |
| 기존 메일 적용 | `gmail.modify` 로 된다. 최대 500통이며 검색어와 `expected_count` 를 카드에 보인다. 500통 이내에서 다시 검색한 수가 다르면 변경 전에 거절하고 `actual_count` 를 반환한다. 500통을 넘으면 `GMAIL_INVALID_INPUT` 으로 거절한다 |
| 전달 | `forward` 를 거절하고 `gmail.settings.sharing` 을 받지 않는다. 전달 주소와 계정 밖으로 나가는 설정을 관리하지 않는다 |
| 휴지통·스팸·메일 삭제 | 라벨 이름과 변환한 번호 모두에서 `TRASH`, `SPAM` 을 막고 메일의 휴지통·삭제 endpoint 를 두지 않는다 |

옛 토큰은 확인 도구와 라벨·메일 도구에서 계속 쓴다. 필터 API 의 403만 별도 코드로 구분하고 두 scope 로 토큰을 다시 받도록 안내한다.
필터 API 는 수정이 없으므로 기존 필터를 읽고 승인 뒤 지운 다음, 새 필터도 별도 승인 뒤 만든다.

### 서버와 검사

빌드와 실행에 Bun 을 함께 써 배포 시 변환을 줄인다. 실행 중 의존성을 내려받지 않는다.
빌드는 Bun 1.3.14와 lockfile 을 고정하고 CI 와 로컬 검사에서 소스의 타입, HTTP 대역 시험, 커밋한 묶음 파일과 재빌드 결과 일치를 확인한다. 실행은 검증한 최소 버전 1.3.14 이상을 허용한다. 시작 시 프록시 값이 있으면 그 값을 뺀 환경으로 같은 묶음 파일을 다시 실행해 Bun 의 시작 시 프록시 기억을 피한다. 표준 입출력과 종료 신호는 자식 프로세스로 이어 준다.
Gmail 전용 시험은 커넥터의 `tests/` 에 두며, 여러 커넥터의 계약 시험은 `hermes/tests/` 에 남긴다.
토큰 발급은 사용자 컴퓨터에서 한 번 실행하는 표준 라이브러리 도구이므로 Python 을 유지한다.

### 대안 기각

- **Python 서버 유지**: 사용자가 정한 새 커넥터의 언어와 달라 두 언어의 서버를 유지해야 한다.
- **실행 때 패키지 설치**: 설치 환경과 네트워크 상태에 따라 서버가 뜨지 않고, 검토한 의존성과 실행한 의존성이 달라질 수 있다.
- **더 넓은 scope**: 전달 주소나 영구 삭제를 열 이유가 없다. 필요한 필터 권한만 더한다.
- **수와 관계없이 검색 결과를 바로 적용**: 승인 뒤 새 메일이 늘면 사람이 본 대상 수보다 많은 메일이 바뀐다.

### 결과

Python 서버의 실행 정의를 가진 기존 profile 은 배포 전에 Gmail 커넥터 설치를 제거하고, 배포 뒤 같은 자격 증명으로 다시 설치한다. 새 manifest 는 옛 command·args 와 맞지 않아 옛 소유 기록의 상태 조회·제거·probe 를 거절한다. 자격 증명의 호환성과 설치 정의의 호환성은 별개이며, 옛 토큰을 재사용할 수 있어도 재설치는 필요하다. 운영 반영 순서는 비공개 운영 저장소가 갖는다.

- 얻는 것: 라벨과 새 메일의 자동 분류, 기존 메일 정리를 같은 커넥터에서 수행한다. 실행 파일은 의존성을 포함하며 기존 연결 값과 도구 계약을 유지한다.
- 감당할 것: 필터를 쓰려면 사용자가 권한을 더 받아야 한다. 서버 언어가 바뀌므로 운영 실행 파일 목록도 바꾸고 배포 뒤 기존 연결의 `get_profile` 을 왕복 확인해야 한다. 수가 같아도 조회와 적용 사이에 대상이 바뀌는 것은 API 가 원자적으로 막지 못한다.

도구와 설정 절차는 [Gmail 커넥터](../../connectors/gmail/README.md)가 갖는다.
권한의 근거는 [필터 생성](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.settings.filters/create), 일괄 변경의 근거는 [batchModify](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/batchModify)다.
