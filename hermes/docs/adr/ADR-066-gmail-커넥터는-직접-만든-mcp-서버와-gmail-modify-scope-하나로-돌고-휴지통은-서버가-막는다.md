## ADR-066: Gmail 커넥터는 직접 만든 MCP 서버와 `gmail.modify` scope 하나로 돌고 휴지통은 서버가 막는다

- **status**: `accepted`
- Date: 2026-10-02
- [ADR-064](ADR-064-범용-커넥터는-이-저장소의-hermes-connectors-에-두고-저장소가-유지보수한다.md) 의 첫 커넥터다. 도구 목록과 설정 방법은 [Gmail 커넥터](../../connectors/gmail/README.md) 가 갖는다.

### 결정

**대체된 부분**: Python 서버와 단일 scope 는 [ADR-084](ADR-084-gmail-typescript-filters.md)로 대체했다.
TypeScript 묶음 파일과 필터 권한을 쓰며, 휴지통·메일 삭제 차단과 기존 연결·승인 계약은 유지한다.
아래 표의 서버와 scope 행은 초기 결정의 기록이다.

| 항목 | 정한 것 |
| --- | --- |
| 인증 | 사용자가 자기 Google Cloud 프로젝트에서 만든 OAuth client 의 id, secret 과 자기 계정의 refresh token 을 연결 화면에 붙여 넣는다. Control Plane 과 웹에는 OAuth 로그인 흐름이 없다 |
| 비밀값이 있는 곳 | 다른 커넥터와 같이 그 사용자의 연결용 profile 에만 있다. access token 은 MCP 서버 프로세스의 메모리에만 둔다 |
| MCP 서버 | 이 저장소가 Python `mcp` SDK 와 표준 라이브러리로 만든다. HTTP 는 `urllib` 로 부른다 |
| scope | `https://www.googleapis.com/auth/gmail.modify` 하나 |
| 승인 없이 되는 것 | 계정 확인, 검색, 메일 읽기, 스레드 읽기, 라벨 목록 |
| 승인 뒤에만 되는 것 | 초안 만들기, 보내기, 답장 보내기, 라벨 바꾸기(보관 포함) |
| 매번 승인받는 것 | 보내기와 답장 보내기. 상시 허락을 닫는다([ADR-065](../../../docs/adr/ADR-065-외부로-나가는-도구는-상시-허락을-닫는-선언을-둔다.md)) |
| 닫는 것 | 휴지통과 영구 삭제. 도구를 만들지 않고, 라벨 바꾸기에서 `TRASH` 와 `SPAM` 을 거절한다 |
| 첨부 | 이름, 종류, 크기만 보인다. 내려받는 도구는 두지 않는다 |
| 검사 | 실제 Gmail 에 닿지 않는다. Gmail API 를 흉내 내는 로컬 HTTP 대역으로 돈다 |

### 맥락

**scope 로는 휴지통을 닫지 못한다.**
보관은 메일에서 `INBOX` 라벨을 떼는 것이고 그 호출(`messages.modify`)은 `gmail.modify` 를 요구한다.
`gmail.modify` 는 읽기, 초안, 보내기, 라벨 변경과 함께 휴지통으로 옮기기를 허용한다.
영구 삭제만 더 넓은 scope(`https://mail.google.com/`)를 요구하므로, 그 scope 를 받지 않는 것으로 영구 삭제는 닫힌다.
그래서 휴지통은 서버 코드가 막는다. 휴지통 endpoint 를 부르는 코드를 두지 않고, 라벨 바꾸기 도구가 더하거나 뗄 라벨에 `TRASH` 나 `SPAM` 이 있으면 Gmail 을 부르지 않고 거절한다.
검사가 그 거절과, 서버 코드에 휴지통과 삭제 endpoint 의 경로가 없다는 것을 본다.

**이미 있는 Gmail MCP 서버를 2026-10-02 에 살폈다.**

| 살핀 것 | 맞지 않는 점 |
| --- | --- |
| refresh token 을 env 로 받는 서버 | 하나뿐이었다. 삭제, 휴지통, 전달 주소 설정 도구가 함께 열려 있고 열 달 넘게 고친 이력이 없다 |
| 가장 활발히 유지되는 서버 | 브라우저 로그인과 토큰 파일을 전제로 한다. 보내기와 답장과 전달이 도구 하나라 도구 이름으로 정책을 나누지 못한다. 라벨 도구로 휴지통에 보낼 수 있다 |
| Google 의 원격 MCP 서버 | 미리 보기 단계이고 stdio 가 아니며 보내기가 없다. MCP 클라이언트가 OAuth 를 해야 한다 |

커넥터의 실행 파일은 운영자가 정하고 서버의 인자는 plugin 디렉터리 안의 파일만 받는다([`docs/connectors.md`](../../../docs/connectors.md)).
실행할 때 패키지를 내려받는 방식은 이 구조에 맞지 않는다.
필요한 호출은 Gmail REST 여덟 가지와 토큰 갱신 하나다.

**Google 은 앱의 게시 상태로 refresh token 의 수명을 정한다.**
게시 상태가 「테스트」 인 외부 앱의 refresh token 은 7일 뒤 만료된다. Gmail scope 는 예외가 아니다.
「프로덕션」 으로 게시하면 이 만료가 없다. 본인과 아는 사람 소수가 쓰는 앱은 검수를 받지 않아도 되고, 동의 화면에 미검수 경고가 한 번 뜬다.

### 대안 기각

- **앱이 OAuth 로그인 흐름을 갖는다**: Control Plane 이 client secret 과 redirect 주소를 가져야 하고, 비밀값을 갖지 않는다는 지금 구조가 바뀐다. 받아 띄운 사람마다 주소가 달라 Google 쪽 등록도 각자 해야 한다.
- **`gmail.readonly` 와 `gmail.compose` 만 받는다**: 휴지통이 scope 로 닫히지만 보관과 읽음 처리를 못 한다.
- **초안 만들기를 승인 없이 연다**: 초안도 계정의 상태를 바꾸는 쓰기이고 `WRITE` 의 승인 하한은 `required` 다. 읽기로 선언하면 위험도의 뜻이 흐려지고 다른 커넥터가 그대로 따라 한다. 초안은 밖으로 나가지 않으므로 사용자가 상시 허락으로 줄일 수 있다.
- **초안을 번호로 보내는 도구를 둔다**: 승인 카드에 받는 사람과 본문이 아니라 초안 번호만 보인다. 사람이 무엇을 승인하는지 읽을 수 없다.
- **첨부를 내려받는 도구를 둔다**: 연결용 에이전트에는 파일을 둘 곳이 없다. 본문을 글로 바꿔 모델에 넣으면 입력만 커진다.

### 결과

- 얻는 것: 사용자가 자기 계정의 메일을 찾고 읽고, 사람이 확인한 답장을 보낸다. 앱은 Google 의 비밀을 갖지 않는다. 도구 이름과 인자를 우리가 정하므로 정책 선언이 판이 오를 때 어긋나지 않는다.
- 감당할 것:
  - **휴지통을 막는 것은 서버 코드와 그 검사뿐이다.** refresh token 을 가진 사람은 Gmail API 를 직접 불러 휴지통에 보낼 수 있다. 토큰은 연결용 profile 밖으로 나가지 않아야 한다.
  - 사용자가 Google Cloud 프로젝트를 만들고 토큰을 손으로 받아야 한다. 처음 한 번의 설정이 길다.
  - 「테스트」 상태에 둔 사용자는 7일마다 토큰을 다시 받는다. 설정 안내가 게시를 권한다.
  - 비밀번호를 바꾸거나 접근을 철회하거나 6개월 동안 쓰지 않으면 refresh token 이 죽는다. 그 뒤의 도구 호출과 연결 확인은 자격 증명 거절로 끝나고, 사용자가 토큰을 다시 받아 등록한다.
  - 메일 본문은 모델 입력으로 들어간다. 그 글이 모델을 속여도 닿는 범위는 이 커넥터의 도구와 그 대화의 답이다([ADR-045](../../../backend/docs/adr/ADR-045-커넥터-에이전트는-자기-mcp-서버만-받고-memory-와-control-plane-도구를-받지-않는다.md)). 감싼 글을 모델이 지시로 읽지 않는다는 보장은 없다.
  - 실제 계정으로 도는지는 검사가 보지 못한다. 소유자가 [Gmail 커넥터](../../connectors/gmail/README.md) 의 「실제 계정으로 확인하기」 를 손으로 돌린다.
