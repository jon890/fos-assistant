## ADR-087: 같은 도구의 승인 줄은 묶음으로 보이고 상시 허락을 줄 수 있는 줄만 한꺼번에 승인한다

- **status**: `accepted`
- Date: 2026-10-06
- [ADR-050](../../../backend/docs/adr/ADR-050-커넥터-쓰기는-control-plane-이-승인-줄을-저장하고-승인한-인자로-한-번만-실행한다.md) 의 승인 카드에 화면 쪽 조건을 더한다. 서버의 승인 계약은 바꾸지 않는다.

### 결정

**같은 커넥터의 같은 도구(`toolName`)로 기다리는 승인 줄은 승인 영역에서 한 묶음으로 보인다. 펼친 묶음의 모든 건이 아래 조건을 채우면 「N건 모두 승인」 을 둔다.**

| 항목 | 정한 것 |
| --- | --- |
| 넣는 줄 | `PENDING` 이고, 위험도가 `WRITE` 이고, `grantAllowed` 가 참이고, `hiddenArgs` 가 거짓인 줄 |
| 빼는 줄 | 상시 허락을 닫은 도구(`grant: false`), `DESTRUCTIVE` 와 `FINANCIAL`, 위험도를 모르는 줄, 가려진 인자가 있는 줄. 하나라도 섞인 묶음에는 단추가 없다 |
| 보이는 때 | 묶음을 펼친 뒤에만 보인다. 펼치면 건마다 위에 보이는 인자와 「자세히」 가 보인다. 이 줄들은 상시 허락을 줄 수 있는 줄이라 한 장의 카드와 같이 나머지 인자를 「자세히」 에 접는다 |
| 보내는 방법 | 건마다 승인 요청을 차례로 보낸다. 기간(`grant`)은 싣지 않는다 |
| 멈추는 때 | 요청이 실패하면 멈추고 목록을 다시 읽는다. 요청은 성공했지만 결과가 `SUCCEEDED` 나 `EXECUTING` 이 아니면(`FAILED`, `UNKNOWN`, `REJECTED`, `EXPIRED`) 거기서 멈춘다. 어느 쪽이든 승인 영역에 오류를 남긴다 |
| 보내는 동안 | 그 묶음의 줄은 단추가 막힌다. 앞 건이 끝나 묶음이 한 장으로 바뀌어도 막힌 채다. 묶음의 한 건을 따로 보내는 동안에는 「모두 승인」 이 막힌다 |
| 묶지 않는 줄 | 도구 이름이 없는 줄(`schema: 1` 커넥터의 선언 없는 도구)은 묶지 않는다. 이런 줄은 `grantAllowed` 도 거짓이다 |
| 서버 | 바꾸지 않는다. 한꺼번에 승인하는 API 를 두지 않는다 |

판정은 `web/src/lib/connector-action.ts` 의 `bulkApprovable` 이 갖는다.

### 맥락

에이전트가 같은 도구를 여러 번 부르면 승인 줄이 그 수만큼 생긴다.
라벨 넷을 만들라고 하면 카드 넷이 쌓이고, 사용자는 같은 모양의 카드를 네 번 읽고 네 번 누른다.

`grantAllowed` 가 참인 도구는 이미 「승인하고 묻지 않기」 로 30일까지 묻지 않게 할 수 있다.
그 도구의 펼친 줄을 한 번에 승인하는 것은, 사람이 보지 않은 앞으로의 호출까지 허락하는 상시 허락보다 범위가 좁다.
그래서 이 도구들에서는 승인의 뜻이 약해지지 않는다.

상시 허락을 닫은 도구는 호출마다 사람이 원문을 다 읽게 하려고 닫았다([ADR-065](../../../docs/adr/ADR-065-외부로-나가는-도구는-상시-허락을-닫는-선언을-둔다.md)).
한꺼번에 승인하면 그 뜻이 무너지므로 넣지 않는다.

### 대안 기각

- **모든 묶음에 「모두 승인」 을 둔다**: 메일 보내기처럼 상시 허락을 닫은 도구도 한 번에 나간다. ADR-065 가 막은 길이다.
- **서버에 한꺼번에 승인하는 API 를 둔다**: 승인은 줄마다 잠그고 실행한다. 여러 줄을 한 요청으로 받으면 일부만 실행된 결과를 따로 정의해야 한다. 화면이 차례로 보내면 지금 계약 그대로다.
- **접힌 묶음에서도 「모두 승인」 을 둔다**: 무엇을 승인하는지 건마다 보지 않고 누를 수 있다.
- **묶지 않고 카드 높이만 줄인다**: 같은 도구의 카드가 여럿이면 제목과 단추가 되풀이되어 여전히 자리를 차지한다.

### 결과

- 얻는 것: 같은 도구의 요청이 여럿이어도 승인 영역이 한 묶음 크기로 남고, 상시 허락을 줄 수 있는 도구는 한 번에 처리한다.
- 감당할 것:
  - 「모두 승인」 은 요청을 하나씩 보내므로 건수만큼 시간이 걸린다. 그동안 묶음의 단추는 막힌다.
  - 중간에 실패하면 앞의 건은 이미 승인된 채로 남는다. 목록을 다시 읽어 남은 건을 보인다.
  - 실행했는지 모르는 결과(`UNKNOWN`) 뒤에 같은 동작을 이어 보내지 않는다. 사람이 그 서비스에서 확인한 뒤 남은 건을 승인한다.
