## ADR-074: 지금 화면은 원래 기록을 읽어 만든 view 이고 정해진 카드 다섯만 그린다

- **status**: `accepted`
- **결정**: #161 의 Living View 를 **지금 화면**이라 부른다. 주소는 `/now` 이고 사이드바 최상단 「새 대화」 단추 바로 아래의 「지금 볼 것」 링크로 들어간다.
  홈 `/` 은 새 대화 화면 그대로 두고, 「확인할 것 N건」 한 줄만 더한다. 그 한 줄은 홈을 그린 뒤에 채운다.

  1. **지금 화면은 view 다.** 원래 기록(실행, 승인, Memory 제안, 할 일, 결과 전달 상태)을 읽어 요청마다 만든다. 화면 상태를 따로 저장하지 않고, 화면에 보인 것이 원래 기록을 대신하지 않는다.
  2. **카드는 다섯으로 정해져 있다.** 카드의 순서와 보이는 여부와 안의 항목만 바뀐다. 모델이 화면 구성이나 카드 문구를 만들지 않는다.

     | 열쇠 | 화면 이름 | 담는 것 |
     | --- | --- | --- |
     | `failures` | 실패 | 실패한 대화 turn 과 결과 전달 실패 |
     | `needs_me` | 내 차례 | 승인 대기, 받아들이기를 기다리는 Memory 제안과 할 일 제안, 열린 할 일 |
     | `delegated` | 맡긴 일 | 도는 중이거나 최근 끝난 위임 실행 |
     | `continue` | 이어서 하기 | 최근 대화 |
     | `reports` | 보고 | 먼저 살펴보기의 다섯 칸 보고. 늘 `LATER` 이고 건수에 세지 않는다 |

  3. **카드 순서는 규칙 하나로 정한다.** `NOW` 항목이 있는 카드가 먼저이고, 같은 무리 안에서는 위 표의 순서다. 카드 안에서는 `NOW` 항목이 먼저이고 그다음 시각이 최근인 것이다.
  4. **항목마다 이유와 출처를 보인다.** 이유는 판정의 「왜」 칸을 정해진 문구로 그린 것이고, 출처는 그 기록의 대화, 에이전트, 시각이다.
  5. **사용자 제어는 숨기기와 미루기다.** 숨기기는 그 항목에 새 변화가 올 때까지, 미루기는 내일 아침이나 일주일 뒤까지다. 제어는 원래 기록을 바꾸지 않고 `attention_control` 에 남는다. 고정은 뒤로 미룬다.
  6. **실패와 결과 전달 실패 카드는 #162 의 상태를 읽기만 한다.** 전달 상태를 저장하거나 고치는 책임을 화면에 두지 않는다.
  7. **기존 부품으로 그린다.** `web/src/components/ui/` 의 카드, 배지, 빈 상태, 안내 상자와 실행 상태 문구를 쓴다.
- **맥락**: #161 은 고정 위젯 대신 지금의 목표와 실행 상태에 따라 우선순위가 바뀌는 화면을 실험하자고 했다.
  지금 홈 `/` 은 새 대화 화면뿐이고 서버에서 읽는 데이터가 없어 바로 뜬다([`frontend/structure.md`](../../../docs/frontend/structure.md)).
  2026-10-04 에 사용자가 네 가지를 정했다.
  - 별도 화면으로 두고 홈에는 한 줄만 둔다. 그 한 줄도 홈의 첫 표시를 기다리게 하지 않는다
  - 카드는 넷이다. 오늘과 다음은 일정 커넥터가 생긴 뒤, 비용 이상은 관리자 영역 안에서, 중요 맥락은 문맥 묶음이 생긴 뒤로 미룬다
  - 제어는 숨기기와 미루기다
  - 알림은 화면 안에서만 보인다
  2026-10-05 에 [ADR-085](../../../docs/adr/ADR-085-매일-깨우기는-예약-작업을-다시-쓰고-다섯-칸-보고를-지금-화면에-올린다.md)의 보고 카드를 다섯째로 더했다.
- **대안 기각**:
  - **홈을 지금 화면으로 바꾸거나 홈 아래에 카드를 둔다.** 홈이 서버 조회를 기다리게 되어 대화를 시작하는 첫 반응이 늦어진다. 실험이 실패하면 되돌리는 범위도 크다.
  - **모델이 화면 구성을 만든다.** 같은 기록에 다른 화면이 나와 「왜 이 카드가 있는가」 를 설명하지 못한다. 만든 화면이 원래 기록처럼 읽힐 위험이 있다.
  - **사용자가 위젯을 골라 배치한다.** #161 이 피하려던 고정 대시보드다. 배치를 저장하는 상태도 생긴다.
  - **비용 이상 카드를 관리자에게만 보인다.** 관리자 전용 표시를 일반 화면에 섞지 않는다(ADR-063).
- **결과**:
  - 얻는 것:
    - 원래 기록이 바뀌면 다음에 열 때 화면이 따라 바뀐다. 화면과 기록이 어긋날 저장 상태가 없다.
    - 홈의 첫 반응 시간이 지금과 같다.
    - 지금 화면을 지워도 원래 기록과 다른 화면이 그대로다.
  - 감당할 것:
    - 화면을 열 때마다 여러 기록을 읽는다. 항목 수와 기간에 상한을 둔다([`backend/attention.md`](../../../docs/backend/attention.md)).
    - 카드를 더하려면 코드와 이 결정을 고쳐야 한다. 오늘과 다음, 비용 이상, 중요 맥락이 그 후보다.
    - 고정이 없어 사용자가 원하는 항목을 늘 위에 두지 못한다.
- **적용 범위**: 화면의 배치와 폭별 동작, 문구는 [`frontend/now.md`](../../../docs/frontend/now.md), 응답과 판정은 [`backend/attention.md`](../../../docs/backend/attention.md) 가 갖는다.
