## ADR-20261112 / handoff-drawer: 화면 넘기기 카드는 새 창 대신 대화 위 옆 패널에 「내 브라우저」 를 띄운다

- **status**: `accepted`
- Date: 2026-11-12
- **decision-type**: `architecture`
- **현재 규칙의 원본**: 설계 [`docs/features/user-browser/design.md`](../../../docs/features/user-browser/design.md) 의 「인터페이스와 데이터」, 스펙 [`spec.md`](../../../docs/features/user-browser/spec.md) 의 REQ1~REQ6(사용자 확인 2026-11-12), 기능 파일 [`docs/features/user-browser.md`](../../../docs/features/user-browser.md) 의 「대화 위 화면」
- **결정**: 화면 넘기기 카드의 「내 브라우저 열기」 는 대화 화면의 옆 패널(작업 과정·결과물과 같은 자리, 1024px 보다 좁으면 전체 폭 시트)에 그 탭의 `BrowserScreen` 을 띄운다. 보고 있는 대화에 새 카드가 생기거나 넘기기 알림으로 들어오면 패널이 저절로 열리고, 패널 안의 「다 했어요」 가 패널을 닫고 정해 둔 글을 보낸다. 넘긴 탭의 주소가 바뀌면 끝났는지 묻기만 하고 보내지 않는다.
- **대체하는 것**: [ADR-20261111 / connector-handoff](../../../docs/adr/ADR-20261111-connector-handoff.md) 의 「카드」 행 가운데 「「내 브라우저 열기」 는 그 탭을 고른 채 새 창을 열고」 를 대체한다. 새 창은 패널 머리의 「새 창으로 열기」 로 남는다. 넘기기의 나머지 계약은 그 ADR 그대로다.
- **맥락**: 새 창으로 넘어가 풀고 돌아와 「다 했어요」 를 찾는 사이에 사용자가 할 일을 놓치고, 휴대폰에서는 창을 오가기 어렵다(사용자 2026-11-12). 넘기기의 서버 계약(결과 모양, 판정 줄, 사람이 보낸 turn 이 닫기)은 바꿀 것이 없고 사람이 돕는 자리만 바꾸면 된다.
- **대안 기각**:
  - 화면 가운데의 모달: 대화와 답을 가려 모델이 쓴 사정을 읽으며 풀 수 없다. 이미 쓰는 옆 패널과 모양이 달라진다
  - 패널 전용 화면 부품: 입력 변환, 확인 창, 다시 열기를 두 벌로 갖게 된다. `BrowserScreen` 에 선택 속성 `onTabs` 와 `onReopen` 둘만 더한다
  - 주소가 바뀌면 바로 보내기: 2단계 인증처럼 중간에 주소가 바뀌면 잘못 이어 가 다시 막힌다(스펙 DECISION2)
  - 알림 응답에 넘기기 번호를 더한다: Control Plane 을 바꿔야 하고, 「다 했어요」 한 번이 열린 넘기기를 모두 닫아 어느 것을 열어도 결과가 같다
- **결과**:
  - 얻는 것: 사람이 대화를 떠나지 않고 풀며, 새 카드와 알림에서 할 일이 바로 보인다. Control Plane, fos-ctx, 플러그인은 그대로다
  - 감당할 것: 같은 대화를 여러 창에서 보면 창마다 패널이 열려 마지막에 연 창이 화면을 가진다. 밀린 창은 지금의 「다른 창에서 화면을 열었어요」 를 보인다. 주소 변화로 끝을 아는 것은 짐작이라, 주소가 그대로인 보안 확인은 「다 했어요」 를 직접 눌러야 한다
- **확인 방법**: `web/test/browser/handoff-card.spec.ts`, `web/test/unit/handoff.test.ts`, `web/test/unit/notification.test.ts`
