## ADR-051: 화면 색은 새벽 보라로 바꾸고 강조 색은 누를 것과 고른 것과 초점에만 쓴다

- **status**: `accepted`
- **결정**: 화면의 색 값을 테라코타와 회색에서 「새벽 보라」 팔레트로 바꾼다.
  강조 색(보라)은 주 단추, 지금 고른 것, 초점 테두리 세 곳에만 쓴다.
  상태는 의미 색(성공, 경고, 오류, 정보)이 맡고, 비서가 일하는 중이라는 신호는 라임 점 하나가 맡는다.
  움직임은 길이 셋과 곡선 둘을 토큰으로 두고, 모든 움직임이 `prefers-reduced-motion` 을 한곳의 규칙으로 따른다.
  모션 라이브러리는 더하지 않는다.
- **맥락**:
  - 이 화면은 가족이 쓰는 개인형 비서다. 대화가 중심이고 관리 도구처럼 보이지 않아야 한다.
    2026-10-01 화면 감사에서 테라코타와 회색 무채색 위계가 편집물 같은 인상을 주고, 이 정체성과 거리가 있다고 판단했다.
  - 강조 색 하나가 주 단추, 선택, 초점, 링크, 숫자, 비서 얼굴, 진행 점, 내 말풍선을 모두 맡았다.
    그래서 무엇이 누를 수 있는 것인지 색으로 구분되지 않았다.
  - 의미 색이 `destructive` 하나뿐이었다. 실패 배지가 검은 테두리, 오류 상자가 회색, 성공이 회색이었다.
  - 대비가 모자란 곳이 둘 있었다. 밝음에서 `muted` 위 `muted-foreground` 가 4.47:1, 입력칸 테두리가 바탕 위 1.26:1 이었다.
  - 표면이 `background` 와 `muted` 둘뿐이고 `card` 와 `popover` 가 바탕과 같은 값이라, 층을 테두리 선으로만 나눴다.
  - 화면 전환, 메시지 등장, 펼침에 움직임이 없었고, `tw-animate-css` 의 대화상자와 시트 움직임은 줄인 움직임 설정을 따르지 않았다.
- **대안 기각**:
  - **테라코타를 유지하고 의미 색만 더한다.** 강조 색이 여러 일을 맡는 문제와 탁한 어두움 테마가 그대로 남는다.
  - **맑은 하늘(파랑).** 무난하지만 흔하고, 정보 색과 겹친다.
  - **밝은 산호.** 친근하지만 오류 색과 가까워 오류를 진홍으로 옮겨야 하고, 흰 글자 대비가 모자라 단추 글자를 짙은 갈색으로 둬야 한다.
  - **먹색 단추에 노랑 신호.** 노랑은 흰 바탕 위 대비가 낮아 초점 테두리에 쓸 수 없다. 인상이 차갑다.
  - **`motion` 패키지를 더한다.** 이번에 필요한 움직임(등장, crossfade, 높이 펼침, 시트와 대화상자)은 CSS 로 된다.
    그 패키지가 필요한 것은 목록 재배치뿐이고 지금 그런 화면이 없다. 필요해지면 그때 다시 정한다.
  - **토큰을 `oklch()` 로 적는다.** 브라우저 검사의 대비 계산이 hex 와 `rgb()` 를 읽는다. 값의 이점이 없어 hex 로 둔다.
- **결과**:
  - 얻는 것:
    - 보라가 보이면 누를 수 있거나 지금 고른 것이다. 링크와 숫자는 글자색으로 돌아간다
    - 성공, 경고, 오류, 정보가 색과 아이콘으로 구분된다
    - `card` 와 `popover` 가 바탕과 다른 값이라 선 없이 층이 생긴다
    - 움직임의 길이와 곡선을 한곳에서 바꾼다. 줄인 움직임 설정을 부품마다 챙기지 않는다
  - 감당할 것:
    - 보라를 새 자리에 쓰려면 아래 「강조 색을 쓰는 곳」 에 들어가는지 먼저 본다. 들어가지 않으면 쓰지 않는다
    - 의미 색 글자는 그 색의 `-soft` 바탕이나 `background`, `card` 위에서만 대비 4.5:1 을 넘는다. `muted` 위에 쓰기 전에 대비를 확인한다
    - 라임 점은 글자색으로 쓰지 않는다. 밝은 바탕 위 대비가 낮다. 점은 `pill` 바탕 위나 테두리를 두른 채로 쓴다
    - 화면 전환의 View Transitions 는 Next 의 실험 기능이다. 설정 하나로 끌 수 있게 두고, 꺼도 화면이 그대로 동작해야 한다
    - 색을 값으로 박아 둔 검사를 두지 않는다. 검사는 토큰과 비교한다
- **적용 범위**: [ADR-023](ADR-023-화면-부품은-shadcn-ui-를-저장소에-복사해-쓴다.md) 의 「값은 바꾸지 않는다」 를 대체한다.
  부품을 shadcn/ui 에서 복사해 쓰는 것, 토큰 이름 체계, 폼 원소를 네이티브로 두는 것은 그대로다.

### 강조 색을 쓰는 곳

| 쓰는 곳 | 토큰 |
| --- | --- |
| 주 단추. 한 화면에서 지금 누를 단추 하나 | `primary` 바탕 |
| 지금 고른 것. 고른 대화, 고른 답 방식, 고른 카드 | `primary-soft` 바탕에 `primary-soft-foreground` 글자 |
| 켜진 스위치의 길. 켜 둔 것도 지금 고른 것이다 | `primary` 바탕 |
| 초점 테두리 | `ring` |

| 쓰지 않는 곳 | 대신 쓰는 것 |
| --- | --- |
| 링크 | 글자색에 밑줄 |
| 금액과 숫자 | 글자색 |
| 비서 얼굴 | `muted` 바탕에 글자색 |
| 성공과 오류 | 의미 색 |
| 진행 표시 | `signal` 점, 글자색 회전 표시 |
| 비활성 단추 | `muted` 바탕에 `muted-foreground` 글자. 강조 색을 투명하게 바래게 하지 않는다 |

### 의미 색

상태를 나타내는 배지와 알림 상자는 `-soft` 바탕에 그 색 글자와 아이콘을 함께 쓴다.
색만으로 뜻을 전하지 않는다.

| 뜻 | 예 |
| --- | --- |
| 성공 | 저장했어요, 실행 성공, 「켜짐」 배지 |
| 경고 | 한도에 가까워요, 문맥이 빠졌어요 |
| 오류 | 답을 받지 못했어요, 실행 실패 |
| 정보 | 안내, 새로 생긴 것 |

### 모서리

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `radius-sm` | 0.25rem | 코드 조각 |
| `radius-md` | 0.75rem | 단추, 입력칸, 알림 상자 |
| `radius-lg` | 1rem | 카드, 작업 과정 상자, 대화상자 |
| `radius-xl` | 1.25rem | 말풍선 |
| `radius-2xl` | 1.5rem | 대화 입력창 |
| `radius-full` | 9999px | 알약, 원형 단추 |

이 여섯 밖의 모서리 값을 쓰지 않는다.

| 토큰 | 값 |
| --- | --- |
| `duration-fast` | 120ms |
| `duration-base` | 200ms |
| `duration-slow` | 260ms |
| `ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` |
| `ease-spring` | `cubic-bezier(0.34, 1.36, 0.64, 1)` |

| 곳 | 움직임 |
| --- | --- |
| 내 말풍선 등장 | 200ms, 오른쪽 아래에서 0.96배가 1배로, 6px 오름, `ease-spring` |
| 비서 답 등장 | 200ms, 4px 오름과 흐려짐, `ease-out` |
| 기다림에서 답으로 | 같은 자리에서 내용만 바뀐다. 높이가 튀지 않는다 |
| 작업 과정 펼치기 | 260ms, `grid-template-rows` 0fr 에서 1fr, `ease-out`. 화살표 회전 200ms |
| 화면 전환 | 들어오는 화면 200ms, 8px 오름과 흐려짐. 나가는 화면 120ms, linear. 대화 화면끼리 오갈 때와 새 대화가 대화 주소로 바뀔 때는 움직이지 않는다 |
| 시트와 서랍 | 260ms, 전체 폭을 밀어 넣는다 |
| 대화상자 | 200ms, 흐려짐과 0.96배 |
| 메뉴와 툴팁 | 120ms, 흐려짐과 0.95배. 누른 자리 바로 옆에 뜨는 작은 표면이라 짧게 둔다 |
| 목록 추가와 삭제 | 추가는 200ms 등장, 삭제는 120ms 흐려짐 뒤 제거 |
| 누름 | 120ms, 0.97배 |

화면 전환은 Next 의 실험 기능 View Transitions 를 쓰고 기본값은 켬이다. 끄려면 이미지를 빌드할 때 `NEXT_PUBLIC_VIEW_TRANSITION=off` 를 build arg 로 준다. 끈 빌드에서는 들어오는 화면만 CSS 로 움직인다.

**줄인 움직임 설정에서는 이동과 크기 변화를 하지 않는다.** 100ms 흐려짐만 남기고, 높이는 바로 바뀐다.
`globals.css` 의 `@media (prefers-reduced-motion: reduce)` 블록 하나가 이것을 정한다.
`tw-animate-css` 의 움직임도 그 블록을 따른다. 부품마다 `motion-reduce:` 를 적지 않는다.
끝없이 도는 회전 표시와 뼈대의 깜빡임만 부품이 `motion-reduce:animate-none` 으로 끈다.
끝없이 도는 표시를 문장으로 바꿔 보일 때는 `motion-reduce:hidden` 과 `motion-reduce:flex`, `motion-reduce:inline` 을 쓴다. 기다림 점이 그 예다.

**대화 화면은 화면 전환의 대상이 아니다.** 흐르던 답과 입력창이 다시 만들어지면 안 되기 때문이다.
