# web 화면의 구조

화면 목록과 화면 틀, 부품을 두는 자리, 화면 전체에 걸리는 규칙을 갖는다.
화면이 보이는 것과 화면 전환, 부르는 순서는 [`docs/features/`](../../docs/features/) 의 기능 파일이 갖는다.

## 화면 목록

아래가 화면이고, 나머지는 이 화면들을 이루는 부품이다.

| 경로 | 화면 |
| --- | --- |
| `/` | 새 대화 화면 |
| `/settings` | 「설정」. 묶음 목록과, 넓은 화면에서 처음 골라진 「에이전트」 화면. 아래 「설정 틀」 |
| `/settings/notifications` | 설정의 「알림」. 이 기기에서 웹 푸시를 받을지와 내 기기 목록([`docs/features/attention.md`](../../docs/features/attention.md) 의 「웹 푸시」) |
| `/n/{id}` | 푸시를 누르면 여는 주소. 알림을 읽음으로 바꾸고 그 알림이 가리키는 곳으로 넘긴다. 화면을 그리지 않는다 |
| `/now` | 지금 화면. 실패, 내 차례, 맡긴 일, 이어서 하기, 보고 카드([`docs/features/attention.md`](../../docs/features/attention.md)) |
| `/chat/{id}` | 대화 하나. `{id}` 는 대화의 공개 식별자 |
| `/c/{번호}` | 옛 주소. 주인이면 `/chat/{id}` 로, 없거나 남의 대화면 `/` 로 넘긴다. 그 밖의 실패는 오류 화면이다 |
| `/signin` | 로그인 |
| `/privacy` | 데이터 보관 안내. 로그인 없이 열리며 로그인 화면에서 안내 링크로 간다. [`docs/privacy.md`](../../docs/privacy.md)의 대화 보관·암호화 한계·모델 제공사 전달·삭제와 연결 해제 안내를 다섯 절로 요약한다. 공개 화면 틀을 쓰며 로그인 없는 렌더는 Control Plane을 부르지 않는다. 로그인한 사용자가 열면 설정 틀 안에 보이고 로그인 안내와 「로그인 화면으로」 를 그리지 않는다 |
| `/memory` | 에이전트가 남긴 기억의 검토와 고치기, 개인 문서. 구성은 [`docs/features/memory.md`](../../docs/features/memory.md) |
| `/new` | 새 대화. `?agent=<code>` 로 처음 고를 에이전트를 받는다 |
| `/executions/{id}` | 실행 하나의 도구와 하위 에이전트 실행 트리 |
| `/agents` | 내가 쓸 수 있는 에이전트 목록과 「새 에이전트」. `?new=1` 이면 「새 에이전트」 창이 열린 채로 보이고, 뒤로 가기나 새로 고침에 다시 열리지 않게 주소에서 `new=1` 을 지운다 |
| `/agents/{code}` | 에이전트 하나의 설정. 성격, 도구, 스킬, 먼저 살펴보기와 매일 깨우기. 주인과 `ADMIN` 에게 공개와 삭제 |
| `/agents/{code}/skills/new` | 새 스킬. 주인과 `ADMIN` |
| `/agents/{code}/skills/{name}` | 올린 스킬 편집. 주인과 `ADMIN` |
| `/connections` | 「외부 서비스 연결」. 플러그인 카드 목록. [`docs/features/connector.md`](../../docs/features/connector.md) 의 「연결 뒤 에이전트 고르기」 를 따른다. 카드마다 아이콘, 이름, 연결 상태, 설명, 링크, 도구 수와 위험도별 수, 붙인 에이전트 수를 보인다([ADR-20261008 / connector-card](../../docs/adr/ADR-20261008-connector-card.md)) |
| `/connections/{id}` | 플러그인 하나의 외부 서비스 연결 화면. 머리에 아이콘, 이름, 설명, 링크를 보이고, 계정을 연결하고, 이 연결을 붙인 에이전트를 보인다 |
| `/connections/accountbook` | 옛 주소. `/connections/{id}` 로 넘긴다 |
| `/browser` | 내 브라우저. 만들기, 켜기, 끄기, 지우기와 자동 중지 안내, 켜져 있거나 꺼져 있을 때 로그인 화면(「화면 열기」). `?url=` 은 화면을 열 때 갈 시작 주소이고 `http`, `https` 가 아니면 무시한다. 설정의 「연결」 묶음과 `/connections` 위쪽의 「내 브라우저」 링크로 간다([`docs/features/user-browser.md`](../../docs/features/user-browser.md)) |
| `/files` | 파일 공간. 「내 파일」 목록을 먼저 보이고 「에이전트 작업 폴더」 는 링크로 들어간다. 옛 실행 공간 주소(`?path=`, `?file=`)는 `/files/workspace` 의 같은 자리로 넘긴다. 설정의 「내 데이터」 묶음에서 간다. [`docs/features/workspace.md`](../../docs/features/workspace.md) 의 「파일 공간」 |
| `/files/workspace` | 에이전트 작업 폴더. 내 에이전트들이 함께 쓰는 실행 공간의 목록, 미리보기, 내려받기, 지우기. `?path=` 는 연 디렉터리이고 `?file=` 은 미리 보는 파일이다 |
| `/dev-docs` | 개발 문서. 로그인한 모든 사용자. 배포 커밋의 로드맵(`docs/prd.md` 의 「로드맵」)과 문서 목록. 설정의 「도움말」 묶음에서 간다([`docs/features/dev-overview.md`](../../docs/features/dev-overview.md)) |
| `/dev-docs/{저장소 경로}` | 개발 문서 하나. 목록에 든 문서만 열고 나머지는 404 다 |

| `/tasks/new` | 예약 작업 만들기 |

| `/notifications` | 전의 알림 화면 주소. 「알림」 탭이 열린 `/now?tab=notifications` 로 넘긴다([`docs/features/attention.md`](../../docs/features/attention.md) 의 「화면(알림)」) |
| `/admin` | 관리자 영역의 첫 화면(요약). 그룹 전체의 최근 7일 실패와 이번 달 사용량 카드 둘. 카드마다 따로 읽는다([`docs/features/admin-area.md`](../../docs/features/admin-area.md)) |

| `/admin/models` | 그룹 모델 설정과 모델 숨김 |

`/admin` 아래는 `ADMIN` 만 연다.

## 화면 틀

ChatGPT 의 배치를 따른다. 위쪽 가로 메뉴를 두지 않고 왼쪽 사이드바 하나에 모은다.
화면 높이를 채우고 그 안에서 메시지 영역만 스크롤한다. 입력창은 늘 아래에 붙어 있다.

```
┌─ 사이드바 ─┬─ 대화 ─────────────────────┬─ 작업 과정 패널 ─┐
│ 앱 이름    ◧│ 에이전트 이름               │ (열었을 때만)     │
│ 대화방      │                            │                  │
│ ✎ 새 대화   ├────────────────────────────┤                  │
│ 🔍 검색     │ 메시지                      │ 실행 트리         │
│ 지금 볼 것 3│                            │                  │
│ 예약 작업   │                            │                  │
│ 기억 (2)    ├────────────────────────────┤                  │
│─────────── │ 입력창                 ■ / ↑│                  │
│ 오늘        │                            │                  │
│  대화 A     │                            │                  │
│ 지난 7일    │                            │                  │
│  대화 B     │                            │                  │
│─────────── │                            │                  │
│ 👤 이름     │                            │                  │
└────────────┴────────────────────────────┴──────────────────┘
```

사이드바는 대화 쪽 화면(`/`, `/new`, `/chat/{id}`, `/now`, `/tasks`, `/memory`)에 있다. `/notifications` 는 `/now?tab=notifications` 로 넘기기만 한다.
관리자 영역의 틀은 아래 「관리자 영역의 틀」, 설정 화면들의 틀은 「설정 틀」 절이 갖는다.
무엇을 남기고 무엇을 뒤로 보냈는지와 그 까닭은 [`docs/features/app-shell/spec.md`](../../docs/features/app-shell/spec.md) 가 갖는다.

사이드바는 위에서부터 네 구역이다.

| 구역 | 높이가 모자랄 때 |
| --- | --- |
| 앱 이름, 대화방, 「새 대화」, 대화 검색, 「지금 볼 것」 | 줄어들지 않는다. 대화 목록이 길어도 스크롤 없이 보인다 |
| 주요 화면 메뉴(「예약 작업」, 「기억」) | 대화 목록이 다 줄어든 뒤에 줄어들고 그 안에서 스크롤한다 |
| 대화 목록 | 남는 높이를 쓰고 그 안에서 스크롤한다. 가장 먼저 줄어든다 |
| 맨 아래 이름 줄 | 줄어들지 않는다 |

「지금 볼 것」 은 주요 화면 메뉴가 아니다. 좁은 폭에서는 서랍으로 연 사이드바의 같은 자리이고, 사이드바를 접은 머리에는 두지 않는다.

**사이드바의 항목마다 아이콘을 글자 앞에 둔다.** 아이콘은 `lucide-react` 에서 고르고 낭독기에서는 숨긴다. 이름은 글자가 읽는다.
서랍으로 연 사이드바도 같은 부품이라 같은 아이콘이 보인다.

| 항목 | 아이콘 |
| --- | --- |
| 새 대화 | `SquarePen`. 좁은 화면 머리의 「새 대화」 와 같다 |
| 지금 볼 것 | `Inbox` |
| 예약 작업 | `CalendarClock` |
| 기억 | `Brain` |
| 이름 줄 | `UserRound` |
| 설정(이름 메뉴) | `Settings` |
| 관리자 화면(이름 메뉴) | `ShieldCheck` |
| 로그아웃(이름 메뉴) | `LogOut` |

설정 틀의 묶음 목록도 같은 규칙이다. 에이전트 `Bot`, 알림 `Bell`, 외부 서비스 연결 `Plug`(플러그인 아이콘이 없는 서비스의 카드도 같다), 내 브라우저 `Globe`(관리자 메뉴의 「브라우저」 와 같다), 파일 공간 `FolderOpen`, 개발 문서 `BookOpen`, 데이터 보관 안내 `ShieldQuestion` 이다.

**맨 아래 이름 줄은 화면 높이가 낮아도 잘리지 않는다.**
전에는 메뉴와 이름이 한 덩어리였고 줄어들지 않아, 가로로 돌린 전화기나 키보드가 올라온 화면에서 아래쪽이 화면 밖으로 잘렸다.
설정과 관리자 입구, 로그아웃이 이 줄의 메뉴에 있으므로 이 줄만은 늘 보이게 한다.

**이름 줄을 누르면 이름 메뉴가 열린다.** 맨 위에 이름, 그 아래 「설정」(`/settings`), 「관리자 화면」(`ADMIN` 만), 「화면 밝기」 라디오 셋, 「로그아웃」 이다.
「화면 밝기」 는 하위 메뉴로 두지 않는다. 좁은 서랍에서 하위 메뉴가 부모 메뉴를 덮는다.
로그아웃은 `POST /signout` 이 이 브라우저의 세션만 지운 뒤 `/signin` 을 문서째 연다. 뒤로 가기로 bfcache 에서 꺼낸 문서는 화면 틀이 세션을 확인해 없을 때 다시 읽는다. 순서와 까닭은 [`docs/features/app-shell/design.md`](../../docs/features/app-shell/design.md) 의 「로그아웃」 이 갖는다.

알림 단추는 없다. 「지금 볼 것」 줄이 할 것의 수나 새 알림의 점을 붙이고, 좁은 화면에서는 서랍을 열지 않아도 보이게 위 막대의 「새 대화」 옆에 같은 단추를 하나 더 둔다. 서랍에서 앱 이름 줄의 오른쪽 끝은 서랍 닫기 단추 자리라 비워 둔다.
수와 점의 규칙은 [`docs/features/app-shell/design.md`](../../docs/features/app-shell/design.md) 의 「지금 볼 것 수와 점」, 알림 목록은 [`docs/features/attention.md`](../../docs/features/attention.md) 의 「화면(알림)」 이 갖는다.

### 관리자 입구

이름 메뉴의 「관리자 화면」 은 `ADMIN` 에게만 보이는 줄이고 `/admin` 으로 간다.
**일반 화면에서 관리자 영역으로 가는 입구는 이것 하나다.** 메뉴에 관리 화면 링크를 따로 두지 않는다.

**역할을 읽지 못했으면 입구를 말없이 빼지 않는다.**
레이아웃이 `/api/v1/me` 를 읽지 못하면 역할을 알 수 없다. 그때 `MEMBER` 로 치면 관리자의 입구가 까닭 없이 사라진다.
화면 틀이 브라우저에서 `/api/me` 를 한 번 다시 읽고, 그래도 못 읽으면 맨 아래 이름 줄에 「계정 정보를 읽지 못했어요」 와 「다시 읽기」 단추, 아이콘만 보이는 메뉴 단추를 나란히 보인다.
읽지 못한 동안에도 메뉴는 열리지만 「관리자 화면」 과 관리자 전용 표시는 그리지 않는다. 로그아웃할 길은 남는다.

### 설정 틀

`/settings`, `/agents`, `/connections`, `/browser`, `/files`, `/dev-docs` 와 그 아래, 로그인한 `/privacy` 는 사이드바 대신 설정 틀을 쓴다.
어느 경로가 드는지와 묶음 목록은 `web/src/components/shell/settings-area.ts` 가 갖는다.

- 머리에 「설정」 과 오른쪽 「대화로」 를 둔다. 「대화로」 는 관리자 틀의 「사용 화면으로 돌아가기」 와 같이 마지막으로 본 대화, 없으면 `/` 로 간다(`back-to-chat.ts`).
- 넓은 화면은 왼쪽에 묶음 목록, 오른쪽에 본문이다. `/settings` 자체는 「에이전트」 가 골라진 것으로 치고, 그 아래 주소(`/settings/notifications`)는 자기 줄이 골라진다. 실행 하나의 화면은 설정 틀 밖에서 보인다.
- 좁은 화면은 `/settings` 에서 묶음 목록만, 다른 주소에서는 본문만 보이고 머리 왼쪽의 뒤로 가기가 목록으로 돌아간다. 넓이는 CSS 로만 나눈다.
- 대화 목록과 알림 구독은 끄지 않는다. 「대화로」 로 돌아갈 때 다시 읽지 않는다. 단축키는 켜지 않는다.
- 묶음 목록의 폭은 사이드바와 같다. 본문 자리의 폭이 같아 사이드바 틀의 화면에서 설정으로 옮겨도 제목의 왼쪽 끝이 같다.

### 화면 머리 틀과 세 안내

사이드바와 설정에서 여는 화면은 `components/ui/page-frame.tsx` 의 `PageFrame` 하나로 감싼다. 대상 화면과 문구는 [`docs/features/app-shell/design.md`](../../docs/features/app-shell/design.md) 의 「같은 머리 틀」 이 갖는다.

- **화면이 폭 클래스와 `h1` 을 따로 갖지 않는다.** `PageFrame` 이 바깥 폭, 뒤로 가기(상세 화면), 제목과 한 줄 설명, 오른쪽 주 단추, 본문 자리를 그린다. 폭을 고르는 prop 은 없다. 화면마다 폭을 고르면 화면을 옮길 때 내용이 좌우로 튄다.
- 목록 화면의 제목과 설명은 `lib/page-head.ts` 가 갖고 page 와 `loading.tsx` 가 같은 값을 읽는다.
- `loading.tsx` 는 `PageFrame` 을 `busy` 로 그린다. 머리는 실제 글자이고 본문에 뼈대를 둔다. 이름을 아직 모르는 상세 화면만 제목 자리에 뼈대를 둔다.
- 에이전트 상세의 절 부품은 폭을 갖지 않는다. `AgentDetailBody` 가 일반 화면은 `PageFrame` 으로, 관리자 영역은 그 영역의 폭으로 감싼다.

화면의 목록이 비었을 때, 불러오지 못했을 때, 읽는 중일 때는 아래 부품을 쓴다.

| 상태 | 부품 |
| --- | --- |
| 빈 목록 | `components/ui/empty-state.tsx` 의 `EmptyState` |
| 불러오기 실패 | `components/ui/page-state.tsx` 의 `LoadFailure`. 한 줄과 「다시 읽기」 다. 브라우저가 읽는 화면은 다시 읽는 함수를 `onRetry` 로 넘기고, 서버가 읽는 화면은 넘기지 않아 문서를 새로 연다 |
| 읽는 중 | 같은 파일의 `ListSkeleton` |

화면 안쪽의 작은 목록(에이전트 상세의 절, 기억의 필터 결과, 작업 폴더 탐색기)은 대상이 아니다.

### 관리자 영역의 틀

`/admin` 아래의 화면은 사이드바를 그리지 않고 자기 틀을 쓴다. 대화 목록도 읽지 않는다.

```
넓은 화면
┌──────────────────────────────────────────────────────┐
│ [관리자]                    ← 사용 화면으로 돌아가기   │
├───────────┬──────────────────────────────────────────┤
│ 메뉴       │                                          │
│ (세로 목록) │   고른 메뉴의 화면                        │
│           │                                          │
└───────────┴──────────────────────────────────────────┘

좁은 화면
┌────────────────────────────┐
│ ☰ [관리자]   ← 사용 화면으로 │  ← ☰ 가 같은 메뉴를 왼쪽 서랍으로 연다
├────────────────────────────┤
│ 고른 메뉴의 화면             │
└────────────────────────────┘
```

메뉴는 「살펴보기」, 「비서 설정」, 「사용자와 자원」 세 묶음이고 묶음 제목은 누를 수 없다. 묶음과 순서는 [`docs/features/users.md`](../../docs/features/users.md) 「관리자 영역」 의 표와 같고, 목록은 `components/shell/admin-shell.tsx` 가 갖는다.
「요약」 줄은 `/admin` 과 주소가 같을 때만 골라진다. 좁은 화면의 서랍은 줄을 고르거나 바깥을 누르거나 `Esc` 로 닫힌다.

머리의 「관리자」 는 배지다. 색과 부품은 일반 화면과 같은 토큰을 쓴다.
관리자 메뉴도 항목마다 아이콘을 둔다. 요약 `LayoutDashboard`, 사용자 `Users`, 에이전트 `Bot`, 모델 `Cpu`, 사용량과 비용 `Receipt`, 도구 `Wrench`, 외부 서비스 연결 `Plug`, 브라우저 `Globe`, 파일 공간 `HardDrive`, 서버 비밀값 `KeyRound` 다.
머리에 특정 그룹을 뜻하는 이름을 적지 않는다.

**「사용 화면으로 돌아가기」 는 마지막으로 보던 대화로 간다.**
화면 틀이 `/chat/{id}` 를 볼 때마다 그 경로를 그 탭의 `sessionStorage` 에 적어 둔다.
적어 둔 것이 없거나 저장소를 읽지 못하면 `/` 로 간다.
그 대화가 그사이 지워졌으면 대화 화면이 찾을 수 없다는 안내와 새 대화 단추를 보인다.

`MEMBER` 역할 사용자가 `/admin` 아래의 주소를 열면 `/` 로 넘긴다. 역할을 읽지 못했으면 넘기지 않고 읽지 못했다는 안내를 보인다.
화면 목록과 일반 화면에서 옮겨 온 것은 [`docs/features/users.md`](../../docs/features/users.md) 의 「관리자 영역」 절이 갖는다.

| 너비 | 사이드바 | 작업 과정 패널 |
| --- | --- | --- |
| `lg` 이상 | 왼쪽에 늘 보인다. 접을 수 있다 | 대화 오른쪽에 붙는다 |
| `md` 이상 `lg` 미만 | 왼쪽에 늘 보인다. 접을 수 있다 | 대화 위에 겹친다 |
| `md` 미만 | 서랍. 위쪽 막대의 단추로 열고 대화를 고르면 닫힌다 | 화면 전체를 덮는다 |

위 표의 사이드바는 일반 화면의 것이다.

접은 상태는 그 브라우저에 남긴다.
좁은 화면의 위쪽 막대에는 서랍 단추, 화면 제목, 「지금 볼 것」 단추, 새 대화 단추를 둔다.
화면 제목이 없으면 앱 이름을 보인다. 제목은 가운데 정렬하고 길면 말줄임한다.
제목을 누르면 `/` 로 가서 새 대화를 시작한다. 이미 홈이어도 대화 상태와 입력을 비운다.
화면 낭독기는 보이는 제목과 관계없이 「<앱 이름> 홈」 으로 읽는다.
새 대화 화면은 이 제목 자리를 이름표 단추로 바꾼다. 화면이 `components/shell/title-slot.ts` 의 `useShellTitleSlot` 으로 자리를 차지하면 위쪽 막대(`mobile-top-bar.tsx`)는 제목 링크 대신 그 자리를 보이고, 화면이 portal 로 단추를 그린다. 단추의 상태는 화면에 남는다.
모바일 서랍이 열리면 서랍의 홈 링크만 읽고, 닫히면 머리줄의 홈 링크만 읽는다.

서랍은 누른 곳으로 옮겨진 뒤에 닫힌다.
옮기는 동안에는 열어 두어 누른 줄의 회전 표시와 「옮기는 중」 안내가 보이게 한다.
지금 있는 화면을 다시 누르면 옮길 것이 없으므로 곧바로 닫는다.

단축키는 새 대화, 사이드바 접기와 펴기, 대화 검색칸으로 가기 셋이다. 키 조합은 `web/src/components/shell/use-shortcuts.ts` 가 갖는다.
`Esc` 는 아래 차례로 하나만 한다.

**`Esc` 는 한 곳에서만 해석한다.** 대화 화면의 처리기 하나가 아래 차례로 보고 처음 맞는 하나만 한다.

1. 한글을 조합하는 중이면 아무것도 하지 않는다
2. 이름 입력칸, 확인 창, 서랍, `@` 목록처럼 더 안쪽의 것이 이미 처리했으면 아무것도 하지 않는다.
   그것들은 `Esc` 를 처리하면 전파를 막는다.
   Radix 부품이 `Esc` 로 닫으면 기본 동작이 막혀 대화 화면의 처리기가 건너뛴다. 막지 않는 부품이면 `onEscapeKeyDown` 에서 막는다.
   「중지」 의 풀이는 예외다. 풀이가 열려 있으면 `Esc` 가 풀이를 닫고 3번으로 넘어간다.
   마우스를 올려 둔 채 누른 `Esc` 가 풀이만 닫고 답을 멈추지 않으면 사용자는 두 번 눌러야 한다.
   이미 닫히고 있는 풀이도 같다. 어느 단추의 풀이든 닫히는 움직임이 끝날 때까지 화면에 남아 `Esc` 를 받는데,
   사용자에게는 닫을 것이 보이지 않으므로 그 `Esc` 는 3번으로 넘어간다.
   창이나 확인 창, 메뉴가 열려 있을 때는 넘기지 않는다
3. 작업 과정 패널이 열려 있으면 닫는다
4. 답을 만드는 중이면 중지한다

이름 바꾸기를 `Esc` 로 취소했는데 돌던 답까지 멈추면 안 된다.

**입력창은 사용자가 대화를 바꿀 때만 새로 만든다.**
입력창이 올린 사진을 갖고 있고, 없어질 때 보내지 않은 사진을 서버에서 지운다.
대화 식별자가 생겼다고 새로 만들면 방금 올린 사진이 사라진다.
배치를 옮길 때도 같은 입력창 하나를 그대로 두고 자리만 바꾼다. 새 대화 화면의 가운데에서 아래로 내려갈 때가 그렇다.

### 새 메시지를 따라간다

메시지가 늘면 아래로 따라 내려간다.
다만 사용자가 위로 올려 지난 대화를 읽고 있으면 따라가지 않는다.
읽던 자리가 밀려나기 때문이다. 대신 `새 메시지` 단추를 띄워 누르면 내려간다.

## 디렉터리

`app/` 은 경로와 서버에서 읽는 것만 담고, 화면을 이루는 부품은 `components/` 에 둔다.
`components/ui/` 는 어느 화면에도 속하지 않는 조각이고, 그 밖의 파일은 한 화면의 부품이다.

**서버에서 데이터를 읽는 화면 경로는 `loading.tsx` 를 함께 둔다.** 옮기는 동안 보일 뼈대다.
뼈대는 그 화면의 바깥 틀(최대 폭, 제목 자리, 목록이나 표의 줄 높이)을 `page.tsx` 와 같게 둔다.
화면 머리 틀을 쓰는 화면은 같은 틀을 `busy` 로 그려 폭과 제목 자리를 맞추고, 본문은 화면과 상관없이 같은 `ListSkeleton` 을 둔다. 읽는 중의 모양을 화면마다 같게 하려는 것이라 줄 높이는 맞추지 않는다.
`/` 에는 두지 않는다. 로그인 확인 말고는 서버에서 읽는 데이터가 없다.

**`components/ui/` 를 shadcn/ui 에서 복사한 부품으로 채우기로 했다.** 근거는
[ADR-023](adr/ADR-023-화면-부품은-shadcn-ui-를-저장소에-복사해-쓴다.md) 에 있다.
대화상자, 메뉴, 서랍, 알림 풍선을 직접 만들지 않는다.

## 색과 간격은 테마 토큰이 소유한다

색과 간격을 인라인 스타일로 적지 않고 `globals.css` 의 토큰과 Tailwind 클래스로 쓴다.
규칙의 까닭과 예외는 [rule-56](../../docs/code-rules/rule-56.md)이 갖는다.

토큰은 `globals.css` 한 곳에서만 선언한다. 밝기 모드도 거기서 갈린다.

토큰 이름은 shadcn 의 이름 체계를 쓴다. 옛 이름과의 대응표와 근거는 [ADR-023](adr/ADR-023-화면-부품은-shadcn-ui-를-저장소에-복사해-쓴다.md) 이 갖는다.
색 값, 모서리, 움직임 토큰의 값과 근거는 [ADR-051](adr/ADR-051-화면-색은-새벽-보라로-바꾸고-강조-색은-누를-것과-고른-것과-초점에만-쓴다.md) 이 갖는다.

## 우리 화면의 정체성

가족이 쓰는 개인형 비서다. 대화가 중심이고 관리 도구처럼 보이지 않게 한다.
팔레트는 「새벽 보라」 다. 강조 색은 보라(`primary`, 밝음 `#6D4AFF`)이고, 비서가 일하는 중이라는 신호만 라임 점(`signal`)이 맡는다.
값과 근거는 [ADR-051](adr/ADR-051-화면-색은-새벽-보라로-바꾸고-강조-색은-누를-것과-고른-것과-초점에만-쓴다.md) 이 갖는다.

| 토큰 | 쓰는 곳 |
| --- | --- |
| `primary` | 주 단추. 한 화면에서 지금 누를 단추 하나 |
| `primary-strong` | 주 단추를 눌렀을 때와 마우스를 올렸을 때 |
| `primary-soft`, `primary-soft-foreground` | 지금 고른 것의 바탕과 글자, 내 말풍선 바탕 |
| `ring` | 초점 테두리 |
| `signal`, `pill` | 일하는 중을 알리는 점과 그 점을 담는 알약 |
| `success`, `warning`, `info`, `destructive` 와 각 `-soft` | 상태를 알리는 배지와 알림 상자 |
| `card`, `muted` | 한 층 위의 표면과 낮은 표면 |

**상태는 색과 아이콘을 함께 쓴다.** 비서 얼굴은 `muted` 바탕으로 그린다.
강조 색과 공통 부품, 움직임 토큰의 규칙은 [rule-56](../../docs/code-rules/rule-56.md)이 갖는다.

글꼴은 Pretendard 다. 한국어 화면에서 인상의 절반을 글꼴이 정한다.

**글꼴 파일을 우리가 들고 배포한다.** 외부 CDN 에서 받지 않는다.
가족만 쓰는 화면이라 화면을 열 때마다 외부에 요청이 나가는 것을 원하지 않는다.
망이 끊긴 집에서도 같은 화면이 나와야 한다.

대화 화면의 구조는 ChatGPT 의 배치를 따른다.

| 요소 | 규칙 |
| --- | --- |
| 화면 틀 | 왼쪽 사이드바 하나. 위쪽 가로 메뉴를 두지 않는다 |
| 대화 열 | 가운데 정렬한 좁은 열. 화면 폭을 다 쓰지 않는다 |
| 내가 보낸 줄 | 오른쪽 정렬 말풍선. 폭은 열의 70% 까지 |
| 비서가 답한 줄 | 열 전체 폭. 배경과 테두리가 없다 |
| 입력창 | 둥근 상자 하나에 두 줄. 위 줄은 글 칸, 아래 줄은 왼쪽에 「＋」(사진 첨부)와 모델 단계 단추, 오른쪽에 원형 보내기 단추. 답을 만드는 동안 보내기 옆에 중지 단추가 나온다. 상자 밖에 따로 떠 있는 줄은 없다 |
| 작업 과정 | 답 위에 접힌 블록 하나. 펼치거나 오른쪽 패널로 연다 |
| 메시지 동작 | 답 아래 한 줄. 복사, 다시 생성, 판 넘기기 |
| 새 대화 | 입력창이 가운데. 위에 인사, 아래에 추천 질문. 에이전트는 넓은 화면의 대화 영역 머리 줄, 좁은 화면의 위쪽 막대 가운데에 있는 이름표로 고른다 |

**사이드바의 대화 목록은 화면 틀이 갖는다.** 대화 화면이 갖지 않는다.
다른 화면에서도 목록이 보여야 하고, 대화 화면은 보낸 뒤 목록에 알리기만 한다.
`components/shell/` 의 목록 context 가 목록을 읽고, 대화 화면이 그 context 의 갱신 함수를 부른다.

**목록은 한 쪽(30개)만 읽고 끝에 닿으면 이어 읽는다.** 사용자의 대화가 수백 개가 돼도 첫 화면은 한 쪽만 부른다.
갱신 함수(`refresh`)는 첫 쪽만 다시 읽고 이어 읽어 둔 줄은 남긴다. 읽는 중에 여러 번 불려도 진행 중인 읽기에 얹혀 많아야 두 번 나간다.
첫 쪽에 없는 오래된 대화를 주소로 열면 `useConversation` 이 그 대화 한 줄만 따로 읽는다. 목록의 순서에는 끼지 않는다.
사이드바의 대화 링크는 `prefetch={false}` 다. 보이는 링크마다 대화 화면을 미리 읽으면 한 화면에서 요청이 수십 개 한꺼번에 나가 edge 의 요청 상한(429)에 닿는다.

비서의 답만 폭을 다 쓰는 이유는 표와 코드 블록이 오기 때문이다.
좁은 말풍선에 넣으면 그 안에서 가로로 밀어야 읽힌다.

## 화면 밖에서 오는 글은 마크다운으로 읽는다

에이전트의 답은 마크다운으로 그려 표와 목록과 코드 블록이 제 모양으로 보이게 한다.
외부 본문의 렌더링 경계는 [rule-57](../../docs/code-rules/rule-57.md)이 갖는다.

## 밝기 모드

이름 메뉴의 「화면 밝기」 에서 밝게, 어둡게, 기기 설정 셋 중에서 고른다. 고른 값은 그 브라우저에 남는다.
아무것도 고르지 않았으면 시스템 설정을 따른다.

첫 화면이 밝게 그려졌다가 어둡게 바뀌는 일이 없어야 한다.
`next-themes` 가 그리기 전에 저장된 값을 읽어 `html` 에 붙인다.
