# 근거 원본 최신화 확인

지원 준비를 시작하기 전에 로컬 사본으로 읽는 근거 원본이 원격보다 뒤처졌는지 확인한다.
`application-package-writer` 가 이 문서를 따른다.
`resume-preparer` 도 같은 원본을 읽지만, 이 스킬을 거쳐 왔다면 검사를 이미 마친 것으로 본다.

## 먼저 확인하는 이유

뒤처진 사본은 오류를 내지 않는다.
없는 문서는 없는 경험으로 판정되고 적합도 점수만 낮아진다.

실측에서 지원 한 건을 준비하는 동안 로컬 `fos-study` 사본이 원격보다 388커밋, 넉 달 뒤처져 있었다.
그 사이에 추가된 문서 넷이 판정과 이력서를 바꿨다.

| 문서 | 바뀐 것 |
| --- | --- |
| `ocr-api-gateway-removal.md` | 이력서에 새 절로 들어갔고, 공고의 API 설계 항목 점수가 올라 총점이 84.5 에서 86.5 로 바뀌었다 |
| `ocr-scale-connection-resilience.md` | 기존 이력서 문장이 실제 진행 상태와 어긋난 것을 잡았다 |
| `docparser-*.md` 와 `observability-to-error-triage-loop.md` | 주장별 근거 대조의 근거가 됐다 |

판정이 낮게 나오고 아무 경고도 나오지 않는 것이 문제다.
그래서 사람이 알아차리기를 기다리지 않고 시작할 때 한 번 검사한다.

## 대상 셋

| 원본 | 어떻게 읽는가 | 최신 여부를 누가 보는가 |
| --- | --- | --- |
| 프로젝트 근거 디렉터리 | `CAREER_EVIDENCE_DIR`(`workspace paths` 의 `evidenceDir`). 검사기는 이 변수가 있을 때만 그 자리와 바로 위를 본다 | 이 문서의 검사기가 본다 |
| 후보자 맥락 문서 | 기억에서 `memory_search`, `memory_read` 로 읽는다 | 뒤처질 사본이 없다 |
| 지원서 공통 프로필 | 기억의 「커리어: 지원서 공통 프로필」 을 읽는다 | 뒤처질 사본이 없다. 아래 절이 설명한다 |

**검사기가 보는 것은 프로젝트 근거 디렉터리 하나뿐이다.**
로컬에 사본을 두는 원본에만 뒤처질 위험이 있다.

프로젝트 근거는 별도 Git 저장소(`fos-study`)이며 이 스킬에서는 읽기 전용이다.
검사기는 그 위치를 셸 환경 변수 `CAREER_EVIDENCE_DIR` 로만 받고 `.env` 를 찾지 않는다.
`CAREER_EVIDENCE_DIR` 는 저장소의 루트이거나 그 바로 아래 디렉터리(`task/`)여야 한다.
검사기는 그 자리와 상위를 순서대로 보고, 앞의 자리에서 저장소를 찾으면 뒤는 보지 않는다.

**그 자리가 Git 저장소의 루트일 때만 그 원본으로 인정한다.**
저장소 안의 평범한 디렉터리는 상위 저장소의 `.git` 을 물려받아 저장소처럼 보인다.
실측에서 빈 근거 디렉터리가 그것을 담은 다른 저장소의 상태를 `fos-study` 의 상태로 보고했다.

`CAREER_EVIDENCE_DIR` 가 없으면 검사기는 작업 폴더의 `evidence/` 를 대신 보지 않고 `unavailable` 로 끝난다.
작업 폴더 `root` 가 우연히 Git 저장소의 루트면 그 저장소를 원본으로 오인하기 때문이다.

## 지원서 공통 프로필을 경로로 확인하지 않는 이유

지원서 공통 프로필과 후보자 맥락 문서는 파일을 여는 곳이 아니라 기억에서 그때그때 읽는 곳이다.
프로젝트 근거는 로컬 clone 을 두고 읽으므로 원격이 앞서 나가면 조용히 낮게 판정된다.
기억은 읽을 때마다 현재 상태라 그 상태가 생기지 않는다. 작업 폴더 `context/` 의 사본은 읽은 직후에만 쓰고 원본으로 삼지 않는다.

기억의 실패는 다른 모양으로 온다. 찾았는데 그 제목의 문서가 없는 것이다.
본인에 관한 사실은 사용자에게 묻기 전에 공통 프로필과 후보자 맥락 문서를 먼저 읽는다.
읽어서 없을 때만 사용자에게 묻는다.
공통 프로필에 없거나 틀린 사실은 이 스킬이 고치지 않는다. 사용자에게 기억 화면에서 고치라고 알린다.
후보자 맥락 문서의 사실은 `career-connector` 스킬의 「맥락 문서 읽고 고치기」 로 고친다.

## 확인 방법

작업 트리를 바꾸지 않고 원격 ref 만 받아 대조한다.
원본 위치를 `CAREER_EVIDENCE_DIR` 로 받으므로 어느 디렉터리에서 실행해도 결과가 같다.

```bash
<CAREER_LOCAL> package check-sources
```

원격을 받지 않고 직전에 받아 둔 ref 로만 보려면 `--no-fetch` 를 붙인다.
연결이 없는 환경에서 검사를 이어갈 때만 쓴다.

실행기를 쓸 수 없으면 원본마다 같은 두 명령을 직접 실행한다.

```bash
git -C <원본 경로> fetch --quiet origin main
git -C <원본 경로> rev-list --count HEAD..origin/main
```

## 판정별 다음 행동

| 판정 | 뜻 | 다음 행동 |
| --- | --- | --- |
| `up_to_date` | 원격과 같은 커밋이다 | 다음 단계로 간다 |
| `behind` | 원격에만 있는 커밋이 있다 | 멈추고 사용자에게 알린다 |
| `unavailable` | 어느 자리에서도 저장소를 찾지 못했다 | 멈추고 `CAREER_EVIDENCE_DIR` 가 근거 저장소(Git 저장소의 루트이거나 그 바로 아래)를 가리키게 하라고 알린다. 근거 디렉터리가 Git 저장소가 아니라 이 검사를 할 수 없는 사용자가 이어가라고 하면 최신 여부를 확인하지 못했다고 적고 진행한다 |
| `unreachable` | 저장소는 있으나 원격을 받지 못했다 | 사용자에게 알리고, 사용자가 이어가라고 하면 확인하지 못한 범위를 적고 진행한다 |

`unavailable` 의 `detail` 은 자리마다 왜 아니었는지를 담는다.
경로가 없는 것과 환경 변수가 없는 것을 거기서 구분한다. 사용자가 할 일이 다르기 때문이다.

### 종료 코드

| 코드 | 언제 |
| --- | --- |
| 0 | 모든 원본이 `up_to_date` 다 |
| 1 | 그 밖의 판정이 하나라도 있다 |
| 2 | 인자나 옵션이 규격에 맞지 않다 |

**확인하지 못한 원본도 1 로 끊는다.**
확인하지 못한 것을 최신으로 보면 검사가 없는 것과 같고, 이 검사는 바로 그 상태를 막으려고 있다.
이어갈지는 사용자가 정하며, 실행기가 대신 정하지 않는다.

**뒤처진 것을 발견하면 스킬이 자동으로 당기지 않는다.**
읽기 전용 저장소이고, 당기는 과정에 아래 함정이 있어 사람이 판단해야 한다.

사용자에게 알릴 때 원본 이름, 뒤처진 커밋 수, 원격 최신 커밋 시각과 이 원본이 바꾸는 판정을 함께 적는다.
사용자가 뒤처진 채로 진행하라고 하면 그 사실을 `evidence/status.md` 의 「사용자 확인 필요」에 남긴다.

## 로컬 사본을 당길 때의 함정

사용자가 당기기로 했을 때 실제로 걸린 것이다.

- **미추적 파일이 원격의 추적 파일과 같은 경로에 있으면 `git pull` 이 거부한다.** 지우기 전에 로컬 전용인지 확인한다. 실측에서 스킬 둘이 로컬에만 있었다.
- **원격이 실제 파일을 심볼릭 링크로 바꿔 둔 경우가 있었다.** 경로 이름이 같아도 내용이 아니라 종류가 바뀐 것이다.
- **지우기 전에 백업한다.** 되돌릴 수 있는 상태를 만들고 나서 당긴다.

## 통과 조건

검사기가 보는 원본의 판정이 `up_to_date` 다.
그렇지 않으면 사용자에게 알렸고, 사용자가 이어가라고 한 원본은 확인하지 못한 범위를 기록했다.
